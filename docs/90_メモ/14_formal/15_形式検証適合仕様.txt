    表し、accepted 経路を構造化追跡することで unverified

■ 設計原則
  - proof_class は bundle である。
      yaml に書く formal.proof.* attribute のうち、proof_
      class 1 つの値が他 6 dimension（cadence_class /
      artifact_class / orchestrator_preference / coverage_
      weight / regression_corpus_class / reviewer_kind_
      requirement）を一意に導出する。各軸 spec の作者 /
      業務作者 / drill_owner が dimension を個別に override
      する経路は持たない。
  - dimension override は禁止する。
      「v1_temporal_safety_proof のうち cadence_class を
      緩めたい」要望は新 class を切ることで表現する。class
      数の爆発は意味論の規律として受け入れる。
  - dead spec を CI で殺す。
      classes.yaml に登録された全 class、proof_matrix.lock
      .yaml に列挙された全 cell、proof_inventory.yaml /
      counter_example.lock.yaml / proof_review.lock.yaml /
      assumption.lock.yaml に列挙された全 entry、proof_
      regression_corpus に保存された全 reproducer は、
      いずれも参照されなくなった時点で CI fail とする。
      service のうち proof ownership_table.lock.yaml に
      4 軸 entry が無いものも CI fail（proof ownership 未
      宣言の deploy を deny by default）。
  - 5 種類 enforcement orchestrator を全 proof_class に
    必須化する。
      tlaplus_apalache_pipeline / p_pgo_pipeline /
      stainless_dafny_pipeline / lean_mathlib_pipeline /
      kani_cbmc_pipeline の 5 orchestrator は、各 class が
      必要とする層を宣言する。同一 proof は複数 orchestrator
      に分散しないが、同一 axis では複数 class が複数
      orchestrator を併用する。
  - proof cadence を物理 property とする。
      「cell の cadence_days 以内に必ず該当 class の proof
      を再 verify し、宣言された certificate hash で
      verified する」を Tekton Pipeline + reproducibility
      checker daemon で必ず検証する。13 の v1_proof_
      coverage_compliance / v1_proof_freshness_compliance
      / v1_counter_example_closure_compliance / v1_proof_
      review_dual_signoff_compliance が cluster_label 付き
      metric で隣接 cluster を観測し、cell verified 破綻を
      即時 alert + admission block に流す。
  - defense-in-depth は 5 層で構成する。
      層 A : compile 時（PR の proof_class 注釈必須、
              proof_matrix.lock.yaml schema 通過）
      層 B : lint（catalog の coverage / cadence /
              ownership / reproducibility / reviewer
              dual-signoff）
      層 C : drill chaos test（Tekton + Argo Workflows
              + Apalache + TLC + Stainless + Dafny +
              Lean + Kani + CBMC）
      層 D : runtime（5 orchestrator の実 deploy）
      層 E : physical（cosign signature / Kyverno
              admission webhook / Ceph RGW Object Lock
              Compliance mode / proof_event hash chain /
              dual reviewer cosign の物理層強制）
      任意の単層が破れても他層が必ず止める。物理
      enforcement は最終 safety net。

■ 5 phase（全 cell が phase closure を要求）
  - specify：軸 spec の formal_obligations 段落で
    obligation を theorem 名 + 自然言語 + tool 候補で
    宣言
  - model：tool に応じて TLA+ / P / Stainless / Dafny /
    Lean / Kani / CBMC の spec / harness を書く
  - prove：Tekton Pipeline で tool 起動、verification
    obligation を SMT / model checker で discharge
  - review：dual reviewer cosign signoff（reviewer のうち
    1 名以上は人間、cryptographic proof は crypto-domain
    expert）
  - archive：proof artifact + certificate hash + reviewer
    sigs を proof_status.lock.yaml に fingerprint、Ceph
    RGW Object Lock Compliance mode で retention

  各 cell の phase_closure_state ∈ {v1_complete, v1_in_
  progress_handled, v1_blocked} の 3 値、v1_blocked が 1
  cell でもあれば 1.0.0 ship blocker。
