============================================================
formal 非提供スコープ
============================================================

■ 一文方針
  - formal は「コード経路に依存せず数学的に証明されるべき
    invariant」のみを管掌対象とし、それ以外（実行ベース
    検証 / threat 宣言 / SLO target / OSS 選択 / proof
    obligation の意味論そのもの）は他軸の所有とする。

■ 採用しない設計（提供しない）
  - 商用 proof assistant（Coq Inria 派生 / Isabelle/HOL
    の Isabelle UK 商用 fork / F* Microsoft Research /
    SPARK Pro AdaCore 商用版）は採用しない。
        - 理由：v1_l1plus_primary に Lean 4 + mathlib /
          Stainless / Dafny / TLA+ + Apalache / P / Kani /
          CBMC の OSS 7 種を単一深耕することで covered。
          商用 license の cost ではなく「単一 OSS L1+ 深耕」
          の規律から外れる。
        - 例外：研究文献引用としての Coq / Isabelle 既知
          theorem（Bellare-Rogaway 等の暗号 assumption）は
          assumption.lock.yaml に文献 pointer + DOI で記載、
          formal proof artifact としては Lean / Stainless で
          再証明 or 既存 mathlib import で吸収。
  - 商用 model checker（SPIN proprietary / NuSMV 商用 /
    UPPAAL Pro）は採用しない。
        - 理由：TLA+ + Apalache / P / Kani / CBMC で covered。
  - 「文章のみで証明済み」（natural language proof、論文
    引用のみ、informal proof）は禁止。
        - 理由：machine-checkable artifact が単一の真。
          informal proof は assumption の bookkeeping を
          失い、回帰検出が不可能。
        - 例外：assumption.lock.yaml に明示登録された
          cryptographic assumption（DDH / RSA hardness /
          discrete log 等）は文献 pointer で良い。assumption
          数の cap（v1=20 件）を 14_強制機構 で物理 enforce。
  - SMT solver の単独運用（Z3 / CVC5 を直接 driver で叩く）
    は採用しない。
        - 理由：Stainless / Dafny / Kani / CBMC が SMT
          solver を内包する形で抽象化される。direct invocation
          は意味論層をスキップし、proof artifact の単一の真
          が崩れる。
  - proof obligation の意味論そのものの記述（「何を証明
    すべきか」の宣言）：
        - → 各軸 spec（07/08/.../39/infra01/.../test/15）が
          「formal_obligations 段落」を持ち、formal は
          obligation を集約・enforce するのみ。
        - formal は「証明されるべき invariant」を新規発生
          させない。
  - threat の宣言：
        - → 10_security/15_脅威モデル適合仕様。formal は
          threat の「攻撃者視点 invariant 否定」を temporal
          _safety_proof の 1 obligation として転写するのみ、
          threat 自体は宣言しない。
  - SLI / SLO target 値の意味論：
        - → 05_tier1/13_SLO適合仕様。formal は v1_proof_
          coverage_compliance / v1_proof_freshness_
          compliance / v1_counter_example_closure_
          compliance / v1_proof_review_dual_signoff_
          compliance を SLO として登録するのみで target 値
          自体の意味論は持たない。
  - OSS 選択：
        - → 02_採用OSS一覧 / 各層 04_採用OSS。formal は
          L1+ 単一深耕の規律を踏襲するのみ。
  - 観測可能性 SoR の物理運用：
        - → 05_tier1/09_観測適合仕様 / 09_data。formal は
          proof execution の OTel trace / ClickHouse 保存を
          SoR に従属させる側。
  - cluster 構築 / 廃棄 / 位相：
        - → 08_infra/15_クラスタ位相適合仕様。formal は
          topology change 時の proof artifact 退避経路を
          claim するのみ。
  - migration pair の compatibility 判定：
        - → 05_tier1/08_マイグレーション適合仕様。formal は
          dual-write の linearizability theorem を proof_
          inventory に持つのみ、pair の意味論は migration 軸
          の所有。
  - test execution の意味論：
        - → 13_test/15_検証規律適合仕様。formal は test
          軸の v1_property_axiom と双方向 lock するのみで、
          test cell の意味論は test 軸の所有。
  - assertion / property の意味論そのもの：
        - → 各軸 spec、formal は obligation を集約・enforce
          するのみ、obligation の中身は各軸 spec の所有。
  - 「proof は完成が難しいから後回し」「critical invariant
    の証明は v2 で良い」は禁止。
        - 1.0.0 完璧 release の哲学（CLAUDE.md）に反する。
          v1 cap=20 の枠で全 critical invariant を必ず
          verified or accepted_with_assumption に到達させる。
  - LLM-generated proof の人手査読なし採用は禁止。
        - 理由：LLM 出力 proof は Lean / Stainless / Dafny /
          TLA+ で machine-checkable に通る場合のみ採用、
          かつ proof_review.lock.yaml の dual-reviewer
          sign-off 必須（reviewer のうち 1 名は LLM 自身で
          ない人間 reviewer）。tool が verified と判定しても
          spec / model 自体の妥当性査読は人手必須。

■ 採用する代替（formal の中で他軸に投影せず自軸内で持つ
  道具立て）
  - proof_inventory.lock.yaml：critical invariant の集約。
    各軸 spec の formal_obligations 段落から generator で
    生成、手書き禁止。
  - proof_status.lock.yaml：build artifact、各 proof の
    {verified / in_progress / failed / accepted_with_
    assumption} と certificate hash を保持。
  - counter_example.lock.yaml：build artifact、model checker
    が検出した反例 + close_kind + close_due_at + reproducer
    pointer を保持。
  - proof_review.lock.yaml：dual reviewer sign-off の
    artifact、reviewer 2 名の cosign signature を bind。
  - assumption.lock.yaml：cryptographic / external library
    assumption の文献 pointer + DOI + 軽減策 + revisit 期限
    を artifact 化、cap v1=20 件で物理制限。
  - mathlib_pin.lock.yaml：Lean 4 mathlib revision の pin、
    upstream pull の break-glass token + dual review 必須。
  - tla_apalache_pin.lock.yaml：TLA+ tools / Apalache version
    の pin、major version migration drill 必須。
  - kani_cbmc_pin.lock.yaml：Kani / CBMC version の pin、
    bound parameter（unwind / object-bits）の drill 必須。
  - proof_review_assignment.yaml：reviewer pool（人間 + LLM
    補助）の round-robin 割当、reviewer のうち 1 名以上は
    必ず人間。
  - proof_minutes_budget.yaml：proof 実行時間の四半期 budget、
    超過は CI alert + ops 経由 page。

■ 至高路線における除外の意図
  - 商用 proof assistant 不採用：単一 OSS L1+ 深耕の規律
    （CLAUDE.md「運用コスト度外視」とは別、設計規律として
    の単一深耕）と整合。Lean 4 + mathlib / Stainless /
    Dafny / TLA+ + Apalache / P / Kani / CBMC の 7 OSS で
    cover、横並びを持たない。
  - informal proof 不採用：「文章運用に頼らず物理
    enforcement に転写する」という全層共通の哲学を、proof
    層でも貫く。assumption.lock.yaml の cap で「やむを得ず
    informal で持つ部分」を可視化・制限。
  - LLM-generated proof の人手査読省略不採用：proof_review
    の dual sign-off を物理 enforce、reviewer の cosign
    signature を proof artifact に bind。
  - 商用 model checker 不採用：TLA+ + Apalache / P / Kani /
    CBMC で全 proof_class を cover、商用 fallback を持たない
    ことで規律を最大化。
  - SMT solver 直接運用不採用：意味論層を必ず Stainless /
    Dafny / Kani / CBMC のいずれかに通すことで、proof
    artifact の単一の真を保つ。
  - proof obligation の所有を formal が持たない：obligation
    の意味論は各軸 spec が所有することで、軸 spec の
    invariant が単一の真であり、formal は集約・enforce
    layer に徹する。
