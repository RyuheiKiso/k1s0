============================================================
formal 位置づけ
============================================================

■ 5 階層 + 横断 layer 中の位置
  - tier1   : システム共通処理（Library / Server / 認証 /
              観測可能性）
  - tier2   : ドメイン業務共通化処理
  - tier3   : 個別業務の Web サイト / exe
  - infra   : 物理 / 仮想基盤 + 制御平面
  - data    : データ層（保全 / lifecycle / 暗号化）
  - security: 全層を直交に貫く「脅威 ⊗ 軸 ⊗ 層」
              invariant の管掌 layer
  - ops     : 全層 + security を直交に貫く「loop ⊗ phase
              ⊗ 軸 ⊗ 層」 invariant の管掌 layer
  - test    : 全層 + security + ops を直交に貫く
              「verification_class ⊗ axis ⊗ phase ⊗ 層」
              invariant の管掌 layer
  - formal  : 全層 + security + ops + test を直交に貫く
              「proof_class ⊗ axis ⊗ phase ⊗ 層」
              invariant の管掌 layer ← 本層

  - formal は tier1 / tier2 / tier3 / infra / data / security
    / ops / test の上下左右に並列して存在するのではなく、
    8 階層 × 19 軸の grid を直交に貫く meta-meta-layer と
    して位置づく。formal は新しい責務を宣言するのではなく、
    既存軸の defense-in-depth 層 A〜E から発信される全
    invariant 候補のうち「コード経路に依存せず数学的に
    証明可能な部分集合」を proof_inventory.yaml に集約し、
    cell ごとの last_verified_at が cadence 内に維持される
    ことを assert する。
  - test と formal は同型だが直交する：
      - test は「実行 artifact」（pact / playwright trace /
        chaos workflow result / mutation report）を 18 axis
        × 5 verification_class = 90 cell に詰める。
      - formal は「machine-checkable certificate」（TLA+
        TLC / Apalache trace / P trace / Stainless cert /
        Dafny log / Lean .olean / Kani report / CBMC .json）
        を 19 axis × 5 proof_class = 95 cell に詰める。
      - 両者の bind：test/15 の v1_property_axiom cell と
        formal/15 の v1_temporal_safety_proof / v1_program_
        correctness_proof cell は cross-cutting に bound、
        property test の corpus は proof obligation の
        instance、proof obligation は property の axiom 形式。
  - formal が新規物理機構を持ち込むことは原則しない（既存
    軸の invariant を bind するのみ）。例外は proof_matrix
    generator / counter-example archive / mathlib pinning
    engine / proof reviewer assignment engine のような本質
    的に cross-axis な道具立てのみ。

■ 上下方向の関係
  - 上方向（5 階層 + security + ops + test が formal に依存
    する経路）：
      - tier1 transport（07）→ bidi handshake state machine
        / backoff retry loop / circuit-breaker threshold
        adaptation の TLA+ safety + liveness proof、frame
        decoder の Kani memory-safety proof を proof_inventory
        に登録、verified が deploy 前提
      - tier1 migration（08）→ 4 phase（pre / dual / cutover
        / post）の dual-write の linearizability proof
        （TLA+ refinement）を proof_inventory に登録、
        cutover 期間中の global state monotonicity を Lean
        で program proof
      - tier1 観測可能性（09）→ span causality（parent_
        span_id partial order）の HLC proof（infra16 と
        cross）、sampling boundary の sampling_rate
        invariant proof を Stainless / Lean で
      - tier1 認証（10）→ token state machine の TLA+ safety
        proof（minted → active → refreshed → revoked の
        transition closure）、JWT decoder の Kani memory-
        safety proof
      - tier1 鍵管理（11）→ rotation protocol の TLA+
        refinement proof（KEK → DEK envelope の
        cryptographic invariant）、Shamir distribution の
        threshold property を Lean で number-theoretic proof
      - tier1 schema（12）→ forward / backward compatibility
        の refinement proof、breaking detection の SMT
        decision proof
      - tier1 SLO（13）→ rate limiter の monotonicity SMT
        proof（cap 越え不可能性）、burn rate accumulation
        の Stainless proof、v1_proof_coverage_compliance /
        v1_proof_freshness_compliance / v1_counter_example_
        closure_compliance を SLO として登録
      - tier1 OSS lifecycle（14）→ TLA+ / Apalache / P /
        Stainless / Dafny / Lean 4 / Kani / CBMC の
        v1_l1plus_primary 登録、major version / mathlib
        revision migration の v1_refinement_proof drill
        必須化、framework EoL window は ops 経由で page
      - tier1 capacity（15）→ quota allocation algorithm
        の monotonicity / fairness proof（Stainless / Lean）、
        noisy_neighbor isolation の SMT decision proof
      - tier2 RLS FORCE（32）→ tenant 越境の non-interference
        proof（information flow logic、Stainless / Lean で
        証明、tenant context が tenant boundary を超えない
        ことを query rewriter level で証明）
      - tier3 client（39）→ 4-state machine（fresh / dirty
        / syncing / reconciled）の TLA+ safety proof
        （transition closure）、reconcile_loop の termination
        proof（well-founded ordering）
      - infra topology（infra01）→ failover protocol の
        TLA+ liveness proof（leader 喪失 → 新 leader 選出
        が eventually 成立）、partition 中の split-brain
        impossibility safety proof
      - infra clock（infra16）→ HLC monotonicity proof
        （TLA+ + Lean）、clock skew bound proof
      - data preservation（data01）→ backup-restore lossless
        proof（pre-backup state ⊆ restored state）、
        crypto-erase の cryptographic indistinguishability
        proof（Lean / 自前定理 + 既存 cryptographic library
        引用）
      - security threat（10_security/15）→ 各 threat に対し
        attacker invariant 否定 theorem（safety
        property）を 1:1 bind、threat の new entry が出現
        したら formal 軸の proof_inventory も同 commit で
        更新（双方向 lock）
      - security build_provenance（10_security/17）→ SLSA
        chain monotonicity proof、attestation graph の
        DAG cycle-freeness proof
      - client distribution（12_client/15）→ 5 distribution_
        class 全てに対する SDK adapter equivalence proof
        （Stainless / Lean、language-specific adapter が
        proto spec の意味論 instance）
      - ops loop（11_ops/15）→ 5 signal_class 全ての runbook
        の idempotency / progress / safety proof（同一
        runbook の二重実行が単一実行と同等であること、
        runbook が必ず終端することを TLA+ で）
      - test verification（13_test/15）→ v1_property_axiom
        / v1_type_invariant cell が formal の v1_temporal_
        safety_proof / v1_program_correctness_proof cell と
        cross-cutting に bound、test の seed pool は proof
        の instantiation、proof は test の universal closure

      - 物理 enforcement の道具立て：

■ 19 軸 + meta 中の位置
  - formal は 19 軸目の候補として 00_軸登録適合仕様 の
    meta-registry に entry 追加される（cap v1=20 中 19 /
    20、残 1 余地。ops が 15 軸目、test が 16 軸目、build_
    provenance が 17 軸目、clock_integrity が 18 軸目、
    formal が 19 軸目で全 19 軸が同 cap 内に登録される。
    残 1 枠は v2 拡張（idempotency / lineage / data_
    residency 等）の追加余地）。
  - 18 軸 + security + ops + build_provenance + clock_
    integrity + test が「層別 × 機能別 × 脅威別 × signal
    別 × supply chain 別 × 時刻 / 因果性別 × verification
    実行別」軸であるのに対し、formal は「proof_class 別 ×
    axis 別 × phase 別 × tool 別」軸として直交方向に位置
    する。
    proof_class（temporal_safety_proof / temporal_liveness_
    proof / refinement_proof / program_correctness_proof /
    runtime_modelcheck_proof）を class 軸として持ち、各
    class が 5 phase（specify / model / prove / review /
    archive）の closure を要求する fan-out 構造を持つ。
    formal 軸 proof_matrix.lock.yaml の cell 数は 19 axis
    × 5 proof_class = 95 cell。
  - 00 meta（軸登録）の release_gate.lock.yaml AND-gate
    に、formal の proof_status.lock.yaml の `all_critical_
    verified` 状態 + counter_example.lock.yaml の `no_open_
    above_severity_low` 状態 + proof_review.lock.yaml の
    `dual_review_completeness=100%` 状態が入力される。
    全 (axis × proof_class) cell の proof_status が
    {verified, accepted_with_assumption} でない限り、
    または counter-example が high severity で open 残存
    する限り 1.0.0 ship blocker。

■ 至高路線における位置づけの帰結
  - formal は「個別軸の規律を再宣言する layer」ではなく、
    「個別軸の規律から発生する critical invariant が proof
    matrix で必ず closure される」ことを machine-checkable
    に保証する meta-meta-layer。
  - 運用コスト度外視（CLAUDE.md 上位方針）の哲学に従い、
    proof coverage は最大化する。「実行 test で十分なはず
    だから formal を書かない」「proof は時間がかかるから
    一部 critical invariant を諦める」判断は採らない。
    proof_obligation entry 自体は省略しない。重い proof は
    Lean / Stainless 上の長時間 run + Tekton Pipeline 大型
    runner で吸収。
  - 1.0.0 完璧 release：5 proof_class 全てに対し全 19 軸の
    cross-axis proof closure（5 phase 全 verified）、
    proof matrix 全 cell が verified or accepted_with_
    assumption（assumption 文書化済）、counter-example
    quarterly closure（high severity 0、medium severity
    decreasing monotonic）、proof reviewer dual sign-off
    100%、までを ship blocker とする。
  - 1.0.0 以降の v2 拡張ルール：proof_class 数は固定（5）、
    axis 拡張は 00 meta cap v2=25 への移行で +5、proof_
    obligation の追加は purely additive（既存 obligation の
    意味変更は新 theorem 名で表現）。
