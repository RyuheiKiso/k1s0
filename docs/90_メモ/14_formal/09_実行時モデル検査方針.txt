============================================================
formal 実行時モデル検査方針（v1_runtime_modelcheck_proof）
============================================================

■ 一文方針
  - v1_runtime_modelcheck_proof は、各軸の実装コード
    （Rust / C / C++）に対し bounded model checking を
    Kani（Rust）/ CBMC（C / C++）で起動し、memory safety /
    parser closure / overflow / concurrency safety / SMT-
    based property を machine-checkable に検査する proof_
    class であり、実装 binary に proof certificate が bind
    されることを物理 enforce する。

■ 担当 proof_class
  - v1_runtime_modelcheck_proof：
      - 意味論：「実装コードを SMT に lowering して bounded
        depth で symbolic execution、未定義動作 / panic
        / overflow / race / data structure invariant
        violation の不存在を bound 内で証明」
      - artifact：Kani .rs harness + .json report / CBMC
        .c harness + .xml + .json report、bound parameter
        は kani_cbmc_pin.lock.yaml で固定
      - cadence_class：v1_per_module_change_or_weekly、
        cadence_days = 7
      - artifact_class：v1_runtime_modelcheck_certificate
      - orchestrator_preference：kani_cbmc_pipeline /
        proof_gate_kyverno
      - coverage_weight：1.0
      - 対応する drill_class：kani_module_check_drill /
        cbmc_module_check_drill / bound_parameter_review_
        drill
      - primary defense_layers：kani_cbmc_pipeline /
        proof_gate_kyverno
      - 最低限の cross-axis：07 transport / 10 auth / 11
        key / 12 schema / 15 capacity / 32 data-tenant /
        infra01 topology / infra16 clock
      - active cell 数（v1 cap）：14（Rust / C / C++ 実装が
        存在する軸のみ）

■ tool の住み分け
  - Kani（Rust 実装）：
      - 担当：tier1 Server / Library の Rust 実装、infra
        components の Rust 実装、tier2 の Rust 実装、tier3
        の Rust 実装
      - 主要 obligation：memory safety（unsafe block の
        soundness）、parser closure（malformed input への
        反応）、overflow safety、concurrency safety
        （Loom 補助で thread interleaving）
  - CBMC（C / C++ 実装）：
      - 担当：infra eBPF program、HSM driver C 実装、
        kernel module、PTP daemon C 実装、chrony driver、
        legacy native component
      - 主要 obligation：memory safety、buffer overflow、
        null dereference、concurrency safety（pthread）

■ bound parameter の規律
  - bound parameter（unwind / object-bits / loop iteration
    count / SMT timeout）は kani_cbmc_pin.lock.yaml で
    固定、proof artifact の reproducibility に直結。
  - bound 値の選択：
        - unwind：loop の理論上 max iteration を upper
          bound として設定、上限を超える可能性のある loop
          は v1_program_correctness_proof 側で termination
          metric として handle
        - object-bits：heap allocation の bit precision、
          実機構の word size に合わせる（64-bit）
        - SMT timeout：30 min/module を default、長時間
          run は別 Pipeline で night batch
  - bound 値の引き上げ要望は drill 経由で評価、引き上げ
    PR は dual review。

■ 各軸の代表 runtime modelcheck obligation

  - 07 transport（Kani）：
      - FrameDecoderMemorySafety：bidi frame decoder の
        Rust 実装が malformed frame に対し panic / UB
        無く反応
      - HeaderParserClosure：HTTP/2 / HTTP/3 header
        parser の closure（任意 input で必ず Ok / Err 返却）

  - 10 auth（Kani）：
      - JWTDecoderMemorySafety：JWT decoder の Rust 実装
        が malformed JWT に対し panic / UB 無く反応
      - SignatureVerificationClosure：JWS signature
        verification function の closure

  - 11 key（Kani / CBMC）：
      - EnvelopeDecryptionDecision：DEK envelope
        decryption decision logic の Kani proof
      - HSMDriverMemorySafety：HSM driver の C 実装の
        CBMC proof

  - 12 schema（Kani）：
      - BufBreakingImpl：buf-breaking decision の Rust
        実装が schema-evolution rule に従い正しく決定

  - 15 capacity（Kani）：
      - QuotaCounterOverflowSafety：quota counter の Rust
        実装が overflow しない（i64 overflow guard）
      - RateLimiterImpl：rate limiter の Rust 実装の
        memory safety + monotonicity

  - 32 data-tenant（Kani）：
      - QueryRewriterMemorySafety：query rewriter の Rust
        実装が malformed SQL に対し panic 無く反応
      - RLSPolicyEnforcementImpl：RLS policy enforcement
        の Rust 実装が tenant boundary を超えない

  - infra01 topology（CBMC / Kani）：
      - eBPFProgramSafety：infra01 が使う eBPF program の
        verifier-passing + CBMC bound check
      - LeaderElectionImpl：leader election の Rust 実装
        の memory safety + concurrency safety

  - infra16 clock（CBMC / Kani）：
      - PTPDaemonMemorySafety：PTP daemon の C 実装
      - ChronyDriverMemorySafety：chrony driver の C 実装
      - HLCImplCorrectness：HLC update の Rust 実装の
        Kani proof

  - data01 preservation（Kani）：
      - BackupSerializerMemorySafety：backup serializer
        の Rust 実装

  - security15 threat（CBMC）：
      - SyscallFilterEBPFSafety：syscall filter eBPF
        program の CBMC proof

  - security17 build_provenance（Kani）：
      - SLSAVerifierMemorySafety：SLSA verifier の Rust
        実装

  - client15 SDK distribution（Kani）：
      - SDKAdapterMemorySafety：5 distribution_class の
        Rust 系 SDK adapter

  - test15 verification（Kani）：
      - CoverageMatrixGeneratorMemorySafety：coverage
        matrix generator の Rust 実装

  - ops15 loop（Kani）：
      - RunbookExecutorMemorySafety：runbook executor の
        Rust 実装

  - formal（自軸）：
      - ProofRunnerMemorySafety：proof runner の Rust
        実装の self-host proof

■ workflow
  - specify：軸 spec の formal_obligations 段落で runtime
    modelcheck obligation を module 名 + entry point +
    bound parameter で宣言
  - model：Kani の `#[kani::proof]` annotation または
    CBMC の harness ファイルで bounded harness を書く
  - prove：Tekton Pipeline で Kani / CBMC を起動、bound
    parameter sweep で SMT solver discharge
  - review：dual reviewer sign-off、bound 値の妥当性 review
  - archive：proof certificate + bound parameter +
    SMT solver version を proof_status.lock.yaml に
    fingerprint

■ Loom（concurrency model checker）の補助利用
  - Rust の concurrency safety は Kani 単独では sweep が
    弱いため、Loom（thread interleaving model checker）
    を補助的に利用。
  - Loom の利用は v1_runtime_modelcheck_proof の補助
    artifact、primary は Kani。Loom が独立軸 OSS として
    14 OSS-lifecycle に登録されるかは v2 検討。

■ Miri（unsafe block の interpreter）の補助利用
  - Kani が cover しない unsafe block の dynamic check は
    Miri を補助的に利用、test/15 軸の v1_property_axiom
    と co-bind。
  - Miri は test 軸 OSS、本軸では「補助 driver」扱い。

■ 採用しない設計
  - SPARK Pro / Frama-C / Verifast は採用しない。
  - 直接 SMT solver invocation 不可。
  - bounded を超える depth の analysis は v1_program_
    correctness_proof 側に投影（Stainless / Dafny / Lean
    で unbounded proof）。
  - bound 値の頻繁な引き下げ：禁止、bound 引き下げ PR は
    counter-example detect の可能性として CI alert。

■ CI 不変条件（v1_runtime_modelcheck_proof 担当部分）
  - 整合 1：proof_inventory.lock.yaml の全 v1_runtime_
    modelcheck_proof entry が module_name + tool_kind +
    entry_point + bound_parameter + statement_hash 完備
  - 整合 2：全 v1_runtime_modelcheck_proof cell の last_
    verified_at が cadence_days=7 以内
  - 整合 3：counter_example.lock.yaml の v1_runtime_
    modelcheck_proof entry が close_due_at 以内に closure
  - 整合 4：kani_cbmc_pin.lock.yaml の Kani / CBMC
    version + bound_parameter が pin 済み、bound 引き下げ
    PR は dual review
  - 整合 5：generator output と手書き drift = 0
