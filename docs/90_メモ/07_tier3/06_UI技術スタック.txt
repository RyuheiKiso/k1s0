============================================================
tier3 の UI 技術スタック
============================================================

■ 方針
  - UI 技術スタックは tier3 の責務であり、tier2 / tier1 の領分
    ではない（「06_tier2/17_非提供スコープ」UI / 画面節と整合）。
  - 同一の業務 pack を消費する複数 tier3 で UI 技術が ad-hoc に
    分裂しないよう、本ファイルが「既定 / 許容 / 採用禁止」を
    明示する。
  - 採用禁止扱いとなる「レガシー UI 技術」（IE 専用 ActiveX / 古い
    WebForms / Silverlight 等）は新規採用しない（後述「採用禁止
    扱い」節参照）。既存資産は「36_レガシー資産統合」の経路で
    扱う。

■ Web SPA フレームワーク
  - 既定：TypeScript + React。
      - 採用理由：tier2 Library SDK の TypeScript 提供（「06_
        tier2/12_言語スタック」）に対するエコシステム親和性、
        ジュニア層を含む採用要員確保の容易さ、長期メンテに耐え
        るコミュニティ規模。
  - 許容：Vue / Svelte。
      - 採用要件：tier3 単位で他フレームワークと混在しないこと。
        共通コンポーネントライブラリ（後述）との互換ラッパが
        既に提供されていること。
  - 選定基準 :
      - 業務 UI の要件（複雑な一覧 / フォーム / 大量データ可視
        化）への適性。
      - tier2 SDK の TypeScript 型をそのまま受けられること。
      - 共通コンポーネントライブラリの当該フレームワーク向け
        提供があること。
      - 長期メンテ（フレームワークのライフサイクル / LTS 状況）。
  - 採用禁止：レガシー UI 技術（後述）。

■ 状態管理ライブラリ（クライアント側）
  - tier3 のクライアント状態は「08_状態管理」と整合する。
  - 既定 :
      - サーバ状態同期 : TanStack Query（React Query）相当の
        非同期状態キャッシュ。tier2 Service への問い合わせは
        ここで一元化する。
      - クライアント UI 状態 : 局所状態は React の useState /
        useReducer。横断状態は Zustand / Jotai 等の軽量 store。
  - 採用禁止 :
      - tier3 内で「永続データの正解」を持つことは禁止
        （「08_状態管理」参照）。
      - サーバ状態とクライアント状態を混ぜて管理する大規模
        store の採用は避ける。

■ スタイリング
  - 既定：utility CSS（Tailwind CSS）+ 共通コンポーネントライブ
    ラリの design token を CSS variables で受ける。
  - 許容：CSS Modules / CSS-in-JS（Stitches / Vanilla Extract 等）。
    ただし共通コンポーネントライブラリと同居可能なものに限る。
  - 採用禁止 :
      - グローバル CSS の tier3 横断的な持ち回り。
      - design token を介さない直接の色 / フォント指定。
  - デザインシステム（「09_デザインシステム」）と整合する。

■ レンダリング戦略
  - 既定：CSR（Client Side Rendering）。
      - 採用理由 : tier3 業務 UI は認可がリクエスト単位で動的、
        SEO 不要、認証必須、テナント識別子に依存する画面構成。
        SSR / SSG の利点が業務 UI の要件と合致しない。
  - 許容：限定的な SSR（Server Components 等）を、tier3 リポジ
    トリ単位で初期表示要件がある場合に採用してよい。ただし :
      - 認可判定は tier2 経由で行う。SSR ノードが tier1 / OSS に
        直接接続することは禁止する（「02_位置づけ」と整合）。
      - tier2 Service への問い合わせは Gateway 経由で行う。
  - 採用禁止 :
      - SEO 目的の SSG（業務 UI は基本的にインデックス対象外）。
      - 認証前のユーザに業務データを露出する経路。

■ デスクトップ exe フレームワーク
  - Windows 限定（社内固定環境）:
      - C# WPF または WinUI 3 を既定とする。
      - tier2 Library（NuGet package）を直接消費する。
  - クロスプラットフォーム（Windows / macOS / Linux）:
      - C# Avalonia または .NET MAUI を既定とする。
      - Rust + Tauri も許容する（UI は WebView 上 TypeScript +
        共通コンポーネントライブラリ）。
  - 選定基準 :
      - 端末 OS の固定度。
      - tier2 Library の言語（C# / Rust）への親和性。
      - UI 共通コンポーネントの再利用性（Tauri は Web SPA と
        共通コンポーネントを共有できる利点がある）。
  - 採用禁止 :
      - WinForms 新規採用（既存資産の移行段階で残す場合のみ。
        「36_レガシー資産統合」参照）。
      - Electron（プラットフォーム標準として採用しない。Tauri
        を選ぶ）。

■ レガシー .NET Framework での UI
  - 対象：.NET Framework 4.6.2+ 上で動作する tier3。
  - 許容：WinForms / WPF（既存資産尊重）。
  - 既定方針 :
      - 既存資産の段階的移行・並行運用が要件のテナント向けで
        あり、新規 tier3 を一から作る場合はクロスプラットフォ
        ームのデスクトップ exe を推奨する（「04_アプリケーショ
        ン形態」と整合）。
      - tier2 への接続は Companion + Gateway 経由 tier2 Service
        に固定。Library 直接組込は不可（「05_言語スタック」と
        整合）。
  - 採用禁止 :
      - IE 専用 ActiveX / 古い WebForms（Web Forms .aspx）/
        Silverlight 等のレガシー UI 技術の新規採用。

■ 共通コンポーネントライブラリ
  - tier3 横断のデザインシステム実装を別 package（npm /
    NuGet / crate）として配布する。
  - 内容 :
      - 業務 UI で頻出するコンポーネント（Button / Form フィー
        ルド群 / Table / Modal / Toast / Banner / Wizard 骨格 /
        日付・時刻入力 / 通貨入力 / バーコード入力補助 等）。
      - design token（色 / typography / spacing / shadow / motion）。
      - アクセシビリティの既定実装（フォーカス管理 / キーボード
        操作 / ARIA 属性。「21_アクセシビリティ国際化」参照）。
      - 国際化基盤（i18n catalog のロード / 数値・日付フォーマット）。
  - 配布形態 :
      - Web SPA 向け : npm package（React / Vue / Svelte の
        フレームワーク別 entrypoint）。
      - C# WPF / WinUI 3 / Avalonia 向け : NuGet package。
      - Tauri / Web SPA 共通の WebView 想定 : 上記 npm package
        を共用する。
  - 配布先：tier1 / tier2 と同じ内部パッケージリポジトリに固定
    する（「05_tier1/04_Library」強制機構層 3 と整合）。

■ バンドラ / ビルドツール
  - Web SPA :
      - 既定：Vite。許容：Turbopack 等の同等 SSR / Bundler。
  - デスクトップ exe（C#）:
      - 既定：dotnet publish（self-contained）。
  - Tauri :
      - フロント：Vite。アプリ本体：cargo + Tauri CLI。
  - レガシー (.NET Framework) :
      - msbuild。
  - 詳細は「34_配布デプロイ運用」参照。

■ 採用禁止扱い（レガシー UI 技術）
  - 新規採用を禁止する技術 :
      - IE 専用 ActiveX。
      - Web Forms（.aspx / postback ベースの古い ASP.NET）。
      - Silverlight。
      - Flash / Shockwave。
      - jQuery を主軸とする UI 構築（補助スクリプトとしての利用
        も避ける）。
  - 既存資産が上記に該当する場合は「36_レガシー資産統合」の経路
    で扱う。新規 tier3 では本節の既定 / 許容スタックから選ぶ。

■ 1.0.0 出荷時の対応範囲
  - Web SPA : TypeScript + React + Tailwind + Vite + 共通
    コンポーネントライブラリ（npm）。
  - デスクトップ exe : C# WinUI 3（Windows 固定）/ C# Avalonia
    （クロスプラットフォーム）/ Rust + Tauri を出荷時の選択肢
    として揃える。
  - レガシー : C# WinForms / WPF（既存資産併存テナント向け）。
