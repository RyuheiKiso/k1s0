============================================================
tier3 の検索 / 一覧 UX
============================================================

■ 方針
  - tier2 の wire 仕様（「06_tier2/18_API設計規約」）に従い、
    一覧 / 検索 UI は cursor pagination を前提に設計する。
    offset 表現（ページ番号 / 件数オフセット）は UI からも禁止
    する（大規模データでの重複・欠落・性能劣化を回避するため）。
  - 検索条件は URL にシリアライズし、ディープリンク・共有・
    ブラウザ戻るが業務操作として成立することを既定とする
    （「11_画面遷移ルーティング」整合）。
  - サーバ確定の結果のみを真とし、クライアント側で勝手な
    並べ替え / 集計を行わない（cursor pagination の整合性を
    壊すため）。

■ 一覧形態の選定
  - 無限スクロール（infinite scroll）:
      - 採用条件：時系列の流し読み用途、件数を意識せず探す
        業務（通知履歴 / 監査自身分操作履歴 / 活動 feed）。
      - 例：自身の操作履歴一覧、関与中 Workflow 一覧。
  - ページャ（cursor 前後 / next-prev）:
      - 採用条件：1 件の確認 → 戻る → 別の 1 件、という
        「閲覧して戻る」業務（発注一覧 → 発注詳細 → 戻る）。
      - 「○件中 ○-○件」の総件数表示は禁止する（cursor
        pagination では正確な総件数が取れないため。概算が
        必要なら明示的に「概算」と表記する）。
  - ハイブリッド:
      - 採用条件：通常はページャ、ユーザ要求で「もっと表示」
        を押した時のみ追記読込。多くの業務一覧の既定とする。
      - 例：発注一覧 / 検査結果一覧 / 仕入先一覧。

■ フィルタ UI
  - 多面フィルタ（faceted filter）:
      - tier2 の検索 API が宣言する filter 軸（status / 期間 /
        担当 / 拠点 / 品目カテゴリ等）を UI に展開する。
      - 各 facet の候補値・件数（概算可）はサーバから取得し、
        クライアント定数化しない（マスタ変更で UI が腐るため）。
  - 範囲指定:
      - 期間 / 数量 / 金額の範囲フィルタは start / end 両方
        optional で受け、片側のみの指定も成立させる。
      - タイムゾーンは「21_アクセシビリティ国際化」表示規約に
        従い、wire は ISO 8601 + offset で送信する。
  - 業務エンティティ参照:
      - 仕入先 / 担当 / 品目 等のフィルタはピッカー UI（検索
        付きセレクト）で選ばせる。フリーテキスト ID 直打ちは
        既定 UI から除く（補助としての許容は可）。

■ 保存検索（saved view）
  - 個人 saved view: 自身のみが利用する検索条件 + 列構成 +
    ソート。クライアント永続化と tier2 経由のサーバ永続化を
    両方提供する（「08_状態管理」永続化節と整合）。
  - チーム共有 saved view: tier2 の業務 API（業務横断の view
    管理 API、業務語彙では「業務ビュー」）経由で共有する。
    共有範囲は ABAC で判定する（「18_権限UI制御」整合）。
  - saved view の URL シリアライズは個人 view と同じ形式で
    成立させる（共有は URL 共有でも成立する）。

■ 列カスタマイズ
  - 表示項目 / 順序 / 幅 / ピン留めはユーザ操作で変更可能と
    し、変更を永続化する（「08_状態管理」整合）。
  - 永続化先：
      - 個人ローカル（localStorage / IndexedDB / OS keychain）
      - tier2 経由のサーバ保存（複数端末同期 / 端末入れ替え
        対応）
      - いずれを既定にするかはアプリで宣言。混在時はサーバ
        側を真とし、ローカルは cache とする。
  - 列定義のスキーマは tier2 SDK の生成型に従う。tier3 が
    独自に列を発明しない（業務語彙の腐敗を防ぐ）。

■ ソート
  - server-side ソートのみ採用する。client sort は禁止する
    （cursor pagination と組合せると欠落・重複が発生する
    ため）。
  - 複合ソート（複数キー）は tier2 が宣言した組合せのみを
    UI から指定可能とする（任意組合せは index 設計を破綻
    させる）。
  - ソート反転（asc / desc）の UI 表現は列ヘッダクリック
    トグルを既定とする。

■ 仮想スクロール（virtualization）
  - 数百件以上を扱う一覧は仮想スクロールを既定とする。
  - 行高は固定または計測キャッシュを採用し、可変行高で
    スクロール位置がずれることを避ける。
  - 仮想スクロールでもアクセシビリティ要件（screen reader /
    キーボード操作）を維持する（「21_アクセシビリティ国際化」
    整合）。

■ 一括選択 / 一括操作
  - 業務 UI からは原則非提供とする。一括 select / 一括 action
    は業務管理 UI 側のスコープとする（「03_非提供スコープ」
    「26_業務管理UI境界」「28_運用UI」整合）。
      理由：業務 UI で bulk 操作を許すと、業務不変条件 /
      認可境界の見落としが起きやすく、監査痕跡も曖昧になる。
  - 例外：自身が起票した Draft の一括破棄など、認可・監査が
    自明な範囲に限り、tier2 が bulk API を宣言した時のみ
    提供する。

■ 状態表示
  - 空状態（empty）:
      - 検索結果 0 件か、母集団 0 件かを区別して表示する。
      - 0 件時は「条件を緩める」「新規作成」など次アクションを
        示す（「10_UX原則」次アクション提示節と整合）。
  - エラー状態:
      - tier2 業務エラーは「19_業務エラーUX」に従う。
      - システム失敗時は再試行ボタン + サポート問合せ導線。
  - 部分結果状態:
      - 検索が時間切れ（deadline）で部分結果しか返らない場合、
        その旨を明示し、絞込み or 再試行を促す。

■ latency と UX
  - tier2 の業務 API SLO（「06_tier2/27_信頼性運用準備」p95 <
    200ms / p99 < 500ms）を前提に、200ms を超える待機が
    予想される操作にはスケルトン表示・スピナーを出す
    （「10_UX原則」整合）。
  - 検索送信は debounce（既定 250ms）し、入力中 RPC 連射を
    避ける。debounce 中の前回結果は灰色表示などで「確定前」
    を示す。

■ 全文検索 / 類似検索 / vector search の UI 表現
  - 「06_tier2/24_読み取りモデル方針」検索節と整合させる。
      - 部分一致 / 類似度（pg_trgm）: 既定の文字列検索 UI。
        ハイライト表示で一致箇所を示す。
      - 全文検索（tsvector）: 業務文書 / コメント検索。
        スニペット表示と一致語ハイライトを既定とする。
      - 意味検索（pgvector）: 「類似する不良票」「類似品目」
        等、tier2 が業務語彙で公開した範囲のみを UI に出す
        （「品目検索一般を意味検索化」のような勝手な置換は
        禁止する）。
  - 検索方式の切替は明示的なタブ / トグルで提示し、結果の
    意味（完全一致 / 類似 / 意味）を業務語彙で説明する。

■ 検索条件の URL シリアライズ
  - filter / sort / saved view ID / page_token を URL の
    query string にシリアライズする。
  - page_token は opaque（「06_tier2/18_API設計規約」cursor
    節）として扱い、UI 側で中身を解釈しない。
  - URL 長制限（ブラウザ・サーバ）に近づく場合、saved view
    化を促す UI に切替える（フィルタ条件の URL 直記述に
    依存しない）。
  - ブラウザ「戻る」で前の検索状態に戻れることを担保する
    （「11_画面遷移ルーティング」整合）。
