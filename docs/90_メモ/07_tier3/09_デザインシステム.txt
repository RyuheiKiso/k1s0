============================================================
tier3 のデザインシステム
============================================================

■ 方針
  - tier3 横断で統一されたデザインシステムを 1.0.0 出荷時に提供
    する。各 tier3 アプリが独自にコンポーネントを再実装すること
    を禁止する（一貫性 / アクセシビリティ / 業務 UX の質を担保
    するため、「10_UX原則」整合）。
  - デザインシステムは tier3 共通 package（npm / NuGet / crates.io
    内部 registry）として配布する。配布形式は「34_配布デプロイ
    運用」整合。
  - tier2 と同じ互換性ポリシー（SemVer、major version up は並行
    運用期間あり）を適用する（「30_互換性ポリシー」整合）。
  - 業界 pack / テナント別カスタマイズは「既定値の差替え」のみを
    認め、コンポーネント構造の差替えは禁止する（業務 UX の一貫性
    を破壊しないため）。

■ デザイントークン
  - カテゴリ :
      - カラー : 基本パレット / 状態色（success / warn / error /
        info）/ 背景 / 前景 / アクセント。
      - タイポグラフィ : フォントファミリ / サイズスケール /
        行間 / 文字間 / weight。日本語 / 英語 / RTL を意識した
        サイズ調整トークン（「21_アクセシビリティ国際化」整合）。
      - スペーシング : 4px ベースの 8 段階スケール。
      - 影 : 0〜5 段階の elevation。
      - 角丸 : 0 / sm / md / lg / pill の 5 段階。
      - モーション : duration / easing。WCAG 2.1 AA prefers-reduced
        -motion に従う。
  - トークンは設計ファイル（Style Dictionary 等）を単一の真とし、
    各言語のスタイル定義（CSS Custom Properties / SCSS 変数 /
    XAML resource / Rust 定数）を生成する。手書きで複製しない。
  - テナント別ブランディング override 可（「37_業務カスタマイズ
    粒度」整合）。override 範囲はカラー / タイポ / 影 / 角丸の
    既定値差替えに限る。スペーシングスケールの差替えは禁止
    （レイアウト崩れ防止）。

■ 共通コンポーネント
  - 1.0.0 出荷時の必須コンポーネント :
      - Button（primary / secondary / danger / ghost）
      - Input（text / password / number / decimal）
      - Select / Combobox
      - DatePicker / TimePicker / DateTimePicker
      - Table（仮想化 / ソート / 列固定対応）
      - Modal / Drawer / Popover
      - Toast / Banner（業務エラー banner は専用、後述）
      - Stepper / Wizard
      - Form（Section / FieldGroup / Field）
      - Tabs / Accordion
      - Pagination（cursor-based。「13_検索一覧UX」整合）
      - Breadcrumb（「11_画面遷移ルーティング」整合）
      - Spinner / Skeleton / EmptyState / ErrorState
      - Checkbox / Radio / Switch / Slider
      - Tooltip / HelpText
      - FileUpload / AttachmentPreview（「20_添付帳票UX」整合）
  - すべて WCAG 2.1 AA 準拠を既定として組込む（「21_アクセシビリ
    ティ国際化」整合）。focus visible / aria-* / keyboard 操作 /
    contrast を default で満たす。

■ アイコン体系
  - 統一アイコンセット（Material Symbols / Phosphor 等から 1 つ
    を選定）を採用し、独自イラスト化は禁止する。
  - 業務語彙対応のドメインアイコン :
      - 状態（Draft / Confirmed / Cancelled / PendingApproval /
        Expired）に対応するアイコンを統一定義（「14_状態遷移UI」
        整合）。
      - 業界 pack 別のドメインアイコン（製造業：設備 / ロット /
        検査 / 発注 等）を業界 pack ごとに専用パッケージで提供。
  - サイズ : xs / sm / md / lg / xl の 5 段階。pixel 値は固定
    （px ベース）。
  - 色 : currentColor 既定。色のみで状態を伝えないこと（WCAG 1.4.1
    整合、「21_アクセシビリティ国際化」整合）。

■ 状態バリアント
  - 全インタラクティブ要素が以下の状態を network 等価に表現する :
      - default
      - hover（マウス / トラックパッド）
      - focus（キーボードフォーカス、focus-visible 区別）
      - active（押下中）
      - disabled
      - error
      - loading（spinner inline / skeleton）
      - readonly
  - 状態組合せの優先順位 : disabled > readonly > error > loading >
    focus > hover > active > default。
  - 状態色のコントラスト比は WCAG 2.1 AA を最低基準（テキスト
    4.5:1、UI 部品 3:1）。テナント override で要件未達の組合せが
    生じた場合は build 時 fail（「31_強制機構」整合）。

■ 業務 UI 特有のコンポーネント
  - 状態バッジ : Draft / Confirmed / Cancelled / PendingApproval /
    Expired を統一表示する Badge コンポーネント。tier2 状態 enum
    との 1:1 対応（「14_状態遷移UI」「06_tier2/19_状態遷移
    パターン」整合）。
  - 業務エラーバナー : DomainError / ValidationError /
    BusinessConflict / AuthorizationDenied を区別して表示する
    専用コンポーネント。recovery_hints を表示する slot を持つ
    （「19_業務エラーUX」「06_tier2/18_API設計規約」エラーレス
    ポンス形式整合）。
  - 認可ロック表示 : ABAC 結果で操作不可の要素を「ロック」表示
    する。tooltip に拒否理由（業務語彙）を表示（「18_権限UI制御」
    整合）。grey-out のみで理由を示さない実装は禁止。
  - 添付プレビュー : 画像 / PDF / Office 文書 / CAD 等のプレビュー
    と業務帳票（請求書 / 検収票 / 検査票）の表示（「20_添付帳票
    UX」整合）。
  - 楽観更新インジケータ : 楽観値を表示中であることを示す
    inline indicator（「08_状態管理」楽観更新節整合）。
  - 多段承認ステッパ : 承認 step の進行状況を表示（「14_状態遷移
    UI」「06_tier2/19_状態遷移パターン」Approval Workflow 整合）。
  - 通知センター : Toast queue / Banner / 通知履歴一覧（「17_
    通知UI」整合）。
  - LRO progress : Long-running operation の進捗表示（「15_非同期
    処理UX」「06_tier2/18_API設計規約」LRO 整合）。

■ バージョニング
  - SemVer。tier2 と同じ互換性ポリシー（「30_互換性ポリシー」
    整合）。
  - major version up :
      - コンポーネント API 破壊的変更 / トークン削除 / 構造変更を
        含む。
      - 並行運用期間（既定 6 ヶ月）に新旧 major を共存させる
        （tier3 アプリの段階的移行）。
  - minor version up : コンポーネント追加 / トークン追加 /
    既定値の非破壊変更。
  - patch : バグ修正 / アクセシビリティ改善 / 内部実装。

■ 配布
  - tier3 横断の package として配布する :
      TypeScript : npm 内部 registry（@k1s0/design-system）
      C#         : NuGet 内部 feed（K1s0.DesignSystem）
      Rust       : 内部 cargo registry（k1s0-design-system）
  - tier1 の内部パッケージリポジトリ方針（「05_tier1/04_Library」
    強制機構 層 3）と整合させる。OSS UI ライブラリの直接 import
    を tier3 で禁止し、デザインシステム経由のみとする。
  - Storybook（または各言語等価物）でカタログを公開し、Backstage
    TechDocs から参照可能とする（「35_開発者体験」整合）。

■ Visual regression test
  - 全コンポーネントに visual regression test を必須化する
    （「29_テスト方針」整合）。Chromatic / Playwright 等で
    実行する。
  - tier3 アプリ側のテーマ / トークン override 適用後の見た目も
    visual regression で守る（テナント別ブランディング差替えで
    崩れないことを保証）。
  - 差分検出時は merge を fail にする。視覚回帰の検査を運用判断
    に依存させない。

■ ダーク / ライトテーマ
  - 既定はライトテーマ。ダークテーマを 1.0.0 で同等に提供する。
  - 切替はユーザー設定（OS 設定追従 / 手動切替）。設定は
    localStorage に保持（「08_状態管理」永続化整合）。
  - 全コンポーネント / 業務専用コンポーネントが両テーマで visual
    regression を通過することを merge 条件とする。

■ 業界 pack 別カスタマイズ範囲
  - 許可 :
      - デザイントークンの既定値差替え（カラー / タイポ等）
      - 業界専用ドメインアイコンの追加
      - コンポーネントの slot に対する業界専用 placeholder の差替え
  - 禁止 :
      - コンポーネント構造の差替え（DOM / XAML 木の改変）
      - WCAG 2.1 AA 要件を満たさない override
      - スペーシングスケールの差替え
      - 状態バリアントの削除
  - override 範囲は YAML で宣言し、CI で実装に対し検査する
    （「31_強制機構」整合）。
