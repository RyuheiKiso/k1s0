============================================================
tier3 の UX 原則
============================================================

■ 方針
  - tier3 は「企業内の業務担当が高頻度・長時間使う業務 UI」で
    あることを前提とする。一般消費者向けの WebサービスやSaaS
    landing page と同じ UX 原則を持ち込まない。
  - 一貫性 / 効率 / 安全性 / アクセシビリティを最上位に置き、
    美観や流行は二次とする。
  - 業務担当の作業ロスを最小化することを「至高の業務 UX」と定義
    する（「CLAUDE.md」運用コスト度外視・技術者として至高 整合）。

■ 業務 UI の前提
  - 高頻度 : 1 日数百〜数千の操作（フォーム入力 / 一覧操作 /
    画面遷移）が連続する。
  - 長時間 : 8 時間連続使用が常態。眼精疲労 / 集中力低下を考慮
    する。
  - 高密度 : 1 画面に多数のフィールド / 列 / ステータスを表示
    する必要がある（業務文書を 1 画面で完結させる要請）。
  - キーボード優先 : 業務担当はマウス操作より高速なキーボード
    操作を望む。テンキー入力 / Tab 移動 / ショートカット中心。
  - 監査前提 : 全操作が監査ログ対象（「06_tier2/14_業務エラー
    監査コンプライアンス」整合）。誤操作のリカバリ / undo の
    扱いを明示する。

■ 一貫性 > 美観
  - 同じ操作は同じ場所・同じラベル・同じ挙動で提供する。
      例：保存ボタンは画面右下、ラベルは「保存」、shortcut は
          Ctrl+S（Windows）/ Cmd+S（macOS）。tier3 アプリ間で
          ずらさない。
  - 業界 pack / テナントごとに「保存」を「確定」「登録」に変える
    のは禁止する。tier2 の業務語彙（Draft / Confirmed / Cancelled
    等）を UI 文言にそのまま使う（後述「認知負荷削減」整合）。
  - デザインシステム経由のコンポーネント以外を使わない（「09_
    デザインシステム」整合）。アプリ独自のボタン / フォームを
    手書きしない。

■ フィードバック原則
  - 操作開始 100ms 以内に視覚的反応 :
      - クリック / タップで pressed 状態を表示。
      - フォーム送信ボタンは即座に loading 状態へ遷移。
  - 1s 以内に進捗表示 :
      - spinner / skeleton / プログレスバー。
      - 何が進行中か業務語彙で表示（「発注を確定中」など）。
  - 3s 超は LRO 扱い :
      - tier2 業務 API の LRO 形態（「06_tier2/18_API設計規約」
        LRO 節）に従い、operation_id を取得し進捗ページ / バナー
        で表示する（「15_非同期処理UX」整合）。
      - 「処理中ですしばらくお待ちください」と書いて画面を blocking
        modal で固める実装は禁止（業務担当を拘束しない）。

■ 確認モーダル濫用禁止
  - 確認モーダルは「破壊的かつ undo 不能」な操作のみに限定する。
      例：テナント削除 / 監査ログ purge / 大量データ一括削除。
  - undo 可能な操作は undo を優先する :
      - 削除直後に「元に戻す」toast を 10 秒間表示（「17_通知UI」
        整合）。
      - 状態遷移（Confirmed → Cancelled 等）も undo 可能なら
        undo 提示。tier2 の Cancelled / Modified パターン
        （「06_tier2/19_状態遷移パターン」整合）と接続する。
  - 「保存しますか？」の二重確認は禁止。1 クリックで保存できる
    こと。

■ ロード / 空 / エラー / 部分失敗の網羅
  - 全データ表示画面で以下 4 状態を必ず実装する :
      - loading : skeleton / spinner。3s 超は LRO 化。
      - empty : 業務語彙で「まだ発注がありません」「該当する
        検査結果がありません」等を表示。検索条件の見直し / 新規
        作成への導線を提示。
      - error : DomainError / ValidationError / BusinessConflict
        / AuthorizationDenied を区別して提示（「19_業務エラー
        UX」整合）。
      - 部分失敗 : 一覧の一部が取得失敗した場合、取得済み分は
        表示し失敗分を inline で示す（全画面エラーで暗転させ
        ない）。
  - 4 状態は visual regression test の対象とする（「09_デザイン
    システム」「29_テスト方針」整合）。

■ 認知負荷削減
  - 不要な選択肢を出さない :
      - 認可で許可されない操作はそもそも UI に出さない（「18_権限
        UI制御」整合）。grey-out よりも非表示を既定とする。ただし
        操作位置の一貫性を壊さないため、レイアウト上の隙間として
        は残す。
      - 業界 pack で使わない機能は features の dead-code 除去で
        bundle にも含めない（「34_配布デプロイ運用」整合）。
  - tier2 の業務語彙をそのまま UI 文言に使う :
      - tier2 が「発注 (PurchaseOrder)」なら UI も「発注」。
      - tier3 ごとに「購買オーダー」「発注書」とずらさない。
      - 業務語彙は tier2 が一元管理する用語集（業界 pack 単位）
        を i18n 翻訳キーで参照する（「21_アクセシビリティ国際化」
        整合）。

■ 業務担当の効率
  - キーボード操作 :
      - 全インタラクティブ要素が Tab で到達可能（「21_アクセシビ
        リティ国際化」WCAG 2.1.1 整合）。
      - フォーム入力は Enter で送信、Esc でキャンセル / モーダル
        閉じ（「12_フォーム設計規約」整合）。
      - 一覧画面は方向キーで行移動、Enter で詳細を開く（「13_
        検索一覧UX」整合）。
  - ショートカット :
      - 共通 : Ctrl/Cmd+S 保存、Ctrl/Cmd+Z undo、Ctrl/Cmd+F 検索、
        Ctrl/Cmd+N 新規、Esc 閉じる。
      - アプリ固有のショートカットは画面上で help（?）から一覧
        できること。
      - tier3 アプリ間で同一ショートカットの意味をずらさない。
  - マウスホイール / トラックパッドジェスチャに業務的意味を
    持たせない（誤操作 / アクセシビリティ阻害）。

■ 自動保存・復元
  - 業務担当のフォーム編集は数十分〜数時間に及ぶことがある。
    クラッシュ / 回線断 / 端末交換で作業ロスを起こさないため、
    自動保存を既定とする（「08_状態管理」フォーム下書き保存節
    「12_フォーム設計規約」整合）。
  - 保存先 : IndexedDB（PII 不可、「08_状態管理」永続化整合）。
  - 復元 :
      - 起動時 / 同一フォーム再オープン時に下書きを検出して復元
        を提案。
      - tier2 サーバ状態と version がずれている場合は復元 / 破棄
        をユーザーに選択させる（silent 上書き禁止）。
  - 自動保存中はステータス表示（「最終保存 : 2 秒前」等）。

■ アクセシビリティ既定
  - WCAG 2.1 AA を最低基準とする（「21_アクセシビリティ国際化」
    整合）。
  - color-only で情報を伝えない。状態バッジは色 + 形 + テキスト
    の 3 重表現（「14_状態遷移UI」「09_デザインシステム」整合）。
  - スクリーンリーダ対応 : aria-* 属性 / live region / 適切な
    role を全コンポーネントに既定で組込（「09_デザインシステム」
    整合）。
  - prefers-reduced-motion / prefers-contrast / prefers-color
    -scheme に対応する。

■ 業務エラーの presentation
  - 詳細は「19_業務エラーUX」を参照。
  - 原則 :
      - DomainError / ValidationError / BusinessConflict /
        AuthorizationDenied を 4 種別に区別して表示する。
      - tier2 が返す recovery_hints（「06_tier2/18_API設計規約」
        エラーレスポンス形式 整合）を必ず提示する。
      - 「エラーが発生しました」だけの汎用文言は禁止。

■ 国際化
  - 文字長変動 : 翻訳によりラベルが 2 倍以上に伸びる前提でレイ
    アウトを組む（固定幅禁止、「21_アクセシビリティ国際化」整合）。
  - RTL : アラビア語等の右→左言語に対応するため、論理プロパティ
    （margin-inline-start 等）を既定とする。
  - 数値 / 日付 / 通貨 / 単位 : tier2 の Decimal 文字列 / ISO 8601
    timestamp / 通貨単位（「06_tier2/18_API設計規約」整合）を
    Locale 別フォーマッタで表示する。
  - タイムゾーン : 表示は actor の Locale 既定 TZ。保管は UTC。
============================================================
