■ 設計原則
  - clock_integrity_class は bundle である。
      yaml に書く infra.clock_integrity.* attribute のうち、
      clock_integrity_class 1 つの値が他 5 dimension（sync_
      protocol / skew_tolerance / causality_discipline /
      ttl_clock_source / leap_second_strategy）を一意に導出
      する。Kustomize overlay / Helm chart / Argo CD
      ApplicationSet / Kyverno admission policy / DaemonSet
      manifest の作者が dimension を個別に override する経路
      は持たない。
  - dimension override は禁止する。
      「v1_intra_rack_ptp の skew_tolerance を 10µs に下げ
      たい」「v1_cross_dc_ntp_smeared の leap_second_strategy
      を step に変えたい」要望は新 class を切ることで表現
      する。class 数の爆発は意味論の規律として受け入れる。
  - dead spec を CI で殺す。
      classes.yaml に登録された全 class、scenarios.yaml に
      登録された全 assertion id、clock_inventory.lock.yaml
      に列挙された全 node、clock_skew_matrix.lock.yaml に
      列挙された全 (node × node) cell、clock_drill.lock.yaml
      に登録された全 drill、clock_causality_proof.lock.yaml
      に登録された全 proof entry は、いずれも参照されなく
      なった時点で CI fail とする。clock_integrity_class
      注釈の無い node の Pod は Kyverno admission deny by
      default（class 未宣言 node の deploy を物理 reject）。
  - 5 種類 enforcement orchestrator を全 clock_integrity_class
    に必須化する。
      chrony_ntp_daemon / linuxptp_grandmaster_chain / k1s0
      _hlc_runtime / clock_skew_ebpf_probe / kyverno_clock_
      admission の 5 orchestrator は、各 class が必要とする
      層を宣言する。同一 enforcement は複数 orchestrator に
      分散しないが、同一 node では複数 class が複数
      orchestrator を併用する。
  - clock_drill / leap_smear_drill を物理 property とする。
      `last_green_at + cadence_days >= now()` を CI 検査。
      30d 内に skew injection drill / 365d 内に leap smear
      drill を Litmus で実行し、SLO 内回復したことを property
      test で証明する。文章運用ではなく機械検証。
  - defense-in-depth は 5 層で構成する。
      層 A : compile（Rust phantom type / Go monotonic
              wrapper / .NET MonotonicTimestamp struct、wall-
              clock 混入を compile reject）
      層 B : lint（Conftest custom rule の 5 dcv_pr_blocks_*、
              Semgrep で wall-clock TTL API grep、GitHub
              Actions Required Status Check）
      層 C : chaos test（Litmus で ±10s / ±60s skew 注入、
              GPS source kill、PTP grandmaster failover、
              leap second 仮想注入、ntpd BGP hijack 模擬の 5
              blueprint、property test で HLC monotonicity /
              freshness / TTL 健全性を assertion）
      層 D : runtime（Kyverno admission policy の 5 dcv_
              kyverno_blocks_*、node label 必須化）
      層 E : 物理（GPS-disciplined OCXO grandmaster 二重化、
              PTP-aware NIC HW timestamping、PTP boundary
              clock switch、eBPF kernel-level skew probe、
              Rekor RFC3161 trusted timestamp authority）
      任意の単層が破れても他層が必ず止める。物理 enforcement
      は最終 safety net。

■ v1 clock_integrity_class セット（5 class）
  - yaml に書ける clock_integrity_class は次の 5 値のみ。各
    node 実体は clock_inventory.lock.yaml の枝で classes.yaml
    の keys と照合する。

      class                              | sync_protocol                       | skew_tolerance         | causality_discipline             | ttl_clock_source           | leap_second_strategy
      -----------------------------------+-------------------------------------+------------------------+----------------------------------+----------------------------+--------------------------
      v1_intra_rack_ptp                  | ptp_ieee1588v2_boundary_clock       | sub_microsecond_1us    | hlc_with_ptp_uncertainty_window  | clock_monotonic_raw        | smear_24h_linear
      v1_cross_dc_ntp_smeared            | chrony_multi_stratum1_gps           | millisecond_5ms        | hlc_with_commit_wait             | clock_monotonic_raw        | smear_24h_linear
      v1_application_hlc_only            | inherit_from_node_layer             | inherit                | hlc_mandatory                    | clock_monotonic_raw        | inherit
      v1_browser_client_skew_tolerant    | server_anchor_no_client_sync        | client_clock_untrusted | server_issued_hlc_token_only     | server_side_only           | server_anchor_irrelevant
      v1_air_gapped_legacy               | gps_radio_clock_or_manual           | second_1s              | hlc_mandatory_compensates_drift  | clock_monotonic_raw        | step_allowed_on_recovery

  - 各 class の不変条件と典型用途：

      - v1_intra_rack_ptp
          - 同一 rack / 同一 AZ 内 node の clock 規律。data
            01 cross-region replicated 系の write 経路、
            tier2 業務 saga / Outbox commit、09 audit hash
            chain emit、cross-AZ synchronous_replicated commit
            の本命。production の data path で最も厳密な
            clock 規律を要求する class。
          - sync_protocol：ptp_ieee1588v2_boundary_clock。
            grandmaster は GPS-disciplined OCXO（rubidium
            holdover ≥ 24h）を rack ごとに ≥ 2 台二重化、
            switch 上に boundary clock + transparent clock、
            NIC は PTP-aware HW timestamping（Intel E810 /
            Mellanox ConnectX-6 Dx 級）。BMCA で active
            grandmaster 自動切替。
          - skew_tolerance：sub_microsecond_1us（intra-rack）
            / sub_10us（intra-DC）。eBPF probe が 100ms 周期
            で CLOCK_REALTIME と CLOCK_MONOTONIC_RAW の delta
            を sampling し、tolerance 超過の瞬間に Pod を
            admission label 剥奪 → Kyverno が新規 schedule
            block。
          - causality_discipline：hlc_with_ptp_uncertainty_
            window。HLC の physical_ms 増分は PTP uncertainty
            window 内に bound、cross-rack span は HLC tuple
            comparison で因果性を保つ。
          - ttl_clock_source：clock_monotonic_raw。Rust
            `MonotonicInstant` newtype / Go `monotonic.Time`
            generated wrapper / .NET `MonotonicTimestamp`
            struct 経由のみ。`SystemTime::now()` / `time.Now()`
            / `DateTime.UtcNow` を TTL 判定に使う経路は
            Conftest + Semgrep + Rust `#[deny]` lint で禁止。
          - leap_second_strategy：smear_24h_linear。Google 式
            24h 線形 smear、`leap-smear.list` + chrony
            `leapsecmode slew`、PTP は smear 期間中のみ
            time_traceable bit を落とす。step は production
            で禁止、smear 期間中の skew 拡大は HLC で吸収。
          - 典型：data01 v1_cross_region_replicated 配下の
            tier2 SoR write、tier1 Workflow Activity 永続化、
            Outbox commit、09 audit hash chain emit、cross-
            AZ synchronous_replicated commit、KEK Shamir
            distribution rotation。
          - active_node 数しきい値：≥ 3 / cluster、grandmaster
            ≥ 2 / rack、PTP-aware NIC が node 全数 100%。

      - v1_cross_dc_ntp_smeared
          - cross-DC / cross-region node の clock 規律。
            v1_intra_rack_ptp が PTP 物理層に届かない distance
            （30km 超 / IP 経路 ≥ 5 hop）で採用する。
          - sync_protocol：chrony_multi_stratum1_gps。
            stratum-1 GPS source 最低 3 系統（Pool 不可）、
            chrony multi-source、`leapsecmode slew`、cross-DC
            fallback。
          - skew_tolerance：millisecond_5ms（cross-DC）/
            sub_50ms（cross-region）。
          - causality_discipline：hlc_with_commit_wait。
            cross-region write は HLC tuple + commit-wait
            window（grandmaster skew_tolerance + PTP_
            uncertainty + network RTT/2）を待ってから ack。
            Spanner TrueTime 流の external consistency を
            commodity GPS-OCXO で代替。
          - ttl_clock_source：clock_monotonic_raw。
          - leap_second_strategy：smear_24h_linear。
          - 典型：cross-region replication 経路の tier2 SoR、
            cross-DC OTel Collector / ClickHouse cluster 間
            の trace 連結、cross-region cert-manager 更新
            cadence。
          - active_node 数しきい値：≥ 3 / cluster、stratum-1
            GPS source ≥ 3 系統。

      - v1_application_hlc_only
          - tier1 / tier2 / tier3 application 層の HLC 規律
            class。物理層の sync は v1_intra_rack_ptp / v1_
            cross_dc_ntp_smeared から継承し、application code
            は HLC tuple のみを因果性の単一の真とする。
          - sync_protocol：inherit_from_node_layer。
          - skew_tolerance：inherit。
          - causality_discipline：hlc_mandatory。span / log /
            audit / saga / Outbox event の全て emit 時点で
            HLC tuple `(uint64 physical_ms, uint32 logical_
            counter, uint128 node_id)` を保持。wall-clock
            subtraction は禁止、freshness 計測は HLC delta、
            audit hash chain hash 入力に HLC tuple 必須包含。
          - ttl_clock_source：clock_monotonic_raw。
          - leap_second_strategy：inherit。
          - 典型：tier1 / tier2 / tier3 の全 application
            code path、特に 09 audit / 13 SLO freshness 計測
            / 07 Bidi resume_token decode / 10 認証 JWT exp
            検証 / 39 Idempotency-Key TTL の application 側
            実装。
          - 不変条件：本 class が active な node では k1s0_
            hlc_runtime の logical_counter overflow を
            compile-time const_assert で拒否、physical_ms
            backwards step を runtime panic に converting
            （連続性破壊の不可視化を物理排除）。

      - v1_browser_client_skew_tolerant
          - Browser SPA / 旧 .NET Framework Companion / OS
            の clock 設定が k1s0 制御外にある client 層の
            class。client wall-clock を不信扱い。
          - sync_protocol：server_anchor_no_client_sync。
            server から `Server-HLC` header（HMAC 署名済）を
            毎 response 配信、client は HLC token を
            opaque blob として storage / IndexedDB に保持
            し、idempotency / resume_token / pending_queue
            expiry の判定で client wall-clock を一切使わない。
          - skew_tolerance：client_clock_untrusted。client
            の wall-clock が ±1h / ±1d 滑っていても server
            正解として動作する設計。
          - causality_discipline：server_issued_hlc_token_only。
            client が HLC tuple を生成する経路は SDK 表面に
            存在しない（hlc_now() は server-anchored token
            の opaque pass-through のみ）。
          - ttl_clock_source：server_side_only。expiry 判定
            は全て server で実行、client は server から
            `expires_at_hlc` を受け取り表示するのみ。client
            wall-clock 比較は禁止。
          - leap_second_strategy：server_anchor_irrelevant。
          - 典型：07_tier3 Browser SPA、Tauri webview 内
            client、12_client/16 .NET Framework Companion 役割
            B、12_client/15 v1_browser_spa_typescript / v1_
            legacy_dotnet_framework distribution_class。
          - 不変条件：39 Idempotency-Key の TTL は server
            側 HLC で判定、client は header `Server-HLC` を
            request に echo する責務のみ。SDK 表面に
            wall-clock API ゼロ（13_test mutation score 対象）。

      - v1_air_gapped_legacy
          - air-gapped / 旧 industrial / .NET Framework 4.6.1
            未満などで NTP / PTP daemon を持てない node の
            class。HLC で物理 drift を吸収する degrade 経路。
          - sync_protocol：gps_radio_clock_or_manual。GPS 受信
            機 / 標準電波（JJY / DCF77 / WWVB）/ 手動 sync。
          - skew_tolerance：second_1s。手動 sync cadence は
            ≤ 24h、GPS 受信可能な場合は連続 sync。
          - causality_discipline：hlc_mandatory_compensates_
            drift。HLC が物理 drift を吸収するため、wall-clock
            が 1s ずれても application 因果性は保たれる。
          - ttl_clock_source：clock_monotonic_raw。
          - leap_second_strategy：step_allowed_on_recovery。
            air-gapped 環境では smear が現実的でないため
            recovery 時の step を例外的に許容、step 時は HLC
            の physical_ms を logical_counter で保護。
          - 典型：industrial gateway、.NET Framework 4.6.1
            未満ホスト、製造ライン edge appliance、ops-edge
            cluster の last-mile node。
          - 不変条件：active_node 数 ≤ 全 node 数の 5%、
            production data path に立たない（13 SLO の
            v1_data_durability に寄与しない、v1_request_
            availability の primary 経路にも立たない）。

  - 上記 5 class で v1 が covering。製造業 pack 想定 12 業務
    シナリオの stress test を本仕様末尾に示す。

■ dimension の根拠
  - sync_protocol は時刻同期の物理機構の射程：
        ptp_ieee1588v2_boundary_clock       → IEEE 1588v2 +
                                                grandmaster +
                                                boundary +
                                                transparent
                                                + HW
                                                timestamping
        chrony_multi_stratum1_gps           → multi-source
                                                stratum-1 +
                                                slew + cross-
                                                DC fallback
        inherit_from_node_layer             → 上位 class から
                                                継承（application
                                                層 only）
        server_anchor_no_client_sync        → client 側 sync
                                                を持たず server
                                                から HLC token
                                                を配信
        gps_radio_clock_or_manual           → 受信機 / 標準
                                                電波 / 手動
                                                sync
    複数粒度を重ねた表現は class 内 fixed。
  - skew_tolerance は許容 drift の上界：
        sub_microsecond_1us                 → ≤ 1µs
        millisecond_5ms                     → ≤ 5ms
        inherit                             → 親 class 継承
        client_clock_untrusted              → 不信
        second_1s                           → ≤ 1s
    混合は class 内 fixed。
  - causality_discipline は因果性の論理機構：
        hlc_with_ptp_uncertainty_window     → HLC + PTP
                                                uncertainty
                                                bound
        hlc_with_commit_wait                → HLC + commit-
                                                wait（external
                                                consistency
                                                emulation）
        hlc_mandatory                       → HLC tuple 必須
        server_issued_hlc_token_only        → server 発行
                                                opaque token
                                                のみ
        hlc_mandatory_compensates_drift     → HLC で物理 drift
                                                を吸収
  - ttl_clock_source は TTL 判定の clock 種別：
        clock_monotonic_raw                 → CLOCK_MONOTONIC
                                                _RAW（kernel
                                                直接）
        server_side_only                    → server 側で
                                                判定、client
                                                は受け取った
                                                HLC token を
                                                opaque で保持
  - leap_second_strategy は閏秒対応：
        smear_24h_linear                    → Google 24h
                                                linear smear
        inherit                             → 親 class 継承
        server_anchor_irrelevant            → server 側のみ
                                                適用
        step_allowed_on_recovery            → recovery 時の
                                                step を例外
                                                許容（air-
                                                gapped only）

■ derived dimension（per-node threshold）を独立次元にしない
  理由
  - per-node の閾値（v1_intra_rack_ptp の grandmaster_count
    _min=2 / consensus_gps_sources_min=3 vs v1_cross_dc_ntp_
    smeared の stratum1_sources_min=3 / drift_alert_threshold
    _ms=5）は本来 dimension たり得るが、5 class それぞれで
    「同じ sync_protocol / skew_tolerance / causality_
    discipline / ttl_clock_source / leap_second_strategy 構造
    で閾値だけが instance 別」という同形操作になる。
  - 閾値は class instantiate 時の instance 属性として宣言し、
    build artifact が DaemonSet manifest / chrony.conf /
    ptp4l.conf / Kyverno admission policy / Litmus chaos
    experiment を生成する形に統一。
  - infra / security オペレータ / 業務側で迷う余地がない
    ため、独立 dimension 化する利得が乏しい。

■ 5 種類 enforcement orchestrator の責務分離（特殊機構）
  - orchestrator 1: chrony_ntp_daemon
      - v1_cross_dc_ntp_smeared / v1_air_gapped_legacy / v1_
        application_hlc_only（物理層 fallback）の主担当。
        chrony が DaemonSet として全 node で動作、stratum-1
        GPS source ≥ 3 系統と sync、`leapsecmode slew` で
        24h linear smear、cross-DC fallback で grandmaster
        喪失時に NTP 経路で degrade。
      - 14_OSS ライフサイクル適合仕様 の v1_l1plus_primary
        として登録、license は BSD-3、linkage_model は
        process_boundary（CLI 起動）。
      - 層 D の runtime + 層 E の物理（GPS 受信機）を担当。

  - orchestrator 2: linuxptp_grandmaster_chain
      - v1_intra_rack_ptp の主担当。ptp4l + phc2sys + ts2phc
        の 3 daemon が DaemonSet として PTP-aware NIC を
        持つ全 node で動作、GPS-disciplined OCXO grandmaster
        + boundary clock switch + transparent clock の chain
        を構成。BMCA で active grandmaster 自動切替。
      - 14_OSS ライフサイクル適合仕様 の v1_l1plus_primary
        として登録、license は GPL-2.0、本企画 [0](c) GPL
        規律に従い process_boundary（CLI 起動）でのみ採用。
        Rust / Go static link への組込は禁止。
      - 層 E の物理（HW timestamping + GPS-OCXO）を担当。

  - orchestrator 3: k1s0_hlc_runtime
      - v1_application_hlc_only / v1_intra_rack_ptp（HLC
        tuple emit） / v1_cross_dc_ntp_smeared（HLC + commit-
        wait） / v1_browser_client_skew_tolerant（server-
        anchor token） / v1_air_gapped_legacy（drift 吸収）の
        全 class の application 側主担当。CockroachDB HLC
        アルゴリズムを Rust / Go / .NET 8 / Browser TypeScript
        の 4 言語に in-house 移植、phantom type / generic
        constraint で wall-clock 混入を compile reject。
      - HLC tuple は `(uint64 physical_ms, uint32 logical_
        counter, uint128 node_id)` 固定、wire 互換性を
        property_axiom で 4 言語間検証。logical_counter
        overflow は compile-time const_assert で拒否、
        physical_ms backwards step は runtime panic。
      - 14_OSS ライフサイクル適合仕様 の v1_inhouse_
        authoritative として登録（Connect-RPC .NET 実装と
        同枠）、license は Apache 2.0。
      - 層 A の compile + 層 D の runtime（HLC 演算）を担当。

  - orchestrator 4: clock_skew_ebpf_probe
      - 全 class の skew 監視主担当。Cilium Tetragon を
        substrate として in-house BPF program が CLOCK_

        kprobe で 100ms 周期 sampling、class-declared
        tolerance 超過の瞬間に Prometheus alert + node

      - 14_OSS ライフサイクル適合仕様 の v1_l1plus_primary
        として Cilium Tetragon を登録、license は Apache
        2.0、linkage_model は network_service。
      - 層 C の chaos test（skew injection 検出）+ 層 E の
        物理（kernel 内 sampling）を担当。

  - orchestrator 5: kyverno_clock_admission
      - 全 class の deploy / scheduling 段の最終 gate。
        Kyverno admission policy が node label `k1s0.io/
        clock-class=<class>` + `k1s0.io/clock-skew-status=
        green` を必須化、skew tolerance 超過時に Pod
        scheduling block。08_infra/14_強制機構 の既存
        Kyverno policy bundle に dcv_kyverno_blocks_* 5
        policy を追加。
      - 層 D の runtime + 層 E の物理 enforcement を担当。

  - 5 orchestrator は順次評価される（ptp4l/chrony → eBPF
    probe → kyverno admission → k1s0_hlc_runtime application
    層 → audit emit）が、各 clock_integrity_class は 1
    orchestrator を「主担当」として宣言。他層は補助的に
    協調動作（例：v1_intra_rack_ptp の主担当は linuxptp_
    grandmaster_chain だが、clock_skew_ebpf_probe が skew
    超過監視を副担当、k1s0_hlc_runtime が application 因果性
    emit を副担当）。

        safety net（08_infra/15 / 09_data/15 / 10_security/15
        / 10_security/17 と同型）。

■ HLC equivalence property（特殊機構）
  - 「±skew_seconds の clock skew 下で N concurrent
    operations を実行しても、Lamport happens-before 関係が
    全て HLC tuple comparison で respect される」を property
    test として CI で必ず green を返すことを必須化：
        ∀ skew ∈ {±10s, ±60s}, ∀ N ≥ 1_000_000:
          ∀ operations o1, o2 with o1 happens_before o2:
            hlc_compare(hlc(o1), hlc(o2)) == LESS
          ∀ concurrent operations o1 || o2:
            hlc_compare(hlc(o1), hlc(o2)) ≠ EQUAL  (logical_
                                                     counter
                                                     で差別化)
        MUST hold

  - 検証手順：
      1. Rust / Go / .NET / Browser TypeScript の 4 言語実装
         の k1s0_hlc_lib に対し、Litmus が node CLOCK_REALTIME
         に ±10s / ±60s 注入下で 1M concurrent operations を
         実行。
      2. 各 operation の HLC tuple を集約、happens-before
         関係を property test で検証、clock_causality_proof
         .lock.yaml に sha256 + 結果を書き込み。
      3. consensus_status: green が `happens_before_
         violation_count: 0` かつ 4 言語間 wire compat が
         満たされたときのみ release pipeline が次段に進める。
      4. 違反検出は 13_test v1_property_axiom の root cause
         investigation を trigger、ops15 runbook drill replay。

  - property に違反した場合の対応：
      - 1 言語のみ red → 当該言語の k1s0_hlc_lib 実装の bug、
        言語横断の wire compat property test で root cause
        identify。
      - 全言語 red → HLC アルゴリズム自体の semantics issue、
        CockroachDB 由来仕様との diff 確認 + spec 修正 PR。
      - logical_counter overflow → uint32 範囲超過、HLC tuple
        size 拡張は v2 候補（v1 では node 重複 / clock skew
        異常としての alert として扱う）。

■ 採用しない方針（structural spec として）
  - TrueTime 級原子時計（Spanner 流）：commodity OSS で
    調達不可、GPS-disciplined OCXO grandmaster + PTP +
    commit-wait で代替する。
  - Vector clock：HLC で十分、v2 候補のみ（air-gapped mesh
    用途）。
  - Wall clock for TTL：禁止、lint で reject。Rust /
    Go / .NET / TypeScript 全言語で wall-clock TTL API は
    SDK 表面に存在しない。
  - Step adjustment（jump）in production：禁止、smear のみ。
    例外は v1_air_gapped_legacy の recovery 時に限定。
  - Client-supplied wall-clock for idempotency / TTL：禁止、
    server-anchor HLC のみ。
  - Spanner / TrueTime 直接採用：commodity 制約と OSS 規律
    に整合せず採用しない（v2 でも commodity GPS-OCXO + PTP
    の sub-100ns 達成までは保留）。
  - systemd-timesyncd：multi-source / leap smear に弱く、
    chrony を選好。systemd-timesyncd を node に同居させる
    経路は Conftest で reject。
  - Floating-point HLC：HLC tuple は uint64 + uint32 +
    uint128 fixed-width のみ、float 版は採用しない（精度
    と wire compat の物理保証のため）。

■ v2 拡張ルール
  - 新 class の追加は purely additive：v1 class はそのまま
    残し、v2 で新規 class（例：v2_quantum_clock_distribution
    / v2_global_truetime_oss / v2_vector_clock_for_air_gap_
    mesh / v2_post_quantum_hlc_signing）を追加する。
  - 既存 class の dimension 値変更は破壊的変更（major version
    up）。
  - 命名は vN_<scope>_<sync_kind> 形式に固定。
  - dimension override 禁止の規律は v1 → v2 跨ぎでも維持
    する。
  - 量子もつれ時刻配信 / commodity GPS-OCXO 大陸間 sub-100ns
    / multi-master air-gapped p2p / post-quantum signed HLC
    は v2 候補。v1 は GPS-OCXO + PTP + chrony + HLC + eBPF
    + Kyverno の 6 機構に固定。

■ 至高路線における位置づけの帰結
  - 本仕様は「個別軸の規律から発生する全 clock dependency
    が単一の真の中で機械検証される」ことを requires する
    clock integrity 軸。運用コスト度外視（CLAUDE.md 上位
    方針）の哲学に従い、GPS-disciplined OCXO grandmaster
    の rack 単位二重化 / PTP-aware NIC の全 node 必須化 /
    PTP boundary clock switch の全 rack 配置 / HLC ライブ
    ラリの 4 言語 in-house 移植 / eBPF kernel-level skew
    probe / Cilium Tetragon substrate / 24h linear smear
    / Rekor RFC3161 trusted timestamp authority 連結 / 12
    stress scenario 全 green を v1 で固定する。「現実には
    起こりにくい」leap second 不整合 / NTP BGP hijack /
    GPS spoofing / clock skew 攻撃を物理層 5 重で塞ぐこと
    で、1.0.0 ship 時点の時刻 / 因果性 安全性を「机上の
    計画」ではなく「物理 enforcement」として確立する。
  - 運用コスト最小化のために grandmaster_count_min を 1 に
    緩めたり、HLC を v2 に逃がしたり、smear 期間を短縮
    したり、systemd-timesyncd を許容したりする選択肢は本軸
    では取らない。「作業量を減らすために機能を削減するの
    は避ける」（CLAUDE.md）の規律に厳密に従い、chrony +
    linuxptp + Cilium Tetragon + k1s0_hlc_lib + Kyverno +
    GPS-OCXO HW + PTP-aware NIC + boundary clock switch
    の 8 機構を全て v1 必須とする。
  - 本軸が「OSS として公開する k1s0 自身の時刻 / 因果性
    規律を OSS 業界 最高水準（CockroachDB HLC + Spanner
    流 commit-wait + Google smear + IEEE 1588v2 PTP の
    全部入り）に保つ」ことを物理保証する。HLC + PTP +
    GPS-OCXO + eBPF kernel probe + multi-language wire
    compat を v1 達成する OSS は 2026 年時点で存在せず、
    本軸の v1 達成自体が 03_競合との差別化 の中核要素
    となる。
