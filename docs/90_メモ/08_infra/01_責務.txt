============================================================
infra 責務
============================================================

■ 一文定義
  - infra は、tier1 / tier2 / tier3 / data の各層が動作する
    物理 / 仮想基盤と、その基盤を「宣言的に維持し続ける」
    制御平面そのものを提供する層である。

■ 責務の境界
  - infra が責務を持つ：
      - Kubernetes cluster の構築 / 運用 / 廃棄
      - cluster 位相（zone / cluster / region 跨ぎ）
      - L4 / L7 ネットワーク（MetalLB / kube-vip / Istio /
        Envoy Gateway substrate）
      - 物理ストレージ（Rook+Ceph / Longhorn）
      - 制御平面（Argo CD / Argo Rollouts / Argo Events /
        Kyverno / cert-manager / OpenBao / External Secrets）
      - サプライチェーン（Harbor / Trivy / Cosign / Syft /
        Grype）
      - CI/CD runner（GitHub Actions self-hosted / Tekton）
      - Chaos 実演（Litmus）
      - IaC（OpenTofu / Helm / Kustomize）
      - 運用 UI / 開発者ポータル（Headlamp / Backstage）
      - cluster 位相の宣言的真（infra/topology/）
      - cluster 規律の物理 enforcement（admission policy /
        topology_spread / etcd quorum / CRUSH map）

  - infra が責務を持たない：
      - ビジネスロジック（→ tier2 / tier3）
      - tier1 Library / Server 系の RPC / Repository 実装
        （→ 05_tier1）
      - data の lifecycle / 保全 / 暗号化方針（→ 09_data）
      - 個別業務の SLI / SLO 定義（→ 13_SLO適合仕様、tier 別
        instance attribute は infra に書かない）
      - テナント別 quota の閾値定義（→ 15_テナント容量適合
        仕様、infra は enforcement_layer の物理層を提供する
        だけ）
      - schema 進化の意味論（→ 12_スキーマ進化適合仕様）

■ 至高路線における立ち位置
  - infra は「文章運用に頼らず物理 enforcement に転写する」
    最終 safety net を提供する層である。RLS FORCE / etcd
    quorum / Ceph CRUSH map / Kafka rack awareness / Kyverno
    admission policy / cosign signed tag は全て infra が
    最終的に強制する。
  - 13 軸の各 spec の defense-in-depth 層 E（物理）は infra
    の物理基盤に転写される。tier1 / tier2 / tier3 / data の
    spec が「物理層で強制」と書く全ての箇所が infra の責務
    に降りる。

■ 至高路線における原則
  - 単一 OSS 深耕：cluster 1 つに対して採用する OSS は
    1 種類に絞り、横並びの選択肢は持たない（02_採用OSS一覧
    の L1+ 方針を踏襲）。
  - 宣言的真：cluster 状態 / topology / OSS バージョン / drill
    履歴は GitOps（Argo CD）と build artifact（lock.yaml）
    でのみ表現し、kubectl で直接書き換えた状態は CI が
    drift として検出して reset する。
  - 不可逆性の禁止：cluster 廃棄は OpenTofu replay で再構築
    可能であること。手動操作で再構築不能な状態に到達する
    経路を持たない。
  - 段階的 release 禁止：1.0.0 時点で 5 topology_class 全てが
    drill green であること（v1_single_zone は dev/stage 用、
    本番は他 4 class）。
