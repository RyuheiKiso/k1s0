============================================================
client 採用 OSS（client 層 subset）
============================================================

■ 位置づけ
  - 「02_採用OSS一覧」の grand catalog のうち、client 層が
    所有する SDK / Companion / Auto-Instrumentation 系 OSS
    を抽出して整理したもの。tier1 Library / Server / 観測
    可能性 SoR / Apicurio Registry は tier1 所有として扱う
    ため本ファイルには含めない（cross 参照で明記）。
  - 本ファイルの全 OSS は 14_OSSライフサイクル適合仕様の
    oss_inventory.lock.yaml に v1_l1plus_primary として登録
    される。

■ license / linkage_model 規律
  - 本 layer の採用 OSS は 02_採用OSS一覧 [0] OSS license 規律
    (NEW-09) に従う。各エントリの linkage_model は {dynamic,
    static, process_boundary, network_service} のいずれかに
    分類され、license-checker / cargo-deny / dotnet-licenses で
    CI 検査される。AGPL / SSPL / BSL / Confluent Community License
    / Elastic License v2 等は採用禁止。
  - 本 layer の非 Apache-2.0 採用 OSS の linkage_model :
      - .NET 8 / Framework 4.6.2  (MIT)        : process_boundary
                                                (CLR runtime 経由)
      - OpenJDK Temurin 21        (GPLv2+CE)   : process_boundary
                                                (JVM runtime 経由、
                                                 Classpath Exception
                                                 により application
                                                 linking は許容)
      - Node.js 20                (MIT)        : process_boundary
                                                (V8 runtime 経由)
      - Tauri                     (MIT/Apache) : static
      - rustc / Rust crate        (MIT/Apache) : static
      - signalfx/splunk-otel-dotnet fork (Apache 2.0) : dynamic
                                                (NuGet 動的 link、
                                                 NEW-04)

------------------------------------------------------------

  -------------------------------+-----------------------------------+---------------
  gRPC C++ コア                  | gRPC                              | Apache 2.0
  gRPC .NET (8 LTS のみ)         | grpc-dotnet (Grpc.Net.Client)     | Apache 2.0
  gRPC Java                      | grpc-java                         | Apache 2.0
  gRPC Node                      | @grpc/grpc-js                     | Apache 2.0
  gRPC-Web TypeScript            | grpc-web (improbable / official)  | Apache 2.0
  gRPC Python                    | grpcio                            | Apache 2.0
  gRPC Ruby                      | grpc                              | Apache 2.0
  gRPC Go                        | google.golang.org/grpc            | Apache 2.0
  gRPC Rust                      | tonic                             | MIT
  Connect TS (Browser / Node)    | @connectrpc/connect-web /         | Apache 2.0
                                 |   @connectrpc/connect-node        |
  Connect Go                     | connectrpc.com/connect            | Apache 2.0
  Connect Kotlin                 | connect-kotlin                    | Apache 2.0
  Connect Swift                  | connect-swift                     | Apache 2.0
  Connect .NET 8 LTS             | k1s0.Connect.NetCore              | Apache 2.0
                                 |   (in-house authoritative、       |
                                 |    14_OSSライフサイクル適合仕様   |
                                 |    の v1_inhouse_authoritative、  |
                                 |    詳細は 12_client/18)           |
  HTTP/3 + WebTransport (browser)| native browser API                | -
  HTTP/3 + WebTransport (server) | quinn / s2n-quic                  | Apache 2.0
                                 | （tier1 Server 系 Rust 実装、     |
                                 |   Envoy Gateway 経由のみ。        |
                                 |   Companion 側 native QUIC は     |
                                 |   v2 候補）                       |
  HTTP/3 + WebTransport (.NET 8+)| System.Net.Quic                   | MIT
                                 | （v1 opt-in、.NET Framework       |
                                 |   Companion には載らない）        |
  WebSocket (TS)                 | native WebSocket                  | -
  WebSocket (.NET)               | System.Net.WebSockets             | MIT
  SSE parser (Browser)           | native EventSource                | -
  SSE parser (.NET / 他言語)     | 自製（言語別、Buf 生成側で固定）  | Apache 2.0

  - SDK 内部で利用する transport library。distribution_class 別:
    - v1_full_native_with_companion (.NET 8 LTS / Java 21 / Node 20
      / Rust / Go / Python / Ruby): gRPC bidi が default、HTTP/3 +
      WebTransport / WebSocket は capability matrix で明示宣言された
      case のみ。Connect-RPC（Connect TS / Connect Go / Connect
      Kotlin / Connect Swift / k1s0.Connect.NetCore）は Browser SPA
      経路と同一 .proto から並走 codegen され、必要に応じて adapter
      選択可能（公式実装は v1_l1plus_primary、.NET 8 LTS のみ自製
      実装 k1s0.Connect.NetCore で v1_inhouse_authoritative。理由：
      Connect 公式に .NET 実装が存在せず、L1+ 単一深耕の health_
      check_cadence を community fork に gambling できないため。
      wire は Connect protocol 公開 spec と byte-equal、Connect
      Conformance Suite 全 form を CI gate で green に保つ。詳細は
      12_client/18_dotnet8_connect_inhouse、14_OSSライフサイクル適合
      仕様 oss_inventory.lock.yaml の k1s0_connect_netcore entry
      参照）。
    - v1_legacy_dotnet_framework (.NET Framework 4.6.2+ かつ
      Windows 10 1607+ / Server 2016+): Grpc.Net.Client は
      WinHttpHandler 経由で当該条件下に動作するが、client-streaming
      / bidi に構造的制約があり、tier1 Library 抽象（bidi RPC を
      含む）を素直に載せられないため本 class では採用しない
      （05_tier1/02_言語スタック 整合、05_tier1/16_HTTP2_enforcement
      の OS prerequisite と双方向 lock）。Companion 役割 B の
      sse_paired adapter が HTTP/1.1 chunked + SSE の自製パーサで
      server-streaming を、HTTP/1.1 POST で unary を担う（自製 SSE
      parser 行参照）。Connect-RPC bidi も .NET Framework は
      WinHttpHandler の HTTP/2 制約（OS 版数依存 + client-streaming
      制約）により不安定なため採用しない（sse_paired を既定とする）。
      OS 版数下限（Windows 10 1607 / Server 2016）未満の端末は
      v1_legacy_http11 capability_class に fall back（per-tab
      subscription 上限 6）し、ALPN h2 を要求しない。
    - v1_browser_spa_typescript: 本 class の bidi primary は
      Connect-RPC over HTTP/2 / HTTP/3（Browser fetch full-duplex
      streams）。grpc-web は unary / server-streaming 用、bidi の
      fallback として自製 frame protocol を使う経路は持たない。
      HTTP/3 + WebTransport は browser native API で opt-in。
    - v1_thick_native_via_tauri: Rust 側 tonic（gRPC bidi）、WebView 側は
      v1_browser_spa_typescript と同じ。
    - v1_thin_business_api_only: HTTP/1.1 + JSON unary（Transcoder 派生）
      + HTTP/1.1 chunked + SSE server-streaming（tier1 Rust ハンドラ
      直接生成）のみ。SDK パッケージは提供しない。
  - SSE parser は data: / id: / event: / retry: の 4 directive
    を解釈する。id: は resume_token として用い、再接続時に
    Last-Event-ID リクエストヘッダで server へ送出する。
    Browser 側は EventSource ネイティブで足りるが、.NET
    Framework など EventSource 非対応環境向けには言語別の
    自製パーサを Companion 同梱で配布する。
  - Connect-RPC は v1_l1plus_primary、Browser SPA capability_class
    =web の bidi primary として gRPC-Web と並走（両者は同一 .proto
    から codegen、wire は HTTP/2 over TLS / HTTP/3 over QUIC で
    成立）。WebSocket-bidi（自製 protobuf binary frame）は v1
    から削除（自製 frame protocol 禁止と整合）。.NET 8 LTS のみ
    Connect 公式実装が存在しないため自製 k1s0.Connect.NetCore
    （v1_inhouse_authoritative）を NuGet 配布する。wire 自体は
    Connect protocol 公開 spec の byte-equal 実装で「自製 frame
    protocol」ではなく公式 spec の self-hosted 実装。Connect
    Conformance Suite で wire 等価性を CI gate（12_client/14、
    12_client/18 参照）。

[6] Browser / Tauri / SPA 系専用
------------------------------------------------------------
  カテゴリ                       | プロダクト                        | ライセンス
  -------------------------------+-----------------------------------+---------------
  IndexedDB ラッパー             | idb (Jake Archibald)              | ISC
  WebCrypto API                  | native browser API                | -
  Tauri 基盤                     | Tauri (Rust + WebView)            | MIT / Apache 2.0
  OS keychain (macOS)            | Tauri tauri-plugin-keychain       | MIT / Apache 2.0
  OS keychain (Windows)          | Tauri DPAPI plugin                | MIT / Apache 2.0
  OS keychain (Linux)            | Tauri Secret Service plugin       | MIT / Apache 2.0
  Service Worker                 | native browser API                | -

  - Browser SPA / Tauri 配下では IndexedDB を offline storage、
    WebCrypto AES-GCM を at-rest 暗号化、device_bound_key を OS
    keychain（Tauri）または non-extractable CryptoKey（pure
    browser）で保管。
  - SDK 起動時に navigator.storage.persist() を要求し、
    granted=true で IndexedDB の eviction 耐性を確保する。
    granted=false の端末では IndexedDB.estimate() で残容量を
    見積り、requested_quota_bytes 未満なら ClientCapability
    Error（subtype=storage_unavailable）を SDK が throw する
    （「07_tier3/22_端末オフラインデバイス」/「07_tier3/39
    _クライアント状態適合仕様」整合）。
  - Service Worker は v1 では offline cache のみ、background
    sync は v2 候補。
