============================================================
tier2 の言語スタック
============================================================

■ 基本方針
  - tier2 は tier1 Library が対応する言語に揃える。tier1 が
    対応しない言語で tier2 を実装することは禁止する（tier1
    Library が無い言語では tier2 業務コードが OSS を直接利用
    する経路を塞げないため）。
  - tier1 対応言語：Rust / C# (.NET 8+) / Go / TypeScript
    （「05_tier1/02_言語スタック」参照）。

■ Service 形態の言語
  - 主要言語：Rust。tier1 Server系（「05_tier1/02_言語スタッ
    ク」）と同方針。
  - 例外：業務 Workflow を Temporal の SDK で記述する部分は、
    Workflow 決定論実行の制約を満たすために tier1 が提供する
    Workflow ラッパに従う。Workflow 内部のロジック自体は Rust
    で記述する。

■ Library 形態の言語
  - 対応言語：Rust / C# (.NET 8+) / Go / TypeScript（tier1
    Library と同集合）。
  - 各言語で同等の API 表面を提供する。表面 API の整合性は
    .proto / Schema 駆動（「11_表現手段」参照）と公開 API
    snapshot（「16_強制機構」参照）で担保する。
  - .NET Framework は tier1 Library と同じく対応外。.NET
    Framework からの利用は Companion + Gateway 経由 tier2
    Service のみとする（「02_位置づけ」「08_配布形態」
    Companion 配慮節を参照）。

■ 業界 pack の言語選定指針
  - 製造業 pack（および将来追加業界 pack）は、本ファイル記載
    の対応言語の中から選ぶ。pack 内で複数言語を混在させる場合、
    Domain Event / API は .proto / Schema 駆動で wire 等価を
    維持する。
  - 業界 pack 単位で「主要言語 1 + 派生 SDK 言語 N」の構成を
    既定とする。1.0.0 出荷の製造業 pack は Service が Rust、
    Library SDK は Rust / C# / Go / TypeScript の 4 言語提供
    とする。

■ Companion 経由クライアントから見た tier2
  - Companion は tier1 が提供する transport / observability /
    認証伝播 runtime（「05_tier1/04_Library」Companion 節）。
    tier2 自体は Companion を提供しない。
  - Companion 経由クライアント（.NET Framework 等）は tier2
    Service を Gateway 経由で消費する。proto に書かれたセマン
    ティクスを Companion の役割 B（Transport Negotiation）が
    transport 非依存に実行する（「02_位置づけ」「08_配布形態」
    と整合）。

■ 言語間 API 表面整合性
  - 同一機能の API シグネチャを、言語の慣用表現の差を許容しつつ
    セマンティクスは等価に保つ。
  - 整合性検査 :
      - 各言語の公開 API snapshot を CI で守る（tier1「05_
        tier1/04_Library」強制機構層 2 と同枠）。
      - .proto / Schema 駆動で生成される型は CI で diff を
        検査。
      - 同一 conformance test suite を全言語で実行し、green を
        merge 条件とする（「15_テスト方針」参照）。

■ 言語固有のイディオム調整
  - 同一機能でも言語ごとに自然な API 形（async / 例外型 /
    null 表現 等）が異なる。tier2 は以下を許容する :
      - Rust         : Result<T, E> / async fn
      - C#           : ValueTask<T> / 業務例外型
      - Go           : (T, error) / context.Context
      - TypeScript   : Promise<T> / Result-like 型
  - 上記イディオムの差は tier1 Library core パッケージ
    （「05_tier1/04_Library」core 集約方針）に共通エラー型 /
    リトライポリシーが定義されている範囲で担保する。tier2 は
    その上に乗る。

■ 言語追加の手順
  - 1.0.0 出荷後に対応言語を追加する場合、以下を満たすことを
    要件とする :
      - tier1 Library がその言語に対応していること（先行
        条件）。
      - tier2 の業務カテゴリすべてを当該言語の Library SDK で
        提供できること（部分対応は不可）。
      - 公開 API snapshot / conformance test を当該言語版で
        green にできること。
