============================================================
tier2 のデータライフサイクル（入口・出口・bulk・品質）
============================================================

■ 方針
  - 26 で扱うのは「保持されているデータの管理」。本ファイル
    で扱うのは「データの入口（オンボーディング）と出口（ポー
    タビリティ / オフボーディング）」、bulk 操作、品質管理。
  - 既存業務システム（.NET Framework アプリ等のレガシー、他
    SaaS 等）からの移行と、テナントが本プラットフォームから
    離脱する際の data export を 1.0.0 出荷時点で機構として
    持つ。

■ 初期データ移行（オンボーディング）
  - 移行対象 :
      - マスタ（品目 / 拠点 / 仕入先 / 組織 / ユーザー / 業務
        カレンダー / 為替レート 等）
      - 業務 entity の現在状態（Confirmed 状態でのスナップ
        ショット、過去履歴は移行対象外を既定とする）
      - 過去履歴の移行（オプション）: 規制対応で必要な場合は
        archive 層への直接 import を提供
  - 移行機構 :
      - tier2 が業界横断 / 業界 pack ごとに「初期移行
        Workflow」を提供する（業務管理 API として、「23_管理
        境界」参照）。
      - 入力形式 : CSV / JSON / proto バイナリ。tier2 が標準
        スキーマを Schema 駆動で定義（「11_表現手段」参照）、
        外部システムからの mapping は tier3 / テナント側責任。
      - 検証 : 移行前に dry-run で検証（参照整合性 / 業務
        不変条件 / マスタ存在確認）。dry-run 結果を業務管理
        UI で確認。
      - 実行 : 承認後に bulk import を実行。並列度はテナント
        capacity に応じて制御。
      - rollback : 移行失敗時の rollback（部分的成功の取消）
        を Workflow の補償で実装。
  - 移行中の業務影響 :
      - 既存業務との dual-run 期間 : 必要に応じて、新旧両方
        のシステムに同時書込する dual-write Service を一時
        的に提供（「13_互換性ポリシー」dual-write 移行支援
        と類似）。
      - dual-run の整合性検証ジョブを「20_スケジューラ・
        バッチ」の機構に乗せて実行。

■ テナント data export（ポータビリティ）
  - GDPR の right to portability 対応として、テナント全データ
    の export を機構として提供する :
      - 対象 : 業務 entity 本体、Domain Event 履歴、監査ログ、
        マスタ、添付ファイル（「31_業務添付帳票資産」参照）。
        PII を含むため認可は tenant_admin 必須。
      - フォーマット : 標準 export 形式は JSON（カテゴリごと
        にファイル分割）+ proto バイナリ（schema 同梱）。csv
        はオプション。
      - 配送 : 大量データのため非同期 LRO（「18_API設計規約」
        LRO 節）。完了通知 + tier1 Object Storage 上の署名 URL
        で配送。
      - 暗号化 : テナント指定の公開鍵で暗号化した上で配送
        （PGP または age）。
      - schema metadata : export には対応 schema バージョン
        / Schema Registry エントリ / 業務語彙 → フィールド
        対応を同梱し、外部での読取可能性を担保。
  - 部分 export :
      - 業務 entity 種別 / 期間 / 個別 aggregate ID 単位での
        部分 export も提供（業務的な引き継ぎ / 監査調査向け）。
  - export 実行の監査 :
      - export 実行は詳細監査エントリ emit。
      - 「いつ・誰が・何を・どこに」を残す（「14_業務エラー
        監査コンプライアンス」と整合）。

■ オフボーディング（テナント離脱）
  - テナント離脱時の手順 :
      - (1) data export を実行（テナント受領）。
      - (2) 業務処理停止（業務 API への新規リクエスト拒否）。
      - (3) Workflow / バッチ ジョブ停止。
      - (4) grace period（既定 30 日）でデータ凍結保管。
      - (5) 規制保管期間が必要なデータを archive へ移送
        （「26_データ保持」アーカイブ階層と整合）。
      - (6) PII を物理削除（「26_データ保持」削除ライフ
        サイクル）。
      - (7) 全削除完了の証跡を監査エントリで記録、テナント
        側に証明書を発行。
  - 離脱中も export 要求は受付可能（grace period 内に限る）。

■ Bulk 操作（業務管理 API として）
  - bulk insert / update / delete を業務管理 API surface
    （「23_管理境界」参照）として提供する :
      - 主に運用作業（マスタ一括更新、複数 entity 一括処理、
        誤データ修正）向け。tier3 のエンドユーザー向け業務
        API では bulk を提供しない（誤操作防止）。
      - 操作前 dry-run を必須とする。dry-run 結果を承認した
        後に実行可。
      - 並列度・rate は per-tenant quota（「27_信頼性運用
        準備」参照）に従う。
      - 全操作を監査エントリ emit。bulk 操作は影響範囲が大
        きいため詳細記録（影響件数 / aggregate ID リスト
        ハッシュ）。
  - bulk 操作の冪等性 :
      - bulk Idempotency-Key を tier2 が発行（「18_API設計
        規約」冪等性節と同枠）。
      - 重複実行は同一結果を返す。

■ データ品質パイプライン
  - 入力時 validation :
      - マスタ / 業務 entity の入力時に schema validation +
        業務不変条件 validation を実施（「14_業務エラー監査
        コンプライアンス」ValidationError）。
      - 移行 / bulk 経路でも同じ validation を通過する
        （バイパス禁止）。
  - 継続的品質検査（業務管理者向け）:
      - マスタの重複検出（同一品番 / 同一仕入先 等）。
      - 参照整合性検査（孤立 entity / 無効参照 検出）。
      - 業務的な異常検知（在庫マイナス / 期限切れ未処理 等）。
      - 検査ジョブは「20_スケジューラ・バッチ」で定期実行、
        結果は業務管理 UI に集約表示。
  - 品質メトリクス :
      - per-tenant のデータ品質スコア（重複率 / 整合性違反率
        等）を tier2 が算出し、業務管理者に提示。

■ 既存基幹システムとの並行運用（migration era）
  - 「01_概要」記載のレガシー資産（.NET Framework アプリ等）
    との並行運用シナリオ向けに、限定的 dual-write を tier2
    が提供 :
      - tier3（Companion 経由含む）→ tier2 → tier1 backend
        の正式経路と並行して、tier2 → 既存基幹（webhook /
        EDI / DB 直接）の outbound（「25_外部システム統合」
        参照）を構成。
      - 並行運用期間中の整合性検証ジョブを実行。
      - 段階的に既存基幹を retirement する（tier3 が完全に
        tier2 を経由するようになった時点で並行運用終了）。
  - 並行運用期間の上限 : テナント契約に応じて定める。tier2
    の互換性ポリシー（「13_互換性ポリシー」並行バージョン
    提供節）の最長 6 ヶ月とは別の運用期間。

■ tier3 の拡張点
  - 移行 mapping（外部 → tier2 schema）の override 実装。
  - export の追加形式 / 追加暗号化方式の差し込み。
  - bulk 操作の業務的事前条件（テナント独自の追加 validation）
    を hook で挿入。
  - 不変条件（override 不可）:
      - 移行 / bulk 経路での schema / 業務不変条件 validation
        の bypass
      - export の監査エントリ emit
      - PII redact / 暗号化要件

■ 1.0.0 出荷時の対応範囲
  - 初期移行 Workflow / data export / bulk 操作 / 品質検査の
    機構を 1.0.0 で揃える。
  - 既存基幹との並行運用 / dual-write 機構も 1.0.0 で提供
    （顧客現場での導入を前提とするため）。
