# 形式検証適合仕様（v1）

## 一文定義
- 形式検証適合仕様は、5 proof_class × 5 phase の cross-product として完全列挙される proof_loop catalog の各 cell に対し、5 enforcement orchestrator のいずれかを必ず物理 pointer として bind し、全 18 軸 + 自軸（19 軸 = formal 自軸を含む全 19 軸。19 × 5 = 95 cell）の defense-in-depth 層 C / D / E / F に bind 済みであることを 5 層 defense-in-depth + 20 項 CI 不変条件 + 16 件 stress test pack で物理 enforce する meta-meta-axis である。同時に 19 axis × 5 proof_class = 95 cell の `proof_matrix.lock.yaml` の全 cell `cell_state` ∈ {v1_baseline_verified, v1_accepted_with_assumption, v1_unverified_handled} を 1.0.0 ship blocker として 00 meta `release_gate.lock.yaml` の AND-gate に物理入力する。

## 位置づけ
- [採用 OSS 一覧](../../02_要件定義/04_技術選定/01_OSS採用一覧.md) の TLA+ + Apalache / P language / Stainless / Dafny / Lean 4 + mathlib / Kani / CBMC / cosign / OpenBao / Kyverno / Tekton / Argo CD / Argo Workflows / Ceph RGW / ClickHouse / Perses、[形式検証要件](../../02_要件定義/03_非機能要件/09_検証規律要件.md) の formal 階層、および 11_formal 設計方針配下の 8 方針メモが散在的に宣言する formal_obligations / proof cadence / counter-example handling / assumption / mathlib pinning / tool version pinning / reviewer pool / break-glass policy の証明 lifecycle を、機械可読な単一の真として一箇所に固定する仕様書。
- formal が物理的に唯一の数学的 enforcement facade として振る舞う。tier1 / tier2 / tier3 / infra / data / security / ops / test から「どの proof_class を どの phase でどう closure するか」を coding で flag するのではなく、proof_class + phase + artifact_pointer + reviewer_sigs を build artifact に注釈する形で宣言する。
- 18 軸 + 本軸 の 1 軸として、本仕様が 07 transport / 08 migration / 09 observability / 10 auth / 11 key / 12 schema / 13 SLO / 14 OSS lifecycle / 15 capacity / 32 data-tenant / 39 client-state / infra01 topology / infra16 clock_integrity / data01 preservation / security15 threat-model / security17 build_provenance / client15 SDK distribution / ops15 loop / test15 verification の各軸の証明 lifecycle 局面を統合する。

## 設計原則
- **proof_class は bundle である**: yaml に書く `formal.proof.*` attribute のうち、proof_class 1 つの値が他 6 dimension（cadence_class / artifact_class / orchestrator_preference / coverage_weight / regression_corpus_class / reviewer_kind_requirement）を一意に導出する。dimension override は禁止。
- **dimension override は禁止する**: 「v1_temporal_safety_proof のうち cadence_class を緩めたい」要望は新 class を切ることで表現する。class 数の爆発は意味論の規律として受け入れる。
- **dead spec を CI で殺す**: `formal_classes.yaml` に登録された全 class、`proof_matrix.lock.yaml` に列挙された全 cell、`proof_inventory.yaml` / `counter_example.lock.yaml` / `proof_review.lock.yaml` / `assumption.lock.yaml` に列挙された全 entry、proof_regression_corpus に保存された全 reproducer は、いずれも参照されなくなった時点で CI fail とする。
- **5 種類 enforcement orchestrator を全 proof_class に必須化する**: tlaplus_apalache_pipeline / p_pgo_pipeline / stainless_dafny_pipeline / lean_mathlib_pipeline / kani_cbmc_pipeline の 5 orchestrator は、各 class が必要とする層を宣言する。同一 proof は複数 orchestrator に分散しないが、同一 axis では複数 class が複数 orchestrator を併用する。
- **proof cadence を物理 property とする**: 「cell の cadence_days 以内に必ず該当 class の proof を再 verify し、宣言された certificate hash で verified する」を Tekton Pipeline + reproducibility checker daemon で必ず検証する。
- **defense-in-depth は 5 層で構成する**:
    - 層 A: compile 時（PR の proof_class 注釈必須、`proof_matrix.lock.yaml` schema 通過）
    - 層 B: lint（catalog の coverage / cadence / ownership / reproducibility / reviewer dual-signoff）
    - 層 C: drill chaos test（Tekton + Argo Workflows + Apalache + TLC + Stainless + Dafny + Lean + Kani + CBMC）
    - 層 D: runtime（5 orchestrator の実 deploy）
    - 層 E: physical（cosign signature / Kyverno admission webhook / Ceph RGW Object Lock Compliance mode / proof_event hash chain / dual reviewer cosign の物理層強制）
    - 任意の単層が破れても他層が必ず止める。物理 enforcement は最終 safety net。

## 5 phase（全 cell が phase closure を要求）
- **specify**: 軸 spec の `formal_obligations` 段落で obligation を theorem 名 + 自然言語 + tool 候補で宣言
- **model**: tool に応じて TLA+ / P / Stainless / Dafny / Lean / Kani / CBMC の spec / harness を書く
- **prove**: Tekton Pipeline で tool 起動、verification obligation を SMT / model checker で discharge
- **review**: dual reviewer cosign signoff（reviewer のうち 1 名以上は人間、cryptographic proof は crypto-domain expert）
- **archive**: proof artifact + certificate hash + reviewer sigs を `proof_status.lock.yaml` に fingerprint、Ceph RGW Object Lock Compliance mode で retention

各 cell の `phase_closure_state` ∈ {v1_complete, v1_in_progress_handled, v1_blocked} の 3 値、`v1_blocked` が 1 cell でもあれば 1.0.0 ship blocker。

## 採用しない設計（spec レベル）
- 商用 proof assistant / model checker: 採用しない（[非提供スコープ](../../02_要件定義/01_スコープ/02_非提供スコープ.md) 参照）
- 直接 SMT solver invocation: 採用しない（Stainless / Dafny / Kani / CBMC が SMT solver を内包）
- 文章 only proof: 禁止、必ず machine-checkable artifact
- LLM 単独 sign-off: 禁止（human 1 必須）、ただし ai_static_analysis evidence は最大 4 model の cross-check を許容
- 単一 reviewer sign-off: 禁止、dual 必須
- PR author self-review: 禁止
- 段階的 release: 禁止、1.0.0 で全 cell verified or accepted_with_assumption
- cosign 署名なし artifact: 禁止、admission policy reject
- mathlib pin なし運用: 禁止
- bound parameter 引き下げ without review: 禁止
- 「文章で説明」の verification: 禁止、必ず lock.yaml + dashboard
- reproducibility violation 容認: 禁止、certificate hash 不一致は CI fail
