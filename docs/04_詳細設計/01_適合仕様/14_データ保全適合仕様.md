# data データ保全適合仕様（v1）

## 一文定義
- データ保全適合仕様は、5 preservation_class × 5 dimension（durability / replication_topology / encryption_layer / restore_window_seconds / drill_cadence_days）の cross-product として宣言される preservation catalog の各 instance に対し、5 enforcement orchestrator のいずれかを必ず物理 pointer として bind し、restore_drill の last_green_at が drill_cadence_days 以内であることを Litmus chaos test + Kyverno admission policy で物理 enforce する meta-axis である。

## 位置づけ
- 採用 OSS（CloudNativePG / PostgreSQL / PgBouncer / Kafka(Strimzi) / Apicurio Registry / Valkey / ClickHouse / Rook+Ceph / Longhorn）、data 階層、09_data 配下の 8 方針メモが散在的に宣言する durability / replication_topology / encryption_layer / restore_window / drill_cadence を、機械可読な単一の真として一箇所に固定する仕様書
- 13 軸 + meta の 1 軸として、本仕様が tier1 / tier2 / tier3 / infra の各軸の永続化局面を統合する
- data が物理的に唯一の preservation facade として振る舞う

## 設計原則
- **preservation_class は bundle**: preservation_class 1 つの値が他 5 dimension（durability / replication_topology / encryption_layer / restore_window_seconds / drill_cadence_days）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**
- **5 種類 preservation orchestrator を全 preservation_class に必須化**: postgres_wal_streaming / kafka_replication_quorum / clickhouse_keeper_replication / ceph_multi_site / object_lock_compliance
- **restore_drill を物理 property とする**: drill_cadence_days 以内に必ず restore を実演し、宣言された RPO / RTO 内に収束
- **defense-in-depth は 5 層で構成する**

## v1 preservation_class セット（5 class）

| class | durability | replication_topology | encryption_layer | restore_window_seconds | drill_cadence_days |
|---|---|---|---|---|---|
| `v1_local_only` | local | none | at_rest_only | 14400 (4 h) | 180 |
| `v1_zone_replicated` | zone_quorum | sync_within_cluster | at_rest + column_envelope | 60 | 90 |
| `v1_cluster_replicated` | cluster_quorum | async_cross_cluster | at_rest + column_envelope | 300 (5 min) | 60 |
| `v1_cross_region_replicated` | region_quorum（C-priority during partition）| sync_cross_region | at_rest + column_envelope + topic_payload_envelope + kek_shamir_distributed | 300 (5 min) | 30 |
| `v1_global_replicated` | global_quorum | cell_partitioned_multi_region | at_rest + column_envelope + topic_payload_envelope + archive_triple_wrap + kek_shamir_distributed | 0 (per-cell continuous) | 14 |

### 各 class の不変条件と典型用途

#### v1_local_only
- 単一 zone 内の単一 instance。dev / stage / 検証用途
- CloudNativePG 1 primary（standby なし）、Kafka RF=1、ClickHouse 1 replica
- durability: local（fsync 完了で commit 確定、zone 障害で永続喪失の可能性）
- 本番業務は採用しない（infra topology v1_single_zone とのみ整合）

#### v1_zone_replicated
- 単一 region 内の複数 AZ（≥ 3 zone）にまたがる単一 cluster。本番業務の標準 default
- CloudNativePG 1 primary + 2 sync standby（zone 分散）、Kafka RF=3 ISR=2 rack 跨ぎ、ClickHouse 1 shard × 3 replica
- durability: zone_quorum（zone failure 時 quorum 維持で書き込み継続）
- replication_topology: sync_within_cluster（synchronous_commit=remote_write、min.insync.replicas=2 rack 跨ぎ）
- encryption_layer: at_rest（Longhorn LUKS）+ column_envelope（PII / monetary 列）
- restore_window: 60 秒（automatic recovery、新 primary 昇格）

#### v1_cluster_replicated
- 同 region 内の複数 cluster（≥ 2 cluster）が active-active
- CloudNativePG 内 zone_replicated + 別 cluster に async standby
- Kafka MirrorMaker2 cross-cluster mirror、ClickHouse 別 cluster の Distributed table 経由 async push
- durability: cluster_quorum（1 cluster 完全断でも他 cluster が即時 traffic 引受、async lag 分の data loss は容認）

#### v1_cross_region_replicated
- 複数 region（primary + standby ≥ 1）。standby region は読み取り可能だが書き込みは primary のみ
- CloudNativePG Replica Cluster で WAL streaming sync、Kafka MM2 strict-ordering、ClickHouse macro replicas、Ceph multi-site
- durability: region_quorum（**RPO ≈ 0**: partition 中の primary write を block）
- commit-after-crash visibility fence: pg_failover_slots + 二段 fencing token で可視性制御
- 本仕様は「partition 中 commit がゼロ」「ack 済 record の standby 到達率 100%」を物理 invariant として CI 検査
- commit latency: cross-region RTT に支配される物理制約あり

#### v1_global_replicated
- 複数 region（≥ 2）が active-active で並走。書き込み点は cell 単位で単一 region に固定

## 5 enforcement orchestrator
- `postgres_wal_streaming`: CloudNativePG Replica Cluster + WAL archive
- `kafka_replication_quorum`: Strimzi rack awareness + min.insync.replicas
- `clickhouse_keeper_replication`: clickhouse-keeper Raft
- `ceph_multi_site`: Ceph RGW multi-site sync
- `object_lock_compliance`: Ceph RGW Object Lock Compliance mode

## 単一の真

### `classes.yaml`（軸 5 preservation_class enum）

### `preservation_substrates.lock.yaml`（build artifact）
- 生成器: data instance catalog の単一の真
- input: classes.yaml + 各 instance の CR（CloudNativePG / Kafka / ClickHouse / Apicurio）
- 出力: instance ごとの preservation_class / orchestrator pointer / topology bind
- infra topology_class と双方向 lock

### `restore_drill.lock.yaml`（build artifact）
- 生成器: Litmus chaos test + drill orchestrator の実行結果
- 出力: instance ごとの drill 種別別 last_green_at / RPO/RTO 観測値

## 5 層 defense-in-depth
- 層 A: compile（CR / migration ファイルの preservation_class 注釈必須、sqlx prepare 通過）
- 層 B: lint（preservation_class 注釈の存在 / 値域検査 / preservation_substrates.lock.yaml と整合）
- 層 C: restore_drill chaos test（Litmus）
- 層 D: runtime（5 orchestrator の実 deploy）
- 層 E: physical（CloudNativePG synchronous_commit / Kafka min.insync.replicas / clickhouse-keeper Raft / Ceph CRUSH zone failure_domain / Longhorn LUKS の物理層強制）

## CI 不変条件
- 全 instance に preservation_class 注釈
- `preservation_substrates.lock.yaml` は build artifact と git の完全一致
- `restore_drill.lock.yaml` の全 cluster で last_green_at が drill_cadence_days 以内（v1_local_only を除く）
- 全 admission policy が build artifact から生成
- 全 entity table に tenant_id / version_id / created_at / updated_at / deleted_at 列
- 全 PII 分類列に envelope encryption 注釈
- 全 KafkaTopic に min.insync.replicas / replicationFactor / cleanup.policy / retention.ms が preservation_class 規定値
- 全 ClickHouse Replicated table に TTL clause
- infra topology_class と data preservation_class の bind 表が双方向 lock
- 全 schema migration が forward-only

## 1.0.0 ship blocker
- 5 preservation_class（v1_local_only を除く 4 class）全てで restore_drill green
- 全 採用 OSS が L1+ primary として `oss_inventory.lock.yaml` に登録
- Kyverno admission policy 完全適用
- infra01 failover_drill との AND-gate で同時 green

## 採用しない設計
- preservation_class dimension override: 禁止
- 単一 zone での本番運用: v1_local_only は dev/stage 専用
- destructive DDL の online 実行: expand-contract pattern のみ許容
- dual-write between heterogeneous stores: Outbox + CDC のみ
