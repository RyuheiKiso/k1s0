## 軸の同型構造（全 19 軸共通）

全 19 軸は以下の構造を持つ。これを持たない軸は axis_registry への登録不可。

| 必須要素 | 配置 |
|---|---|
| class bundle 定義 | `<軸>/classes.yaml` |
| 適合仕様 .md（≥ 1 件） | `04_詳細設計/01_適合仕様/<NN>_*.md` |
| 強制機構 .md | `04_詳細設計/02_強制機構/<NN>_<軸>強制機構.md` |
| lock.yaml（≥ 1 件） | `<軸>/*.lock.yaml`（build artifact 化必須） |
| defense-in-depth A〜E 層 bind | frontmatter `covered_by.defense_in_depth_layers` |
| 5 proof_class のいずれかの proof obligation | formal 軸が転写 |

## 新軸追加プロセス

新軸追加は次の AND-gate 全 pass が条件。1 つでも fail した場合は追加禁止。

1. **スロット確認**: axis_registry.lock.yaml の残スロット ≥ 1
2. **同型構造 6 要素の完備**: class bundle / 適合仕様 / 強制機構 / lock.yaml / defense A〜E / proof_obligation の全 6 件を新規作成
3. **P1 Meta exit criteria 通過**: axis_registry.lock.yaml の `last_green_at` が更新、release_gate cell の axis_registration が green
4. **依存方向の DAG 検査**: CI で循環依存ゼロを確認
5. **cross-cutting 適合仕様との接合宣言**: 新軸が cross-cutting 適合仕様のどの軸接合点に参加するかを depends_on で明示
6. **dual sign-off**: k1s0 作者 + formal 軸担当の 2 名が cosign で署名

## v2 以降の軸追加

v2 以降で残 1 スロットを使う場合は、上記プロセスに加えて **cap 引き上げの破壊的変更** として全 19 軸の release_gate を再評価し、v2 の 1.0.0 ship blocker を再設定する。

## 軸削除プロセス

軸の削除は次の手順を要する。削除は破壊的変更（cap 変動なし / スロット番号は tombstone として保持）。

1. `axis_registry.lock.yaml` の当該軸を `status: tombstone` に変更
2. 当該軸の全適合仕様・強制機構・lock.yaml を `status: deleted` に変更
3. cross-cutting 適合仕様から当該軸への depends_on を全て削除
4. CI で dangling 参照ゼロを確認
5. release_gate の当該 cell を `status: removed` に変更
6. dual sign-off（k1s0 作者 + security 軸担当）

## 軸登録 CI 不変条件

- axis_registry.lock.yaml の軸数が 20 超 → CI fail
- axis_registry.lock.yaml に記載された軸が同型構造 6 要素を欠く → CI fail
- axis_registry.lock.yaml が cosign 署名なし → admission block
- 新軸が P1 exit criteria AND-gate を未通過 → merge block

## 採用しない設計

- cap 超過（v1=20 を超える軸登録）
- 同型構造なしの軸追加（適合仕様なし / lock.yaml なし / proof_obligation なし）
- 軸名の変更（rename は tombstone + 新規追加の組合せ）
- single sign-off による軸追加（必ず dual sign-off）
