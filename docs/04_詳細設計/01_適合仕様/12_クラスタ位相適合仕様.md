# infra クラスタ位相適合仕様（v1）

## 一文定義
- クラスタ位相適合仕様は、5 topology_class × 5 dimension（blast_radius / failover_mode / data_consistency / control_plane_locality / drill_cadence_days）の cross-product として宣言される topology catalog の各 cluster に対し、5 failover orchestrator のいずれかを必ず物理 pointer として bind し、failover_drill の last_green_at が drill_cadence_days 以内であることを Litmus chaos test + Kyverno admission policy で物理 enforce する meta-axis である。

## 位置づけ
- infra 階層、08_infra 配下の 8 方針メモが散在的に宣言する fleet topology / failover mode / data consistency / blast radius / drill cadence を、機械可読な単一の真として一箇所に固定する仕様書
- 13 軸 + meta の 1 軸として、本仕様が tier1 / tier2 / tier3 / data の各軸の DR / failover 局面を統合する
- infra が物理的に唯一の topology facade として振る舞う

## 設計原則
- **topology_class は bundle**: topology_class 1 つの値が他 5 dimension（blast_radius / failover_mode / data_consistency / control_plane_locality / drill_cadence_days）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**: classes.yaml に登録された全 class、cluster_inventory.lock.yaml に列挙された全 cluster、failover_drill.lock.yaml に列挙された全 drill record が参照されなくなった時点で CI fail。Argo CD ApplicationSet のうち topology_class 注釈が無いものも CI fail
- **5 種類 failover orchestrator を全 topology_class に必須化**: kubernetes_pod_eviction / istio_locality_failover / metallb_bgp_failover / argo_rollouts_traffic_shift / external_dns_multi_region
- **failover_drill を物理 property とする**: drill_cadence_days 以内に必ず failover を実演し、宣言された RTO / RPO 内に収束する
- **defense-in-depth は 5 層で構成する**

## v1 topology_class セット（5 class）

| class | blast_radius | failover_mode | data_consistency | control_plane_locality | drill_cadence_days |
|---|---|---|---|---|---|
| `v1_single_zone` | zone | manual | strong_local | single | 180 |
| `v1_multi_zone_per_cluster` | cluster | automatic_within_window | strong_local | single | 90 |
| `v1_multi_cluster_active_active` | region | automatic_continuous | eventual_async | federated | 60 |
| `v1_multi_region_active_passive` | region | automatic_within_window | synchronous_replicated（C-priority during partition）| federated | 30 |
| `v1_multi_region_active_active` | global | automatic_continuous | cell_partitioned_synchronous | mesh | 14 |

### 各 class の不変条件と典型用途

#### v1_single_zone
- 単一 AZ 内の単一 cluster。dev / stage / 検証用途
- failover_mode: 手動。zone 障害は zone 復旧待ち、cluster 障害は再構築（OpenTofu replay）
- data_consistency: strong_local（PostgreSQL synchronous_commit=on / Ceph zone_replica=3）
- 本番業務は採用しない（DR 不可能なため）

#### v1_multi_zone_per_cluster
- 単一 region 内の複数 AZ（≥ 3 zone）にまたがる単一 cluster。本番業務の標準 default
- failover_mode: 自動 / 検出窓 30 秒以内
- data_consistency: strong_local（PostgreSQL synchronous_commit=remote_write、Ceph CRUSH map で zone_failure_domain、Kafka rack awareness）
- 典型: 本番 production cluster の default 採用

#### v1_multi_cluster_active_active
- 同 region 内の複数 cluster（≥ 2 cluster）が active-active で並走
- failover_mode: 自動 / 連続。1 cluster 完全断でも他 cluster が即時 traffic 全引受
- data_consistency: eventual_async
- 典型: region 内 HA を最大化、計画 maintenance を online で実施

#### v1_multi_region_active_passive
- 複数 region（primary + standby ≥ 1）。書き込みは primary region のみ、standby region は read-only replica
- failover_mode: 自動 / 検出窓 5 分以内
- data_consistency: synchronous_replicated（C-priority during partition）
- partition 中の不変条件: standby region 到達不能の窓では primary 側 write は physical block
- **RPO ≈ 0**（partition 中の primary write を block）、RTO ≤ 5 分
- 典型: 規制要件で cross-region DR が必須な業務、PII / monetary を扱う Service

#### v1_multi_region_active_active
- 複数 region（≥ 2）が active-active で並走。書き込み点は cell 単位で単一 region に固定

## 5 failover orchestrator
- `kubernetes_pod_eviction`: Pod 単位の eviction
- `istio_locality_failover`: L7 routing の zone / cluster / region 跨ぎ自動切替
- `metallb_bgp_failover`: cluster 全断時の BGP withdrawn / ECMP shift
- `argo_rollouts_traffic_shift`: progressive delivery と連動した traffic shift
- `external_dns_multi_region`: region failover 時の DNS weight 切替

## 単一の真

### `classes.yaml`（軸 5 topology_class enum）
- topology_class 5 enum 軸を宣言、purely additive

### `cluster_inventory.lock.yaml`（build artifact）
- 生成器: cluster catalog の単一の真
- input: classes.yaml + 各 cluster の OpenTofu state + Argo CD ApplicationSet
- 出力: cluster ごとの topology_class / failover orchestrator pointer

### `failover_drill.lock.yaml`（build artifact）
- 生成器: Litmus chaos test の実行結果
- 出力: cluster ごとの last_green_at / next_due_at / drill_status

### 共通制約
- 全 yaml は CUE schema で type 検証
- 全 yaml は cosign signed snapshot として periodic に publish

## 5 層 defense-in-depth
- 層 A: compile（Argo CD ApplicationSet / Kustomize overlay / Helm chart の topology_class 注釈必須）
- 層 B: lint（topology_class 注釈の存在 / 値域検査 / cluster_inventory.lock.yaml と整合）
- 層 C: failover_drill chaos test（Litmus）
- 層 D: runtime（5 orchestrator の実 deploy）
- 層 E: physical（kube-apiserver multi-AZ etcd quorum / Ceph CRUSH map zone topology / Kafka rack awareness / CloudNativePG Replica Cluster の物理層強制）

## CI 不変条件
- `cluster_inventory.lock.yaml` の全 cluster が topology_class 注釈持ち
- `failover_drill.lock.yaml` の全 cluster で last_green_at が drill_cadence_days 以内（v1_single_zone を除く）
- 全 Argo CD ApplicationSet に topology_class 注釈、注釈なし PR は CI fail
- topology_class dimension override の coding flag PR は Kyverno で reject
- 5 failover orchestrator が全 topology_class で必須化されていることを Conftest が検証

## 1.0.0 ship blocker
- 5 topology_class 全てで drill green（v1_single_zone を除く 4 class）
- 全 OSS が L1+ primary として `oss_inventory.lock.yaml` に登録
- Kyverno admission policy 完全適用
- `failover_drill.lock.yaml` の全 entry が drill_cadence_days 以内

## 採用しない設計
- topology_class dimension override: 禁止
- 単一 zone での本番運用: 禁止
- manual failover の本番採用: 禁止
- 商用 multi-cluster orchestration SaaS: 採用しない
