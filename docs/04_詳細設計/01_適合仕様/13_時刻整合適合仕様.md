# infra clock integrity 適合仕様（v1）

## 一文定義
- clock integrity 適合仕様は、5 clock_integrity_class × 5 dimension（sync_protocol / skew_tolerance / causality_discipline / ttl_clock_source / leap_second_strategy）の cross-product として宣言される clock catalog の各 node に対し、5 enforcement orchestrator のいずれかを必ず物理 pointer として bind し、clock_drill の last_green_at が cadence_days 以内であることを Litmus chaos test + eBPF probe + Kyverno admission policy で物理 enforce する meta-axis である。

## 位置づけ
- 採用 OSS（chrony / linuxptp / Cilium Tetragon / k1s0_hlc_lib / GPSD + LinuxPPS / Prometheus / Perses / OpenTelemetry Collector / Litmus / Kyverno）、infra 階層全 5 階層が依存する時刻同期 / 因果性 / TTL clock source / leap second 方針 / clock attack 防御を、機械可読な単一の真として一箇所に固定する仕様書
- canonical axis 04 (infra) の 2 spec の一つ（clock_integrity = spec 13）。cap v1=20 中 19 / 20、残 1 スロット
- infra 軸が物理的に唯一の clock SoR facade として振る舞う

## 設計原則
- **clock_integrity_class は bundle**: clock_integrity_class 1 つの値が他 5 dimension（sync_protocol / skew_tolerance / causality_discipline / ttl_clock_source / leap_second_strategy）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**: classes.yaml / clock_inventory.lock.yaml / clock_skew_matrix.lock.yaml / clock_drill.lock.yaml / clock_causality_proof.lock.yaml に登録された全 entry が参照されなくなった時点で CI fail。clock_integrity_class 注釈の無い node の Pod は Kyverno admission deny by default
- **5 種類 enforcement orchestrator を全 clock_integrity_class に必須化**: chrony_ntp_daemon / linuxptp_grandmaster_chain / k1s0_hlc_runtime / clock_skew_ebpf_probe / kyverno_clock_admission
- **clock_drill / leap_smear_drill を物理 property とする**: 30d 内に skew injection drill / 365d 内に leap smear drill を Litmus で実行
- **defense-in-depth は 5 層で構成する**

|---|---|---|---|---|---|

### 各 class の不変条件と典型用途

#### v1_intra_rack_ptp
- 同一 rack / 同一 AZ 内 node の clock 規律
- 用途: data01 cross-region replicated 系の write 経路、tier2 業務 saga / Outbox commit、09 audit hash chain emit、cross-AZ synchronous_replicated commit
- sync_protocol: ptp_ieee1588v2_boundary_clock。grandmaster は GPS-disciplined OCXO（rubidium holdover ≥ 24h）を rack ごとに ≥ 2 台二重化、PTP-aware HW timestamping NIC
- skew_tolerance: sub_microsecond_1us（intra-rack）/ sub_10us（intra-DC）
- causality_discipline: hlc_with_ptp_uncertainty_window
- ttl_clock_source: clock_monotonic_raw（Rust `MonotonicInstant` / Go `monotonic.Time` / .NET `MonotonicTimestamp`）
- leap_second_strategy: smear_24h_linear（Google 式 24h 線形 smear）
- active_node 数しきい値: ≥ 3 / cluster、grandmaster ≥ 2 / rack、PTP-aware NIC が node 全数 100%

#### v1_cross_dc_ntp_smeared
- cross-DC / cross-region node の clock 規律
- sync_protocol: chrony_multi_stratum1_gps。stratum-1 GPS source 最低 3 系統（Pool 不可）
- skew_tolerance: millisecond_5ms（cross-DC）/ sub_50ms（cross-region）
- causality_discipline: hlc_with_commit_wait（Spanner TrueTime 流の external consistency を commodity GPS-OCXO で代替）
- 典型: cross-region replication 経路の tier2 SoR、cross-DC OTel Collector / ClickHouse cluster 間の trace 連結

#### v1_application_hlc_only
- application 層で HLC を生成し、書き込み順序を local 単調増加で保証する

#### v1_browser_client_skew_tolerant
- browser client の clock を信頼しない
- server_issued_hlc_token_only: server 側で発行した HLC token のみを使用
- 用途: tier3 SPA / browser client 経由の業務 operation

#### v1_air_gapped_legacy
- air-gapped 環境（v2 候補）

## 5 enforcement orchestrator
- `chrony_ntp_daemon`: chrony NTP daemon
- `linuxptp_grandmaster_chain`: linuxptp の grandmaster chain（ptp4l / phc2sys / ts2phc）
- `k1s0_hlc_runtime`: 自製 HLC runtime（Rust / Go / .NET 等の言語別 wrapper）
- `clock_skew_ebpf_probe`: Cilium Tetragon の eBPF probe で kernel-level skew 検出
- `kyverno_clock_admission`: Kyverno admission policy で clock_integrity_class 注釈必須化

## 5 層 defense-in-depth
- 層 A: compile（Rust phantom type / Go monotonic wrapper / .NET MonotonicTimestamp struct、wall-clock 混入を compile reject）
- 層 B: lint（Conftest custom rule の 5 dcv_pr_blocks_*、Semgrep で wall-clock TTL API grep、GitHub Actions Required Status Check）
- 層 C: chaos test（Litmus で ±10s / ±60s skew 注入、GPS source kill、PTP grandmaster failover、leap second 仮想注入、ntpd BGP hijack 模擬の 5 blueprint、property test で HLC monotonicity / freshness / TTL 健全性を assertion）
- 層 D: runtime（Kyverno admission policy の 5 dcv_kyverno_blocks_*、node label 必須化）
- 層 E: 物理（GPS-disciplined OCXO grandmaster 二重化、PTP-aware NIC HW timestamping、PTP boundary clock switch、eBPF kernel-level skew probe、Rekor RFC3161 trusted timestamp authority）

## CI 不変条件
- 全 node に clock_integrity_class 注釈、注釈なしは Kyverno admission deny
- `clock_drill.lock.yaml` の last_green_at が cadence_days 以内（30d for skew、365d for leap smear）
- wall-clock TTL API（`SystemTime::now()` / `time.Now()` / `DateTime.UtcNow`）の TTL 判定使用ゼロ
- HLC tuple comparison が全 cross-rack span で実装済み

## 1.0.0 ship blocker
- 5 clock_integrity_class 全てで drill green
- HLC monotonicity / freshness の property test 全 cell green
- PTP grandmaster ≥ 2 / rack 物理配置完了
- GPS-disciplined OCXO の rubidium holdover ≥ 24h 維持

## 採用しない設計
- wall-clock TTL: 禁止（必ず monotonic clock）
- step（leap second）: production で禁止、smear のみ
- single GPS source: 禁止、stratum-1 GPS source 最低 3 系統
- clock_integrity_class dimension override: 禁止
