# 運用ループ適合仕様（v1）

## 一文定義
- 運用ループ適合仕様は、5 signal_class × 5 phase の cross-product として完全列挙される `ops_loop` catalog の各 cell に対し、5 action_class のいずれかを必ず物理 pointer として bind し、全 14 軸（13 軸 + meta + security）+ 自軸の defense-in-depth 層 D / E に bind 済みであることを 5 層 defense-in-depth + 17 項 CI 不変条件 + 15 件 stress test pack で物理 enforce する meta-axis である。

## 位置づけ
- 採用 OSS（Argo Rollouts / Argo CD / Argo Workflows / Tekton / Alertmanager / Sloth / Pyrra / 自製 escalation engine / incident.io OSS / flagd / OpenFeature / Mattermost）、ops 階層、08_ops 配下の 8 方針メモが散在的に宣言する operational signal / runbook / rotation / postmortem / change / toil の運用 lifecycle を、機械可読な単一の真として一箇所に固定する仕様書
- 14 軸 + meta + security + 本軸 の 1 軸として、本仕様が tier1 / tier2 / tier3 / infra / data / security の各軸の operational lifecycle 局面を統合する
- canonical axis 07 (ops) の単一 spec（運用ループ = spec 17）。cap v1=20 中 19 / 20、残 1 スロット

## 設計原則
- **signal_class は bundle である**: yaml に書く `ops.signal.*` attribute のうち、signal_class 1 つの値が他 4 dimension（severity_default / window_class_default / paging_budget_weight / postmortem_class）を一意に導出する
- **dimension override は禁止する**
- **dead spec を CI で殺す**: classes.yaml に登録された全 class、ops_loop に列挙された全 cell、runbook_catalog に列挙された全 runbook、alert_catalog に列挙された全 alert は、いずれも参照されなくなった時点で CI fail
- **5 種類 ops orchestrator を全 signal_class に必須化する**: argo_rollouts_canary / kyverno_admission_block / tekton_runbook_pipeline / alertmanager_routing / self_escalation_engine
- **drill cadence を物理 property とする**: `runbook_drill_cadence_days` 以内に必ず runbook を演習し、宣言された RTO 内に loop closure することを Litmus chaos test + Tekton dry-run で必ず検証
- **defense-in-depth は 5 層で構成する**

## 軸 class（5 class、signal_class を primary key として採用）

| signal_class | severity_default | paging_budget_weight | active action 数 (v1 cap) |
|---|---|---|---|
| `v1_slo_breach` | v1_page（≥ 14.4x で v1_freeze）| 1.0 | ≥ 30 |
| `v1_capacity_breach` | v1_page | 0.8 | ≥ 25 |
| `v1_change_induced` | v1_page（auto rollback trigger 時 v1_freeze）| 1.2 | ≥ 30 |
| `v1_dependency_outage` | v1_page | 0.7 | ≥ 25 |
| `v1_drill_failure` | v1_notify | 0.3 | ≥ 20 |

- 全 5 signal_class の active action 総数 ≥ 130（v1）

### 各 class の詳細

#### v1_slo_breach
- 13 SLO の error budget burn rate ≥ 6x で発火
- primary defense_layers: alertmanager_routing / tekton_runbook_pipeline / argo_rollouts_canary / kyverno_admission_block
- 最低限の cross-axis: tier1/13 SLO / 09 観測 / 14 OSS lifecycle
- 対応する drill_class: chaos_zone_partition / chaos_dependency_failure / restore_rpo_test

#### v1_capacity_breach
- per_tenant_volume / cluster headroom / partition capacity の hard threshold 違反
- 最低限の cross-axis: tier1/15 capacity / 32 data-tenant / data01 preservation
- 対応する drill_class: noisy_neighbor_simulation / capacity_forecast_breach

#### v1_change_induced
- deploy / migration / canary / topology change 直後の SLO 急変
- 最低限の cross-axis: tier1/08 migration / 12 schema / infra01 topology / data01 preservation
- 対応する drill_class: canary_breach_simulation / migration_pair_cutover_drill / topology_drift_drill

#### v1_dependency_outage
- 上位 / 下位 service / 外部 SaaS / IDP / DNS の unavailability
- 最低限の cross-axis: tier1/10 auth / 14 OSS lifecycle / infra01 topology
- 対応する drill_class: external_dependency_kill_drill / idp_outage_drill / dns_outage_drill

#### v1_drill_failure
- chaos drill / restore drill / red team drill で想定外 failure mode に到達
- 最低限の cross-axis: infra01 topology / data01 preservation / security01 threat

## 5 phase（signal の loop closure に対応）

| phase | 内容 | SLA |
|---|---|---|
| phase_1_detect | signal の発火 → on-call ack | page → ack ≤ 5 min（severity_freeze 時 ≤ 3 min）|
| phase_2_triage | incident class 確定 → IR ticket 起票 → Mattermost incident channel | ack → triage 完了 ≤ 30 min |
| phase_3_mitigate | 即時対処（auto rollback / manual rollback / throttle / freeze / runbook 起動）| triage → mitigation 開始 ≤ 5 min（freeze 時）/ ≤ 15 min（page 時）|
| phase_4_resolve | SLO budget 復活 / capacity 平常化 / customer impact 終了 → incident close | class 別 MTTR target |
| phase_5_postmortem | postmortem PR 起票 → review → action item branch out → merged | open ≤ 72h / merged ≤ 14d |

## 5 enforcement orchestrator

### argo_rollouts_canary
- 担当 signal_class: v1_change_induced（primary）/ v1_slo_breach（auto rollback）
- 主要 OSS: Argo Rollouts
- 起動 surface: Argo Rollouts AnalysisTemplate での SLO breach detection

### kyverno_admission_block
- 担当 signal_class: v1_slo_breach / v1_capacity_breach / v1_drill_failure
- 主要 OSS: Kyverno
- 起動 surface: admission webhook で deploy / migration / DDL block

### tekton_runbook_pipeline
- 担当 signal_class: 全 5 class
- 主要 OSS: Tekton Pipelines / Tekton Triggers
- 起動 surface: Alertmanager webhook → Tekton Trigger → Pipeline 自動起動

### alertmanager_routing
- 担当 signal_class: 全 5 class
- 主要 OSS: Alertmanager
- 起動 surface: alert routing tree / inhibition rule

### self_escalation_engine
- 担当 signal_class: 全 5 class
- 主要 OSS: Argo Workflows + Tekton Triggers + Mattermost（独立 ops-edge cluster 上）
- 起動 surface: 3 階層 escalation DAG（[ops_edge_cluster](../03_クロスカッティング適合仕様/10_ops_edge_cluster.md) と双方向 lock）

## 5 層 defense-in-depth
- 層 A: compile（PR の change_class 注釈必須、ops_loop.lock.yaml schema 通過）
- 層 B: lint（catalog の coverage / SLA / runbook ref / ownership entry / blameless 文体）
- 層 C: runbook_drill chaos test（Litmus + Tekton dry-run + chainsaw）
- 層 D: runtime（5 orchestrator の実 deploy）
- 層 E: physical（cosign signature / Kyverno admission webhook / Argo Rollouts pause / ops_event hash chain の物理層強制）
