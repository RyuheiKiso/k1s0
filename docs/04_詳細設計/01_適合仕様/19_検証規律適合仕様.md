# 検証規律適合仕様（v1）

## 一文定義
- 検証規律適合仕様は、5 verification_class × 5 phase の cross-product として完全列挙される verification_loop catalog の各 cell に対し、5 enforcement orchestrator のいずれかを必ず物理 pointer として bind し、全 17 軸 + 自軸（18 軸 = test を含む 19 軸から formal 軸を除いた軸）の defense-in-depth 層 C / D / E に bind 済みであることを 5 層 defense-in-depth + 18 項 CI 不変条件 + 16 件 stress test pack で物理 enforce する meta-axis である。同時に 18 axis × 5 verification_class = 90 cell の `coverage_matrix.lock.yaml` の全 cell `drill_state ∈ {v1_baseline_green, v1_drill_red_handled}` を 1.0.0 ship blocker として 00 meta `release_gate.lock.yaml` の AND-gate に物理入力する。

## 位置づけ
- 採用 OSS（pytest / Vitest / Hypothesis / fast-check / proptest / jqwik / FsCheck / gopter / Pact / Pact Broker / Playwright / Apache JMeter / Locust / Litmus / Toxiproxy / Chaos Mesh / pitest / mutmut / Stryker / cargo-mutants / go-mutesting / AFL++ / 言語別 fuzz tool / Testcontainers / chainsaw / kuttl）、test 階層、08_test 配下の 8 方針メモが散在的に宣言する verification claim / drill cadence / pact / chaos blueprint / property corpus / scenario journey / mutation score / performance baseline / regression corpus / flaky quarantine の検証 lifecycle を、機械可読な単一の真として一箇所に固定する仕様書
- 16 軸 + 本軸 の 1 軸として、本仕様が 17 軸の各軸の検証 lifecycle 局面を統合する（17 軸 + 自軸 = 18 軸 = 19 軸から formal を除く test 向けの軸数）
- canonical axis 09 (test) の単一 spec（検証規律 = spec 19）。cap v1=20 中 19 / 20、残 1 スロット

## 設計原則
- **verification_class は bundle**: verification_class 1 つの値が他 5 dimension（cadence_class / artifact_class / orchestrator_preference / coverage_weight / regression_corpus_class）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**
- **5 種類 enforcement orchestrator を全 verification_class に必須化**: pact_broker_pipeline / litmus_chaos_pipeline / mutation_pitest_pipeline / e2e_playwright_pipeline / coverage_gate_kyverno
- **drill cadence を物理 property とする**
- **defense-in-depth は 5 層で構成する**

## 5 enforcement orchestrator

### pact_broker_pipeline
- 担当 class: v1_contract_pair（primary）
- 主要 OSS: Pact / Pact Broker（self-host）/ Buf-breaking
- 起動 surface: Tekton Pipeline `pact-publish` / `pact-verify`、Pact Broker webhook

### litmus_chaos_pipeline
- 担当 class: v1_fault_chaos（primary）/ v1_scenario_replay（co-primary for drill_journey）
- 主要 OSS: Litmus + Toxiproxy + Chaos Mesh + 言語別 fuzz tool
- 起動 surface: Litmus workflow CR、Tekton Triggers

### mutation_pitest_pipeline
- 担当 class: 全 5 class の mutation testing（test の test）
- 主要 OSS: pitest / mutmut / Stryker / cargo-mutants / go-mutesting
- 起動 surface: Tekton Pipeline `mutation-run`

### e2e_playwright_pipeline
- 担当 class: v1_scenario_replay（primary）/ v1_property_axiom（補助 for browser property）
- 主要 OSS: Playwright + Apache JMeter + chainsaw
- 起動 surface: Tekton Pipeline `scenario-replay`、Argo Workflows orchestration

### coverage_gate_kyverno
- 担当: 全 verification_class の合流点として coverage_matrix の cell 状態を Kyverno admission policy 入力に bind、deploy 時に物理 enforce

## 5 phase（verification の closure）

| phase | 内容 |
|---|---|
| `phase_1_specify` | 軸 spec の `verification_claim` 段落で claim を verification_class + cadence + tool で宣言 |
| `phase_2_generate` | tool に応じて corpus / pact / scenario / chaos blueprint / mutation harness を生成 |
| `phase_3_execute` | Tekton Pipeline / Pact Broker / Litmus で execution、result artifact を生成 |
| `phase_4_triage` | flaky / regression / equivalent mutant の triage、artifact-signed PR で人間 reviewer + drill_owner ack |
| `phase_5_learn` | regression_corpus に append、mutation_score に反映、cell の last_green_at 更新 |

## 5 層 defense-in-depth
- 層 A: compile（PR の verification_class 注釈必須、coverage_matrix.lock.yaml schema 通過）
- 層 B: lint（catalog の coverage / cadence / ownership / regression_corpus / blameless 文体）
- 層 C: drill chaos test（Litmus + Tekton Pipeline + chainsaw + Playwright + Apache JMeter + Pact Broker）
- 層 D: runtime（5 orchestrator の実 deploy）
- 層 E: physical（cosign signature / Kyverno admission webhook / Ceph RGW Object Lock Compliance mode / test_event hash chain の物理層強制）
