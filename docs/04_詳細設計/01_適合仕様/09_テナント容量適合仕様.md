# tier1 テナント容量適合仕様（v1）

## 一文定義
- テナント容量適合仕様は、5 quota_class × 4 dimension（enforcement_layer / fairness_model / burst_window / exhaustion_response）の cross-product として宣言される quota catalog の各 instance に対し、4 階層 enforcement（envoy_local_rate_limit / library_token_bucket / oss_native_quota / storage_layer_quota / broker_layer）の物理機構で enforce し、noisy neighbor isolation を chaos test で物理検証する meta-axis である。

## 位置づけ
- 02_採用 OSS 一覧 Envoy Gateway / Istio / Kafka / KEDA / Temporal / Rook+Ceph / Longhorn、04_提供機能カテゴリ 全カテゴリの per-tenant 利用面、tier2 マルチテナント方針 / 信頼性運用準備（noisy neighbor / 公平性記述）/ テナント分離適合仕様、tier3 アプリケーション形態 / 端末オフラインデバイス、01_Bidi 適合仕様 messaging_bridge constraints の partition_count が散在的に宣言する per-tenant quota / fairness model / burst window / exhaustion response / enforcement layer を、機械可読な単一の真として固定
- 6 軸の最終、cross-axis enforcement integrator として、本仕様が transport / migration / observability / auth / key / schema / SLO / OSS lifecycle / data の各軸に跨る per-tenant 利用面を統合
- tier1 が物理的に唯一の quota facade として振る舞う

## 設計原則
- **quota_class は bundle**: class 1 値が他 4 dimension（`enforcement_layer` / `fairness_model` / `burst_window` / `exhaustion_response`）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**: Library 公開 API のうち `quota_class` 注釈が無いものも CI fail（quota 未宣言の API 追加を deny by default）
- **4 階層 enforcement を全 quota_class に必須化**: 同一 quota は複数層に分散しないが、同一 fleet では複数 class が複数層を併用
- **noisy neighbor isolation を物理 property とする**: 「1 テナントの burst が他テナントの SLO を破らない」を chaos test で必ず検証
- **defense-in-depth は 5 層**

## v1 quota_class セット（5 class）

| class | enforcement_layer | fairness_model | burst_window | exhaustion_response |
|---|---|---|---|---|
| `v1_per_tenant_qps` | envoy_local_rate_limit | per_tenant | short_1s | reject_429 |
| `v1_per_tenant_concurrency` | library_token_bucket | per_tenant_per_action | medium_1m | queue_with_timeout |
| `v1_per_tenant_volume` | storage_layer_quota | per_tenant | long_1h | overflow_to_cold |
| `v1_per_tenant_compute` | oss_native_quota | per_tenant_per_action | medium_1m | shed_by_priority |
| `v1_global_fair_queue` | broker_layer | global_share | continuous | partition_rebalance |

### 各 class の不変条件と典型用途
- `v1_per_tenant_qps`: per-tenant 単位の API QPS。Envoy Gateway の Local Rate Limit filter で enforcement、burst 倍率 2x まで許容、429 即時返却 + Retry-After
- `v1_per_tenant_concurrency`: per-tenant 同時実行上限（Library token bucket、Workflow concurrent execution、long-poll 同時保持数）。queue 滞留を許容、deadline 超過で打ち切り
- `v1_per_tenant_volume`: per-tenant ストレージ byte / event count / row count。Rook+Ceph + CloudNativePG + ClickHouse + Kafka 等の storage layer で enforcement。overflow_to_cold（hot SSD → cold S3=Ceph RGW）
- `v1_per_tenant_compute`: per-tenant CPU / GPU / memory（Workflow execution 時間、vector search QPS、ML inference 時間）。専用 OSS native quota（Temporal namespace 別 quota、KEDA scaledobject、pgvector workload pool）
- `v1_global_fair_queue`: 全テナント横断の公平 share。Kafka partition rebalance、broker layer での global I/O fairness、Istio destination rule の outlier detection

## dimension の根拠
- `enforcement_layer` は物理 enforcement の所在を決める（envoy_local_rate_limit / library_token_bucket / oss_native_quota / storage_layer_quota / broker_layer）。複数層に同 quota を分散すると整合性が崩れる
- `fairness_model` は per_tenant / per_tenant_per_action / per_workload / global_share の 4 種
- `burst_window` は exhaustion 検出の時定数（short_1s / medium_1m / long_1h / continuous）
- `exhaustion_response` は枯渇時の挙動（reject_429 / queue_with_timeout / overflow_to_cold / shed_by_priority / partition_rebalance）

## derived dimension（per-action threshold）を独立次元にしない理由
- per-action の閾値は class instantiate 時の instance 属性として宣言、build artifact が enforcement rule を生成

## 4 階層 enforcement の責務分離
- 階層 1: ingress（Envoy Gateway Local Rate Limit）— `v1_per_tenant_qps` の主担当。tenant_id を JWT claim から ingress filter で抽出
- 階層 2: Library token bucket（in-process）— `v1_per_tenant_concurrency` の主担当。Library 内の semaphore / token bucket
- 階層 3: OSS native quota — `v1_per_tenant_compute` の主担当（Temporal namespace 別、KEDA ScaledObject の per-tenant scope、pgvector workload group / connection pool quota、Apache Superset row limit）
- 階層 4: storage / broker layer — `v1_per_tenant_volume` と `v1_global_fair_queue`（Rook+Ceph namespace / pool quota、CloudNativePG tablespace metering、ClickHouse tenant 別 retention TTL、Kafka per-tenant topic quota + partition fairness）

## 単一の真（3 ファイル構成）

### `classes.yaml`（軸 quota_class enum）
- class bundle 定義

### `scenarios.yaml`（軸 catalog）
- scenario × quota_class → Litmus chaos scenario id + assertion id
- 主要 scenario: `noisy_neighbor_burst_does_not_break_neighbor_slo` / `qps_burst_returns_429` / `concurrency_queue_drains_under_deadline` / `volume_overflow_to_cold_succeeds` / `compute_priority_shed_correct_order` / `kafka_partition_rebalance_under_global_share`

### `enforcement_points.lock.yaml`（build artifact）
- 各 enforcement point（Envoy filter / Library token bucket / Temporal quota / KEDA / Kafka broker / Ceph）の static 自己宣言を tier1 build script が集約して生成。手書き禁止

## 5 層 defense-in-depth
- 層 A: compile 時（Library 公開 API は `quota_class` 注釈必須）
- 層 B: lint（`quota_class` 注釈の存在 / 値域検査）
- 層 C: noisy neighbor chaos test（Litmus）
- 層 D: runtime（4 階層 enforcement の実 deploy）
- 層 E: physical（storage layer reject / Kafka broker quota / KEDA scale-to-zero の物理層強制）

## CI 不変条件（merge 不可）
- 整合 1: `classes.yaml` の全 class が `scenarios.yaml` の Litmus chaos scenario でカバーされる
- 整合 2: `scenarios.yaml` の noisy neighbor isolation property assertion が green
- 整合 3: `enforcement_points.lock.yaml` は手書き禁止、build artifact と git の差分検出
- 整合 4: Library 公開 API のうち `quota_class` 注釈が無いものは CI fail
- 整合 5: client 軸の retry budget（[リトライバックオフ方針](../../03_概要設計/09_client設計方針/06_リトライバックオフ方針.md)）と `v1_global_fair_queue` の双方向 lock
- 整合 6: dead spec 検出

## 1.0.0 ship blocker
- 5 quota_class × 全 enforcement point の完全 conformance green
- noisy neighbor isolation chaos test で「1 テナント burst が他テナント SLO を破らない」property green
- 13 SLO 適合仕様 と双方向 lock（quota 違反時に SLO burn-rate alert が連動）

## 製造業 pack stress test（v1 の正当性証跡、8 業務シナリオ）
1. 業務担当 SPA の API burst（`v1_per_tenant_qps` で 429）
2. 注文一括投入（`v1_per_tenant_concurrency` で queue）
3. 図面アップロード（`v1_per_tenant_volume` で overflow_to_cold）
4. 在庫予測 ML inference 集中（`v1_per_tenant_compute` で shed_by_priority）
5. Domain Event burst（`v1_global_fair_queue` で partition_rebalance）
6. 隣接テナント burst 中の自テナント SLO 維持
7. Workflow 同時実行上限超過時の queue 順守
8. ClickHouse 集計 query slot 枯渇時の Apache Superset queue

## 採用しない設計
- quota_class dimension override
- Library 公開 API での quota 未宣言
- 同 quota の複数層分散
- per-tenant quota の文章運用（build artifact から enforcement rule を生成）
- 「特定テナントだけ quota 緩める」型の override
