# trace_ledger 体系

## 一文方針

`trace_ledger.lock.yaml` は docs 適合仕様（FR-ID）と src 実装（IMPL-ID）の semantic 対応関係を 6 層 trace skeleton として記録する build artifact であり、`release_gate.lock.yaml` の `meta.requirement_coverage_ratchet` / `meta.trace_coverage_ratchet` cell の評価根拠となる唯一の真である。

## 背景：mechanical green 問題

`release_gate.lock.yaml` の 83 cell は `count(lock.yaml, ...) >= N` による field 充足判定であり、docs 仕様 → src 実装の semantic 対応を確認していない。commit 履歴中「全 gap 解消」が 10 回以上反復された事実（1930 commit 中 161 件が audit 系）は、測定基盤が無いまま fix を回す構造的問題を示す。本体系はこの振動を物理的に止める。

## 6 層 trace ID skeleton

| 層 | ID | 正規表現 | 配置 |
|---|---|---|---|
| L1 business reason | `BR-<axis>-<NNN>` | `^BR-[a-z][a-z0-9_]*-[0-9]{3}$` | `docs/02_要件定義/02_機能要件` frontmatter |
| L2 functional req | `FR-<axis>-<NNN>` | `^FR-[a-z][a-z0-9_]*-[0-9]{3}$` | 適合仕様 frontmatter `trace.fr_ids` + 本文 `<span>` |
| L3 conformance spec | `detail.<axis>.<slug>` | 既存 frontmatter id | `docs/04_詳細設計/01_適合仕様/` |
| L4 implementation | `IMPL-<axis>-<NNNN>` | `^IMPL-[a-z][a-z0-9_]*-[0-9]{4}$` | src 言語別 attribute（R3 以降） |
| L5 test | `TEST-<axis>-<NNNN>-<vclass>` | 省略 | src/test/ attribute（R3 以降） |
| L6 proof | `PROOF-<axis>-<pclass>-<NNN>` | 省略 | src/formal/ annotation（R4 以降） |
| L6' evidence | `EVID-<sha256:16>-<kind>` | 省略 | build_evidence.lock.yaml（R5 以降） |

`axis` 部は `axis_registry.lock.yaml` の `axis_name` enum から動的 import。cap v1=20 → v2=30 スケール時も schema breaking なし（数字 cap_slot を ID から物理分離）。

## release_gate への 4 ratchet cell 統合

`generate_release_gate_v2.py` の `_CELL_CATALOG` に追加済みの 4 cell:

| cell_id | 閾値 | 対応 rollout |
|---|---|---|
| `meta.trace_skeleton_schema_locked` | `schema_version == v1` | R0 |
| `meta.requirement_coverage_ratchet` | `fr_to_spec_ratio >= 0.0` → R1: `>= 0.5` → R2: `== 1.0` | R1/R2 |
| `meta.trace_coverage_ratchet` | `fr_to_impl_ratio >= 0.0` (R3 以降有効) | R3 |
| `meta.proof_coverage_ratchet` | `impl_to_proof_ratio >= 0.0` (R4 以降有効) | R4 |

`ratchet_ge()` DSL 関数: 現在値 >= threshold かつ前回値以下への単調減少なしで green。これにより「audit → fix → 新 gap」の振動を物理的に殺す。

## docs 側 marker 追加手順（R1/R2 で実施）

適合仕様 .md の frontmatter に `trace` フィールドを追加:

```yaml
trace:
  fr_ids: ["FR-tier1-001", "FR-tier1-002"]
  br_ids: ["BR-tier1-001"]
  realized_by_specs: ["detail.tier1.auth_conformance"]
```

FR-ID 命名規約: `FR-<axis_name>-<NNN>` (axis_name は axis_registry の axis_name enum と整合)。例: `FR-tier1-001`, `FR-cross_http2-001`。

## docs_lint check [12] 対応

`tools/docs_lint/run_lint.py` に追加された check [12]:

- `trace.fr_ids` が存在する場合、各要素が `^FR-[a-z][a-z0-9_]*-[0-9]{3}$` パターンに適合することを検証
- パターン違反は CI fail
