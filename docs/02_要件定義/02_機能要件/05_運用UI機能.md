# 運用 UI 機能要件

## 一文方針
- 運用 UI は 8 軸別運用 UI（infra / data / security / ops / client / test / formal + 開発者体験統合）+ Backstage プラグインで機能要件として宣言する。Perses / Apache Superset / Jaeger v2 / Headlamp / Backstage TechDocs を主要 UI として採用、Grafana / Tempo / Loki（AGPL-3）は不採用。

## 8 軸別運用 UI
- [01_infra 運用 UI](../../04_詳細設計/04_運用UI開発者体験/01_infra運用UI.md): cluster 状態 / topology / failover_drill / Headlamp
- [02_data 運用 UI](../../04_詳細設計/04_運用UI開発者体験/02_data運用UI.md): preservation / restore_drill / Apache Superset
- [03_security 運用 UI](../../04_詳細設計/04_運用UI開発者体験/03_security運用UI.md): threat catalog / audit search / KEK shamir ceremony
- [04_ops 運用 UI](../../04_詳細設計/04_運用UI開発者体験/04_ops運用UI.md): SLO dashboard / on-call rotation / incident response / Perses
- [05_client 運用 UI](../../04_詳細設計/04_運用UI開発者体験/05_client運用UI.md): SDK 開発者 inner loop / Tilt / Companion local mock / Pact
- [06_test 運用 UI](../../04_詳細設計/04_運用UI開発者体験/06_test運用UI.md): coverage matrix / mutation score / regression corpus
- [07_formal 運用 UI](../../04_詳細設計/04_運用UI開発者体験/07_formal運用UI.md): proof matrix / counter-example list / reviewer queue
- [08_開発者体験統合](../../04_詳細設計/04_運用UI開発者体験/08_開発者体験統合.md): Backstage 統合、Software Template、ChatOps

## 主要 OSS
- **Backstage**: 開発者ポータル、tech docs、Software Template
- **Headlamp**: K8s Web UI
- **Perses**: メトリクス可視化（Grafana の代替）
- **Apache Superset**: ad-hoc SQL（ClickHouse）
- **Jaeger v2**: トレース UI（内蔵 ClickHouse storage）
- **Mattermost**: ChatOps（Slack の代替）

## 業務管理 UI（Backstage プラグイン）
- マスタ管理 / 監査検索 / 緊急対応 / schedule 編集 / partner 連携設定
- tier3 業務 UI と物理分離

## 受入条件
- 8 軸別運用 UI の動作確認
- Backstage Software Template で tier3 / tier2 リポジトリ生成 green
- ChatOps で `/ops`, `/formal review-assign`, `/formal break-glass` 等の slash command 動作
- AGPL-3 OSS（Grafana / Tempo / Loki）の不採用が CI 検査 green
