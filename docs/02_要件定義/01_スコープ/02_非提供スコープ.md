# 非提供スコープ

## 一文方針
- 本ドキュメントは 19 軸の各軸の `03_非提供スコープ.txt` を集約 view として「明示的に提供しない機能 / 設計 / OSS」を宣言する。各非提供は理由 + 例外 + 委譲先（他軸 / 外部）の 3 点 set で記述し、open-ended 例外を構造的に拒否する。

## 至高路線における立ち位置
- 「採用しない設計」を全面明示する。「特別な事情があれば採用する」のような open-ended 例外は禁止。
- 非提供スコープは「機能削減」ではなく「責務分割」である。委譲先が必ず存在する。

## 軸別非提供スコープ

### tier1 軸

#### 採用しない設計（OSS / tooling）
- **業務固有領域の Library 抽象**: tier3 業務ロジック / UI / 画面遷移制御は Library 非提供
- **Operator / Controller の Library 配布**: Go で別途実装、Library パッケージ非提供
- **可視化 UI の Library 抽象**: Perses / Apache Superset / Jaeger v2 はプラットフォーム側で運用、Library 非提供
- **Service Mesh（Istio）機能の Library 再露出**: mTLS / トラフィック制御はメッシュが透過的に担う、Library は認証 / トレースコンテキスト伝播のみ
- **ブロックストレージ（Longhorn / Ceph RBD）の Library 抽象**: tier2 / tier3 は K8s PVC 経由
- **証明書 / PKI（cert-manager）の Library 抽象**: プラットフォーム側で発行・配布、Library は受領済み TLS コンテキストを利用するのみ
- **開発体験 / 運用ツールの Library 配布**: Backstage / Testcontainers / Tilt / Helm / Kustomize / sqlx-cli はテンプレート / ドキュメントで案内
- **L3 / L2\* で OSS 概念の API 表面露出**: L1+ 露出概念 allowlist 外の OSS 型が公開シグネチャに現れたら CI fail
- **day-1 multi-backend 並走**: L1+ は OSS ライフサイクルイベント時のみ移行 toolchain 起動
- **自製 WebSocket bidi**（gRPC 公式仕様外、Connect-RPC L1+ 単一深耕）
- **HashiCorp Vault**（BUSL、OpenBao 一本）
- **OPA Gatekeeper**（Kyverno L1+ 単一深耕）
- **HTTP/2 prior-knowledge accept / cleartext h2c**（業務 listener は ALPN h2 必須）
- **HTTP/1.1 業務 ingress**（v1_legacy_http11 専用 listener のみ別ポートで残存）
- **`google.protobuf.Any` の External Proto 直接利用**（既知型 oneof / `bytes` + content_type に置換）
- **Transcoder upstream の SSE 派生 option 依存**（tier1 Rust ハンドラ内で SSE フレーミングを直接生成）
- **External Proto への streaming RPC 直接公開**（射影マップで unary / SSE に変換）
- **External / Internal Proto 二重表現の Internal 側曲げ**（External 経路の都合で Internal を曲げない）
- **`v1_inhouse_authoritative` 以外での自製禁止**（OSS 採用 + 移行コミットメントが原則）

#### 委譲する責務（他軸 / 外部の所有）
- **infra 階層**: cluster 構築 / cluster 位相 / Operator 基盤運用
- **data 階層**: persistence / preservation_class / lifecycle
- **security 階層**: 脅威モデル / supply chain attestation / incident response
- **ops 階層**: 運用 loop / on-call / postmortem
- **client 階層**: SDK 配布 / Companion / SDK 開発者 inner loop
- **business logic / 業務エラーカテゴリ**: tier2 / tier3
- **UI コンポーネント**: tier3 SPA
- **業務固有 schema / aggregate**: tier2 / tier3（aggregate_qualified_name は tier1 が単一所有）
- **OS 固有依存（APNs / FCM / WinHttpHandler 等）**: ops-edge / Companion の例外規律
- **mathematical proof（formal）**: formal 軸（tier1 適合仕様の proof 化を formal 軸が担う）

#### 採用しない設計（運用 / 規律）
- conformance_class / auth_class / key_class / schema_class / slo_class / lifecycle_class / quota_class / sdk_distribution_class の dimension override
- Library 公開 API snapshot drift（codemod / migration の不在で merge）
- 4 primary pair の dry_run cadence（365 日）超過のままの release
- L2\* 同族 conformance test の片側 only green での merge
- KEK shamir M-of-N の単一 region 復元 API 呼出（admission block）

- 手書き build artifact（`capabilities.lock.yaml` / `dry_run.lock.yaml` / `instruments.lock.yaml` / `enforcement_points.lock.yaml` / `backends.lock.yaml` / `idp_capabilities.lock.yaml` / `oss_inventory.lock.yaml` / `registries.lock.yaml`）

### security 軸

#### 採用しない設計（OSS / tooling）
- **商用 EDR / XDR / SIEM SaaS**（CrowdStrike / Splunk Enterprise Security 等）: 採用しない
    - 理由: vendor lock-in 回避と本企画の audit SoR = ClickHouse 一本化方針のため、本番 audit / detection は ClickHouse + Vector + Falco の OSS 経路に固定
- **Wazuh**: 採用しない
    - 理由: Elastic 依存（Elasticsearch indexer）と本企画の OpenSearch / Elasticsearch 不採用方針が衝突。Falco + Tetragon + Vector + ClickHouse で吸収
- **HashiCorp Vault**: 採用しない
    - 理由: BUSL のため、シークレット管理は OpenBao（MPL 2.0 fork）に固定
- **Anchore Enterprise / Sysdig Secure / Aqua Security 商用版**: 採用しない
    - 理由: SBOM / image scan は Trivy + Grype + Syft、runtime 検知は Falco + Tetragon の OSS 経路で吸収
- **GitHub Advanced Security（商用 license の SAST 部分）**: 採用しない
    - 理由: SAST / secret scan は Semgrep + gitleaks + trufflehog の OSS 経路で吸収
- **JFrog Xray**: 採用しない
    - 理由: image scan は Trivy で吸収、Harbor 経由の Trivy integration を default
- **独自 audit DB / immudb 単独運用**: 採用しない
    - 理由: audit_event SoR は ClickHouse + Ceph RGW Object Lock の組合せで吸収

### formal 軸

#### 採用しない設計（OSS / tooling）
