# 提供スコープ

## 一文方針
- 本ドキュメントは 19 軸（tier1 / tier2 / tier3 / infra / data / security / ops / client / test / formal + クロスカッティング適合仕様 + meta）の各軸の `01_責務.txt` を集約 view として提供スコープを宣言する。1.0.0 で提供する全機能 / 規律 / artifact をここに完全列挙し、機能削減（CLAUDE.md「機能削減なし」違反）を構造的に拒否する。

## 至高路線における立ち位置
- 「機能削減なし」: 本スコープから機能を削除する場合は、必ず非提供スコープへ移送 + 移送理由 + 委譲先（他軸 / 外部）の 3 点 set を明示する。
- 「段階的 release 禁止」: 本スコープに列挙された全機能が 1.0.0 ship 時点で提供される。一部を v2 に先送りする経路は持たない。

## 軸別提供スコープ

### tier1 軸
詳細は [tier1 設計方針 index](../../03_概要設計/02_tier1設計方針/README.md) を参照。

#### 提供する機能 / artifact
- **infra 隠蔽の単一 facade**: tier2 / tier3 から OSS クライアントの直接 import を 4 層（依存導入 lint / 公開 API snapshot / 内部 registry / Cosign signed）で物理拒否
- **Server 系 5 分類**: Gateway（Envoy + Rust ハンドラ）/ Sidecar（Outbox relay 等、Rust 常駐）/ Backend-for-Library（Token 検証集中点、Rust gRPC）/ Control Plane（flagd 連携、Rust）/ Operator（Go controller-runtime）
- **Library 3 抽象レベル × 17 機能カテゴリ**: L3（Logging / Tracing / Metrics / Auth / Secret / KV / ObjectStore / RPC）/ L2\*（Profiling / FeatureFlag / SchemaRegistry）/ L1+（Messaging / Vector / Workflow / Rule / Relational）
- **L1+ 移行コミットメント**: 4 primary pair（CloudNativePG↔StackGres、Kafka↔RedPanda、Temporal↔Cadence、ZEN↔自製 DSL backend）の dry_run green を 1.0.0 ship 前 + 年次で物理 enforce
- **L2\* 同族 conformance**: 各 L2\* カテゴリで 2 実装 Testcontainers conformance test green を merge 条件
- **Companion（Library 非対応言語向け）**: 役割 A（Observability / 認証コンテキスト伝播、CLR Profiler attach + `k1s0.Companion.NetFx.OTelExt`）+ 役割 B（Transport Negotiation Runtime、6 adapter）
- **`k1s0.Connect.NetCore`**: v1_inhouse_authoritative、.NET 8 LTS 向け Connect-RPC 実装、Connect Conformance Suite 全 case green が ship blocker
- **Proto 二層化（External / Internal）**: gRPC-JSON Transcoder unary 派生 + tier1 Rust ハンドラ SSE 直接生成。長期は単層 + transport ladder へ collapse
- **Transport Adapter Layer**: 8 adapter（grpc_native / connect_bidi / grpc_web / web_transport / sse_paired / paired_post_sse / long_poll / webhook / messaging_bridge）× 5 conformance_class × 9 scenario で意味論的等価性を CI で物理証明
- **Capability Negotiation**: `client_capabilities` ∩ `proto.conformance_class` から `chosen_transport` を決定論的に選択
- **Resume / Replay の transport 非依存化**: server-assigned monotonic seq + `resume_token = (session_id, last_ack_seq)` で transport 跨ぎ session 継続
- **9 適合仕様**: Bidi / 移行 Pair / 観測 / 認証 / 鍵管理 / スキーマ進化 / SLO / OSS lifecycle / テナント容量
- **HTTP/2 + HTTP/3 ingress 強制**: per-tab 16 subscription を multiplex で達成、`v1_legacy_http11` は別ポート listener に分離
- **KEK Shamir 分散保管（M-of-N、N=5、M=3）**: cross-region 鍵冗長、ceremony runbook、annual drill
- **Apicurio Registry GitOps SoT**: Apicurio Registry instance を git lock の物理 cache として再定義、`block-direct-apicurio-write` admission policy で強制

#### 提供する SLO（13 SLO 軸への登録）

- `v1_request_latency_p99`: p99 ≤ class.target / 30d

詳細は [tier2 設計方針 index](../../03_概要設計/03_tier2設計方針/README.md) を参照。

#### 提供する機能 / artifact

- **業界中立性の 3 種機械的担保**（命名禁則 / 依存方向 / stub conformance）
- **bounded context（製造業）**: FA / 調達 / 検査 ドメイン + 共通モジュール（設備 / ロット / 品目 / 拠点 / BOM）
- **cross-domain 参照は Domain Event 経由のみ**（直接参照 CI deny）
- **business asset の owned by tier2 + tier3 override 拡張点**（YAML 宣言 + Pact contract test）
- **マルチテナント方針**: 共有 Pod / 共有 DB default、行レベル `tenant_id` 列による分離、専用 Service への昇格条件
- **テナント識別子強制注入**: tier2 リポジトリ抽象が `tenant_id` 述語を強制注入、業務コードからの省略を不可能化
- **4 テーブル class**（`tenant_scoped` / `tenant_master` / `platform_global` / `pii_segregated`）+ PostgreSQL Row Level Security FORCE
- **session_context 4 GUC**（`app.tenant_id` / `app.actor_id` / `app.purpose` / `app.delegation_chain`）
- **atomic 三表書込**（State change + Outbox + Audit を同一 DB トランザクションに書く、subscribe 失敗で audit 欠落を構造的に不可能化）
- **audit_local schema**（PII 構造的不在）+ hash chain（`hash_prev` / `hash_self`）+ 外部公証 attestation
- **Domain Event emit 必須化**: aggregate 状態変更は必ず Domain Event 経路に乗る、emit 抑制 API を tier2 公開 API に置かない
- **権限モデル**: Keycloak ABAC、Delegation、Emergency Override、impersonation chain
- **Library 形態 / Service 形態の二配布**: 共通 conformance test suite で両方 green を merge 条件
- **共有 Pod / DB の SLO 保護四層 + 自動昇格 trigger**: per-tenant rate limiter / cgroup quota / PG pool tenant 分離 / Kafka quota + 5 min 以内の専用 Pod / DB へ promote
- **`protoc-gen-k1s0-go-fsm`**: Rust / C# / TS と同等の compile-time 不正遷移防止を Go の typestate via nominal types で達成（v1_inhouse_authoritative）
