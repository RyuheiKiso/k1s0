# 観測可能性要件

## 一文方針
- 5 signal class（logs / metrics / traces / profiles / audit）× 4 dimension layer（core / tier1_ext / tier2_ext / tier3_ext）+ trace_id を primary key とする cross-signal cross-tier 相関 + PII redaction の単一の真 を必須要件とする。

## 5 signal class
- **logs**: ClickHouse `logs` table（trace_id top-level）
- **metrics**: Prometheus（exemplar に trace_id 必須）
- **traces**: ClickHouse `traces` table + Jaeger v2 first-party storage
- **profiles**: Parca（trace_id label）
- **audit**: ClickHouse `audit` table（PII 構造的不在、hash chain）

## 4 dimension layer
- **core**: OTel Semantic Conventions base
- **tier1_ext**: `tier1.bidi.*` / `tier1.transport.*` / `tier1.oss.exposed.*`
- **tier2_ext**: `tier2.tenant.id` / `tier2.aggregate.id` / `tier2.business_event` / `tier2.purpose`
- **tier3_ext**: `tier3.screen.id` / `tier3.interaction.kind` / `tier3.web_vitals.*` / `tier3.layer`

## trace_id を primary key
- W3C Trace Context（traceparent / tracestate）+ Baggage を全 RPC / queue / IPC で propagate
- tier3 RUM → BFF → tier1 → tier2 → data の全層で 1 trace に統合
- cross-signal join: ClickHouse 側で trace_id 列の equi-join

## PII redaction
- `redaction.yaml` で PII field を 1 箇所に列挙
- OTel Collector で物理削除
- Library / Companion / app code に同等処理を持たせない

## 観測 Collector の 2 段 pipeline
- 段 1: per-node DaemonSet（loadbalancingexporter で trace_id routing）
- 段 2: gateway-aggregator Deployment（tail_sampling processor + clickhouseexporter）

## 受入条件
- 5 signal class × 4 dimension layer の完全 coverage
- PII redaction property test 全 signal green
- 観測 Collector 2 段 pipeline の HPA + consistent hashing が production load で green
- AGPL-3 OSS（Grafana / Tempo / Loki / k6）の不採用が CI 検査 green
