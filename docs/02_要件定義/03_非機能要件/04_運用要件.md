# 運用要件

## 一文方針
- 本ドキュメントは ops 軸（13 軸 + meta + security の上位 meta-layer）の運用要件を集約する。1.0.0 ship 時点で 5 signal_class × 5 phase = 25 cell の ops_loop catalog 完備、SRE 50% rule 維持、postmortem backlog ゼロ、quarterly toil monotonic decrease を要件として宣言する。

## 至高路線における立ち位置
- 「文章で運用」を禁止し、全 ops 規律を build artifact + Kyverno admission policy + cosign signature の物理機構に転写
- 「page が増えると on-call が疲弊する」を理由に operational signal coverage を縮小しない
- 「postmortem の merge を待っていると速度が落ちる」を理由に ship blocker を緩めない
- 段階的 release を禁止、1.0.0 で全 signal_class が 5 phase 全 closure green

## 機能要件

### 運用ループ要件
- 5 signal_class × 5 phase = 25 cell の完全列挙
- 各 cell に物理 action pointer ≥ 1
- 詳細: [運用ループ適合仕様](../../04_詳細設計/01_適合仕様/17_運用ループ適合仕様.md)

### SLO 駆動運用要件
- MWMBR（multi-window multi-burn-rate）alert を全 SLO に適用
- 5 段階運用 action（observe / notify / page / freeze / rollback）
- error budget burn rate threshold の物理発火（Alertmanager → Argo Rollouts / Argo CD / Kyverno）

### アラート要件
- 5 severity（observe / notify / page / freeze / security_bridge）
- page-level alert の 1:1 runbook coverage
- noise budget ≤ 5% false positive、≤ 1% false negative

### オンコール要件
- 24×365 の 3 階層 escalation（primary / secondary / domain expert）
- rotation gap zero（v1_zero_gap または v1_auto_covered_gap [60 分 cap]）
- fatigue budget 違反ゼロ
- handover document 必須

### インシデント対応要件
- 5 incident class × 6 phase lifecycle 完備
- MTTR SLO target（class 別）
- IR command roles 4 役割（IC / CL / SME / scribe）

### postmortem 要件
- 全 incident（severity = notify 以上）に postmortem PR
- 72h open SLA + 14d merged SLA
- 6 必須 section（Summary / Timeline / RCA / Mitigation / Action Items / Metrics）
- blameless 原則 + Semgrep custom rule で文体 lint

### 変更管理要件
- 5 change class（routine / schema / topology / security_critical / emergency）
- progressive delivery（canary / blue-green / rolling）+ auto rollback
- AnalysisTemplate generator output と一致

### runbook 要件
- 5 runbook class（alert / incident / break_glass / drill / change）
- 二段構え（Backstage TechDocs + Tekton Pipeline）
- Markdown only allow cap 5%
- drill cadence 内 green 維持

### toil 削減要件
- SRE 50% rule（個人別 / team 別 toil ≤ 50%）
- quarterly target ≥ 5% 減少 monotonic
- automation backlog の P0 item ship blocker

## 非機能要件

### SLO target（13 SLO 軸 と connect）
- `v1_oncall_page_per_week ≤ 3`
- `v1_team_page_per_week ≤ 5 × team_size`
- `v1_oncall_after_hours_page_per_month ≤ 5`
- `v1_oncall_consecutive_days ≤ 7`
- `v1_individual_toil_ratio ≤ 0.50`
- `v1_team_toil_ratio ≤ 0.50`
- `v1_runbook_drill_compliance`: 100%
- `v1_postmortem_sla_compliance`: 100%（72h open / 14d merged）
- `v1_break_glass_count`: 監視のみ（target なし、増加トレンドが root cause analysis trigger）
- `v1_mttr_slo_p95`: incident class 別 target

### 可用性 / 災害対策
- ops-edge escalation cluster: target cluster outage 時にも escalation 物理発火
- 3 階層 escalation の二重化（自製 engine + ops-edge）
- audit_ingest_gap_monitor の dead-man via ops-edge

### コンプライアンス
- 全 operator action（break-glass / approval / override / rotation swap）を audit_event subject に emit
- audit_event の immutability（preservation_class v1_zone_replicated 以上 + 7 年 retention）
- postmortem PR の永続 retention（preservation_class v1_zone_replicated 以上）

## 受入条件（1.0.0 ship blocker）
- 全 5 signal_class × 5 phase = 25 cell の物理 action pointer 完備
- `ops_loop.lock.yaml` の `closure_green = true`
- postmortem backlog ゼロ
- toil quarterly target monotonic decrease 維持
- ops-edge cluster 上の自製 escalation engine が target cluster outage 時にも page 物理発火（drill green）
- 15 件 stress test pack 全 green
- `release_gate.lock.yaml` の ops cells 全 green

## 制約と前提
- 商用 incident management SaaS（PagerDuty / Opsgenie の有償 SLA）採用しない
- 商用 APM / observability SaaS（DataDog / New Relic / Honeycomb）採用しない
- AGPL-3 OSS（Tempo / Loki / Grafana / Grafana k6 / Grafana OnCall）採用しない
- 段階的 release 禁止
- big-bang deploy 禁止
- 単窓 alert 禁止（MWMBR 必須）
