# 検証規律要件

## 一文方針
- 本ドキュメントは test 軸（実行ベース検証）+ formal 軸（数学的証明）の 2 軸が要件定義レベルで提供する「検証規律」要件を集約する。1.0.0 ship 時点で 18 axis × 5 verification_class = 90 cell の coverage matrix（test 軸）+ 19 axis × 5 proof_class = 95 cell（proof_matrix 基底）の proof matrix（formal 軸）が完備、両 matrix の双方向 lock drift = 0、reviewer dual sign-off 100% を要件として宣言する。

## 至高路線における立ち位置
- 「文章で運用」を禁止し、全検証規律を build artifact + Kyverno admission policy + cosign signature の物理機構に転写する。
- 「proof は完成が難しいから後回し」「critical invariant の証明は v2 で良い」を禁止し、1.0.0 ship blocker に物理 bind する。
- 「実行で発見されない潜在反例」を数学的に impossible にする層 F enforcement を要件として要求する。

## test ↔ formal 双方向 lock 要件
- test 軸の v1_property_axiom cell と formal 軸の v1_temporal_safety_proof / v1_program_correctness_proof cell は cross-cutting に bound
- property test の corpus は proof obligation の instance、proof obligation は property の axiom 形式
- 双方向 lock drift は CI fail
- counter-example で発見された input は test 軸の `regression_corpus.lock.yaml` に物理転写、property test の seed pool に追加

## 検証規律 cadence 要件

### 日次（daily）
- reproducibility checker: 全 verified proof を再 run、certificate hash 一致確認
- proof_event hash chain online verification

### 週次（weekly）
- v1_temporal_safety_proof: 7 day cadence
- v1_program_correctness_proof: 7 day cadence
- v1_runtime_modelcheck_proof: 7 day cadence

### 隔週（biweekly）
- v1_temporal_liveness_proof: 14 day cadence
- v1_refinement_proof: 14 day cadence

### 月次（monthly）
- mathlib upstream pull drill

### 四半期（quarterly）
- bound parameter review drill
- proof_minutes_per_quarter / verified_theorem_count / counter_example_open_count / proof_artifact_size_bytes metric の monotonic 評価

### 半年（6 month）
- tool major version migration drill（TLA+ / Apalache / Stainless / Dafny / Lean 4 / Kani / CBMC）

## 受入条件（要件として）
- 全 95 cell（proof_matrix 基底）が `proof_inventory.lock.yaml` に entry 登録済み
- 全 95 cell（proof_matrix 基底）が `proof_status.lock.yaml` で `cell_state` ∈ {v1_baseline_verified, v1_accepted_with_assumption, v1_unverified_handled}
- 全 entry が dual reviewer cosign signature 完備
- counter-example open entry が close_due_at 以内に closure
- assumption / accepted_as_bug / termination_exempt の各 cap 内
- `release_gate.lock.yaml` の formal cells 全て green

## 制約と前提
- TBD は禁止（status: locked への昇格時に解消必須）
- 「論文引用のみ」「文章のみで証明済み」は禁止
- 商用 proof assistant / model checker は採用しない
- LLM 単独 sign-off は禁止
- 段階的 release は禁止
