# 可用性災害対策

## 一文方針
- 本ドキュメントは infra + data + ops + security の cross-axis cross-axis として「可用性 / 災害対策 / 時刻整合 / restore drill」要件を集約する。1.0.0 ship 時点で 5 topology_class（v1_single_zone を除く 4 class）全てで failover_drill green、5 preservation_class で restore_drill green、5 clock_integrity_class で clock_drill green、ops-edge cluster 経由の escalation 物理発火 を要件として宣言する。

## 至高路線における立ち位置
- 「現実的に運用が楽」を理由に scope を縮小しない（CLAUDE.md「至高路線」）
- 段階的 release 禁止
- 単一 zone での本番運用禁止
- manual failover の本番採用禁止
- ops-edge cluster による self-observation invariant 担保（target cluster outage 時にも escalation 物理発火）

## topology_class 要件（infra）
詳細: [クラスタ位相適合仕様](../../04_詳細設計/01_適合仕様/12_クラスタ位相適合仕様.md)

| class | drill cadence | RPO | RTO | 用途 |
|---|---|---|---|---|
| `v1_single_zone` | 180 day | - | - | dev / stage（本番不可）|
| `v1_multi_zone_per_cluster` | 90 day | strong_local | 30 sec 以内 detect | 本番 default |
| `v1_multi_cluster_active_active` | 60 day | eventual_async | 即時 traffic 全引受 | region 内 HA 最大化 |
| `v1_multi_region_active_passive` | 30 day | ≈ 0（partition 中の primary write block）| ≤ 5 分 | 規制要件で cross-region DR 必須 |
| `v1_multi_region_active_active` | 14 day | cell_partitioned_synchronous | automatic_continuous | global active-active |

## clock_integrity_class 要件（infra）
詳細: [時刻整合適合仕様](../../04_詳細設計/01_適合仕様/13_時刻整合適合仕様.md)

|---|---|---|---|
| `v1_intra_rack_ptp` | ptp_ieee1588v2_boundary_clock | sub_microsecond_1us | 30 day（skew injection）/ 365 day（leap smear）|

| `v1_application_hlc_only` | inherit | inherit | inherit |

## preservation_class 要件（data、Phase 2 で詳述）
詳細: [データ保全適合仕様](../../04_詳細設計/01_適合仕様/14_データ保全適合仕様.md)

- 5 preservation_class（v1_single_zone / v1_zone_replicated / v1_cross_zone_replicated / v1_cross_region_replicated / v1_audit_log）
- restore_drill cadence: preservation_class 別

## ops 要件（cross 参照）
詳細: [ops 設計方針](../../03_概要設計/08_ops設計方針/README.md)

- 5 incident class × 6 phase lifecycle
- postmortem PR の 72h open SLA + 14 日 merged SLA
- ops-edge cluster: target cluster outage 時にも escalation 物理発火する独立 cluster
- audit_ingest_gap_monitor: hash chain の honest 補完（ingest gap detection）

## security 要件（cross 参照）
詳細: [セキュリティ要件](03_セキュリティ要件.md)

- WORM Object Lock（preservation 期限内 物理 delete 不可）
- audit_event の immutability 三重化
- minimum retention 7 年（v1_audit_log）

## SLO target

### infra SLO
- `infra.failover_drill_compliance`: 100%（cadence 内 cluster 比率）
- `infra.clock_drill_compliance`: 100%（skew injection / leap smear cadence 内）
- `infra.cluster_upgrade_window_compliance`: minor version skew ≤ 1、upgrade window ≤ 30 日

### data SLO
- `data.restore_drill_compliance`: 100%（preservation_class 別 cadence 内）
- `data.replication_lag_p99`: preservation_class 別 RPO 内

### ops SLO（cross 参照）
- `v1_postmortem_sla_compliance`: 100%
- `v1_runbook_drill_compliance`: 100%

## 受入条件（1.0.0 ship blocker）
- 5 topology_class（v1_single_zone を除く 4 class）全てで failover_drill green
- 5 clock_integrity_class 全てで clock_drill green
- 5 preservation_class 全てで restore_drill green
- ops-edge cluster 経由の escalation 物理発火 drill green（target cluster kill 時に page 到達）
- audit_event の hash chain divergence ゼロ
- audit_ingest_gap_seconds = 0

## 制約と前提
- クラウド非依存（cluster は素の Kubernetes + MetalLB + kube-vip）
- 段階的 release 禁止
- 単一 zone での本番運用禁止
- manual failover 禁止
- wall-clock TTL 禁止（monotonic clock のみ）
- step（leap second）禁止、smear のみ
