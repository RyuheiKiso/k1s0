# セキュリティ要件

## 一文方針
- 本ドキュメントは security 軸（13 軸 + meta-spec の上位 meta-layer）の要件を集約する。1.0.0 ship 時点で 5⁴ cell の threat catalog 完備、5 build_provenance_class 全 production artifact が consensus green、各 SLO 4 SLI green 維持を要件として宣言する。

## 至高路線における立ち位置
- 「文章で運用」を禁止し、全 security 規律を build artifact + Kyverno admission policy + cosign signature の物理機構に転写する
- 「現実には起こりにくいから登録しない」「mitigation が高コストだから緩める」判断を採らない
- 「LLM 単独 sign-off」「単一 reviewer sign-off」「PR author の self-review」を禁止
- 段階的 release を禁止、1.0.0 で全 mitigation green

## 機能要件

### 脅威モデル要件
- 5⁴ = 625 cell の完全列挙（reachable cell に必ず mitigation pointer ≥ 1）
- mitigation pointer の物理機構経路完備（textual cap 5%、boundary section cap 0%）
- actor class 別 active mitigation 数 ≥ {30, 35, 40, 35, 30}
- 詳細: [脅威モデル適合仕様](../../04_詳細設計/01_適合仕様/15_脅威モデル適合仕様.md)

### 境界制御要件
- 6 surface（north-south / east-west / control-plane / persistence / supply-chain / build-time）の trust boundary 完備
- 各 surface crossing は 4 mitigation（authn + authz + transport + audit）を必ず重ねる
- zero-trust default deny + explicit allow

### 秘密管理要件
- 8 secret class の rotation cadence 物理 enforce
- OpenBao の lease ベース短期発行のみ
- gitleaks + trufflehog + Trivy secret + Falco の三重検知

### 脆弱性管理要件
- 5 検知経路完備（image scan + dep audit + SAST + IaC + 自社発見）
- patch SLO: critical 72h / high 7d / medium 30d / low 90d
- Trivy + Grype double-bound（severity escalation 規律）

### 監査要件
- 全特権操作を audit_event に append-only emit
- immutability 三重化（DB + cryptographic chain + WORM Object Lock）
- minimum retention 7 年（v1_audit_log preservation_class）
- 4 ingest 経路冗長化 + heartbeat による gap detection

### PII 保護要件
- 5 PII class taxonomy 完備、全 column が `pii_class` 注釈持ち
- 6 軸 cross-axis bind（鍵階層 / schema 判定 / RLS FORCE / preservation / client / audit）
- envelope encryption + class 別 rotation cadence

### インシデント対応要件
- 7 incident class × 6 phase playbook 完備
- postmortem PR merge を次 release の物理 prerequisite
- on-call rotation L1〜L3 + 自製 escalation engine

### 訓練要件
- 7 drill class の cadence 内 green 維持
- scenario_catalog が全 threat_class を coverage
- 開発者 onboarding security baseline 教育

### build provenance 要件
- 5 build_provenance_class 完備、全 production artifact が cosign signed + SBOM attached
- reproducibility consensus（3 builder 並行 verify）
- runner image self-attestation daily check
- per-job ephemeral signing key 24h rotation

## 非機能要件

### SLO target（13 SLO 軸 と connect）
- `audit_log_ingest_latency`: ≤ 5 sec p99
- `patch_window_compliance`: 100%（severity 別 SLO 内）
- `cve_open_critical_count`: 0（critical CVE 72h 超過は本番 deploy block）
- `drill_overdue_count`: 0
- `audit_chain_health`: 100%（chain divergence ゼロ）
- `audit_ingest_gap_seconds`: 0
- `build_provenance_consensus_status`: 100% green

### 可用性 / 災害対策
- 4 ingest 経路冗長化（application emit / DB engine audit / cluster audit / Kyverno admission audit）
- audit pipeline の dual backend（file + webhook）
- ops-edge cluster による gap monitor SPOF 対策

### コンプライアンス
- WORM Object Lock Compliance mode（root 権限でも解除不可）
- audit retention 最低 7 年
- PII 分類 + 暗号化必須

## 受入条件（1.0.0 ship blocker）
- 全 5 actor class の cross-axis mitigation green（active mitigation 数 ≥ 170）
- `threat_model.lock.yaml` の `coverage_green = true`
- 全 13 件 製造業 pack stress test green
- 全 5 build_provenance_class production artifact が consensus green
- `release_gate.lock.yaml` の security cells 全 green
- TBD / 未定 / 後述 が `status: locked` ドキュメント中にゼロ

## 制約と前提
- 商用 EDR / XDR / SIEM SaaS は採用しない
- HashiCorp Vault は採用しない（BUSL、OpenBao 一本）
- 商用 PenTest 結果のみで脆弱性管理を完了させない（自動 CVE 配信 + Renovate + 定期 PenTest の三重化必須）
- single scanner 依存禁止（Trivy + Grype double-bound）
- LLM 単独 sign-off 禁止
- 段階的 release 禁止
