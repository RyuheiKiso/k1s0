# クラウド非依存制約

## 一文方針
- 本企画は cloud vendor lock-in を回避し、Kubernetes 上の OSS 一本で全機能を完結する。cloud managed service（AWS RDS / DynamoDB / SQS / Lambda / Cognito 等）への依存を採らず、L1+ 移行コミットメントで cloud lock-in 移行先（Aurora / Neon / AWS MSK / Confluent Cloud / Temporal Cloud）を 1.0.0 primary pair から除外する。

## クラウド独立の方針
- Kubernetes cluster 上で全機能を完結（OSS Kubernetes、cloud managed Kubernetes も可だが optional）
- cloud-specific API への依存ゼロ
- cloud-specific managed service の不採用

## 不採用 cloud managed service
- **DB**: AWS RDS / Aurora / Cosmos DB / Cloud SQL / Spanner（PostgreSQL CloudNativePG で代替）
- **Document Store**: DynamoDB / Cosmos DB（v1 unsupport）
- **Messaging**: AWS SQS / Pub/Sub / EventBridge / MSK（Apache Kafka Strimzi で代替）
- **Workflow**: AWS Step Functions / Cloud Workflows（Temporal で代替）
- **Auth**: AWS Cognito / Auth0 / Azure AD（Keycloak で代替、enterprise federation は Keycloak identity brokering）
- **Object Storage**: S3 / GCS / Azure Blob（Ceph RGW で代替、S3 wire 互換）
- **Secret**: AWS Secrets Manager / GCP Secret Manager（OpenBao で代替）
- **Container Registry**: ECR / GCR / ACR（Harbor で代替）
- **CI/CD**: AWS CodeBuild / Cloud Build（GitHub Actions self-hosted + Tekton で代替）
- **Serverless**: AWS Lambda / Cloud Functions / Knative（v2 候補）
- **Cluster Autoscaler**: EKS Karpenter（KEDA + Cluster Autoscaler で代替）

## cloud lock-in 移行先（L1+ primary pair から除外）
- Aurora PG / Neon: relational_pg_pair の primary 移行先候補に該当しない
- AWS MSK / Confluent Cloud: messaging_kafka_pair の primary 移行先候補に該当しない
- Temporal Cloud: workflow_pair の primary 移行先候補に該当しない

これらは v2 以降の対応候補。1.0.0 では pure OSS 内移行で証明する。

## ハイブリッドクラウド対応
- on-premises Kubernetes cluster 上で動作可能
- AWS / GCP / Azure の Kubernetes managed service（EKS / GKE / AKS）上でも動作可能
- multi-region deployment は 5 topology_class（v1_multi_region_active_active 等）で対応
- 物理 cluster の constructive 自由度を維持

## OS 固有依存例外との整合
- APNs / FCM の利用は ops-edge escalation cluster の last-mile 通知のみ
- cloud-specific 通知 service への依存ではない（業界 OS 提供 service への依存）

## 受入条件
- cloud-specific managed service 利用ゼロ（CI 検査）
- on-premises Kubernetes cluster で全機能 production ready
- 5 topology_class が cluster-api / kubeadm + IaC（OpenTofu）で declarative 構築可能
