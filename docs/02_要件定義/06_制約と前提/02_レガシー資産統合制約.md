# レガシー資産統合制約

## 一文方針
- レガシー .NET Framework 4.6.2+ の業務 exe / Service 資産は、tier1 Library 直接組込不可、tier2 Service を Companion + Gateway 経由 HTTP/1.1 + JSON（unary）/ HTTP/1.1 + SSE（server-streaming）で消費する形態に固定する。`v1_legacy_http11` 別ポート listener（8443-legacy）に分離、per-tab 6 subscription で縮退、v2 で廃止候補。

## レガシー .NET Framework 制約
- tier1 Library / tier2 Library の直接組込不可（WinHttpHandler の HTTP/2 制約）
- tier2 Service を Gateway 経由で消費
- Companion（`k1s0.Companion.NetFx`）が観測可能性 / 認証コンテキスト伝播 / Transport Negotiation を担当

## v1_legacy_http11 capability_class
- 該当条件:
  - 企業 FW / DLP / TLS インスペクション appliance が ALPN h2 を遮断
  - Windows 7 / 8.1 / Server 2008R2 / Server 2012 等、ホスト OS の WinHTTP が h2 を持たない版数
  - .NET Framework 4.6.1 以前
- per-tab subscription 上限: 6（HTTP/1.1 物理上限）
- 別ポート listener（8443-legacy）に分離
- 業務 SLO は別系統で管理（`v1_legacy_http11_request_latency_p99_ms`）

## prerequisite check
Companion 配布時の prerequisite:
- .NET Framework 4.6.2+ かつ Windows 10 1607+ / Server 2016+ かつ WinHttpHandler 必須
- Backstage onboarding workflow の prerequisite step で OS 版数 check を H2 reachability check と並列必須化

## レガシー形態の業務コード制約
- tier3 業務コードからは Companion runtime + tier2 Service の proto 派生 SDK のみが見える
- OSS クライアントへの直接アクセスは禁止

## 長期収斂
- 業界 OS の WinHTTP h2 普及率 trigger で v2 廃止候補
- 08_OSS ライフサイクル適合仕様 の `deprecation_clock` に登録

## 受入条件
- レガシー .NET Framework 4.6.2+ 端末が `v1_legacy_http11` capability_class で動作
- prerequisite check が Backstage onboarding workflow で必須
- Companion 役割 A（CLR Profiler attach）+ 役割 B（sse_paired adapter）動作確認
