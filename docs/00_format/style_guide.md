# 文体・記法 style guide

## 一文方針
- 全 `.md` ドキュメントは「至高路線（運用コスト度外視 / 1.0.0 で完璧 / 段階的 release 禁止 / 機能削減なし）」を体現する文体で書く。曖昧表現 / 留保 / 段階的譲歩を排し、断定形 + 物理 enforce の宣言で記述する。

## 至高路線における原則
- 文章は意思決定の宣言である。「〜したほうが良い」「〜が望ましい」「〜を検討する」は禁止。「〜する」「〜しない」「〜を CI fail とする」と断定する。
- 「TBD」「未定」「あとで書く」「TODO」「後述」「将来検討」は `status: locked` のドキュメントでは CI fail。`status: draft` でのみ許容。
- 文体は読者の感情ではなく機械的整合に向けて書く。装飾 / 喚起 / 物語性は排除する。

## 言語

- 日本語を主言語とする。
- 技術用語（HTTP/2 / TLS / OIDC / Kyverno / TLA+ / Stainless 等）は原語のままで良い。日本語訳を付加しない。
- 英文の引用 / 仕様参照は半角空白で区切り、過剰な日本語化はしない。

## 文字種・記号

| 種別 | 規則 |
|---|---|
| 全角 / 半角 | 英数字 / 記号は半角。括弧 `( )` も半角。`「 」` は全角を使う |
| 半角空白 | 日本語と英数字の境界には半角空白を 1 つ入れる（例: `tier1 の責務`） |
| 句読点 | `、` `。` を使う。カンマ `,` ピリオド `.` は混在させない（コードブロック内除く） |
| 引用符 | コード内の文字列は `'...'` または `"..."` を使う。文中強調は `「 」`、コード断片は バッククォート |
| ダッシュ | `—` `–` は使わない。`-` または `:` を使う |

## 強調

- 太字 `**...**` は **真に強調すべき定義 / 制約**にのみ使う。1 ドキュメント内で 5 箇所以上にならないことを目安。
- 斜体 `*...*` `_..._` は使わない。
- 取り消し線 `~~...~~` は使わない（代わりに削除する）。
- HTML タグ（`<strong>` `<em>` 等）は使わない。

## 数字

- 単位付き: `200 ms` `3 台` `5 OSS` のように半角空白で区切る。
- 範囲: `5〜10` （全角チルダ）または `5 to 10`。`-` は使わない。
- パーセント: `50%` （半角）。
- バイト等: `1 MB` `4 GB`。

## 否定 / 例外の書き方

- 「禁止」「採用しない」「維持しない」を明示する。曖昧化しない。
- 例外は **必ず明示的に enumerate** する。「特別な事情がある場合は除く」のような open-ended 例外は禁止。
  - 良い例: `例外: APNs/FCM の last-mile 通知に限定許容`
  - 悪い例: `例外として、必要な場合は許容する`

## 値 / 閾値の書き方

- 数値 / 期限 / cap は frontmatter または本文表中に明示する:
  - 良い例: `cap=20 件以内` `cooldown=90 day` `cadence=14 day`
  - 悪い例: `十分な期間を空ける` `必要十分な数だけ`

## 比較 / 選定の書き方

- 採用 / 不採用は **理由 + 例外の 3 点 set** で書く:
  ```
  - 商用 proof assistant は採用しない。
      - 理由: 単一深耕の規律から外れる
      - 例外: assumption.lock.yaml に明示登録された cryptographic assumption は文献 pointer 可
  ```

## ファイル冒頭

全 `.md` は以下の構造で開始する:

```markdown
---
<frontmatter>
---

# <タイトル>

## 一文方針
- ...
```

- `# <タイトル>` の前後に空行 1 行ずつ。
- `## 一文方針` を最初の `##` セクションとする（kind=index 等の例外を除く）。

## ファイル末尾

- 末尾は改行 1 つで終える（trailing newline）。
- 余計な空行を末尾に残さない。

## 段落 / 改行

- 1 段落 = 1 主張。複数主張を 1 段落に詰めない。
- 段落間は空行 1 つ。
- 行幅は固定しない（自動折返しに任せる）。手動の改行を意味のない場所で入れない。

## リスト

- リストは `- ` で始める。`*` `+` は使わない。
- 番号付きリストは順序が本質的に意味を持つ場合のみ使う。順序が任意なら通常リストにする。
- リスト項目末尾の句点 `。` は付ける（短い箇条書きのみ省略可、ドキュメント内で統一）。
- ネスト規約は `conventions/section_marker.md` を参照。

## 表

- 表は MD table を使う。`conventions/section_marker.md` 参照。
- 列数 10 以上 / 行数 200 以上の表は別ファイル（YAML / TSV）に分離。

## コードブロック

- フェンス記法 ` ``` ` を使う。インデント記法は使わない。
- 言語タグ必須:
  - `yaml` / `json` / `toml`
  - `rust` / `csharp` / `go` / `typescript` / `python` / `scala`
  - `protobuf` / `graphql`
  - `bash` / `shell`
  - `rego` / `cue` / `dhall`
  - `tla` / `dafny` / `lean`
  - `markdown` / `text`（言語不明 / 疑似コード時）
- インラインコードはバッククォート 1 個 `` `code` ``。

## 引用

- 引用 `>` は知識層 / 外部資料からの転載に限り使用。本文の自己引用には使わない。

## リンク

- 規約は `conventions/crosslink.md`。
- 外部 URL は本文中に bare URL で書かず、必ず `[表示文言](URL)` 形式。
- 90_archive への参照は `conventions/crosslink.md` 末尾参照。

## 画像

- 画像は対応する `img/` サブフォルダに配置（例: `01_企画/01_背景と目的/img/`）。
- 図面は drawio 形式で保持し、SVG export も同フォルダに置く（`drawio-authoring` skill 規約）。
- alt text 必須: `![<説明>](img/<filename>.svg)`。

## 禁止表現（status: locked で CI fail）

| 表現 | 代替 |
|---|---|
| TBD | 削除して具体内容を書く |
| 未定 | 削除 |
| あとで書く | 削除 |
| TODO | issue tracker に移す |
| 後述 | 該当箇所への link |
| 将来検討 | v2 以降の検討事項として明示的に lock_artifacts 化 |
| たぶん / おそらく | 削除して断定する |
| 〜したほうが良い | 「〜する」 |
| 〜が望ましい | 「〜とする」 |
| 〜できる場合がある | 「〜は次の場合に限る」 |

## 禁止表現（status: draft でも CI warn）

| 表現 | 理由 |
|---|---|
| 〜と思います | 個人見解は文書に書かない |
| 簡単に / 容易に | 主観表現 |
| 多くの / 少しの | 数値で書く |

## 禁止される構造

- 結論を最後に書く構造は禁止。`## 一文方針` で結論先出し。
- 「経緯」「変更履歴」「議事録」セクションは禁止（CLAUDE.md）。
- 「謝辞」「免責」セクションは禁止。
- ドキュメント内に複数の `# タイトル` を持つことは禁止。

## 検証規約（Phase 5 で実装）

> **pre-P0 注記**: 以下の機械検出は P2 deliverable（pre-P0 時点で未配線）。

- `tools/docs_lint/textlint.config.mjs` で禁止表現を機械的に検出。
- `tools/docs_lint/markdownlint.json` で MD 構造規約を機械的に検出。
- `status: locked` のドキュメントで禁止表現が残存していれば CI fail。
- `status: draft` のドキュメントで禁止表現は warn 経路（ship 前に解消必須）。
