# tier1 軸エンジニア 責務とスコープ

## 一文方針

- tier1 軸エンジニアは Server 系 5 分類 / Library 3 抽象レベル × 17 機能カテゴリ / Companion 役割 / 9 適合仕様の実装を担う。業務ロジック（tier2）/ クライアント UI（tier3）/ cluster 構築（infra）は非責務である。

## 責務

### Server 系 5 分類

tier1 は以下の 5 種類のサーバコンポーネントを実装する。

| 分類 | 説明 |
|---|---|
| Gateway | 外部クライアントとの接続点。TLS 終端・認証・レートリミットを担う |
| BFF (Backend for Frontend) | tier3 クライアント専用の集約レイヤ |
| Domain Service | 業務ドメインロジックを持つコアサービス（tier2 業務資産を呼び出す） |
| Worker | 非同期処理・バッチ処理サービス |
| Sidecar | 観測 / 認証 / 鍵管理の補助コンテナ |

### Library 3 抽象レベル × 17 機能カテゴリ

tier1 ライブラリは 3 抽象レベル（primitive / domain-agnostic / domain-aware）× 17 機能カテゴリ（transport / auth / observability / schema-evolution / slo / oss-lifecycle / tenant / key-mgmt / migration / bidi / etc.）で構成される。

### Companion 役割

proto ファイルと Buf 設定（`buf.yaml` / `buf.gen.yaml`）を管理し、4 言語（Rust / Go / C# / TypeScript）の gRPC stub を生成する。

### 9 適合仕様の実装

`docs/01_企画/90_メモ/` 配下の 9 軸適合仕様（07-15）に基づく機能を実装する。

| 軸番号 | 仕様名 |
|---|---|
| 07 | Bidi 双方向ストリーミング |
| 08 | 移行 Pair |
| 09 | 観測 |
| 10 | 認証 |
| 11 | 鍵管理 |
| 12 | スキーマ進化 |
| 13 | SLO |
| 14 | OSS ライフサイクル |
| 15 | テナント容量 |

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| 業務ドメインロジック実装 | tier2 軸エンジニア |
| 個別業務 UI / 帳票 | tier3 軸エンジニア |
| cluster 構築 / Kubernetes 設定 | infra 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |
| formal 証明 | formal 軸エンジニア |
| production cluster 運用 | ops 軸エンジニア |
| proto / OSS 定義の governance 最終承認 | k1s0 作者 |
