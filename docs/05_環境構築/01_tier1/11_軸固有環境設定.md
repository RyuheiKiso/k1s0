# 軸固有環境設定

## 一文方針

- `buf generate` を実行して 4 言語 stub が生成されること / 9 適合仕様ページが参照できること / OSS lifecycle 監視設定が完了することを本ページの検収とする。

## proto → 4 言語 stub 生成演習

`buf.gen.yaml` に 4 言語のプラグイン設定が必要。`src/tier1/buf.gen.yaml` はまだ存在しないため、以下の内容でファイルを作成してから実行すること。

```yaml
# src/tier1/buf.gen.yaml として作成する
version: v1
plugins:
  - plugin: buf.build/protocolbuffers/go
    out: gen/go
    opt: paths=source_relative
  - plugin: buf.build/grpc/go
    out: gen/go
    opt: paths=source_relative,require_unimplemented_servers=false
  - plugin: buf.build/protocolbuffers/python
    out: gen/python
  - plugin: buf.build/community/nipunn1313-mypy
    out: gen/python
```

```bash
cd src/tier1
buf generate
ls gen/go gen/python
```

TypeScript stub は `ts-proto` プラグインを使用する。

```bash
# buf.gen.yaml に ts-proto を追加した場合
buf generate
ls gen/ts
```

C# stub は `Grpc.Tools` NuGet パッケージが `dotnet build` 時に自動生成するため手動の `buf generate` は不要。

## 9 適合仕様ページの参照確認

`docs/01_企画/90_メモ/` 配下の 9 軸方針メモが存在することを確認する。

```bash
ls docs/01_企画/90_メモ/ | grep -E "07|08|09|10|11|12|13|14|15"
```

各軸の `15_<軸名>適合仕様.txt` が存在することを確認する。

## OSS lifecycle 監視設定

tier1 は OSS ライフサイクル軸（14 番）の責任者として、依存 OSS のバージョン監視を設定する。

```bash
# Rust: cargo audit でセキュリティ脆弱性確認
cargo install cargo-audit
cargo audit

# Go: govulncheck
go install golang.org/x/vuln/cmd/govulncheck@latest
govulncheck ./...

# .NET: dotnet list package --vulnerable
dotnet list package --vulnerable

# Node: pnpm audit
pnpm audit
```

## 検収コマンド

```bash
buf generate && echo "stub 生成: OK"
cargo audit && echo "Rust audit: OK"
govulncheck ./... && echo "Go vuln: OK"
```
