# 検収基準

## 一文方針

- `tlc -help` / `apalache-mc help` / `dafny --version` / `lean --version` / `cargo kani --version` / `cbmc --version` の全コマンドが正常応答し、かつ sample proof 5 件が成功することが formal 軸エンジニアの環境構築完了の唯一の定義である。

> **pre-P0 注記**: `src/` および `tools/` は P0〜P10 deliverable（pre-P0 時点で実体ゼロ）。以下の検収コマンドは各 Phase 完了後に有効。

## 検収コマンド一覧

以下のコマンドを全て実行し、期待結果が得られることを確認する。

```bash
# 1. TLA+ CLI
tlc -help 2>&1 | head -3
# 期待: TLA+ Version が表示される

# 2. Apalache
apalache-mc help 2>&1 | head -3
# 期待: apalache-mc のヘルプが表示される

# 3. Dafny CLI
dafny --version
# 期待: "Dafny X.Y.Z" の形式でバージョンが表示される

# 4. Lean 4
lean --version
# 期待: "Lean (version X.Y.Z, ...)" の形式でバージョンが表示される

# 5. Kani
cargo kani --version
# 期待: "kani X.Y.Z" の形式でバージョンが表示される

# 6. CBMC
cbmc --version
# 期待: "CBMC version X.Y Z-bit" の形式でバージョンが表示される

# 7. sample proof 5 件（07_テスト検証環境 の各コマンドを再実行）
dafny verify Sample.dfy 2>&1 | grep -c "Verified"
lean Sample.lean && echo "Lean: pass"
cargo kani 2>&1 | grep "SUCCESSFUL"
cbmc cbmc_sample.c --bounds-check 2>&1 | grep "SUCCESSFUL"
tlc HelloSpec.tla -deadlock 2>&1 | grep "No error"
```
