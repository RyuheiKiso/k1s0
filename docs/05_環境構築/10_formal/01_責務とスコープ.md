# formal 軸エンジニア 責務とスコープ

## 一文方針

- formal 軸エンジニアは 5 proof_class × 19 軸 = 95 cell の proof_matrix 管理 / counter-example closure / dual reviewer sign-off（LLM 単独禁止）/ cryptographic proof の domain expert review を責務とし、テスト実行（test 軸）・実装（tier1-3）は非責務とする。

## 責務 4 本

### proof_matrix 管理

5 proof_class（TLA+ / Dafny / Lean 4 / Kani / CBMC）× 19 軸 = 95 cell の proof_matrix を管理する。各 cell の status（red / yellow / green）を更新し、新軸追加時に対応する proof_class の適用可否を判定する。proof_matrix の雛形 YAML は `docs/` 配下に保管し、変更ごとに lint が green であることを確認する。

### counter-example closure

Apalache / TLC / Dafny / Lean 4 が出力した counter-example を分析し、仕様の修正・補題の追加・仮定の明示化によって閉鎖する。閉鎖完了の証拠として、対応する proof_class の sample spec が clean pass するコミットを作る。

### dual reviewer sign-off

proof の合否判定は LLM 単独で行うことを禁止する。人間 2 名（formal 軸エンジニア + domain expert）が sign-off して初めて該当 cell を green にできる。sign-off の記録は commit message または PR body に残す。

### cryptographic proof の domain expert review

暗号プリミティブ（例: 鍵交換プロトコル / commitment scheme）に関する proof は、domain expert（security 軸または外部の暗号専門家）のレビューを必須とする。formal 軸エンジニア単独で green にすることを禁止する。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| 単体テスト / 統合テスト実行 | test 軸エンジニア |
| tier1 Rust / Go 実装 | tier1 軸エンジニア |
| tier2 業務ドメイン実装 | tier2 軸エンジニア |
| tier3 UI 実装 | tier3 軸エンジニア |
| production cluster 運用 | ops 軸エンジニア / プラットフォーム運営者 |
| KEK shamir ceremony | プラットフォーム運営者 |
| infra cluster 構築 | infra 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |

## LLM 補助の扱い

LLM（Claude Code 含む）による spec 草案作成・proof_matrix YAML 生成補助は許容する。ただし以下は人間 dual sign-off が必須：

- proof_matrix の cell を green に変更すること
- cryptographic proof の合否判定
- counter-example closure の最終確認
- dual reviewer の一方としての LLM 単独判定
