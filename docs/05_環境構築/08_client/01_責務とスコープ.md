# client 軸エンジニア 責務とスコープ

## 一文方針

- client 軸エンジニアは 5 distribution_class の SDK 配布管理 / SDK conformance test 維持 / browser matrix 対応の 3 責務を持ち、ビジネスロジック（tier2）実装 / cluster 管理（infra）は対象外である。

## 5 distribution_class

| class | 説明 | 主要技術 |
|---|---|---|
| v1_full_native_with_companion | ネイティブアプリ + コンパニオン API 付き完全版 | Rust / Tauri / C# |
| v1_legacy_dotnet_framework | .NET Framework 4.x 向けレガシー対応版 | C# / .NET Framework |
| v1_browser_spa_typescript | ブラウザ SPA 向け TypeScript SDK | TypeScript / pnpm / Vite |
| v1_thick_native_via_tauri | Tauri 経由のリッチネイティブクライアント | Tauri 2.0 / Rust / TypeScript |
| v1_thin_business_api_only | ビジネス API のみの薄い SDK | TypeScript / Node 20 |

## 責務 3 本

### SDK 配布管理

5 distribution_class それぞれの SDK ビルド・パッケージング・配布を管理する。各 class に対してリリースチェックリストを持ち、version タグとともに artifact を配布する。配布先: npm registry / NuGet / GitHub Releases / winget。

### SDK conformance test 維持

SDK conformance test は各 distribution_class がプロトコル仕様（tier1 で定義）と一致することを検証する。cadence は class ごとに定義する。

| class | cadence |
|---|---|
| v1_full_native_with_companion | 14 日ごと |
| v1_legacy_dotnet_framework | 30 日ごと |
| v1_browser_spa_typescript | 14 日ごと |
| v1_thick_native_via_tauri | 14 日ごと |
| v1_thin_business_api_only | 14 日ごと |

### browser matrix 対応

v1_browser_spa_typescript は Chrome / Firefox / Webkit（Safari）の 3 ブラウザで動作を保証する。Playwright を使って matrix を CI で自動実行する。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| ビジネスドメインロジック実装 | tier2 軸エンジニア |
| UI / 帳票実装 | tier3 軸エンジニア |
| Kubernetes cluster 構築 | infra 軸エンジニア |
| transport プロトコル実装 | tier1 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |
| SLO 管理 / postmortem 主導 | ops 軸エンジニア |
| 検証規律（Pact / mutation） | test 軸エンジニア |

## LLM 補助の扱い

LLM（Claude Code 含む）による SDK wrapper 草案 / Playwright テストスクリプト生成 / conformance test 草案は許容する。ただし以下は人間 dual sign-off が必須：

- SDK public API の breaking change
- distribution_class の追加・廃止
- conformance test の pass 基準変更
