# テスト検証環境

## 一文方針

- Backstage / Grafana / Prometheus をローカル docker compose で全コンテナ Up の状態にし、k6 load test ローカル実行と SLO budget 計算スクリプト実行まで通ることが本ページの検収条件である。

> **pre-P0 注記**: `src/` は P10 deliverable（pre-P0 時点で実体ゼロ）。以下の手順は P10 完了後に有効。

## docker compose 構成

```yaml
# ops/docker-compose.yml（リポジトリ内に配置）
version: "3.9"
services:
  prometheus:
    image: prom/prometheus:latest
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
  alertmanager:
    image: prom/alertmanager:latest
    ports:
      - "9093:9093"
  grafana:
    image: grafana/grafana:latest
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
    depends_on:
      - prometheus
  loki:
    image: grafana/loki:latest
    ports:
      - "3100:3100"
```

## docker compose 起動手順

```bash
cd ops/   # docker-compose.yml のあるディレクトリ
docker compose up -d
docker compose ps    # 全コンテナが Up であることを確認
```

起動確認:

- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000 (admin/admin)
- Alertmanager: http://localhost:9093
- Loki: http://localhost:3100

## k6 load test ローカル実行

```bash
# サンプル k6 スクリプト
cat > /tmp/test.js << 'SCRIPT'
import http from 'k6/http';
import { sleep } from 'k6';
export const options = { vus: 10, duration: '10s' };
export default function () { http.get('http://localhost:9090'); sleep(1); }
SCRIPT

k6 run /tmp/test.js
```

k6 の結果（p95 latency / request rate）が SLO 計算スクリプトへの input になる。

## SLO error budget 計算スクリプト実行

```bash
# SLO budget 計算（Python スクリプト例）
python3 - << 'EOF'
# 28 日間の availability SLO budget 計算
target = 0.999        # 99.9% SLO
window_days = 28
total_minutes = window_days * 24 * 60
budget_minutes = total_minutes * (1 - target)
print(f"Error budget: {budget_minutes:.1f} min / {window_days} days")
EOF
```

## コンテナ停止

```bash
docker compose down
```

## 検収コマンド

```bash
docker compose up -d
docker compose ps | grep -c "Up"   # 4 以上の Up を確認
k6 run --version
docker compose down
```
