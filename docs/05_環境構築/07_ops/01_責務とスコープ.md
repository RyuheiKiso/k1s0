# ops 軸エンジニア 責務とスコープ

## 一文方針

- ops 軸エンジニアは 5 signal_class × 5 phase ops loop 管理 / SRE 50% rule 徹底 / SLO dashboard 維持 / on-call rotation 設計 / postmortem 主導 / runbook 整備 / Backstage TechDocs 管理の 7 責務を持ち、cluster 構築（infra）・tier1-3 実装・脅威モデル（security）は対象外である。

## 責務 7 本

### 5 signal_class × 5 phase ops loop 管理

latency / traffic / errors / saturation / availability の 5 signal_class に対して、detect → triage → mitigate → resolve → retrospective の 5 phase ops loop を回す体制を設計・維持する。各 phase に runbook entry が存在することを保証する。

### SRE 50% rule 徹底

toil 作業（手動オペレーション）が ops 軸エンジニアの工数の 50% を超えないよう計測・改善する。toil 計測スクリプトを週次で実行し、超過した場合は自動化 PR を優先する。

### SLO dashboard 管理

Grafana 上の SLO dashboard を所有する。error budget 残量を weekly で確認し、burn rate が高い場合は on-call を即座に召集する。SLO 定義（availability target / latency target）は `docs/01_企画/` の該当仕様が source of truth であり、dashboard との乖離を検知したら即座に同期する。

### on-call rotation 設計

PagerDuty / Alertmanager に on-call シフトを設定し、escalation policy を定義する。on-call ハンドオフ文書は Backstage TechDocs で管理する。

### postmortem 主導

インシデント発生後 48 時間以内に postmortem ドキュメントを起票し、5 Why analysis / action item を記録する。postmortem は blameless で行い、action item には owner と期限を必ず付与する。

### runbook 整備

Backstage TechDocs に runbook を集約する。alert → runbook のリンクを Alertmanager annotation に埋め込み、alert 発火時に担当者が即座に手順を参照できる状態を維持する。

### Backstage TechDocs 管理

Backstage の Software Catalog に software template を登録し、TechDocs でドキュメントを管理する。`techdocs-cli` によるローカルビルドで docs の整合性を確認する。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| Kubernetes cluster 構築・provisioning | infra 軸エンジニア |
| tier1 Rust / Go / C# / TypeScript 実装 | tier1 軸エンジニア |
| tier2 業務ドメイン実装 | tier2 軸エンジニア |
| tier3 UI / 帳票実装 | tier3 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |
| formal 証明 | formal 軸エンジニア |
| SDK 配布管理 | client 軸エンジニア |
| 検証規律（Pact / mutation） | test 軸エンジニア |

## LLM 補助の扱い

LLM（Claude Code 含む）による runbook 草案・SLO 計算スクリプト生成は許容する。ただし以下は人間 dual sign-off が必須：

- SLO target 値の変更
- on-call escalation policy の変更
- Alertmanager routing rule の変更
- postmortem action item の owner 決定
