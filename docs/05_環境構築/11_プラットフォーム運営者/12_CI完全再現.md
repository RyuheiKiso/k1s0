# CI 完全再現

## 一文方針

- `.github/workflows/docs_lint.yml` の全 job を push 前に手元で再現し、exit 0 を確認してから push する。CI で初めて気づく fail はプラットフォーム運営者の規律違反である。

## docs_lint.yml の job 構成

```yaml
jobs:
  lint:            # "docs lint (8 check)"
  release_gate_check:  # depends-on: lint
```

### job: lint の手元再現

```bash
source .venv/bin/activate
bash tools/docs_lint/run_lint.sh
python3 tools/docs_lint/run_lint.py
```

### job: release_gate_check の手元近似

```bash
python3 tools/lock_yaml_generator/generate_release_gate.py
cat tools/lock_yaml_generator/samples/release_gate.lock.yaml
```

## ops 固有の CI 再現

OPA conftest による RBAC policy lint は現状 CI に配線されていない。手元で実行して green を確認する。

```bash
# conftest が存在する場合
conftest test src/ops/rbac/ --policy src/ops/policy/ 2>/dev/null || echo "policy dir 未作成（演習環境では acceptable）"
```

## push 前チェックリスト

```bash
# 1. lint 双方が green
bash tools/docs_lint/run_lint.sh && python3 tools/docs_lint/run_lint.py

# 2. id 重複がないこと
python3 tools/docs_lint/run_lint.py 2>&1 | grep "id 重複"

# 3. depends_on が dangling / 循環していないこと
python3 tools/docs_lint/run_lint.py 2>&1 | grep -E "解決不能|循環"

# 4. dangling link がないこと
python3 tools/docs_lint/run_lint.py 2>&1 | grep "dangling link"
```

全コマンドが出力なしで終われば push 可能。

## 検収コマンド

```bash
bash tools/docs_lint/run_lint.sh && \
  python3 tools/docs_lint/run_lint.py && \
  echo "CI 完全再現: GREEN"
```
