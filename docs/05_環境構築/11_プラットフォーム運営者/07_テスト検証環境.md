# テスト検証環境

## 一文方針

- プラットフォーム運営者は shamir share assembly 演習 / break-glass dry-run 演習 / audit hash chain replay 演習の 3 演習をローカルで完走し、各演習の成功を確認してから「テスト検証環境の構築完了」とする。

## 演習 1: shamir share assembly 演習

OpenBao の shamir operator init を使い、M-of-N 鍵分散のローカル rehearsal を行う。

```bash
# OpenBao を dev mode で起動（rehearsal 専用）
bao server -dev &

# 別ターミナルで operator init を実行
export VAULT_ADDR='http://127.0.0.1:8200'
bao operator init -key-shares=5 -key-threshold=3
```

`key-shares=5 / key-threshold=3` は M=3, N=5 の設定。出力される 5 つの unseal key の中から任意の 3 つを使って unseal できることを確認する。

```bash
# unseal 演習（3 keys 入力）
bao operator unseal <key-1>
bao operator unseal <key-2>
bao operator unseal <key-3>
bao status | grep Sealed
# 期待: Sealed: false
```

演習後は rehearsal で生成した鍵を全て破棄する。production 鍵は本番 ceremony でのみ生成する。

## 演習 2: break-glass dry-run 演習

break-glass は `kubectl --as=system:masters` を使った緊急操作。dry-run で実際の変更なしに手順を確認する。

```bash
# kubeconfig が設定されていることを前提とする（kind cluster 等）
kubectl --as=system:masters get pods -A --dry-run=client
```

dry-run 完了後、操作ログを確認する。

```bash
# audit log に記録されていることを確認
kubectl get events -A | grep "system:masters"
```

break-glass を実行した場合（rehearsal 含む）、必ず postmortem エントリを作成する規律を演習する。

```bash
# postmortem エントリの作成（テンプレート使用）
cat > /tmp/breakglass-postmortem.md << 'TEMPLATE'
# break-glass postmortem

## 日時
YYYY-MM-DD HH:MM JST

## 実行内容
kubectl --as=system:masters ...

## 理由
（理由を記載）

## 事後対応
（対応内容を記載）
TEMPLATE
cat /tmp/breakglass-postmortem.md
```

## 演習 3: audit hash chain replay 演習

audit log の hash chain を replay し、chain が途切れていないことを確認する。

```bash
# audit-trail スクリプトの dry-run
bash src/ops/audit-trail/replay-audit.sh --dry-run 2>&1 | tail -10
# 期待: "chain integrity: OK" または同等のメッセージ
```

スクリプトが存在しない場合はサンプルの hash chain を手動で作成して確認する。

```bash
# SHA-256 による手動 hash chain 確認
echo "entry1" | sha256sum
echo "entry1entry2" | sha256sum
```

