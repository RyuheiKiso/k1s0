# プラットフォーム運営者 責務とスコープ

## 一文方針

- プラットフォーム運営者は production cluster 運用 / KEK shamir M-of-N ceremony 執行 / break-glass 執行 / audit hash chain 管理 / 24h on-call 3 階層 escalation の 5 責務を持ち、実装（tier1-3）/ 鍵の設計（security）/ cluster 構築（infra）は非責務とする。

## 責務 5 本

### production cluster 運用

production cluster の稼働状態を監視し、SLO 逸脱時に escalation ルートに従い対応する。Argo CD / Kyverno / Istio などの GitOps コンポーネントの health を確認し、異常時は infra 軸エンジニアにエスカレーションする。

### KEK shamir M-of-N ceremony 執行

KEK（Key Encryption Key）を Shamir 秘密分散で保護する M-of-N ceremony を執行する。k1s0 作者は rehearsal のみを担当し、production 鍵は本番 ceremony で生成する。ceremony には Yubikey PIV ハードウェアトークンを使用し、share holder（N 名）の中から M 名が揃った場合にのみ鍵を復元できる。

### break-glass 執行

通常の認可フローが機能しない緊急事態において、`kubectl --as=system:masters` などの break-glass 権限を使用して cluster を復旧させる。break-glass 実行は全操作を audit log に記録し、事後に postmortem を作成する義務を負う。

### audit hash chain 管理

audit log の hash chain を管理し、改ざん検知の完全性を維持する。定期的に hash chain を replay し、chain が途切れていないことを確認する。

### 24h on-call 3 階層 escalation

24 時間オンコール体制を維持し、アラート受信から初動対応まで 5 分以内で行う。対応不能な場合は 3 階層（L1: 本人 / L2: 別の運営者 / L3: infra 軸エンジニア）のいずれかにエスカレーションする。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| tier1 / tier2 / tier3 実装 | 各軸エンジニア |
| KEK の設計・鍵スキーム選定 | security 軸エンジニア |
| production cluster の構築 | infra 軸エンジニア（運営者は受け取るのみ） |
| cosign 署名鍵の保管 | k1s0 作者 |
| formal proof の実施 | formal 軸エンジニア |

## LLM 補助の扱い

| 作業 | LLM 可 |
|---|---|
| runbook 草案の作成 | ○ |
| audit log の初期分析 | ○（補助のみ） |
| KEK ceremony の実行 | 禁止（人間 M 名の物理参加が必須） |
| break-glass の実行判断 | 禁止（人間の判断が必須） |
| audit hash chain の署名 | 禁止 |
