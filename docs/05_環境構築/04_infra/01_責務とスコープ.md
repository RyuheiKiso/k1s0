# infra 軸エンジニア 責務とスコープ

## 一文方針

- infra 軸エンジニアは k8s cluster 構築（5 topology_class）/ 5 clock_integrity_class / 25+ Kyverno admission policy 管理 / Argo CD GitOps pipeline 運用の 4 責務を持つ。アプリ実装（tier1-3）/ DB 保全（data 専任）/ 鍵管理（security 専任）は対象外である。

## 責務 4 本

### cluster 構築（5 topology_class）

k8s cluster を 5 つの topology_class（single-zone / multi-zone / multi-region / edge / hybrid）で設計・構築する。ローカルでは kind を使い multi-zone 相当の設定を再現し、production cluster は IaC（Terraform / Pulumi）で管理する。

### 5 clock_integrity_class の適用

clock_integrity_class（ntp-only / ptp-local / ptp-grandmaster / tai-utc-aware / monotonic-strict）を cluster ごとに定義し、NTP / PTP 設定を Kyverno policy で強制する。時刻の不整合が生じた場合は infra 軸が原因箇所を特定して修正する責務を持つ。

### 25+ Kyverno admission policy 管理

Kyverno で 25 件以上の admission policy を GitOps 管理する。policy は以下の分類で整理する。

| 分類 | 例 |
|---|---|
| セキュリティ | privileged container 禁止 / hostPath 禁止 / root 実行禁止 |
| リソース制限 | requests/limits 必須 / PDB 必須 |
| ラベル規約 | app.kubernetes.io/name 必須 |
| ネットワーク | NetworkPolicy 必須 / ExternalIP 禁止 |
| イメージ管理 | 署名済みイメージのみ許可（Cosign 連携） |

policy は ClusterPolicy として Git 管理し、Argo CD で sync する。

### Argo CD GitOps pipeline

Argo CD を使い全 k8s manifest を Git からデプロイする。手動 kubectl apply は禁止し、全変更は PR → merge → Argo CD sync の経路で適用する。Argo CD の ApplicationSet でマルチクラスタ管理を行う。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| アプリ層（tier1-3）の実装 | 各 tier 軸エンジニア |
| DB・メッセージング保全（PostgreSQL / Kafka / ClickHouse） | data 軸エンジニア |
| KEK shamir M-of-N ceremony | プラットフォーム運営者 |
| 脅威モデル / penetration testing | security 軸エンジニア |
| production cluster SRE 対応（オンコール） | ops 軸エンジニア |
| 形式検証 | formal 軸エンジニア |

## LLM 補助の扱い

k8s manifest の草案生成・Kyverno policy の草案作成は LLM 補助を許容する。ただし以下は人間 dual sign-off 必須:

- production cluster への Argo CD sync 実行
- Kyverno ClusterPolicy の deny rule 追加
- 新 topology_class の設計決定
