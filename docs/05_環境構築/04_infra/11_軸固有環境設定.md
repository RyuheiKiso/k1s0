# 軸固有環境設定

## 一文方針

- kind cluster 起動 → Argo CD bootstrap → Kyverno 25+ policy 適用 → 5 topology_class 確認の 4 ステップを順に完了させ、全て green になることを infra 軸固有環境設定の完了条件とする。

## Step 1: kind cluster 起動（5 topology_class 相当）

```bash
cat <<'EOF' > /tmp/kind-infra.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
name: k1s0-infra
nodes:
  - role: control-plane
    labels:
      topology.kubernetes.io/region: local
      topology.kubernetes.io/zone: zone-a
  - role: worker
    labels:
      topology.kubernetes.io/region: local
      topology.kubernetes.io/zone: zone-a
      topology-class: single-zone
  - role: worker
    labels:
      topology.kubernetes.io/region: local
      topology.kubernetes.io/zone: zone-b
      topology-class: multi-zone
  - role: worker
    labels:
      topology.kubernetes.io/region: local
      topology.kubernetes.io/zone: zone-c
      topology-class: multi-zone
EOF

kind create cluster --config /tmp/kind-infra.yaml
kubectl get nodes --show-labels
```

5 topology_class（single-zone / multi-zone / multi-region / edge / hybrid）のうち、ローカル kind では single-zone と multi-zone を再現する。

## Step 2: Argo CD bootstrap

```bash
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# Argo CD が Ready になるまで待機
kubectl rollout status deployment argocd-server -n argocd --timeout=300s

# 初期 admin パスワードの取得
kubectl get secret argocd-initial-admin-secret -n argocd -o jsonpath="{.data.password}" | base64 -d
echo ""

# argocd CLI でログイン（port-forward 経由）
kubectl port-forward svc/argocd-server -n argocd 8080:443 &
argocd login localhost:8080 --username admin --password "$(kubectl get secret argocd-initial-admin-secret -n argocd -o jsonpath='{.data.password}' | base64 -d)" --insecure
```

## Step 3: Kyverno 25+ policy 適用

```bash
# Kyverno のインストール
helm repo add kyverno https://kyverno.github.io/kyverno/
helm repo update
helm install kyverno kyverno/kyverno -n kyverno --create-namespace

kubectl rollout status deployment kyverno -n kyverno --timeout=300s

# 適用済み policy 数の確認（25+ を目標。新規インストール直後は 0 — 以降のカテゴリ別追加で累積する）
kubectl get clusterpolicy 2>/dev/null | wc -l
```

主要 ClusterPolicy カテゴリ（25+ 件に達するまで追加する）:

| カテゴリ | policy 例 | 件数 |
|---|---|---|
| セキュリティ | deny-privileged / deny-host-path / require-non-root | 5+ |
| リソース制限 | require-requests-limits / require-pdb | 3+ |
| ラベル規約 | require-app-label / require-team-label | 4+ |
| ネットワーク | require-network-policy / deny-external-ip | 3+ |
| イメージ管理 | verify-image-signature / deny-latest-tag | 5+ |
| Istio 連携 | require-sidecar-injection / require-peer-auth | 5+ |

## Step 4: 5 topology_class 確認

```bash
kubectl get nodes -L topology.kubernetes.io/zone,topology-class
```

zone ラベルが各ノードに設定されていることを確認する。

## 検収コマンド

```bash
kubectl get nodes --context kind-k1s0-infra | grep -c Ready
# control-plane 1 + worker 3 = 4 以上であること

kubectl get pods -n argocd | grep -c Running
# argocd pod が Running であること

kubectl get pods -n kyverno | grep -c Running
# kyverno pod が Running であること
```
