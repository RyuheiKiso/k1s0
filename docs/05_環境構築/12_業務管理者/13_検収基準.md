# 検収基準

## 一文方針

- Backstage UI へのアクセス成功 / tier2 admin API 接続成功 / tenant マスタ操作 demo 完了 / 監査検索 1 件ヒットの 4 条件を全て満たすことが業務管理者の環境構築完了の唯一の定義である。

> **pre-P0 注記**: `src/` および `tools/` は P0〜P10 deliverable（pre-P0 時点で実体ゼロ）。以下の検収コマンドは各 Phase 完了後に有効。

## 検収コマンド一覧

```bash
# 1. tier2 admin API 接続確認
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  https://api.staging.example.internal/v2/admin/health | jq '.status'
# 期待: "ok"

# 2. k1s0-admin CLI 確認
k1s0-admin --version 2>/dev/null || (curl --version | head -1 && jq --version)

# 3. tenant マスタ操作 demo（11_軸固有環境設定 Demo 1 の完走確認）
echo "Demo 1: tenant CRUD demo 完走を確認済みか？"

# 4. 監査検索 1 件ヒット確認（UI 目視 + CLI 確認）
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "https://audit.staging.example.internal/api/v1/logs?limit=1" \
  | jq '.items | length'
# 期待: 1 以上
```

## 検収チェックリスト

| 項目 | 確認方法 | 期待 |
|---|---|---|
| Backstage UI アクセス | ブラウザで URL を開く | ページが表示される |
| tier2 admin API 接続 | `curl .../health` | `"ok"` |
| tenant マスタ作成 | Demo 1 ステップ 1 | 成功レスポンス |
| tenant マスタ編集 | Demo 1 ステップ 3 | 成功レスポンス |
| tenant マスタ削除 | Demo 1 ステップ 4 | 成功レスポンス |
| 監査検索 1 件ヒット | 監査検索 UI / API | 1 件以上の結果 |
| 決定表エディタ表示 | Backstage UI | エディタが開く |
| docs lint | `bash tools/docs_lint/run_lint.sh`（P2 deliverable） | exit 0 |

上記 8 項目を全て満たした時点で「業務管理者の環境構築完了」とする。
