# テスト検証環境

## 一文方針

- 業務管理者は staging 環境での tier2 admin API による tenant マスタ操作 demo / 決定表編集 → 検証フロー / partner 連携設定フローの 3 フローを完走し、全て成功することを「テスト検証環境の構築完了」の定義とする。

> **pre-P0 注記**: `src/` は P10 deliverable（pre-P0 時点で実体ゼロ）。以下の手順は P10 完了後に有効。

## フロー 1: tier2 admin API による tenant マスタ操作 demo

staging 環境で tenant マスタの作成・編集・削除を行う。

```bash
# k1s0-admin CLI を使った場合の例
export ADMIN_TOKEN="<staging-token>"
export ADMIN_API="https://api.staging.example.internal"

# テナント作成
k1s0-admin tenant create \
  --name "demo-tenant-001" \
  --tier "tier1" \
  --env staging

# テナント一覧確認
k1s0-admin tenant list --env staging

# テナント編集
k1s0-admin tenant update demo-tenant-001 \
  --description "環境構築演習用テナント" \
  --env staging

# テナント削除
k1s0-admin tenant delete demo-tenant-001 --env staging --confirm
```

curl + jq による代替:

```bash
# テナント作成（curl 代替）
curl -s -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"demo-tenant-001","tier":"tier1"}' \
  "$ADMIN_API/v2/admin/tenants" | jq '.'
```

## フロー 2: 決定表編集 → 検証フロー

Backstage の決定表エディタで編集を行い、変更申請フローを確認する。

```
手順:
1. Backstage UI で [Decision Table Editor] を開く
2. テスト用決定表（test-ruleset-001）を選択する
3. いずれかのルールの値を変更する
4. [Save draft] をクリックする
5. [変更申請] ボタンが表示され、レビューリクエストが作成されることを確認する
6. Backstage プラグインの schema validation が成功することを確認する
7. [却下] または [Rollback] でドラフトを取り消す
```

## フロー 3: partner 連携設定フロー

partner テナントの連携設定を staging で確認する。

```bash
# partner API キー発行（例）
k1s0-admin partner create-key \
  --tenant "partner-tenant-001" \
  --scope "read:tenants,write:events" \
  --env staging

# partner webhook URL 設定（例）
k1s0-admin partner set-webhook \
  --tenant "partner-tenant-001" \
  --url "https://partner.example.com/webhook" \
  --env staging
```

## 検収コマンド

staging 環境への接続確認:

```bash
# API 疎通確認
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  https://api.staging.example.internal/v2/admin/health | jq '.status'
# 期待: "ok"
```
