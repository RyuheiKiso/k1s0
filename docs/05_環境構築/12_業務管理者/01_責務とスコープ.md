# 業務管理者 責務とスコープ

## 一文方針

- 業務管理者はテナント別マスタ管理 / 決定表編集 / 監査検索 / 緊急対応 / partner 連携設定の 5 責務を持ち、システム構築（全軸エンジニア）/ リリース（k1s0 作者）は非責務とする。

## 責務 5 本

### テナント別マスタ管理

tier2 admin API（`k1s0-admin` コマンドまたは curl + jq）を使い、tenant マスタを作成・編集・削除する。変更はすべて monitoring 画面および監査ログに記録される。変更前に staging 環境で動作確認を行う規律を持つ。

### 決定表編集

Backstage プラグインの決定表エディタを使い、業務ルール（承認フロー / 制限値 / 振り分けロジック）を編集する。編集後は変更申請フローに従い、審査を通過してから production に適用する。

### 監査検索

監査検索 UI を使い、テナント操作の履歴を検索・確認する。コンプライアンス対応や障害調査の際に証跡を取得する。検索結果は CSV エクスポートが可能。

### 緊急対応

tenant のアクセス停止要求・パスワードリセット要求・データ修正依頼などの緊急対応を行う。対応ログを監査検索 UI で確認し、事後に管理者ログを記録する。

### partner 連携設定

partner テナントの連携設定（API キー発行 / 権限スコープ設定 / webhook URL 設定）を tier2 admin API から行う。設定変更は staging で確認後に production に反映する。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| システム構築（DB / API サーバ / インフラ） | 全軸エンジニア |
| リリース管理 / release gate | k1s0 作者 |
| production cluster 運用 | ops 軸エンジニア / プラットフォーム運営者 |
| KEK ceremony / break-glass | プラットフォーム運営者 |
| formal 証明 | formal 軸エンジニア |

## LLM 補助の扱い

| 作業 | LLM 可 |
|---|---|
| tenant マスタ操作の手順確認 | ○（補助のみ） |
| 決定表のパターン分析 | ○ |
| 監査ログの初期分析 | ○（補助のみ） |
| tenant マスタの実際の作成・編集・削除 | 禁止（人間が UI / CLI で実行） |
| partner API キーの発行 | 禁止（人間が実行） |
