# 軸固有環境設定

## 一文方針

- 業務管理者固有の環境設定として、tenant マスタ作成 → 編集 → 削除の一通り demo / 監査ログ検索 demo / 決定表編集 + 変更申請フローの 3 demo を staging 環境で完走することを必須とする。

## Demo 1: tenant マスタ 作成 → 編集 → 削除

staging 環境で tenant の ライフサイクル全体を操作する。

```bash
export ADMIN_TOKEN="<staging-token>"

# ステップ 1: tenant 作成
k1s0-admin tenant create \
  --name "env-setup-demo-001" \
  --tier "tier2" \
  --description "環境構築 demo 用テナント" \
  --env staging
echo "作成完了"

# ステップ 2: 作成確認
k1s0-admin tenant get env-setup-demo-001 --env staging | jq '.'

# ステップ 3: tenant 編集
k1s0-admin tenant update env-setup-demo-001 \
  --description "環境構築 demo 用テナント（更新済み）" \
  --env staging
echo "編集完了"

# ステップ 4: 削除
k1s0-admin tenant delete env-setup-demo-001 --env staging --confirm
echo "削除完了"
```

## Demo 2: 監査ログ検索 demo

監査検索 UI で demo テナントへの操作ログを検索し、1 件以上ヒットすることを確認する。

```
ブラウザ操作手順:
1. https://audit.staging.example.internal を開く
2. [検索条件] で以下を設定する
   - 対象テナント: env-setup-demo-001
   - 日付範囲: 今日
   - 操作種別: tenant.create, tenant.update, tenant.delete
3. [検索] をクリックする
4. 3 件以上の操作ログがヒットすることを確認する
5. いずれかのエントリを開き、操作者・タイムスタンプ・変更内容を確認する
```

## Demo 3: 決定表編集 + 変更申請フロー

Backstage の決定表エディタで変更申請フローを確認する。

```
Backstage 操作手順:
1. [Decision Table Editor] を開く
2. テスト用決定表（staging-test-ruleset）を選択する
3. rule の condition 値を変更する（例: 閾値を 100 → 110 に変更）
4. [Save draft] をクリックする
5. [変更申請] ボタンが表示されることを確認する
6. 変更申請フームに承認者と変更理由を入力する
7. [申請] をクリックし、申請 ID が発行されることを確認する
8. [却下（撤回）] で申請を取り消す（staging demo のため）
```

## 検収コマンド

```bash
# tier2 admin API 疎通確認
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  https://api.staging.example.internal/v2/admin/health | jq '.status'
# 期待: "ok"

# tenant 一覧取得確認
k1s0-admin tenant list --env staging | head -5
```

ブラウザでの確認（目視）:
- Backstage UI でテナント一覧が表示される
- 監査検索 UI で 1 件以上ヒットする
