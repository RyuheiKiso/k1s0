# data 軸エンジニア 責務とスコープ

## 一文方針

- data 軸エンジニアは 5 preservation_class の保全実装 / 4 layer 保全 / restore_drill 演習 / migration toolchain 開発の 4 責務を持つ。cluster 構築（infra 専任）/ アプリ層（tier1-3）は対象外である。

## 責務 4 本

### 5 preservation_class の保全実装

5 つの preservation_class（hot / warm / cold / archive / immutable）ごとに保全戦略を実装する。CloudNativePG（PostgreSQL）/ Kafka / ClickHouse / Apicurio Registry / Valkey / Rook+Ceph の各 OSS に対して保全ポリシーを定義し、バックアップ・リストア手順を文書化する。

### 4 layer 保全

データ保全を 4 layer で管理する。

| layer | 内容 |
|---|---|
| L1: アプリ層保全 | WAL / redo log / journal を用いた単一サービス保全 |
| L2: レプリケーション保全 | 非同期 / 同期レプリカによるデータ冗長化 |
| L3: バックアップ保全 | 定期スナップショット / WAL アーカイブ / オブジェクトストレージへの転送 |
| L4: 地理分散保全 | multi-region / cross-cluster バックアップ |

### restore_drill 演習

定期的な restore_drill を通じて、バックアップが実際にリストア可能であることを検証する。手順: backup → drop → restore → verify の 4 ステップで一通り実行し、データ欠損がないことを確認する。

### migration toolchain 開発

スキーマ移行（PostgreSQL: pg_migrate / Kafka: schema evolution / ClickHouse: ALTER TABLE）のツールチェーンを開発・管理する。Apicurio Registry を使ってスキーマの後方互換性を強制する。

## 対象 OSS

| OSS | 用途 |
|---|---|
| CloudNativePG | PostgreSQL Operator（k8s 上の OLTP DB） |
| Kafka | 非同期メッセージング（分散ストリーム処理） |
| ClickHouse | OLAP DB（集計・分析クエリ） |
| Apicurio Registry | Avro / Protobuf スキーマ管理・互換性検査 |
| Valkey | Redis 互換 KVS（セッション / キャッシュ） |
| Rook+Ceph | k8s 上の分散ストレージ（PVC プロビジョニング） |

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| k8s cluster 構築 / Kyverno policy 管理 | infra 軸エンジニア |
| アプリ層（tier1-3）実装 | 各 tier 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |
| KEK shamir M-of-N ceremony | プラットフォーム運営者 |
| production cluster の SRE 対応 | ops 軸エンジニア |
