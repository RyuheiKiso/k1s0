# CI 完全再現

## 一文方針

- `.github/workflows/docs_lint.yml` の全 job を push 前に手元で再現し、exit 0 を確認してから push する。CI で初めて気づく fail は作者の規律違反である。

> **pre-P0 注記**: `tools/docs_lint/` は P2 deliverable（pre-P0 時点で実体ゼロ）。以下の手順は P2 完了後に有効。

## docs_lint.yml の job 構成

```yaml
jobs:
  lint:            # "docs lint (8 check)"
  release_gate_check:  # depends-on: lint
```

### job: lint

```bash
# Step 1: Setup Python（CI: python-version: '3.12'）
# → 手元: source .venv/bin/activate（Python 3.12）

# Step 2: Run docs_lint (bash baseline)
bash tools/docs_lint/run_lint.sh

# Step 3: Run docs_lint (Python strict)
python3 tools/docs_lint/run_lint.py
```

手元での再現:

```bash
source .venv/bin/activate
bash tools/docs_lint/run_lint.sh
python3 tools/docs_lint/run_lint.py
```

### job: release_gate_check

現状は echo placeholder（`echo "release_gate meta.docs_lint_green: checking..."`）であり、実際の検証は行っていない。作者が CI runner を本実装に昇格させるまでは、`generate_release_gate.py` を手元で実行してサンプルを確認することで代替する。

```bash
python3 tools/lock_yaml_generator/generate_release_gate.py
cat tools/lock_yaml_generator/samples/release_gate.lock.yaml
```

## CI との差分チェックリスト

| CI ステップ | 手元コマンド | 同等か |
|---|---|---|
| Setup Python 3.12 | `python3 --version` で 3.12.x 確認 | ○ |
| `run_lint.sh` | `bash tools/docs_lint/run_lint.sh` | ○ |
| `run_lint.py` | `python3 tools/docs_lint/run_lint.py` | ○ |
| release_gate_check | `python3 tools/lock_yaml_generator/generate_release_gate.py` | △（echo のみのため近似） |

## push 前チェックリスト

```bash
# 1. lint 双方が green
bash tools/docs_lint/run_lint.sh && python3 tools/docs_lint/run_lint.py

# 2. 新規ファイルがある場合: id 重複がないこと
python3 tools/docs_lint/run_lint.py 2>&1 | grep "id 重複"

# 3. depends_on が dangling / 循環していないこと
python3 tools/docs_lint/run_lint.py 2>&1 | grep -E "解決不能|循環"

# 4. dangling link がないこと
python3 tools/docs_lint/run_lint.py 2>&1 | grep "dangling link"
```

全コマンドが出力なしで終われば push 可能。

## 検収コマンド

```bash
bash tools/docs_lint/run_lint.sh && \
  python3 tools/docs_lint/run_lint.py && \
  echo "CI 完全再現: GREEN"
```
