# k1s0 作者 責務とスコープ

## 一文方針

- k1s0 作者は toolchain authoring / 19 軸 registry governance / cosign release 署名 / frontmatter schema evolve の 4 責務を持つ。tier1-3 / 横断軸専任 / 業務マスタの実装実務は対象外であり、実装品質の監査のみを行う。

## 責務 4 本

### toolchain authoring

docs_lint（run_lint.sh / run_lint.py）/ lock_yaml 生成器（generate_release_gate.py）/ drawio 作図ツール（drawio-lint / drawio-export / svg-postcheck）を開発・改訂する。CI ワークフロー（.github/workflows/docs_lint.yml）の設計変更も作者が行う。

### 19 軸 registry governance

`docs/01_企画/90_メモ/00_軸登録適合仕様.txt` の registry.yaml を管理し、v1 cap 20 内での新軸追加・廃止を承認する。新軸を追加する場合は同型の 14 方針メモ + 1 構造仕様が整うことを merge 条件とする。

### cosign release 署名

`release_gate.lock.yaml` の AND-gate が green になった後、git tag に cosign 署名を付与する。署名鍵の保管・更新は作者の専管事項であり、他ロールに委譲しない。

### frontmatter schema evolve

`docs/00_format/frontmatter_schema.yaml` の改訂・`tools/docs_lint/run_lint.py` の `PHASE_PREFIX_BY_PATH` 拡張・phase / kind enum 追加を行う。schema 変更は必ず dual sign-off（人間 2 名）を経る。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| tier1 Rust / Go / C# / TypeScript 実装 | tier1 軸エンジニア |
| tier2 業務ドメイン実装 | tier2 軸エンジニア |
| tier3 UI / 帳票実装 | tier3 軸エンジニア |
| infra cluster 構築 | infra 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |
| formal 証明 | formal 軸エンジニア |
| KEK shamir custodian | プラットフォーム運営者 |
| production cluster 運用 | ops 軸エンジニア + プラットフォーム運営者 |

## LLM 補助の扱い

LLM（Claude Code 含む）による toolchain 生成・spec 草案作成は許容する。ただし以下は人間 dual sign-off が必須：

- `docs/00_format/frontmatter_schema.yaml` の変更
- `00_軸登録適合仕様.txt` registry.yaml への entry 追加
- `release_gate.lock.yaml` の AND-gate 更新
- cosign 署名の実行
