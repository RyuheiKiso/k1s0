# tier2 軸エンジニア 責務とスコープ

## 一文方針

- tier2 軸エンジニアは業務資産（Domain Event / Workflow / 決定表 / 業務マスタ / DB schema）の所有 / 拡張点定義 / atomic 三表書込の実装を担う。proto/OSS 定義（tier1）/ クライアント UI（tier3）/ cluster 構築（infra）は非責務である。

## 責務

### 業務資産の所有

tier2 は以下の業務資産を所有し、変更の承認権を持つ。

| 資産種別 | 説明 |
|---|---|
| Domain Event | 業務上の出来事を表すイベントスキーマ（Avro / Protobuf） |
| Workflow | 業務フローの状態遷移定義 |
| 決定表 | 業務ルールを表形式で表現したもの（Decision Table） |
| 業務マスタ | 製品 / 顧客 / 組織などの master data |
| DB schema | PostgreSQL テーブル定義 / マイグレーションスクリプト |

### 拡張点定義

tier1 の Generic コンポーネントに対して業務ドメイン固有の拡張点（extension point）を定義し、tier1 側の汎化実装を業務固有化する。

### atomic 三表書込の実装

「Outbox テーブル / Event ログテーブル / 業務テーブル」の 3 テーブルへの書込を 1 トランザクションで完結させる atomic 三表書込パターンを実装する。Kafka Outbox Pattern と Apicurio Registry を使用した schema バリデーションを含む。

### 業界 pack の管理

業種・業態固有の業務資産をまとめた「業界 pack」を管理する。業界 pack は `src/tier2/<industry>/` 配下に配置し、業務マスタ / 決定表 / Domain Event schema を含む。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| proto 定義 / OSS インターフェース定義 | tier1 軸エンジニア |
| 個別業務 UI / 帳票レイアウト | tier3 軸エンジニア |
| cluster 構築 / Kubernetes 設定 | infra 軸エンジニア |
| 脅威モデル / penetration testing | security 軸エンジニア |
| formal 証明 | formal 軸エンジニア |
| production cluster 運用 | ops 軸エンジニア |
| toolchain / 軸登録 governance | k1s0 作者 |
