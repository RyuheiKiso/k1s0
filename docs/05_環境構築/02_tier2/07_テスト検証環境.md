# テスト検証環境

## 一文方針

- Docker compose で postgres / kafka / clickhouse / apicurio の 4 サービスを同時起動し、atomic 三表書込のローカル検証とドメイン bound CT が全 pass になることを本ページの検収とする。

> **pre-P0 注記**: `src/tier2/` は P10 deliverable（pre-P0 時点で実体ゼロ）。以下の手順は P10 完了後に有効。

## 4 サービス同時起動

tier2 開発用 docker compose ファイルで 4 サービスを起動する。

```bash
docker compose -f src/tier2/docker-compose.dev.yml up -d
```

起動確認:

```bash
docker compose -f src/tier2/docker-compose.dev.yml ps
# postgres / kafka / clickhouse / apicurio が全て Up になること
```

サービスごとの疎通確認:

```bash
# postgres
psql -h localhost -U postgres -d tier2_dev -c "SELECT 1;"

# apicurio
curl http://localhost:8080/apis/registry/v2/system/info

# kafka（kafka-topics コマンド）
docker compose -f src/tier2/docker-compose.dev.yml exec kafka kafka-topics.sh --bootstrap-server localhost:9092 --list
```

## atomic 三表書込のローカル検証

atomic 三表書込（Outbox / Event log / 業務テーブル）のローカル検証を実行する。

```bash
cd src/tier2
cargo test --test atomic_write_test
# または
go test ./... -run TestAtomicWrite
```

3 テーブルへの書込が 1 トランザクションで完結し、ロールバック時に全テーブルが元の状態に戻ることを確認する。

## ドメイン bound CT（Component Test）

業務ドメイン単位のコンポーネントテストを実行する。

```bash
cd src/tier2
# Rust CT
cargo test --test domain_ct --features integration

# Go CT
go test ./... -tags integration -run TestDomain

# .NET CT
dotnet test --filter Category=DomainCT
```

## サービス停止

```bash
docker compose -f src/tier2/docker-compose.dev.yml down
```

## 検収コマンド

```bash
docker compose -f src/tier2/docker-compose.dev.yml up -d
docker compose -f src/tier2/docker-compose.dev.yml ps | grep -E "postgres|kafka|clickhouse|apicurio"
cargo test --test atomic_write_test
docker compose -f src/tier2/docker-compose.dev.yml down
```
