# security 軸エンジニア 責務とスコープ

## 一文方針

- security 軸エンジニアは 5⁴ cell 脅威モデル管理 / 8 secret class 定義 / 5 build_provenance_class / incident response / penetration testing の 5 責務を持つ。KEK shamir custodian の M-of-N ceremony はプラットフォーム運営者が担当し security 軸の対象外である。

## 責務 5 本

### 5⁴ cell 脅威モデル管理

5 次元 × 4 軸の脅威モデルマトリクス（5⁴ = 625 cell）を管理する。各 cell は「攻撃ベクタ / 影響範囲 / 検出可能性 / 対策状況」の 4 軸で評価する。脅威モデルは定期的にレビューし、新脅威を追加・古い脅威を更新する。

### 8 secret class 定義

8 つの secret class を定義し、各 class の管理手順を文書化する。

| class | 内容 |
|---|---|
| SC-1 | 人間 credential（パスワード / MFA seed） |
| SC-2 | サービス credential（API key / service account key） |
| SC-3 | 暗号鍵（対称鍵 / AES / ChaCha20） |
| SC-4 | 非対称鍵（RSA / ECDSA 秘密鍵） |
| SC-5 | PKI 証明書（TLS / mTLS） |
| SC-6 | SPIFFE SVID（X.509 / JWT） |
| SC-7 | KEK（Key Encryption Key）シェア（shamir） |
| SC-8 | build signing 鍵（cosign / sigstore） |

### 5 build_provenance_class の管理

build_provenance_class（source / build / test / sign / deploy）ごとに provenance の生成・検証手順を定義する。SLSA レベルに対応させて各 class の要件を記述する。

### incident response

セキュリティインシデントの初動対応手順（Detection → Containment → Eradication → Recovery → Lessons Learned）を定義・演習する。Falco によるランタイム検知と SIEM 連携手順を整備する。

### penetration testing

OWASP ZAP / Trivy / Semgrep を組み合わせた定期的な penetration testing を実施する。OWASP TOP 10 をカバーするチェックリストを管理し、発見された脆弱性をトラッキングする。

## 非責務（他ロールへの委譲）

| 事項 | 担当ロール |
|---|---|
| KEK shamir M-of-N ceremony（実際の鍵セレモニー） | プラットフォーム運営者 |
| k8s cluster 構築 / Kyverno policy 管理 | infra 軸エンジニア |
| アプリ層（tier1-3）の実装 | 各 tier 軸エンジニア |
| DB 保全（PostgreSQL / Kafka / ClickHouse） | data 軸エンジニア |
| production cluster SRE 対応 | ops 軸エンジニア |

## LLM 補助の扱い

脅威モデルの draft 作成・セキュリティポリシーの草案は LLM 補助を許容する。ただし以下は人間 dual sign-off 必須:

- SC-7 / SC-8 の鍵材料の操作
- Kyverno deny rule の追加（enforce mode）
- penetration testing 結果の公式確認
