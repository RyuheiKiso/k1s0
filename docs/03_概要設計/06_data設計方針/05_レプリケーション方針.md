# data レプリケーション方針

## 一文方針
- PostgreSQL は CloudNativePG Replica Cluster + WAL streaming、Kafka は Strimzi 内 ISR + cluster 跨ぎ MirrorMaker2、ClickHouse は Replicated MergeTree + macro replicas、Ceph は RGW multi-site、を default とする。replication topology は preservation_class が一意に導出する。

## 至高路線における立ち位置
- PostgreSQL logical replication multi-master（pglogical multi-master）採用しない（v1 single-primary）
- Kafka Cluster Linking（Confluent Community）採用しない（MM2 一本）
- ClickHouse non-Replicated MergeTree 採用しない
- dual-write 同期採用しない（Outbox + CDC のみで heterogeneous replication）
- manual promote（人間が runbook を叩く）採用しない（v1_local_only 除く）

## replication topology（preservation_class 別）

### v1_local_only
- PostgreSQL: primary のみ（standby なし）
- Kafka: RF=1（dev/stage 限定）
- ClickHouse: 1 shard × 1 replica
- Valkey: 単一 master
- cross-zone / cross-region replication なし

### v1_zone_replicated
- PostgreSQL: 1 primary + 2 sync standby（zone 分散）、`synchronous_commit=remote_write`、`synchronous_standby_names='ANY 1 (...)'`
- Kafka: RF=3, ISR=2、`broker.rack=zone`、`unclean.leader.election.enable=false`
- ClickHouse: 1 shard × 3 replica（Replicated MergeTree、zone 分散）、clickhouse-keeper 3 nodes zone 分散
- Valkey: master + 2 replica、Sentinel quorum=2

### v1_cluster_replicated
- PostgreSQL: v1_zone_replicated + 別 cluster に async standby（CloudNativePG cluster-to-cluster streaming）
- Kafka: v1_zone_replicated + MirrorMaker2 で別 cluster に async mirror
- ClickHouse: ≥ 2 shard × 2 replica
- Valkey: Cluster mode

### v1_cross_region_replicated
- PostgreSQL: primary region に 1 primary + 1 sync standby、standby region に 1 sync standby（`synchronous_commit=remote_apply`、Replica Cluster モード）、**RPO ≈ 0**
- Kafka: primary region に RF=3, ISR=2、standby region に MirrorMaker2 で strict-ordering async mirror
- ClickHouse: primary region に Replicated MergeTree、standby region に macro replicas
- Ceph: RGW multi-site で primary → standby async replication

### v1_global_replicated
- PostgreSQL: cell-based partitioning、各 cell は per-region single-leader 構造
- Kafka: cell-partitioned topic、MirrorMaker2 は read-replication 用途で双方向 mirror
- ClickHouse: macro replicas は per-region replicated
- Ceph: RGW multi-site bidirectional sync、object 命名に cell_id / region prefix を含めて bucket 単位の書き込み owner を home region に固定

## CloudNativePG Replica Cluster
- mode: streaming replication、`synchronous_commit` を preservation_class 別に固定
- Replica Cluster CR: standby region 側に source primary の情報を CR で宣言、CloudNativePG が WAL streaming を確立
- failover: Argo Events trigger で standby を promote
- 物理機構: synchronous_commit は OS fsync 完了を待って commit、remote_apply は standby が WAL apply 完了を待つ

## Strimzi（Kafka）レプリケーション
- cluster 内: rack awareness で broker を zone に紐付け、`min.insync.replicas=2` を rack 跨ぎで物理強制
- cluster 跨ぎ: MirrorMaker2 を Strimzi KafkaMirrorMaker2 CR で deploy
    - v1_cluster_replicated: 単方向 async mirror
    - v1_cross_region_replicated: 単方向 strict-ordering + offset translation
    - v1_global_replicated: 双方向 mirror（read-replication 用途）
- topic 命名: mirror 先で `<source-cluster>.<topic-name>` prefix を付与
- schema: GitOps SoT 経路（Argo CD + Apicurio Operator が各 cluster へ declarative reconcile）

## ClickHouse レプリケーション
- 単一 cluster 内: Replicated MergeTree + clickhouse-keeper で part metadata を全 replica 同期
- 複数 cluster 間（同 region）: Distributed table を front、背後の Replicated MergeTree が複数 cluster で keeper cluster federation
- 複数 region: macro replicas、keeper を region 内独立、Distributed の `internal_replication=true` で cell 内に push
- DDL: ON CLUSTER 句で全 replica 同期適用

## Valkey レプリケーション
- 範囲: cache 用途、永続化対象外、cross-cluster 同期なし
- cluster 内: Sentinel mode（≤ v1_cluster_replicated）/ Cluster mode（≥ v1_cross_region_replicated）
- cross-region: 同期しない（cache の divergence を許容、application 側で再 fetch）

## Ceph RGW multi-site
- mode: master zone（primary region）+ secondary zone（standby region）、bidirectional は v1_global_replicated 時のみ
- bucket 単位 replication policy、object lock は両 zone で同一適用
- 物理: RGW の sync agent が pull、object 単位で eventual consistency

## replication lag SLI
- 各 replication 経路に lag SLI を持つ:
    - `v1_replication_lag_postgres`: `pg_stat_replication.replay_lag`
    - `v1_replication_lag_kafka_mm2`: MirrorMaker2 metric per topic
    - `v1_replication_lag_clickhouse`: keeper の queue 長
    - `v1_replication_lag_ceph`: multi-site sync status
- lag が preservation_class の RPO target を超過すると 13 SLO error budget burn として連動

## split-brain 防止
- PostgreSQL: synchronous_commit + Replica Cluster の quorum 構造で primary 二重昇格を不可能化、CloudNativePG が fence 制御
- Kafka: `unclean.leader.election=false`、ZooKeeper（KRaft）が leader election quorum で物理保証
- ClickHouse: clickhouse-keeper の Raft quorum で part metadata の整合保証、minority partition は read-only
- Ceph: RGW multi-site の master / secondary は明示的、split-brain 時は secondary が read-only

## failover orchestration（data 層担当部分）
- infra 15 の 5 orchestrator のうち、data 層が物理 trigger を提供するもの:
    - `external_dns_multi_region`: DNS 切替後に data 層 endpoint が新 region を指す
    - `argo_rollouts_traffic_shift`: standby promote 完了を Argo Events が検知、rollout が traffic を切替
- data 層が単独で動かす機構:
    - CloudNativePG の auto-promote
    - clickhouse-keeper の leader election
    - Kafka KRaft controller の leader election

## 強制機構との bind
- 本方針は [data 強制機構](../../04_詳細設計/02_強制機構/05_data強制機構.md) の以下経路で物理 enforce される:
    - 層 D: Kyverno `require-postgres-synchronous-commit` `require-kafka-min-insync` `require-replicated-clickhouse` `require-kafka-unclean-leader-disable` admission policy
    - 層 E: synchronous_commit / min.insync.replicas / clickhouse-keeper Raft の物理機構

## 採用しない replication 機構
- PostgreSQL logical replication multi-master: 採用しない
- Kafka Cluster Linking: MM2 一本
- ClickHouse non-Replicated MergeTree: 採用しない
- dual-write 同期: 採用しない
- manual promote（人間が runbook を叩く）: 自動 promote、runbook は再現可能 script として artifact 化
