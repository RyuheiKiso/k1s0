# data 復旧訓練方針

## 一文方針
- 全 preservation_class の RPO / RTO は restore_drill で必ず物理検証する。drill cadence を超過した cluster は admission policy が即時 block、drill 結果は `restore_drill.lock.yaml` に build artifact として刻む。infra01 の failover_drill と data01 の restore_drill は AND-gate で 1.0.0 ship blocker。

## 至高路線における立ち位置
- 「business が忙しい時は drill cadence を緩める」禁止
- production 上の chaos 直接適用禁止（drill 専用の sandbox cluster で実行、production への drill は v1_global_replicated のみ cell 単位）
- drill 結果の人手判定禁止（assertion は機械的に評価）

## drill 種別（4 種）

### drill 1: full restore（PITR）
- PostgreSQL: base backup + WAL から N 時点の state を新 cluster に復元、application から read query を実行して整合検証
- 目標: RPO / RTO を SLA 内達成

### drill 2: cross-region failover restore
- v1_cross_region_replicated / v1_global_replicated 対象
- primary region を Litmus で network partition、standby promote → traffic shift → 旧 primary recovery → fallback の full cycle
- 目標: RPO=0 / RTO ≤ 5 min

### drill 3: crypto-erase verification
- GDPR 削除要求の crypto-erase が物理的に復号不可化を達成しているか、削除後 archive copy の test decrypt が必ず失敗することを検証
- 目標: rotation 後の old DEK で decrypt 不可

### drill 4: archive_to_offline restore
- cold archive 期限超過 object の復元演習。tape / 外部 bucket からの fetch、復号、整合確認まで
- 目標: 24 時間 SLA 内に復元完了

## drill cadence（preservation_class 別）

| class | drill 1 | drill 2 | drill 3 | drill 4 |
|---|---|---|---|---|
| `v1_local_only` | 180 day | - | - | - |
| `v1_zone_replicated` | 90 day | - | 90 day | - |
| `v1_cluster_replicated` | 60 day | 60 day | 90 day | 180 day |
| `v1_cross_region_replicated` | 30 day | 30 day | 90 day | 180 day |
| `v1_global_replicated` | 14 day | 14 day | 90 day | 180 day |

## drill 物理機構（Litmus / Argo Events）

### drill 1（full restore）
- Litmus chaos test を ChaosEngine CR で起動
- new ephemeral cluster を OpenTofu apply で構築
- CloudNativePG `bootstrap.recovery` を流して PITR
- sample query を実行、checksum 比較
- drill record を `restore_drill.lock.yaml` に追記

### drill 2（cross-region failover）
- Litmus で primary region を network partition
- Argo Events が standby promote trigger
- external-dns が DNS 切替（infra 15 と連動）
- traffic 統計で RTO 計測、data lag SLI で RPO 計測
- 旧 primary 復旧 → fallback 完了まで full cycle

### drill 3（crypto-erase）
- 試験用 PII row を生成、DEK で encrypt
- DEK を OpenBao で revoke（rotation 経路で破壊）
- archive copy を取得、test decrypt 試行
- 復号失敗を確認、復号成功なら drill red

### drill 4（archive_to_offline）
- tape / 外部 bucket から sample object を fetch
- 復号 + checksum 比較
- 24 時間 SLA 内達成を確認

## restore_drill.lock.yaml（build artifact）
- 構造:
    - `cluster_id`
    - `preservation_class`
    - `drill_type`
    - `last_green_at`
    - `rpo_seconds_observed`
    - `rto_seconds_observed`
    - `artifacts`（artifact_id / stored_at）
    - `audit_signal_id`
- 全 drill の最終 green 時刻を class instantiation 単位で持つ
- 生成: drill orchestrator が CI に push、手書き禁止
- 整合: classes.yaml の drill_cadence_days を超過した cluster は admission policy が新規 deploy block

## admission block 経路
- Kyverno admission policy `block-on-restore-drill-red`:
    - `require-preservation-class-annotation` で全 data object に preservation_class が宣言されていることを保証
    - `restore_drill.lock.yaml` の green 状態を確認
    - drill_cadence_days を超過した instance への新規 deploy / 新規 schema migration を block
- break-glass: infra 14 と同じ break-glass 経路

## drill 失敗時の運用
1. 該当 cluster を `restore_drill.lock.yaml` で red 状態
2. admission policy が新規 deploy block
3. 13 SLO error budget freeze と連動
4. postmortem PR 起票必須、原因 → policy fix → drill re-run まで完了で green 復帰
- drill 失敗の累積: 3 期連続失敗で preservation_class 自体の v1 適格性を CI で fail

## infra01 failover_drill との AND-gate
- 1.0.0 ship blocker:
    - infra01 `failover_drill.lock.yaml` で全 cluster green
    - data01 `restore_drill.lock.yaml` で全 cluster green
    - 上記 AND が `release_gate.lock.yaml` の AND-gate に入力
- infra topology の zone partition drill が green でも data restore drill が red なら ship 不可

## chaos coverage
- Litmus chaos experiment が drill 経路に組み込まれる最小コーパス:
    - postgres-primary-kill（drill 1, 2）
    - kafka-broker-kill（drill 1）
    - kafka-controller-kill（KRaft）
    - clickhouse-replica-kill（drill 1）
    - region-network-partition（drill 2）
    - clickhouse-keeper-kill（drill 2）
    - cross-region-replication-pause（drill 2）
    - openbao-key-revoke（drill 3）
    - cold-archive-fetch（drill 4）

## drill 自動化と再現性
- drill は手動で叩かない（v1_local_only 除く）
- 全 drill は Argo Events トリガで自動起動、Litmus ChaosEngine CR を build artifact から生成
- drill script は version controlled、手書き runbook は禁止
- drill artifact（log / 検証 query 結果）は preservation_class v1_cross_region_replicated 以上で 5 年保全

## 強制機構との bind
- 本方針は [data 強制機構](../../04_詳細設計/02_強制機構/05_data強制機構.md) の以下経路で物理 enforce される:
    - 層 C: Litmus chaos experiment の自動 replay
    - 層 D: Kyverno `block-on-restore-drill-red` admission policy
    - 層 E: cosign signed restore_drill.lock.yaml + Ceph RGW Object Lock retention

## 採用しない drill 機構
- 「business が忙しい時は drill cadence を緩める」: 禁止
- production 上の chaos 直接適用: drill 専用の sandbox cluster で実行
- drill 結果の人手判定: 禁止
