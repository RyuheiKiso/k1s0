# data 保全方針

## 一文方針
- 全 data store は preservation_class が要求する WAL / snapshot / archive の物理機構で「N 時点の state を必ず復元できる」ことを保証する。retention 期限と restore_drill cadence は preservation_class から一意に導出され、instance 個別 override は持たない。

## 至高路線における立ち位置
- logical backup（pg_dump）単独採用しない（CloudNativePG base backup + WAL streaming を default）
- external snapshot（Velero VolumeSnapshot）単独採用しない（補助のみ）
- 「retention は manual に設定」禁止（preservation_class が一意導出）

## 保全レイヤ（4 層）
- **層 1: online primary**（書き込みを受ける instance）: CloudNativePG primary、Kafka leader broker、ClickHouse primary replica、Valkey master、Apicurio primary pod
- **層 2: synchronous replica**（即時整合）: CloudNativePG synchronous standby、Kafka follower（min.insync.replicas）、ClickHouse Replicated MergeTree replica（keeper 経由）
- **層 3: asynchronous replica / WAL streaming**（短期復元）: CloudNativePG WAL archive、Kafka MirrorMaker2、ClickHouse Distributed table、Longhorn snapshot
- **層 4: cold archive**（長期保全）: Ceph RGW（cold tier、Object Lock 適用）、archive_to_offline（手動 / 別契約、tape / 外部 bucket）

## CloudNativePG 保全
- WAL: pg_wal-archive で連続 archive、archive 先は Ceph RGW（同 cluster）+ cross-region Ceph RGW（v1_cross_region_replicated 以上）
- Base backup: CloudNativePG が daily に基底 backup を取得、Ceph RGW に保管

### retention（preservation_class 別）
| class | retention |
|---|---|
| `v1_local_only` | 7 日 |
| `v1_zone_replicated` | 30 日 |
| `v1_cluster_replicated` | 90 日 |
| `v1_cross_region_replicated` | 365 日 |
| `v1_global_replicated` | 365 日 + immutable archive |

- PITR: base backup + WAL の任意時点へ復元可能。RPO = WAL archive 完了 lag（≤ 60 秒、target ≤ 5 秒）
- 物理機構: synchronous_commit / WAL archive 完了確認 / pg_wal の disk flush は OS layer の fsync で物理 enforce

## Strimzi（Kafka）保全

### replication（preservation_class 別）
| class | replication.factor | min.insync.replicas |
|---|---|---|
| `v1_local_only` | RF=1 | ISR=1 |
| `v1_zone_replicated` | RF=3 | ISR=2（rack 跨ぎ）|
| `v1_cluster_replicated` | RF=3 + MM2 | - |
| `v1_cross_region_replicated` | RF=3 + MM2 strict-ordering | - |
| `v1_global_replicated` | RF=3 + MM2 双方向 mirror | - |

### retention.ms（preservation_class 別）
| class | retention.ms |
|---|---|
| `v1_local_only` | 1 d |
| `v1_zone_replicated` | 7 d |
| `v1_cluster_replicated` | 30 d |
| `v1_cross_region_replicated` | 90 d |
| `v1_global_replicated` | 90 d + cold archive |

- tiered storage: v2 候補
- cold archive: retention 超過 topic は Kafka Connect で Ceph RGW に sink、object lock 30 日
- 物理機構: min.insync.replicas は acks=all 時に物理 enforce、broker 側で reject

## ClickHouse 保全
- Replicated MergeTree: keeper 経由で全 replica が WAL（part の zk metadata）を共有
- tiered storage（disk_s3）: hot SSD（Longhorn）→ cold S3（Ceph RGW）、TTL move による自動移動
- backup: clickhouse-backup（CLI）で base backup を Ceph RGW に保存
- cross-region: v1_cross_region_replicated 以上で macro replicas を別 region keeper に配置

## Valkey 保全
- 原則: Valkey は cache 用途のみ、保全対象外
- persistence（AOF / RDB）は無効が default
- 永続化が必要な KV は CloudNativePG の `kv_<context>` table に降ろす

## Apicurio Registry 保全
- storage backend = CloudNativePG instance、その instance の preservation_class が Apicurio の保全 class と等価
- subject 削除は禁止（schema 進化の forward-only と整合）

## Outbox / audit_local 保全
- Outbox table: tier2 業務 Service の同 transaction で INSERT、Debezium publisher が Kafka に流した後 published_at update。retention は published 後 30 日
- audit_local table: tier1/09 観測可能性 の audit signal の local 一次保管。ClickHouse への push が成功したら flush、retention は 7 日

## archive_to_offline（cold tier）
- retention 超過した base backup / WAL / Ceph object は archive_to_offline 経路:
    - archive 先 1: Ceph RGW（別 region cluster、cold tier）
    - archive 先 2: 手動 / 別契約（tape / 外部 cloud bucket）
- immutable: Ceph RGW Object Lock を Compliance mode で適用、retention 期限内は物理 delete 不可
- encryption: SSE-KMS（OpenBao 経由）+ application-layer envelope encryption の二重
- 復元: archive_to_offline からの復元は manual runbook、完了 SLA は 24 時間

## retention の物理 enforcement
- retention 値は preservation_class が決め、KafkaTopic CR / CloudNativePG ScheduledBackup CR / ClickHouse TTL / Ceph RGW Lifecycle が物理 enforce
- retention 値の application-side override は admission block
- retention 短縮（90日 → 30日）は新 preservation_class を切る形でしか表現できない

## RPO / RTO の物理保証

| class | RPO | RTO |
|---|---|---|
| `v1_local_only` | 24 h | 4 h（手動）|
| `v1_zone_replicated` | 5 s | 60 s |
| `v1_cluster_replicated` | 60 s | 5 min |
| `v1_cross_region_replicated` | 0 | 5 min |
| `v1_global_replicated` | 0 | 0（per-cell continuous）|

- RTO は restore_drill で物理検証
- RPO は WAL archive lag / replication lag の SLI で常時監視

## 強制機構との bind
- 本方針は [data 強制機構](../../04_詳細設計/02_強制機構/05_data強制機構.md) の以下経路で物理 enforce される:
    - 層 D: Kyverno `require-postgres-synchronous-commit` `require-kafka-min-insync` `block-on-restore-drill-red` admission policy
    - 層 E: synchronous_commit / min.insync.replicas / Ceph Object Lock の物理機構

## 採用しない保全機構
- logical backup（pg_dump）単独: 採用しない
- external snapshot（Velero）単独: 補助のみ
- 「retention は manual に設定」: 禁止
