# 認証コンテキスト伝播

## 一文方針
- Keycloak OIDC で取得した access_token と AuthContext / SessionContext を、tier3 BFF auth-edge → tier1 Gateway → tier1 Backend-for-Library → tier2 リポジトリ抽象 → tier3 / tier2 Domain Event → tier1 Companion runtime まで全 layer で同型に伝播する。tenant_id は AuthContext から取得を強制し、form / URL / body での受付を物理拒否する。

## 伝播 envelope（全 SDK / 全層共通）
- `tenant_id`（OIDC token claim `tid`）
- `actor_id`（OIDC token claim `sub`）
- `session_context`（tier1 10/11 適合仕様 SessionContext）
- `authorization`（OIDC access_token、Bearer）
- `idempotency_key`（SDK 自動採番）
- `trace_context`（W3C `traceparent` / `tracestate`）
- `baggage`（OTel baggage、tenant_id 等のサブセット）
- `preferred_locality`（infra topology 由来）

## 5 auth_class（[tier1 認証適合仕様](../../04_詳細設計/01_適合仕様/04_認証適合仕様.md)）
- `v1_human_session` / `v1_workload_jwt` / `v1_device_attest` / `v1_federated_exchange` / `v1_emergency_step_up`

## BFF auth-edge（[BFF auth-edge](../../04_詳細設計/03_クロスカッティング適合仕様/06_BFF_auth_edge.md)）
- 1 tier3 ごとに 1 BFF Service
- httpOnly cookie 保管（access_token を SPA に渡さない）
- Authorization header 自動付与（BFF が backend に Bearer attach）
- refresh_token rotation（silent renew 代替）
- OIDC back-channel logout 受信
- CSRF + CORS 規律

## tenant_id 強制注入
- tier1 Library が transaction 開始時に SET LOCAL する GUC（`app.tenant_id`、`app.actor_id`、`app.purpose`、`app.delegation_chain`）
- tier2 リポジトリ抽象が `tenant_id` 述語を強制注入（業務コードからの省略を不可能化）
- tier3 form / URL / クエリパラメータでの `tenant_id` 受付を CI で deny

## SDK 経由での access_token 不可視化
- SDK 公開 API として `getAccessToken()` 不在
- localStorage / sessionStorage / cookie / window.* / IndexedDB / Service Worker いずれにも置かない
- BFF cookie 経由のみで backend と通信

## 採用しない設計
- access_token の SDK 公開 API 露出
- form / URL / クエリパラメータでの tenant_id 受付
- iframe + prompt=none による silent renew
- localStorage / cookie への access_token 平文保管
- impersonation の SDK ユーザによる能動開始
