# 観測コンテキスト伝播

## 一文方針
- W3C Trace Context（`traceparent` / `tracestate`）+ Baggage を tier3 RUM → BFF → tier1 → tier2 → data の全層で 1 trace に統合する。5 signal class（logs / metrics / traces / profiles / audit）の SoR は ClickHouse / Prometheus に分離、4 dimension layer（core / tier1_ext / tier2_ext / tier3_ext）を OpenTelemetry Weaver で生成、PII redaction は OTel Collector で物理削除。

## 5 signal class
- **logs**: ClickHouse `logs` table（trace_id top-level）
- **metrics**: Prometheus（exemplar に trace_id 必須）
- **traces**: ClickHouse `traces` table + Jaeger v2 first-party storage（tail sampled）
- **profiles**: Parca（trace_id label）
- **audit**: ClickHouse `audit` table（PII 構造的不在、hash chain）

詳細は [観測適合仕様](../../04_詳細設計/01_適合仕様/03_観測適合仕様.md)。

## 4 dimension layer
- **core**: OTel Semantic Conventions base
- **tier1_ext**: `tier1.bidi.*` / `tier1.transport.*` / `tier1.oss.exposed.*`
- **tier2_ext**: `tier2.tenant.id` / `tier2.aggregate.id` / `tier2.business_event` / `tier2.purpose`
- **tier3_ext**: `tier3.screen.id` / `tier3.interaction.kind` / `tier3.web_vitals.*` / `tier3.layer`

## trace_id を primary key とする cross-signal cross-tier 相関
- tier3（Web SPA / Companion）で生成または継承された trace_id が tier2 業務 API / Companion Gateway / tier1 backend を貫く
- transport adapter は trace context を各 transport で機械的にマップ
- cross-signal join: ClickHouse 側で trace_id 列の equi-join、Apache Superset で SQL JOIN

## 観測 Collector の 2 段 pipeline
- 段 1: per-node DaemonSet（loadbalancingexporter で trace_id routing）
- 段 2: gateway-aggregator Deployment（tail_sampling processor + clickhouseexporter）

## PII redaction の単一の真
- `redaction.yaml` で PII field を 1 箇所に列挙
- OTel Collector の attributes processor / transform processor で物理削除
- Library / Companion / app code に同等処理を持たせない
- audit signal は構造的に PII 不在（schema レベルで物理拒否）

## Companion 経由の trace context 注入
- `k1s0.Companion.NetFx.OTelExt` が CLR Profiler 経由で 4 stack（HttpClient / HttpWebRequest / WebClient / WCF）に Activity attribute 注入
- HLC tuple `(tier1.clock.hlc_physical_ms / tier1.clock.hlc_logical_counter / tier1.clock.hlc_node_id)` を必須包含

## 採用しない設計
- 単段 Collector（DaemonSet 単体で tail_sampling 完結する構成）
- 文字列リテラル直書きの attribute 名
- Library / Companion / app code に redaction 処理を分散
- 高 cardinality attribute の metric 化
- audit schema への PII 列追加
