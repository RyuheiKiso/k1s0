# tier3 業務管理 UI 境界

## 一文方針
- tier3 は「日々の業務操作」のための UI に責務を絞り、業務管理機能（マスタ管理 / 監査検索 / 緊急対応 / schedule 編集 / partner 連携設定）は Backstage プラグインに分離する。tier3 業務 UI に admin 機能を載せる経路は CI 物理拒否（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 2）。

## tier3 業務 UI の責務範囲
- 業務担当者の日々の業務操作（read + write of business aggregate）
- フォームレイアウト / 帳票レイアウト / 通知 UI / 業務エラー UX
- 認可ガードによる activate / deactivate / 表示 / 非表示

## tier3 業務 UI に載せないもの
- マスタ管理（業務管理者が編集）
- 監査検索（compliance + 業務管理者）
- 緊急対応 / break-glass（プラットフォーム運営者 + 業務管理者）
- schedule 編集（cron job / batch 起動）
- partner 連携設定（外部システム連携）
- ABAC policy 編集
- テナント onboarding / offboarding

## 業務管理 UI（Backstage プラグイン）への分離
- Backstage プラグインで業務管理機能を提供
- tier2 admin API 経由（`tier2.<pack>.admin.v1`）
- 全 admin 操作を audit_event に emit
- dual sign-off / break-glass two-person rule（重大度に応じて）

## API package 分離
- 業務 API: `tier2.<pack>.<domain>.v<N>`（tier3 業務 UI から import 可）
- 業務管理 API: `tier2.<pack>.admin.v<N>`（Backstage プラグインのみ、tier3 業務 UI からの import を CI で deny）

## 採用しない設計
- tier3 業務 UI に admin 機能を埋込
- 業務担当者が admin API を直接呼出
- 業務 API と admin API の同 package
- audit emit を伴わない admin 操作
