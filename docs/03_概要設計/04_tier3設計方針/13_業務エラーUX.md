# tier3 業務エラー UX

## 一文方針
- tier2 BusinessConflict subtype（4 種: stale_write / lost_update / supersede / concurrent_edit）と UI presentation の対応を 1:1 で固定する。recovery_hints / エラーコード / PII redaction / 多言語対応 / 部分失敗の標準 UX で表現する。

## tier2 業務例外と UI presentation の対応表

| BusinessConflict subtype | UI presentation | recovery action |
|---|---|---|
| `stale_write` | 通知 toast「他のユーザによる更新が検出されました。自動的に最新値を反映して再送します」 | auto rebase + auto resend |
| `lost_update` | 3-way merge UI dialog | user choice: 自分の変更 / 他者の変更 / merge |
| `supersede` | silent toast「より新しい操作が確認されました」 | queue entry delete |
| `concurrent_edit` | presence indicator update + 「他のユーザが編集中です」notice | user choice: continue / abort |

## 業務的失敗とシステム失敗の区別
- **業務的失敗**: tier2 BusinessConflict / domain validation error → 業務語彙で表現、recovery action 明示
- **システム失敗**: network / 5xx / authentication / authorization → 技術的状態を最小限に、user に「再試行 / サポート連絡」のオプション

## recovery_hints の UI 表示
- tier2 がエラーレスポンスに `recovery_hints` を含める
- 例: 「現在の数量を確認してください」「最新値を読込み」「サポートに連絡」
- UI 側は recovery_hints を action button に変換

## エラーコードの表示
- 業務エラーコードは user に non-technical な短い表現で表示
- 詳細エラーコード（`E_TIER2_PROCUREMENT_001` 等）は「詳細」リンク expand で表示
- サポート連絡時に user が伝えやすい形式

## 詳細エラーの収集（サポート連携）
- detailed error log は ClickHouse `logs` table に emit（trace_id 付き）
- user が「サポートに連絡」を選択 → `trace_id` を copy 可能な UI で提示
- サポート engineer は trace_id で 1 trace を完全 reconstruction 可能

## PII を含むエラー詳細の取扱
- PII を含むエラー message は OTel Collector の redaction processor で物理削除（[観測適合仕様](../../04_詳細設計/01_適合仕様/03_観測適合仕様.md)）
- UI 側にも PII を含むエラー詳細を表示しない
- user 自身の PII は表示可能（自身の入力値）、他者の PII は redact

## 多言語対応
- エラーメッセージは i18n key で表現（[アクセシビリティ国際化](14_アクセシビリティ国際化.md)）
- locale ファイルとの差分を CI で検査（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 7）

## 部分失敗（複数操作の一部成功）の表示
- bulk operation で一部失敗 → 成功件数 / 失敗件数 / 失敗詳細リスト
- 失敗 entry に retry / skip option

## リトライ可能性の明示
- retry_policy_class（[client リトライバックオフ方針](../09_client設計方針/06_リトライバックオフ方針.md)）に基づき UI で明示:
  - `v1_idempotent_safe`: 自動 retry（user 不可視）
  - `v1_idempotent_with_key`: 自動 retry + 失敗時に user に再送提案
  - `v1_non_idempotent`: 自動 retry なし、user 確認後再送
  - `v1_long_streaming_resumable`: resume_token で透過再接続
  - `v1_eventual_via_pending_queue`: pending queue で自動 send

## 採用しない設計
- BusinessConflict subtype と UI 分岐の override（[クライアント状態適合仕様](../../04_詳細設計/01_適合仕様/11_クライアント状態適合仕様.md) で禁止）
- 技術的エラーコードのそのまま表示
- PII を含むエラー詳細の UI 表示
- 自動 retry なしでのシステム失敗
- 部分失敗の隠蔽（必ず詳細表示）
