# tier3 状態遷移 UI

## 一文方針
- aggregate 状態遷移を UI で表現する場合、tier2 状態機械の許可された遷移のみを button / action として提示する。compile-time に不正遷移を防止（[tier2 状態遷移パターン](../03_tier2設計方針/13_状態遷移パターン.md) の 4 言語等価強度）、UI は state-aware で activate / deactivate を制御する。

## 状態 visualization
- 現在状態を badge / chip で表示
- 状態遷移履歴を timeline で表示（audit_event 由来）
- 次の遷移可能 action を button として提示（無効遷移は disable）

## 状態遷移 action
- 各状態で許可された遷移 method（tier2 generated stub 経由）のみ呼出
- 不正遷移は compile error（型レベル enforce）
- action 実行は Optimistic Local layer で即時 UI 反映、ack で Server Truth 昇格

## 状態遷移確認 dialog
- 業務 critical な遷移（注文確定 / 検査結果確定 等）は確認 dialog
- 確認 dialog は a11y 準拠（focus trap / aria-modal）

## 状態遷移後の UI 反応
- 成功: toast + 画面遷移（次の業務操作へ）
- BusinessConflict: subtype 4 種で UI 分岐
- システムエラー: 「再試行 / サポート連絡」action

## tier3 拡張点
- 状態遷移後の hook（pre / post）は tier3 override 可能
- ライフサイクル基本遷移は tier2 が所有（override 不可）

## 採用しない設計
- runtime guard のみによる不正遷移防止（必ず compile-time）
- 状態遷移を tier3 で勝手に定義
- action 実行で server response 待ちで UI block（Optimistic Local 必須）
