# tier3 画面遷移とルーティング

## 一文方針
- SPA routing は React Router（または Tauri WebView 同等）で declarative 宣言、認証ガード / 認可ガード / ディープリンク / 未保存変更破棄警告を 5 標準 hook で物理 enforce。tier3 間遷移は BFF cookie scope（`Domain=<tier3>.<tenant>.<root_domain>`）で構造的に分離。

## SPA routing 規約
- React Router declarative 宣言（`<Route path="...">`）
- URL pattern: `/<industry>/<domain>/<screen>/<aggregate_id?>`
- query string で view state（pagination cursor / filter）
- HTML5 History API（hash routing は採用しない）

## 認証ガード
- BFF cookie 不在 → BFF login redirect endpoint へ navigate
- session expiry 検知 → Snackbar 通知 + 再ログイン redirect
- back-channel logout broadcast → 即座に画面遷移（[BFF auth-edge](../../04_詳細設計/03_クロスカッティング適合仕様/06_BFF_auth_edge.md)）

## 認可ガード
- 各 route に必須 role / permission を `<Route guards={...}>` で declarative 宣言
- 認可 deny → 403 画面（業務的にアクセスできない旨を表示）
- 認可結果は tier2 が一次情報として保持、client-side cache を持たない（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 4）

## ディープリンク
- 全 screen はディープリンク可能（URL から復元可能な状態）
- 未認証で deep link → BFF login redirect 後、元の URL へ復帰
- aggregate 不在 → 404 画面、tier3 業務 UI から代替アクションを提示

## 未保存変更の破棄警告
- Draft layer に dirty state が存在する場合、画面遷移時に confirmation dialog
- React Router の `<Prompt>` または `useBlocker` で実装
- 「保存」「破棄」「キャンセル」の 3 選択肢

## 履歴 / 戻るボタン
- ブラウザ戻るボタンで前画面 navigate
- 業務的な「キャンセル」操作は履歴と独立に明示的なボタンで提供
- modal dialog の back ボタン挙動は modal close（route 遷移しない）

## ブレッドクラム
- 全画面に breadcrumb component
- 業務階層（業界 / ドメイン / aggregate）を反映
- breadcrumb は route hierarchy から自動導出

## アプリ間遷移（複数 tier3 連携）
- BFF cookie scope は `Domain=<tier3>.<tenant>.<root_domain>`（tier3 間の cookie 漏洩を構造的に遮断）
- tier3 間 deep link は別 origin への navigate（cross-domain redirect）
- 共通 SSO（Keycloak）で再認証なし
- session state は各 BFF で独立保持

## バージョン違いへの対応
- bundle versioning + cache busting（fingerprint hash）
- 古い bundle 版での deep link は最新 bundle にリダイレクト + 復元
- API バージョン違いは tier2 互換性ポリシーに従う

## 採用しない設計
- hash routing（`#/path`）
- 認証ガード bypass の dev mode
- 認可結果の client-side cache
- ディープリンク不可な画面
- 未保存変更破棄警告の opt-out
- tier3 間 cookie 共有
