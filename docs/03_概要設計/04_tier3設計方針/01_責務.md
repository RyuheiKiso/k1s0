# tier3 の責務（個別業務 UI と業務シナリオ所有）

## 一文方針
- tier3 は個別業務に特化した Web サイト・exe を提供する。プラットフォーム構成における最上位の業務アプリケーション層に位置する。tier2 を一次消費し、業務語彙でユーザに表現する。業務不変条件・整合性境界・認可規則は tier2 が所有し、tier3 は tier2 の override 拡張点を通じて UI 層の業務固有差分のみを表現する。

## tier3 が所有するもの
- 画面遷移シナリオ（業務シナリオ単位の画面フロー / wizard / 多画面トランザクション境界）
- フォームレイアウト（入力欄 / グルーピング / バリデーション表示位置 / キーボード移動順 / 補助入力）
- 業務エラーの UI 表現（tier2 が返す業務エラー型を、ユーザが取れるアクションとして表現）
- 帳票のレイアウト（PDF / 印刷向けレイアウト、明細・集計の可視配置。集計値そのものは tier2 が提供）
- 業務イベントへのユーザ通知 UI（toast / banner / 一覧の差分強調）。発火条件は tier2 の Domain Event に従う
- UI 上のキーボード操作 / ショートカット / IME 補助 / アクセシビリティ補助
- UI 認可結果の反映（活性 / 非活性 / 表示 / 非表示の制御。認可判定そのものは tier2 / tier1 が行う）

## tier3 が所有しないもの

### 業務資産
- Domain Event の schema 定義 / 発行責務
- Workflow / Saga 定義 / 補償処理
- 決定表 / 業務ルール
- 業務マスタ構造
- DB schema
- API 振る舞い（バリデーション / 業務不変条件 / 認可規則）
- これらは tier2/06 業務資産所有権に従い tier2 が所有

### infra への直接アクセス
- DB / Kafka / Temporal / Keycloak / Valkey / Object Storage 等への直接接続は禁止
- tier3 はすべて tier2 の API（Library / Service）経由でアクセス

### tier1 Library / Companion / Gateway の直接消費
- tier3 は tier1 を直接消費しない
- tier1 の横断的共通要素（自動計装 / 認証 token 取得などの runtime）に乗ることだけは許容

### 業界横断概念 / 業界 pack 概念の独自定義
- 業務語彙は tier2 から借りる
- tier3 が独自の業務語彙を作って画面に出すことは禁止

## 背景・狙い
- tier3 担当はジュニア級エンジニア。業務不変条件 / 整合性境界 / セキュリティ制御を tier2 が守り、tier3 は表現に集中することで、業務品質を構造的に底上げする
- tier3 が業務資産を所有すると、別の tier3 が同じ業務を別の実装で扱うことになり、整合性 / 監査 / 規制対応が破綻する
- 業務処理の正解は一つに集約し、tier3 は「同じ業務処理を異なる操作シナリオで表現する場」とする

## 抽象化レベル別 影響範囲
- **Lv 業界横断**: tier2 が提供する横断業務 API（通知 / 監査 / 承認 / 帳票 / マスタ管理）の UI 表現。tier2 のマイナー変更時、tier3 は override 部の追従のみで済む
- **Lv 業界共通**: 業界 pack 内で共通する業務語彙（製造業: 「設備」「ロット」「検査結果」等）の UI 表現。tier3 は override 部 + 該当ドメイン参照部のみ追従
- **Lv 業界固有**: 業界 pack 内ドメイン固有の業務語彙（FA / 調達 / 検査 各ドメイン）の UI 表現。tier3 は当該ドメイン利用部の追従のみで済む
- **Lv テナント固有**: テナント差分は tier2 の override / 設定で吸収される。tier3 のコード変更を伴わない（マスタ・ルール・権限の差分のみ）

tier3 の追従責務は「tier2 が提供した拡張点に対する UI 表現の更新」に限定する。業務不変条件側に踏み込む追従は禁止する。

## 業務管理機能との分離
- マスタ管理 / 監査検索 / 緊急対応 / schedule 編集 / partner 連携設定などの業務管理機能は tier3 業務 UI に載せない
- Backstage プラグインとして提供される業務管理 UI に分離する
- tier3 は「日々の業務操作」のための UI に責務を絞る
