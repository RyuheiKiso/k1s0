# tier3 業務カスタマイズ粒度

## 一文方針
- tier3 業務 UI の業務カスタマイズは 4 抽象化レベル（業界横断 / 業界共通 / 業界固有 / テナント固有）で粒度が定義される。テナント固有差分は tier2 override layer + 設定で吸収、tier3 のコード変更を伴わない。

## カスタマイズ粒度の 4 レベル

### Lv 業界横断
- 通知 / 監査 / 承認 workflow / 帳票 / マスタ管理 / ユーザ・組織管理
- tier2 が単一実装、tier3 は表示する

### Lv 業界共通（製造業）
- 設備 / ロット / 品目 / 拠点 / BOM の参照系
- tier2 が業界 pack 内で単一実装、tier3 は業務シナリオ別 UI

### Lv 業界固有（FA / 調達 / 検査）
- ドメイン固有業務（生産指示 / 進捗実績 / 発注 / 検収 / 検査計画 / 不良票）
- tier2 が pack 内 ドメイン別実装、tier3 は当該ドメイン業務 UI
- tier3 で extension point override 可能

### Lv テナント固有
- テナント別マスタ値 / 承認規則 / 権限ロール定義 / 業務ルール（決定表）
- tier2 override layer + 設定で吸収
- tier3 のコード変更を伴わない（マスタ・ルール・権限の差分のみ）

## tier3 override 可能範囲
- 業界固有 Lv: extension point 経由で業務 UI 拡張可能
- テナント固有 Lv: 設定 / マスタ参照のみで業務 UI 自動切替
- 業界横断 / 業界共通 Lv 不変条件: override 不可

## tier3 業務カスタマイズの実装パターン
- form layout の override（[業務資産所有権](../03_tier2設計方針/06_業務資産所有権.md) extension point）
- 帳票テンプレートの override
- 通知 UI の override
- 業務エラー UI 表現の override

## 採用しない設計
- 業界横断 / 業界共通 Lv 不変条件の override
- 拡張点宣言外の override
- テナント差分のための tier3 コード変更（必ず tier2 override layer 経由）
