# tier3 内部アーキテクチャ

## 一文方針
- tier3 内部はクリーンアーキテクチャの依存方向に従い、UI 層（components）→ application 層（use cases）→ infrastructure 層（tier2 SDK adapter）の単方向依存。tier3 リポジトリ内に .proto ファイルを置かず、tier2 が単一の真。

## レイヤ構成
- **UI 層（components / pages）**: 画面コンポーネント、フォームコンポーネント、共通 UI（ボタン / モーダル / テーブル）。状態管理 hook を呼出
- **Application 層（use cases / state hooks）**: 業務シナリオ単位の use case。4 layer reducer の dispatch、tier2 SDK 呼出、画面遷移制御
- **Infrastructure 層（tier2 SDK adapter）**: tier2 SDK を直接呼出する adapter。BFF cookie 経由の Authorization、4 layer state の persistence（IndexedDB）

## 依存方向
- UI 層 → Application 層 → Infrastructure 層
- 逆方向の参照は禁止
- Infrastructure 層から tier1 Library / OSS への直接 import は CI で deny（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 1）
- UI 層からは tier2 SDK / Infrastructure 層を直接呼出しない（必ず Application 層 use case 経由）

## モジュール分割（製造業 pack の例）
- `domain-fa/`: FA ドメインの業務シナリオ（生産指示画面、進捗実績画面）
- `domain-procurement/`: 調達ドメイン（発注画面、検収画面）
- `domain-inspection/`: 検査ドメイン（検査計画画面、不良票画面）
- `common-ui/`: 業界横断 UI（通知、認証）
- `manufacturing-common-ui/`: 業界共通 UI（設備、ロット、品目、拠点、BOM）

ドメイン間の参照は Domain Event 購読のみ。直接の use case / hook 呼出は禁止（tier2 ドメイン分割と整合）。

## 公開 type の単一の真
- tier3 リポジトリ内に `.proto` ファイルを置かない（tier2 が単一の真）
- 業務 entity / 業務 event は tier2 .proto 由来の生成型のみを使用
- 独自型の宣言は禁止
- CI 検査: tier3 リポジトリ内の `.proto` 配置と業務 entity / 業務 event の独自再宣言を deny

## state library
- React 系: tier2 SDK 内蔵の 4 layer reducer + React hooks。Redux / Zustand 等の外部 state library は採用しない（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 1）
- C# (.NET 8+) WPF / WinForms: tier2 SDK 内蔵の 4 layer reducer + MVVM
- Tauri: WebView 側は React、Rust 側は tier2 Library 直接組込

## form library
- Web SPA: react-hook-form 等は採用するが、tier2 が提供する form schema validator を使う（業務固有 validation は tier2 が所有）
- フォーム入力 → Draft layer に reflect、confirm で send → Pending Queue layer

## UI コンポーネントライブラリ
- v1.0.0 では業界横断 / 業界共通 / ドメイン固有 の UI コンポーネントを「共通 component package」として tier2 が配布、tier3 はそれを消費
- override は extension point（tier2 が宣言）経由のみ

## 採用しない設計
- tier3 リポジトリ内 .proto 配置
- 業務 entity / event の独自再宣言
- Redux / MobX / Recoil / Pinia / NgRx の外部 state library
- 自製 form validator
- UI 層から Infrastructure 層への直接呼出
- ドメイン間の use case 直接呼出
