# tier3 運用 UI

## 一文方針
- tier3 業務 UI の運用観察 UI は Backstage TechDocs（業務担当者向け使い方ガイド）+ Perses（tier3 専用 metric dashboard）+ Apache Superset（ad-hoc 分析）で構成する。SDK バグ / supply chain incident は ops 11 軸の運用ループに統合、tier3 開発者向けは [client 運用 UI](../../04_詳細設計/04_運用UI開発者体験/05_client運用UI.md) を参照。

## tier3 運用観察 UI

### Backstage TechDocs
- 業務担当者向け使い方ガイド（業務 UI 操作マニュアル）
- 各 tier3 の service catalog entry に紐付け
- MkDocs Material plugin で publish

### Perses（tier3 専用 metric dashboard）
- tier3_ext SemConv namespace（`tier3.screen.id` / `tier3.interaction.kind` / `tier3.web_vitals.*` / `tier3.layer`）
- screen 単位 / aggregate_id 単位の latency / error rate
- Web Vitals（LCP / INP / CLS）の RUM dashboard

### Apache Superset（ad-hoc 分析）
- ClickHouse 直 SQL で tier3 RUM event 集計
- 業務 KPI（業界 pack 別）

## tier3 incident response
- SDK バグ / supply chain incident（Cosign 失敗 / 脆弱性検出）は ops 11 軸の運用ループに統合
- tier3 hotfix waterfall は 30 日以内に他言語へ propagate（[client 配布 SemVer 方針](../09_client設計方針/05_配布SemVer方針.md)）
- tier3 CVE 開示は security 軸の incident response policy

## tier3 開発者向け運用 UI
- inner loop（Tilt + Companion local mock + dev container）
- 詳細は [client 運用 UI](../../04_詳細設計/04_運用UI開発者体験/05_client運用UI.md) を参照

## 業務管理 UI との分離
- 業務管理 UI は Backstage プラグイン（[tier2 管理境界](../03_tier2設計方針/14_管理境界.md)）
- tier3 運用観察 UI は Perses / Apache Superset / Backstage TechDocs に集約

## 採用しない設計
- tier3 業務 UI に運用 UI を載せる
- tier3 専用 ops 機構の独自開発（11 軸 ops 運用ループに統合）
- AGPL-3 OSS（Grafana / Tempo / Loki / Grafana OnCall）
