# tier3 リアルタイム更新 UX

## 一文方針
- 業務イベントの to-the-second 反映は HTTP/2 multiplex 上の SSE / Connect-RPC server-streaming で per-tab 16 subscription を上限とする。HTTP/1.1 業務 ingress は廃止、`v1_legacy_http11` は別ポート listener に分離（per-tab 上限 6）。

## per-tab 同時 subscription 16 の物理成立
- HTTP/1.1 は同一 origin 同時 6 接続が RFC / 主要ブラウザ実装の固定上限。HTTP/1.1 + SSE で 16 stream を per-tab に張ることは物理的に不可能
- HTTP/2 multiplexing（`max_concurrent_streams`、Envoy 既定 100）で 16 streams を single connection に乗せれば per-tab 16 subscription が成立
- tier1 ingress を HTTP/2 強制することが per-tab 16 subscription の唯一の物理的解（[HTTP/2 enforcement](../../04_詳細設計/03_クロスカッティング適合仕様/01_HTTP2_enforcement.md)）

## subscription source（4 conformance_class からの選択）
- `v1_alert`: server-driven 警報配信、低 lag + replay
- `v1_event_feed`: server-driven Domain Event 配信、順序保証 + replay
- `v1_live_snapshot`: server-driven 最新値表示、latest-wins
- `v1_interactive`（要 collaborative editing 等）: 双方向対話

詳細は [Bidi 適合仕様](../../04_詳細設計/01_適合仕様/01_Bidi適合仕様.md) を参照。

## UA aware adapter 経路
- `chrome_edge_direct`: Connect-RPC over HTTP/2 + fetch full-duplex streams（bidi primary）
- `chrome_edge_via_corp_proxy`: paired_post_sse（半二重 emulation）
- `firefox_safari`: paired_post_sse
- `dotnet_companion`: sse_paired adapter（Companion 経由）
- `tauri_native`: connect_bidi（Tauri sidecar 経由）

詳細は [Connect-RPC UA-aware adapter](../../04_詳細設計/03_クロスカッティング適合仕様/12_UA_aware_adapter.md) を参照。

## presence indicator
- 他 actor が同 aggregate を編集中の場合、presence indicator を UI に表示
- presence は短時間の TTL（30s）+ heartbeat
- BusinessConflict subtype `concurrent_edit` の発火条件と整合

## subscription life cycle
- 画面マウント時に subscribe 開始、unmount で unsubscribe
- background tab は subscription 継続するが UI 更新を間引く（CPU 節約）
- network 切断検出で subscription pause、復帰で resume_token で再接続（[client Transport 適応方針](../09_client設計方針/02_Transport適応方針.md)）

## 更新通知 UI 表現
- list 一覧: 差分強調（行ハイライト）+ 件数 badge 更新
- 詳細画面: 即時 reflect、user の編集中（Draft layer 存在）は presence indicator に統合
- toast / banner 通知: 業務イベントの種別に応じて発火（[業務エラー UX](13_業務エラーUX.md) と整合）

## subscription 上限超過時の挙動
- per-tab 16 を超える subscription 要求は SDK 内部で queue
- queue 滞留 30s で `SubscriptionLimitExceeded` を throw
- 業務 UI 側は priority 順（業務 critical な subscription を優先）

## v1_legacy_http11 環境での縮退
- `v1_legacy_http11` capability_class（企業 FW / DLP / TLS インスペクション appliance + Windows 10 1607 未満 + .NET Framework 4.6.1 以前）は per-tab 上限 6（HTTP/1.1 物理上限）
- 該当環境では subscription 数を 6 以下に絞る業務設計が必要（capability_matrix.lock.yaml で機械可読化）

## 採用しない設計
- HTTP/1.1 業務 ingress（HTTP/2 強制）
- WebSocket bidi の自製 frame protocol（Connect-RPC L1+ 単一深耕）
- per-tab 16 を超える subscription
- background tab での全 subscription 切断（resume_token で復帰可能）
