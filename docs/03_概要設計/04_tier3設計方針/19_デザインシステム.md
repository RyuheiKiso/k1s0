# tier3 デザインシステム

## 一文方針
- 共通 component package（Button / Modal / Table / Form / Toast / Dialog / Snackbar 等）は tier2 が業界横断 / 業界共通 / 業界固有レベルで配布、tier3 は extension point 経由で override する。WCAG 2.1 AA + Web Vitals 閾値内 + 統一 design token を全 component で必須要件とする。

## 共通 component の所有
- 業界横断 component: tier2 が配布（@k1s0/ui-components）
- 業界共通 component（製造業）: tier2 配布（@k1s0/manufacturing-ui-components）
- 業界固有 component（FA / 調達 / 検査）: tier2 配布、tier3 で extension point override 可能

## design token
- color palette / typography / spacing / shadow / border radius / animation duration を CSS variable + JSON で宣言
- light / dark mode 対応
- locale ごとの font fallback（日本語 / 英語）

## a11y 必須要件
- 全 component で WCAG 2.1 AA 準拠
- aria 属性を component 内部で自動付与
- カラーコントラスト ≥ 4.5:1
- focus indicator visible

## Web Vitals 配慮
- LCP / INP / CLS の閾値内
- lazy loading（route-level + component-level）
- code splitting

## tier3 拡張点
- 業界固有 component の override は tier2 が宣言した extension point 経由
- 独自 component 追加は extension point 内のみ（直接 mutation 禁止）

## 採用しない設計
- Material UI / Ant Design 等の外部 UI library（tier2 共通 component package に統一）
- inline style でのデザイン token 上書き
- ad-hoc な aria 属性追加（必ず共通 component 経由）
