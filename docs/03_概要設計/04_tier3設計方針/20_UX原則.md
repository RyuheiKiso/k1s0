# tier3 UX 原則

## 一文方針
- tier3 業務 UI の UX 原則は「業務語彙のみで表現 / エラーは復旧可能 action として提示 / オフライン透過 / 並行編集 presence 可視化 / a11y 標準準拠 / 学習曲線 minimum」の 6 原則。ジュニア級 tier3 担当でも一貫した UX を実現できる構造を提供する。

## 6 原則

### 業務語彙のみで表現
- 技術用語（HTTP status / DB error / network error）を user に表示しない
- tier2 業務語彙のみで表現
- 詳細エラーは「詳細」リンク expand で表示

### エラーは復旧可能 action として提示
- BusinessConflict subtype（[業務エラー UX](13_業務エラーUX.md)）の 4 種 1:1 UI 分岐
- recovery_hints を action button に変換
- 「再試行 / サポート連絡 / 破棄」の選択肢を明示

### オフライン透過
- 4 layer state で業務コード再設計なしに offline 業務継続
- offline 中は queue に蓄積、復帰時に自動 send
- 25h オフライン best-effort（PWA installed）

### 並行編集 presence 可視化
- 他 actor が同 aggregate を編集中の場合、presence indicator
- BusinessConflict subtype `concurrent_edit` で user choice

### a11y 標準準拠
- WCAG 2.1 AA 最低基準
- axe-core / Lighthouse CI で merge 阻止
- キーボード操作 / スクリーンリーダ対応

### 学習曲線 minimum
- 統一 navigation pattern（breadcrumb / Tab navigation / shortcut keys）
- 統一 form pattern（Section / Step / Wizard）
- 統一 error pattern（業務エラー UX 1:1 UI 分岐）
- onboarding tutorial（初回 login 時）

## 採用しない UX
- 技術用語の user 表示
- ad-hoc なエラー画面
- offline 中の操作 block
- presence 可視化なしの並行編集
- a11y 標準違反
