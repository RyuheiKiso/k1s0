# tier3 非同期処理 UX

## 一文方針
- 非同期処理（Workflow / Saga / batch）は Long-running operation（Start RPC → cursor 付き GetStatus）として表現し、UI は progress indicator + cancel button + 完了通知で標準化する。4 layer state（Pending Queue / Optimistic Local）で透過。

## Workflow 起動 UX
- 起動 button → Start RPC → workflow_id 受領
- progress indicator（stepper / progress bar）で workflow phase 表示
- cancel button（cancellation を Workflow 側で受領）

## 進捗表示
- cursor 付き GetStatus / Poll RPC で定期 polling（5s interval）
- streaming 配信せず、polling で進捗 update
- workflow phase ごとの description 表示（業務語彙）

## 完了通知
- 完了: toast + 画面遷移（結果画面へ）
- 部分失敗: 失敗詳細リスト + retry / skip option
- システムエラー: 「再試行 / サポート連絡」action

## オフライン中の Workflow 起動
- Pending Queue に enqueue、復帰時に自動 send
- offline 中は「保存中」status で UI 表示

## 長時間 Workflow（数分〜数時間）
- background tab に切り替えても polling 継続（Service Worker 経由）
- 完了通知は browser notification API（user 許諾必須）

## 採用しない設計
- streaming で Workflow 進捗配信（必ず polling）
- 完了待ちで UI block（必ず async + 復帰可能）
- offline 中の Workflow 起動 reject（必ず Pending Queue で透過）
