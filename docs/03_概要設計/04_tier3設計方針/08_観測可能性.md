# tier3 観測可能性

## 一文方針
- tier3 は OpenTelemetry Browser SDK + Auto-Instrumentation で span / metric / log / RUM / Web Vitals を自動 emit、tier3_ext SemConv namespace（`tier3.screen.id` / `tier3.interaction.kind` / `tier3.web_vitals.*` / `tier3.layer`）を OpenTelemetry Weaver で生成、PII redaction は OTel Collector で物理削除。

## OTel Browser SDK Auto-Instrumentation
- Web SPA: `@opentelemetry/sdk-trace-web` + `@opentelemetry/auto-instrumentations-web`
- 自動計装対象:
  - Resource Timing / User Timing API / Long Tasks API / Navigation Timing API
  - Service Worker fetch event を span 化
  - WebSocket / WebTransport stream event を auto-instr
  - First Input Delay / Largest Contentful Paint / Cumulative Layout Shift を metric として export

## デスクトップ exe / レガシー .NET Framework の観測
- C# (.NET 8+): OpenTelemetry .NET Auto-Instrumentation（CLR Profiler attach）
- Tauri: Rust 側 `opentelemetry-rust` + WebView 側 `@opentelemetry/auto-instrumentations-web`、context propagation で stitch
- レガシー .NET Framework: `k1s0.Companion.NetFx.OTelExt`（[Companion OTel 拡張](../../04_詳細設計/03_クロスカッティング適合仕様/11_companion_otel_extension.md)）

## tier3_ext SemConv namespace
- `tier3.screen.id`: 画面識別子
- `tier3.interaction.kind`: ユーザインタラクション種別（click / submit / navigate）
- `tier3.web_vitals.*`: Web Vitals（FID / LCP / CLS）
- `tier3.layer`: 4 layer state（ST / OL / PQ / DR）

OpenTelemetry Weaver で各言語の定数コードを生成、文字列リテラル直書きを CI で禁止（[観測適合仕様](../../04_詳細設計/01_適合仕様/03_観測適合仕様.md)）。

## RUM（Real User Monitoring）
- ユーザの実体験を Web Vitals + custom event で SoR に export
- screen 単位 / aggregate_id 単位の latency / error rate を集計
- ad-hoc 分析は Apache Superset で ClickHouse 直 SQL

## trace context propagation
- W3C Trace Context（`traceparent` / `tracestate`）+ Baggage を全 RPC / queue / IPC で propagate
- Browser → BFF → tier1 → tier2 → tier3 RUM が 1 trace で stitch
- Browser → Tauri sidecar / Browser → Service Worker / Tauri Rust → WebView の境界も Baggage 経由

## サンプリング
- default sampling: `parentbased_traceidratio`（rate 1.0 for error trace, 0.05 for success trace）
- sampling rate を 0 にする経路は禁止（最小 sampling rate 0.001）
- override は SDK 公開 API として `rpc.service` prefix 単位でのみ提供

## PII redaction
- tier1 09 観測適合仕様 の `redaction.yaml` と同期
- 物理削除は OpenTelemetry Collector のプロセッサで実施
- Library / Companion / app code に同等処理を持たせない

## audit emit
- `client.login.event` / `client.logout.event` / `client.token_refresh.event` / `client.purge.event` / `client.tenant_switch.event` / `client.actor_switch.event` / `client.impersonation_start.event` / `.end.event` / `client.break_glass.event`

## CSP / セキュリティヘッダ
- CSP / HSTS / X-Content-Type-Options / Referrer-Policy / Permissions-Policy を宣言
- CI 検査:
  - 配信される HTML レスポンスにセキュリティヘッダが含まれていることを E2E で検査
  - `unsafe-inline` / `unsafe-eval` が CSP に含まれていないことを CI で fail
  - SRI（subresource integrity）が第三者 CDN リソースに付与されていることを検査

## 採用しない設計
- 言語別 APM agent（NewRelic / DataDog / AppInsights）
- console.log の OTel 直 emit
- 自製 trace context 形式
- PII を含む自由テキスト attribute
- sampling rate 0 への設定
- CSP の `unsafe-inline` / `unsafe-eval`
