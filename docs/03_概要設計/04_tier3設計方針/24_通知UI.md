# tier3 通知 UI

## 一文方針
- 業務イベント通知 UI は toast / banner / inline / browser notification の 4 種で表現する。発火条件は tier2 Domain Event（[業務エラー監査コンプライアンス](../03_tier2設計方針/08_業務エラー監査コンプライアンス.md)）に従い、tier3 が独自 emit しない。a11y 準拠（aria-live="polite" / "assertive"）。

## 4 種通知

### toast（一時表示）
- 短時間（5s 程度）で消える通知
- 業務操作の成功 / 軽微な情報 / silent な BusinessConflict subtype
- 位置: 画面右下 / 上部
- aria-live="polite"

### banner（永続表示）
- ユーザが dismiss するまで表示
- システム警告 / 業務 critical な BusinessConflict subtype
- 位置: 画面上部
- aria-live="assertive"

### inline（一覧 / 詳細画面内）
- 一覧の差分強調（行 highlight）
- 詳細画面の field-level update 表示
- presence indicator（他 actor 編集中）

### browser notification（OS 通知）
- background tab / 画面非表示中の重要通知
- user 許諾必須（OS 設定 + browser 設定）
- 工場現場の警報配信 / 緊急対応 trigger

## 発火条件
- tier2 Domain Event（v1_alert / v1_event_feed の subscription）
- BusinessConflict subtype（stale_write は silent toast、lost_update は banner、supersede は silent toast、concurrent_edit は inline presence）
- システムエラー（network / 5xx）

## a11y 準拠
- aria-live="polite"（toast）/ "assertive"（banner）
- screen reader で自動 announce
- 通知は keyboard 操作で dismiss 可能

## 通知履歴
- 過去通知を履歴 panel で確認可能
- 通知 source（trace_id）で audit log と相関

## 採用しない設計
- 業務エンジニアが独自に通知 emit（必ず tier2 Domain Event 経由）
- alert モーダル（user 操作を block する）
- a11y 準拠なしの通知
