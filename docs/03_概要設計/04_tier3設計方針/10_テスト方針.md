# tier3 テスト方針

## 一文方針
- tier3 のテストは Playwright E2E + axe-core a11y + Lighthouse Web Vitals + Pact contract test + property based test の 5 種で構成。tier2 が提供する contract test suite を tier3 リポジトリの CI で必須実行、skip / 改変は CI fail。

## E2E（Playwright）
- L1+ primary: Playwright（02_採用 OSS）
- 対象 scenario:
  - login / logout / token refresh / impersonation
  - offline edit → resume scenarios（クライアント状態適合仕様 製造業 pack stress test）
  - capability negotiation の自動切替（UA aware adapter）
  - Service Worker fetch 分離
  - per-tab 16 subscription の HTTP/2 multiplex 動作
- PII 物理検査: headless browser で IndexedDB dump を読み、PII 平文混入を CI fail

## a11y（axe-core）
- axe-core を CI に組み込み、WCAG 2.1 AA 違反は merge 阻止
- 全画面コンポーネントに対し自動検査
- 国際化 / 多言語テスト: pseudolocalization での文字長変動検出も CI で実施

## Web Vitals（Lighthouse CI）
- LCP（Largest Contentful Paint）/ INP（Interaction to Next Paint）/ CLS（Cumulative Layout Shift）を Lighthouse CI で測定
- 閾値違反は merge 阻止
- サポート対象ブラウザでの動作確認を Playwright クロスブラウザで CI 実行

## contract test（Pact）
- L1+ primary: Pact（02_採用 OSS）
- tier2 が提供する contract test suite を tier3 リポジトリの CI で必須実行
- skip / 改変は CI で fail:
  - test runner の skip フラグの使用を検出
  - contract test の改変（assertion の弱体化）を CI で diff 検査
- tier2 minor version up 時、新版 contract test での再実行を CI に組み込む

## property based test
- L1+ primary: fast-check (TS) / FsCheck (.NET) / proptest (Rust)
- 対象:
  - 4 layer reducer の決定論性（39 conflict_tree.yaml の actions 投影）
  - retry backoff 系列の monotonicity / 期待値 ±5%
  - idempotency_key 採番の uniqueness（10^7 回で衝突 0）
  - capability negotiation の決定論性

## integration test（Testcontainers）
- L1+ primary: Testcontainers
- tier1 Server + Companion Mock + tier2 atomic 三表書込（CloudNativePG）+ Outbox（Kafka Strimzi）+ Keycloak + OpenBao を Testcontainers で起動、tier3 が本番に近い backend と round-trip

## 製造業 pack stress test
- 39 適合仕様 製造業 pack stress test scenario の tier3 投影テスト:
  - 業務担当 SPA の login + step_up → 発注承認
  - 工場現場の検査担当が React SPA で 5 件オフライン記録 → 復帰
  - 同 React SPA で 25h オフライン → idempotency_key TTL 超過
  - Browser SPA で BusinessConflict（lost_update）→ 3way merge UI を提示し、resume 後 ack 受領

## CSP / セキュリティヘッダ E2E 検査
- 配信される HTML レスポンスにセキュリティヘッダが含まれていることを E2E で検査
- `unsafe-inline` / `unsafe-eval` が CSP に含まれていないことを CI で fail
- SRI（subresource integrity）が第三者 CDN リソースに付与されていることを検査

## 翻訳キー未定義検出
- i18n の翻訳キーが未定義のまま参照されていないかを CI で検出
- 静的解析: `t('xxx')` 形式の参照を抽出し、locale ファイルとの差分を検査
- 未定義キー / 未使用キーを CI で fail

## 採用しない設計
- 商用 test orchestration platform（BrowserStack / Sauce Labs / LambdaTest / Mabl）
- contract test の skip / 改変
- WCAG 2.1 AA 違反 / Web Vitals 閾値違反の merge
- LLM-generated test の盲目的 merge
- production cluster 上の chaos / scenario / load test
- iframe + prompt=none による silent renew test
