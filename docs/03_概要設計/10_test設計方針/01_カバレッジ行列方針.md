# test カバレッジ行列方針

## 一文方針
- test 軸は 18 軸（07 transport / 08 migration / 09 observability / 10 auth / 11 key / 12 schema / 13 SLO / 14 OSS-lifecycle / 15 capacity / 32 data-tenant / 39 client-state / infra01 topology / data01 preservation / security15 threat-model / client15 SDK distribution / ops15 loop / 10_security/17 build_provenance / 08_infra/16 clock_integrity）を行、5 verification_class を列とする 18 × 5 = 90 cell の coverage matrix を `coverage_matrix.lock.yaml` の build artifact として固定し、全 cell が `last_green_at + artifact_pointer + cadence_days + drill_state + owner_4axis` の必須 field を欠かさず保持することを Kyverno admission policy + Conftest で物理 enforce する。`drill_state ∈ {green, red_handled, pending_with_artifact}` の 3 enum で red 経路を構造化追跡し、release_gate AND-gate には全 cell の `drill_state ∈ {green, red_handled}` を物理入力する。

## 至高路線における立ち位置
- matrix の単一の真: 手書き禁止、build artifact only
- dimension override 禁止、override したい場合は新 verification_class を切る
- dead spec を CI で殺す: matrix に entry がない (axis × class) 組合せ、artifact_pointer が物理に存在しない cell、cadence_days を超過した cell、owner_4axis 4 軸のうち 1 つでも `unassigned` を含む cell は CI fail
- 90 cell（v1 では 80 / 80）全 drill_state ∈ {v1_baseline_green, v1_drill_red_handled} が 1.0.0 ship blocker

## 全 cell 必須 field（6 field）

| field | 内容 |
|---|---|
| `cell_id` | `<axis>__<verification_class>` の文字列 PK |
| `artifact_pointer` | 実 artifact への relative path（pact / Playwright trace / chaos blueprint / mutation report / coverage XML / property test corpus）|
| `last_green_at` | 直近 green の UTC ISO8601 |
| `cadence_days` | 許容 staleness 日数（class × axis ごとに enum 化）|
| `drill_state` | v1_baseline_green / v1_drill_red_handled / v1_pending_with_artifact の 3 enum |
| `owner_4axis` | service_owner / domain_owner / framework_owner / drill_owner の 4 軸 owner ID |

## 5 verification_class（列、bundle）

| class | cadence_days | primary tool |
|---|---|---|
| `v1_type_invariant` | 1（PR ごと、daily refresh）| tsc / cargo check / go vet / Buf / jsonschema / CUE |
| `v1_property_axiom` | 7（weekly green）| Hypothesis / fast-check / proptest / jqwik / FsCheck |
| `v1_contract_pair` | 3（PR + nightly Pact verification）| Pact / Pact Broker / Buf |
| `v1_scenario_replay` | 14（biweekly、infra01 / data01 / 11 key / security15 / ops15 は 30）| Playwright / Apache JMeter / chainsaw |
| `v1_fault_chaos` | 30（infra01=90 / data01=30-180 / security15=90）| Litmus / Toxiproxy / AFL++ |

## 18 軸（行）と各軸の verification 必須 set

各軸は 5 verification_class 全てに必須 cell を持つ（90 cell の完全列挙）。詳細な必須 set は [検証規律適合仕様](../../04_詳細設計/01_適合仕様/19_検証規律適合仕様.md) を参照。

例:
- 07 transport: type_invariant（frame 型）/ property_axiom（backoff jitter）/ contract_pair（gRPC + gRPC-Web pair）/ scenario_replay（reconnect journey）/ fault_chaos（handshake drop / partial decode / network partition）
- 08 migration: type_invariant（4 phase enum）/ property_axiom（compatibility window）/ contract_pair（old / new pair）/ scenario_replay（dry_run 4 phase journey）/ fault_chaos（cutover failure）

## class × axis cadence_days 表（class_axis_cadence_table.yaml）
- `type_invariant`: 全軸 1 day
- `property_axiom`: 全軸 7 day
- `contract_pair`: 全軸 3 day（client15 のみ各 distribution_class の conformance_cadence_days を継承 = 14 / 30 day mixed）
- `scenario_replay`: 14 day（infra01 / data01 / 11 key rotation / security15 red-team / ops15 runbook drill は 30 day）
- `fault_chaos`: 30 day（infra01 failover_drill = 90 day、data01 restore_drill = 30〜180 day class 別、security15 red-team = 90 day）

## matrix 生成 pipeline（generator）

### input
- `registry.yaml`（00_軸登録）
- 各軸 spec の `verification_claim` entry
- test framework execution result（pytest / Hypothesis / Pact Broker / Playwright / Litmus / pitest / Apache JMeter）
- `class_axis_cadence_table.yaml`
- `ownership_table.lock.yaml`（test_owner 4 軸）

### generator
- Tekton Pipeline `coverage-matrix-generate`、deterministic
- cosign signed artifact、`release_gate.lock.yaml` の AND-gate に入力

### drift
- Argo CD の drift detect で `coverage_matrix.lock.yaml` の手書き変更を検出 → self-heal
- drift PR は Kyverno で merge block

## 例外と escalation

### 新軸追加時の grace window
- 00_軸登録 で軸が追加されても、coverage_matrix の対応 5 cell が green になるまでの猶予は最大 30 day（grace_window_days enum）
- grace 期間は cell.expected_status = `pending_with_artifact` 必須、grace 越えは新軸追加 PR の deploy block

### flaky cell
- cell が「green と red を交互に出す」と `flaky_quarantine.lock.yaml` に entry、quarantine_due_at 14 day 以内に修正必須、超過は cell delete + axis spec の verification_claim 削除（dead spec 殺し）

### test ownership 不在
- `owner_4axis` のいずれかが `unassigned` の cell は新規追加禁止、既存 cell は 7 day 以内に owner 割当必須、超過は service deploy block

## CI 不変条件（test カバレッジ行列の固有部分）
- 90 cell 全てに artifact_pointer / last_green_at / cadence_days / drill_state / owner_4axis 6 field が宣言、欠損 cell ゼロ
- `drill_state ∈ {v1_baseline_green, v1_drill_red_handled}` の cell のみが release_gate AND-gate に物理入力
- v1_baseline_green cell は last_green_at が cadence_days 以内
- artifact_pointer の path が物理に存在
- matrix の手書き drift = 0
- dead cell（未参照 axis × class）ゼロ
- mutation_score が monotonic increase（quarter 比較）
- flaky_quarantine の cell が quarantine_due_at 以内

## 強制機構との bind
- 本方針は [test 強制機構](../../04_詳細設計/02_強制機構/09_test強制機構.md) の以下経路で物理 enforce される:
    - 層 A: jsonschema / CUE による coverage_matrix.lock.yaml schema 検証
    - 層 B: Conftest による 90 cell 完備 / cadence 内 / owner 完備 check
    - 層 D: Kyverno `require-coverage-cell-green` admission policy
    - 層 E: cosign signed coverage_matrix.lock.yaml + Ceph RGW Object Lock retention
