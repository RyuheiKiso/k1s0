# test 契約検証方針（v1_contract_pair）

## 一文方針
- test 軸は v1_contract_pair verification_class を Pact L1+ + Pact Broker self-host + Buf-breaking との double-bound で実装し、隣接層間（producer / consumer / peer / SDK / DB / event / config / infra の 7 declaration 系列）の contract が双方向に一致することを Pact pact + buf-breaking signature の二系統 artifact で物理 enforce し、breaking detection を Kyverno admission policy で PR merge block する。

## 至高路線における立ち位置
- 商用 Pact SaaS（Pactflow）採用しない、self-host
- Pact 以外の contract test（Spring Cloud Contract / Karate）採用しない
- 文章のみで「contract OK」禁止、必ず Pact pact + Buf-breaking signature の双方を artifact 化
- breaking_policy override の人間判断介在禁止
- 商用 schema registry（Confluent / AWS Glue）採用しない、Apicurio Registry self-host

## 設計原則
- **contract pair は bundle である**: yaml の `test.contract.*` attribute のうち、pair_id 1 つの値が他 5 dimension（producer_role / consumer_role / declaration_class / pact_lifecycle / breaking_policy）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**: pacts.yaml に登録された全 pair_id、Pact Broker に publish された全 pact、buf workflow に declared 全 module、proto に annotated 全 RPC method の retry / slo / quota / observability annotation 欠損は CI fail
- **7 declaration 系列を全 pair で完備**: producer_to_consumer / peer_to_peer / sdk_to_server / db_to_app / event_to_consumer / config_to_runtime / infra_to_app
- **breaking detection は機械可読**: Buf-breaking + Pact can-i-deploy + jsonschema diff の三系統で物理判定、人間判断を介在させる経路は持たない
- **pact_lifecycle は append-only + tagging**: pact publication は immutable、tag による rollout（v1_dev / v1_staging / v1_prod / v1_archived）で state 表現

## pair_id 命名と field 構造
- 命名規則: `<axis>__<producer_role>__<consumer_role>__<declaration_class>` の 4 segment（例: `07_transport__server__client__producer_to_consumer`）

### 必須 field（7 field）
- `pair_id`: PK
- `producer_role` / `consumer_role`: service / SDK / DB / event / config 等の role enum
- `declaration_class`: 7 系列の enum
- `pact_lifecycle`: v1_dev / v1_staging / v1_prod / v1_archived
- `breaking_policy`: v1_strict（既定）/ v1_deprecation_window（08 migration の dual_window 中のみ allow）
- `artifact_pointer`: Pact Broker の pact reference + buf-breaking signature reference

## 7 declaration 系列
- `producer_to_consumer`: API producer → API consumer
- `peer_to_peer`: tier1 ↔ tier1 / tier2 ↔ tier2 の同層 peer pact
- `sdk_to_server`: 12 client distribution の SDK ↔ server pact（5 distribution_class 全て）
- `db_to_app`: PostgreSQL ↔ application、12 schema aggregate qualified name の DB-side declaration
- `event_to_consumer`: Kafka / NATS / event bus の producer ↔ consumer pact
- `config_to_runtime`: flagd / config map → runtime consumer pact
- `infra_to_app`: infra control plane ↔ workload contract（Kubernetes CRD / Argo CD application spec / Kyverno policy schema）

## pact 生成 pipeline
- **generator**:
    - consumer 側で Pact runtime（pact-python / pact-jvm / pact-js / pact-net / pact-go / pact-rust）が test 中に pact を出力
    - 出力 pact は Tekton Pipeline `pact-publish` 経由で Pact Broker self-host に publish
    - Pact Broker → producer の verify webhook を Tekton trigger に bind、producer 側で verify test を自動起動
    - Buf-breaking は producer 側 PR で proto / openapi / asyncapi の breaking detection を物理 fail
- **cosign**:
    - publish された pact は cosign signed、verify 結果も cosign signed
    - signature は `release_gate.lock.yaml` の AND-gate に入力

## pact lifecycle と tagging

| tag | 内容 |
|---|---|
| `v1_dev` | consumer の dev branch から publish、producer 側 verify 不要（参考用）|
| `v1_staging` | staging deploy 時の pact、producer verify 必須、verify red の場合 PR merge block |
| `v1_prod` | prod deploy 時の pact、producer verify 必須 + can-i-deploy green が release_gate AND-gate に入力 |
| `v1_archived` | rollback 後の pact、verify 不要、retention のみ（90 day）|

- tag 遷移: dev → staging → prod は monotonic、逆遷移は rollback としてのみ allow
- 同 pair に複数 tag が同時 active な場合は can-i-deploy が AND（全 active tag が green）

## breaking detection の 3 系統

### 系統 1: Buf-breaking
- proto / openapi / asyncapi の field add / remove / type change を Buf-breaking が物理判定
- breaking 検出 PR は Kyverno で merge block

### 系統 2: Pact can-i-deploy
- Pact Broker の can-i-deploy command が consumer / producer 側の deploy 適合性を判定
- red の場合 deploy が Kyverno admission policy で block

### 系統 3: jsonschema / CUE diff
- non-proto schema（jsonschema / CUE / yaml schema）に対する diff、Buf-breaking 同等の規律
- 13 SLO の SLO yaml schema、infra01 topology schema、data01 preservation schema 等が対象

## breaking_policy enum

### v1_strict（既定）
- 任意の field add / remove / type change を breaking として deploy block
- 7 transport / 12 schema / 13 SLO / client15 SDK distribution / 32 RLS が default

### v1_deprecation_window
- 08 migration の dual_window 中のみ allow
- dual_window_days の cadence_days 内に新 pair version の green が必須、cadence 越えは deploy block
- 適用範囲: 08 migration 4 phase 中の旧 / 新 pair に限定

## Pact Broker self-host 構成
- Pact Broker（OSS）を self-host、PostgreSQL backend
- cosign 署名された pact のみ publish allowed
- webhook:
    - Pact published → Tekton Pipeline `pact-verify` 自動起動
    - Pact verify result → `coverage_matrix.lock.yaml` の v1_contract_pair 列 cell の last_green_at 更新
    - can-i-deploy red → Mattermost incident channel に notify、ops の v1_change_induced signal として bridge

## cross-axis bind（contract_pair 列の cell）
- 07 transport: producer = tier1_server、consumer = sdk_runtime（5 distribution_class 全て）の 5 pact、Buf-breaking + Pact 双方向 lock
- 08 migration: 4 phase の旧 / 新 pact pair、dual_window 中の v1_deprecation_window pair が cadence 内
- 09 observability: OTel exporter ↔ collector の pact、SemConv attribute schema の Buf-breaking
- 10 auth: IDP ↔ client の OIDC contract、Keycloak の discovery document jsonschema
- 11 key: KMS ↔ application の API contract、KMS plaintext / wrapped envelope schema
- 12 schema: producer / consumer / DB / event / config の 5 declaration が aggregate qualified name で結節、本軸が双方向 lock
- 13 SLO: Sloth ↔ Pyrra の rule generator pact、recording rule の name space invariant
- 14 OSS-lifecycle: pair_target の旧 / 新 OSS API contract、major version migration drill 中の pact
- 15 capacity: quota engine ↔ admission policy の contract
- 32 data-tenant: GUC propagation contract、SessionContext の schema
- 39 client: client ↔ server resync contract、4-state machine transition contract
- infra01 / data01 / security15 / client15 / ops15: cluster ↔ control plane / replication / threat mitigation / SDK ↔ server / runbook ↔ alert の各 pact

## 強制機構との bind
- 本方針は [test 強制機構](../../04_詳細設計/02_強制機構/09_test強制機構.md) の以下経路で物理 enforce される:
    - 層 D: Pact Broker（self-host）の can-i-deploy result を Kyverno admission policy 入力に bind
    - 層 D: Kyverno `require-pact-can-i-deploy` admission policy
    - 層 E: cosign signed pact / buf-breaking signature

## 採用しない方針
- 商用 Pact SaaS（Pactflow）: 採用しない
- Pact 以外の contract test（Spring Cloud Contract / Karate）: 採用しない
- 文章のみで「contract OK」: 禁止
- breaking_policy override の人間判断介在: 禁止
- 商用 schema registry: 採用しない
- LLM-generated pact の盲目的 merge: 禁止
