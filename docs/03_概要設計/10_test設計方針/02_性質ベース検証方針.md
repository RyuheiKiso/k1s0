# test 性質ベース検証方針（v1_property_axiom）

## 一文方針
- test 軸は v1_property_axiom verification_class を Hypothesis（Python）/ fast-check（TS）/ proptest（Rust）/ jqwik（JVM）/ FsCheck（.NET）/ gopter（Go）の 6 言語 1 OSS L1+ 単一深耕で実装し、各軸 spec が宣言する property（不変条件）を generative input に対する反証不能性として artifact 化、shrink 後の最小反証 input を Hypothesis-database 互換の corpus 形式で immutable 保存し、seed の deterministic 化と stateful property test の model 同型化を Conftest + Kyverno admission policy で物理 enforce する。

## 至高路線における立ち位置
- random seed の test runner ローカル random 化禁止、必ず seed_pool / replay_corpus / pr_deterministic
- corpus の shrink 結果削除禁止、append-only + dead spec 検出のみ
- stateful property の手続き型 test 化禁止、必ず Hypothesis stateful / proptest-state-machine の model で記述
- LLM-generated property の盲目的 merge 禁止
- SaaS による property test as a service 採用しない

## 設計原則
- **property は bundle である**: yaml に書く `test.property.*` attribute のうち、property_id 1 つの値が他 5 dimension（generator_strategy / shrink_policy / seed_class / corpus_lifecycle / runtime_budget_seconds）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**: properties.yaml に登録された全 property_id、test code に annotated された @property 全件、`property_corpus.lock.yaml` に列挙された全 corpus entry が参照されなくなった時点で CI fail。1 ヶ月以上 invocation されない property_id は自動 PR で削除提案
- **seed は deterministic、artifact は immutable**: `seed_pool.lock.yaml` から読む、test runner ローカルで random 生成する経路は持たない
- **stateful property は model 同型を必須化する**: 4-state machine（39 client）/ tenant isolation（32）/ migration phase（08）/ key rotation（11）は Hypothesis stateful / proptest-state-machine / jqwik @StatefulProperty で model check 同型に書く
- **runtime_budget は class 別に固定する**: 30 / 120 / 600 second の 3 段階のいずれか

## generator strategy enum

| strategy | 説明 | 主用途 |
|---|---|---|
| `v1_random_uniform` | 完全 random、Hypothesis default | 単純な field 単独の不変条件 |
| `v1_random_biased` | boundary 偏重（MIN / MAX 周辺、empty string、NaN、∞）| 境界条件型 invariant |
| `v1_grammar_guided` | 文法 driven（CFG / regex 由来）| 12 schema migration の forward / backward compat / 07 transport frame parser |
| `v1_state_machine` | stateful、Hypothesis stateful / proptest-state-machine | 39 client 4-state / 32 tenant isolation / 08 migration 4 phase / 11 key rotation |
| `v1_metamorphic` | 入力変換 → 出力 invariant | 13 SLO recording rule / 12 schema aggregate qualified name の rename invariant / 09 SemConv attribute rename |

## shrink policy enum

| policy | 内容 |
|---|---|
| `v1_default` | Hypothesis / fast-check / proptest 既定 shrink、最小化試行 100 回 cap |
| `v1_extended` | 失敗時 1000 回 cap、cluster integration 系 property（08 / 11 / infra01 / data01）で必須 |
| `v1_disabled` | shrink off、performance 系 property（soak / load 系）で例外的に許容、必ず justification artifact 必須（`disabled_shrink_justification.lock.yaml` に entry）|

|---|---|

| lifecycle | 内容 |
|---|---|

## stateful property の model 規律

### 4-state machine（39 client）の必須 stateful property
- **transition closure**: 全 (state_from, action, state_to) tuple が enum と一致
- **liveness**: dirty → reconciled に必ず到達（cap 5 step 以内）
- **safety**: syncing 中の double-write が起きない
- **fairness**: reconcile race で順序崩れが起きない

### tenant isolation（32）の必須 stateful property
- cross-tenant access は generative attempt 1000 回で 0 件成功
- GUC propagation の継承が SessionContext の全 boundary で保たれる
- RLS FORCE bypass attempt が物理 deny

### migration phase（08）の必須 stateful property
- 4 phase の任意の (from, to) transition で dual_window invariant が破られない
- rollback 経路が full path で復路として通る

### key rotation（11）の必須 stateful property
- rotate 中の sign / verify が交差時刻で破綻しない
- KEK / DEK 階層 rotation の order invariant

## corpus storage / SoR
- `property_corpus.lock.yaml`: build artifact、cosign signed
- storage: 09 観測 SoR の ClickHouse + Ceph RGW（data01 v1_zone_replicated 以上）に hot / cold 二重保存
- retention: v1_immutable_archive のみ 365 day Compliance mode、それ以外は 90 day cold archive 後 crypto-erase
- access: corpus.read は unrestricted、corpus.write（新 entry 追加）は test runner 経由のみ、UI 上の手動編集は audit_event 必須

## cross-axis bind（property_axiom 列の cell）
- 各軸の必須 property は [カバレッジ行列方針](01_カバレッジ行列方針.md) で list 化
- formal 軸の `v1_temporal_safety_proof` / `v1_program_correctness_proof` cell と双方向 lock（property test corpus は proof obligation の instantiation）
- 13 SLO の `v1_test_coverage_compliance` に property_axiom 列の green rate を計算入力として bind
- 14 OSS-lifecycle 移行時、property framework 自身の major version 移行は v1_scenario_replay drill として別 class で claim
- 11 ops の `v1_drill_failure` に「property test の nightly green が前 quarter から regress」signal を bind

## 強制機構との bind
- 本方針は [test 強制機構](../../04_詳細設計/02_強制機構/09_test強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Semgrep custom rule によるseed deterministic 化 check / corpus drift = 0 check
    - 層 D: Kyverno `require-coverage-cell-green` admission policy
    - 層 E: property_corpus.lock.yaml の cosign signed + Ceph RGW Object Lock retention 365 day

## 採用しない方針
- random seed の test runner ローカル random 化: 禁止
- corpus の shrink 結果削除: 禁止
- stateful property の手続き型 test 化: 禁止
- LLM-generated property の盲目的 merge: 禁止
- SaaS による property test as a service: 採用しない
- runtime_budget 越え property の PR pipeline 残置: 禁止
