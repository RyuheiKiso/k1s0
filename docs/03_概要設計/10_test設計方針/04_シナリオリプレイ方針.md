# test シナリオリプレイ方針（v1_scenario_replay）

## 一文方針
- test 軸は v1_scenario_replay verification_class を Playwright（browser / mobile / API）+ Apache JMeter（synthetic / load journey）+ chainsaw（k8s integration）の 3 OSS L1+ で実装し、各軸 spec が宣言する journey scenario を determinism_class に応じた再現性として artifact 化、shadow cluster（infra01 v1_multi_region_active_passive の passive 側）上で nightly replay を Tekton Pipeline + Argo Workflows で物理 enforce し、replay 失敗を ops の v1_drill_failure signal_class へ自動 bridge する。

## 至高路線における立ち位置
- production cluster 上の scenario_replay 禁止、必ず shadow cluster
- flaky scenario の長期残置禁止、quarantine 14 day cap
- non-deterministic scenario の cell bind 禁止、determinism_violation として独立 alert
- 商用 e2e SaaS（BrowserStack / Sauce Labs / Mabl）採用しない
- LLM auto-record の盲目的 merge 禁止
- shadow cluster での write を経由した prod data 汚染禁止

## 設計原則
- **scenario は bundle**
- **dimension override 禁止**
- **dead spec を CI で殺す**
- **replay は determinism_class が宣言する等価関係を必須**: scenario の input fixture / database seed / network record / time clock / random seed の 5 系統が determinism_class に応じた等価関係を満たす。byte-level deterministic を物理不可な transport（gRPC bidi / HTTP/3 + WebTransport / SSE / WebSocket 越境）の cell は v1_observable_invariant 必須
- **shadow cluster 上で実行**: production cluster で行わない、必ず passive cluster で実行、prod gameday は別 verification_class（fault_chaos）で

## scenario_id 命名と field 構造
- 命名規則: `<axis>__<journey_class>__<replay_target>` の 3 segment（例: `08_migration__dual_phase__cutover_journey`）

### 必須 field（8 field）
- `scenario_id`: PK
- `journey_class`: v1_user_facing_journey / v1_internal_pipeline_journey / v1_admin_console_journey / v1_drill_journey
- `replay_target`: v1_full_native / v1_browser_spa / v1_thick_native / v1_thin_business / v1_api_only（client15 と整合）
- `blast_radius`: v1_isolated / v1_partial_shadow / v1_prod_dryrun / v1_prod_gameday（v1_prod_gameday は scenario_replay では不可）
- `determinism_class`: v1_full_deterministic / v1_seeded_random / v1_clock_controlled / v1_observable_invariant
- `fixture_lifecycle`: v1_per_run / v1_per_journey / v1_immutable_corpus
- `runtime_budget_minutes`: v1_fast_5 / v1_medium_15 / v1_long_60 / v1_extreme_240
- `artifact_pointer`: Playwright trace dir / JMeter result file / chainsaw test dir 等

## journey_class enum

| class | driver | 例 |
|---|---|---|
| `v1_user_facing_journey` | Playwright | login → tenant 切替 → 業務操作 → logout |
| `v1_internal_pipeline_journey` | Apache JMeter + chainsaw | 08 migration 4 phase / 11 key rotation / 14 OSS major version migration |
| `v1_admin_console_journey` | Playwright | tenant onboarding / quota 設定 / RLS policy 確認 / postmortem PR 作成 |
| `v1_drill_journey` | Tekton Pipeline + Litmus | data01 restore_drill / infra01 failover_drill / ops15 5 signal runbook drill |

## determinism class enum

| class | 等価関係 |
|---|---|
| `v1_full_deterministic` | 全 input fixture / random seed / clock / network record が固定、replay は完全再現（trace byte 同一）|
| `v1_seeded_random` | random seed のみ deterministic、それ以外は fixture 化、再現失敗は seed の bug として treat |
| `v1_clock_controlled` | clock のみ mocked（pause / advance）、time dependent property の journey で必須 |
| `v1_observable_invariant` | trace byte 同一は要求しない。代わりに業務 invariant（state machine の終端状態 / 観測 event 集合 / 等価 hash）の同一を要求。byte-level deterministic が物理不可な transport で必須 |

## blast_radius enum

| radius | 内容 | 用途 |
|---|---|---|
| `v1_isolated` | shadow cluster 完全分離、prod data 一切触らず | default、scenario_replay の 95% 以上 |
| `v1_partial_shadow` | shadow cluster + prod read-only API access | data01 restore_drill / 09 SemConv attribute observability journey 等 |
| `v1_prod_dryrun` | prod read-only access のみ、write 厳禁 | 13 SLO の burn rate journey / 15 capacity の forecast journey 等 |
| `v1_prod_gameday` | prod write、scenario_replay class では不可、fault_chaos class へ転写必須 | scenario_replay cell に注釈は Conftest fail |

## runtime_budget_minutes enum

| budget | 分 | 実行 |
|---|---|---|
| `v1_fast_5` | 5 | PR ごとに必ず実行 |
| `v1_medium_15` | 15 | nightly pipeline |
| `v1_long_60` | 60 | weekly pipeline |
| `v1_extreme_240` | 240 | monthly pipeline、cluster shadow 上 dedicated executor |

## replay 経路と shadow cluster
- shadow cluster: infra01 v1_multi_region_active_passive の passive 側 cluster を replay 専用に共用
- data01 v1_cross_region_replicated の data replica を read-only access、write 厳禁
- shadow cluster の cosign signed image は prod と同一
- replay run の SoR: `test_event` subject に `v1_scenario_replay_run` fact emit、ClickHouse + Ceph RGW 二重保存
- replay 失敗の bridge: replay red の場合、ops の `v1_drill_failure` signal_class へ自動 bridge

## scenario corpus
- `scenarios.yaml`: scenario_id catalog
- `corpus/`: fixture / seed / HAR / clock / random seed の 5 系統 input
- corpus は build artifact、cosign signed

## cross-axis bind（scenario_replay 列の cell）
- 07 transport: reconnect journey（5 distribution_class 全てで再現）。bidi / HTTP/3 + WebTransport / SSE / WebSocket 越境の cell は determinism_class が v1_observable_invariant 必須
- 08 migration: 4 phase journey
- 09 observability: trace continuity journey
- 10 auth: login + step-up + logout
- 11 key: rotation drill journey
- 12 schema: schema migration journey（aggregate rename + DB column add の 7 declaration 同期）
- 13 SLO: burn rate alert journey
- 14 OSS-lifecycle: major version migration journey
- 15 capacity: per_tenant_volume overflow → cold archive journey
- 32 data-tenant: tenant onboarding journey
- 39 client: offline → reconcile journey
- infra01: drain → migrate journey
- data01: restore_drill journey
- security15: red-team replay journey
- client15: 5 distribution_class 全ての conformance journey
- ops15: 5 signal_class 全ての runbook drill journey

## 強制機構との bind
- 本方針は [test 強制機構](../../04_詳細設計/02_強制機構/09_test強制機構.md) の以下経路で物理 enforce される:
    - 層 C: chainsaw / kuttl による shadow cluster 上の e2e 試験
    - 層 D: Argo Workflows による long-running scenario replay の orchestration
    - 層 D: Kyverno `block-on-shadow-only-violation` `block-on-deterministic-violation` admission policy
    - 層 E: cosign signed scenario corpus + Ceph RGW Object Lock retention

## 採用しない方針
- production cluster 上の scenario_replay: 禁止
- flaky scenario の長期残置: 禁止
- non-deterministic scenario の cell bind: 禁止
- 商用 e2e SaaS: 採用しない
- LLM auto-record の盲目的 merge: 禁止
- shadow cluster での write を経由した prod data 汚染: 禁止
- replay 失敗の文章 only triage: 禁止
