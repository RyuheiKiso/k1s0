# test 変異検証方針（mutation testing）

## 一文方針
- test 軸は mutation testing を「test の test」として pitest（JVM）+ mutmut（Python）+ Stryker Mutator（TS / .NET）+ go-mutesting（Go）+ cargo-mutants（Rust）の 5 言語 1 OSS L1+ 単一深耕で実装し、mutation_score（killed / total）を `mutation_score.lock.yaml` に build artifact として固定、quarterly monotonic increase を Kyverno admission policy で物理 enforce、equivalent mutant の認定は justification artifact 必須化、mutation testing 自体を全 5 verification_class（type_invariant 含む）に再帰適用することで test の質を物理 measurable にする。

## 至高路線における立ち位置
- mutation testing skip の経済合理性主張禁止
- score_floor の引き下げ禁止、monotonic increase only、PR merge block
- 文章のみの equivalent mutant justification 禁止
- 商用 mutation SaaS（Diffblue Cover Pro / Sealights）採用しない
- LLM-only mutation 認定禁止、人間 reviewer + drill_owner の二重 ack 必須
- mutation testing を「ベストエフォート」と位置づけ禁止、release_gate.lock.yaml の AND-gate 物理入力

## 設計原則
- **mutation_score は bundle**: module_id 1 つの値が他 5 dimension（mutation_operator_class / scope / cadence_days / equivalent_mutant_policy / score_floor）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**
- **score_floor は monotonic increase only**: `mutation_score.lock.yaml` の各 module_id score は四半期比較で必ず monotonic increase
- **equivalent mutant は機械可読 justification 必須**: `equivalent_mutants.lock.yaml` に append-only entry、reason_class enum + symbolic_proof_pointer が必須
- **mutation testing は 5 verification_class 全てに再帰適用する**:
    - `v1_type_invariant`: 型 mutation が type test で検出
    - `v1_property_axiom`: property mutation が property test で検出
    - `v1_contract_pair`: pact field mutation が Buf-breaking で検出
    - `v1_scenario_replay`: scenario step mutation が Playwright trace で検出
    - `v1_fault_chaos`: blueprint mutation が chaos workflow で検出

## module_id 命名と field 構造
- 命名規則: `<axis>__<lang>__<module_path>` の 3 segment

### 必須 field（10 field）
- `module_id`: PK
- `language`: rust / python / typescript / java / go / csharp / kotlin
- `mutation_operator_class`: 6 enum
- `scope`: v1_per_module / v1_per_axis_subset / v1_full_codebase の 3 enum
- `cadence_days`: v1_per_pr_smoke（1 day）/ v1_nightly（1 day）/ v1_weekly（7 day）/ v1_quarterly（90 day）の 4 enum
- `equivalent_mutant_policy`: v1_symbolic_proof / v1_structured_documented / v1_per_axis_documented
- `score_floor`: percentile（0.0〜1.0）、四半期 monotonic increase
- `last_run_at`: UTC ISO8601
- `last_score`: 直近 score
- `artifact_pointer`: mutation report HTML / XML / JSON の path

## mutation_operator_class（PIT / mutmut / Stryker 標準、6 enum）
- `v1_arithmetic`: + ↔ - / * ↔ /
- `v1_conditional`: == ↔ != / < ↔ >=
- `v1_boundary`: < ↔ <= / > ↔ >=
- `v1_return_value`: return value swap
- `v1_increment`: i++ → i--
- `v1_void_method_call`: void method 呼出削除

- 上記 6 operator は全 module で必須有効化

## scope enum

| scope | 内容 | cadence |
|---|---|---|
| `v1_per_module` | module 単位、PR の changed file subset | v1_per_pr_smoke（1 day）|
| `v1_per_axis_subset` | 1 軸の対応 module set 全体 | v1_nightly |
| `v1_full_codebase` | 全 codebase 全 module | v1_quarterly、cluster shadow 上 dedicated executor |

## score_floor の monotonic increase 規律
- `mutation_score.lock.yaml` は append-only 履歴 + current state の二系統 yaml
- quarter 比較: 直近 quarter の score >= 前 quarter の score
- 例外なし: score 引き下げ PR は Kyverno で merge block
- 新規 module の grace: 初期 score_floor は新規 module 追加 quarter の翌 quarter までに達成必須

## equivalent mutant 規律

### 認定経路
1. mutation testing 後、survived mutant が `equivalent_mutants.lock.yaml` に提案 entry として自動 append
2. drill_owner が reason_class enum を選択
3. policy 別に必要 artifact:
    - `v1_symbolic_proof` policy module（symbolic exec 適用可能言語: Rust / C / C++ → KLEE+CBMC、Java → JBMC、Go → 静的 SMT）: symbolic_proof_pointer 必須
    - `v1_structured_documented` policy module（symbolic exec 不可言語: TS / Python / Ruby / .NET / Kotlin 等）: 構造化 artifact（mutation diff + 反証用 test corpus pointer + reviewer 二重 ack record の machine-readable set）必須
    - `v1_per_axis_documented` policy module: comment artifact 必須
4. PR 起票、人間 reviewer 1 人 + drill_owner の二重 ack で merge

### reason_class enum
- `v1_dead_code`: 実行不能 path（unreachable）
- `v1_logically_equivalent`: 意味論的に同等
- `v1_safe_optimization`: compiler 最適化等価
- `v1_test_independent`: mutation 領域が test assertion の責任領域外

## mutation report の SoR
- `mutation_score.lock.yaml`: current state、cosign signed
- `mutation_history.lock.yaml`: append-only 履歴
- mutation report HTML / XML / JSON: Ceph RGW Object Lock Compliance mode で 365 day retention
- ClickHouse: mutation_score quarter ごとの aggregate metric

## run pipeline

| pipeline | budget | scope | 場所 |
|---|---|---|---|
| PR pipeline | 5 min | changed file subset の per-module mutation | local CI |
| nightly pipeline | 120 min | 各軸の subset を順次 mutation | cluster shadow 上 |
| quarterly pipeline | 24h | 全 codebase 全 module | cluster shadow 上 dedicated executor |

## cross-axis bind
- 13 SLO: `v1_mutation_score_compliance` を SLO 登録、quarter monotonic 違反で burn rate alert
- 11 ops: mutation_score regress の `v1_drill_failure` signal_class へ bridge
- 14 OSS-lifecycle: mutation framework 自身の major version migration drill 必須化
- カバレッジ行列方針: mutation_score は v1_property_axiom / v1_type_invariant cell の補助 metric として bind
- 10 security: security-critical module（10 auth / 11 key / 32 RLS）は score_floor が relaxed 不可、score 0.95 以上を物理要件。equivalent_mutant_policy は v1_symbolic_proof（適用可能言語）または v1_structured_documented（適用不可言語）のいずれかを必須、v1_per_axis_documented は採用不可

## 強制機構との bind
- 本方針は [test 強制機構](../../04_詳細設計/02_強制機構/09_test強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による mutation_score quarter monotonic increase check
    - 層 D: Kyverno `require-mutation-score-monotonic` `block-on-equivalent-mutant-without-proof` admission policy
    - 層 E: cosign signed mutation_score.lock.yaml + Ceph RGW Object Lock retention 365 day

## 採用しない方針
- mutation testing skip の経済合理性主張: 禁止
- score_floor の引き下げ: 禁止
- 文章のみの equivalent mutant justification: 禁止
- 商用 mutation SaaS: 採用しない
- LLM-only mutation 認定: 禁止
- mutation testing を「ベストエフォート」と位置づけ: 禁止
