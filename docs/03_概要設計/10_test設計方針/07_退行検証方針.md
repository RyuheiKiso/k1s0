# test 退行検証方針（regression / golden / snapshot）

## 一文方針
- test 軸は退行検証（過去 incident / past failure / past PR で検出された defect の再発防止）を property_corpus + scenario_corpus + chaos_blueprints の三系統 corpus に entry を必ず追加する形で artifact 化し、flaky quarantine を quarantine_due_at 14 day cap で物理 enforce、golden snapshot test を deterministic + 機械可読 diff で運用、snapshot 更新を artifact-signed PR + drill_owner ack 必須化することで test の腐敗を物理に防ぐ。

## 至高路線における立ち位置
- flaky の長期 quarantine（14 day 越え）禁止、cap = 14 day、延長は新 verification_class を切ること
- snapshot 手動更新 without artifact-signed PR 禁止
- regression_corpus_added 注釈なしの defect 修正 PR 禁止、Kyverno で merge block
- snapshot mask の濫用（cap 20% 越え）禁止
- 商用 visual regression SaaS（Applitools / Percy）採用しない
- LLM auto-snapshot 認定禁止
- 「flaky だから skip」の文章注釈禁止

## 設計原則
- **過去 defect は corpus に必ず entry する**: production / staging / nightly drill / property shrink で発見された defect は、対応 verification_class の corpus に必ず entry を追加、PR 中の `regression_corpus_added` 注釈を Conftest が物理 enforce、注釈なしの defect 修正 PR は merge block
- **flaky は物理 quarantine、永続化禁止**: flaky 認定 test は `flaky_quarantine.lock.yaml` に entry、quarantine_due_at は既定 14 day、cap も 14 day（延長禁止）
- **golden snapshot は deterministic 必須**: snapshot output（Playwright trace / OTel span tree / pact contract / mutation report）の比較は normalized form（line ending / timestamp / UUID / dynamic field の placeholder 化）で行う、非 deterministic field は snapshot mask に登録
- **snapshot 更新は artifact-signed PR 必須**: `--update-snapshots` の手動実行による snapshot 上書きは禁止
- **flaky 認定は機械的に**: 「直近 N run で red / green が混在」（N=20、cap 30%）を機械判定

## regression_corpus の追加経路

### 経路 1: property_axiom shrink 結果
- shrink 後の最小反証 input → `property_corpus.lock.yaml` に append-only 追加

### 経路 2: scenario_replay 失敗 trace
- 失敗 trace の Playwright HAR + OTel span tree → `scenarios/<scenario_id>/regression/<incident_id>.har` として保存、`scenarios.yaml` の regression subset に登録

### 経路 3: fault_chaos drill 失敗 input
- 失敗 chaos workflow → `chaos_blueprints.lock.yaml` の regression entry として append、recovery_validation の追加 step として登録

### 経路 4: production incident postmortem
- postmortem PR の reproducer artifact → 上記 1〜3 のいずれかに転写、postmortem PR merge には `regression_corpus_added` 注釈必須（Kyverno 物理 enforce）

## flaky quarantine 規律

### 認定基準
- 直近 N run（N=20）で red / green 混在率 30% 以上
- 自動判定は `test_event` subject の集計 metric 経由、Tekton Pipeline `flaky-classifier` が毎日実行

### 認定後の lifecycle
1. `flaky_quarantine.lock.yaml` に entry 自動追加、quarantine_due_at = now + 14 day
2. `coverage_matrix.lock.yaml` の対応 cell に `flaky_quarantined` 注釈追加
3. test_owner（ownership_table の framework_owner）に Mattermost page、PR 起票要請
4. quarantine 期間中は cell の last_green_at は凍結
5. 期限内に修正 PR が merged: cell 復帰、entry 削除
6. 期限超過: 自動 PR で test 削除 + cell expected_status を `removed_with_reason_artifact` 化、ownership escalate

## snapshot 系列

### Playwright trace snapshot
- HAR + screenshot + video の 3 系統
- screenshot は pixel diff（threshold 0.1%）、video は frame diff
- dynamic field（timestamp / UUID / cookie / session token）は snapshot_masks に登録、placeholder 化

### OTel span tree snapshot
- span attribute の SemConv に従う subset を snapshot
- span_id / trace_id / start_time / duration は mask
- 09 SemConv の attribute schema 変更時に snapshot_masks も同 commit で更新

### pact contract snapshot
- Pact pact の field schema を snapshot、value は generator から導出、UUID / timestamp は mask
- 07 transport / 12 schema の field add 時に snapshot 自動更新

### mutation report snapshot
- `mutation_score.lock.yaml` の score per module を snapshot
- quarter 比較で monotonic increase 物理 enforce

## snapshot_masks.lock.yaml

### mask entry 構造
- `mask_id`: PK
- `field_path`: jsonpath / jq selector / regex
- `placeholder`: `<UUID>` / `<TIMESTAMP>` / `<SESSION_TOKEN>` 等の固定文字列
- `reason_class`: v1_dynamic_field / v1_environment_specific / v1_security_redaction の 3 enum
- `artifact_pointer`: mask 適用例の sample

### mask 追加経路
- PR 中で snapshot 更新 → 比較 diff に dynamic field が混入 → snapshot_masks に entry 追加 PR 必須、人間 reviewer 1 人 + drill_owner ack

### mask 過剰使用の物理制限
- mask 数 / snapshot field 数 の比率 cap = 20%
- cap 越えは Conftest fail、snapshot 設計の見直し必須

## test_event の SoR
- subject schema:
    - `event_id` / `test_id` / `cell_id` / `verification_class` / `run_id` / `status`（pass / fail / skip / quarantined）/ `timestamp` / `executor_cluster` / `artifact_pointer` / `regression_corpus_id`（or null）
- storage:
    - ClickHouse hot tier（90 day）+ Ceph RGW cold tier（365 day）
    - immutable archive: security incident reproducer / mutation equivalent mutant 認定の input は Object Lock Compliance mode で 365 day

## regression_corpus の ageing
- corpus entry は append-only、削除は dead spec 検出時のみ
- corpus entry の last_replayed_at が cadence 内（class 別、property=7 day / scenario=14 day / chaos=30 day）、cadence 越えは regression replay pipeline で自動再実行
- 1 年以上 invocation されない corpus entry は ageing notice、drill_owner が「現役 regression test」として ack するか dead spec として削除するかの quarter 1 回の review 必須

## cross-axis bind
- 11 ops: production incident → postmortem PR の `regression_corpus_added` 注釈を Kyverno で物理 enforce
- 13 SLO: `v1_flaky_quarantine_compliance` SLO 登録、flaky cap 越えは burn rate alert
- 10 security: security incident reproducer は immutable archive 365 day、retention 期限内 物理 delete 不可
- 09 observability: `test_event` SoR を ClickHouse の SemConv 互換 subject として共用
- 14 OSS-lifecycle: snapshot 系の OSS（Playwright / Pact / pitest）の major version migration 時の snapshot mask 追加 PR 必須

## 強制機構との bind
- 本方針は [test 強制機構](../../04_詳細設計/02_強制機構/09_test強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による flaky_quarantine cap / regression_corpus_added 注釈 / snapshot mask cap check
    - 層 D: Kyverno `require-flaky-quarantine-cap` `require-regression-corpus-added` `require-snapshot-signed` `block-on-snapshot-mask-overflow` admission policy
    - 層 E: regression_corpus / snapshot artifact の cosign signed + Ceph RGW Object Lock retention

## 採用しない方針
- flaky の長期 quarantine（14 day 越え）: 禁止
- snapshot 手動更新 without artifact-signed PR: 禁止
- regression_corpus_added 注釈なしの defect 修正 PR: 禁止
- snapshot mask の濫用（cap 20% 越え）: 禁止
- 商用 visual regression SaaS: 採用しない
- LLM auto-snapshot 認定: 禁止
- 「flaky だから skip」の文章注釈: 禁止
