# test 故障注入検証方針（v1_fault_chaos）

## 一文方針
- test 軸は v1_fault_chaos verification_class を Litmus L1+ + Toxiproxy（network fault）+ Chaos Mesh（low blast radius、double-bound）+ 言語別 fuzz tool セット（cargo-fuzz / `go test -fuzz` / jazzer.js / atheris / AFL++ / SharpFuzz）の組合せで実装し、各軸 spec が宣言する fault mode（network / storage / clock / process / dependency / attacker）に対する resilience を chaos blueprint（`chaos_blueprints.lock.yaml`）の build artifact として固定し、blast radius を Kyverno admission policy で物理制限、prod gameday を OpenBao response wrapping の break-glass + 二人承認 + audit_event で物理 enforce する。

## 至高路線における立ち位置
- 商用 chaos SaaS（Gremlin / AWS FIS / Harness Chaos）採用しない、Litmus L1+ 単一深耕
- 文章 only chaos drill 禁止
- blast_radius 注釈なし experiment 禁止
- prod gameday の単独承認禁止、二人承認必須
- drill skip の経済合理性主張禁止
- LLM-generated chaos blueprint の盲目的 merge 禁止
- active incident 中の chaos experiment 自由起動禁止

## 設計原則
- **chaos blueprint は bundle**: blueprint_id 1 つの値が他 6 dimension（fault_class / blast_radius / target_layer / drill_cadence_days / attacker_class / recovery_validation_class）を一意に導出
- **dimension override 禁止**
- **dead spec を CI で殺す**
- **6 fault_class を全 axis で coverage**
- **blast radius の物理制限**: shadow cluster / partial production / production gameday の 3 段階を Kyverno で物理 enforce
- **drill_cadence_days を物理 property とする**: cadence 越えの blueprint は Kyverno で関連 service deploy 物理 block

## blueprint_id 命名と field 構造
- 命名規則: `<axis>__<fault_class>__<attacker_class_or_none>` の 3 segment

### 必須 field（10 field）
- `blueprint_id`: PK
- `fault_class`: 6 enum
- `blast_radius`: v1_shadow_only / v1_partial_prod / v1_prod_gameday
- `target_layer`: tier1 / tier2 / tier3 / infra / data / security / ops の 7 enum
- `drill_cadence_days`: 30 / 90 / 180 / 365 enum
- `attacker_class`: security15 threat 1:1 bind、または `none`
- `recovery_validation_class`: v1_slo_recovery / v1_data_recovery / v1_state_recovery / v1_security_containment
- `last_green_at`: UTC ISO8601
- `last_green_blast_radius`
- `artifact_pointer`: Litmus workflow CR / Toxiproxy config / 言語別 fuzz corpus dir 等

## fault_class（6 class）

| class | tool | fault | 主用 axis |
|---|---|---|---|
| `v1_network_fault` | Toxiproxy + Litmus chaos-network | partition / latency / packet loss / DNS NXDOMAIN / TLS handshake reject | 07 transport / 09 / 10 / infra01 / data01 cross-region |
| `v1_storage_fault` | Litmus chaos-disk + charybdefs | disk full / IO error / read corruption / inode exhaustion | data01 / 09 SoR ClickHouse / 12 schema PostgreSQL |
| `v1_clock_fault` | Litmus chaos-clock-skew | drift +/- 5 min / sudden jump 24h / clock freeze | 08 migration window / 11 key rotation / 13 SLO burn rate / data01 RPO window |
| `v1_process_fault` | Litmus chaos-pod-kill / Chaos Mesh stress-chaos | random pod kill / OOM kill / crash loop / SIGTERM ignore | infra01 / ops15 5 signal_class runbook |
| `v1_dependency_fault` | Litmus chaos-http-fault + Toxiproxy | upstream / IDP / KMS / event broker unavailability、5xx / timeout / 429 | 10 auth / 11 key / 14 OSS-lifecycle / 15 capacity |
| `v1_kek_share_threshold_fault` | Litmus chaos-network + 専用 KEK reconstruction probe workflow | N region 中 (N - M + 1) region 以上を完全断 | 05_tier1/11 鍵管理 / 09_data/15 / 09_data/16 PII cluster / 10_security/14 |
| `v1_attacker_fault` | Litmus + 専用 attacker workflow + 言語別 fuzz tool セット | security15 threat 1:1 attacker simulation | security15 / 32 data-tenant / 10 auth / 12 schema |

## blast_radius の admission policy 制限
- Kyverno admission policy:
    - `require-blast-radius-annotation`: chaos experiment CR に blast_radius 注釈必須
    - `block-prod-gameday-without-break-glass`: v1_prod_gameday は break-glass token 必須
    - `require-recovery-validation-pointer`: experiment に recovery_validation_class の artifact pointer 必須
    - `block-during-active-incident`: active incident 中の chaos experiment block。`incident_active_duration > 14d` の場合、当該 incident は v1_extended_incident に再分類され、cadence_escape_valve が発動: 次回 chaos drill cadence 期限を 30d 自動延長（最大 2 回まで）、ops lead 二人承認 + audit_event subject に `v1_cadence_escape_valve` fact emit を必須化、関連 cell の drill_state は v1_drill_red_handled として coverage_matrix に物理記録
    - `block-during-global-freeze`: global freeze window 内の v1_prod_gameday を block

### blast_radius 段階
- `v1_shadow_only`: infra01 passive cluster 完全分離、自由起動 allow
- `v1_partial_prod`: prod cluster の特定 namespace のみ、Mattermost incident channel 通知必須
- `v1_prod_gameday`: prod 全域、break-glass 必須、二人承認（primary + secondary on-call）必須、audit_event subject に `v1_chaos_gameday` fact emit 必須

## recovery_validation_class enum
- `v1_slo_recovery`: SLO burn rate が drill 後 N 分で baseline 復帰を物理 verify
- `v1_data_recovery`: data01 v1_zone_replicated 以上の data が RPO 以内
- `v1_state_recovery`: 32 RLS / 39 client 4-state / 08 migration phase の state machine が drill 後 invariant に戻る
- `v1_security_containment`: security15 attacker fault に対し containment が物理発火、attacker の lateral movement が物理に止まる

## 言語別 fuzz tool の corpus 規律
- 適用対象:
    - Rust target → cargo-fuzz / libFuzzer
    - Go target → `go test -fuzz`
    - TS / JS target → jazzer.js
    - Python target → atheris
    - C / C++ / Rust binary target → AFL++
    - .NET / C# target → SharpFuzz
- 各 target の harness は言語別に書き、`fuzz_corpus.lock.yaml` に target_lang を含む entry として登録
- corpus storage: `fuzz_corpus.lock.yaml` に entry、Ceph RGW Object Lock Compliance mode で 365 day retention
- run cadence: PR ごとに 5 min smoke fuzz / nightly に 60 min fuzz / quarter ごとに 24h dedicated fuzz

## chaos drill cadence 表
- tier1 系（07 / 08 / 09 / 10 / 11 / 12 / 13 / 14 / 15）: 30 day
- tier2（32）: 30 day
- tier3（39）: 30 day
- infra01: 90 day（zone partition / region failover）
- data01: 30〜180 day（preservation class 別）
- security15: 90 day（red-team）、365 day（full red-team campaign）
- client15: 14〜30 day（distribution class 別）
- ops15: drill 自体が self-bound

## prod gameday 規律

### 起動経路
1. ops の `change_calendar.lock.yaml` に entry 登録、72h 前
2. break-glass token 発行（OpenBao response wrapping、有効期限 1h）
3. primary + secondary on-call の二人承認（ChatOps slash command）
4. audit_event subject に `v1_chaos_gameday` fact emit
5. drill 中も `ops_event` の hash chain は継続、chain divergence 不可
6. 終了後 1h 以内に postmortem PR 起票必須

### 失敗時
- drill 中 SLO burn rate 越えで Argo Rollouts + Kyverno が物理 freeze、人間 ack 不要
- drill 失敗 → ops の `v1_drill_failure` signal として `v1_drill_postmortem` 起票
