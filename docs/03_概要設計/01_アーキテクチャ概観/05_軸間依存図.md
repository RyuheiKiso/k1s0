# 軸間依存図

## 一文方針
- 19 軸間の依存関係は (a) 階層依存（5 階層論の単方向）+ (b) cross-cutting 接合（13 cross-cutting 適合仕様）+ (c) proof_obligation（formal 軸が他軸の不変条件を proof として転写）の 3 種で表現される。各軸 spec の `depends_on` で機械可読に固定し、release_gate.lock.yaml AND-gate で全軸接合の green を物理 enforce する。

## (a) 階層依存（5 階層論の単方向）

```
tier3 → tier2 → tier1 → data
                       → infra
```

- tier3 は tier2 経由でのみ業務資産にアクセス
- tier2 は tier1 Library 経由でのみ infra にアクセス
- tier1 は data / infra を直接利用
- 逆方向の依存は CI で物理拒否

## (c) proof_obligation（formal 軸が他軸の不変条件を proof として転写）

formal 軸の 5 proof_class が他軸の不変条件を proof obligation として転写:

| proof_class | 転写元 unbreakable invariant |
|---|---|
| temporal_safety_proof | tier2 atomic 三表書込 P1〜P4 / tier1 Bidi conformance / 鍵管理 KEK shamir threshold |
| temporal_liveness_proof | tier3 pending queue resume completion / data restore_drill RTO / Workflow completion |
| refinement_proof | tier1 移行 pair 旧→新 / Connect-RPC ↔ paired_post_sse 等価性 |
| program_correctness_proof | tier1 Library API contract / KEK shamir threshold algebra / HLC happens-before |
| runtime_modelcheck_proof | infra eBPF / HSM driver / PTP daemon / Rust 実装 memory safety |

## 軸間整合の機械検査
- 各軸 spec の `depends_on` フィールドを CI で参照整合性検査
- 循環依存検出（DAG 検査）
- cross-cutting 適合仕様の `depends_on` が複数軸を参照していることを検査
- formal 軸の proof obligation が他軸の不変条件 id と参照整合

## release_gate.lock.yaml AND-gate
- 全 19 軸の release_gate cell が AND で green を要求
- cell の入力:
  - 各軸の `*.lock.yaml` の `last_green_at` が cadence 内
  - cross-axis cross-cutting assertion green
  - formal proof 95 cell（proof_matrix 基底）green
  - cosign signed tag が物理 prerequisite

## meta-axis（00_軸登録適合仕様）
- 軸自体の追加削除を物理 enforce
- v1 cap = 20、残 1
- 新軸追加は purely additive、メタ枠超過は破壊的変更

## 軸間依存の図示
- Backstage TechDocs plugin で軸間依存図を automatic 生成
- mermaid / drawio で視覚化
- 各軸 spec の `depends_on` を入力に DAG 描画

## 採用しない設計
- 階層依存の逆方向（tier1 → tier3 等）
- cross-cutting 適合仕様の単一軸所有（必ず複数軸の接合点を担当）
- formal proof 不在の軸（必ず 5 proof_class のいずれかが対象）
- meta-axis cap 超過の軸追加（破壊的変更扱い）
