# 19 軸論

- 本企画は 10 主要軸 + 9 cross-cutting / meta 軸の合計 19 軸で構成される。全軸が同型構造（class bundle / dimension override 禁止 / dead spec 殺し / build artifact 化 / 5 層 defense-in-depth）を持ち、軸間接合は 軸間依存マップ + cross-cutting 適合仕様で機械的に検証可能。

## 軸の同型構造
全 19 軸が次の構造を持つ:

### 設計原則
- **class bundle**: 軸の主要 class（5-6 個）が他 dimension を一意に導出
- **dimension override 禁止**: dimension を個別に override する経路なし
- **dead spec を CI で殺す**: classes / scenarios / lock_artifact / instance のいずれも参照消失で CI fail
- **build artifact 化**: lock.yaml は build script で生成、手書き drift 禁止
- **defense-in-depth は 5 層（A〜E、formal は + F）**

### 単一の真（3-5 ファイル構成）
- `classes.yaml`: 軸 enum + bundle 定義
- `scenarios.yaml`: scenario × class → assertion id matrix
- `*.lock.yaml`: build artifact（capabilities / dry_run / instruments / oss_inventory 等）

### CI 不変条件
- 整合 1〜N、merge 不可
- dead spec 検出
- build artifact と git の差分検出
- cross-axis assertion の dangling 検出

## 軸間接合
- 全 軸 spec で `depends_on` が宣言
- cross-cutting 適合仕様が複数軸の接合点を単一所有
- formal 軸が他軸の不変条件を proof_obligation として転写

- 軸の文章記述のみ（必ず class bundle + lock artifact）
