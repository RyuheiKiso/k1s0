# client オフライン耐性方針

## 一文方針
- SDK のオフライン耐性は tier3 39_クライアント状態適合仕様 の 4 layer（Server Truth / Optimistic Local / Pending Queue / Draft）と conflict tree に従い、SDK 側で言語横断同型に実装する。SDK は意味論を再定義せず、SDK 提供 API は 39 の 1:1 投影のみ。

## SDK 側責務（39 適合仕様の 1:1 投影）
- SDK が提供する:
  - Layer 4 種の reducer / store helper（Application 層）
  - Pending Queue durable storage（IndexedDB encrypted / OS keychain integration / DPAPI / Tauri secret store）
  - Idempotency-Key 自動採番 + 24h TTL enforce
  - Adapter 層 effect 実行器（IndexedDB I/O / WebCrypto encrypt-decrypt / network send / OS keychain probe）
  - conflict_tree.yaml の event dispatch helper
  - PII strip-at-enqueue / attach-at-send の機構
  - purge trigger（logout / refresh_token expiry / tenant switch / actor switch）の wiring
  - subscriber API（domain_event_received → SDK 内部 reducer）
- SDK が提供しない:
  - layer 種類の変更 / event 追加 / subtype 追加（→ 39 改定が前提）
  - UI コンポーネント（→ tier3 業務側 SPA）
  - ビジネス specific 衝突解決（→ 39 の business_conflict_received subtype に従う）

## オフライン storage の物理仕様

| distribution_class | storage | encryption | key |
|---|---|---|---|
| `v1_full_native_with_companion` | OS keychain + memory | OS native（macOS Keychain / DPAPI / SecretService） | OS managed |
| `v1_legacy_dotnet_framework` | DPAPI protected blob | DPAPI（CurrentUser scope） | OS managed |
| `v1_browser_spa_typescript` | IndexedDB | WebCrypto AES-GCM | non_extractable_cryptokey |
| `v1_thick_native_via_tauri` | IndexedDB（WebView）+ Rust 側 sled or sqlite | WebCrypto AES-GCM + OS keychain wrap | OS keychain（Tauri plugin） |
| `v1_thin_business_api_only` | not provided | not applicable | not applicable |

storage 選択は dimension override 禁止。

## pending_queue durable contract
- SDK は queue を必ず durable に保持する（`v1_thin_business_api_only` 以外）
- queue entry の構造（39 適合仕様 lineage と同型）:
  - `tenant_id`, `actor_id`, `aggregate_id`, `base_version`
  - `method`（proto FQN）, `request_payload`（PII stripped）
  - `idempotency_key`, `enqueued_at`, `attempted_count`, `last_error_class`, `attempt_states[]`
- per-aggregate serialize（aggregate ID 単位で in-flight 1 件、enqueue 順を保つ）を SDK が実装
- PII fields は proto descriptor の `(k1s0.field_pii) = true` annotation で識別、enqueue 時に strip、send 直前に in-memory form state から attach
- send は Adapter 経由で network、ack で promote、4xx で rollback / business_conflict 分岐

## idempotency_key
- 自動採番: ULID + tenant_id prefix + RPC method short hash。user-supplied は受け付けない
- TTL: 24h（39 適合仕様の `idempotency_key_ttl` と同期）
- 超過時の挙動: `over_ttl_policy` に従う（`mark_as_stale` → `require_user_confirmation_to_resend` → confirm: generate_new_idempotency_key / discard: remove_entry）
- server 側 32 atomic 三表書込との dedup contract は tier2 で保証、SDK は idempotency_key を必ず request header `x-idempotency-key` として送出

## refresh_token / device_bound_key の rotation
- device_bound_key の生成タイミング:
  - Browser SPA: 初回 init 時、`WebCrypto.subtle.generateKey({ name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt'])` で non-extractable
  - Tauri / Native: OS keychain に key blob を保管、Rust 側で取得
  - .NET FW: `DPAPI.Protect` でユーザ scope 暗号化
- rotation: refresh_token 失効を検知すると即時:
  - 全 layer storage を purge
  - device_bound_key を再生成（旧 storage は復号不能）
  - purge を 09 観測可能性 SoR に audit emit（`client.purge.event`）

## background sync / Service Worker
- v1 Browser SPA: Service Worker は cache-first read-through cache のみ採用。background sync は v2 候補（`v2_sw_background_sync`）
- v1 Tauri: Tauri sidecar が常駐、background は sidecar process 上で動作

## 接続復帰検知
- online/offline event:
  - Browser: `window.online` / `offline` + Network Information API
  - Tauri: `navigator.onLine` + `tauri::api::notification` 補助
  - Native: SDK 内部で health probe（5s interval、jitter 付き）
- offline 中の queue 蓄積上限:
  - per-aggregate 100 entry hard cap
  - per-tenant 1000 entry hard cap
  - storage byte 上限: 50 MB（超過時 oldest non-PII を evict、PII 含む entry はユーザ確認待ち）
- 復帰時の send 順序: 39 conflict_tree.yaml の `pending_queue_resume` と同期、enqueue 順 + per-aggregate serialize

## purge triggers
- 全 trigger と挙動（39 適合仕様 `purge_triggers` と同期）:
  - `logout` → 全 layer purge + audit emit
  - `refresh_token_expiry` → 全 layer purge + audit emit
  - `tenant_switch` → 全 layer purge + 新 tenant_id で再 init
  - `actor_switch` → 全 layer purge + 新 actor_id で再 init
  - `device_bound_key_rotate` → 全 layer purge + 新鍵で再 init

## at-rest PII の物理 enforce
- SDK 内部 type レベル: `(k1s0.field_pii) = true` annotation の field は IndexedDB / OS keychain に rest しない（compile time check + runtime redaction）
- 物理検査: headless browser integration test で IndexedDB の物理 dump を解析、PII 平文混入が検出されたら CI fail
- SDK は WebCrypto の AES-GCM 256bit、IV ランダム、AAD は `aggregate_id+version` で固定。自製 crypto 禁止

## 25h オフラインケース（製造業 pack）
- 39 適合仕様 製造業 pack stress test 6（オフライン 25h 経過した検査入力の再送試行）と同等を SDK contract test で全自動検証
- SDK は idempotency_key TTL（24h）超過判定、ユーザに再送 / 破棄を確認、新 idempotency_key で resend のフローを完全自動

## 採用しない選択肢
- LocalStorage / SessionStorage への PII 平文書込（lint で deny）
- cookie への refresh_token 永続化以外: HttpOnly + Secure + SameSite=Lax のみ許容
- 自製 crypto
- PII を含むまま enqueue（strip → in-memory 再 attach フローを物理 enforce）

## 至高路線における立ち位置
- 「offline storage を諦めれば SDK が軽い」を理由に Browser SPA / Tauri から offline 機構を削減しない
- PII 取扱い / 暗号化は WebCrypto / OS keychain の物理機構を最終 safety net とし、文章運用に依存しない
