# client コード生成方針

## 一文方針
- 全言語 SDK の RPC stub / type / event payload / config / SDK metadata は protoc + Buf による単一 codegen pipeline で生成する。手書き SDK code path は CI fail。

## 単一の真
- 入力（source of truth）:
  - tier1 03_Server 系 / 04_Library が公開する `.proto` file 群（`k1s0.proto.*` package、`buf.yaml` で workspace 管理）
  - tier1 12_スキーマ進化適合仕様 の compatibility 規約（Buf breaking change check）
  - Apicurio Registry に登録された Avro / JSON schema（event / external integration 用、Buf for Apicurio plugin 経由）
  - method annotation（k1s0 carrier extensions: `retry_policy` / `slo_class` / `quota_class` / `observability_class` / `pii` / `capability_class`）
- 出力:
  - 各言語 SDK の RPC stub / type
  - SemConv attribute helper（09 観測適合仕様 SemConv と同期）
  - Capability matrix lock（07_Bidi 適合仕様 と同期）
  - retry policy table（[リトライバックオフ方針](06_リトライバックオフ方針.md)）
  - PII field map（[オフライン耐性方針](03_オフライン耐性方針.md) strip-at-enqueue 対象）

## Buf workflow
- `buf.yaml`: proto workspace。複数 module（`tier1.proto.api` / `tier1.proto.event` / `tier2.proto.domain` / `k1s0.proto.capability`）を含む
- `buf.gen.yaml`: 言語別 generator 設定。9 言語分を 1 yaml に集約
- `buf breaking`: MAJOR.MINOR up 時に必ず実行、BC 違反は CI fail
- `buf lint`: proto style guide 強制（field name snake_case / enum prefix / reserved 番号 / package depth ≤ 4 等）
- `buf format`: 自動整形、PR 時に diff があれば fail

## codegen pipeline（CI / Tekton）
- trigger: proto / Apicurio schema の変更 PR
- steps:
  1. `buf lint`（style）
  2. `buf breaking`（compatibility）
  3. `buf generate`（全 9 言語）
  4. 言語別 build（compile + unit test）
  5. SemConv 整合 check（tier1 09 と diff）
  6. capability matrix 生成 + diff（tier1 03 と双方向 lock）
  7. retry policy table 生成（annotation 抽出）
  8. PII field map 生成（annotation 抽出）
  9. SBOM 生成（Syft）+ scan（Grype）
  10. Cosign sign
  11. Harbor push（success のみ）

## method annotation（custom proto extensions）
k1s0 carrier extension（`k1s0.proto.options.proto` に定義）:

```
extend google.protobuf.MethodOptions {
  k1s0.RetryPolicyClass retry_policy = 50001;
  k1s0.SloClass slo_class = 50002;
  k1s0.QuotaClass quota_class = 50003;
  k1s0.ObservabilityClass observability_class = 50004;
  k1s0.CapabilityClass capability_class = 50005;
}
extend google.protobuf.FieldOptions {
  bool field_pii = 50101;
  k1s0.RedactionClass redaction_class = 50102;
}
```

全 RPC method はこれら annotation を必須とする。未付与は `buf lint` で fail。

## Apicurio Registry 連携
- event payload の schema（Avro / JSON Schema）は git SoT（`apicurio_subjects/` repo）で管理し、Argo CD + Apicurio Operator が各 cluster の Apicurio Registry に declarative reconcile する（cluster local cache としての Registry。Registry API への直接 push は禁止）
- codegen の schema fetch 元:
  - CI / 開発時: git SoT 直接（`apicurio_subjects/`）
  - runtime ランタイム consume: 各 cluster の Apicurio Operator が reconcile した cluster local Registry endpoint
- buf-for-apicurio plugin（自製、または OSS 化前は本企画 internal tool）は git SoT を読み proto と双方向 lock
- schema evolution は tier1 12 適合仕様の compatibility モード（FORWARD / BACKWARD / FULL）に従い、git PR レビュー時に Apicurio compatibility check（Operator が dry-run として実行）が CI gate

## 出力ファイル構造
- generated code は git 管理しない（gitignore）。CI で都度生成、Harbor cache で再現性確保
- reproducibility: 同 input proto / 同 buf version → 同 output bit hash

## 言語別 codegen 詳細
- .NET 8 / .NET Framework 4.6.2+: `Grpc.Tools` NuGet（`protoc-gen-grpc` + `protoc-gen-csharp`）
- Java 21: `protoc-gen-grpc-java` + `protoc-gen-java`
- Node.js 20: `ts-proto` + `@grpc/grpc-js` helper、ESM + CJS dual emit
- Browser TS: `ts-proto`（gRPC-Web 互換 stub）+ 自製 capability adapter
- Tauri: `tonic-build`（Rust）+ `ts-proto`（WebView）
- Rust: `tonic-build`
- Python: `protoc-gen-python` + `grpcio-tools`、retry policy は generated class metadata + decorator
- Ruby: gRPC protoc plugin、retry policy は generated module constant
- Go: `protoc-gen-go` + `protoc-gen-go-grpc`、retry policy は generated file の package var

## generated code の同型検証
- CI で「全言語 SDK の公開 API（method 名 / type 名 / annotation 値）が一致する」property test を実行
- 各言語の generated code から method signature を抽出（reflection / source parsing）、言語横断で diff、不一致は fail
- SemConv attribute name の同型検証も同 CI ステップで実行

## business API only の OpenAPI 派生
- `v1_thin_business_api_only` 用に、proto から OpenAPI 3.0 spec を派生:
  - Envoy Gateway gRPC-JSON Transcoder の `openapi.proto` annotation を proto に追加
  - `openapi-generator-cli` で curl 例 / Postman collection / OpenAPI yaml を生成、release artifact として配信
  - 言語別の OpenAPI generator 利用は user 側に委ねる（SDK は提供しない）

## supply chain attestation
- codegen pipeline は in-toto attestation（`slsa-provenance`）を生成、Cosign で署名、Harbor に attestation 添付
- SBOM は Syft で生成、SDK package と attestation 双方に紐付け（security15 threat-model 整合）

## 採用しない選択肢
- 手書き RPC stub
- 言語別の独自 generator（Buf workflow 統一）
- generated code の git 管理（CI 都度生成）
- method annotation の runtime override（codegen 時固定）

## 至高路線における立ち位置
- 単一 codegen pipeline で言語横断同型を物理 enforce
- method annotation を必須化することで、retry / slo / quota / observability / capability の規律が proto レベルで明示される（dimension override 禁止 / dead spec 殺しの上流）
