# client リトライバックオフ方針

## 一文方針
- リトライ / バックオフ / circuit breaker / retry budget は全言語 SDK で同一規約。method / error / deadline / retry budget の組合せから一意に動作が決まり、SDK 公開 API として individual override を受けない。

## 5 retry_policy_class（v1）

| class | unary | server-streaming | client-streaming | bidi |
|---|---|---|---|---|
| `v1_idempotent_safe` | yes | yes | no | no |
| `v1_idempotent_with_key` | yes | yes | no | no |
| `v1_non_idempotent` | no | no | no | no |
| `v1_long_streaming_resumable` | no | yes | no | yes |
| `v1_eventual_via_pending_queue` | yes | no | no | no |

各 class の動作:
- `v1_idempotent_safe`
  - retry 条件: `UNAVAILABLE` / `DEADLINE_EXCEEDED` / `INTERNAL`（transient）
  - max_attempts: 5、backoff: `exponential_with_jitter`、base=200ms、factor=2.0、cap=4s、jitter=full
  - retry budget: 30 retry / 60s
  - 用途: read 系（Get / List / Search）
- `v1_idempotent_with_key`
  - 必須 metadata: `x-idempotency-key`（SDK 自動採番）
  - server 側は `idempotency_key` で dedup
  - 用途: write 系で server-side dedup を持つもの
- `v1_non_idempotent`
  - retry: しない、失敗時はアプリに即時 throw
  - 用途: 副作用が dedup できない write
- `v1_long_streaming_resumable`
  - 切断時に `resume_token` で再接続
  - max_attempts: 無制限（exponential cap=30s）
  - 用途: Domain Event subscription / log tail
- `v1_eventual_via_pending_queue`
  - 失敗時は pending_queue に enqueue（[オフライン耐性方針](03_オフライン耐性方針.md)）
  - SDK は同期 retry を行わず、queue 経由の eventual send に委ねる
  - 用途: tier3 SPA から tier2 への mutation

retry_policy_class は method 単位で proto annotation され、Buf workflow が SDK codegen 時に固定。dimension override 禁止。

## exponential backoff
- 算出式: `base * factor ^ (attempt - 1) + random_jitter`
- 全言語 SDK で完全に同一の動作（property test で確認）
- jitter: AWS Architecture Blog の "full jitter"（`sleep = random(0, base * factor ^ (attempt - 1))`）
- cap: 1 RPC class につき固定 cap

## deadline 残量との連動
- 各 retry attempt 前に deadline 残量を check
- 残量が次の attempt 推定時間より少なければ retry を中止して `DEADLINE_EXCEEDED` で throw
- server-side のレスポンス時間 + network RTT を SDK 内部統計（OTel SemConv）から推定

## retry budget
- per-tenant: 30 retry / 60s sliding window
- per-method: 10 retry / 60s sliding window
- per-aggregate（mutation）: 5 retry / 60s
- budget 枯渇時は retry を停止して `RESOURCE_EXHAUSTED` で throw（`RetryBudgetExhausted`）
- per-stream（`v1_long_streaming_resumable`）は budget 別管理: per-stream 100 reconnect / hour、per-tenant 1000 reconnect / hour

## circuit breaker
- endpoint 単位で次の状態遷移:
  - `Closed`: 通常動作
  - `Open`: 直近 60s で error_rate > 50% かつ request 数 ≥ 20 で open、retry を即時 fail
  - `Half-Open`: open 後 30s 経過で 1 request だけ probe、success で Closed 復帰、failure で Open 維持
- circuit breaker 状態は OTel metric で emit:
  - `client.circuit_breaker.state{endpoint, state}`
  - `client.circuit_breaker.transition.event{endpoint, from, to}`
- SDK ユーザに circuit breaker を override する API は提供しない

## hedging
- v1 unsupport（複数並走の retry budget 管理が複雑なため）。`v2_hedging_with_retry_budget` 候補

## DNS / TCP / TLS handshake failure
- DNS 解決失敗: SDK 内部 5 attempts、exponential backoff、その後 `OnEndpointUnreachable` event
- TCP connect 失敗: Socket level retry は OS / runtime に委ねる、SDK は connection pool の health check で reconnect 判定
- TLS handshake failure: 1 度だけ retry（cert rotation タイミング考慮）、それ以上は `OnAuthRequired` または `OnEndpointMisconfigured` 発火

## deadlocks / starvation 防止
- 各 SDK は per-aggregate write の concurrent in-flight 1 を強制
- read-side は同 aggregate の並行 read を制限しない

## jitter property の検査
- property based test: SDK ランダム seed 1000 回で計算した backoff 系列が「monotonic non-decreasing without jitter」かつ「平均 sleep が exponential 期待値の ±5% 以内」を満たす

## 観測 emit
- 全 retry attempt は OTel span として emit、attribute は SemConv compatible（`rpc.service` / `rpc.method` / `retry.attempt_number` / `retry.policy_class` / `retry.backoff_ms` / `retry.budget_remaining` / `error.class`）
- retry exhaust は WARN log + audit event（`client.retry_exhaust.event`）

## 採用しない選択肢
- SDK ユーザによる個別 retry_policy_class override
- hedging（v1）
- 自製 retry library 利用（SDK 内蔵の機構のみ）
- ENG が判断して runtime override する型

## 至高路線における立ち位置
- 全言語 SDK の retry semantics が完全同一（property test で物理検証）
- retry budget は noisy neighbor 防止のため SDK 側で物理 enforce、tier1 15 capacity 適合仕様の `v1_global_fair_queue` と双方向 lock
