# ops アラート方針

## 一文方針
- 全 alert は `alert_catalog.lock.yaml` に build artifact として固定し、severity / SLO bind / runbook pointer / auto-action pointer / noise budget の 5 attribute を必須化、page-level alert は actionable のみ、informational alert は cap 5% を CI で物理確認、noise budget 違反 alert は自動 silence + tuning ticket 化を物理 enforce する。

## 至高路線における立ち位置
- runbook なし page 禁止、CI fail
- 「とりあえず alert を増やす」運用禁止
- 商用 alert SaaS（PagerDuty / VictorOps 商用）採用しない
- alert UI の personalization 禁止
- silence の無理由実行禁止、audit_event 必須
- false positive の放置禁止、noise budget 違反は強制 tuning

## alert class（severity 5 段階、SLO budget action と整合）

| class | severity | 動作 |
|---|---|---|
| `v1_observe` | info | SLO budget 観測のみ、page しない、Mattermost 投稿もしない。dashboard 上の status のみ |
| `v1_notify` | warning | Mattermost channel に informational 投稿、page しない、ticket は任意 |
| `v1_page` | critical | 自製 escalation engine 経由で primary on-call へ page、ack window 5 分、runbook pointer 必須 |
| `v1_freeze` | critical-urgent | page + Kyverno admission policy が関連 namespace への deploy を block |
| `v1_security_bridge` | critical-security | security incident の triage 後 operational impact phase に bridge |

## alertable / non-alertable の判定

### alertable（page 候補）
- SLO budget burn rate（短窓 / 長窓 / 中窓）
- critical infrastructure failure（cluster unreachable / control_plane_failure）
- critical security signal（threat detect、security 14 で生成、ops に bridge）
- capacity hard breach（per_tenant_volume / cluster headroom 0%）
- rotation overdue（鍵 / cert / secret）
- postmortem PR overdue（active incident で 24h 経過 unmerged）
- drill cadence overdue（restore_drill / red_team / chaos_drill）
- migration window overdue（compat window expired）

### non-alertable（page 候補から除外、ticket 経路のみ）
- audit log generation（subject 観測 metric）
- dashboard 自身の load latency
- log shipping pipeline lag（< threshold 内）
- single-host CPU spike（noisy neighbor、capacity 軸が page 候補）
- test environment failure（dev / stage namespace）

## alert_catalog.lock.yaml（build artifact）
- 1 row = `(alert_id, severity, slo_bind, runbook_ref, auto_action_ref, noise_budget_ratio, mute_window_class, description)`
- severity が `v1_page` / `v1_freeze` の場合、`runbook_ref` と `auto_action_ref` のいずれか必須
- `noise_budget_ratio`: 30 日 window で false positive 率 ≤ 5%（page level、informational は cap 不問）
- `mute_window_class`:
    - `v1_no_mute`: mute 不可（severity = security_bridge / freeze は常時 alert）
    - `v1_business_hour`: 09:00-18:00 JST のみ alert（batch job 失敗等）
    - `v1_planned_window`: planned maintenance 期間のみ mute（change management で artifact 化）

## noise budget（false positive / negative 抑制）
- 全 page-level alert に対し 30 日 false positive ratio metric を Sloth で物化
- threshold: ≤ 5% false positive、≤ 1% false negative
- 違反時の処置:
    1. 自動 silence（alertmanager mute）24h
    2. tuning ticket 起票（`alert_tuning_backlog.lock.yaml` に entry 追加）
    3. 翌週の ops review で必須 tuning（threshold rebuild / SLO 再 tune / runbook 改善）
    4. 連続 4 週違反は alert を deprecate phase へ移行

## alert routing（Alertmanager）
- 全 alert は Alertmanager の routing tree で 4 層 tag 分類:
    - 環境（`v1_prod` / `v1_stage` / `v1_dev`）
    - severity（`v1_observe`〜`v1_security_bridge`）
    - team（service owner、`ownership_table.lock.yaml` で管理）
    - signal_class（`slo_burn` / `capacity` / `rotation` / `drill_overdue` / `postmortem_overdue` / `security_bridge`）
- routing tree の yaml は build artifact、手書き routing は CI fail
- team ownership table は CODEOWNERS と双方向 lock

## deduplication / inhibition
- Alertmanager の inhibition rule で「上位 alert が active な間は下位 alert を mute」を build artifact 化
- 同一 alert の重複 page は 5 分以内 1 件に dedup

## paging budget（個人 fatigue 抑制）
- on-call 1 人あたりの 1 週間 page 数 ≤ 3 件 を SLO 化（`v1_oncall_page_per_week ≤ 3`）
- 違反は [オンコール方針](03_オンコール方針.md) の fatigue budget と双方向 lock
- paging budget は per-individual / per-team の二重 metric

## page-to-runbook の 1:1 対応
- 全 page-level alert は runbook pointer 必須、runbook 不在は CI fail
- runbook pointer は Tekton Pipeline 名 or Backstage TechDocs URL の二択、Markdown 単独は cap 5%
- [runbook 方針](07_runbook方針.md) の `runbook_catalog.lock.yaml` と双方向 lock

## alert lifecycle metric
- 各 alert に対し以下 metric を ClickHouse に永続:
    - `firing_count`（30d）
    - `ack_latency_p50/p95/p99`（page → ack 時間）
    - `resolution_latency_p50/p95/p99`（page → resolved）
    - `false_positive_count`
    - `runbook_invocation_count`
    - `auto_action_invocation_count`
    - `postmortem_link_count`

## 強制機構との bind
- 本方針は [ops 強制機構](../../04_詳細設計/02_強制機構/07_ops強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による alert ⇔ runbook 1:1 coverage / runbook ref 必須 check
    - 層 D: Alertmanager routing tree / inhibition rule の物理発火
    - 層 D: Kyverno `require-runbook-for-alert` admission policy

## 採用しない方針
- 単窓 alert: 禁止
- runbook なし page: 禁止、CI fail
- 「とりあえず alert を増やす」運用: 禁止
- 商用 alert SaaS: 採用しない
- alert UI の personalization: 禁止
- silence の無理由実行: 禁止
- alert を SLO 外で page 化: cap 10%
- false positive を放置: 禁止
