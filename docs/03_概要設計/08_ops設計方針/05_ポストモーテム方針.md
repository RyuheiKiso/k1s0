# ops ポストモーテム方針

## 一文方針
- 全 incident（ops + security 双方）に対し postmortem PR を 72h 以内に open / 14 日以内に merged を ship blocker として bind し、blameless / 5whys / action item / SLO budget delta / runbook coverage / toil delta の 6 必須 section を template 化、action item は別 issue + owner + expires_at 必須で物理 enforce する。

## 至高路線における立ち位置
- blame culture 経路禁止、blameless lint で物理覆面検出
- postmortem の short-circuit（template 省略）禁止
- action item の同 PR 内記述禁止、必ず別 issue branch out
- 「忙しいから来週書く」禁止、72h open SLA / 14 日 merged SLA、違反は service deploy block
- postmortem の internal-only memo 禁止、GitHub PR が primary
- severity 高 incident の skip 禁止
- external incident の skip 禁止

## blameless 原則
- postmortem は blameless: 個人 / role を責める表現を禁止、行動の背景にあった system / 組織 / process の欠陥を root cause として分析
- reviewer による blame 表現の検出は CODEOWNERS 必須 review で確認、blame 発見時は revision request 必須
- blameless 違反の文言は CI で正規表現 + Semgrep custom rule で覆面検出（文体 lint）、違反 PR は merge block
- blameless culture 教育は [オンコール方針](03_オンコール方針.md) の training cadence に組み込み

## postmortem template（6 必須 section）

### section 1: Summary（1 段落）
- incident_id / class / severity / impact / timeline overview

### section 2: Timeline
- detect / triage / mitigate / resolve / postmortem の 5 phase 各 timestamp + key event log
- audit_event subject の `incident_event` row から自動 generate

### section 3: Root Cause Analysis（5whys + contributing factors）
- 5whys: 1〜5 段階の why-because chain を文書化
- contributing factors: technical / process / organizational / environmental の 4 軸
- blame 表現検出 lint（Semgrep）必須

### section 4: Mitigation Actions
- 既に取った mitigation の log
- 各 mitigation の outcome（成功 / 失敗 / 部分成功）
- mitigation runbook が存在した場合は runbook_ref + execution_log

### section 5: Action Items（最重要）
- 別 GitHub Issue として branch out（postmortem PR 内に列挙のみ、実体は別 issue）
- 各 action item に owner / expires_at / priority / type（preventive / detective / responsive / tooling / runbook / SLO_tuning）必須
- implementation status が `merged` / `deployed` になるまで recurrence detection で elevated priority 維持

### section 6: Metrics（quantitative impact）
- SLO budget delta（before / after の error budget 残量）
- customer_impact_minutes
- mttr / mtbf 更新値
- runbook coverage delta（新規 runbook 化分）
- toil delta（toil_minutes_per_week metric への影響、[toil 削減方針](08_toil削減方針.md) と双方向 lock）

- 6 必須 section の section header 一致を CI で物理確認、欠落 section は merge block

## postmortem PR の lifecycle

| phase | 内容 | SLA |
|---|---|---|
| 1: open | resolve → 72h 以内 PR open | 72h |
| 2: draft | timeline / root cause 初稿、author + IC + scribe で round 1 review | - |
| 3: review | CODEOWNERS で関連 axis owner 必須 review、blameless 違反 / fact 不一致を指摘 | - |
| 4: action item branch out | section 5 の全 action item を別 GitHub Issue に branch out | - |
| 5: merged | PR open → 14 日以内 merged | 14d |

- phase 1 違反は Kyverno が関連 service の image deploy を block
- phase 5 違反は service 全 deploy block

## action item lifecycle
- 全 action item は GitHub Issue + Project board で管理:
    - label: `postmortem-action` / `type:<class>` / `priority:<level>`
    - field: `owner` / `expires_at` / `linked_postmortem` / `linked_recurrence`
- quarterly review:
    - `expires_at` を超過した未完了 action item は quarterly review で必須 re-evaluation
- implementation 完了:
    - action item issue の close は対応 PR の merged を必須化
    - close 後 30 日間は recurrence detection で implementation 効果検証
- cancel:
    - cancel は ops lead + service owner の二人承認必須、cancel reason を audit_event 必須

## recurrence と action item の bind
- [運用インシデント方針](04_運用インシデント方針.md) の `recurrence_table.lock.yaml` と双方向 lock
- 3 回以上 recurrent な incident_class は対応 action item の implementation を ship blocker
- recurrence detection で同 root cause が確認されたら、action item の priority を automatically elevated に変更

## external incident（external dependency / SaaS outage）
- 外部 SaaS / IDP / DNS / CA outage 等の external incident でも postmortem PR 必須化
- 本企画 service の impact mitigation 経路（fallback / circuit breaker / degradation pattern）を必ず action item 化
- 外部 vendor の RCA 公開時は本 postmortem PR に link

## postmortem の retention
- 全 postmortem PR + linked issue は GitHub に永続 retention
- Backstage TechDocs に search index を mirror
- postmortem 検索: `incident_class` / `severity` / `root_cause_keyword` / `time_range` で Backstage 上 search

## 公開範囲（separation of concerns）
- 通常 postmortem: 社内 GitHub repository に public
- 機密 postmortem（PII leak / security adjacency / legal sensitive）: private repository に分離、CODEOWNERS で限定 reviewer

## 強制機構との bind
- 本方針は [ops 強制機構](../../04_詳細設計/02_強制機構/07_ops強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Semgrep blameless lint + 6 必須 section header check
    - 層 D: Kyverno `block-on-postmortem-overdue` `block-on-postmortem-merge-overdue` `require-postmortem-section-completeness` admission policy
    - 層 E: GitHub PR review automation + Backstage archive retention

## 採用しない方針
- blame culture 経路: 禁止
- postmortem の short-circuit: 禁止
- action item の同 PR 内記述: 禁止
- 「忙しいから来週書く」: 禁止
- postmortem の internal-only memo: 禁止
- severity 高 incident の skip: 禁止
- external incident の skip: 禁止
- cancel の文章 only: 禁止
