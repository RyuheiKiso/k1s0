# ops オンコール方針

## 一文方針
- on-call rotation は `roster.lock.yaml` に build artifact として固定し、24×365 の primary / secondary / domain-expert の 3 階層 escalation を必須化、rotation gap ゼロ / fatigue budget 違反ゼロ / handover artifact 必須を CI で物理 enforce、商用 SLA 機能には依存せず自製 escalation engine（Argo Workflows suspend/resume + Tekton Triggers + Mattermost）+ audit_event で全 lifecycle を Apache 2.0 / MIT 経路に固定する。

## 至高路線における立ち位置
- 単一 on-call（primary のみ）禁止、3 階層 escalation 必須
- `rotation_gap_class` が `v1_unhandled_gap` に転位する allowance 禁止
- fatigue budget の cap 緩和禁止
- on-call の 24h 連続 shift 禁止、`consecutive_days ≤ 7`
- shadow rotation skip 禁止
- 商用 escalation SaaS（PagerDuty / VictorOps 商用 SLA）依存しない

## rotation 構造（3 階層 escalation）
- **階層 1: primary on-call**
    - page を最初に受ける義務、ack window 5 分
    - service tier 別に rotation 分割（tier1 / tier2 / tier3 / infra / data / security / ops の 7 rotation を独立保持）
- **階層 2: secondary on-call**
    - primary の ack window 経過時 escalate、ack window 5 分
- **階層 3: domain expert**
    - secondary も ack window 経過時 escalate
    - severity = freeze / security_bridge は階層 3 まで parallel page

## rotation cadence
- primary: 1 週間交代（Mon 09:00 JST handover）
- secondary: 1 週間交代（Wed 09:00 JST handover、shift by 2 days from primary で fatigue 分散）
- domain expert: 2 週間交代（業務知識保持期間が必要なため）
- holiday / 年末年始: cadence 維持、休暇申請は roster rebalance を必ず triger

## rotation gap invariant（rotation_gap_class enum）

| class | 内容 |
|---|---|
| `v1_zero_gap` | roster.lock.yaml で 3 名 assigned、全員 reachable |
| `v1_auto_covered_gap` | 1 名 unreachable だが自製 escalation engine が automatic swap proposal を ops lead 承認済、secondary が primary 役を物理担当。承認 → 物理担当開始までの window が 60 分以内（max_window_minutes=60）の cap で allow |
| `v1_unhandled_gap` | 上記いずれにも該当しない（CI fail）|

- `v1_unhandled_gap` 検出は CI fail
- 連続 7 日以上の不在計画（休暇）は 14 日前までに `roster.lock.yaml` に commit

## fatigue budget（v1 SLO 化）

### per-individual
- `v1_oncall_page_per_week ≤ 3`（30d rolling）
- `v1_oncall_after_hours_page_per_month ≤ 5`（22:00-06:00 JST page）
- `v1_oncall_consecutive_days ≤ 7`（連続 on-call shift 日数）

### per-team
- `v1_team_page_per_week ≤ 5 × team_size`

### 違反時の処置
1. 即時 roster rebalance
2. quarterly review で恒常的 violation の根本原因解析
3. 連続 4 週違反は alert deprecation phase か team 増員 PR 起票必須

## ack / acknowledge protocol
- ack window: page 発火後 5 分以内（severity_freeze 時は 3 分）、未 ack で next 階層 escalate
- ack 経路: Mattermost mobile app push / Mattermost slash command / Tekton Trigger HTTP callback の三系統
- ack 後の義務: 30 分以内に triage 完了 → Mattermost incident channel で incident.io OSS の incident 起票
- re-page: ack 後 60 分以内に resolved にならない場合、secondary に automatic escalation page

## handover protocol（artifact 必須）
- rotation 切替時（毎週 Mon 09:00 JST）に handover document を必ず生成:
    - 過去 1 週間の page log（resolved / ongoing 区別）
    - ongoing incident の context（postmortem PR の status / action items pending）
    - active freeze（解除予定時刻）
    - active break-glass session（expiry 時刻）
    - 来週の change management calendar（planned deploy / chaos drill）
- handover document は Backstage TechDocs に append、過去 handover は永続 retention

## break-glass 経路（on-call 専用、break_glass_class enum）

| class | 内容 |
|---|---|
| `v1_break_glass` | 通常 incident（incident_active_duration ≤ 14d）の short-lived elevated permission。常用化禁止 |
| `v1_extended_incident_break_glass` | extended incident（incident_active_duration > 14d）中の運用 break-glass。常用化禁止 constraint の対象外だが、二人承認 + 全 audit_event 維持 + 独立 metric 計上を必須化 |

### break-glass 発行 protocol
1. OpenBao response wrapping で短期 cluster-admin / DB superuser / Argo CD admin token を発行
2. 発行は Mattermost slash command 経由、`incident_ref`（active incident ID）必須、`break_glass_class` を明示
3. 全操作は audit_event subject に `v1_break_glass` または `v1_extended_incident_break_glass` fact emit
4. 使用後 1 時間以内に postmortem PR 起票必須
5. break-glass 使用は 13 SLO error budget の `v1_break_glass_count` として記録

## 3 階層 escalation の Argo Workflows DAG 展開
- `escalation_policy.lock.yaml` の宣言を Argo Workflows manifest に機械的に翻訳:
    1. trigger: Alertmanager webhook → Tekton Triggers → Argo Workflows submit
    2. step1_page_primary: primary に Mattermost mobile push + slash command 通知 → suspend（timeout = 5 分）
    3. step1_resume_on_ack: ack receipt（三系統）で resume、escalation DAG 終了
    4. step1_timeout_to_step2: suspend timeout で次階層へ
    5. step2_page_secondary: secondary に同経路で page + suspend
    6. step2_timeout_to_step3: 同様の timeout
    7. step3_page_domain_expert: domain expert に page、severity = freeze / security_bridge は step1 で parallel page（DAG branch）
    8. all_timeout_to_manager: 3 階層全 timeout で manager-page + audit_event `escalation_unhandled` emit
- 詳細実装は [ops_edge_cluster](../../04_詳細設計/03_クロスカッティング適合仕様/10_ops_edge_cluster.md) を参照（target cluster 障害時にも escalation を物理発火）

## on-call training cadence
- 新規 on-call 加入は以下の前提を必須化:
    - 全 runbook の Backstage TechDocs を一通り読了確認
    - chaos drill（Litmus）の参加 ≥ 3 回
    - red team table top の参加 ≥ 1 回
    - shadow rotation（先輩 on-call に同伴で 2 週間）完了
- quarterly drill（game day）: 全 on-call は必須参加

## 4 軸 ownership（service ownership table）
- service ownership table（`ownership_table.lock.yaml`）で 4 軸を必須化:
    - `primary_team`
    - `secondary_team`
    - `domain_expert`
    - `ops_liaison`
- 全 service は 4 軸 ownership 必須、未宣言 service の deploy は Kyverno で物理 block

## 強制機構との bind
- 本方針は [ops 強制機構](../../04_詳細設計/02_強制機構/07_ops強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による rotation gap zero / fatigue budget within / handover document complete check
    - 層 D: 自製 escalation engine（ops-edge cluster 上）の active escalation policy
    - 層 D: Kyverno `block-on-rotation-gap-unhandled` `require-ownership-table-entry` admission policy
    - 層 E: target cluster outage 時にも独立 ops-edge cluster からの page 発火（[ops_edge_cluster](../../04_詳細設計/03_クロスカッティング適合仕様/10_ops_edge_cluster.md)）

## 採用しない方針
- 単一 on-call: 禁止
- `v1_unhandled_gap` の allowance: 禁止
- fatigue budget の cap 緩和: 禁止
- on-call の 24h 連続 shift: 禁止
- shadow rotation skip: 禁止
- 商用 escalation SaaS: 採用しない
- rotation 編成の文章 only 管理: 禁止
- v1_break_glass の常用: 禁止
