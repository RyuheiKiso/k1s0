# security 境界制御方針

## 一文方針
- trust boundary は 6 surface（north-south / east-west / control-plane / persistence / supply-chain / build-time）で完全列挙、各 surface の crossing は authn + authz + transport 暗号化 + audit emit の 4 mitigation を必ず重ねた上で物理通過、いずれかが欠落する経路は admission block / network policy block / cosign verify fail で物理拒否する。

## 至高路線における立ち位置
- zero-trust 原則: 全 surface で「default deny」+ 「explicit allow」のみ
- IP based 認可禁止、必ず identity 認証 + 認可 policy
- long-lived service account token 禁止、必ず short-lived（OIDC token / OpenBao lease ≤ 1 時間）
- cluster-admin 常設運用禁止、break-glass + 短期発行のみ

## 6 surface の trust boundary

### v1_north_south
- scope: tier1 Server 系 ingress（公開 RPC / HTTP）
- 対向: v1_external_unauth / v1_external_auth
- 4 mitigation:
    - **authn**: [tier1/10 認証適合仕様](../../04_詳細設計/01_適合仕様/04_認証適合仕様.md)（OIDC / JWT）
    - **authz**: tier1/10 + [tier2/32 RLS POLICY](../../04_詳細設計/01_適合仕様/10_テナント分離適合仕様.md)
    - **transport**: TLS 1.3（cert-manager 管掌、infra 配信、PFS only）
    - **audit**: 09 観測 SoR の `auth_attempt` subject
- 物理層: Envoy Gateway / Istio gateway（infra 提供）+ Envoy ext_authz filter

### v1_east_west
- scope: cluster 内 service ↔ service（gRPC / messaging）
- 対向: v1_insider_application
- 4 mitigation:
    - **authn**: mTLS（Istio mutual TLS、cert-manager が SPIFFE 形式 cert を配信）
    - **authz**: Authorization Policy（Istio）+ namespace boundary
    - **transport**: mTLS、plaintext fallback 経路ゼロ
    - **audit**: Falco / Tetragon の east-west 通信 subject + Istio access log
- 物理層: Istio sidecar / NetworkPolicy（infra 14 で `require-istio-sidecar` 強制）

### v1_control_plane
- scope: Argo CD / etcd / Kyverno / External Secrets / OpenBao / Harbor / Tekton API
- 対向: v1_insider_operator
- 4 mitigation:
    - **authn**: OIDC + WebAuthn 必須
    - **authz**: Kubernetes RBAC + namespace + Argo CD project boundary
    - **transport**: cluster 内 mTLS + 外部 TLS 1.3
    - **audit**: k8s audit policy（ALL request / metadata level + 機微 verb は RequestResponse level）
- 物理層: admission policy + audit webhook、cluster-admin 権限は break-glass のみで短期発行

### v1_persistence
- scope: CloudNativePG / Kafka / ClickHouse / Valkey / Apicurio Registry / Ceph RGW 物理 store
- 対向: v1_insider_operator / v1_supply_chain
- 4 mitigation:
    - **authn**: DB superuser は OpenBao response wrapping のみで短期発行、SCRAM / mTLS で daemon 認証
    - **authz**: tier2/32 RLS FORCE / tier1/11 鍵階層 / preservation_class 別 access policy
    - **transport**: CloudNativePG mTLS / Kafka SASL_SSL / ClickHouse mTLS、plaintext 禁止
    - **audit**: DB engine audit（pgaudit）+ CDC subject（audit_event）
- 物理層: Kyverno admission（`require-mtls-data-instance`）+ DB engine 物理機構

### v1_supply_chain
- scope: source repo / CI runner / Harbor / SBOM / image / artifact
- 対向: v1_supply_chain
- 4 mitigation:
    - **authn**: CI runner identity = OIDC short-lived token（GitHub Actions OIDC → OpenBao exchange）
    - **authz**: repo / branch protection / required reviewers / signed commits
    - **transport**: HTTPS、SSH（公開鍵 only）
    - **audit**: cosign signature 検証 log + Tekton Chains attestation
- 物理層: cosign verify（Kyverno）+ branch protection + GPG signed commits

### v1_build_time
- scope: build runner 内の動作（compile / test / package / sign）
- 対向: v1_supply_chain
- 4 mitigation:
    - **authn**: build runner identity（GitHub OIDC）+ runner image self-attestation（runner image 自身が Cosign signed + SBOM attached + Rekor inclusion proof、[build_provenance 適合仕様](../../04_詳細設計/01_適合仕様/16_build_provenance適合仕様.md) の `runner_image_self_attestation_uri` と双方向 lock）
    - **authz**: build job が触れる secret は OpenBao short-lived token のみ、long-lived secret 不可。signing key は per-job ephemeral（24h rotation、HSM PKCS#11 transit、[tier1/11 鍵管理適合仕様](../../04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md) の `build_provenance_signing` enforcement_point と双方向 lock）
    - **transport**: build artifact upload は cosign sign 後 Harbor 経由のみ。Internal mirror（Athens / Verdaccio / Harbor proxy / cargo registry / NuGet feed）のみ通過、build container は `RUN --network=none`（Buildkit）+ Bazel sandbox + Nix sandbox の三重 sandbox で Internet 直接 fetch を物理不可能化
    - **audit**: in-toto / witness attestation + Tekton Chains が `in-toto/slsaprovenance/v1.0` predicate を emit
- 物理層: build runner = ephemeral pod（Tekton / GitHub Actions self-hosted ephemeral）、state 残存ゼロ。runner image は distroless / chainguard を base に Cosign signed + SBOM attached + Rekor inclusion proof、Linux user namespace + seccomp + cgroup v2 の三重 isolation を kernel 物理層で強制

## zero-trust 原則
- 全 surface で「default deny」+ 「explicit allow」のみ
- NetworkPolicy は default-deny ingress + default-deny egress を全 namespace で物理 enforce
- 全 service ↔ service 通信は mTLS 必須、plaintext fallback 経路ゼロ
- 認証 token は short-lived（≤ 1 時間）、long-lived は OpenBao の管理下のみ
- east-west の認可は SPIFFE ID + service-account の joint で評価、IP based 認可は禁止

## 4 mitigation の必須化と検証
- `threat_model.lock.yaml` の各 cell で、surface = crossing する場合は 4 mitigation 全てを mitigation pointer として持つことを CI で物理確認
- `mitigation_bindings.lock.yaml` に `boundary_mitigation` section を持ち、各 surface × 4 mitigation = 24 cell が全て physical pointer を持つことを CI が verify
- 文章 only mitigation は boundary section では限定禁止（cap 0%、runbook も不可）

## 採用しない方針
- 「内部 network だから plaintext 許容」: 禁止、全経路 mTLS / TLS
- IP allowlist のみで認可: 禁止、必ず identity 認証 + 認可 policy が前段にある
- long-lived service account token: 禁止、必ず short-lived（OIDC token / OpenBao lease）
- cluster-admin 常設運用: 禁止、break-glass + 短期発行のみ
- 「特定 namespace のみ NetworkPolicy 適用」: 全 namespace に default-deny を物理 enforce

## 強制機構との bind
- 本方針は [security 強制機構](../../04_詳細設計/02_強制機構/06_security強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による boundary_mitigation の 6 surface × 4 mitigation = 24 cell 全埋まり check
    - 層 D: Kyverno `require-mtls-east-west` `require-network-policy-default-deny` `require-istio-sidecar` 等
    - 層 E: TLS 1.3 cipher suite OS 強制（weakcipher handshake reject）
