# security 秘密管理方針

## 一文方針
- 全ての secret（authn token / API key / DB password / KEK / DEK / TLS private key / signing key / SSH key）は OpenBao の lease ベース短期発行のみで配信、source repo / image / config map / 環境変数（plaintext）への secret 含有は CI / runtime / build-time の三重層で物理 block、rotation overdue は admission block する。

## 至高路線における立ち位置
- `.env` file / direnv / dotenv の本番運用禁止、開発でも Testcontainers 経由の OpenBao dev mode のみ許容
- Kubernetes Secret への直接書き込み禁止、External Secrets 経由のみ
- long-lived API key の運用禁止、API key も rotation cadence 必須
- ad-hoc な secret rotation 禁止、rotation は `rotation_progress.lock.yaml` の schedule のみ

## secret class taxonomy（8 class）

| class | lifetime | rotation cadence | store |
|---|---|---|---|
| `v1_authn_token` | ≤ 1 時間（refresh 含めて ≤ 24 時間）| lifetime 期限（自動）| OpenBao + External Secrets |
| `v1_api_key` | ≤ 90 日 | 90 日強制（v1）、v2 で 30 日へ短縮検討 | OpenBao kv2 + External Secrets |
| `v1_db_password` | ≤ 24 時間（response wrapping）| 24 時間（自動 lease 更新）| OpenBao Database secret engine |
| `v1_kek` | （tier1/11 が決定）| 90 日標準、機微度別に短縮 | OpenBao Transit + HSM-backed |
| `v1_dek` | （tier1/11 が決定）| - | data store 内（KEK で wrap 済）|
| `v1_tls_private_key` | ≤ 90 日 | cert-manager 自動更新 | Kubernetes Secret + OpenBao 経由 root CA |
| `v1_signing_key` | 永続（rotation 365 日）| 365 日強制 | OpenBao Transit / KMS（HSM-backed）|
| `v1_ssh_key` | ≤ 1 時間 | lifetime 期限（自動）| OpenBao SSH secret engine（CA-based）|

## secret hygiene の三重層

### build-time
- gitleaks（pre-commit hook + CI push）
- trufflehog（CI push）
- Trivy secret scan（image build）
- SBOM 内 secret 検出（Syft）
- 検出時は merge / push / image push 全 block

### source-of-truth
- 全 secret は OpenBao 内のみ
- Kubernetes Secret は External Secrets 経由で同期される ephemeral copy として扱う
- Kubernetes Secret に直接書き込む経路は admission block

### runtime
- Falco rule で「環境変数 / file / argv に secret-like pattern」を detect、検出時は audit_event + on-call page
- Tetragon eBPF で secret file open の監査

## rotation cadence 違反の admission block
- `rotation_progress.lock.yaml`（[tier1/11 鍵管理適合仕様](../../04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md) で build artifact 化）に各 secret class の `last_rotated_at` を記録
- cadence 超過した secret class が 1 つでもあれば、本番 cluster への新規 deploy を Kyverno admission policy（`block-on-rotation-overdue`）で物理 block
- 例外経路は break-glass のみ、postmortem PR が義務

## secret 配信経路（OpenBao → application）
- External Secrets Operator が OpenBao の lease を Kubernetes Secret に同期
- application は Kubernetes Secret から read（直接 OpenBao を読まない）
- 例外: CI runner / Tekton job は OpenBao の short-lived token を OIDC exchange で直接取得
- 全配信経路で secret は memory only、disk persist は禁止（tmpfs / in-memory volume のみ）

## secret exposure 検知時の IR 経路
- exposure 検知 → [インシデント対応方針](07_インシデント対応方針.md) の class = `secret_exposure` playbook を起動
- 該当 secret class 全 instance を OpenBao 側で即時 revoke（lease revoke）
- rotate された新 secret を External Secrets で再配信、application は Kubernetes Secret reload で吸収
- exposure された場所（git history / image layer / log）の cleanup PR を起票
- 全工程の audit_event を 09 観測 SoR に emit、postmortem PR が ship blocker

## 採用しない方針
- `.env` / direnv / dotenv の本番運用: 禁止
- Kubernetes Secret への直接書き込み: 禁止、External Secrets 経由のみ
- long-lived API key の運用: 禁止
- secret を環境変数で渡す経路の plaintext 環境変数値: 禁止
- ad-hoc な secret rotation: 禁止
- secret rotation の opt-out: 禁止

## 強制機構との bind
- 本方針は [security 強制機構](../../04_詳細設計/02_強制機構/06_security強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による secret class taxonomy 全 entry に rotation cadence 宣言 check
    - 層 D: Kyverno `block-on-rotation-overdue` `block-secret-in-config-map` admission policy
    - 層 E: OpenBao Transit + HSM-backed KEK（key material physical export 不可）
