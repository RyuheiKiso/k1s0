# security セキュリティ訓練方針

## 一文方針
- セキュリティ訓練は class 別 cadence と success criteria を build artifact 化し、`threat_model.lock.yaml` の全 threat_class に対し対応 drill が定義され、cadence 違反 / drill red 状態が 1 つでも発生した場合は本番新規 deploy を admission block で物理停止する。

## 至高路線における立ち位置
- drill cadence の opt-out 禁止、cadence 超過は admission block
- 文章 only scenario 禁止、build artifact 化必須
- 訓練省略を理由とした SLO 緩和禁止
- drill 失敗の隠蔽禁止、red 状態は admission block で本番遮断、postmortem PR が ship blocker

## drill class taxonomy（7 class）
| class | 内容 |
|---|---|
| `v1_chaos_failure_drill` | infra 11 Chaos 工学方針 が担当する failure 系 drill。security 層は availability_loss incident class の発火試験として cross-axis に bind |
| `v1_restore_drill` | data 11 復旧訓練方針 が担当する DB / topic / object store の restore 演習 |
| `v1_secret_compromise_drill` | secret_exposure incident class の table-top + 実機演習 |
| `v1_supply_chain_drill` | cosign signing key の rotation 試験、Harbor 上 quarantine 実機演習、affected image の cluster 全領域からの撤去経路試験 |
| `v1_red_team_table_top` | incident class 別 table-top 演習（机上）、scenario は build artifact から randomly pick |
| `v1_red_team_live` | cluster 上での active red-team 演習 |
| `v1_external_pen_test` | 年次外部 firm による PenTest、black-box / gray-box |

## cadence と success criteria

| drill class | cadence | success criteria |
|---|---|---|
| `v1_chaos_failure_drill` | 月次（class 別）| 13 SLO budget 消費 ≤ target |
| `v1_restore_drill` | preservation_class 別（v1_zone 30 日 / v1_cross_region 90 日 等）| RPO/RTO target 内 |
| `v1_secret_compromise_drill` | 四半期 | revoke → re-issue 完了 ≤ 30 分 |
| `v1_supply_chain_drill` | 四半期 | cosign key rotation + image quarantine + cleanup ≤ 60 分 |
| `v1_red_team_table_top` | 月次（rotation）| playbook step 全踏破 + postmortem PR |
| `v1_red_team_live` | 半年 | escalation 経路の detection rate ≥ target |
| `v1_external_pen_test` | 年次 | 全発見が CVE 風 catalog 化 + patch SLO 内に修正 |

- cadence 別 `last_green_at` は `drill_progress.lock.yaml`（build artifact）に記録
- cadence 違反は admission block（`block-on-drill-overdue`）
- success criteria 違反は SLO error_budget 消費 + incident class 化（IR phase 起動）

## drill scenario の build artifact 化
- drill scenario は `scenario_catalog.lock.yaml` に build artifact 化、文章 only scenario は禁止
- 必須 field: `threat_class_ref` / `capability` / `surface` / `asset` / `expected_detection_signal` / `expected_contain_action` / `success_criteria`
- scenario は `threat_model.lock.yaml` の全 threat_class を coverage 必須、未 cover の threat_class は CI fail
- drill 実行記録は audit_event の `v1_ir` fact + `drill_progress.lock.yaml` に追記（手書き禁止、Tekton job が自動更新）

## 教育 / training
- 開発者 onboarding 時に security baseline 教育（PII taxonomy / threat_model 概観 / IR 基本動作）が git pre-merge gate（CODEOWNERS 経由 reviewer 必須）として strict enforce
- 年 1 回 refresh 演習（red_team_table_top の subset を全員参加 mode で実施）、未参加者は本番 deploy 権限の OpenBao policy で物理剥奪
- phishing 演習は v1 では scope 外（メール基盤を持たない、社内 chat / GitHub のみで運用）、v2 で範囲再評価

## 採用しない方針
- drill cadence の opt-out: 禁止、cadence 超過は admission block
- 文章 only scenario: 禁止、build artifact 化必須
- 訓練省略を理由とした SLO 緩和: 禁止
- 商用 training SaaS 一本化: 採用しない
- drill 結果の自由形式記録: 禁止、`drill_progress.lock.yaml` への構造化記録のみ
- drill 失敗の隠蔽: 禁止、red 状態は admission block で本番遮断

## 強制機構との bind
- 本方針は [security 強制機構](../../04_詳細設計/02_強制機構/06_security強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による drill_progress / scenario_catalog の coverage check
    - 層 C: chainsaw / kuttl による drill scenario 自動 replay
    - 層 D: Kyverno `block-on-drill-overdue` admission policy

## 同型構造（13 軸との整合）
- `drill_progress.lock.yaml` は infra 11 / data 11 の `failover_drill.lock.yaml` / `restore_drill.lock.yaml` と同型構造
- [release_gate.lock.yaml](../../04_詳細設計/05_lock_yaml体系/03_release_gate体系.md) の AND-gate 入力に含まれる（`drill_overdue_count = 0` が 1.0.0 ship blocker）
- scenario coverage は `threat_model.lock.yaml` の全 threat_class に対応する drill scenario が存在することを CI で物理確認
- drill 結果は audit_event subject に `v1_ir` fact として emit、09 監査方針 と同 schema を使用
