# formal プログラム正当性方針（v1_program_correctness_proof）

## 一文方針
- v1_program_correctness_proof は、各軸の実装コードに対し Hoare-style pre / post-condition / refinement type / loop invariant / termination を Stainless（Scala）/ Dafny（multi-lang）/ Lean 4 + mathlib（math + crypto）で machine-checkable に証明する proof_class であり、19 軸の critical implementation function に対し function contract が verified されることを物理 enforce する。

## 至高路線における立ち位置
- 「proof は実装の comment に書く」を禁止し、必ず machine-checkable artifact を要求する。
- 全 loop / recursion に termination metric（well-founded ordering）を必須化する。
- LLM-generated proof の人手査読を省略しない（[proof_review 方針](08_proof_review方針.md) 参照）。

| artifact | Stainless `.scala` + `.stainless` certificate / Dafny `.dfy` + `.doo` / Lean `.lean` + `.olean` + mathlib revision pin |

| active cell 数 (v1 cap) | 19（全軸） |

## tool の住み分け

### Stainless（Scala / JVM 系）
- 担当: tier1 Server tier の一部 Scala 実装、tier2 の domain logic（業務ロジック）の一部 Scala 実装、information flow logic（RLS）
- 主要 obligation: function contract、refinement type（subset type、dependent type の sugar）、information flow lattice

### Dafny（multi-lang code-gen）
- 担当: implementation 言語 spec が複数言語に code-gen される component（observability SemConv 抽象、schema-evolution decision logic、build_provenance SLSA chain logic、test/15 coverage matrix completeness check）
- 主要 obligation: function contract、loop invariant、termination、code-gen による implementation 言語への投影

### Lean 4 + mathlib（math + crypto）
- 担当: cryptographic invariant、number-theoretic property、HLC algebra、causality algebra、cryptographic assumption（DDH / RSA / AES / SHA-3）の文書化
- 主要 obligation: mathematical theorem、cryptographic construction の correctness、assumption の論理的 consistency

## 各軸の代表 program correctness obligation

### 09 observability（Dafny）
- `SemConvFieldTypeCorrectness`: SemConv field の type encoding decoder が field schema に従い正しく decode
- `SamplingDecisionCorrectness`: sampling decision function が tenant boundary を尊重

### 11 key（Lean、cryptographic）
- `ShamirThresholdProperty`: Shamir secret sharing の threshold property を Lean で証明（finite field algebra、Lagrange interpolation）
- `KEKEnvelopeCryptographicCorrectness`: KEK envelope の AES-GCM 構成が AEAD 性質を満たす（assumption: AES が PRP）
- `HKDFCorrectness`: HKDF expand-then-extract の correctness（assumption: HMAC-SHA256 が PRF）

### 12 schema（Stainless / Dafny）
- `BufBreakingDecisionCorrectness`: buf-breaking decision logic が schema-evolution rule に従い正しく決定
- `SchemaCompatibilityFunction`: N ↔ N+1 schema 間の compatibility 判定 function が forward / backward の各 case に対し正しい boolean を返す

### 13 SLO（Stainless）
- `RateLimiterMonotonicity`: rate limiter の counter が monotonic increase、cap 越え時に reject
- `BurnRateAccumulation`: burn rate window の accumulation function が time-bound 内で正しい

### 15 capacity（Stainless）
- `QuotaAllocationFairness`: quota allocation algorithm が tenant 間で fairness（max-min / proportional）を満たす
- `QuotaCounterOverflowSafety`: quota counter が overflow しない（pre-condition: counter ≥ 0、post-condition: counter ≥ 0 を保つ）

### 32 data-tenant（Stainless）
- `RLSNonInterference`: tenant A の query が tenant B の row を参照不可（information flow lattice、Stainless の `@io` annotation）
- `SessionContextBound`: session context の tenant_id が transaction boundary で必ず set（function contract）

### 39 client（Stainless）
- `ReconcileLoopTermination`: reconcile loop が well-founded ordering で必ず終了
- `StateTransitionCorrectness`: 4-state transition function が valid state のみを返す

### data01 preservation（Lean / Stainless）
- `BackupRestoreLossless`: backup-restore round-trip が lossless（Stainless function contract）
- `CryptoEraseIndistinguishability`: crypto-erase 後の key material と random の indistinguishability を Lean で証明（assumption: AES-256 が PRP）

### infra16 clock（Lean / Stainless）
- `HLCMonotonic`: HLC update function が wall_clock skew を吸収して monotonic
- `HLCCausality`: parent → child の causality を HLC encoding が preserve（Lean algebra）

### security15 threat（Stainless / Dafny）
- `ThreatCoverageClosure`: threat catalog が全 mitigation bind 済み（catalog completeness function）

### security17 build_provenance（Dafny）
- `SLSAChainMonotonic`: SLSA chain の verification function が monotonic、未署名 artifact を必ず reject
- `AttestationGraphDAGCheck`: attestation graph に cycle が無いことを Dafny で proof

### client15 SDK distribution（Stainless / Dafny）
- `SDKAdapterEquivalence`: 5 distribution_class の adapter function が proto spec の意味論を等価に preserve（refinement と co-bound）

### test15 verification（Dafny）
- `CoverageMatrixCompleteness`: `coverage_matrix.lock.yaml` の generator output が 18 axis × 5 class の cell を完備に埋める

### ops15 loop（Stainless）
- `RunbookIdempotency`: 5 signal_class の runbook function が冪等（同入力で同 state 遷移）
- `RunbookTermination`: runbook function が必ず終了

### formal（自軸）
- `ProofMatrixGeneratorCorrectness`: proof_matrix generator が axis spec の `formal_obligations` 段落を正しく集約
- `AssumptionConsistency`: `assumption.lock.yaml` の集合が論理的に矛盾しない（Lean meta-theory）

### 07 transport（Stainless）
- `BidiBackoffMonotonicity`: backoff 値が retry ごとに非減少
- `CircuitBreakerThresholdLogic`: threshold 越え判定 function の正当性

### 08 migration（Stainless）
- `DualWriteAtomicityFunction`: dual-write function が片肺 write 残骸を残さない
- `PhaseTransitionLogic`: 4 phase transition function の正当性

### 10 auth（Stainless）
- `TokenStateMachineFunction`: token state transition function が valid state のみを返す
- `StepUpInvariantFunction`: step-up auth requirement check function の正当性

### 14 OSS-lifecycle（Dafny）
- `L1PlusUniquenessFunction`: L1+ primary uniqueness check function が機能カテゴリごとに唯一を保証

### infra01 topology（Stainless）
- `FailoverFunction`: failover function の atomicity
- `LeaderElectionFunction`: leader election function の決定性

## workflow
- **specify**: 軸 spec の `formal_obligations` 段落で program correctness obligation を function 名 + pre / post + invariant + termination metric で宣言
- **model**: 実装言語に応じて Stainless / Dafny / Lean に write、function contract を annotation で書く
- **prove**: Tekton Pipeline で tool を起動、verification obligation を SMT solver で discharge（Stainless: Inox、Dafny: Z3、Lean: tactics + decision procedures）
- **review**: dual reviewer sign-off、cryptographic proof は domain expert（暗号 specialist）の review 必須
- **archive**: proof certificate を `proof_status.lock.yaml` に fingerprint、Lean は `mathlib_pin.lock.yaml` に revision pin

## termination proof
- 全 loop / recursion に termination metric（well-founded ordering）を必須化。
- 例: reconcile loop は dirty record 数を metric とする減少関数で終了、quota allocation loop は残 quota の monotonic decrease で終了。
- 無限 loop が意図的（daemon thread）の場合、軸 spec で `termination_exempt: true` を陽に annotation し、正当性を spec 段落で文書化（`assumption.lock.yaml` に cap=20 件以内で計上）。

## cryptographic assumption の扱い
- Lean 4 + mathlib で証明する cryptographic invariant は必ず `assumption.lock.yaml` に文献 pointer + DOI + 軽減策 + revisit 期限を記載。
- assumption の例:
    - AES-256 が PRP（Bellare-Desai-Jokipii-Rogaway 文献）
    - HMAC-SHA256 が PRF（Bellare 文献）
    - X25519 が CDH（DJB 文献）
    - SHA-3 が collision-resistant（NIST FIPS 202）
- assumption の cap: v1=20 件、超過は CI fail。

## 採用しない設計
- Coq / Isabelle / F* / SPARK Pro は採用しない（[非提供スコープ](../../02_要件定義/01_スコープ/02_非提供スコープ.md) 参照）。
- 直接 SMT solver invocation（Z3 / CVC5 を driver で叩く）は採用しない。
- 「proof は実装の comment に書く」不可、必ず machine-checkable artifact。
- LLM-generated proof の人手査読省略不可。

## 強制機構との bind
- 本方針は [formal 強制機構](../../04_詳細設計/02_強制機構/10_formal強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による termination_exempt cap check / assumption cap check
    - 層 D: Kyverno `require-mathlib-pinned` `require-termination-exempt-cap` admission policy
    - 層 E: cosign signed program correctness certificate + mathlib revision の git submodule + cosign 署名
    - 層 F: Stainless / Dafny / Lean による型 / proof check 自体

## CI 不変条件（v1_program_correctness_proof 担当部分）
- 整合 1: `proof_inventory.lock.yaml` の全 v1_program_correctness_proof entry が function_name + tool_kind + pre / post / invariant / termination_metric + statement_hash 完備
- 整合 2: 全 v1_program_correctness_proof cell の last_verified_at が cadence_days=7 以内
- 整合 3: `counter_example.lock.yaml` の v1_program_correctness_proof entry が close_due_at 以内に closure
- 整合 4: `mathlib_pin.lock.yaml` の Lean mathlib revision が pin 済み、upstream pull は break-glass + dual review
- 整合 5: `assumption.lock.yaml` の cryptographic assumption が cap=20 件以内、文献 pointer + DOI + 軽減策完備
- 整合 6: `termination_exempt` annotation 数の cap（v1=10 件以内）
- 整合 7: generator output と手書き drift = 0
