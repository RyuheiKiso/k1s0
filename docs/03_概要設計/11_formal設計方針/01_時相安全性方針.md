# formal 時相安全性方針（v1_temporal_safety_proof）

## 一文方針
- v1_temporal_safety_proof は、各軸の「常に成り立つべき safety invariant（"bad thing never happens"）」を TLA+ + Apalache（symbolic model checker）で machine-checkable に証明する proof_class であり、19 軸全 cell に対し theorem 名 + statement_hash + tool_version + certificate_hash が `proof_inventory.lock.yaml` に登録され、かつ `proof_status.lock.yaml` で verified であることを 1.0.0 ship blocker として物理 enforce する。

## 至高路線における立ち位置
- safety property は最 critical な invariant であり、coverage_weight=1.5 を割り当てる。
- 「文章のみで safety claim」「論文引用のみ」を禁止し、必ず machine-checkable artifact を要求する。
- 「実用上はほぼ起きない」を理由とする safety property の省略を禁止する。

## 担当 proof_class メタデータ

| 項目 | 値 |
|---|---|
| 意味論 | temporal logic の formula `[](P)`（always P）として表現される safety property、即ち state space 上のどの reachable state でも P が成り立つ |
| artifact | TLA+ `.tla` spec + Apalache `.json` trace + TLC inv proof log |
| cadence_class | v1_per_axis_change（軸 spec 変更時 + weekly minimum） |

| artifact_class | v1_apalache_certificate |
| orchestrator_preference | tlaplus_apalache_pipeline |
| coverage_weight | 1.5 |
| primary defense_layers | tlaplus_apalache_pipeline / proof_gate_kyverno |
| active cell 数 (v1 cap) | 19（全軸） |

## TLA+ + Apalache 採用の根拠
- TLA+ は 4 半世紀以上の業界実績（DEC SRC 由来、AWS S3 / DynamoDB / CockroachDB / TigerBeetle / Microsoft Azure Cosmos DB が運用）を持ち、temporal logic で safety + liveness を一貫して書ける唯一の OSS。
- Apalache（Symbolic Model Checker for TLA+、Apache 2.0、Informal Systems）は SMT-based の symbolic model check で、TLC の exhaustive enumeration では到達できない state space を SMT solver で symbolic に探索可能。
- bound parameter は init / next の transition relation に対し bounded depth で symbolic execution。
- SPIN / NuSMV / UPPAAL を採用しない（[非提供スコープ](../../02_要件定義/01_スコープ/02_非提供スコープ.md) 参照）。

## Safety property 形式の規律
- 全 safety property は TLA+ の `Inv == ...` 形式で invariant として書く。temporal modal `[]` を陽に書くのではなく、init + next + invariant の triple で表現（Apalache が要求する形式）。
- state space は finite に bound できる範囲で書く（例: bidi state machine の concurrent connection 数を有界、auth token 数を有界）。bound 値は spec 内に constant として宣言、proof 時に sweep。
- 反例（counter-example）が出た場合は close_kind ∈ {fixed_in_code, fixed_in_spec, accepted_as_bug, scope_narrowed} のいずれかで 14 day 以内に closure（[counter_example 方針](07_counter_example方針.md) 参照）。

## 各軸の代表 invariant（19 軸の主要 obligation）

### 07 transport
- `InvBidiHandshake`: bidi handshake state machine が deadlock free、未確定 state なし
- `InvBackoffMonotonic`: backoff 値が retry ごとに非減少、cap を超えない
- `InvCircuitBreakerThreshold`: threshold 越えで open、half-open で probe、closed で全通過の transition closure

### 08 migration
- `InvDualWriteAtomicity`: dual-write 期間中に source / target の両方への書き込みが必ず atomic（片肺 write 残骸ゼロ）
- `InvCutoverNoLost`: cutover boundary で in-flight request が必ず source または target のどちらかで処理される
- `InvPhaseTransition`: 4 phase（pre / dual / cutover / post）の遷移が monotonic、逆戻りなし

### 09 observability
- `InvSpanCausality`: parent_span_id partial order が DAG（cycle なし）、causality preserved
- `InvSamplingBoundary`: sampling rate が tenant boundary を超えて leak しない

### 10 auth
- `InvTokenStateMachine`: token の state machine（minted → active → refreshed → revoked）が closure、revoked 後の active 復帰なし
- `InvStepUpInvariant`: step-up auth が必要な resource への access は step-up 完了後のみ

### 11 key
- `InvKeyRotationMonotonic`: key version が rotation ごとに非減少、過去 version の re-mint なし
- `InvKEKEnvelopeIntegrity`: DEK は KEK でのみ wrap、KEK の取り違えなし

### 12 schema
- `InvSchemaForwardCompat`: N+1 schema が N schema を forward-compatible に読める
- `InvSchemaBackwardCompat`: N schema が N+1 schema を backward-compatible に読める

### 13 SLO
- `InvRateLimiterCap`: rate limiter が cap 越えを拒否、cap 越え通過 state 不可達

### 14 OSS-lifecycle
- `InvL1PlusUniqueness`: 機能カテゴリごとに L1+ primary が唯一、横並びゼロ

### 15 capacity
- `InvQuotaNonNegative`: quota counter が負にならない、overflow 時の rollback closure

### 32 data-tenant
- `InvRLSNonInterference`: tenant A の query が tenant B の row を参照不可（information flow 不可達）
- `InvSessionContextBound`: session context の tenant_id が transaction boundary で必ず set

### 39 client
- `InvClientStateMachine`: 4-state（fresh / dirty / syncing / reconciled）の transition closure、invalid state 不可達

### infra01 topology
- `InvSplitBrainImpossible`: partition 中に複数 leader 同時 active 不可
- `InvFailoverAtomicity`: failover が atomic、partial failover 残骸なし

### infra16 clock
- `InvHLCMonotonic`: HLC が wall_clock skew を吸収して monotonic
- `InvCausalityPreserved`: parent → child の causality が HLC で preserve

### data01 preservation
- `InvBackupPriorState`: backup 取得時の state が restore 後に subset として復元（lossless）
- `InvCryptoEraseFinality`: crypto-erase 後に key material が再構築不可

### security15 threat
- 各 threat 1 件に対し `InvThreat_<id>`: 「攻撃者が threat の goal を達成不可」を temporal safety で claim、threat の new entry が出現したら同 commit で `proof_inventory` 追加

### security17 build_provenance
- `InvSLSAChainMonotonic`: build → image → deploy の attestation chain が monotonic、未署名 artifact が deploy 不可達
- `InvAttestationDAG`: attestation graph が DAG（cycle なし）

### client15 SDK distribution
- `InvSDKAdapterEquivalence`: 5 distribution_class の adapter が proto spec の意味論を等価に preserve、client → adapter → proto の round-trip closure

### ops15 loop
- `InvRunbookSafety`: 5 signal_class 全ての runbook が safety invariant を破らない
- `InvIdempotency`: runbook の二重実行が単一実行と等価

### test15 verification
- `InvCoverageMatrixCompleteness`: 18 axis × 5 verification_class の cell が完備、欠損ゼロ

### formal（自軸）
- `InvProofStatusMonotonic`: proof_status の verified → unverified 退化が新 theorem 切り without しか起きない
- `InvAxiomConsistency`: assumption.lock.yaml に登録された assumption 集合が論理的に矛盾しない

## workflow（specify → model → prove → review → archive）
- **specify**: 各軸 spec に `formal_obligations` 段落を書き、obligation を theorem 名 + 自然言語 statement + expected tool で宣言。obligation は generator で `proof_inventory.lock.yaml` に転写。
- **model**: obligation を TLA+ `.tla` spec として記述、constants / variables / init / next / invariant を定義。
- **prove**: Tekton Pipeline で Apalache を起動、symbolic model check で invariant violation を探索。bound parameter（state space depth / SMT timeout）は `tla_apalache_pin.lock.yaml` で固定。
- **review**: `proof_review_assignment.yaml` に従い 2 名 reviewer を round-robin 割当、cosign signature 双方を `proof_review.lock.yaml` に bind。reviewer のうち 1 名は LLM 補助でない人間。
- **archive**: verified certificate を Ceph RGW Object Lock Compliance mode に retention（cap 10 year）、`proof_status.lock.yaml` に statement_hash + certificate_hash + tool_version + reviewer_sigs を fingerprint。

## 採用しない設計
- SPIN / NuSMV / UPPAAL を採用しない（[非提供スコープ](../../02_要件定義/01_スコープ/02_非提供スコープ.md) 参照）。
- TLA+ で書けるが Apalache では bound 不能な spec: bound 値を有限化する形に rewrite、または refinement_proof 経由で別 tool（Stainless / Dafny / Lean）に投影。
- 文章のみ safety claim 不可、必ず machine-checkable artifact。
- 反例の「軽微だから無視」不可、必ず 4 close_kind のいずれかに分類。

## 強制機構との bind
- 本方針は [formal 強制機構](../../04_詳細設計/02_強制機構/10_formal強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest custom rule（proof_inventory schema 検証 / cadence 検証）
    - 層 C: Tekton Pipeline → Apalache 起動の e2e 試験
    - 層 D: Kyverno `require-proof-cell-verified` admission policy
    - 層 E: cosign signed Apalache certificate + Ceph RGW Object Lock retention
    - 層 F: TLA+ + Apalache symbolic model check 自体

## CI 不変条件（v1_temporal_safety_proof 担当部分）
- 整合 1: `proof_inventory.lock.yaml` の全 v1_temporal_safety_proof entry が theorem_name + statement_hash + tool_version + expected_certificate_hash 完備
- 整合 2: 全 v1_temporal_safety_proof cell の last_verified_at が cadence_days=7 以内
- 整合 3: `counter_example.lock.yaml` の v1_temporal_safety_proof entry が close_due_at 以内に closure（high=14d / medium=30d / low=90d）
- 整合 4: `tla_apalache_pin.lock.yaml` の TLA+ tools / Apalache version が pin 済み、major version migration drill の last_green_at が cadence 内
- 整合 5: generator output と手書き drift = 0（`proof_inventory.lock.yaml` は build artifact、手書き禁止）
