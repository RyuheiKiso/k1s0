# tier2 の責務（ドメイン業務共通化）

## 一文方針
- tier2 は tier3 にドメイン業務の共通化処理を提供する責務を持つ。tier3 から見える業務の語彙を tier2 に集約し、業界 / ドメイン横断で再利用される業務資産（Domain Event / Workflow 定義 / 決定表 / 業務マスタ / DB schema 等）を所有する。

## 1.0.0 出荷スコープ
- 1.0.0 で出荷する業界 pack: 製造業のみ
- 本ディレクトリの全文書で扱う「業界横断」「業界 pack」「業界拡張」は tier2 の構造的前提であり、製造業以外の pack は後続バージョンで [業界拡張モデル](02_業界拡張モデル.md) に従って追加する
- 製造業固有概念を業界横断層に置くことは禁止（強制機構は [tier2 強制機構](../../04_詳細設計/02_強制機構/02_tier2強制機構.md) を参照）

## 方針
- tier2 は tier3 にドメイン業務の共通化処理を提供する責務を持つ
- tier3 から見える業務の語彙（製造業であれば「設備」「ロット」「検査結果」等）を tier2 に集約し、業界 / ドメイン横断で再利用される業務資産（Domain Event / Workflow 定義 / 決定表 / 業務マスタ / DB schema 等）を所有する
- tier3 は tier2 の提供する API / Service 経由でのみ業務資産にアクセスする。tier2 を迂回して tier1 Library を直接組み合わせ、業務処理を独自に再実装することは禁止する
- tier1 の OSS / ミドルウェアへの直接アクセスは禁止する。tier2 内部の infra 接続はすべて tier1 Library 経由とする

## 背景・狙い
- 例: tier3 が独自に「検査結果の確定」Workflow を Temporal で実装した場合、別の tier3 が同じ業務を別の Workflow で実装し、検査結果の確定基準・補償処理・通知タイミング等が乖離する。監査・規制対応・業務連携の各局面で破綻する
- tier2 で業務資産を所有しておけば、業界 / ドメイン横断の整合性を tier2 で担保でき、tier3 は業務固有の差分のみを表現すればよい
- tier3 担当（ジュニア級）が業務不変条件を踏み抜く経路を構造で塞ぐ

## tier3 への提供方針
- 業務資産の既定実装は tier2 が所有し、tier3 は [業務資産所有権](06_業務資産所有権.md) に従って override で業務固有の差分を表現する
- override の拡張点は contract test で守られ、tier2 のバージョンアップで silently 壊れない

## tier3 への影響範囲（抽象化レベル別）
- **Lv 業界横断**: 業界に依存しない業務語彙（通知 / 監査 / 承認 / 帳票 / マスタ管理）。tier2 の API 変更時、tier3 は override 部のみ追従
- **Lv 業界共通**: 業界 pack 内で共通する業務語彙（製造業であれば「設備」「ロット」等）。tier3 は override 部 + 該当ドメイン参照部のみ追従
- **Lv 業界固有**: 業界 pack 内ドメイン固有の業務語彙（FA / 調達 / 検査 各ドメイン）。tier3 は当該ドメイン利用部を追従
- **Lv テナント固有**: テナントごとの差分は override / 設定で吸収。tier2 / tier3 のコード変更は伴わない（マスタ・ルール・権限の差分のみ）

詳細は [抽象化レベル](03_抽象化レベル.md) を参照。
