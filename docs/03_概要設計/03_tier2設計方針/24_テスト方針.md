# tier2 テスト方針

## 一文方針
- tier2 のテストは property based test + Pact contract test + Testcontainers integration test + Litmus chaos drill + atomic 三表書込 invariant test の 5 種で構成。18 軸 × 5 verification_class = 90 cell（18 軸 = 19 軸から formal を除く）coverage matrix の tier2 cell を満たすことを必須要件とする。

## 5 種テスト

### property based test
- 5 言語: FsCheck (.NET) / fast-check (TS) / Hypothesis (Python) / proptest (Rust) / jqwik (Java)
- 対象: aggregate invariant / BusinessConflict subtype 判定 / 状態遷移 / atomic 三表書込 P1〜P4

### Pact contract test
- provider（tier2 Service）/ consumer（tier3） の双方向 verify
- tier3 リポジトリの CI で必須実行、skip / 改変 CI fail
- tier2 minor version up 時、新版 contract test での再実行を CI に組込

### Testcontainers integration test
- tier1 Server + Companion Mock + atomic 三表書込（CloudNativePG）+ Outbox（Kafka Strimzi）+ Keycloak + OpenBao を起動
- 業務 use case の round-trip（write 経路 + read model 反映）
- cross-tenant integration test（tenant A の context で tenant B のデータ取得不可）

### Litmus chaos drill
- noisy neighbor（per-tenant burst が他 tenant SLO を破らない）
- replication_lag 注入
- partition rebalance 中の cutover
- cross-region failover

### atomic 三表書込 invariant test
- P1: 状態変更時に Outbox + Audit が同 transaction
- P2: Outbox 投入失敗時 rollback
- P3: tenant_id mismatch で WITH CHECK reject
- P4: pgaudit が pii_segregated 全 SELECT / INSERT / UPDATE / DELETE 捕捉

## verification_class（19_検証規律適合仕様 と整合）
tier2 cell:
- type_invariant: aggregate type 不変条件
- property_axiom: BusinessConflict subtype / atomic 三表書込
- contract_pair: Pact provider / consumer
- scenario_replay: 製造業 pack 9 業務シナリオ
- fault_chaos: Litmus chaos drill

## 受入条件
- 18 軸 × 5 verification_class = 90 cell（18 軸 = 19 軸から formal を除く）の tier2 cell green
- atomic 三表書込 P1〜P4 invariant property test green
- cross-tenant integration test 全 green
- 製造業 pack stress test 9 業務シナリオ全 green
