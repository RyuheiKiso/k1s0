# tier2 言語スタック

## 一文方針
- tier2 は tier1 Library 対応 4 言語（Rust / C# (.NET 8+) / Go / TypeScript）と同一の言語スタックで実装する。bounded context（製造業 FA / 調達 / 検査）ごとに最適な言語を選択するが、4 言語の境界を超えない。.NET Framework は tier2 業務 service の対象外（Companion で吸収）。

## 言語スタック
- **Rust**: 主言語、performance-critical な業務 service / 共通モジュール
- **C# (.NET 8+)**: business engineer 親和性、Microsoft 生態系統合
- **Go**: cloud-native / Operator 系業務 service
- **TypeScript**: BFF auth-edge 等の薄い service、tier3 共通 component package

## 言語選択基準
- bounded context 単位で言語を選択
- 業務エンジニアの母集団 + 業界知識との親和性
- ドメイン業務処理の性質（CPU bound / IO bound / batch）

## 共通要件
- 全言語で tier1 Library 経由のみ infra 利用（直接 import 禁止、CI で deny）
- 全言語で同 atomic 三表書込 / BusinessConflict subtype / ABAC policy 評価
- 4 言語等価強度の compile-time 不正遷移防止（[状態遷移パターン](13_状態遷移パターン.md)）

## 採用しない言語
- .NET Framework: tier2 業務 service の対象外（レガシー資産 tier3 のみ Companion で吸収）
- Java / Python / Ruby: tier2 対象外（SDK 配布の対象言語、tier1 / tier2 言語スタックには含まれない）
- C / C++: tier2 対象外（infra / formal の検査対象のみ）

## 言語追加の手順
- 新言語追加は tier1 言語追加の手順に従う（[tier2 互換性ポリシー](11_互換性ポリシー.md)）
- 4 言語等価強度の物理 enforce が必須
