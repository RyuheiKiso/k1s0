# tier2 外部システム統合（outbound）

## 一文方針
- 既存基幹 / partner / SaaS との連携は tier1 External Proto + Companion + Webhook の 3 形態で表現する。inbound / outbound いずれも proto を単一の真とし、wire 規約は External Proto BACKWARD 互換、認証は OAuth 2.1 token exchange、配送保証は at-least-once + idempotent 受信。

## outbound の形態
- **External Proto via tier1 Gateway**: tier2 が Domain Event を Outbox に書く → Kafka → tier1 Server が外部に push（gRPC / HTTP/JSON）
- **Companion via Webhook**: 外部システムが webhook receive endpoint を持つ場合、tier1 Companion が webhook POST で push
- **External Proto via External Proto reverse**: 外部システムが External Proto consumer の場合、tier1 Gateway 経由で proto stub を提供

## subscription model
- 外部システムが Domain Event を subscribe する場合、Apicurio Registry に Avro schema を提供
- subscriber 側で long backlog を持つ可能性を考慮し、deprecation_window 24 ヶ月（[スキーマ進化適合仕様](../../04_詳細設計/01_適合仕様/06_スキーマ進化適合仕様.md) `v1_event_avro` FULL）

## 信頼性 / 配送保証
- at-least-once: Outbox + Kafka MirrorMaker 2
- 受信側の idempotent: Idempotency-Key 強制（24h TTL）
- 配送失敗の retry: exponential backoff with full jitter（[client リトライバックオフ方針](../09_client設計方針/06_リトライバックオフ方針.md) `v1_idempotent_with_key`）
- DLQ（Dead Letter Queue）: Kafka topic で error event を分離

## 認証 / 暗号化 / 署名
- OAuth 2.1 Client Credentials Grant + JWT signing（tier1 04 認証適合仕様 `v1_workload_jwt`）
- 外部 partner との連携は token exchange（RFC 8693、`v1_federated_exchange`）
- 全 outbound payload は TLS 1.3 + mTLS（infra Istio mesh STRICT）
- 機密データを含む payload は AES-256-GCM application-layer envelope 暗号化（[鍵管理適合仕様](../../04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md) `v1_data_dek`）

## 業務語彙との対応
- 外部システムの語彙と本企画の業務語彙の差は External Proto field mapping で吸収
- mapping は宣言的に YAML 管理、CI で双方向整合検査
- 業界横断的な外部連携（例: 親会社 ERP）は業界横断 Lv API で表現

## inbound との対称性
- inbound webhook receive endpoint は tier1 Server 系（Backend-for-Library）が担当
- inbound payload は External Proto schema で型 validate
- inbound 認証は外部発行 token を JWKS verify
- tier2 業務処理は inbound / outbound で同 use case を共有（CQRS の write 経路）

## 監査 / observability
- 全 outbound / inbound 操作は audit_event に emit（external_system_id / direction / status）
- trace_id を W3C Trace Context で外部システムに propagate
- 外部システムが trace_id を返さない場合、新 root trace として継続

## tier3 の拡張点
- 外部システム個別の業務 mapping は tier3 / テナント運用責任
- tier2 は外部統合 facade の機構（proto + Webhook）のみ提供

## 1.0.0 出荷時の対応範囲
- 製造業 pack の主要外部連携（親会社 ERP / 取引先 EDI / 検査機器 / SCADA）
- partner federation は OAuth 2.1 token exchange + Keycloak identity brokering

## 採用しない設計
- 外部システム個別の独自 wire protocol（proto を真とする）
- at-most-once 配送（必ず at-least-once + idempotent 受信）
- mTLS 不在の outbound
- audit emit 省略
- 同期 RPC のみで外部連携（必ず Outbox + Kafka 経由）

## 5 adapter 仕様

`src/tier2/integration/src/` に実装された 5 つの外部統合 adapter の責務と業界中立性の説明。

### edi_x12 — ANSI X12 EDI 取引先電文アダプタ

| 項目 | 内容 |
|---|---|
| 実装ファイル | `src/tier2/integration/src/edi_x12.rs` |
| 対応規格 | ANSI X12 850 Purchase Order トランザクション |
| 変換方向 | inbound のみ（外部取引先 → tier2 proto） |

**責務**: X12 850 発注電文（BEG / PO1 / N1 セグメント）を tier2 `PurchaseOrder` proto 形式（`MappedPurchaseOrder`）に変換する。フィールドマッピングは `external_proto_mapping.yaml §edi_x12` を SoT とする。

**フィールド変換ルール**

| X12 セグメント | 変換先フィールド | 変換方式 |
|---|---|---|
| `BEG03_OrderNumber` | `order_id` | identity コピー |
| `BEG05_OrderDate`（YYYYMMDD） | `ordered_at`（RFC3339） | `YYYYMMDD → YYYY-MM-DDT00:00:00Z` |
| `PO1_01_OrderedQuantity` | `quantity`（int64） | 文字列 → int64 parse |
| `PO1_03_UnitPrice`（小数点文字列） | `unit_price_jpy`（int64 円） | 小数点以下切り捨て |
| `N1_02_Name` | `customer_code` | identity コピー |

**業界中立性**: `X12Adapter` / `MappedPurchaseOrder` の公開型名は業界固有語（設備 / ロット / 拠点等）を含まない。X12 は業界横断的な EDI 標準であり業界 pack 依存ではない。製造業 pack 固有のフィールド拡張は tier3 / テナント運用責任で行う。

---

### inspection_machine_modbus — 検査機器 Modbus TCP アダプタ

| 項目 | 内容 |
|---|---|
| 実装ファイル | `src/tier2/integration/src/inspection_machine_modbus.rs` |
| 対応規格 | Modbus TCP Holding Register（FC03） |
| 変換方向 | inbound のみ（検査機器 → tier2 proto） |

**責務**: Modbus holding register フレーム（7 レジスタ）を tier2 `InspectionResult` proto 形式（`MappedInspectionResult`）に変換する。フィールドマッピングは `external_proto_mapping.yaml §inspection_machine_modbus` を SoT とする。

**レジスタマッピング**

| レジスタ番号 | 変換先フィールド | 変換方式 |
|---|---|---|
| `register_0` + `register_1` | `measured_value`（f64） | big-endian 2-word float32 デコード（IEEE 754） |
| `register_2` | `machine_id`（`MACHINE-{id:04}`） | uint16 → フォーマット文字列 |
| `register_3` | `inspection_type`（`dimensional` / `surface` / `weight`） | uint16 → enum 文字列 |
| `register_4` + `register_5` | `measured_at`（RFC3339） | big-endian 2-word uint32 → Unix timestamp → RFC3339 |
| `register_6` | `pass_fail`（bool） | `0=pass=true`、その他 `false` |

**業界中立性**: `ModbusAdapter` は検査値の型変換のみを担い、製造業固有のビジネスロジック（不良判定ルール等）は含まない。Modbus は製造業に限らず建設・エネルギー等でも使用される業界横断的プロトコルであり業界 pack 依存ではない。

---

### oauth_token_exchange — OAuth 2.1 Token Exchange アダプタ

| 項目 | 内容 |
|---|---|
| 実装ファイル | `src/tier2/integration/src/oauth_token_exchange.rs` |
| 対応規格 | RFC 8693 OAuth 2.0 Token Exchange |
| 変換方向 | outbound（tier2 → Keycloak authorization server） |

**責務**: サービス間のトークン変換を担う。Keycloak の token エンドポイントに HTTP POST して `subject_token` を `target_audience` 向けアクセストークンに交換する。

**API**

| メソッド | 引数 | 戻り値 | 説明 |
|---|---|---|---|
| `exchange(subject_token)` | 変換元 Bearer トークン文字列 | `String`（access_token のみ） | 軽量 API |
| `exchange_full(subject_token)` | 変換元 Bearer トークン文字列 | `TokenExchangeResponse` | `expires_in` / `scope` も必要な場合 |

**エラー種別**

| `ExchangeError` | 発生条件 |
|---|---|
| `Http` | ネットワーク障害 / タイムアウト（接続 10 秒 / リクエスト 30 秒） |
| `HttpStatus(code)` | 2xx 以外のレスポンス（401: クレデンシャル不正 / 403: スコープ不足 等） |
| `Parse` | JSON デシリアライズ失敗 |
| `MissingToken` | レスポンス JSON に `access_token` フィールドが存在しない |

**業界中立性**: `OAuthTokenExchange` は RFC 8693 の汎用実装であり業界 pack 依存ではない。Keycloak の identity brokering を通じた partner federation（`v1_federated_exchange`）のコア機構として tier2 が提供する。

---

### scada_opcua — SCADA OPC-UA アダプタ

| 項目 | 内容 |
|---|---|
| 実装ファイル | `src/tier2/integration/src/scada_opcua.rs` |
| 対応規格 | OPC-UA DataChange Notification（IEC 62541） |
| 変換方向 | inbound のみ（SCADA / OPC-UA サーバー → tier2 proto） |

**責務**: OPC-UA DataChange 通知（`OpcUaDataChangeNotification`）を tier2 `ProductionProgress` proto 形式（`MappedProductionProgress`）に変換する。フィールドマッピングは `external_proto_mapping.yaml §scada_opcua` を SoT とする。

**フィールド変換ルール**

| OPC-UA フィールド | 変換先フィールド | 変換方式 |
|---|---|---|
| `NodeId` | `machine_id` | identity コピー |
| `Value_Value`（Variant） | `production_count`（int64） | JSON 数値 / 文字列 → int64 parse |
| `Value_SourceTimestamp` | `produced_at`（RFC3339） | .NET DateTimeOffset 形式 → RFC3339 正規化 |
| `StatusCode` | `status_ok`（bool） | `0（Good）=true`、その他 `false` |
| `WorkorderId`（Variant） | `work_order_id`（文字列） | JSON 文字列 / null → 文字列 |

**業界中立性**: `OpcUaAdapter` は OPC-UA の型変換のみを担い、製造業固有の業務ロジックは含まない。OPC-UA は製造業・エネルギー・ビル管理等で広く使用される業界横断的プロトコルであり業界 pack 依存ではない。Modbus 同様に `NodeId` の意味解釈（どの機器の何のパラメータか）は tier3 / テナント運用責任で行う。

### webhook — HMAC-SHA256 署名付き Webhook 配信アダプタ

| 項目 | 内容 |
|---|---|
| 実装ファイル | `src/tier2/integration/src/webhook.rs` |
| 対応方式 | HMAC-SHA256 署名付き HTTP POST |
| 変換方向 | outbound のみ（tier2 Domain Event → 外部エンドポイント） |

**責務**: tier2 の Domain Event を Outbox 経由で受け取り、HMAC-SHA256 署名（`X-K1s0-Signature: sha256={hex}`）を付与した上で外部エンドポイントに HTTP POST で配信する。5xx 時は指数バックオフ（1s / 2s / 4s…）でリトライ。

**API**

| メソッド | 引数 | 戻り値 | 説明 |
|---|---|---|---|
| `compute_signature(secret, body)` | シークレット文字列 / ペイロードバイト列 | `String`（`sha256={hex64}`） | 静的メソッド（テスト・外部検証にも利用可能） |
| `deliver(payload)` | `WebhookPayload`（`event_type` + `body`） | `Result<(), WebhookError>` | HMAC 署名付き HTTP POST（最大 `max_retries` 回リトライ） |

**エラー種別**

| `WebhookError` | 発生条件 |
|---|---|
| `SignatureCompute` | HMAC 初期化失敗（不正なシークレット） |
| `Http` | ネットワーク障害 / タイムアウト（接続 10 秒 / リクエスト 30 秒） |
| `HttpStatus(code)` | 4xx（クライアントエラー / リトライ不可）または 5xx 最大リトライ超過 |
| `Serialization` | ペイロード JSON シリアライズ失敗 |

**シークレット管理**: HMAC 署名用シークレットは OpenBao Transit 経由で管理する（`docs/04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md §v1_data_dek`）。シークレットを src/ に直接記述することは禁止。

**業界中立性**: `WebhookDelivery` は汎用 HMAC-SHA256 Webhook 配信機構であり業界 pack 依存ではない。`WebhookPayload.event_type` の意味解釈・エンドポイント URL はテナント設定に委ねる。
