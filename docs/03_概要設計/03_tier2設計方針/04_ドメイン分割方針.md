# tier2 ドメイン分割方針

## 一文方針
- 業界 pack 内のドメイン分割は bounded context 単位で行い、cross-domain 参照は Domain Event 経由に限定する。直接参照（cross-domain repository / API direct call）は禁止。

## bounded context（製造業 pack の例）
- **FA ドメイン**: 生産指示、進捗実績、設備稼働、ライン制御
- **調達ドメイン**: 発注、入荷、検収、仕入先マスタ
- **検査ドメイン**: 検査計画、検査結果、不良票、品質マスタ
- **共通モジュール（業界共通 Lv）**: 設備、ロット、品目、拠点、BOM
- 業界横断層: 通知、監査、承認 workflow、帳票、マスタ管理

## ドメイン間参照の規約
- **同ドメイン内**: 直接参照可（同 bounded context 内の aggregate / repository / service）
- **cross-domain 参照**: Domain Event 経由のみ
  - publisher: 状態変更時に Domain Event を Outbox に書込（atomic 三表書込）
  - subscriber: Apicurio Registry に登録された Avro schema を介して subscribe
  - 直接 repository / API call は CI で deny（依存方向検査）
- **業界横断層 ↔ 業界 pack**: 業界 pack → 業界横断層の単方向のみ（[業界拡張モデル](02_業界拡張モデル.md) 業界中立性の機械的担保 (2)）

## クリーンアーキテクチャの依存方向
- ドメイン層 → tier2 application 層 → tier1 Library 層
- ドメイン層から tier1 Library / Service への直接依存を禁止
- application 層が tier1 Library を介して infra にアクセス
- ドメイン層は pure domain logic（副作用なし）

## Domain Event の単一の真
- Domain Event の Avro schema は Apicurio Registry の git SoT（[apicurio_gitops_sot](../../04_詳細設計/03_クロスカッティング適合仕様/03_apicurio_gitops_sot.md)）
- Schema compatibility mode は FULL（双方向互換、24 ヶ月 deprecation）
- Domain Event の命名は `<industry>.<domain>.<event_name>`（[スキーマ進化適合仕様](../../04_詳細設計/01_適合仕様/06_スキーマ進化適合仕様.md) `aggregate_qualified_name` と整合）

## bounded context の追加 / 削除
- 新ドメインの追加は purely additive。既存ドメインの aggregate / Domain Event は変更しない
- ドメインの統合 / 分割は破壊的変更（major version up）として扱う
- ドメイン削除は 24 ヶ月 deprecation 後に実施（subscriber が長期 backlog を持つ可能性に対応）

## 採用しない設計
- cross-domain repository の直接参照
- 同 aggregate を複数ドメインで多重所有
- ドメイン層から tier1 Library / OSS の直接 import
- Domain Event を介さない cross-domain RPC
