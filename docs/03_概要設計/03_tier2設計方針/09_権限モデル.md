# tier2 権限モデル

## 一文方針
- 権限モデルは Keycloak ABAC（Attribute-Based Access Control）を tier2 が業務語彙でラップして提供。AuthContext の attribute（subject / tenant_id / purpose / delegation_chain）と aggregate / action の attribute を policy で組合わせる。Delegation / Emergency Override / impersonation chain は session attribute として 32 適合仕様の `session_context` と直交。

## ABAC 設計原則
- Authentication: Keycloak OIDC（[認証適合仕様](../../04_詳細設計/01_適合仕様/04_認証適合仕様.md)）
- Authorization: ABAC policy（subject_attribute × resource_attribute × action × context）
- subject 識別子は Keycloak subject（不可逆 ID、`sub` claim）
- tenant_id は AuthContext から取得（クライアントが任意の値を引数で渡せない）
- policy 評価は Backend-for-Library が一括で行う（tier2 業務 service は policy 結果のみ受領）

## tier2 が業務語彙でラップする attribute
- subject 側:
  - `subject.role`: 業務ロール（operator / supervisor / approver / admin）
  - `subject.tenant_id`: AuthContext から取得
  - `subject.delegation_chain`: 委譲元 user の配列（empty は通常操作）
- resource 側:
  - `resource.aggregate_class`: 業務 aggregate のクラス（PurchaseOrder / Inspection / Equipment 等）
  - `resource.tenant_id`: aggregate の所属 tenant
  - `resource.aggregate_id`: aggregate の識別子
- context 側:
  - `context.purpose`: business_op / support / export / migration / emergency
  - `context.action_class`: low_risk / medium_risk / high_risk

## action_class
- **low_risk**: read 系（GET / List / Search）
- **medium_risk**: write 系（Create / Update）、reversible
- **high_risk**: 業務的に重要 / irreversible（注文確定、検査結果確定、データ削除、cluster-admin 操作）
- step_up は high_risk action 直前に発動（[認証適合仕様](../../04_詳細設計/01_適合仕様/04_認証適合仕様.md) `v1_human_session` で `step_up_required: on_high_risk`）

## Delegation
- admin が user A を user B として代行する pattern
- AuthContext.delegation_chain に元 admin を append
- audit_event に元 admin と委譲先 user の両方を emit
- 32 適合仕様の `app.delegation_chain` GUC と同期

## Emergency Override（break-glass）
- `purpose='emergency'` で取得された `v1_emergency_step_up` auth_class
- always step_up: 取得時に必ず WebAuthn 等で再認証 + 理由文記入
- 通常権限を超える action（cluster-admin 操作 / 他 tenant の support 業務 等）が許容される
- audit_event に強制 emit、postmortem PR 起票必須

## impersonation chain
- 認証適合仕様の `impersonation_policy: scoped`（`v1_federated_exchange`）でのみ許容
- AuthContext.impersonation_chain で chain を保持
- SDK ユーザは impersonation を能動的に開始できない（権限の昇格は server 側 endpoint 経由のみ）

## policy 単一の真
- ABAC policy は YAML で宣言: `policies/<industry>/<domain>/<aggregate_class>.yaml`
- policy は git SoT、Argo CD + Keycloak Operator が reconcile
- policy への直接 write は禁止（admission policy `block-direct-keycloak-write`）

## 採用しない設計
- RBAC のみの単純権限（ABAC で attribute 組合せ）
- subject_id を業務 ID として漏洩（Keycloak `sub` のみ）
- クライアント側から tenant_id を任意に指定（AuthContext から取得）
- impersonation を SDK ユーザが能動的に開始
- emergency override の audit emit 省略
- 文章のみの権限ポリシー（必ず YAML + Keycloak）
