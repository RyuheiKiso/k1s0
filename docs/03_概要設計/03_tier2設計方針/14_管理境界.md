# tier2 管理境界

## 一文方針
- 業務 API（tier3 業務 UI 経由、日々の業務操作）と業務管理 API（admin、マスタ管理 / 監査検索 / 緊急対応）を物理的に分離する。業務管理 UI は Backstage プラグインに集約し、tier3 業務 UI に admin API を import する経路を CI で物理拒否（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 2）。

## 管理 API の分離
- 業務 API: `tier2.<pack>.<domain>.v<N>`（tier3 業務 UI 経由）
- 業務管理 API: `tier2.<pack>.admin.v<N>`（Backstage プラグイン経由のみ）
- proto package で物理分離、tier3 から admin proto package を import する経路を CI deny

## 運用 UI（Backstage プラグイン）
- マスタ管理 / 監査検索 / 緊急対応 / schedule 編集 / partner 連携設定は Backstage プラグインで提供
- Backstage は内部運営者向け（業務担当者ではない）
- tier3 業務 UI には admin 機能を載せない

## マスタ編集の workflow
- マスタ編集は admin API + Backstage プラグイン経由
- 全マスタ編集は audit_event に emit（actor_id / before / after）
- decision table 編集は decision table override layer + ZEN Engine（tier1 Rule Engine Library 経由）

## 決定表編集の workflow
- 決定表は YAML / Excel-like 表形式で記述
- Backstage プラグインで業務担当者が編集（PR 形式 + git レビュー）
- Apicurio GitOps SoT と同型（[apicurio_gitops_sot](../../04_詳細設計/03_クロスカッティング適合仕様/03_apicurio_gitops_sot.md)）の規律で git → Argo CD reconcile

## 監査検索 API
- audit signal SoR（ClickHouse）に対する SQL 検索 API
- Apache Superset で ad-hoc SQL（Backstage 経由）
- search_audit API は admin role 必須、`purpose='support'` で実行
- pgaudit が SELECT 自体も DB layer audit に記録（[テナント分離適合仕様](../../04_詳細設計/01_適合仕様/10_テナント分離適合仕様.md) `pii_segregated`）

## 緊急対応の経路
- emergency override は `v1_emergency_step_up` auth_class（[認証適合仕様](../../04_詳細設計/01_適合仕様/04_認証適合仕様.md)）
- always step_up: 取得時に必ず WebAuthn 等で再認証 + 理由文記入
- audit_event に強制 emit、postmortem PR 起票必須
- break-glass 操作は ops-edge cluster 経由

## プラットフォーム運営者と業務管理者の境界
- **プラットフォーム運営者**: infra / data / security / ops 軸の運用責務（cluster admin、KEK shamir custodian 等）
- **業務管理者**: tier2 admin API 経由のマスタ管理 / 決定表編集 / 監査検索（Backstage プラグイン）
- **業務担当者**: tier3 業務 UI で日々の業務操作

権限境界:
- プラットフォーム運営者は業務データを直接読まない（emergency override で `purpose='emergency'` のみ）
- 業務管理者は infra / data / security に直接アクセスしない
- 業務担当者は admin API を使えない

## tier3 の拡張点
- tier3 は admin API を import する経路を持たない
- 業務管理 UI 拡張は Backstage プラグイン extension point で表現
- 業務 UI と業務管理 UI の混在を CI で deny（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 2）

## 採用しない設計
- 業務 API と admin API の同 package
- tier3 業務 UI への admin 機能埋込
- 業務管理者による infra / data / security 直接アクセス
- emergency override の audit emit 省略
- 文章のみの権限境界（必ず CI / lint で物理 enforce）
