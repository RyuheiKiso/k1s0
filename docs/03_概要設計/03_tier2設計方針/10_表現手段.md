# tier2 業務資産表現手段

## 一文方針
- 業務資産は「コード（一般的な業務ロジック）/ Schema 駆動（多言語横断 / wire 一致が要るもの）/ DSL（業務ルール / 決定表）」の 3 表現手段に分類し、用途別に手段を固定する。codegen で重複削減 / 一貫性担保し、手書きと codegen 出力の混在を CI で fail。

## コード（一般的な業務ロジック）
- 業務 use case / aggregate behavior / Workflow handler は各言語で実装
- Rust / C# / Go / TypeScript の 4 言語、tier1 Library 経由
- domain logic は副作用を持たない（pure function）、application layer が tier1 Library を介して infra にアクセス
- 業務 service の境界は bounded context（[ドメイン分割方針](04_ドメイン分割方針.md)）

## Schema 駆動（多言語横断 / wire 一致が要るもの）
4+1 軸を `aggregate_qualified_name` 名前空間で束ねる:
- **proto**: tier1 03_Server 系 External / Internal Proto。RPC method / message
- **Avro**: Apicurio Registry の Domain Event payload schema
- **DDL**: PostgreSQL table schema（[テナント分離適合仕様](../../04_詳細設計/01_適合仕様/10_テナント分離適合仕様.md) 4 table class）
- **yaml**: feature flag / quota / SLO / 業界 pack 定義 / route_atlas 等
- **OTel SemConv**: tier2_ext attribute namespace（[観測適合仕様](../../04_詳細設計/01_適合仕様/03_観測適合仕様.md)）

詳細は [スキーマ進化適合仕様](../../04_詳細設計/01_適合仕様/06_スキーマ進化適合仕様.md) `schema_class` 6 種を参照。

## DSL（業務ルール / 決定表）
- 業務ルール（例: 検査基準、承認条件）は ZEN Engine 決定表 DSL（tier1 Rule Engine Library 経由）
- 決定表は YAML / Excel-like 表形式で記述、tier2 が業務語彙でラップ
- テナント別 override は decision table override layer で吸収

## codegen（重複削減 / 一貫性担保）
- proto → 各言語 stub（Buf workflow）
- proto → Avro schema（buf-for-apicurio plugin、業務 Domain Event 用）
- proto → DDL ヘッダ（aggregate_qualified_name から table 名 / 列名導出）
- proto → SemConv attribute schema（OpenTelemetry Weaver で各言語定数生成）
- generated code は git 管理しない（CI 都度生成）
- 同 input → 同 output bit hash（reproducibility）

## 「コード or DSL」の選択基準
- **コード採用条件**: 業務ロジックが pure function で表現可能、副作用が 1 aggregate に閉じる、変更頻度が低い
- **DSL 採用条件**: 業務ルールがテナント別に頻繁に変わる、業務担当者が直接編集したい、決定表として表形式で表現可能
- **混在禁止**: 同一業務ルールをコードと DSL の両方で表現する経路を持たない

## ドキュメント生成
- proto / Avro / DDL / yaml / SemConv の宣言から MkDocs Material で API ドキュメント自動生成
- Backstage TechDocs plugin で tier2 / tier3 が tech docs として参照
- 手書き API ドキュメントは禁止（生成元の宣言が単一の真）

## 採用しない設計
- 手書き codegen 出力（generated code を git 管理）
- 同一業務ルールのコード / DSL 重複
- proto を介さない wire 仕様（必ず proto から派生）
- aggregate_qualified_name の片寄せ（proto を権威 / DDL を権威 のような）
