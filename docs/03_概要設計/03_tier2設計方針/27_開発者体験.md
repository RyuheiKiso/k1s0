# tier2 開発者体験

## 一文方針
- tier2 業務エンジニアの inner loop は Tilt + tier1 Companion local mock + dev container + Pact contract test + Testcontainers integration test で構成。Backstage Software Template で tier2 リポジトリ生成時点で 8 層強制機構を自動組込、業務エンジニアは業務 use case 実装に集中できる。

## inner loop
- **Tilt**: K8s ローカル開発、業務 use case の hot-reload
- **tier1 Companion local mock**: tier1 Server に接続せず tier2 業務 service を local 開発
- **dev container**: VS Code Remote Containers / GitHub Codespaces、4 言語 toolchain 完備

## 開発者ポータル（Backstage）
- service catalog: 各 tier2 業務 service を component 登録
- Software Template: 「新業務 service を作る」「新 aggregate を作る」「新 Domain Event を追加する」 template
- TechDocs: tier2 公開 API ドキュメント自動生成

## CI inner loop
- proto / Avro schema 変更 → buf generate → tier2 build → Pact contract test → Testcontainers integration test → property based test
- inner loop time budget:
  - schema 変更 → codegen: ≤ 10s
  - tier2 service build: ≤ 30s
  - 全 contract test: ≤ 5min
  - Testcontainers integration test: ≤ 10min

## ChatOps
- Mattermost slash command で tier2 admin API 操作
- マスタ編集 / 決定表編集 / break-glass token 発行
- 全操作を audit emit

## オンボーディング（業務エンジニア向け）
- 1 day onboarding（Backstage Software Template + dev container）
- 業務エンジニアは業務 use case 実装に集中、強制機構は template 自動組込

## 採用しない設計
- 商用 internal developer portal（Cortex / OpsLevel 商用 / Roadie SaaS）
- 商用 SaaS test platform
- AGPL-3 OSS（Grafana / Tempo / Loki / k6）
