# tier2 業務エラー監査コンプライアンス

## 一文方針
- 業務エラー / Domain Event / 監査エントリは「いつ・誰が・何をした」の事後追跡を技術 telemetry と統一的に解析可能にする。aggregate 状態変更は必ず Domain Event を emit する経路に乗る。State change / Outbox / Audit を同一 DB トランザクションで atomic に書く（subscribe 失敗で audit が欠落する事故を構造的に不可能化）。

## 業務イベント emit 必須化
- aggregate 状態変更は必ず Domain Event を emit する経路に乗る
- emit を抑制する API（raw SQL 実行等）を tier2 公開 API に置かない
- atomic 三表書込で State change + Outbox + Audit を同一トランザクションに書く（[テナント分離適合仕様](../../04_詳細設計/01_適合仕様/10_テナント分離適合仕様.md)）

## audit_local schema
- `audit_local` は tier2 が提供する monolithic audit table（PII 不在）
- カラム:
  - `id`, `tenant_id`, `actor_id`, `purpose`, `operation`, `aggregate_type`, `aggregate_id`, `business_event`, `before`, `after`, `created_at`, `trace_id`
  - hash chain: `hash_prev`, `hash_self`（cryptographic chaining）
- PII は構造的に含まれない（schema レベルで物理拒否）

## hash chain
- 各 audit_event に対し `hash_self = SHA256(hash_prev || canonicalize(audit_event))` を計算
- 年次 root（tenant 別）に `v1_audit_root_signing` 鍵で署名し、外部公証（RFC 3161 trusted timestamp + Sigstore transparency log）に提出
- chain divergence は alert + page

## audit signal の SoR
- audit signal の SoR は ClickHouse `audit` table（[観測適合仕様](../../04_詳細設計/01_適合仕様/03_観測適合仕様.md) 5 signal class）
- audit relay が `audit_local` → ClickHouse に転送（at-least-once + ReplacingMergeTree で idempotent）
- ClickHouse 側で hash chain を再検証

## audit ingest gap monitor
- audit_event hash chain の「書かれた行同士の改竄検知」しか保証できない（ingest 段の loss は chain に現れない）
- ingest pipeline の gap / drop を別経路で検出: heartbeat insert + gap monitor（[audit_ingest_gap_monitor](../../04_詳細設計/03_クロスカッティング適合仕様/09_audit_ingest_gap_monitor.md)）

## PII 取扱
- `audit_local` には PII を含めない（schema レベルで物理拒否）
- actor 識別子は Keycloak subject（不可逆 ID、`sub` claim）のみ
- 氏名 / メール / 電話 / 端末 ID は audit signal に出さない
- Domain Event payload に PII を含む場合は Apicurio Registry の Avro schema で `field_pii` annotation を付与し、Outbox 投入時に redact

## emergency override / break-glass
- `purpose='emergency'` で実行された操作は audit_event に強制 emit
- break-glass は 09_鍵管理適合仕様 `v1_emergency_step_up` auth_class と連動
- postmortem PR 起票必須

## 採用しない設計
- audit_event の sampling
- audit_event の logical delete（crypto-erase 経路のみ）
- 単一経路 emit（必ず atomic 三表書込）
- raw SQL 経由の状態変更（Domain Event emit を抑制する API は提供しない）
- audit_local schema に PII 列追加
