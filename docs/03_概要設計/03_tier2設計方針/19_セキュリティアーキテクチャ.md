# tier2 セキュリティアーキテクチャ

## 一文方針
- 脅威モデルは [脅威モデル適合仕様](../../04_詳細設計/01_適合仕様/15_脅威モデル適合仕様.md) 5⁴ cell の business surface を tier2 が単一所有。8 secret class lifecycle / 5 検知経路 / sample 不可な audit / KEK shamir M-of-N / 暗号アジリティ で物理 enforce、ペネトレーションテストは年次 + 自動 CVE 配信 + Renovate の三重化必須。

## 脅威モデル（Threat Model）の対象
- 5 actor class × 5 capability × 5 surface × 5 asset × 5 mitigation = 625 cell の cross-product（[脅威モデル適合仕様](../../04_詳細設計/01_適合仕様/15_脅威モデル適合仕様.md)）
- tier2 が business surface（north-south / east-west / persistence）の所有者
- mitigation pointer は物理機構経路完備（textual cap 5%、boundary section cap 0%）

## 主要脅威と緩和策
- **テナント越境**: PostgreSQL RLS FORCE + atomic 三表書込 + cross-tenant integration test（[テナント分離適合仕様](../../04_詳細設計/01_適合仕様/10_テナント分離適合仕様.md)）
- **PII 漏洩**: pii_segregated table + envelope encryption + KEK shamir 分散 + crypto-shred（[鍵管理適合仕様](../../04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md)）
- **認可 bypass**: Keycloak ABAC + Backend-for-Library 一括評価 + RLS FORCE 二重 enforce
- **audit 改竄**: hash chain + 外部公証 attestation + WORM Object Lock
- **token 漏洩**: BFF auth-edge + DPoP + httpOnly cookie + access_token getter ゼロ
- **supply chain**: Cosign + SBOM + SLSA L3+ + reviewer dual sign-off

## 脆弱性管理
- 5 検知経路（image scan / dep audit / SAST / IaC / 自社発見）
- patch SLO: critical 72h / high 7d / medium 30d / low 90d
- Trivy + Grype double-bound（severity escalation 規律）
- Renovate で日次 dependency update PR

## Secret rotation
- 8 secret class（authn token / api key / db password / kek / dek / tls / signing / ssh）の rotation cadence 物理 enforce
- OpenBao Transit lease ベース短期発行
- Secret rotation は Argo Workflows + cert-manager + External Secrets Operator で自動

## 暗号アジリティ（Cryptographic Agility）
- 暗号 algorithm の変更は KEK rotation cadence と同期
- 1.0.0: AES-256-GCM / Ed25519 / RSA-4096
- post-quantum 対応は v2 候補（NIST 標準確定後）

## ペネトレーションテスト
- 年次 + 自動 CVE 配信 + Renovate の三重化必須
- 商用 PenTest 結果のみで脆弱性管理を完了させない
- red team drill / black box test を Backstage 経由で記録

## サポート用アクセス
- `purpose='support'` で取得された `v1_human_session` auth_class
- pii_segregated への support engineer access は audit_local + pgaudit + 上長承認 workflow
- emergency override は `v1_emergency_step_up`、always step_up

## tier3 / テナントの拡張点
- tier3 は CSP / セキュリティヘッダ宣言 + axe-core a11y 検査（[tier3 強制機構](../../04_詳細設計/02_強制機構/03_tier3強制機構.md) 層 11）
- テナントは ABAC policy override（業界固有 / テナント固有 Lv のみ）

## 1.0.0 出荷時の対応範囲
- 製造業 pack の脅威 catalog 完備（5⁴ cell の reachable mitigation pointer ≥ 1）
- 全 tier2 業務 service の脆弱性スキャン日次
- ペネトレーションテスト 1.0.0 ship 前に少なくとも 1 回完了

## 採用しない設計
- 文章 only の脅威モデル
- mitigation の文章記述（必ず物理機構 pointer）
- 「現実には起こりにくいから登録しない」
- 単一 SAST tool 依存
- 商用 PenTest 結果のみで脆弱性管理を完了
- AGPL / SSPL 系 OSS の業務資産配信
- LLM 単独 sign-off / 単一 reviewer sign-off / PR author の self-review
