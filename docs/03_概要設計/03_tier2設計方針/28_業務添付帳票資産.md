# tier2 業務添付帳票資産

## 一文方針
- 業務添付ファイル（業務写真 / 検査証跡 / 図面 / 注文書 PDF 等）と帳票（PDF / 印刷向け）は tier1 Object Storage Library（Rook+Ceph RGW、S3 wire 互換）経由で保管、AES-256-GCM application-layer envelope 暗号化 + retention policy + crypto-shred 互換で物理 enforce する。

## 業務添付ファイル
- **保管先**: tier1 Object Storage Library 経由（Rook+Ceph RGW）
- **暗号化**: AES-256-GCM application-layer envelope（DEK = `v1_data_dek`、KEK = `v1_data_kek`）
- **MIME type validation**: 業務 use case 別の許可 MIME type allowlist
- **virus scan**: アップロード時に必須（tier1 経由）
- **メタデータ**: aggregate_id / actor_id / uploaded_at / file_size / content_type / hash を tier2 entity に保管

## ダウンロード経路
- tier1 Object Storage Library で signed URL 生成（短期 TTL）
- tier3 業務 UI から signed URL 経由で取得
- Content-Disposition header + sandbox iframe で開く

## 帳票（PDF / 印刷向け）
- 帳票テンプレートは tier2 が所有（ドメインごと）
- 帳票生成は tier2 業務 service で行い、Object Storage に保管
- レイアウトは tier3 で override 可能（[tier2 業務資産所有権](06_業務資産所有権.md)）

## retention policy
- 業務添付 / 帳票の retention は [データ保持](17_データ保持.md) カテゴリ別に固定
- 業務 entity 関連: 7 年 + 規制要件次第
- audit 関連: 10 年（規制要件）

## crypto-shred 互換
- 添付 / 帳票本体は AES-256-GCM 暗号化、KEK destroy で当該 tenant の wrapped DEK を不可逆失効
- Object Storage 上の暗号文は immutable archive（Ceph RGW Object Lock Compliance mode）

## tier3 拡張点
- 帳票レイアウトは tier3 で override 可能
- 添付ファイルの業務 use case 別 MIME type allowlist 追加は tier3 / テナント運用責任

## 採用しない設計
- 添付 / 帳票本体を tier2 entity table に直接保管（必ず Object Storage 経由）
- 暗号化なしの添付 / 帳票保管
- retention policy なしの長期保管
- KEK shamir なしの DEK 単独保管
