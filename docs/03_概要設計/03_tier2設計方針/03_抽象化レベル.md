# tier2 業務抽象化レベル

## 一文方針
- tier2 の業務資産・API はカテゴリごとに到達可能な抽象化レベルが異なる。一律に「業界横断」を要求すると業界固有のセマンティクスが業務ロジックに染み出すカテゴリで Library に乗らない結論になり、tier3 が業界固有概念を独自に再実装する抜け穴を生む。tier2 は 4 段階の Lv を認め、カテゴリごとに到達目標を割り当てる。

## 4 レベル定義

### Lv 業界横断（Cross-industry）
- 業界に依存しない業務語彙・業務資産
- 想定対象: 通知（メール / SMS / push）、監査ログ、承認 workflow、帳票生成、マスタ管理、ユーザー / 組織管理、テナント識別子伝播 等
- 受け入れ基準: 第二業界 stub からも同型 API で素直に消費可能であること（[業界拡張モデル](02_業界拡張モデル.md) 業界中立性の機械的担保 (3)）
- 命名・依存規約: 業界固有語の出現を CI で禁止。業界 pack への依存を CI で禁止

### Lv 業界共通（Industry-common）
- 業界 pack 内で複数ドメインに共通する業務語彙
- 想定対象（製造業）: 「設備」「ロット」「品目」「拠点」「BOM」等の業界基幹概念。FA / 調達 / 検査 各ドメインから参照される
- 受け入れ基準: 業界 pack 内のすべてのドメインから業務ロジックの再設計なしに参照可能
- 配置: 業界 pack 内の共通モジュール（例: `manufacturing/common`）に置く。業界横断層には置かない

### Lv 業界固有（Industry-specific / per-domain）
- 業界 pack 内の特定ドメインに固有の業務語彙
- 想定対象（製造業）: FA ドメインの「生産指示」「進捗実績」、調達ドメインの「発注」「検収」、検査ドメインの「検査計画」「不良票」等
- 受け入れ基準: 当該ドメイン内で完結すること。他ドメインへの依存被参照は Domain Event 経由に限定（直接参照は禁止）

### Lv テナント固有（Tenant-specific）
- テナントごとに差分が発生する業務資産
- 想定対象: テナント別マスタ値、テナント別承認規則、テナント別権限ロール定義、テナント別業務ルール（決定表）等
- 受け入れ基準: tier2 / tier3 の業務コードを変更せずに差分を吸収できること。差分の表現手段は override / 設定 / マスタデータに限定
- tier2 はテナント差分の格納と評価機構を提供し、差分そのものは保持しない（差分はテナントの運用責任）

## レベル昇格・降格
- **業界横断 → 業界共通への降格**: stub conformance を満たさない API は降格、tier2 の major version up として扱う
- **業界共通 → 業界固有への降格**: 業界 pack 内の複数ドメインから参照されなくなった API は降格
- **業界固有 → 業界共通への昇格**: 複数ドメインからの参照が発生した時点で昇格を検討。昇格時は業界固有のセマンティクスが残っていないかを精査
- **業界共通 → 業界横断への昇格**: 第二業界 stub で同型シナリオが green になることを示せた時点で昇格を検討。stub 検査が通らなければ昇格しない

## 1.0.0 出荷時の各レベル充足状況
- **Lv 業界横断**: 1.0.0 で実装、stub conformance を CI で強制
- **Lv 業界共通**: 製造業 pack の共通モジュールとして実装
- **Lv 業界固有**: 製造業 pack の各ドメイン（FA / 調達 / 検査）として実装
- **Lv テナント固有**: 機構（差分格納・評価）のみ tier2 が提供。差分そのものは tier3 / テナント運用責任

## 各レベルでの override 拡張点
- tier3 は [業務資産所有権](06_業務資産所有権.md) で定める拡張点を通じて override
- override の許容範囲は Lv ごとに異なる（業界横断 / 業界共通 Lv の不変条件は override 不可、業界固有 / テナント固有 Lv は override 可）
