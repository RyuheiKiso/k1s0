# tier2 信頼性 / 運用準備（DR / SLO / Workflow 運用 / 障害対応）

## 一文方針
- DR / SLO / Workflow 運用 / 障害対応は文章運用ではなく、tier1 SLO 適合仕様 + ops 運用ループ適合仕様 + Litmus chaos drill + ops-edge cluster の物理機構に転写。「波及確率 5% 以下抑制 + 5 min 自動昇格」の honest な SLO 表現を採用（[SLO_protection_layers](../../04_詳細設計/03_クロスカッティング適合仕様/05_SLO_protection_layers.md) と整合）。

## DR / BCP（災害復旧 / 事業継続）
- preservation_class（[データ保全適合仕様](../../04_詳細設計/01_適合仕様/14_データ保全適合仕様.md) 5 class）に従う:
  - `v1_zone_replicated`: default、RTO 60s / RPO 0
  - `v1_cluster_replicated`: 複数 cluster 跨ぎ、RPO ≈ 0
  - `v1_cross_region_replicated`: cross-region、RPO ≈ 0（partition 中 commit block）
- restore_drill: drill_cadence_days 以内に必ず実演（Litmus chaos test）
- audit / Outbox は preservation_class minimum `v1_zone_replicated`（10 年保持要件）

## SLO / SLA フレームワーク
- tier1 SLO 適合仕様 6 slo_class を採用:
  - `v1_request_availability`: 99.9% / 30d
  - `v1_request_latency_p99`: p99 ≤ class.target / 30d
  - `v1_event_freshness`: p95 ≤ class.target / 7d
  - `v1_workflow_completion`: 99.5% / 30d
  - `v1_data_durability`: 11n + freeze_on_any_loss / 365d
- error budget は物理 enforcement（Kyverno admission policy で deploy 物理 freeze）
- MWMBR alert（multi-window multi-burn-rate）で false positive 抑制

## アラート方針
- ops 軸 11_運用ループ適合仕様 5 severity:
  - `observe` / `notify` / `page` / `freeze` / `security_bridge`
- page-level alert は 1:1 runbook coverage
- noise budget ≤ 5% false positive、≤ 1% false negative
- 二段 escalation: 自製 escalation engine + ops-edge cluster

## キャパシティプランニング
- tier1 テナント容量適合仕様 5 quota_class（[テナント容量適合仕様](../../04_詳細設計/01_適合仕様/09_テナント容量適合仕様.md)）
- 共有 Pod / DB の SLO 保護四層 + 自動昇格（[SLO_protection_layers](../../04_詳細設計/03_クロスカッティング適合仕様/05_SLO_protection_layers.md)）
- KEDA + Cluster Autoscaler で需要追従

## Workflow 運用
- Temporal Workflow / Saga（[tier1 提供機能カテゴリ](../02_tier1設計方針/04_提供機能カテゴリ.md) Workflow L1+）
- 補償処理は Workflow 定義で明示
- timeout / cancellation policy は Activity で表現
- Workflow visibility は Backstage プラグインで業務管理者が確認

## インシデント response runbook
- ops 軸 5 incident class × 6 phase lifecycle（detect / triage / mitigate / resolve / postmortem）
- runbook 5 class（alert / incident / break_glass / drill / change）の Backstage TechDocs + Tekton Pipeline 二段構え
- IR command roles: IC / CL / SME / scribe の 4 役割

## Post-incident review（事後レビュー）
- 全 incident（severity = notify 以上）に postmortem PR
- 6 必須 section（Summary / Timeline / RCA / Mitigation / Action Items / Metrics）
- 72h open SLA + 14d merged SLA
- blameless 原則 + Semgrep custom rule で文体 lint

## 1.0.0 出荷時の対応範囲
- 製造業 pack の業務 SLO target 確定
- 全業務 critical RPC の MWMBR alert 配備
- 業務担当者向け runbook（基本操作 / 緊急対応）の 1.0.0 完備

## 採用しない設計
- 文章のみの SLO 記述
- 単窓 alert（MWMBR 必須）
- noise > 5% の alert 配備
- runbook なしの page-level alert
- postmortem 省略 / blameful postmortem
- emergency override の audit emit 省略
