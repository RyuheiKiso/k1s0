# tier2 業務 entity の状態遷移パターン

## 一文方針
- aggregate の状態遷移は型レベルで不正遷移を防止する。Rust phantom type / C# sealed record + Roslyn analyzer / TypeScript branded type + ESLint custom rule / Go typestate via nominal types（`protoc-gen-k1s0-go-fsm`）の 4 言語等価強度で物理 enforce する。Domain Event は遷移ごとに必ず emit、補償処理は Saga / Workflow で表現。

## 標準ライフサイクル
- 業務 entity（aggregate）は明示的なライフサイクル状態を持つ:
  - `Draft` / `Confirmed` / `InProgress` / `Completed` / `Cancelled` / `Archived`
- 状態は proto enum で定義、aggregate_qualified_name で命名

## 状態機械の実装規約
- 各状態は別 concrete type として表現
- 許可された遷移のみ method として生やす（不正遷移は compile fail）
- 詳細は [protoc-gen-go FSM](../../04_詳細設計/03_クロスカッティング適合仕様/04_protoc_gen_go_fsm.md) を参照

### 4 言語等価強度
- **Rust**: phantom type + sealed trait（compile-time bypass 不可）
- **C# (.NET 8+)**: sealed record + phantom type parameter + Roslyn analyzer（compile-time + analyzer）
- **TypeScript**: branded type（intersection with unique symbol）+ phantom type parameter + ESLint custom rule（compile-time + lint）
- **Go**: 状態別 concrete struct + package-internal sealed interface（unexported method による sealed）+ golangci-lint forbidigo + property based test（typestate via nominal types）

## Domain Event 命名標準
- 命名: `<aggregate_qualified_name>.<event_name>.v<N>`（例: `manufacturing.procurement.purchase_order.confirmed.v1`）
- 状態遷移ごとに必ず Domain Event emit（aggregate.before / aggregate.after を payload に含む）
- Apicurio Registry の Avro schema として登録（[apicurio_gitops_sot](../../04_詳細設計/03_クロスカッティング適合仕様/03_apicurio_gitops_sot.md)）

## 監査履歴の残し方
- 各状態遷移は audit_local に記録（actor_id / before / after / timestamp / trace_id）
- atomic 三表書込（State change + Outbox + Audit を同一トランザクション、[テナント分離適合仕様](../../04_詳細設計/01_適合仕様/10_テナント分離適合仕様.md)）

## 補償処理（Saga / Workflow）
- 多 aggregate / 多 service にまたがる業務処理は Temporal Workflow + Saga pattern
- 補償処理は Workflow 定義で明示
- failure mode は Workflow Activity の retry policy と Saga 補償で表現
- 業務コードからは Workflow handler のみが見える

## 状態遷移の override 拡張点
- aggregate ライフサイクルの基本遷移は tier2 が所有（override 不可）
- ただし状態遷移後の hook（pre / post）は tier3 override 可能（[業務資産所有権](06_業務資産所有権.md) 拡張点）

## 製造業 pack の適用例
- `purchase_order`: Draft → Confirmed → InProgress → Completed / Cancelled
- `inspection`: Planned → InProgress → Completed → Approved / Rejected
- `production_order`: Scheduled → InProgress → Completed / Cancelled

## 状態遷移以外のパターン
- 非状態遷移操作（read、update of non-state field）は通常の repository update
- ただし audit emit は同様に強制

## 採用しない設計
- runtime guard のみによる不正遷移防止（必ず compile-time 検査）
- Domain Event emit を抑制する API
- atomic 三表書込なしの状態変更
- ライフサイクル基本遷移の tier3 override
