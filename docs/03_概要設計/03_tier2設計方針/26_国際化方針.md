# tier2 国際化方針

## 一文方針
- tier2 は業務語彙の i18n key 管理 + locale-aware 数値 / 日付 / 通貨 / 単位フォーマット + UTF-8 統一 + timezone（ユーザ設定 + tenant default）を業務資産として所有する。1.0.0 で日本語 / 英語 ship、追加 locale は purely additive。

## i18n 対象
- 業務エラーメッセージ（BusinessConflict subtype 4 種 + ValidationError + DomainError）
- 業務イベント通知メッセージ（Domain Event 別）
- 業界横断 / 業界共通 / 業界固有のマスタ表示名（pack ごとに locale ファイル）
- 帳票テンプレート（PDF / 印刷向け）
- 通知テンプレート（メール / SMS / push）

## i18n 規律
- 翻訳キーは `t('xxx.yyy.zzz')` 形式（aggregate_qualified_name と整合）
- locale ファイル（JSON / YAML）を git 管理
- 未定義キー / 未使用キーを CI で検出
- pseudolocalization での文字長変動検出を CI 必須化

## locale-aware フォーマット
- 数値 / 日付 / 通貨 / 単位は `Intl.NumberFormat` / `Intl.DateTimeFormat`（client）または同等の言語別 library
- ICU library（C# / Java / .NET / Rust）で同型処理
- timezone はユーザ設定 + tenant default、UTC 内部保持

## tier3 拡張点
- tier3 が override で業務 UI 別の翻訳追加可能
- 業務語彙の翻訳キー命名は tier2 が単一の真

## 1.0.0 出荷 locale
- 日本語（ja-JP）
- 英語（en-US）

## v2 候補 locale
- 中国語（zh-CN / zh-TW）
- 韓国語（ko-KR）
- フランス語（fr-FR）/ ドイツ語（de-DE）等
- RTL 対応（アラビア語 / ヘブライ語）は v2 候補

## 受入条件
- 翻訳キー未定義参照ゼロ
- pseudolocalization テスト green
- 1.0.0 で日本語 / 英語 完備
- 数値 / 日付 / 通貨 / 単位の locale-aware フォーマット動作
