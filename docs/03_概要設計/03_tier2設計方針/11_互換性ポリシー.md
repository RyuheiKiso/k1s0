# tier2 互換性ポリシー

## 一文方針
- 1.0.0 完璧主義（CLAUDE.md）との整合のもと、tier2 は SemVer + 並行バージョン提供 + 移行コミットメントの 3 機構で互換性を物理 enforce。tier3 が tier2 のバージョンアップで silently 壊れない contract を CI で検証する。

## 1.0.0 完璧主義との整合
- 段階的 release を採らず、1.0.0 で全機能を完備
- 1.0.0 後の MINOR up は purely additive のみ
- 既存 API の signature 変更 / 削除は MAJOR up で deprecation_window 経由

## SemVer の運用
- MAJOR.MINOR.PATCH（SemVer 2.0.0）
- MAJOR up: 破壊的変更（拡張点 signature 変更 / 不変条件強化 / 4 抽象化レベルでの降格）
- MINOR up: purely additive（新 use case / 新拡張点 / 新 schema field optional 追加）
- PATCH up: バグ修正のみ

## 並行バージョン提供
- MAJOR up 時は旧 MAJOR と新 MAJOR を並行提供（180 日 deprecation_window）
- tier2 Service は両 version で並行 deploy（Kafka / Database / Schema Registry も並行）
- tier3 は段階的に新 version に移行
- 旧 MAJOR の sunset は deprecation_window 経過後

## tier2 移行コミットメント（major version up 時）
- tier1 L1+ 移行コミットメントと同枠（[移行 Pair 適合仕様](../../04_詳細設計/01_適合仕様/02_移行Pair適合仕様.md)）
- 提供する toolchain:
  - schema diff（旧 MAJOR / 新 MAJOR の proto / Avro / DDL 差分）
  - 業務コード移行 codemod（tier3 の override 部に対する自動修正提案）
  - dual-write 移行支援（旧 MAJOR / 新 MAJOR の両 backend に二重書込）
  - observability 連続性（trace_id / span 名の意味論維持）
  - 業務コード移行ガイド（拡張点ごとの修正点チェックリスト）
- toolchain は tier2 リポジトリで継続的に維持、年次 dry-run で green を CI で検証

## 業界横断 Lv の降格 / 業界 pack 統合 / 削除
- stub conformance を満たさない業界横断 API は業界共通 Lv に降格（major version up）
- 業界 pack 内で複数ドメイン参照されなくなった API は業界固有に降格
- API 削除は 24 ヶ月 deprecation 後

## 拡張点 contract の安定性
- 拡張点 signature の追加は purely additive
- 拡張点 signature の変更 / 削除は 24 ヶ月 deprecation + 移行 codemod 必須
- invariants の強化（追加）は tier3 側 contract test fail で検出 → tier3 修正が必須
- invariants の緩和（削除）は purely additive

## tier1 のバージョン追従
- tier1 minor up: tier2 は purely additive 範囲で吸収、tier3 への伝播なし
- tier1 major up: tier2 は移行 toolchain を提供、tier3 への影響範囲は L1+ 露出概念一覧に従う

## 監査 / コンプライアンス観点での bumping 制約
- audit_event schema の MAJOR up は 24 ヶ月 deprecation + 並行 emit（旧 schema / 新 schema）
- crypto-shred 機構の MAJOR up は KEK rotation cadence と同期
- 規制対応（GDPR 等）の deadline は MAJOR up cadence と独立に最優先

## 採用しない設計
- 段階的 release（1.0.0 完璧主義）
- 1.0.0 後の MINOR up での破壊的変更
- deprecation_window 短縮（180 日 minimum）
- toolchain なしの MAJOR up
- tier3 への silently 破壊的変更
