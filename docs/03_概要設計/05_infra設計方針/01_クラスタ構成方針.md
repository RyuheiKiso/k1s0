# infra クラスタ構成方針

## 一文方針
- cluster は topology_class（[クラスタ位相適合仕様](../../04_詳細設計/01_適合仕様/12_クラスタ位相適合仕様.md)）の宣言で形が決まり、OpenTofu で IaC 化、Argo CD で配信される。手動操作で構築・変更する経路は持たない。

## 至高路線における立ち位置
- hand-rolled cluster bootstrap 禁止、OpenTofu / kubeadm / cluster-api のいずれかに固定
- 単一 zone での本番運用禁止（v1_single_zone は dev/stage 専用）
- mixed-version cluster 長期運用禁止（minor version skew ≤ 1、upgrade window ≤ 30 日）
- GUI 操作による cluster 構築 / 廃棄禁止（Headlamp / Backstage は読み取り / 限定的 trigger 専用）

## ノードタイプ

### control plane node
- kube-apiserver / etcd / kube-controller-manager / kube-scheduler を hosting
- 最小 3 台、奇数（quorum 維持）
- kube-vip + Layer2 / BGP で control plane VIP 提供
- workload は taint で排除（`node-role.kubernetes.io/control-plane:NoSchedule`）

### worker node
- tier1 / tier2 / tier3 / data の Pod を hosting
- topology_spread_constraints で zone 跨ぎ均等配置
- kubelet eviction policy で node 障害時に Pod を他 node へ migrate

### infra-tools node（オプション）
- Argo CD / Argo Rollouts / Argo Events / Kyverno / cert-manager / OpenBao / Litmus を hosting
- taint: `infra-tools=true:NoSchedule`
- tier 各層の Pod が混入しないよう物理隔離

### storage node（二系統に物理分離）
- **storage-ceph node**（Rook+Ceph 専用）:
    - OSD / monitor / RGW / CephFS MDS を hosting
    - taint: `storage-ceph=true:NoSchedule`
    - device path は Ceph 専用に固定（`bluestore` 用 raw partition、CRUSH map で zone 跨ぎ配置）
- **storage-longhorn node**（Longhorn 専用）:
    - Longhorn replica engine / instance manager を hosting
    - taint: `storage-longhorn=true:NoSchedule`
    - device path は Longhorn 専用に固定（`/var/lib/longhorn` mount を独立 disk に置き、Ceph と device 競合しない）
- 両系統の混在禁止

## etcd 構成
- control plane node 上に co-locate（kubeadm default）または external etcd cluster の二択
- v1 では co-locate を default、v2 で external 候補
- quorum 維持: minimum 3 node、推奨 5 node
- WAL / data dir は local SSD（NVMe 推奨）、Ceph PV は使用しない（latency 観点）
- snapshot は cron で 1 時間ごと、object storage（Ceph RGW）に転送

## Pod 配置原則

### 全 Deployment / StatefulSet 必須
- `topology_spread_constraints`（layer A: compile）:
    - `topologyKey: topology.kubernetes.io/zone`
    - `whenUnsatisfiable: DoNotSchedule`
    - `maxSkew: 1`
- `PodDisruptionBudget`（layer A: compile）:
    - `minAvailable: ⌈replicas × 2/3⌉` または `maxUnavailable: 1`（StatefulSet）

### Affinity / Anti-Affinity
- tier1 Server / tier2 Service: node anti-affinity で同 node に同 pod を避ける
- data 層 Pod: zone anti-affinity で zone 跨ぎ replica

### Priority Class
- system-critical（control plane / cni / csi）
- infra-critical（Argo CD / Kyverno / cert-manager）
- business-high / business-default / business-batch
- dev-best-effort

## namespace 規約
- 階層的 namespace（Hierarchical Namespace Controller / HNC）で tier1 / tier2 / tier3 / infra-tools を root とした構造
- namespace 間通信は NetworkPolicy で default deny

## upgrade 規律
- Kubernetes minor version skew は ≤ 1（cluster 内 / cluster 間）
- upgrade window は ≤ 30 日
- 長期 mixed-version 運用は dead spec として CI fail

## 強制機構との bind
- 本方針は [infra 強制機構](../../04_詳細設計/02_強制機構/04_infra強制機構.md) の以下経路で物理 enforce される:
    - 層 A: kustomize build / helm lint / kubeval
    - 層 B: Conftest による topology_class / topology_spread / PDB 注釈必須 check
    - 層 D: Kyverno `require-topology-spread` `require-pdb` admission policy
    - 層 E: kubelet eviction / node taint の物理機構

## 採用しない方針
- hand-rolled cluster bootstrap: 禁止
- 単一 zone での本番運用: 禁止
- manual failover の本番採用: 禁止
- GUI 操作による cluster 構築 / 廃棄: 禁止
- mixed-version cluster 長期運用: 禁止
- cloud managed Kubernetes への hard dependency: 持たない（クラウド非依存）
