# infra セキュリティ方針

## 一文方針
- 5 段階防御（image / runtime / network / secret / policy）を全 cluster で必須化、Kyverno admission policy が物理 enforcement の最終 layer。

## 至高路線における立ち位置
- 文章 only の運用ルール禁止、全規律は機械検証可能な形で codify
- OPA Gatekeeper 採用しない（Kyverno L1+ 単一深耕）
- 商用 admission engine 採用しない
- Falco / Tetragon は runtime threat detection の L1+ として security 層所有
- security 軸の詳細は [security 設計方針](../07_security設計方針/README.md) 参照、本方針は infra 物理基盤 substrate

## 段階 1: image / supply chain
- registry: Harbor 一本、cluster からは Harbor のみ pull 可能
- signature: Cosign で signed、verify policy が Kyverno で必須
- SBOM: Syft で生成、Harbor に attach
- 脆弱性: Trivy + Grype を CI 必須、CVSS critical / high が残存する image は merge fail
- base image: distroless / chainguard images を default、full OS image は禁止
- build provenance（hermetic build / SLSA L3+ baseline / SLSA L4 target / 多重 builder consensus / runner image self-attestation）: [build_provenance 適合仕様](../../04_詳細設計/01_適合仕様/16_build_provenance適合仕様.md) が単一所有
- Kyverno と Conftest の責務分離:
    - Kyverno は cluster 段の deploy reject（admission webhook）
    - Conftest は PR 段の merge block（GitHub Actions Required Status Check）

## 段階 2: runtime
- Pod Security Standard: restricted profile を default、Kyverno で全 namespace に適用
- SELinux / AppArmor: node 上で enforcing mode、Kubernetes SecurityContext で default profile 強制
- read-only rootfs: Pod の rootfs は read-only、書き込み必要箇所は emptyDir / PV で明示的に mount
- capabilities: drop ALL を default、必要な capability は individual に grant
- hostPath / hostNetwork / hostPID: 禁止（Kyverno reject）。例外は Rook+Ceph / Longhorn / CNI / monitoring agent に限定、明示的 allowlist
- seccomp profile: RuntimeDefault を default、業務 Pod は custom profile を override 可能
- 特権 Pod: 禁止。Rook / Longhorn 等の例外は infra-tools namespace に限定

## 段階 3: network
- default deny NetworkPolicy: 全 namespace で必須（[ネットワーク方針](02_ネットワーク方針.md)）
- Istio mTLS STRICT: 全 mesh 内通信で mTLS 必須
- egress: cluster 外への egress は egress gateway 経由に限定、許可ドメインは Kustomize overlay で declarative 宣言
- ingress: Envoy Gateway 経由のみ。NodePort / LoadBalancer Service の直接公開は禁止

## 段階 4: secret
- secret 管理: OpenBao を SoT、Kubernetes Secret は External Secrets で同期した derived のみ
- secret rotation: cadence は [鍵管理適合仕様](../../04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md) の rotation policy に従う
- secret zero-trust: Pod に必要な secret のみ inject、cluster-wide secret は禁止
- HSM: production cluster の root CA / KEK は HSM（PKCS#11）に格納、OpenBao が PKCS#11 backend で interface

## 段階 5: policy（Kyverno admission policy）
- 全 admission policy は Kyverno で codify、infra build artifact から自動生成。手書き policy は CI fail
- 主要 policy（[infra 強制機構](../../04_詳細設計/02_強制機構/04_infra強制機構.md) で詳細）:
    1. image signature verification（Cosign）
    2. Pod Security Standard restricted enforcement
    3. NetworkPolicy default deny
    4. Istio mTLS STRICT
    5. topology_spread_constraints / PDB 必須
    6. quota_class / topology_class / preservation_class 注釈必須
    7. drill cadence violation block
    8. SLO error budget freeze block
    9. cve_backlog_threshold block
    10. dimension override 検出

## 認証 / 認可
- cluster RBAC: ServiceAccount + RoleBinding を default、User は Backstage 発行 OIDC token のみ
- kubectl 直接アクセス: break-glass 用途のみ、OpenBao response wrapping で短期 token 発行
- Kubernetes audit log: 全 cluster で full audit、ClickHouse に bulk insert（[security 監査方針](../07_security設計方針/05_監査方針.md) と整合）

## 監査 / インシデント
- 全 audit signal は [observability 適合仕様](../../04_詳細設計/01_適合仕様/03_観測適合仕様.md) の audit signal sub-class として ClickHouse に bulk insert
- infra 固有 audit signal:
    - `infra.cluster.create.event`
    - `infra.cluster.upgrade.event`
    - `infra.cluster.destroy.event`
    - `infra.topology.failover.event`
    - `infra.policy.violation.event`
    - `infra.secret.rotation.event`
    - `infra.image.unsigned.reject.event`

## ハードニング基準
- CIS Kubernetes Benchmark: 本番 cluster で適合必須、kube-bench で定期 scan
- CIS Docker Benchmark: build daemon（Buildkit）で docker-bench-security 適合必須、違反は admission block
- NSA/CISA Kubernetes Hardening Guidance: ガイドラインに従う
- SLSA: build pipeline は SLSA L3+ baseline / SLSA L4 target

## 強制機構との bind
- 本方針は [infra 強制機構](../../04_詳細設計/02_強制機構/04_infra強制機構.md) の以下経路で物理 enforce される:
    - 層 B: Conftest による全 admission policy build artifact 生成 check
    - 層 D: Kyverno admission webhook（25+ policy）
    - 層 E: kernel SELinux / AppArmor / seccomp + LUKS 物理機構

## 採用しない方針
- 文章 only の運用ルール: 禁止
- OPA Gatekeeper: Kyverno L1+ 単一深耕、横並びは持たない
- 商用 admission engine: 採用しない
