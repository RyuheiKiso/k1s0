# infra ネットワーク方針

## 一文方針
- L4 は MetalLB / kube-vip、L7 は Envoy Gateway / Istio で統一。multi-cluster / multi-region は Istio multi-primary mesh と external-dns で連結する。

## 至高路線における立ち位置
- service mesh の Linkerd / Cilium Service Mesh 採用しない（Istio L1+ 単一深耕、横並び mesh は採用しない）
- cluster 跨ぎ global rate limit は v2 候補
- cilium eBPF data plane / Cilium ServiceMesh は v2 候補
- v1_multi_zone_per_cluster で zone ≥ 3 必須（本番）

## CNI（Container Network Interface）
- L1+ primary: **Calico**（BGP mode）
- rationale:
    - eBPF data plane を選択肢として持ちつつ（Calico eBPF mode）、kernel-routing も併用可能
    - NetworkPolicy 完全実装
    - MetalLB BGP mode との相性
- v2 候補: Cilium（eBPF 専用、Istio ambient と組合せ）

## MetalLB（data plane LB）
- mode: 本番 cluster で BGP mode 必須、開発で Layer2 mode 許容
- BGP peer: cluster 外 router（ToR / spine / cloud BGP endpoint）と speaker Pod が peer
- IP プール: tier 別に分離（tier1-services / tier2-services / tier3-public / tier3-private / data-internal）
- v1_multi_cluster_active_active: 複数 cluster からの ECMP announcement、外部 router が anycast で受信

## kube-vip（control plane VIP）
- mode: BGP mode を default、Layer2 は dev のみ
- control plane の HA: kube-apiserver は port 6443 で listen、kube-vip が VIP を制御 plane node 間で float

## Istio service mesh
- data plane: sidecar mode（v1）、ambient mode（v2 候補）
- mTLS: PERMISSIVE で開始、3 ヶ月以内に STRICT へ強制。Kyverno admission policy で STRICT 維持を validate
- locality_lb_setting: zone / cluster / region 距離に応じた failover を [クラスタ位相適合仕様](../../04_詳細設計/01_適合仕様/12_クラスタ位相適合仕様.md) の topology_class に基づき自動設定
- root CA: cluster 単位の sub-CA、cluster 跨ぎ root は OpenBao が発行（[tier1/11 鍵管理適合仕様](../../04_詳細設計/01_適合仕様/05_鍵管理適合仕様.md)）
- multi-cluster: multi-primary mesh、共通 root CA、cross-cluster service discovery は Istio が担う

## Envoy Gateway
- role: tier1 Transport Adapter Layer の substrate
- 担当: HTTP/2 + gRPC / HTTP/3 plain / HTTP/3 + WebTransport / HTTP/1.1 Upgrade（WebSocket）/ HTTP/1.1 chunked + SSE
- rate limit: Local Rate Limit filter で [テナント容量適合仕様](../../04_詳細設計/01_適合仕様/09_テナント容量適合仕様.md) の v1_per_tenant_qps を enforcement。cluster 跨ぎ global rate limit は v2 候補
- JWT 認証: JWKS は Keycloak から取得、tenant_id を JWT claim から ingress filter で抽出
- TLS: cert-manager + Let's Encrypt / 内部 CA。TLS 1.3 必須、TLS 1.2 は legacy 経路（.NET Framework Companion）のみ許容、deprecation timeline は 12 ヶ月

## DNS
- cluster 内: CoreDNS（Kubernetes default）
- cluster 外: external-dns で cluster Service / Ingress を DNS provider（Route53 / Cloud DNS / 内部 BIND）に publish
- multi-region: `external_dns_multi_region` orchestrator が region 単位の health check + weight で routing

## NetworkPolicy
- default deny: 全 namespace で default deny ingress / egress を Kyverno admission policy で強制
- 通信許可:
    - tier1 ↔ tier2 ↔ tier3 の許可される通信を Kustomize overlay で declarative に宣言
    - data 層への通信は data-stores namespace への egress 許可で制限
    - infra-tools への通信は admin operator + Argo CD sync 経路のみ
- cluster 間通信: Istio multi-primary mesh で mTLS、source cluster の identity を destination 側で validate

## HTTP/3 + WebTransport
- HTTP/3 plain（QUIC + HTTP semantics）の Envoy Gateway listener は v1 本番必須。QUIC は UDP/443、firewall で許可
- WebTransport over HTTP/3 の Envoy native サポートは現状 alpha / experimental 段階のため、v1 では capability_negotiation 経由の opt-in 採用
- WebTransport の本番必須化は v2 に降格

## WebSocket / Long-poll
- Envoy Gateway HTTP/1.1 Upgrade で WebSocket、long-poll は HTTP/1.1 chunked
- Istio L7 routing は WebSocket / long-poll connection の zone affinity を維持

## ingress / egress 監視
- Kubeshark で API トラフィックの ad-hoc 監視
- Istio access log を OTel Collector 経由で ClickHouse に転送（09 観測可能性 SoR）

## failover orchestrator（network 層の責務）
- `istio_locality_failover`: L7 routing の zone / cluster / region 跨ぎ自動切替
- `metallb_bgp_failover`: cluster 全断時の BGP withdrawn / ECMP shift
- `external_dns_multi_region`: region failover 時の DNS weight 切替

## 強制機構との bind
- 本方針は [infra 強制機構](../../04_詳細設計/02_強制機構/04_infra強制機構.md) の以下経路で物理 enforce される:
    - 層 D: Kyverno `require-network-policy` `require-istio-strict-mtls` `block-host-network-host-pid` admission policy
    - 層 E: Linux kernel SELinux / AppArmor / seccomp による物理 enforcement

## 採用しない方針
- service mesh の Linkerd / Cilium Service Mesh: 採用しない
- cluster 跨ぎ global rate limit: v2 候補
- cilium eBPF data plane / Cilium ServiceMesh: v2 候補
