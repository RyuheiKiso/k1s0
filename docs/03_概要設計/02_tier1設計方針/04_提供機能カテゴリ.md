# tier1 Library 提供機能カテゴリと現行実装 OSS

## 一文方針
- tier1 Library は 17 機能カテゴリを 3 抽象化レベル（L3 / L2\* / L1+）のいずれかに割付けて提供する。各カテゴリは tier2 / tier3 から見た契約面 / 露出 OSS 概念 / 移行先候補が単一の真として宣言される。

## 17 機能カテゴリ × Lv 割付 × 現行実装 OSS

| カテゴリ | 対象 | Lv | 主な提供 API | 現行実装 OSS |
|---|---|---|---|---|
| Observability / Logging | both | L3 | 構造化ログ出力、コンテキスト伝播 | OpenTelemetry Library + Collector → ClickHouse |
| Observability / Tracing | both | L3 | 分散トレース span 発行、伝播 | OpenTelemetry Library + Collector（clickhouseexporter）→ ClickHouse + Jaeger v2（内蔵 CH storage） |
| Observability / Metrics | both | L3 | カウンタ / ヒストグラム / ゲージ | OpenTelemetry Library + Prometheus |
| Observability / Profiling | backend | L2\* | Continuous Profiling 有効化、ラベル付与 | Parca |
| Authentication / Authorization | both | L3 | OIDC クライアント、トークン検証、認可 | Keycloak |
| Secret Management | backend | L3 | シークレット取得、ローテーション通知 | OpenBao + External Secrets Operator |
| Configuration / Feature Flag | both | L2\* | フラグ評価、動的設定読込 | OpenFeature + flagd |
| KeyValue / Cache | backend | L3 | KV 操作、TTL、分散ロック | Valkey |
| Object Storage | backend | L3 | オブジェクト put / get、署名付き URL | Rook + Ceph（RGW） |
| RPC / Gateway | both | L3 | inter-service RPC クライアント / サーバ | Envoy Gateway + gRPC |
| Messaging / EventBus | backend | L1+ | publish / subscribe、Outbox 連携 | Apache Kafka（Strimzi） |
| Schema Registry | backend | L2\* | イベントスキーマ登録 / 取得 / 互換検証 | Apicurio Registry + Buf |
| Relational Store / Single-leader | backend | L1+ | トランザクション、リポジトリ抽象、パーティション lifecycle、拡張機能 API | PostgreSQL（CloudNativePG）+ PgBouncer + pg_partman |
| Relational Store / Distributed SQL | backend | L1+ | 将来カテゴリ。tier3 がアーキテクチャ設計時に Single-leader と排他選択 | （未定） |
| Vector Search | backend | L1+ | ベクトル登録 / 類似検索、SQL JOIN 内 ANN | pgvector |
| Workflow / Long-running Saga | backend | L1+ | Workflow / Activity 定義、補償処理 | Temporal |
| Rule Engine | backend | L1+ | 決定表評価、ルール実行 | ZEN Engine |

## 抽象化レベル（Lv）の意味
- L3: 業界標準 wire / protocol が存在する領域。OSS 中立。差し替え時、業務コードは無変更
- L2\*: 軽セマンティクスかつ真に互換性の高い OSS 族が存在する領域。差し替え時、業務コードは型置換 + 一部チューニングで済む（業務ロジックは不変）。族の外への差し替えは保証外
- L1+: 高セマンティクス領域。単一 OSS への深耕を選ぶ代わり、OSS の全機能（拡張・運用機能を含む）を Library API として表現。OSS ライフサイクルイベント時は tier1 が移行 toolchain を成果物として提供

レベル定義および各レベルの受け入れ基準は [Library](02_Library.md) を参照。

## L1+ / L2\* カテゴリで露出する代表的な OSS 概念（移行時影響箇所）

| カテゴリ | 露出概念 |
|---|---|
| Profiling | profile 種別（cpu / heap / goroutine 等）、サンプリングレート、ラベル基数 |
| Configuration / Feature Flag | evaluation context、ターゲティング規則、セグメント定義 |
| Schema Registry | 互換性モード、グループ / artifact 体系 |
| Vector Search | インデックス種別（HNSW / IVFFlat）、距離関数、SQL JOIN 内 ANN、transactional ANN（同 transaction で upsert + 検索）、pg_partman 連携、再構築コスト |
| Messaging / EventBus | 分割キー、順序保証、consumer pool、再試行 / DLQ ポリシー、Outbox 設計、トランザクション送信 |
| Relational Store / Single-leader | トランザクション分離レベル、advisory lock、SQL 方言、接続プーリング制約、マイグレーション形式、パーティション lifecycle、利用拡張（pg_trgm / PostGIS / pgvector 等） |
| Workflow / Long-running Saga | Workflow / Activity 境界、WorkflowID 体系、補償処理の書き方、決定論実行の制約 |
| Rule Engine | 決定表 DSL、ルール評価セマンティクス |

## L2\* カテゴリの同族定義（差し替え保証対象範囲）

| カテゴリ | 同族 |
|---|---|
| Profiling | pprof 族（Parca / Pyroscope） |
| Configuration / Feature Flag | OpenFeature provider 族（flagd / GO Feature Flag / GrowthBook 等） |
| Schema Registry | Confluent Schema Registry wire 互換族（Apicurio / Karapace） |

族の外への差し替えは保証対象外。族の改廃自体は Library の破壊的変更（major version up）として扱う。

Vector Search はかつて k-NN 族として L2\* 候補に挙げていたが、pgvector の transactional ANN / SQL JOIN 内 ANN と Qdrant / Milvus 等 standalone vector engine の semantics 差が業務ロジックに染み出すため、本企画では L1+ 単一深耕（pgvector）+ 移行コミットメント枠で扱う。

## L3 カテゴリの wire 互換前提（業務コード無変更を成立させる根拠）

| カテゴリ | wire / protocol |
|---|---|
| Logging / Tracing / Metrics | OpenTelemetry SDK + OTLP |
| Authentication / Authorization | OIDC / OAuth 2.1 |
| Secret Management | External Secrets Operator 経由（Provider 差し替えに対し Library API 不変） |
| RPC / Gateway | gRPC（Library 経由言語向け）+ Transport Adapter Layer による transport-neutral な External 公開（`sse_paired` / `websocket` / `webhook` / `web_transport` / `long_poll` / `messaging_bridge` を conformance proof で等価実装） |
| KeyValue / Cache | RESP 族（Valkey / Dragonfly / KeyDB） |
| Object Storage | S3 API 族（Ceph RGW / MinIO / SeaweedFS） |

## L1+ カテゴリの本命 OSS と移行先候補

| カテゴリ | 本命 | 移行先候補 |
|---|---|---|
| Relational Store / Single-leader | PostgreSQL（CloudNativePG） | 別 PG operator（StackGres / Crunchy PGO / EDB）、Aurora PG、Neon |
| Relational Store / Distributed SQL | （将来カテゴリ） | 顧客要件発生時に CR / YB / TiDB / Spanner-API 等が候補 |
| Messaging / EventBus | Apache Kafka（Strimzi） | RedPanda、AWS MSK、Confluent Cloud |
| Workflow / Long-running Saga | Temporal | Cadence、Temporal Cloud |
| Rule Engine | ZEN Engine | 自製 DSL、別 OSS |
| Vector Search | pgvector | PG ecosystem 内のみ toolchain 保証（pgvector index 種別 / 距離関数 / 別 PG operator）。族外 standalone vector engine（Qdrant、Milvus、Weaviate）への移行は transactional ANN / SQL JOIN を持たないため業務コード再設計が必要、L1+ toolchain 保証範囲外、独立プロジェクトとして 14_OSS ライフサイクル適合仕様 の `project_spawn` 経路で扱う |

L1+ では day-1 で複数 backend を並走させない。OSS ライフサイクルイベント時に tier1 が移行 toolchain を成果物として提供する（詳細は [Library](02_Library.md) L1+ 移行コミットメント節を参照）。

## RPC / Gateway カテゴリの追加次元（transport-neutral）
- 本カテゴリは L3（OSS 中立）に加え、もう一つの中立性次元を持つ。Transport Adapter Layer により、bidi を含む全 RPC 形式は transport（wire 上の搬送方式）からも独立に表現される
- これは「異なる transport（HTTP/2 + gRPC / HTTP/3 + WebTransport / HTTP/1.1 + WebSocket / HTTP/1.1 + SSE / inbound webhook / cursor poll / messaging bridge 等）が同じ bidi semantics を等価実装する」ことを CI で証明する形で担保される
- proto に宣言された意味論（ordering / half_close / resumable / max_msg_lag_ms / conformance_class）が単一の真であり、transport はその interpreter として複数並立する
- 受け入れ基準（業務コードへの影響）:
  - 新 transport の追加: 業務コード無変更（adapter 追加のみ）
  - 古い transport 退役: 業務コード無変更（capability 宣言から自動降格）
  - transport 切替（例: SSE → WebSocket）: 業務コード無変更（Companion / Library 内部で完結）
- 「OSS 中立」と「transport 中立」の二軸が成立することにより、本カテゴリは tier2 / tier3 から見た最も安定した抽象表面となる
- この発想は L1+「単一 OSS 深耕 + 移行コミットメント」の哲学を transport 軸に転写したもの（単一 transport 深耕ではなく、bidi semantics 深耕 + transport 移行コミットメント）
