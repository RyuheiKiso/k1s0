# 軸内実装順序

## 一文方針
- tier1 sub-component・infra 5 topology_class・data 5 preservation_class の軸内依存順序を単一の真として保持し、後続 PR での依存逆転を物理排除する。

## tier1 sub-component 依存順序

```
Transport Adapter（8 adapter 同型 API）
  └→ AuthContext / KeyHandle（必須引数、生 bytes 隠蔽）
       └→ Schema Registry Client（Apicurio GitOps SoT）
            └→ Connection Pool（PgBouncer + sqlx）
                 └→ SLO Protection 四層（envoy / library / cgroup / storage）
```

| 手順 | sub-component | blocking 理由 |
|---|---|---|
| 1 | Transport Adapter（8 adapter） | Library facade の土台。adapter なくして API 投影不可 |
| 2 | AuthContext / KeyHandle | 生 key bytes / 生 token を層 A（compile）で隠蔽。以降の全実装が前提とする |
| 3 | Schema Registry（Apicurio） | tier2 async messaging の schema SoT。domain-event 全体の source-of-truth |
| 4 | Connection Pool（PgBouncer） | tier2 RLS / multi-tenant 分離の物理基盤 |
| 5 | SLO Protection 四層 | envoy_local_rate_limit → library_token_bucket → cgroup quota → storage_layer_quota の順 |

**言語対応**:

| sub-component | Rust | Go | C# | TypeScript |
|---|:-:|:-:|:-:|:-:|
| Transport Adapter | ● | ● | ● | ● |
| AuthContext / KeyHandle | ● | ● | ● | ● |
| Schema Registry Client | ● | ● | — | ● |
| Connection Pool（管理） | — | ●（Operator） | — | — |
| SLO Protection | ●（Server） | — | — | — |

## infra 5 topology_class 実装順序

| 順序 | class 名 | 用途 | drill 必須 | topology_class.lock 影響 |
|---|---|---|---|---|
| 1 | `v1_single_zone` | dev / stage 専用 | 不要 | なし |
| 2 | `v1_multi_zone_per_cluster` | 本番業務 default | 自動 failover 30 秒以内検出 | 必須 green |
| 3 | `v1_multi_cluster_active_active` | region 内 HA 最大化 | eventual async 整合 drill | 必須 green |
| 4 | `v1_multi_region_active_passive` | RPO ≈ 0 / RTO ≤ 5 分 | standby read-only drill | 必須 green |
| 5 | `v1_multi_region_active_active` | cell partitioned-synchronous | global DR drill | 必須 green |

`topology_class.lock.yaml` は `v1_multi_zone_per_cluster` 以上の drill が cadence（90 日）以内 green で lock artifact 化。`v1_single_zone` は drill 対象外のため lock への影響なし。

## data 5 preservation_class 実装順序

| 順序 | class 名 | RPO / RTO | restore_drill cadence | preservation_substrates.lock 影響 |
|---|---|---|---|---|
| 1 | `v1_local_only` | 24h / 4h（手動） | 四半期（任意） | なし |
| 2 | `v1_zone_replicated` | 5s / 60s | 月次 | 必須 green |
| 3 | `v1_cluster_replicated` | 60s / 5min | 月次 | 必須 green |
| 4 | `v1_cross_region_replicated` | 0 / 5min | 週次 | 必須 green |
| 5 | `v1_global_replicated` | 0 / 0（per-cell） | 日次 | 必須 green |

`preservation_substrates.lock.yaml` は class 2〜5 の restore_drill が `class.restore_drill_cadence_days` 以内 green の場合に lock 確定。`v1_local_only` は class 1 として実装するが preservation_substrates lock の必須 green 対象外。

## 至高路線における判断
- tier1 sub-component の strict 依存順序は層 A（compile 時）の型制約で機械的に担保する。手順 2 より前に手順 3〜5 の実装を書けば型エラーになる構造にする。
- infra の `v1_single_zone` は drill 不要だが先行実装する。後続 class の drill harness が `v1_single_zone` を base として共有するため。
- data の `v1_local_only` は lock 影響なしだが先行実装する。後続 class の restore_drill が `v1_local_only` の backup 機構を base として拡張するため。
