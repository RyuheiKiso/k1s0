============================================================
client SDK 配布構成方針
============================================================

■ 一文方針
  - SDK は sdk_distribution_class（15_クライアントSDK配布
    適合仕様）の宣言で形が決まり、Buf で codegen され、Harbor
    mirror から各言語 registry 経由で配信される。手動で
    パッケージを差し込む経路は持たない。

■ パッケージ階層（言語横断）
  - 各言語で同型に次の 3 層を提供する。
      - 1) Library パッケージ
            - tier1 04_Library で定義された Library 公開 API
              を直接組み込めるネイティブ言語向け。例：
                .NET 8 LTS  : k1s0.Library.Net8
                Java 21 LTS : io.k1s0:library-java
                Node.js 20  : @k1s0/library-node
                Rust        : k1s0-library
                Go          : github.com/k1s0/library-go
                Python      : k1s0-library
                Ruby        : k1s0-library
            - Browser TS は本来「Library を直接組み込めない」
              側に分類される（後述 Companion 経路）が、SPA 用
              に Browser SDK パッケージとして同型 API を提供：
                Browser TS  : @k1s0/library-web
            - Tauri は @k1s0/library-web + tauri sidecar の
              組合せ（後述）。
      - 2) Companion パッケージ
            - tier1 Library を直接組み込めない言語、または
              レガシー資産向け。観測可能性 / 認証コンテキスト
              伝播 / Transport Negotiation を別経路で提供。
                .NET FW 4.6.2+: k1s0.Companion.NetFx
                Browser TS    : @k1s0/companion-web
                Tauri sidecar : k1s0-companion-tauri (Rust)
                Python (薄)   : k1s0-companion-python
                Ruby (薄)     : k1s0-companion-ruby
            - Companion は薄い proxy として動作し、ビジネス
              API は Envoy Gateway 経由で tier1 Server に到達する
              （unary は gRPC-JSON Transcoder、server-streaming は
              tier1 Rust ハンドラが直接生成する SSE。01_概要.txt
              参照）。
      - 3) Auto-Instrumentation パッケージ
            - 全 distribution_class で同型に observability を
              注入する。可能な限り bytecode / IL 改変方式の
              attach 型、不可能な場合は library 自動 import 型。
                .NET FW + .NET 8 : opentelemetry-dotnet-instrumentation
                Java 21          : opentelemetry-java-instrumentation
                Node.js 20       : @opentelemetry/auto-instrumentations-node
                Browser TS       : @opentelemetry/auto-instrumentations-web
                Python           : opentelemetry-instrumentation
                Ruby             : opentelemetry-ruby auto-load
                Go               : opentelemetry-go-instrumentation (eBPF, v2 候補)
            - 1.0.0 では default on、disable 経路を SDK 公開
              API として持たない（off にしたい場合は init で
              namespace 単位 sampling rate を 0 にできるだけ）。

■ 5 distribution_class（v1）
  - 全 SDK パッケージは次の 5 class のいずれかに属する。
    class が決まれば language_runtime / distribution_channel /
    transport_capability_class / auto_instrumentation_mode /
    companion_provision_mode / device_at_rest_encryption_mode /
    refresh_token_storage_mode が一意に導出される（dimension
    override 禁止）。

      class                                | 主用途
      -------------------------------------+----------------------------------------------------
      v1_full_native_with_companion        | tier1 Library を直接組み込めるサーバ側 / 太い client
                                           | （.NET 8、Java 21、Node.js 20、Rust、Go、Python、Ruby）
      v1_legacy_dotnet_framework           | レガシー .NET Framework 4.6.2+ exe / Service
      v1_browser_spa_typescript            | Browser SPA（TypeScript / React / Blazor WASM 等）
      v1_thick_native_via_tauri            | Tauri デスクトップアプリ（Rust + WebView）
      v1_thin_business_api_only            | Library/Companion を組み込めない polyglot 環境向け
                                           | HTTP/JSON unary は Envoy Gateway gRPC-JSON Transcoder、
                                           | SSE server-streaming は tier1 Rust ハンドラ直接生成

  - 各 class の詳細：
      - v1_full_native_with_companion
          - language_runtime: .NET 8 LTS / OpenJDK 21 / Node 20
            / CPython 3.12 / Ruby 3.3 / Rust stable / Go 1.22
          - distribution_channel: NuGet / Maven / npm / PyPI /
            RubyGems / cargo / Go module（全て Harbor mirror
            経由）
          - transport_capability_class: full（gRPC bidi、HTTP/3
            + WebTransport optional、WebSocket fallback）
          - auto_instrumentation_mode: agent_attach（.NET / Java）
            または library_auto（Node / Python / Ruby / Go / Rust）
          - companion_provision_mode: optional（基本不要、
            tier1 Library を直接利用）
          - device_at_rest_encryption_mode: server_side（offline
            storage は通常持たない、必要なら local secret store
            は OS keychain）
          - refresh_token_storage_mode: process_memory_only
      - v1_legacy_dotnet_framework
          - language_runtime: .NET Framework 4.6.2+
          - distribution_channel: NuGet（Harbor mirror）
          - transport_capability_class: limited（HTTP/1.1 + JSON
            unary は Envoy gRPC-JSON Transcoder 派生、HTTP/1.1
            chunked + SSE server-streaming は tier1 Rust ハンドラ
            直接生成、Companion 役割 B の sse_paired adapter で
            受信。bidi（v1_interactive）と client-streaming
            （v1_bulk_upload）は capability から除外、External
            Proto の射影で取扱う）
          - auto_instrumentation_mode: clr_profiler_attach
            （opentelemetry-dotnet-instrumentation）
          - companion_provision_mode: required（k1s0.Companion
            .NetFx）
          - device_at_rest_encryption_mode: dpapi（Windows
            DPAPI）
          - refresh_token_storage_mode: dpapi_protected_blob
      - v1_browser_spa_typescript
          - language_runtime: Browser（Chromium 系 + Firefox +
            Safari の latest LTS）
          - distribution_channel: npm（Harbor + Verdaccio mirror）
          - transport_capability_class: web（gRPC-Web、WebSocket、
            HTTP/3 + WebTransport browser native API）
          - auto_instrumentation_mode: library_auto（@otel/sdk-
            trace-web + auto-instrumentations-web）
          - companion_provision_mode: required（@k1s0/companion-
            web、Service Worker registration を含む）
          - device_at_rest_encryption_mode: webcrypto_aes_gcm_
            non_extractable_cryptokey
          - refresh_token_storage_mode: in_memory_only +
            httponly_cookie_for_refresh
      - v1_thick_native_via_tauri
          - language_runtime: Tauri（Rust + WebView）
          - distribution_channel: cargo + npm（フロント TS）+
            Tauri バンドル（msi / dmg / AppImage）
          - transport_capability_class: full（Tauri sidecar が
            Rust 側で gRPC bidi / HTTP/3 / WebTransport / WebSocket
            を担当、WebView は IPC 経由）
          - auto_instrumentation_mode: dual（Rust 側は OTel
            Rust、WebView 側は OTel Browser）
          - companion_provision_mode: required（k1s0-companion-
            tauri sidecar）
          - device_at_rest_encryption_mode: webcrypto_aes_gcm_
            with_os_keychain_key_wrap
          - refresh_token_storage_mode: os_keychain_secure_storage
      - v1_thin_business_api_only
          - language_runtime: 任意（C++ / Erlang / Elixir /
            COBOL / その他 polyglot）
          - distribution_channel: 公式 OpenAPI 仕様 + 言語側
            generator（curl 例、postman collection、OpenAPI
            generator）。本企画は SDK パッケージは提供しない。
          - transport_capability_class: business_api_only
            （HTTP/1.1 + JSON unary は Envoy Gateway gRPC-JSON
            Transcoder 経由、HTTP/1.1 + SSE text/event-stream
            server-streaming は Envoy Gateway 配下の tier1 Rust
            ハンドラが直接生成）
          - auto_instrumentation_mode: side_companion_proxy
            （独立 OTel Collector sidecar が観測を引き受け）
          - companion_provision_mode: side_companion_proxy
          - device_at_rest_encryption_mode: not_applicable
            （offline storage を提供しない）
          - refresh_token_storage_mode: not_applicable
            （token は infra 配下の API Gateway が処理）

  - 5 class で v1 covering。新 class は purely additive で
    追加（v2 拡張ルール）。

■ パッケージサイズ / 起動時間
  - SDK サイズと cold start latency は 14 OSS lifecycle 適合
    仕様の signal_source_endpoint で観測対象、v1 は計測 only、
    v2 で削減目標を SLO 化検討。「サイズが大きい」を理由に
    Auto-Instrumentation を default off にすることはしない
    （至高路線）。
  - tree-shaking / lazy load を SDK 内部で活用するが、公開
    API としての optional package split は行わない。「core /
    extra」型の分割は禁止。

■ パッケージ命名 / namespace 規約
  - .NET     : k1s0.* （PascalCase）
  - Java     : io.k1s0.* （reverse DNS）
  - Node.js  : @k1s0/* （npm scope）
  - Browser  : @k1s0/* （同上）
  - Python   : k1s0_* （snake_case）
  - Ruby     : k1s0/* （namespace） + k1s0-* （gem name）
  - Rust     : k1s0_* （crate name は kebab → underscore）
  - Go       : github.com/k1s0/* （module path）
  - 全言語で「namespace の root が k1s0」を物理 enforce
    （CI で公開 API snapshot 検査）。

■ パッケージライフサイクル
  - 構築：proto / Apicurio schema を input として Buf workflow
    で codegen → 各言語 build → Cosign signed → Harbor push。
    手書き SDK code path は CI fail。
  - 更新：09_配布SemVer方針 の lockstep release に従う。
  - 廃棄：major version の sunset は 14 OSS lifecycle 適合
    仕様の deprecation_window（180 日 + 1 LTS overlap）を踏襲。
    旧 SDK は Harbor 上に永久保管（pull 可能、push のみ block）。
  - 再現性：sdk_inventory.lock.yaml に全 SDK のバージョン /
    SHA / SBOM 場所を build artifact として記録、git に
    commit する。手書き禁止。

■ companion sidecar の局所性
  - Companion は本企画の「tier1 Library を直接組み込めない
    言語向け薄 proxy」。原則として：
      - .NET FW Companion : 同 process 内 NuGet
      - Browser Companion : Service Worker + main thread
      - Tauri Companion   : Tauri sidecar（別 OS process、
                            IPC 経由）
      - thin API          : 独立 sidecar pod（infra 側に置く）
  - Companion 自体の wire 規約は SDK と同型（gRPC / gRPC-Web /
    WebSocket）。言語別 transport の差異は Companion 内 adapter
    で吸収（07_tier3/39 と同型）。

■ legacy 資産配慮
  - .NET Framework 4.6.2+：opentelemetry-dotnet-instrumentation
    の CLR Profiler attach 方式（コード変更不要）+ Companion
    NuGet（観測 / 認証 / Transport Negotiation）の二点セット
    で v1_legacy_dotnet_framework class に分類。
  - 古い Java 8 などの環境：v1 では unsupport（v2 候補）。
    現実的に Java 21 LTS への移行コミットメントを request する。
  - Internet Explorer / Edge Legacy：v1 unsupport。Browser
    SPA は Chromium 系 + Firefox + Safari の latest LTS のみ。

■ 至高路線の整合
  - 「言語数を絞れば運用が楽」を理由に SDK class を削減
    しない。1.0.0 で 5 class を全 release。
  - 「Companion を提供すれば Library を諦める」型の分岐は
    持たない。Library を直接組み込める言語は Library を、
    そうでない言語は Companion を、Browser/Tauri は両方を、
    という「distribution_class が一意に決める」原理に従う。
  - パッケージは Cosign signed のみ install 可能、 unsigned
    パッケージは infra 側 Kyverno admission policy（require-
    image-from-harbor / require-cosign-signature）で reject
    される（SDK 配布は image だけでなく package も Cosign
    署名対象、08_infra/14_強制機構 整合）。
