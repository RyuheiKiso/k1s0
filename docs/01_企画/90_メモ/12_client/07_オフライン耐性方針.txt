============================================================
client オフライン耐性方針
============================================================

■ 一文方針
  - SDK のオフライン耐性は tier3 39_クライアント状態適合仕様
    の 4 layer（Server Truth / Optimistic Local / Pending Queue
    / Draft）と conflict tree に従い、SDK 側で言語横断同型に
    実装する。SDK は意味論を再定義せず、SDK 提供 API は 39 の
    1:1 投影のみ。

■ SDK 側責務（39 適合仕様の 1:1 投影）
  - SDK が提供する：
      - Layer 4 種の reducer / store helper（Application 層）
      - Pending Queue durable storage（IndexedDB encrypted /
        OS keychain integration / DPAPI / Tauri secret store）
      - Idempotency-Key 自動採番 + 24h TTL enforce
      - Adapter 層 effect 実行器（IndexedDB I/O / WebCrypto
        encrypt-decrypt / network send / OS keychain probe）
      - conflict_tree.yaml の event dispatch helper（39 の
        actions を実装する純粋関数 + Adapter）
      - PII strip-at-enqueue / attach-at-send の機構
      - purge trigger（logout / refresh_token expiry / tenant
        switch / actor switch）の wiring
      - subscriber API（domain_event_received → SDK 内部
        reducer）
  - SDK が提供しない：
      - layer 種類の変更 / event 追加 / subtype 追加（→ 39
        改定が前提）
      - UI コンポーネント（→ 07_tier3 業務側 SPA）
      - ビジネス specific 衝突解決（→ 39 の business_conflict
        _received subtype に従う）

■ オフライン storage の物理仕様
  - distribution_class 別の固定組合せ：

      class                                | storage                    | encryption                                        | key
      -------------------------------------+----------------------------+---------------------------------------------------+--------------------------------
      v1_full_native_with_companion        | OS keychain + memory       | OS native（macOS Keychain / DPAPI / SecretService）| OS managed
      v1_legacy_dotnet_framework           | DPAPI protected blob       | DPAPI（CurrentUser scope）                        | OS managed
      v1_browser_spa_typescript            | IndexedDB                  | WebCrypto AES-GCM                                 | non_extractable_cryptokey
      v1_thick_native_via_tauri            | IndexedDB（WebView） +     | WebCrypto AES-GCM + OS keychain wrap              | OS keychain（Tauri plugin）
                                           | Rust 側 sled or sqlite     |                                                   |
      v1_thin_business_api_only            | not provided               | not applicable                                    | not applicable

  - storage 選択は dimension override 禁止。class が決まれば
    一意。アプリ作者が「ローカルストレージにしたい」を理由に
    切り替える経路は持たない。

■ pending_queue durable contract
  - SDK は queue を必ず durable に保持する（v1_thin_business_
    api_only 以外）。
  - queue entry の構造（39 適合仕様 lineage と同型、SDK が
    type 化）：
      - tenant_id, actor_id, aggregate_id, base_version
      - method (proto FQN), request_payload (PII stripped)
      - idempotency_key, enqueued_at, attempted_count, last_
        error_class, attempt_states[]
  - per-aggregate serialize（aggregate ID 単位で in-flight 1
    件、enqueue 順を保つ）を SDK が実装。
  - PII fields は proto descriptor の `(k1s0.field_pii) = true`
    annotation で識別、enqueue 時に strip、send 直前に in-
    memory form state から attach。
  - send は Adapter 経由で network、ack で promote、4xx で
    rollback / business_conflict 分岐（39 の actions と同期）。

■ idempotency_key
  - 自動採番：ULID + tenant_id prefix + RPC method short hash。
    user-supplied は受け付けない。
  - TTL：24h（39 適合仕様の idempotency_key_ttl と同期）。
  - 超過時の挙動：39 適合仕様の over_ttl_policy に従う：
    mark_as_stale → require_user_confirmation_to_resend →
    confirm: generate_new_idempotency_key / discard: remove_
    entry。
  - server 側 32 atomic 三表書込との dedup contract は tier2
    で保証、SDK は idempotency_key を必ず request header
    `x-idempotency-key` として送出（HTTP/JSON 経路含む）。

■ refresh_token / device_bound_key の rotation
  - device_bound_key の生成タイミング：
      - Browser SPA: 初回 init 時、WebCrypto.subtle.generateKey
        ({ name: 'AES-GCM', length: 256 }, false, ['encrypt',
        'decrypt']) で non-extractable
      - Tauri / Native: OS keychain に key blob を保管、Rust
        側で取得
      - .NET FW: DPAPI.Protect でユーザ scope 暗号化
  - rotation：refresh_token 失効を検知すると即時：
      - 全 layer storage を purge
      - device_bound_key を再生成
      - 旧 storage は復号不可（鍵が rotate しているので physical
        に decrypt 不能）
      - purge を 09 観測可能性 SoR に audit emit（client.purge
        .event、tenant_id / actor_id を記録）

■ background sync / Service Worker
  - v1 Browser SPA：Service Worker は cache-first read-through
    cache のみ採用。background sync は v2 候補（v2_sw_background
    _sync）。
  - v1 Tauri：Tauri sidecar が常駐するため、background は
    sidecar process 上で動作。app reopen で IPC 経由に状態
    復元。

■ 接続復帰検知
  - online/offline event：
      - Browser: window.online / offline + Network Information API
      - Tauri: navigator.onLine + tauri::api::notification 補助
      - Native: SDK 内部で health probe（5s interval、jitter
        付き）
  - offline 中の queue 蓄積に上限：
      - per-aggregate 100 entry hard cap（超過は public API
        が EnqueueLimitReached を throw）
      - per-tenant 1000 entry hard cap
      - storage byte 上限：50 MB（超過時 oldest non-PII を
        evict、PII 含む entry は ユーザ確認待ち）
  - 復帰時の send 順序：39 conflict_tree.yaml の pending_
    queue_resume と同期、enqueue 順 + per-aggregate serialize。

■ purge triggers
  - 全 trigger と挙動（39 適合仕様 purge_triggers と同期）：
      - logout                  → 全 layer purge + audit emit
      - refresh_token_expiry    → 全 layer purge + audit emit
      - tenant_switch           → 全 layer purge + 新 tenant_id
                                   で再 init
      - actor_switch            → 全 layer purge + 新 actor_id
                                   で再 init
      - device_bound_key_rotate → 全 layer purge + 新鍵で再 init
  - purge は audit emit を必ず伴う（PII 含み得る storage が
    削除されたことを SoR に記録）。

■ at-rest PII の物理 enforce
  - SDK 内部の type レベル：proto descriptor の `(k1s0.field
    _pii) = true` アノテーションが付いた field は IndexedDB /
    OS keychain に rest しない（compile time check + runtime
    redaction）。
  - 物理検査：headless browser integration test で IndexedDB
    の物理 dump を解析、PII 平文混入が検出されたら CI fail
    （39 適合仕様 整合 7 と同等）。
  - SDK は WebCrypto の AES-GCM 256bit、 IV ランダム、AAD は
    aggregate_id+version で固定。自製 crypto 禁止。

■ 25h オフラインケース（製造業 pack）
  - 39 適合仕様 製造業 pack stress test 6（オフライン 25h
    経過した検査入力の再送試行）と同等を SDK contract test
    で全自動検証。
  - SDK は idempotency_key TTL（24h）超過判定、ユーザに
    再送 / 破棄を確認、新 idempotency_key で resend のフロー
    を完全自動。

■ 採用しない選択肢
  - LocalStorage / SessionStorage への PII 平文書込：禁止
    （lint で deny）。
  - cookie への refresh_token 永続化：HttpOnly + Secure +
    SameSite=Lax のみ許容（OIDC redirect 戻りでの cookie 失効を
    回避するため、07_tier3/25_認証認可マルチテナント /
    07_tier3/40_BFF_auth_edge / 07_tier3/32_セキュリティアーキ
    テクチャ と整合。CSRF は Double-Submit Cookie + Origin/
    Referer 二重検査で担保）、SDK 内 JavaScript からは触れない。
  - 自製 crypto：禁止。
  - PII を含むまま enqueue：禁止。strip → in-memory 再 attach
    のフローを物理 enforce。

■ 至高路線の整合
  - 「offline storage を諦めれば SDK が軽い」を理由に v1_
    browser_spa_typescript / v1_thick_native_via_tauri から
    offline 機構を削減しない。
  - PII 取扱い / 暗号化は WebCrypto / OS keychain の物理
    機構を最終 safety net とし、文章運用に依存しない。
