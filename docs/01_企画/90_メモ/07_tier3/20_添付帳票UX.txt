============================================================
tier3 の添付ファイル / 帳票 UX
============================================================

■ 方針
  - 「06_tier2/31_業務添付帳票資産」のクライアント側表現を tier3
    が担う。添付ファイル本体・帳票本体・改竄検知ハッシュ・PII flag
    などの実体は tier2 が所有し、tier3 はそれらを業務語彙で操作
    可能にする UI に責務を絞る。
  - 添付 / 帳票の業務種別 enum・許容形式・サイズ上限・retention は
    tier2 から取得する（クライアントが独自に定義しない、「23_tier2
    消費方針」整合）。tier3 が画面で提示する選択肢はすべて tier2 の
    宣言に同期する。

■ アップロード UI
  - chunked upload を既定とする。大容量ファイルでも単一トランザク
    ションに依存しない実装とする。
  - progress 表示 : 各チャンクの送信完了率を per-file / 全体の二段
    で提示する。
  - cancel : 送信途中の中断を可能とし、サーバ側に積まれた未完成
    chunk は tier2 にクリーンアップ要求を送る。
  - 並列アップロード : 同時送信数を tier3 SDK で上限固定する
    （ブラウザ / 端末の HTTP 並列上限と整合）。
  - 中断 resume : ネットワーク断 / 端末スリープからの復帰時、
    送信済 chunk を tier2 に問合せて未送信分のみ再送する。
      例：upload_session_id を tier2 から発番し、resume 時に
          完了済 chunk index を取得して残りを送る。
  - ドラッグ & ドロップ / クリップボードからの貼付対応
      例：検査写真をスクリーンショット直貼り、図面 PDF を
          ファイラからドロップ。

■ 受入種別 / サイズ上限の事前提示
  - 業務種別ごとの許容形式・サイズ上限を tier2 から取得し、ファイル
    選択ダイアログに先に反映する（「12_フォーム設計規約」事前提示
    原則と整合）。
  - 拒否はファイル選択時に即時表示する（送信後に弾かない）。
      例：drawing 種別は DWG / PDF のみ、サイズ上限 50 MB。
          受入不可時は「許容形式 / サイズ上限」を文字情報で示す。
  - 種別 enum はサーバ側 enum と機械的に同期する（「31_強制機構」
    翻訳キー / enum 整合と同枠）。

■ quarantine 状態の UI
  - アップロード完了直後は quarantine 状態として「ウイルススキャン
    待ち」を明示表示する。ダウンロード / プレビュー操作は disable
    する。
  - スキャン完了で active 化された時点で「17_通知UI」経由でトースト
    通知 + 一覧の差分強調を行う。
  - スキャン検出時は業務管理者通知後にクライアント側でも該当添付を
    削除済として扱う。tier3 業務 UI から再アップロード経路は提示
    するが、強制的なローカル復元は行わない。

■ 添付プレビュー
  - サポート種別 : PDF / image（PNG / JPEG）/ CSV / 帳票 PDF。
      例：PDF は埋込ビューア、image は viewer 内でズーム / 回転、
          CSV は先頭 N 行をテーブル表示。
  - SVG / HTML は inline 禁止 : XSS 防止のため画面に直接埋め込まな
    い。プレビューが必要な場合は sandboxed iframe + safe sanitizer
    を経由する（「32_セキュリティアーキテクチャ」整合）。
  - 大容量プレビュー : 全体ロードを避け、PDF はページ単位 / image
    は decimated 表示でメモリ消費を抑える。

■ ダウンロード
  - 小サイズ : tier2 Service 経由でストリーミング受信し、ブラウザ
    の Save ダイアログで保存する。
  - 大サイズ : tier2 が発行する Object Storage 署名 URL（短時間
    有効）でクライアントが直接ダウンロードする（「06_tier2/31_業務
    添付帳票資産」配送節整合）。
  - 署名 URL 期限切れの再取得 UX : 期限切れが検出されたら自動的に
    tier2 へ署名 URL の再発行を要求し、ユーザ操作なしで再開する。
    再発行は監査エントリが emit されることをユーザに事前提示する。

■ Content-Disposition
  - 既定は attachment（download 強制）。
  - inline 表示は安全種別（PDF / image / CSV）に限定し、HTML / SVG
    は inline 禁止（前述の XSS 防止整合）。
  - クライアントが Content-Disposition を上書きする経路は持たない
    （tier2 のレスポンスに従う）。

■ バージョン履歴 navigation
  - 同一業務 entity + 同一添付種別の複数バージョンを navigation
    可能にする。最新版を既定表示とし、過去版へは明示遷移とする。
  - 差分表示 :
      - PDF / 帳票 PDF : ページ単位の差分プレビュー（同一ページの
        左右並置）。
      - CSV : 行単位 diff。
      - image : サムネイル並置 + EXIF 差分。
  - 業務 entity の状態（「19_業務エラーUX」「14_状態遷移UI」整合）
    によって過去版の参照可否が変わるため、可否は tier2 のレスポンス
    に従う。

■ PII 含有 flag の UI
  - tier2 が flag を立てた添付は一覧 / 詳細で「PII 含有」を明示する。
  - redact 表示 : サムネイル / プレビューで PII 領域を黒塗り / モザ
    イク表示する（tier2 が redact 済バリアントを返す前提、「18_権限
    UI制御」整合）。
  - 追加認可フロー : ダウンロード / 原本プレビューには追加認可
    （理由入力 + ステップアップ認証）を要求する（「32_セキュリティ
    アーキテクチャ」サポート用アクセス整合）。
  - 追加認可の通過 / 拒否はすべて監査エントリに記録される旨を画面
    で事前提示する。

■ 帳票生成 UI
  - テンプレート選択 : 業務 entity に紐付く帳票テンプレート enum
    を tier2 から取得し、ユーザが選択可能にする。
      例：発注書 / 検収書 / 検査成績書 / 不良票。
  - プレビュー : tier2 が生成した帳票 PDF を埋込ビューアで表示。
    ページ送り / 印刷プレビュー / ズームを提供する。
  - 印刷 : OS 印刷ダイアログを呼び出し、印刷ジョブを送る。
  - ダウンロード : 添付ダウンロードと同枠（小 / 大サイズ分岐、
    署名 URL）。

■ 帳票印刷統合
  - OS 印刷ダイアログ : ブラウザ / デスクトップそれぞれの標準ダイ
    アログを使用する。クライアント独自ダイアログは作らない。
  - クライアント印刷 : ラベルプリンタ等の専用機（「22_端末オフ
    ラインデバイス」整合）は Adapter 層で吸収する。
  - 一括印刷 : 複数 entity を 1 ファイルにまとめる帳票生成は
    LRO（「15_非同期処理UX」整合）として実行する。Operation
    オブジェクトの polling / Webhook で完了通知を受ける。

■ 帳票テンプレート編集の境界
  - 帳票テンプレートの編集は業務管理 UI の責務であり、tier3 業務
    UI には載せない（「26_業務管理UI境界」整合）。
  - tier3 業務 UI では「テンプレートを選んで出力する」操作のみを
    提供し、テンプレート自体の追加 / 編集 / 承認 workflow には
    Backstage プラグイン経由で deep link する。

■ template injection 防止
  - クライアント側で帳票テンプレート / プレビュー HTML / SVG を
    動的に組み立てる経路を持たない。テンプレートエンジン eval は
    禁止する（「32_セキュリティアーキテクチャ」整合）。
  - ユーザ入力を含む帳票プレビューは tier2 が safe mode で生成
    した PDF / image を表示するに留める。
  - HTML プレビューが必要な場合のみ、sandboxed iframe + 厳格な
    sanitizer（DOMPurify 等）を Adapter 層に集約する。

■ 改竄検知 UI
  - 規制対応添付 / 帳票には hash chain の検証結果を表示する。
      例：「検証 OK」「検証 NG（要確認）」「未検証」を業務語彙で
          提示し、検証 NG はユーザ操作を抑制する。
  - 外部公証 / Trusted Timestamp との突合結果を表示するペインも
    用意する（連携が有効なテナントのみ）。
  - 検証ロジック自体は tier2 / tier1 が担当し、tier3 は検証結果を
    表示する責務に留まる。

■ アップロード補助
  - ドラッグ & ドロップ : ドロップ領域は画面上に常設し、操作可能
    な範囲を視覚的に明示する（「10_UX原則」フィードバック整合）。
  - クリップボード貼付 : Ctrl+V / Cmd+V でスクリーンショット /
    画像を即添付できる経路を提供する。
  - モバイル / タブレットからのカメラ撮影直貼り（「22_端末オフ
    ラインデバイス」カメラ整合）。
