============================================================
tier3 のアクセシビリティと国際化
============================================================

■ 方針
  - tier3 はアクセシビリティと国際化を「後付け対応」で扱わない。
    1.0.0 出荷時点で WCAG 2.1 AA 準拠を最低基準とし、AAA 適合可能な
    レベルを目指す。製造業のグローバル展開（複数国・複数言語・複数
    通貨）に day-1 から追従する（「06_tier2/21_国際化方針」整合）。
  - canonical（言語非依存・UTC・SI 単位・基準通貨）と表示形式の分離
    を Application 層で徹底する。Presentation 層は表示形式変換のみ
    を担う（「07_内部アーキテクチャ」整合）。

■ アクセシビリティ最低基準
  - WCAG 2.1 AA 準拠を 1.0.0 のリリース必須要件とする。
  - AAA 適合可能なコンポーネント設計を行い、テナント / 業務 pack
    側で AAA 設定が選択可能とする。
  - 達成度は CI で axe-core / pa11y / Lighthouse Accessibility
    score を計測し、しきい値を割ったら fail とする（「31_強制機構」
    整合）。

■ キーボード操作
  - 全機能をキーボードのみで完結可能とする（マウス前提の操作経路を
    持たない、「12_フォーム設計規約」「13_検索一覧UX」整合）。
  - 標準キー割当 :
      - Tab / Shift+Tab : フォーカス移動
      - Enter : 主要アクション（送信 / 確定）
      - Esc : モーダル / ドロワーの閉じる
      - 矢印キー : 一覧 / グリッド内の移動
      - Ctrl+S / Cmd+S : 下書き保存（「08_状態管理」整合）
  - ショートカットは画面ヘルプから一覧参照可能とする（「10_UX原則」
    発見可能性整合）。
  - キーボードトラップ禁止 : モーダル / ドロワーは Esc / フォーカス
    トラップ脱出経路を必ず提供する。

■ スクリーンリーダ対応
  - aria 属性を業務語彙で適切に付与する（aria-label / aria-describedby
    / aria-live / role 等）。
  - 業務 entity の状態 / 関係性を文字情報で伝達 :
      - 一覧の選択行に「選択中」「未選択」を text 化。
      - 状態遷移ステータス（Draft / Confirmed / Cancelled 等、
        「14_状態遷移UI」整合）を text で読み上げ可能にする。
      - 親子関係（aggregate root と子 entity）を aria-owns /
        aria-controls で関連付ける。
  - 動的更新（リアルタイム / toast 通知、「16_リアルタイム更新UX」
    「17_通知UI」整合）は aria-live で読み上げる。重要度に応じて
    polite / assertive を使い分ける。

■ カラーコントラスト
  - 比率 :
      - テキスト : 4.5:1 以上（AA）、AAA を目指す場合は 7:1。
      - UI 要素（ボーダー / アイコン / 状態色）: 3:1 以上。
  - デザイントークン（「09_デザインシステム」整合）でコントラスト
    比を機械的に検査する（CI でトークン値の組合せを評価）。
  - 色のみで意味を伝えない : 状態色 + アイコン + text を併用する
    （色覚多様性配慮）。
      例：エラーは赤背景 + 警告アイコン + 「エラー」文言。

■ 動きの抑制（prefers-reduced-motion）
  - prefers-reduced-motion: reduce を尊重する。アニメーション /
    トランジション / 自動スクロールを停止または短縮する。
  - 必須でない演出（ローディングスピナのバウンス等）は完全に静的
    表現に切り替える。
  - ユーザ設定からも上書き可能とする（OS 設定取得不可な環境向け）。

■ フォーカス表示
  - フォーカス枠は「09_デザインシステム」のトークンに従い、
    高コントラストで明示する。
  - outline: none を CSS で打ち消すことを禁止する（「31_強制機構」
    で lint）。
  - フォーカス可視を維持しながら mouse hover との視覚的衝突を避ける
    デザイントークンを用意する。

■ フォーカス管理
  - モーダル / ウィザード遷移時のフォーカス移動規約 :
      - モーダル open : 最初の入力欄 / 主要ボタンへフォーカス。
      - モーダル close : open 元の要素へフォーカスを戻す。
      - ウィザード step 遷移 : 新 step の最初のフォーカス候補へ
        移動。
      - フォームエラー時 : 最初のエラー欄へフォーカス（「12_フォー
        ム設計規約」整合）。
  - フォーカスの履歴は Application 層で保持し、Presentation 層が
    破壊しないように制約する。

■ 国際化対象（「06_tier2/21_国際化方針」整合）
  - 言語 :
      - 識別子は IETF BCP 47（ja / ja-JP / en / en-US 等）。
      - 解決順 : リクエスト → ユーザ → テナント → en。
      - 切替は即時反映（リロード不要、「11_画面遷移ルーティング」
        整合）。
  - TZ :
      - 表示はテナント / ユーザ / リクエスト指定 TZ で解決。
      - 内部処理はすべて UTC（「08_状態管理」整合）。
      - tzdata は tier2 配信に追従し、tier3 はキャッシュしない。
  - 単位 :
      - テナント / ユーザ設定の表示単位への変換は明示換算のみ。
      - 暗黙換算禁止 : kg ↔ lb のような換算は明示メソッドで行い、
        UI には換算結果と元単位を併記する。
          例：「100 kg（換算 220.46 lb）」。
  - 通貨 :
      - 元通貨 + 表示通貨を並記する。
          例：「1,000 USD（参考 150,000 JPY、為替 snapshot
              2026-05-07T00:00Z）」。
      - 為替 snapshot 時刻を併記し、事後の為替変動で過去取引が
        変化しないことを明示する。

■ 数値・日付の表示形式
  - locale 依存の表示形式（小数点 . / , / 桁区切り / 日付
    フォーマット）を ICU ベースのフォーマッタで実装する。
  - 内部処理は canonical（小数点 . / 千区切りなし / ISO 8601）を
    維持する。Presentation 層配下の formatter モジュール（「07_
    内部アーキテクチャ」整合）でのみ表示形式へ変換する。

■ 文字長変動への耐性
  - ボタン / ラベル / メニュー項目が翻訳で伸縮しても破綻しない
    レイアウトを採用する :
      - 固定幅前提のレイアウトを禁止する。
      - 切り詰め（ellipsis）はツールチップで全文参照可能とする。
      - flex / grid + min-width / max-width で柔軟な伸縮に対応。
  - 視覚回帰テスト（「29_テスト方針」整合）に短文 / 長文 / RTL
    バリアントを含める。

■ RTL 対応
  - 1.0.0 では RTL 適合可能な構造で組む（CSS logical properties
    margin-inline-start 等を使用、left / right 直書きを禁止）。
  - dir 属性 / アイコン左右反転 / フォーカスフロー反転を Adapter 層
    で対応する。
  - 1.0.0 出荷時点でアラビア語等の RTL 言語を翻訳カタログに同梱
    しなくても、UI の RTL 切替で破綻しないことを CI で検査する。

■ 翻訳カタログ
  - tier2 提供分（業界横断 / 業界 pack）と tier3 固有分を別 namespace
    で管理する。
      例：tier2.cross_industry.notification.* /
          tier2.manufacturing.procurement.* /
          tier3.<app>.<feature>.*
  - tier3 固有翻訳は features/<domain>/i18n/ 配下に配置する。
  - 既定言語は ja / en の 2 言語を 1.0.0 で同梱（「06_tier2/21_国際
    化方針」1.0.0 出荷範囲整合）。追加言語はテナント運用が
    翻訳追加で対応可能。

■ 翻訳キー未定義検出（「31_強制機構」「06_tier2/16_強制機構」整合）
  - 翻訳キー参照を機械的に列挙し、カタログに未登録のキーを CI で
    検出する。
  - 逆方向（カタログにあるが参照されないキー）も別途検出し、未使用
    キーは削除候補としてレポートする。
  - hardcoded な日本語 / 英語文字列が画面コードに混入することを
    eslint / Roslyn analyzer で検出する。

■ 多言語切替 UI
  - 共通ヘッダから言語切替を提供する（クライアント状態として
    「08_状態管理」グローバルストアに保持）。
  - 切替時は :
      - サーバ状態 cache を invalidate（業務メッセージ / マスタ
        表示名の言語が変わるため、「08_状態管理」整合）。
      - クライアント状態のフォーム編集中値は維持。
  - 切替は監査エントリ emit 対象ではない（読取のみの設定変更）。

■ アクセシビリティと国際化の交差
  - スクリーンリーダ読み上げの言語 = UI 表示言語と一致させる
    （aria-* も翻訳対象）。
  - RTL + スクリーンリーダ : 読み上げ順は logical order に従う。
    視覚順序での読み上げ違反を避ける。
  - 単位 / 通貨表記はスクリーンリーダ向けに展開形（「100 キログラム」
    等）を併記する設定を提供する。
