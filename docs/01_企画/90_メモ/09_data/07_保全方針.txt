============================================================
data 保全方針
============================================================

■ 一文方針
  - 全 data store は preservation_class が要求する WAL /
    snapshot / archive の物理機構で「N 時点の state を必ず
    復元できる」ことを保証する。retention 期限と restore_
    drill cadence は preservation_class から一意に導出され、
    instance 個別 override は持たない。

■ 保全レイヤ（4 層）
  - 層 1：online primary（書き込みを受ける instance）
      - CloudNativePG primary、Kafka leader broker、
        ClickHouse primary replica、Valkey master、Apicurio
        primary pod
  - 層 2：synchronous replica（即時整合）
      - CloudNativePG synchronous standby（synchronous_
        commit=remote_write）
      - Kafka follower（min.insync.replicas）
      - ClickHouse Replicated MergeTree replica（keeper
        経由）
  - 層 3：asynchronous replica / WAL streaming（短期復元）
      - CloudNativePG WAL archive（pg_wal-archive →
        Ceph RGW）
      - Kafka MirrorMaker2 cross-cluster
      - ClickHouse Distributed table への async push
      - Longhorn snapshot（PV 単位、daily）
  - 層 4：cold archive（長期保全）
      - Ceph RGW（cold tier、Object Lock 適用）
      - archive_to_offline（手動 / 別契約、tape / 外部
        bucket）
  - 各 preservation_class は「最低でもこの層まで保全する」
    を class 不変条件で固定（15_データ保全適合仕様 と整合）。

■ CloudNativePG 保全
  - WAL：pg_wal-archive で連続 archive、archive 先は Ceph
    RGW（同 cluster）+ cross-region Ceph RGW（v1_cross_
    region_replicated 以上）。
  - Base backup：CloudNativePG が daily に基底 backup を
    取得、Ceph RGW に保管。retention は preservation_class
    別：
        v1_local_only           : 7 日
        v1_zone_replicated      : 30 日
        v1_cluster_replicated   : 90 日
        v1_cross_region_repl.   : 365 日
        v1_global_replicated    : 365 日 + immutable archive
  - PITR（Point-In-Time Recovery）：base backup + WAL の
    任意時点へ復元可能。RPO = WAL archive 完了 lag（≤ 60
    秒、target ≤ 5 秒）。
  - 復元手順：CloudNativePG Cluster CR の `bootstrap.recovery
    .recoveryTarget` で時刻指定、新 cluster として復元。
    11_復旧訓練方針 で物理演習。
  - 物理機構：synchronous_commit / WAL archive 完了確認 /
    pg_wal の disk flush は OS layer の fsync で物理 enforce。

■ Strimzi（Kafka）保全
  - replication：replication.factor / min.insync.replicas
    は preservation_class 別：
        v1_local_only           : RF=1, ISR=1
        v1_zone_replicated      : RF=3, ISR=2 (rack 跨ぎ)
        v1_cluster_replicated   : RF=3 + MM2
        v1_cross_region_repl.   : RF=3 + MM2 strict-ordering
        v1_global_replicated    : RF=3 + MM2 active-active
  - retention.ms：preservation_class 別 default：
        v1_local_only           : 1 d
        v1_zone_replicated      : 7 d
        v1_cluster_replicated   : 30 d
        v1_cross_region_repl.   : 90 d
        v1_global_replicated    : 90 d + cold archive
  - tiered storage：v2 候補（Apache Kafka 本体の tiered
    storage feature が GA 後に評価）。
  - cold archive：retention 超過 topic は Kafka Connect で
    Ceph RGW に sink、object lock 30 日。
  - 物理機構：min.insync.replicas は acks=all 時に物理
    enforce、broker 側で reject。

■ ClickHouse 保全
  - Replicated MergeTree：keeper 経由で全 replica が WAL
    （part の zk metadata）を共有、replica 障害時に他
    replica が復元可能。
  - tiered storage（disk_s3）：hot SSD（Longhorn）→ cold S3
    （Ceph RGW）、TTL move による自動移動。
  - backup：clickhouse-backup（CLI）で base backup を
    Ceph RGW に保存、retention は preservation_class 別。
  - cross-region：v1_cross_region_replicated 以上で macro
    replicas を別 region keeper に配置、cell-based の
    場合は per-cell の独立 backup。

■ Valkey 保全
  - 原則：Valkey は cache 用途のみ、保全対象外。
  - persistence（AOF / RDB）は無効が default、enable する
    場合は preservation_class を v1_zone_replicated 以上に
    昇格させ、CloudNativePG への切替を検討。
  - 永続化が必要な KV は CloudNativePG の `kv_<context>`
    table に降ろす規律（06_スキーマ運用方針）。

■ Apicurio Registry 保全
  - storage backend = CloudNativePG instance、その instance
    の preservation_class が Apicurio の保全 class と等価。
  - subject 削除は禁止（schema 進化の forward-only と整合）、
    archive のみ。
  - registry の disaster recovery は backing PostgreSQL の
    PITR で実行。

■ Outbox / audit_local 保全
  - Outbox table：tier2 業務 Service の同 transaction で
    INSERT、Debezium publisher が Kafka に流した後、
    published_at update。retention は published 後 30 日。
  - audit_local table：tier1/09 観測可能性 の audit signal
    の local 一次保管。ClickHouse への push が成功したら
    flush、retention は 7 日（先で hot tier 365 日）。
  - 双方とも CloudNativePG instance 内なので、PostgreSQL
    の preservation_class 規律で保全される。

■ archive_to_offline（cold tier）
  - retention 超過した base backup / WAL / Ceph object は
    archive_to_offline 経路に流れる：
        archive 先 1：Ceph RGW（別 region cluster、cold
                       tier）
        archive 先 2：手動 / 別契約（tape / 外部 cloud
                       bucket）
  - immutable：Ceph RGW Object Lock を Compliance mode で
    適用、retention 期限内は物理 delete 不可。
  - encryption：archive object は SSE-KMS（OpenBao 経由）+
    application-layer envelope encryption（08_暗号化方針）
    の二重。
  - 復元：archive_to_offline からの復元は manual runbook、
    完了 SLA は 24 時間（preservation_class 別 SLI 上）。

■ retention の物理 enforcement
  - retention 値は preservation_class が決め、KafkaTopic
    CR / CloudNativePG ScheduledBackup CR / ClickHouse TTL /
    Ceph RGW Lifecycle が物理 enforce する。
  - retention 値の application-side override は admission
    block（Kyverno require-preservation-class-annotation）。
  - retention 短縮（90日 → 30日）は新 preservation_class を
    切る形でしか表現できない（dimension override 禁止）。

■ RPO / RTO の物理保証
  - preservation_class 別 SLA：
        class                       | RPO     | RTO
        ---------------------------+---------+----------
        v1_local_only              | 24 h    | 4 h（手動）
        v1_zone_replicated         | 5 s     | 60 s
        v1_cluster_replicated      | 60 s    | 5 min
        v1_cross_region_replicated | 0       | 5 min
        v1_global_replicated       | 0       | 0 (continuous)
  - RTO は restore_drill で物理検証（11_復旧訓練方針）、
    drill 期限超過は admission block（Kyverno block-on-
    restore-drill-red）。
  - RPO は WAL archive lag / replication lag の SLI で常時
    監視、target を超過すると 13 SLO error budget burn と
    して連動。

■ 採用しない保全機構
  - logical backup（pg_dump）単独：online write 中の整合
    が保証できないため、CloudNativePG の base backup +
    WAL streaming を default。
  - external snapshot（Velero VolumeSnapshot）単独：DB
    consistent state の snapshot にならないため、補助
    （namespace / config / Secret backup）に限定使用。
  - 「retention は manual に設定」：全 retention は
    preservation_class が一意に導出、instance 個別 override
    禁止。
