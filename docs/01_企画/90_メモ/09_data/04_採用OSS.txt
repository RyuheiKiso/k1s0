============================================================
data 採用 OSS（data 層 subset）
============================================================

■ 位置づけ
  - 「02_採用OSS一覧」の grand catalog のうち、data 層が
    所有する OSS（DB engine / Stream / Cache / Analytics /
    Schema Registry / Migration tool）を抽出して整理した
    もの。Operator は infra 層所有として cross 参照で明記
    する（instance は data 層所有）。
  - 本ファイルの全 OSS は 05_tier1/14_OSSライフサイクル適合
    仕様 の oss_inventory.lock.yaml に v1_l1plus_primary と
    して登録される。

------------------------------------------------------------
[1] RDB（OLTP）
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  RDB engine                     | PostgreSQL             | PostgreSQL
  k8s Operator（infra 提供）     | CloudNativePG          | Apache 2.0
  接続プール                     | PgBouncer              | ISC
  vector index                   | pgvector               | PostgreSQL
  migration tool                 | sqlx-cli               | Apache 2.0 / MIT

  - PostgreSQL は major version skew ≤ 1（cluster 内 / cluster
    間）。CloudNativePG が rolling upgrade を物理層で実行。
  - PgBouncer は transaction pooling mode を default、session
    pooling は LISTEN/NOTIFY を使う場合のみ許容。
  - pgvector は OLTP 同居 vector search の標準。専用 vector
    DB は採用しない。
  - sqlx-cli は migration tool として 06_スキーマ運用方針 で
    versioned migration の真。

------------------------------------------------------------
[2] Stream / Messaging
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Stream broker                  | Apache Kafka           | Apache 2.0
  k8s Operator（infra 提供）     | Strimzi                | Apache 2.0
  CDC                            | Debezium               | Apache 2.0
  Schema Registry                | Apicurio Registry      | Apache 2.0
  Schema Registry（代替）        | Karapace               | Apache 2.0

  - Kafka は KRaft mode（ZooKeeper 廃止後）を本企画の標準。
    Strimzi が KRaft mode を物理 enforce。
  - rack awareness：Kafka broker は zone を rack として
    宣言、min.insync.replicas は rack 跨ぎで物理強制。
  - Debezium は Kafka Connect plugin として動作、独立
    process としては持たない。
  - Apicurio Registry を default、Karapace を代替（cluster
    単位で 1 つ選択、両方並走させない）。

------------------------------------------------------------
[3] Cache / KV
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  In-memory cache                | Valkey                 | BSD-3
  k8s Operator                   | Valkey Operator        | Apache 2.0
                                 | （or KubeBlocks）      |

  - Valkey は Redis 7.2.4 時点の BSD-3 fork（Linux Foundation
    管掌）。Redis（BUSL-1.1 化以降）は採用しない。
  - 本企画の Valkey は session / cache 用途のみ、SoR には
    ならない（preservation_class 上 v1_volatile な扱い）。
  - persistence（AOF / RDB）は無効が default。永続化が必要
    な場合は CloudNativePG / Kafka に降ろす。

------------------------------------------------------------
[4] Analytics（OLAP / signal SoR）
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Columnar OLAP                  | ClickHouse             | Apache 2.0
  k8s Operator（infra 提供）     | Altinity ClickHouse    | Apache 2.0
                                 | Operator               |
  分散調整（KRaft へ統合済）     | clickhouse-keeper      | Apache 2.0

  - ClickHouse は signal SoR（tier1/09 観測可能性 適合仕様）
    と OLAP query 用途を兼務。
  - Replicated MergeTree が cross-zone replication の物理
    強制機構。
  - clickhouse-keeper は ZooKeeper の Raft 互換代替、本企画
    では keeper を default（ZooKeeper は採用しない）。
  - tiered storage（disk_s3）：hot SSD（Longhorn）→ cold S3
    （Ceph RGW）の 2 段階を物理 enforce。

------------------------------------------------------------
[5] Backup / Restore
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Postgres backup                | Barman                 | GPL-3
                                 | （CloudNativePG 内蔵） |
  Volume snapshot                | CSI Snapshotter        | Apache 2.0
                                 | + Longhorn snapshot    |
  Object lock / WORM             | Ceph RGW Object Lock   | Apache 2.0
                                 |                        | / LGPL-2.1
  cluster 跨ぎ backup            | Velero                 | Apache 2.0

  - Barman は CloudNativePG が内部で利用、本企画では
    CloudNativePG 経由の backup を default、Barman 単独
    運用は持たない。
  - Velero は cluster 跨ぎ backup（namespace / PVC 単位）の
    補助、preservation_class の WAL 経路とは独立。
  - Ceph RGW Object Lock は immutable archive（v1_immutable
    系の augmenting）の物理機構として登録。

------------------------------------------------------------
[6] Migration / DDL Tooling
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Postgres migration             | sqlx-cli               | Apache 2.0 / MIT
  Kafka schema migration         | Apicurio CLI           | Apache 2.0
  ClickHouse migration           | go-migrate             | MIT
                                 | （ClickHouse driver）  |
  Schema diff                    | atlas（参照のみ）      | Apache 2.0

  - sqlx-cli が PostgreSQL 物理 migration の真。Liquibase /
    Flyway は採用しない。
  - go-migrate は ClickHouse の DDL versioning 用、
    sqlx-cli では ClickHouse driver を持たないため採用。
  - atlas は schema diff の visualization に参照利用、
    apply は GitOps + sqlx-cli/go-migrate のみ。

------------------------------------------------------------
[7] 観測補助（data 層自身の health 観測）
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Postgres exporter              | postgres_exporter      | Apache 2.0
  Kafka exporter                 | kafka-exporter         | Apache 2.0
                                 | + Strimzi metrics      |
  Valkey exporter                | redis_exporter         | MIT
                                 | （Valkey 互換）        |
  ClickHouse exporter            | ClickHouse 内蔵        | Apache 2.0
                                 | system table + Prom    |

  - 全 exporter の signal は tier1/09 観測可能性 SoR
    （ClickHouse）に集約。data 層自身の health metric も
    ClickHouse に store される（自己観測）。

■ 他層所有の OSS（cross 参照）
  - Operator 基盤：CloudNativePG Operator / Strimzi Operator
    / Altinity ClickHouse Operator / Apicurio Registry
    Operator → 08_infra（GitOps 配信）
  - PV / Object Storage：Longhorn / Rook+Ceph RGW → 08_infra
  - Schema Registry の使用面（schema 登録 / fetch / 進化判定）
    は tier1 → 05_tier1/12_スキーマ進化適合仕様
  - 鍵管理：OpenBao + External Secrets → 08_infra（基盤）/
    05_tier1/11_鍵管理適合仕様（鍵の意味論）
  - DB マイグレーション CLI（sqlx-cli）の binary は CI で
    artifact 化、配信は infra 経由

■ L1+ 深耕の徹底
  - 同一カテゴリで横並びの OSS を本番運用しない（cluster
    単位で 1 つに固定）。
  - 既採用 OSS の機能で吸収できる用件を、別 OSS の追加で
    解決しない（schema diff のために liquibase 追加 ×、
    sqlx-cli 内で吸収）。
  - 新 OSS の追加は 14_OSSライフサイクル適合仕様 の
    pair_target 移行手続を必ず経る。
