============================================================
data レプリケーション方針
============================================================

■ 一文方針
  - PostgreSQL は CloudNativePG Replica Cluster + WAL
    streaming、Kafka は Strimzi 内 ISR + cluster 跨ぎ
    MirrorMaker2、ClickHouse は Replicated MergeTree +
    macro replicas、Ceph は RGW multi-site、を default と
    する。replication topology は preservation_class が
    一意に導出する。

■ replication topology（preservation_class 別）
  - v1_local_only
      - PostgreSQL：primary のみ（standby なし）。
      - Kafka：RF=1（dev/stage 限定）。
      - ClickHouse：1 shard × 1 replica。
      - Valkey：単一 master。
      - cross-zone / cross-region replication なし。

  - v1_zone_replicated
      - PostgreSQL：1 primary + 2 sync standby（zone 分散）、
        synchronous_commit=remote_write、
        synchronous_standby_names='ANY 1 (...)'.
      - Kafka：RF=3, ISR=2、broker.rack=zone、
        unclean.leader.election.enable=false（split-brain
        防止）。
      - ClickHouse：1 shard × 3 replica（Replicated
        MergeTree、zone 分散）、clickhouse-keeper 3 nodes
        zone 分散。
      - Valkey：master + 2 replica、Sentinel quorum=2。

  - v1_cluster_replicated
      - PostgreSQL：v1_zone_replicated + 別 cluster に
        async standby（CloudNativePG cluster-to-cluster
        streaming）。
      - Kafka：v1_zone_replicated + MirrorMaker2 で別
        cluster に async mirror（topic prefix で source
        cluster を識別）。
      - ClickHouse：≥ 2 shard × 2 replica、cluster 内
        Replicated MergeTree + 別 cluster の Distributed
        table 経由 async push。
      - Valkey：Cluster mode（≥ 3 master、各 master に 1
        replica）、cross-cluster 同期なし（cache 用途）。

  - v1_cross_region_replicated
      - PostgreSQL：primary region に 1 primary + 1 sync
        standby、standby region に 1 sync standby（
        synchronous_commit=remote_apply、Replica Cluster
        モード）、**RPO ≈ 0**（同期 ack 必須・quorum loss
        中の primary write block 前提、commit-after-crash
        可視性は pg_failover_slots + 二段 fencing token で
        visibility-blocking 制御。詳細は 09_data/15 fence 設計）。
        書き込み点は primary region 単一、commit latency は
        cross-region RTT に支配される（standby region への WAL
        apply ack 往復が物理下限、infra01/15
        v1_multi_region_active_passive と双方向 lock）。
      - Kafka：primary region に RF=3, ISR=2、standby
        region に MirrorMaker2 で strict-ordering async
        mirror、failover 時 promote。produce 受付は primary
        region のみ（standby region への producer 直接接続
        は admission block）。
      - ClickHouse：primary region に Replicated MergeTree、
        standby region に macro replicas（keeper 跨ぎ）、
        DDL は ON CLUSTER で全 region 同期。
      - Ceph：RGW multi-site で primary → standby async
        replication、object lock は両 region で適用。

  - v1_global_replicated
      - PostgreSQL：cell-based partitioning、各 cell は
        per-region single-leader 構造（v1_zone_replicated
        と同型を per-cell で配置：1 primary + 2 sync
        standby を cell の home_region 内 zone 分散）。
        tenant ↔ cell の affinity で region 跨ぎ書き込み
        を物理排除（cross-region write は admission block
        で物理発生不能）。CAP 観点では「per-tenant 視点
        で synchronous + per-cell partition で AP」の合成
        であり、true multi-master ではない。
      - Kafka：cell-partitioned topic（partition key を
        cell_id で固定し、cross-cell の同 partition 書込
        を発生させない）。MirrorMaker2 は read-replication
        用途で双方向 mirror（同 partition の cross-region
        produce は producer 側 admission policy で block）。
      - ClickHouse：macro replicas は per-region replicated
        （keeper を region 内独立、cross-region は eventual）。
        書き込み非衝突は per-tenant region affinity で物理
        保証（同 row key の cross-region write を発生させない）。
        CRDT 系 MergeTree は v2 候補（v1 では採用しない、
        infra01/15 dimension の根拠と整合）。
      - Ceph：RGW multi-site bidirectional sync、object
        命名に cell_id / region prefix を含めて bucket
        単位の書き込み owner を home region に固定（同 object
        key の cross-region write を物理発生させない）。

■ CloudNativePG Replica Cluster
  - mode：streaming replication、synchronous_commit を
    preservation_class 別に固定：
        v1_local_only           : off（standby なし）
        v1_zone_replicated      : remote_write
        v1_cluster_replicated   : remote_write（同 region）
                                    + async（別 cluster）
        v1_cross_region_repl.   : remote_apply（同 region）
                                    + remote_apply（別 region）
        v1_global_replicated    : 各 cell 内で remote_write
                                    （cell の home_region 内
                                    zone 分散 sync）。cross-cell
                                    / cross-region の sync
                                    replication は持たない（tenant
                                    ↔ cell affinity で cross-cell
                                    write を物理発生させない）。
  - Replica Cluster CR：standby region 側に source primary
    の情報を CR で宣言、CloudNativePG が WAL streaming を
    確立。
  - failover：Argo Events trigger で standby を promote、
    runbook（infra01/15）と連動。promotion 後は旧 primary
    を fence + 再 attach（fallback 後の旧 primary 復旧）。
  - 物理機構：synchronous_commit は OS fsync 完了を待って
    commit、remote_apply は standby が WAL apply 完了を
    待つ。

■ Strimzi（Kafka）レプリケーション
  - cluster 内：rack awareness で broker を zone に紐付け、
    min.insync.replicas=2 を rack 跨ぎで物理強制。
    unclean.leader.election.enable=false で split-brain 時
    の data loss を physical block。
  - cluster 跨ぎ：MirrorMaker2 を Strimzi KafkaMirrorMaker2
    CR で deploy、source cluster → target cluster 方向で
    定義。
        - v1_cluster_replicated     : 単方向 async mirror
        - v1_cross_region_repl.     : 単方向 strict-ordering
                                        + offset translation
        - v1_global_replicated      : 双方向 mirror（read-
                                        replication 用途）。
                                        cell-partitioned topic
                                        を前提とし、partition key
                                        は cell_id に固定。同
                                        partition への cross-region
                                        produce は producer 側
                                        admission policy で物理
                                        block（true active-active
                                        produce ではない）。
  - topic 命名：mirror 先で `<source-cluster>.<topic-name>`
    prefix を付与（Strimzi default 規約）。
  - schema：Apicurio Registry の subject schema / compatibility
    rule / global rule は MirrorMaker2 では同期できない（MM2 は
    Kafka topic value のみを運び、Registry の `/rules` API
    metadata は対象外）。代わりに **GitOps SoT 経路** を採用：
    `apicurio_subjects/` git repo + `apicurio_rules.lock.yaml`
    を単一の真とし、Argo CD + Apicurio Operator が各 cluster へ
    declarative reconcile する。Registry API への直接 push は
    Kyverno admission で禁止（10_security/14 block-direct-
    apicurio-write）。詳細は 05_tier1/18_apicurio_gitops_sot
    と双方向 lock。

■ ClickHouse レプリケーション
  - 単一 cluster 内：Replicated MergeTree + clickhouse-keeper
    で part metadata を全 replica 同期、replica 障害時は
    残存 replica が読み書き継続。
  - 複数 cluster 間（同 region）：Distributed table を front、
    背後の Replicated MergeTree が複数 cluster で keeper
    cluster federation。
  - 複数 region：macro replicas、keeper を region 内独立
    （cross-region keeper はしない）、Distributed の
    `internal_replication=true` で cell 内に push。cross-
    region の同 row key への書き込みは per-tenant region
    affinity で物理発生させない（v1_global_replicated）。
    macro replicas の cross-region 間 propagation は
    eventual で、書き込み非衝突は data 層 admission の
    write owner 制約に依る。
  - DDL：ON CLUSTER 句で全 replica 同期適用、keeper が
    順序保証。

■ Valkey レプリケーション
  - 範囲：cache 用途、永続化対象外、cross-cluster 同期
    なし。
  - cluster 内：Sentinel mode（≤ v1_cluster_replicated）/
    Cluster mode（≥ v1_cross_region_replicated）。
  - cross-region：同期しない（cache の divergence を許容、
    application 側で再 fetch）。
  - 永続化が必要な KV は CloudNativePG / Kafka に降ろす。

■ Ceph RGW multi-site
  - mode：master zone（primary region）+ secondary zone
    （standby region）、bidirectional は v1_global_replicated
    時のみ。
  - bucket 単位 replication policy、object lock は両 zone で
    同一適用。
  - 物理：RGW の sync agent が pull、object 単位で eventual
    consistency。

■ replication lag SLI
  - 各 replication 経路に lag SLI を持つ（13 SLO 適合仕様
    と整合）：
        v1_replication_lag_postgres     : pg_stat_replication
                                          .replay_lag
        v1_replication_lag_kafka_mm2    : MirrorMaker2 metric
                                          per topic
        v1_replication_lag_clickhouse   : keeper の queue 長
        v1_replication_lag_ceph         : multi-site sync
                                          status
  - lag が preservation_class の RPO target を超過すると
    13 SLO error budget burn として連動、admission policy
    が新規書き込みを段階的に slow（write quota burn）。

■ split-brain 防止
  - PostgreSQL：synchronous_commit + Replica Cluster の
    quorum 構造で primary 二重昇格を不可能化、CloudNativePG
    が fence 制御。
  - Kafka：unclean.leader.election=false、ZooKeeper（KRaft）
    が leader election quorum で物理保証。
  - ClickHouse：clickhouse-keeper の Raft quorum で part
    metadata の整合保証、minority partition は read-only。
  - Ceph：RGW multi-site の master / secondary は明示的、
    split-brain 時は secondary が read-only。
  - 物理機構：infra topology_class と data preservation_
    class が双方向 lock、片方だけ宣言する経路は admission
    block：
        - v1_multi_region_active_passive ↔ v1_cross_region_
          replicated（書き込み点単一 region、sync WAL apply）
        - v1_multi_region_active_active  ↔ v1_global_
          replicated（cell-partitioned、tenant ↔ cell affinity
          で cross-cell 書き込みを物理発生させない）
    cross-region の同 partition / 同 row key / 同 object
    key への並行書き込みは admission policy で物理 block
    される（true multi-master / CRDT は v1 で採用しない）。

■ failover orchestration（data 層担当部分）
  - infra 15_クラスタ位相適合仕様 の 5 orchestrator のうち、
    data 層が物理 trigger を提供するもの：
      - external_dns_multi_region：DNS 切替後に data 層
        endpoint（PostgreSQL primary / Kafka bootstrap）が
        新 region を指す
      - argo_rollouts_traffic_shift：standby promote 完了
        を Argo Events が検知、rollout が traffic を切替
  - data 層が単独で動かす機構：
      - CloudNativePG の auto-promote（standby quorum
        majority が WAL を apply 完了したら promote）
      - clickhouse-keeper の leader election（keeper 側
        Raft）
      - Kafka KRaft controller の leader election

■ 採用しない replication 機構
  - PostgreSQL logical replication multi-master（pglogical
    multi-master）：v1 では single-primary に固定。
  - Kafka Cluster Linking（Confluent Community）：MM2 一本。
  - ClickHouse の non-Replicated MergeTree：必ず Replicated
    を採用（dev でも）。
  - dual-write 同期：Outbox + CDC のみで heterogeneous
    replication（02_非提供スコープ と整合）。
  - manual promote（人間が runbook を叩く）：Argo Events
    trigger による自動 promote、runbook は再現可能 script
    として artifact 化（手動経路は dev/stage の v1_local_
    only のみ）。
