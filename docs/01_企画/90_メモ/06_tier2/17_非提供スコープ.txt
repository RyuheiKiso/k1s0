============================================================
tier2 の非提供スコープ
============================================================

■ tier3 固有業務ロジック
  - 個別業務の画面遷移・帳票レイアウト・ユーザー操作シナリオ等、
    特定の tier3 アプリケーションにのみ必要な業務ロジックは
    tier2 の責務外。
  - tier3 が業務固有の差分を表現する手段は override（「07_業務
    資産所有権」参照）に限定する。override 拡張点に乗らない
    差分が必要になった場合、その差分は本来 tier2 で吸収すべき
    ものでないか / 拡張点設計が不足していないかを先に検討する。

■ UI / 画面
  - 画面・コンポーネント・スタイリングは tier3 の責務。tier2
    は UI を提供しない。
  - 帳票・PDF 生成等の出力フォーマットも tier3 の責務とする。
    tier2 は帳票生成のための業務データ（明細・集計）を Library
    / Service で提供するに留める。

■ 新規 infra 抽象
  - 「tier1 が抽象化していない OSS をラップする」ことは禁止
    する。必要な infra 抽象は tier1 に新規カテゴリとして提案
    する（「02_位置づけ」参照）。
  - tier2 内に「内部用 infra ヘルパ」を作り、それを tier3 から
    間接的に使わせる経路も禁止する。

■ 業界外への想定
  - 1.0.0 出荷時点で tier2 が想定する業界は製造業のみ。それ
    以外の業界向けの暫定対応・部分対応は本リリースに含めない。
  - 業界 pack の追加は「03_業界拡張モデル」で定めた手順に従う。
    暫定的な業界横断層への業界固有概念の混入は禁止する。

■ tier1 の責務領域
  - Observability / Authentication / Secret / RPC / KeyValue /
    Object Storage / Messaging / Workflow / Rule Engine 等、
    tier1 が提供する機能カテゴリは tier2 で再ラップしない。
  - tier2 は当該カテゴリを業務語彙に翻訳して tier3 に提供する
    が、tier1 と等価な抽象を二重に持つことはしない。

■ 開発体験 / 運用ツール
  - Backstage / Testcontainers / Tilt / Helm / Kustomize 等は
    tier2 のスコープ外（「05_tier1/06_非提供スコープ」と同様、
    プラットフォーム側で扱う）。
  - tier2 は Backstage の Software Template に従ってリポジトリ
    生成される対象としては関与する（強制機構の組込先として）。

■ 業務固有の長期データ分析
  - 業務 KPI ダッシュボード・データウェアハウス向けの業務分析
    マートの設計は tier2 の責務外。tier2 は Domain Event /
    監査ログ等の素材を提供するに留め、分析側は別途データ層 /
    BI ツールで構築する（「03_プラットフォーム構成」data 層
    と整合）。
