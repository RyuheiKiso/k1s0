============================================================
tier1 スキーマ進化適合仕様（v1）
============================================================

■ 位置づけ
  - 「02_採用OSS一覧」Buf / Apicurio Registry / Karapace / sqlx-cli /
    OpenTelemetry Weaver、「03_Server系」Proto 二層化、「05_提供機能
    カテゴリ」Schema Registry / Domain Event、「06_tier2/11_表現手段」
    （proto / Avro / DDL / yaml）、「06_tier2/13_互換性ポリシー」、
    「06_tier2/16_強制機構」（Buf custom lint）、「06_tier2/32_テナント
    分離適合仕様」（migration ヘッダ）、「07_tier3/30_互換性ポリシー」
    が散在的に宣言する schema_kind / 互換性 mode / deprecation lifecycle
    / breaking change policy / registry backend を、機械可読な単一の真
    として一箇所に固定する仕様書。
  - 「05_tier1/07_Bidi適合仕様」「06_tier2/32_テナント分離適合仕様」
    「05_tier1/10_認証適合仕様」「05_tier1/11_鍵管理適合仕様」と同型
    の枠組みを schema 軸に転写したもの。dimension override 禁止 /
    dead spec 殺し / build artifact 化 / 5 層 defense-in-depth の規律
    はそのまま継承する。
  - 「同 aggregate を表す proto / event / DB column / SemConv 属性が
    drift しない」cross-axis schema sync property を本仕様が単一所有
    する。proto / Avro / DDL / yaml の 4 軸（OTel SemConv 含めると 5
    軸）を一つの aggregate_qualified_name 名前空間で束ねる。

■ 設計原則
  - schema_class は bundle である。
      schema 宣言（proto file 先頭 / Avro subject metadata / migration
      ヘッダ / config yaml header / Weaver model）に書く schema_class
      1 つの値が、他 4 dimension（compatibility_mode / deprecation_
      period / breaking_change_policy / registry_backend）を一意に
      導出する。schema 作者が dimension を個別に override する経路
      は持たない。
  - dimension override は禁止する。
      「v1_event_avro のうち deprecation を 12 ヶ月に縮めたい」要望
      は新 class を切ることで表現する。class 数の爆発は意味論の規律
      として受け入れる。
  - dead spec を CI で殺す。
      classes.yaml に登録された全 class、scenarios.yaml に登録された
      全 assertion id、registries.lock.yaml に列挙された全 registry
      backend は、いずれも参照されなくなった時点で CI fail とする。
      かつ aggregate_qualified_name registry に登録された aggregate
      が 4 軸（proto / event / DB / SemConv）の少なくとも 1 軸からも
      参照されない場合も dead 扱いとして CI fail。
  - 単一の真は「位置」ではなく「導出関係」で守る。
      「同 aggregate name の field 名と型が 4 軸で一致する」property
      は machine 集約で検証する。proto を権威とする / DDL を権威と
      する のような片寄せは取らず、各軸が同名で同型の declaration を
      持つことを invariant とする。差異は CI で fail。
  - codegen 出力は build artifact とし手書き禁止。
      proto → 各言語 stub、proto → Avro schema（mappable subset）、
      proto → DDL ヘッダ、proto → SemConv attribute schema は build
      artifact。手書き diff は CI fail。
  - defense-in-depth は 5 層で構成する。
      層 A : compile 時（codegen 出力のみ消費、生 schema 文字列なし）
      層 B : lint（Buf breaking / Apicurio compat API / sqlx-cli plugin
              / Weaver validate / yaml schema validation）
      層 C : cross-version integration test（n-1 / n+1 互換性）
      層 D : registry runtime（Apicurio が違反 schema を reject）
      層 E : cross-axis sync property（proto + DB + event + SemConv
              の同 aggregate 名で field / type 同形）
      任意の単層が破れても他層が必ず止める。registry runtime と
      cross-axis sync が最終 safety net。

■ v1 schema_class セット（6 class）
  - schema 宣言に書ける schema_class は次の 6 値のみ。各 build script
    は registries.lock.yaml の枝で classes.yaml の keys と照合する。

      class                | schema_kind     | compatibility_mode               | deprecation_period | breaking_change_policy        | registry_backend
      ---------------------+-----------------+----------------------------------+--------------------+-------------------------------+--------------------
      v1_external_proto    | proto_external  | BACKWARD                         | months_12          | major_only                    | buf_bsr
      v1_internal_proto    | proto_internal  | NONE                             | not_applicable     | additive_with_migration       | buf_bsr_internal
      v1_event_avro        | event_avro      | FULL                             | months_24          | major_with_dual_write         | apicurio
      v1_db_ddl            | db_ddl          | forward_backward_via_migration   | not_applicable     | additive_with_migration       | sqlx_migrations
      v1_config_yaml       | config_yaml     | BACKWARD                         | months_6           | additive_only                 | yaml_in_repo
      v1_otel_semconv      | otel_semconv    | FULL                             | months_12          | additive_only                 | weaver

  - 各 class の不変条件と典型用途：

      - v1_external_proto
          - 「03_Server系」二層化の External 層 RPC / message。
            Companion 経由 .NET Framework や第三者 client が消費する
            wire 互換契約。
          - BACKWARD：新 server が旧 client を破らない。field 追加は
            optional + reasonable default に限定、enum 削除禁止、
            type widening 禁止（int32→int64 でも広い側で書くと旧
            client が parse できない場合があり禁止）。
          - deprecation 12 ヶ月：deprecated 宣言から 12 ヶ月経過後
            に削除可能。deprecation 期間中は wire 互換維持。
          - breaking change は major version up（vN_external_proto
            → v(N+1)_external_proto）でのみ許可、移行 toolchain を
            tier1 が提供（08 同枠）。
          - 典型：Companion / 第三者連携の wire API、tier2 / tier3
            から外向きに公開する RPC。

      - v1_internal_proto
          - 「03_Server系」二層化の Internal 層 RPC / message。tier1
            内 / Backend-for-Library 内 / tier2 Service 間で消費。
            wire を外に出さない。
          - 互換性は NONE：breaking 変更を additive_with_migration
            ポリシーで日々許容。代わりに deploy 時に新旧 server /
            client を一括更新する Argo Rollouts（02 OSS）の制約と
            連動する。
          - deprecation 期間なし：unused 化と同時に削除可能。
          - 典型：tier1 内 control plane RPC、tier2 Service 間
            内部 API、Outbox relay の internal queue 形式。

      - v1_event_avro
          - 「06_tier2/24_読み取りモデル方針」Domain Event の
            Apicurio Registry 上 Avro schema。
          - FULL：subscriber と producer の双方向互換。field 追加
            は default 必須、削除は default 必須、type widening 不可。
          - deprecation 24 ヶ月：subscriber が長期 backlog を持つ
            可能性に対応する保守的期間。
          - breaking は major + dual_write：新旧 schema で並行
            publish し、subscriber が新側に切替えた後に旧側を停止。
          - 典型：tier2 Domain Event、Outbox relay payload。

      - v1_db_ddl
          - 「06_tier2/32」migration 由来 DDL。sqlx-cli + 32 の
            migration ヘッダで管理。
          - 互換性 forward_backward_via_migration：rolling upgrade
            中に旧版 / 新版 server が同時稼働する window で双方が
            動くこと。NOT NULL 列追加は default 必須、column rename
            は二段階（add new + dual write + drop old）、type
            change は背景 batch + invariant 維持。
          - deprecation なし：drop column は dual write 完了後に
            実行、別 migration として記録。
          - breaking は additive_with_migration：互換性 break する
            DDL は許容しない（dual write で常に互換維持）。
          - 典型：tier2 業務 entity、Outbox / Audit infrastructure
            tables、read model projection。

      - v1_config_yaml
          - tier1 / tier2 / tier3 の config yaml（feature flag /
            quota / SLO / 業界 pack 定義 / route_atlas 等）。
          - BACKWARD：新版 reader が旧版 yaml を読める。key 追加
            は default 必須、key 削除は deprecation 期間後。
          - deprecation 6 ヶ月：config の lifecycle が短いため。
          - breaking は additive_only：key 削除 / 名前変更は
            deprecation 経由のみ。
          - 典型：tier3 アプリ config、Backstage Software Template
            生成 yaml、route_atlas.yaml、visual_matrix.yaml 等。

      - v1_otel_semconv
          - 「02_OSS」OpenTelemetry Weaver で管理する SemConv tier1
            拡張（業界 attribute / 業務 attribute 命名）。
          - FULL：log / span / metric attribute は producer / consumer
            の双方向互換。
          - deprecation 12 ヶ月：consumer（ClickHouse 集計、
            Perses dashboard、09 redaction.yaml）が依存するため。
          - breaking は additive_only：attribute 削除 / rename は
            deprecation 経由のみ。
          - 典型：09 audit signal の sub-class 属性、tier2 業務
            attribute、tier3 RUM attribute、key.operation 属性
            （11 と接続）。

  - 上記 6 class で v1 が covering。製造業 pack 想定 8 業務シナリオ
    の stress test を本仕様末尾に示す。

■ dimension の根拠
  - schema_kind は backend dispatcher として最上位に置く。proto は
    Buf BSR、Avro は Apicurio、DDL は sqlx migrations、yaml は repo
    内、SemConv は Weaver と、検証 / 配布 / breaking 検出 toolchain
    が完全に異なるため独立 dimension。
  - compatibility_mode は consumer の挙動を機械的に決める。
    BACKWARD は新 server / 旧 client、FORWARD は逆、FULL は双方向、
    NONE は同期 deploy 前提、forward_backward_via_migration は DDL
    特有の rolling upgrade window 互換性。
  - deprecation_period は consumer の更新猶予を決める。external
    （第三者）は長め、internal は短め、event は最長（subscriber
    backlog 想定）。
  - breaking_change_policy は major version up の発動条件と migration
    toolchain の有無を決める。additive_only は break 自体を禁止、
    additive_with_migration は dual write で break を吸収、major_only
    / major_with_dual_write は明示 major up + 移行 toolchain 必須。
  - registry_backend は schema の物理保管先と検証経路を決める。
    backend を class に bundle することで「同 class 内で複数 backend
    を使い分ける」ような分散を排除し、単一の真を維持する。

■ derived dimension（field-level invariant）を独立次元にしない理由
  - field-level の不変条件（required / optional / repeated / map /
    enum / oneof）は class が定める compatibility_mode に従属する：
        v1_external_proto    → optional のみ追加可、enum 値追加可
        v1_internal_proto    → 任意（同期 deploy で吸収）
        v1_event_avro        → default 必須
        v1_db_ddl            → NOT NULL は default 必須
        v1_config_yaml       → 必須 key 追加は default 必須
        v1_otel_semconv      → 必須 attribute 追加禁止
  - field-level rule を独立 dimension にすると class 数が指数化する
    ため、class が暗黙の不変条件として保持する形に留める。
  - v2 で「field-level な per-RPC 互換性 override」需要が出た時点
    で独立次元昇格を検討する余地は残す（major version up）。

■ aggregate_qualified_name 名前空間（cross-axis 同型の鍵）
  - 4 軸（5 軸）に跨る aggregate を表す共通名前空間を本仕様が単一
    所有する：
        <industry>.<domain>.<aggregate>
        例：manufacturing.procurement.purchase_order
  - 4 + 1 軸での declaration 形式：
        proto:    package manufacturing.procurement.v1;
                  message PurchaseOrder { ... }
        avro:     namespace = "manufacturing.procurement"
                  name      = "PurchaseOrderEvent"
                  aggregate_qualified_name = "manufacturing.procurement.purchase_order"
        DDL:      schema = manufacturing
                  table  = procurement_purchase_order
                  -- @aggregate_qualified_name: manufacturing.procurement.purchase_order
        config:   tier2/packs/manufacturing/procurement/purchase_order.yaml
        SemConv:  attribute group "manufacturing.procurement.purchase_order"
  - 各軸の declaration は同名 aggregate に対し同 field 集合 / 同型
    制約を満たすこと（後述 cross-axis sync property）。
  - 名前空間自体の lifecycle は v1_config_yaml で管理し、
    aggregate_registry.yaml に全 aggregate が登録される。

■ 5 層 defense-in-depth

  ── 層 A : compile 時（codegen 出力のみ消費）
      - 業務コード（tier2 / tier3）は build artifact となった
        codegen 出力（generated stub / Avro Java/Rust class /
        SQL query macro / yaml schema 型）を消費するのみ。
      - schema 文字列を runtime で動的 parse する経路を Library
        が提供しない（reflection 系 API 禁止）。
      - generated stub と元 schema の hash を build script が
        bundle し、不一致は compile fail。

  ── 層 B : lint
      - Buf custom lint：proto に schema_class option 必須、aggregate_
        qualified_name option 必須、両者が aggregate_registry.yaml
        と一致。breaking check は previous release tag に対して。
      - Apicurio compatibility API：publish 前に compatibility_mode
        check。違反は publish 自体が API エラー。
      - sqlx-cli plugin：migration ヘッダ（@table_class / @aggregate_
        qualified_name / @schema_class: v1_db_ddl）を必須化、欠落で
        fail（32 と統合）。
      - Weaver validate：SemConv attribute namespace が aggregate_
        registry に存在することを確認。
      - yaml schema validation：v1_config_yaml class の全 yaml に
        対し JSON Schema / cue.lang 検証必須。

  ── 層 C : cross-version integration test
      - n-1 / n / n+1 三世代の server / client / consumer を
        Testcontainers で同居させ、scenarios.yaml の cross_version_
        compatibility cell が全 green を返すことを CI で検証。
      - v1_external_proto / v1_event_avro / v1_db_ddl の三軸で
        rolling upgrade simulation を property test として実装。

  ── 層 D : registry runtime
      - Apicurio Registry が compatibility 違反 publish を 4xx で
        reject。
      - Buf BSR が breaking push を CI gate で reject（PR ブロック）。
      - sqlx-cli は migration plan で違反 DDL（type rename without
        two-phase 等）を fail。
      - Weaver は attribute drift（SemConv 内の rename without alias）
        を validate command で fail。
      - 本層は Apicurio / BSR / sqlx / Weaver の物理機構が schema
        進化規律を runtime で塞ぐ最終 safety net。

  ── 層 E : cross-axis sync property
      - aggregate_registry.yaml の各 aggregate について、proto
        message field 集合 / Avro record field 集合 / DB column
        集合 / SemConv attribute 集合の対応を property test で
        検証。
      - 対応 rule：
          - proto field name ↔ DB column name（snake_case）
          - proto field type ↔ DB column type（許容変換 table）
          - proto field name ↔ Avro field name（同名）
          - proto field name ↔ SemConv attribute name（domain. を prefix）
      - drift（同 aggregate の 4 軸で field 集合が一致しない）は
        CI fail。
      - tier2 / tier3 が新 field を proto に追加する PR は、自動
        codegen で DB migration / Avro schema / SemConv attribute
        を同時生成する Backstage Software Template で発動する。

■ 命名規約と aggregate_qualified_name の単一所有
  - aggregate_qualified_name は <industry>.<domain>.<aggregate> の
    snake_case 3 階層で固定。
  - 業界（industry）は v1_config_yaml の industry_registry.yaml で
    登録（manufacturing / cross_industry / service / public 等、
    08 業界横断 stub と整合）。
  - domain は industry pack（38_製造業pack 等）の bounded context
    と一致する。
  - aggregate は DDD aggregate root と一致。
  - tier2 業務エラーコードの命名（D2 改善、`<taxonomy>.<pack>.
    <domain>.<aggregate>.<subtype>`）と整合。tier2 / tier3 から
    新 aggregate を生やす経路は Backstage Software Template の
    scaffold のみとする。

■ Buf custom lint と各 toolchain の責務（縮約）
  - Buf custom lint の責務：
      1. proto に書かれた schema_class が classes.yaml の keys に
         存在し、proto file は schema_kind と一致（external proto
         file が v1_internal_proto を宣言したら fail 等）。
      2. RPC / message に aggregate_qualified_name option 必須、
         aggregate_registry.yaml と整合。
      3. previous release tag に対する breaking check（v1_external_
         proto は BACKWARD、v1_internal_proto は NONE）。
      4. deprecated field の使用 / 削除を deprecation_period に基づ
         き機械検査。

  - Apicurio plugin の責務：
      1. publish 時に compatibility_strategy = BACKWARD_TRANSITIVE
         を class から強制。
      2. subject metadata に aggregate_qualified_name + schema_class
         を必須化、欠落で publish reject。

  - sqlx-cli plugin の責務（32 と統合）：
      1. migration ヘッダ @schema_class: v1_db_ddl を必須化。
      2. NOT NULL 列追加に default が無い場合 fail。
      3. column rename を一段階で行う migration を fail（two-phase
         必須）。

  - Weaver plugin の責務：
      1. attribute namespace が aggregate_registry に存在すること。
      2. attribute rename は alias を経由すること。
      3. emit 出力（span_schema / metric_schema / log_schema）と
         09 redaction.yaml の整合（PII attribute の drop 宣言）。

  - yaml schema plugin（v1_config_yaml）：
      1. 全 v1_config_yaml class の yaml に対し JSON Schema / cue
         検証必須。
      2. schema 自体も build artifact（proto / Avro と同枠）。

■ Capability Negotiation との関係
  - 03 Capability Negotiation / 10 chosen_idp_adapter / 11 chosen_
    key_backend と並ぶ chosen_registry を起動時に決める：
      1. 全 schema_class C を取得。
      2. lock.yaml で C を supports に含む registry 集合 R を抽出。
      3. constraints 節を満たさない registry を R から除外。
      4. サーバ側で定義された優先順位でソートして chosen_registry
         を返却。
  - lock.yaml は build artifact、deploy 中に動的に書き換わらない。

■ CI 不変条件（4 ファイル + 5 層の関係性検査）
  - 違反は merge 不可。
      整合 1 : classes.yaml の全 class が scenarios.yaml の matrix
               条件で少なくとも 1 scenario によりカバーされる。
      整合 2 : scenarios.yaml の全 assertion id が、それを必要とする
               全 class × 全 backend × 全対応言語で実装されている。
      整合 3 : registries.lock.yaml で claim される class が classes
               .yaml に存在する。
      整合 4 : classes.yaml の全 class がいずれかの backend から
               supports される（unreachable class 検出）。
      整合 5 : registries.lock.yaml は手書き禁止、build artifact と
               git 上の差分検出。
      整合 6 : aggregate_registry.yaml の全 aggregate が最低 2 軸
               の declaration を持つ（孤立 aggregate 検出）。
      整合 7 : aggregate_registry.yaml に登録された全 aggregate が
               proto / event / DB / SemConv 軸の少なくとも 1 軸
               実体に対応する（dead aggregate 検出）。
      整合 8 : cross_axis_aggregate_sync の全 cell（aggregate ×
               cx_*_match）が green。
      整合 9 : codegen_hermeticity の全 cell（class × ch_*）が
               green。`make regen && git diff --exit-code` を全
               リポジトリに必須化。
      整合 10: deprecation_lifecycle 計算が全 deprecated field /
               attribute / column について dl_no_removal_before_
               window_end を満たす（時計駆動 CI）。
      整合 11: tier2 業務エラーコード命名（D2、<taxonomy>.<pack>.
               <domain>.<aggregate>.<subtype>）と aggregate_registry
               の <industry>.<domain>.<aggregate> が整合。
      整合 12: schema_class option が proto / Avro subject /

■ v2 拡張ルール
  - 新 class の追加は purely additive：v1 class はそのまま残し、v2
    で新規 class（例：v2_graphql_sdl、v2_arrow_ipc、v2_distributed_
    sql_ddl）を追加する。
  - 既存 class の dimension 値変更は破壊的変更（major version up）。
    例えば v1_event_avro の deprecation を 12 ヶ月に縮める場合、新
    class v2_event_avro_short を切り、移行 toolchain（08 と同型）を
    tier1 が提供する。
  - 命名は vN_<schema_kind>_<variant?> 形式。
  - dimension override 禁止の規律は v1 → v2 跨ぎでも維持する。
  - registry backend の変更（Apicurio → 別 OSS）は 14_OSS lifecycle
    適合仕様の v1_l1plus_primary → v1_l1plus_pair_target 経路で吸収。
    本仕様の class / scenario は無変更で registries.lock.yaml のみ
    更新。

■ 長期収斂への作用
  - 本仕様の 4 ファイル + aggregate_registry に対し、新業界 pack
    / 新業務 aggregate の追加は purely additive。Backstage Software
    Template が proto / Avro / DDL / SemConv / yaml の同時生成を
    機械化する。
  - L1+「単一 OSS 深耕 + 移行コミットメント」の哲学を schema 軸に
    転写したもの（単一 schema 進化規律 + registry backend 移行
    コミットメント）。Buf BSR / Apicurio / sqlx / Weaver が L1+
    primary、Karapace が L2* 同族、各々の lifecycle event は
    14_OSSライフサイクル適合仕様で管理。
  - cross-axis schema sync property は schema 軸内で完結せず、tier2
    の業務エラー命名 / tier3 の form codegen / 09 の redaction /
    11 の AAD と機械的に接続される。本仕様が aggregate_qualified_
    name の単一所有者として、5 軸（proto / event / DB / SemConv /
    config）+ 5 軸同型（07 / 08 / 09 / 32 / 39）+ 6 新軸（10 / 11
    / 12 / 13 / 14 / 15）の全結節点で aggregate name を提供する。
