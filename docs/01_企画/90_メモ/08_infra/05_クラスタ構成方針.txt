============================================================
infra クラスタ構成方針
============================================================

■ 一文方針
  - cluster は topology_class（15_クラスタ位相適合仕様）の
    宣言で形が決まり、OpenTofu で IaC 化、Argo CD で配信
    される。手動操作で構築・変更する経路は持たない。

■ ノードタイプ
  - control plane node：
      - kube-apiserver / etcd / kube-controller-manager /
        kube-scheduler を hosting
      - 最小 3 台、奇数（quorum 維持）
      - kube-vip + Layer2 / BGP で control plane VIP 提供
      - workload は taint で排除（node-role.kubernetes.io/
        control-plane:NoSchedule）

  - worker node：
      - tier1 / tier2 / tier3 / data の Pod を hosting
      - topology_spread_constraints で zone 跨ぎ均等配置
      - kubelet eviction policy で node 障害時に Pod を
        他 node へ migrate

  - infra-tools node（オプション）：
      - Argo CD / Argo Rollouts / Argo Events / Kyverno
        / cert-manager / OpenBao / Litmus を hosting
      - taint：infra-tools=true:NoSchedule
      - tier 各層の Pod が混入しないよう物理隔離

  - storage node（**二系統に物理分離**）：
      - storage-ceph node（Rook+Ceph 専用）:
          - OSD / monitor / RGW / CephFS MDS を hosting
          - taint：storage-ceph=true:NoSchedule
          - device path は Ceph 専用に固定（`bluestore` 用 raw
            partition、CRUSH map で zone 跨ぎ配置）
          - local SSD / NVMe を CRUSH map で zone 跨ぎ配置
      - storage-longhorn node（Longhorn 専用）:
          - Longhorn replica engine / instance manager を hosting
          - taint：storage-longhorn=true:NoSchedule
          - device path は Longhorn 専用に固定（`/var/lib/longhorn`
            mount を独立 disk に置き、Ceph と device 競合しない）
      - 両系統の混在禁止：raw disk / device path / udev rule
        / OSD discovery が衝突するため、同一 node に両 taint
        を併設しない。05_クラスタ構成方針 / 07_ストレージ方針 /
        15_クラスタ位相適合仕様 で双方向 lock。

■ etcd 構成
  - control plane node 上に co-locate（kubeadm default）
    または external etcd cluster の二択。本企画は v1 では
    co-locate を default、v2 で external 候補。
  - quorum 維持：minimum 3 node、推奨 5 node。
  - WAL / data dir は local SSD（NVMe 推奨）、Ceph PV は
    使用しない（latency 観点）。
  - snapshot は cron で 1 時間ごと、object storage（Ceph
    RGW）に転送。restore 手順は Argo Events runbook 化。

■ Pod 配置原則
  - topology_spread_constraints が全 Deployment / StatefulSet
    に必須（layer A：compile）。
      - topologyKey: topology.kubernetes.io/zone
      - whenUnsatisfiable: DoNotSchedule
      - maxSkew: 1
  - PodDisruptionBudget が全 Deployment / StatefulSet に
    必須（layer A：compile）。
      - minAvailable: ⌈replicas × 2/3⌉ または
      - maxUnavailable: 1（StatefulSet）
  - Affinity / Anti-Affinity：
      - tier1 Server / tier2 Service：node anti-affinity
        で同 node に同 pod を避ける
      - data 層 Pod：zone anti-affinity で zone 跨ぎ replica
  - Priority Class：
      - system-critical（control plane / cni / csi）
      - infra-critical（Argo CD / Kyverno / cert-manager）
      - business-high / business-default / business-batch
      - dev-best-effort

■ namespace 規約
  - 階層的 namespace（Hierarchical Namespace Controller / HNC）
    で tier1 / tier2 / tier3 / infra-tools を root とした
    sub-namespace 階層を維持。
      - tier1-system
        ├ tier1-server
        ├ tier1-library-runtime
      - tier2-<domain>
        ├ tier2-<domain>-service
        ├ tier2-<domain>-data
      - tier3-<app>
      - infra-tools
        ├ argocd
        ├ kyverno
        ├ cert-manager
        ├ openbao
      - data-stores
        ├ postgres-<tenant-pod>
        ├ kafka
        ├ clickhouse
        ├ valkey
  - tenant 用 namespace：tier2-<domain>-<tenant> の形で
    isolation、32 RLS と相補的。

■ kubeconfig / アクセス制御
  - 人間オペレータは Backstage 経由で kubeconfig を発行
    （短期 OIDC token、最大 8 時間）。kubeconfig の長期
    保有は禁止。
  - Argo CD / Argo Rollouts / Argo Events / Kyverno は
    ServiceAccount + RBAC で必要最小限の権限。
  - cluster-admin 権限は break-glass 用途のみ、OpenBao の
    response wrapping で発行、使用時に audit signal 必須。

■ cluster lifecycle
  - 構築：OpenTofu plan → PR → Argo CD sync で cluster
    bootstrap。手動 kubeadm init は禁止。
  - 更新：minor version skew ≤ 1、rolling upgrade window
    ≤ 30 日。upgrade は GitOps PR で trigger、Argo Rollouts
    で canary 評価。
  - 廃棄：OpenTofu destroy plan → 段階的 namespace drain →
    PV snapshot を cold tier に永久保存（09_data/01 と整合）
    → cluster 削除。
  - 再構築検証：dev cluster で四半期に 1 回、OpenTofu replay
    による完全再構築を実演（dr drill）。

■ at-rest / in-transit 暗号化
  - etcd encryption at rest：aescbc / kms provider で必須化。
    encryption key は OpenBao 管理、11 鍵管理適合仕様の
    v1_kek と整合。
  - PV at-rest 暗号化：Ceph RBD は Linux Unified Key Setup
    （LUKS）または Ceph 自体の at-rest encryption。CephFS /
    RGW も同様。
  - in-transit：cluster 内通信は Istio mTLS（PERMISSIVE 経過
    後 STRICT）、cluster 跨ぎは Istio multi-primary mesh の
    mTLS。kube-apiserver は TLS 1.3。

■ region 別 HSM partition の物理配置（KEK Shamir 分散の前提）
  - v1_data_kek（11 鍵管理適合仕様）の KEK material は単一
    region の単一 HSM partition に物理存在しない。N region
    （既定 N=5、05_tier1/17 と双方向 lock）に独立 HSM partition
    を配置し、各 region は Shamir share を 1 個のみ保持する。
  - 物理配置原則：
      - 各 region の HSM partition は別 vendor を許容
        （vendor_diversity: allowed_per_region）。1 vendor の
        firmware 脆弱性が全 region 同時失効を起こさない冗長設計。
      - 各 region の HSM は OpenBao instance（PII cluster 内 +
        業務 cluster 内それぞれ独立）に PKCS#11 backend で接続。
      - cross-region の HSM session は確立しない（OpenBao 自体は
        per-cluster confined を維持、Vault Enterprise の
        Performance/DR Replica は採用不能）。
      - share 復元 ceremony 時のみ、運用者が M region 健全時に
        各 region の OpenBao API 経由で share を取得し、ceremony
        host（air-gapped）上で閾値復元を実施（05_tier1/17 runbook）。
  - region 障害時の continuity：N=5 / M=3 の既定で 2 region
    完全断まで KEK 物理復元継続可能。3 region 以上の同時断は
    意図的に「鍵を取れない」状態とし、不正アクセス防御を優先
    （13_test/09 chaos drill で年次検証）。
