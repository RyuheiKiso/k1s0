============================================================
infra オートスケール方針
============================================================

■ 一文方針
  - Pod 単位は KEDA、node 単位は Cluster Autoscaler
    （cluster-api 系）、cluster 単位は OpenTofu replay。スケール
    指標は 13_SLO適合仕様 / 15_テナント容量適合仕様 の
    metric を SoT とする。

■ Pod スケール（KEDA）
  - L1+ primary：KEDA。Horizontal Pod Autoscaler v2 の
    extension として動作、event 駆動 trigger を支援。
  - 採用 trigger：
      - Prometheus metric（13 SLO recording rule）
      - Kafka consumer lag（07 messaging_bridge constraints
        と整合）
      - Cron（時刻ベース batch）
      - 15_テナント容量適合仕様 の v1_per_tenant_compute の
        per-tenant ScaledObject
  - scale-to-zero：開発 / batch workload に適用、本番 always-
    on workload は min replica ≥ 2（HA 維持）。
  - cool-down：scale-down は 5 分待機、scale-up は即時。
  - per-tenant scope：tenant_id を ScaledObject の selector
    に含める（15_テナント容量適合仕様 と整合）。

■ Vertical Pod Autoscaler（VPA）
  - 採用：default 不採用、特定の memory-bound workload
    （ClickHouse query node 等）でのみ activate。
  - mode：Off（recommendation のみ）または Initial（Pod 起動
    時に推奨値適用）。Auto mode は production で禁止
    （workload restart を頻発させるため）。

■ Node スケール（Cluster Autoscaler）
  - L1+ primary：cluster-api ベースの node provisioning +
    Cluster Autoscaler。
  - 自動 scaling 対象：worker node のみ。control plane / storage
    node / infra-tools node は manual / OpenTofu replay。
  - over-provisioning：Priority Class `cluster-overprovision`
    の placeholder Pod を維持、burst 時の immediate scheduling
    を保証。
  - max node：cluster の topology_class instance attribute
    で宣言、超過 scale は Kyverno admission policy で block。

■ Cluster スケール
  - cluster 自体の scale（cluster 数増加）は OpenTofu replay
    で declarative 化、自動 scaling は採用しない。
  - v1_multi_cluster_active_active で cluster 追加時、Argo CD
    ApplicationSet generator が新 cluster を自動 onboarding。

■ scaling 指標の階層
  - 第 1 指標（business）：13 SLO の v1_request_availability
    / v1_request_latency_p99 / v1_event_freshness。
  - 第 2 指標（capacity）：15 v1_per_tenant_qps /
    v1_per_tenant_concurrency / v1_per_tenant_compute /
    v1_per_tenant_volume / v1_global_fair_queue。
  - 第 3 指標（resource）：Pod CPU / memory / Kafka lag /
    queue depth。
  - scale 判定は第 1 → 第 2 → 第 3 の順で評価、上位指標
    が trigger された場合は下位指標が抑制側でも scale 実施。

■ scale 上限（cluster 容量境界）
  - cluster 容量を超える scale は Kyverno admission policy で
    block。15_テナント容量適合仕様 の v1_per_tenant_volume
    の cluster 側 cap 合計が cluster capacity を超えない
    invariant と整合。
  - cluster 容量逼迫時は Argo Events で alert、cluster 追加
    PR を auto draft（OpenTofu plan）。

■ noisy neighbor isolation との整合
  - KEDA per-tenant ScaledObject は 15 noisy neighbor
    isolation property を維持する設計。1 テナントの burst
    で他テナントの ScaledObject が starve しないこと。
  - resource quota / LimitRange を namespace 単位で必須化、
    cluster 全体の resource を tenant 間で公平 share。

■ scale event の audit
  - KEDA scale-up / scale-down は `infra.scale.event` として
    09 観測可能性 SoR に bulk insert。
  - Cluster Autoscaler node add / remove も audit signal を
    emit。

■ failover との整合（topology との連動）
  - v1_multi_zone_per_cluster の zone 障害時、KEDA は他 zone
    で scale-up、topology_spread_constraints が node 配置を
    保証。
  - v1_multi_cluster_active_active の cluster 障害時、KEDA は
    他 cluster で scale-up、Argo CD ApplicationSet が manifest
    を sync。
  - v1_multi_region_active_passive の standby promote 時、KEDA
    state（current replica count）は cross-region replicated。

■ 採用しない選択肢
  - HPA v1（CPU only）：v2 + KEDA に置き換え。
  - cloud managed autoscaler（Karpenter on EKS 等）：cluster-
    api ベースで cluster 非依存に保つため。Karpenter は
    14_OSSライフサイクル適合仕様 の pair_target 候補（v2）。
  - serverless（Knative）：v2 候補。Library 中心モデルとの
    整合は v2 で再評価。
