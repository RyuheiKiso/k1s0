============================================================
infra セキュリティ方針
============================================================

■ 一文方針
  - 5 段階防御（image / runtime / network / secret / policy）
    を全 cluster で必須化、Kyverno admission policy が物理
    enforcement の最終 layer。

■ 段階 1：image / supply chain
  - registry：Harbor 一本、cluster からは Harbor のみ pull
    可能（他 registry からの pull は Kyverno admission policy
    で reject）。
  - signature：Cosign で signed、verify policy が Kyverno で
    必須。signed でない image は admission reject。
  - SBOM：Syft で生成、Harbor に attach。
  - 脆弱性：Trivy + Grype を CI 必須、CVSS critical / high が
    残存する image は merge fail。Harbor 内で定期 scan、
    既存 deploy が新規 CVE に該当した場合は 14_OSSライフ
    サイクル適合仕様 の signal を emit。
  - base image：distroless / chainguard images を default、
    full OS image は禁止。

■ 段階 2：runtime
  - Pod Security Standard：restricted profile を default、
    Kyverno で全 namespace に適用。
  - SELinux / AppArmor：node 上で enforcing mode、Kubernetes
    SecurityContext で default profile 強制。
  - read-only rootfs：Pod の rootfs は read-only、書き込み
    必要箇所は emptyDir / PV で明示的に mount。
  - capabilities：drop ALL を default、必要な capability は
    individual に grant（Kyverno で audit）。
  - hostPath / hostNetwork / hostPID：禁止（Kyverno reject）。
    例外は Rook+Ceph / Longhorn / CNI / monitoring agent
    に限定、明示的 allowlist。
  - seccomp profile：RuntimeDefault を default、業務 Pod は
    custom profile を override 可能。
  - 特権 Pod：禁止。Rook / Longhorn 等の例外は infra-tools
    namespace に限定。

■ 段階 3：network
  - default deny NetworkPolicy：全 namespace で必須（06_ネット
    ワーク方針）。
  - Istio mTLS STRICT：全 mesh 内通信で mTLS 必須。
  - egress：cluster 外への egress は egress gateway 経由
    に限定、許可ドメインは Kustomize overlay で declarative
    宣言。
  - ingress：Envoy Gateway 経由のみ。NodePort / LoadBalancer
    Service の直接公開は禁止（Kyverno reject）。

■ 段階 4：secret
  - secret 管理：OpenBao を SoT、Kubernetes Secret は External
    Secrets で同期した derived のみ。手動 kubectl create
    secret は CI が drift として検出。
  - secret rotation：cadence は 11_鍵管理適合仕様 の rotation
    policy に従う。
  - secret zero-trust：Pod に必要な secret のみ inject、
    cluster-wide secret は禁止。
  - HSM：production cluster の root CA / KEK は HSM
    （PKCS#11）に格納、OpenBao が PKCS#11 backend で interface。

■ 段階 5：policy（Kyverno admission policy）
  - 全 admission policy は Kyverno で codify、infra build
    artifact から自動生成。手書き policy は CI fail。
  - 主要 policy：
      1. image signature verification（Cosign）
      2. Pod Security Standard restricted enforcement
      3. NetworkPolicy default deny
      4. Istio mTLS STRICT
      5. topology_spread_constraints / PDB 必須
      6. quota_class / topology_class / preservation_class
         注釈必須（cross-axis 連動）
      7. drill cadence violation block（failover_drill /
         restore_drill が red の cluster に新規 deploy 拒否）
      8. SLO error budget freeze block（13 SLO 適合仕様 と
         連動）
      9. cve_backlog_threshold block（14 OSS lifecycle 適合
         仕様 と連動）
      10. dimension override 検出（quota_class / topology_
          class / preservation_class の dimension を coding
          で flag した PR を reject）

■ 認証 / 認可
  - cluster RBAC：ServiceAccount + RoleBinding を default、
    User は Backstage 発行 OIDC token のみ。
  - kubectl 直接アクセス：break-glass 用途のみ、OpenBao
    response wrapping で短期 token 発行。
  - Kubernetes audit log：全 cluster で full audit、ClickHouse
    に bulk insert（09 観測可能性 SoR と整合）。

■ 監査 / インシデント
  - 全 audit signal は 09_観測適合仕様 の audit signal sub-
    class として ClickHouse に bulk insert。
  - infra 固有 audit signal：
      - `infra.cluster.create.event`
      - `infra.cluster.upgrade.event`
      - `infra.cluster.destroy.event`
      - `infra.topology.failover.event`（15_クラスタ位相
        適合仕様）
      - `infra.policy.violation.event`（Kyverno reject
        events）
      - `infra.secret.rotation.event`
      - `infra.image.unsigned.reject.event`
  - インシデント response：Argo Events で alert → Slack /
    PagerDuty / runbook trigger、runbook 自体も Argo Workflow
    で automated execution。

■ ハードニング基準
  - CIS Kubernetes Benchmark：本番 cluster で適合必須、kube-
    bench で定期 scan、failure は 14_OSSライフサイクル適合
    仕様 の signal として emit。10_security/17_build_provenance
    適合仕様 の整合 14 で runner cluster + build daemon でも
    green が CI 必須。
  - CIS Docker Benchmark：build daemon （Buildkit）で
    docker-bench-security 適合必須、違反は admission block。
  - NSA/CISA Kubernetes Hardening Guidance：ガイドラインに
    従う、deviation は明示的に記録。runner cluster でも同
    ガイダンス遵守、deviation は 10_security/17 の audit
    signal として emit。
  - SLSA：build pipeline は SLSA L3+ baseline（v1_runtime_
    image_release / v1_cli_or_oci_artifact_release）/ SLSA L4
    target（v1_library_sdk_release、Nix flake bit-identical
    + multi-builder consensus 3/3 + reviewer attest 2 名 必須）。
    詳細 class enum / dimension は 10_security/17_build_
    provenance適合仕様 が単一所有、本節は概略 reference。
