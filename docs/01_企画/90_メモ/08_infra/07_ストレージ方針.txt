============================================================
infra ストレージ方針
============================================================

■ 一文方針
  - block storage は Longhorn、object storage は Rook+Ceph
    RGW、特殊用途のみ Ceph RBD / CephFS。Database 用 PV は
    Longhorn を default、観測可能性 SoR は ClickHouse 自体の
    tiered storage（disk_s3）を使用する。

■ storage backend のレイヤ分離
  - 層 1：Persistent Volume（Pod 単位の永続化）
      - Longhorn（block、per-volume replication）
      - Ceph RBD（特殊用途、容量最適化が必要な場合）
  - 層 2：Object Storage（S3 互換）
      - Rook + Ceph RGW
  - 層 3：File Share（必要な場合のみ）
      - CephFS
  - 層 4：DB engine 独自の tiered storage
      - ClickHouse の disk_s3 で hot SSD（Longhorn）+ cold
        S3（Ceph RGW）
      - PostgreSQL は CloudNativePG で WAL / data を Longhorn
        の単一 PV、archive_to_offline は pg_wal-archive +
        Ceph RGW
      - Kafka は Strimzi で Longhorn PV、tiered storage は
        v2 候補（Apache Kafka 自体の tiered storage feature）

■ Longhorn 構成
  - replica 数：本番 3、開発 2。
  - data locality：strict-local（書き込み node 上に primary
    replica）。
  - cross-zone replication：v1_multi_zone_per_cluster で 3
    zone × 1 replica = 3 replica。
  - backup target：Rook+Ceph RGW（同 cluster）+ cross-region
    Ceph RGW（v1_multi_region_active_passive 以上）。
  - snapshot cadence：daily、retain 30 日。volume 削除時は
    snapshot を cold tier に 90 日保管。

■ Rook+Ceph 構成
  - deploy mode：cluster 内 Rook operator が Ceph cluster を
    自動構築。
  - storage device：local SSD / NVMe、storage node 限定（taint
    `storage=true:NoSchedule`）。
  - CRUSH map：zone failure_domain を必須化。v1_multi_zone_
    per_cluster で zone-replicated（min_size=2、size=3）、
    v1_multi_region_active_passive で cross-region multi-site。
  - bucket quota：15_テナント容量適合仕様 の v1_per_tenant_
    volume の enforcement_layer として bucket 単位 quota を
    設定。
  - lifecycle：hot SSD（Longhorn primary）→ Ceph RGW（hot S3）
    → Ceph RGW（cold S3、infrequent access tier）→ archive_
    to_offline（手動 / 別契約）の 4 段階。
  - encryption：Ceph 自体の at-rest encryption + Linux LUKS
    で二重化、key は OpenBao 管理。

■ CloudNativePG
  - Operator は infra 層が運用、PostgreSQL instance は data
    層所有として扱う（09_data 配下）。
  - Instance 単位の PV は Longhorn、replication mode は
    synchronous_commit=remote_write を default。
  - Replica Cluster：v1_multi_region_active_passive で WAL
    streaming、RPO=0。
  - WAL archive：Ceph RGW を default、retention は 09_data
    /01 で規定。

■ ClickHouse（tiered storage）
  - Operator は Altinity ClickHouse Operator。
  - hot tier：Longhorn PV（local SSD）、retention 7-30 日。
  - cold tier：Ceph RGW S3（disk_s3）、retention 365 日 +
    archive_to_offline。
  - Replicated MergeTree：cross-zone replication を必須化、
    zone failure 時の continuity 保証。
  - cross-region：v1_multi_region_active_active で macro
    replicas、conflict resolution は cell-based partitioning
    （per-region tenant 分割）。

■ PV 容量計画
  - cluster 構築時に reserve 容量を OpenTofu で宣言、Longhorn
    / Ceph の under-provisioning を Kyverno admission policy
    で block。
  - 15_テナント容量適合仕様 の v1_per_tenant_volume の cluster
    側 cap（hot_byte_limit / cold_byte_limit）の合計が cluster
    capacity を超えない invariant を CI で検証。

■ backup / restore
  - Longhorn snapshot：daily、Rook+Ceph RGW に転送。
  - Ceph RGW backup：cross-region replication で v1_multi_
    region_active_passive 以上で必須。
  - PV restore drill：09_data/01 の restore_drill.lock.yaml
    と double-bound、cadence は preservation_class に応じて
    決まる。

■ at-rest 暗号化
  - PV：Longhorn encryption（LUKS）必須、key は OpenBao + 11
    鍵管理適合仕様 の v1_kek 階層。
  - Ceph RGW：Ceph 内蔵 SSE-S3 / SSE-KMS（OpenBao 経由）。
  - DB engine 内：CloudNativePG / ClickHouse / Kafka の column
    / topic 単位暗号化は data 層 / 11 鍵管理適合仕様 の
    application-layer encryption で実施、PV 暗号化と二重化。

■ 採用しない選択肢
  - cloud managed block storage（EBS / Persistent Disk 等）：
    本企画は cluster をクラウド非依存に保つため、PV は
    Longhorn / Ceph に固定。
  - distributed file system（GlusterFS / OpenEBS Replicated
    Engine 等）：Longhorn の L1+ 深耕のため。
  - HDFS / Hadoop：observability SoR は ClickHouse 一本、
    HDFS は採用しない。
