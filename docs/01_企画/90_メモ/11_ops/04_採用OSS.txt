============================================================
ops 採用 OSS（ops 層 subset）
============================================================

■ 位置づけ
  - 「02_採用OSS一覧」の grand catalog のうち、ops 層が
    cross-axis に bind する OSS（SLO platform / alerting /
    on-call escalation / progressive delivery / IR ticketing
    / postmortem / runbook 実行 / feature flag）を抽出して
    整理したもの。infra / data / security が所有する OSS は
    cross 参照で明記する（ops は使用面を宣言するのみ）。
  - 本ファイルの全 OSS は 05_tier1/14_OSSライフサイクル適合
    仕様 の oss_inventory.lock.yaml に v1_l1plus_primary と
    して登録される。

------------------------------------------------------------
[1] SLO platform / error budget
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  SLO definition / budget        | Sloth                  | Apache 2.0
  SLO recording rule generator   | Pyrra                  | Apache 2.0
  Multi-window multi-burn-rate   | Sloth + Pyrra          | Apache 2.0
  Time-series store              | VictoriaMetrics        | Apache 2.0
                                 | （tier1/09 / infra）   |
  PromQL adapter                 | Prometheus             | Apache 2.0
                                 | （tier1/09 / infra）   |

  - Sloth は SLO 定義 yaml → Prometheus recording rule の
    generator として L1+。Pyrra は MWMBR alert rule
    generator として cross-check（pair_target ではなく
    double-bound 必須化）。
  - SLO target 値は tier1/13 が宣言、ops は SLO の error
    budget burn rate を運用 action（freeze / page）に bind
    する規律のみ管掌。
  - VictoriaMetrics は本企画の Prometheus 互換 TSDB
    L1+、Thanos / Cortex は採用しない（infra 04 と整合）。

------------------------------------------------------------
[2] alerting / routing
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Alert routing                  | Alertmanager           | Apache 2.0
  Alert deduplication            | Alertmanager           | Apache 2.0
  Notification channel           | Alertmanager           | Apache 2.0
                                 | + webhook              |
  Burn rate alert generator      | Sloth + Pyrra          | Apache 2.0
  Synthetic monitoring           | Grafana k6             | AGPL-3
  Probe / blackbox monitor       | blackbox_exporter      | Apache 2.0

  - Alertmanager は alert routing / deduplication / silence
    の L1+、Karma は dashboard として cross-check（infra
    14 / 04 と整合）。
  - PagerDuty / Opsgenie 商用は採用しない、Grafana OnCall
    へ webhook で routing。
  - Sloth + Pyrra の二重 generator で MWMBR alert rule を
    生成、手書き alert rule は cap 5%（infrastructure 例外
    のみ）。
  - Grafana k6 は synthetic / external probe 用、外形監視
    は blackbox_exporter（http / tcp / dns / icmp）で吸収。

  -------------------------------+------------------------+---------------
  on-call escalation             | Grafana OnCall         | AGPL-3

[4] incident management / postmortem
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  IR ticketing                   | incident.io OSS        | (custom OSS)
                                 | / GitHub Issue         |
  IR command bridge              | Mattermost incident    | AGPL-3
                                 | response plugin        |
  postmortem 文書                | Markdown + GitHub PR   | (workflow)
  postmortem template            | Backstage TechDocs     | Apache 2.0
                                 | （infra 13 共有）      |

  - incident.io OSS（または GitHub Issue）の minimal

  - postmortem は Markdown + GitHub PR、template は
    Backstage TechDocs に集約。security 11 の IR

    consumption / runbook coverage / toil delta）。
  - action item は別 GitHub Issue + Project board に登録、
    expires_at と owner 必須、未完了 action item は
    quarterly review で再評価。

[5] progressive delivery / change management
------------------------------------------------------------
  カテゴリ                       | プロダクト             | ライセンス
  -------------------------------+------------------------+---------------
  Progressive delivery           | Argo Rollouts          | Apache 2.0
  Canary analysis                | Argo Rollouts          | Apache 2.0
                                 | AnalysisTemplate       |
  GitOps                         | Argo CD                | Apache 2.0
                                 | （infra 提供）         |
  Workflow / pipeline            | Argo Workflows         | Apache 2.0
                                 | （infra 提供）         |
  Sync wave / hook               | Argo CD                | Apache 2.0
                                 | （infra 提供）         |

    LaunchDarkly / Split.io 商用は採用しない。flag
    definition は build artifact（flags.lock.yaml）。
  - Argo Workflows は ops の change management pipeline
    用（rolling drain / topology cutover / multi-stage
    upgrade）、infra 04 と共有。

■ L1+ 深耕の徹底
  - 同一カテゴリで横並びの OSS を本番運用しない（cluster
    単位で 1 つに固定）。例外：Sloth / Pyrra（SLO rule
    generator は double-bound 必須として並走）、Mattermost
    / Slack（社内 channel と機密 channel の分離必須として
    二系統維持）。
  - 既採用 OSS の機能で吸収できる用件を、別 OSS の追加で
    解決しない（progressive delivery は Argo Rollouts のみ、
    Flagger / Spinnaker 追加 ×）。
  - 新 OSS の追加は 14_OSSライフサイクル適合仕様 の
    pair_target 移行手続を必ず経る。
