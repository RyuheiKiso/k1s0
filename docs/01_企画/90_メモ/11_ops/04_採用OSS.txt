============================================================
ops 採用 OSS（ops 層 subset）
============================================================

■ 位置づけ
  - 「02_採用OSS一覧」の grand catalog のうち、ops 層が
    cross-axis に bind する OSS（SLO platform / alerting /
    on-call escalation / progressive delivery / IR ticketing
    / postmortem / runbook 実行 / feature flag）を抽出して
    整理したもの。infra / data / security が所有する OSS は
    cross 参照で明記する（ops は使用面を宣言するのみ）。
  - 本ファイルの全 OSS は 05_tier1/14_OSSライフサイクル適合
    仕様 の oss_inventory.lock.yaml に v1_l1plus_primary と
    して登録される。

■ license / linkage_model 規律
  - 本 layer の採用 OSS は 02_採用OSS一覧 [0] OSS license 規律
    (NEW-09) に従う。各エントリの linkage_model は {dynamic,
    static, process_boundary, network_service} のいずれかに
    分類され、license-checker / cargo-deny / dotnet-licenses で
    CI 検査される。AGPL / SSPL / BSL / Confluent Community License
    / Elastic License v2 等は採用禁止。
  - 本 layer の非 Apache-2.0 採用 OSS の linkage_model :
      - Mattermost (Team)    (MIT)       : network_service
      - Telegram OSS bot     (GPLv3)     : process_boundary
                                          (escalation / 通知 bot
                                           として独立 binary 起動)
      - Asterisk             (GPL-2.0)   : network_service
                                          (NEW-02 ops-edge cluster
                                           上の独立 SIP service)
      - APNs / FCM           (commercial): network_service
                                          (escalation 用途に限り
                                           02 catalog [0] 例外規律
                                           で許容、NEW-02 と整合)

[3] on-call / escalation
------------------------------------------------------------
  カテゴリ                       | プロダクト                       | ライセンス
  -------------------------------+----------------------------------+---------------
  on-call escalation             | 自製 engine                      | (Apache 2.0)
                                 | （Argo Workflows suspend/resume  |
                                 |  + Tekton Triggers + Mattermost  |
                                 |  webhook + slash command         |
                                 |  callback、新規 OSS 追加なし）   |
  rotation schedule              | roster.lock.yaml                 | (build artifact)
                                 | + Argo Workflows CronWorkflow    | Apache 2.0
  ack receipt（三系統）          | Mattermost (web slash command)   | MIT
                                 | + Mattermost mobile push         |
                                 | + Tekton Trigger HTTP callback   |
  escalation policy              | escalation_policy.lock.yaml      | (build artifact)
                                 | （3 階層 / ack window 5 分 /     |
                                 |   re-page 60 分 / fallback timer |
                                 |   を Argo Workflows DAG に展開） |
  notification channel           | Mattermost (Team Edition)        | MIT
                                 | + Telegram OSS bot               | + GPLv3
  Identity provider              | Keycloak                         | Apache 2.0
                                 | （infra / tier1/10）             |

  - escalation engine は target cluster 外の独立 ops-edge
    escalation cluster（11_ops/16_ops_edge_cluster、NEW-02）上で
    Argo Workflows / Tekton / Mattermost / Keycloak の組合せで実装する。
    target cluster 障害時にも escalation 経路を維持するため、target
    cluster 内のみで escalation を組まない（自己観測 invariant
    矛盾を回避）。Asterisk + 自社契約 SIP trunk 二系統 + APNs / FCM
    の multi-channel 通知を組み合わせる（APNs / FCM は escalation
    用途に限り 02 catalog [0] 例外規律で許容）
    （Grafana OnCall は AGPL-3 のため不採用、02 catalog [0]
    OSS license 規律 の AGPL 厳禁規律と整合）。Argo Workflows の
    suspend/resume + timeout で long-lived stateful timer / ack 待ち
    を表現し、3 階層 escalation を DAG（page → suspend → timeout
    → re-page → suspend → timeout → manager-page）に展開する。
    詳細は 07_オンコール方針 escalation_policy.lock.yaml 節を参照。
  - 通知 channel は Mattermost Team Edition（MIT）を default。
    機密 incident 内容も Mattermost に集約（Slack 商用 SaaS 経路
    は採用しない、AGPL 回避方針と独立に SaaS 依存削減のため）。
  - ack 三系統は Mattermost web slash command / Mattermost mobile
    app push（Grafana OnCall mobile app 代替）/ Tekton Trigger HTTP
    callback の三経路。いずれかで ack receipt を受領可能。
  - rotation roster は build artifact（roster.lock.yaml）として
    宣言、UI 上の手動 swap は audit_event 必須。escalation_policy
    .lock.yaml も build artifact として escalation rule（hierarchy
    / ack window / fallback timer）を宣言する。

■ L1+ 深耕の徹底
  - 同一カテゴリで横並びの OSS を本番運用しない（cluster
    単位で 1 つに固定）。例外：Sloth / Pyrra（SLO rule
    generator は double-bound 必須として並走）、Mattermost
    / Slack（社内 channel と機密 channel の分離必須として
    二系統維持）。
  - 既採用 OSS の機能で吸収できる用件を、別 OSS の追加で
    解決しない（progressive delivery は Argo Rollouts のみ、
    Flagger / Spinnaker 追加 ×）。
  - 新 OSS の追加は 14_OSSライフサイクル適合仕様 の
    pair_target 移行手続を必ず経る。
