============================================================
test 性質ベース検証方針（v1_property_axiom）
============================================================

■ 一文方針
  - test 軸は v1_property_axiom verification_class を
    Hypothesis（Python）/ fast-check（TS）/ proptest
    （Rust）/ jqwik（JVM）/ FsCheck（.NET）/ gopter（Go）
    の 6 言語 1 OSS L1+ 単一深耕で実装し、各軸 spec が
    宣言する property（不変条件）を generative input に
    対する反証不能性として artifact 化、shrink 後の最小
    反証 input を Hypothesis-database 互換の corpus 形式
    で immutable 保存し、seed の deterministic 化と
    stateful property test の model 同型化を Conftest +
    Kyverno admission policy で物理 enforce する。

■ 設計原則
  - property は bundle である。
      yaml に書く test.property.* attribute のうち、
      property_id 1 つの値が他 5 dimension（generator_
      strategy / shrink_policy / seed_class / corpus_
      lifecycle / runtime_budget_seconds）を一意に導出
      する。author が dimension を個別に override する
      経路は持たない。
  - dimension override は禁止する。
      「property_id_42 の runtime_budget_seconds を緩めた
      い」要望は新 property_id を切ることで表現する。
      property 数の爆発は意味論の規律として受け入れる。
  - dead spec を CI で殺す。
      properties.yaml に登録された全 property_id、test
      code に annotated された @property 全件、property_
      corpus.lock.yaml に列挙された全 corpus entry は、
      いずれも参照されなくなった時点で CI fail。1 ヶ月
      以上 invocation されない property_id は自動 PR で
      削除提案。
  - seed は deterministic、artifact は immutable。
      property test の random seed は build artifact
      （seed_pool.lock.yaml）から読む、test runner ローカ
      ルで random 生成する経路は持たない。shrink 後の
      最小反証 input は property_corpus.lock.yaml に
      append-only で追加、削除は dead spec 検出時のみ。
  - stateful property は model 同型を必須化する。
      4-state machine（39 client）/ tenant isolation
      （32）/ migration phase（08）/ key rotation（11）
      は Hypothesis stateful / proptest-state-machine /
      jqwik @StatefulProperty で model check 同型に書く、
      手続き型の test を property_axiom の cell として
      bind することは禁止。
  - runtime_budget は class 別に固定する。
      property_id ごとの runtime_budget_seconds は class
      別 enum、PR ごとに 30 / 120 / 600 second の 3 段階
      のいずれか。長時間 budget 越え property は nightly
      pipeline に必ず分離（nightly_property_pool.lock
      .yaml）。

■ generator strategy enum（generator_strategy）
  - v1_random_uniform：
        - 完全 random、Hypothesis default
        - 主用途：単純な field 単独の不変条件
  - v1_random_biased：
        - boundary 偏重（例：integer の MIN / MAX 周辺、
          empty string、NaN、∞）
        - 主用途：境界条件型 invariant
  - v1_grammar_guided：
        - 文法 driven（CFG / regex 由来）
        - 主用途：12 schema migration の forward / backward
          compat / 07 transport frame parser
  - v1_state_machine：
        - stateful、Hypothesis stateful / proptest-state-
          machine
        - 主用途：39 client 4-state / 32 tenant isolation
          / 08 migration 4 phase / 11 key rotation
  - v1_metamorphic：
        - 入力変換 → 出力 invariant（metamorphic testing）
        - 主用途：13 SLO recording rule / 12 schema
          aggregate qualified name の rename invariant /
          09 SemConv attribute rename

■ shrink policy enum（shrink_policy）
  - v1_default：Hypothesis / fast-check / proptest 既定
    shrink、最小化試行 100 回 cap
  - v1_extended：失敗時 1000 回 cap、cluster integration
    系 property（08 / 11 / infra01 / data01）で必須
  - v1_disabled：shrink off、performance 系 property
    （soak / load 系）で例外的に許容、必ず justification
    artifact 必須（disabled_shrink_justification.lock
    .yaml に entry）

■ seed class enum（seed_class）
  - v1_pr_deterministic：
        - PR ごとに deterministic、PR 番号と property_id
          の hash で derive、PR 内 retry でも同じ seed
  - v1_nightly_random：
        - nightly pipeline で random、新 corpus 発掘用
  - v1_replay_corpus：
        - property_corpus.lock.yaml の entry を再実行、
          regression 防止
  - v1_seed_pool：
        - seed_pool.lock.yaml から chooser、quarter ごと
          に rotate、過去 corpus を bias で混ぜる

■ corpus lifecycle enum（corpus_lifecycle）
  - v1_append_only：
        - shrink 後の最小反証 input を append-only で
          追加、削除は dead spec 検出時のみ。
        - 全 corpus entry は (property_id, input_hash,
          discovered_at, last_replayed_at) を保持。
  - v1_versioned：
        - schema migration 時に corpus を新 version に
          migrate、旧 version は archive、削除しない。
        - data01 v1_zone_replicated 以上で物理保存。
  - v1_immutable_archive：
        - mutation testing の equivalent mutant 認定
          input、security incident の reproducer input
          は Ceph RGW Object Lock Compliance mode で
          retention 365 day。

■ runtime budget enum（runtime_budget_seconds）
  - v1_pr_fast：30 sec、PR ごとに必ず実行
  - v1_pr_medium：120 sec、PR ごとに必ず実行
  - v1_nightly_long：600 sec、nightly pipeline 専属
  - v1_nightly_extreme：3600 sec、quarter ごとに 1 回、
    cluster shadow 上で実行（infra01 v1_multi_region_
    active_passive の passive 側）

■ stateful property の model 規律
  - 4-state machine（39 client）の必須 stateful property：
        - transition closure：全 (state_from, action,
          state_to) tuple が enum と一致
        - liveness：dirty → reconciled に必ず到達（cap
          5 step 以内）
        - safety：syncing 中の double-write が起きない
        - fairness：reconcile race で順序崩れが起きない
  - tenant isolation（32）の必須 stateful property：
        - cross-tenant access は generative attempt 1000
          回で 0 件成功
        - GUC propagation の継承が SessionContext の
          全 boundary で保たれる
        - RLS FORCE bypass attempt が物理 deny
  - migration phase（08）の必須 stateful property：
        - 4 phase の任意の (from, to) transition で
          dual_window invariant が破られない
        - rollback 経路が full path で復路として通る
  - key rotation（11）の必須 stateful property：
        - rotate 中の sign / verify が交差時刻で破綻し
          ない
        - KEK / DEK 階層 rotation の order invariant

■ corpus storage / SoR
  - property_corpus.lock.yaml：build artifact、cosign
    signed
  - storage：09 観測 SoR の ClickHouse + Ceph RGW
    （data01 v1_zone_replicated 以上）に hot / cold 二重
    保存
  - retention：v1_immutable_archive のみ 365 day
    Compliance mode、それ以外は 90 day cold archive 後
    crypto-erase
  - access：corpus.read は unrestricted、corpus.write
    （新 entry 追加）は test runner 経由のみ、UI 上の
    手動編集は audit_event 必須

■ cross-axis bind（property_axiom 列の cell）
  - 各軸の必須 property は 05_カバレッジ行列方針 で list
    化、property_id を coverage cell の artifact_pointer
    に bind
  - 13 SLO の v1_test_coverage_compliance に property_
    axiom 列の green rate を計算入力として bind
  - 14 OSS-lifecycle 移行時、property framework 自身の
    major version 移行は v1_scenario_replay drill として
    別 class で claim
  - 11 ops の v1_drill_failure に「property test の
    nightly green が前 quarter から regress」signal を
    bind

■ 採用しない経路
  - random seed の test runner ローカル random 化：禁止、
    必ず seed_pool / replay_corpus / pr_deterministic
    のいずれか
  - corpus の shrink 結果削除：禁止、append-only +
    dead spec 検出のみ
  - stateful property の手続き型 test 化：禁止、必ず
    Hypothesis stateful / proptest-state-machine の model
    で記述
  - LLM-generated property の盲目的 merge：禁止、LLM
    生成は ai_generator_id / model_version / prompt_hash
    注釈付き、人間 reviewer による model 同型 check 必須
  - SaaS による property test as a service：採用しない、
    OSS L1+ self-host
  - runtime_budget 越え property の PR pipeline 残置：
    禁止、必ず nightly_property_pool.lock.yaml に分離
