============================================================
test 運用 UI と開発者体験
============================================================

■ 一文方針
  - test 軸の運用 UI と開発者体験は、Backstage TechDocs +
    Perses dashboard + GitHub PR + Mattermost ChatOps の
    既存 UI 道具立てに subordinate し、新規 UI を test 軸
    が独自開発することは原則しない。test 軸が要求する
    UX は (a) coverage matrix の Perses dashboard 化、
    (b) PR 上の machine-readable check check（coverage
    cell green / mutation_score monotonic / flaky_
    quarantine 期限内 / pact can-i-deploy / chaos drill
    cadence）、(c) Backstage 上の test ownership UI、
    (d) ChatOps slash command（test replay / mutation
    reproduce / chaos blueprint dry-run）、の 4 経路の
    みで完結する。

■ 設計原則
  - 既存 UI 上での投影：
      Backstage / Perses / GitHub PR / Mattermost に
      投影することで test 軸の独自 UI 開発を禁止、UI
      開発による drift 経路を物理に持たない。
  - 機械可読性 first：
      developer 向け表示（PR check / Perses dashboard /
      Backstage card）は全て test artifact（coverage_
      matrix.lock.yaml / mutation_score.lock.yaml /
      flaky_quarantine.lock.yaml / pact verify result /
      chaos blueprint cadence）から導出される build
      artifact、手書き dashboard yaml は cap 5%（infra
      14 / 04 と整合）。
  - local replay：
      developer は local で coverage cell の test を
      replay できる、test framework は cluster shadow を
      要求しない範囲（type_invariant / property_axiom /
      contract_pair / unit + integration scenario）の
      replay を local CLI で完結。
  - audit trail：
      ChatOps slash command（test 軸関連）は全件 audit
      _event subject に v1_test_chatops fact emit、必須
      column：actor / scenario_or_blueprint_id / ack_
      pointer / blast_radius（chaos の場合）/ ticket_ref。

■ Backstage TechDocs 上の test カード
  - 各 service の Backstage entity に test card を表示：
        - coverage matrix 中の本 service 関連 cell の
          green / red 状態
        - mutation_score current / quarter monotonic
          推移
        - flaky_quarantine 中の test 一覧
        - pact verify can-i-deploy 状態
        - chaos drill last_green_at + 次回 cadence
        - test ownership 4 軸（service / domain /
          framework / drill）
  - 全 card は coverage_matrix.lock.yaml / mutation_
    score.lock.yaml 等から導出、Backstage TechDocs
    plugin が自動 render
  - 手動編集禁止、Argo CD self-heal で drift detect

■ Perses dashboard
  - dashboard 1：coverage matrix overview
        - panel：16 axis × 5 verification_class の grid
          を heatmap として表示、green / red / quarantined
          / pending の色分け
        - panel：last_green_at の cadence 越え cell の
          一覧
  - dashboard 2：mutation_score quarter trend
        - panel：module_id ごとの quarter score 推移、
          monotonic increase の物理可視化
        - panel：equivalent mutant 認定数の推移
  - dashboard 3：flaky quarantine
        - panel：quarantine 中 test 一覧、quarantine_
          due_at までの残日数
        - panel：quarantine 期限超過の警告（escalation
          経路）
  - dashboard 4：performance baseline
        - panel：各 perf_scenario_id の SLI baseline
          quarter 推移、regression 検出の物理可視化
  - dashboard 5：drill cadence
        - panel：v1_fault_chaos / v1_scenario_replay の
          last_green_at cadence 表、cadence 越え cell
          の一覧
  - 全 dashboard は build artifact（dashboards/test/
    *.json）として管理、手動編集 cap 5%

■ GitHub PR check
  - PR check（必須 green）：
        - test_coverage_matrix_check：coverage_matrix
          .lock.yaml の green 維持、PR の changed 軸 +
          changed verification_class cell が green
        - test_mutation_score_check：mutation_score
          monotonic 維持
        - test_flaky_quarantine_check：flaky_quarantine
          の cap 越えなし
        - test_pact_can_i_deploy_check：Pact Broker の
          can-i-deploy green
        - test_chaos_drill_cadence_check：chaos blueprint
          の cadence 越えなし
        - test_regression_corpus_added_check：defect 修正
          PR に regression_corpus_added 注釈
        - test_snapshot_signed_check：snapshot 更新 PR が
          drill_owner ack 済み
  - PR check 失敗時は merge block（Kyverno admission
    policy + GitHub branch protection の double）。
  - PR 上の表示は GitHub Action の job summary に build
    artifact から生成された markdown を投稿、人手 PR
    description は test 軸関連注釈なし。

■ Mattermost ChatOps slash command
  - `/test replay <scenario_id>`：
        - shadow cluster 上で v1_scenario_replay の
          replay を起動、Tekton Pipeline trigger
        - 結果は audit_event + Mattermost channel post
  - `/test mutate <module_id>`：
        - mutation testing を on-demand 起動、quarter
          baseline 比較
  - `/test chaos dryrun <blueprint_id>`：
        - chaos blueprint の dry-run（v1_shadow_only
          のみ）、prod gameday は別 break-glass 経路
  - `/test pact verify <pair_id>`：
        - Pact Broker の verify を on-demand 起動
  - `/test coverage cell <axis> <verification_class>`：
        - 対応 cell の current state + last_green_at +
          artifact_pointer を post
  - 全 slash command は audit_event subject に v1_test_
    chatops fact emit、必須 column 完備

■ local CLI（developer 体験）
  - `k1s0-test cell-status <axis> <verification_class>`：
        - coverage cell の状態を表示、artifact pointer
          path を返す
  - `k1s0-test replay <scenario_id> --target=local`：
        - local container（Testcontainers）で scenario
          replay、shadow cluster 不要 subset
  - `k1s0-test mutate <module_id> --quick`：
        - changed file subset の mutation testing、5
          min budget
  - `k1s0-test property <property_id>`：
        - property test を replay corpus + pr_
          deterministic seed で実行
  - `k1s0-test pact verify <pair_id>`：
        - Pact runtime で local pact verify
  - 全 CLI は build artifact（k1s0-test binary）として
    管理、cosign signed、checksum 配布

■ test ownership 4 軸
  - service_owner：service の business owner
  - domain_owner：domain（軸ごと）の technical lead
  - framework_owner：test framework（pytest / Pact /
    Litmus 等）の expert
  - drill_owner：drill cadence 維持の責任者
  - ownership_table.lock.yaml：各 service / 各 spec の
    4 軸 owner を完備宣言、欠損は service deploy block
    （ops 14 と整合）

■ test 開発の経路（ハッピーパス）
  - 経路 1：新軸 spec が 5 verification_class 全てに
    cell 追加 → test 軸 PR で coverage matrix 自動生成
    → 5 cell の artifact 生成 → green 後に release_
    gate AND-gate に入力
  - 経路 2：既存 cell の defect 検出 → regression_corpus
    に entry 追加 PR → defect fix PR → cell 復帰
  - 経路 3：flaky 認定 → quarantine 14 day 内 fix PR
    → cell 復帰
  - 経路 4：mutation_score 引き上げ → mutation_score
    .lock.yaml の quarter score を artifact PR で更新
    → quarter monotonic 維持
  - 経路 5：chaos drill cadence 越え予兆 → drill_owner
    が `/test chaos dryrun` で事前 dry-run → cadence
    内に v1_shadow_only drill 起動

■ 採用しない経路
  - test 軸独自の UI 開発（Web / Mobile / Desktop）：
    禁止、Backstage / Perses / GitHub / Mattermost に
    subordinate
  - PR description のみで test 状況伝達：禁止、PR check
    + ChatOps + Backstage card で機械可読
  - Slack や discord 等の他チャネル使用：原則禁止、
    Mattermost に統一（Slack は ops 14 で internal
    channel 例外、test 軸は使用しない）
  - test slash command の audit_event 省略：禁止
  - manual dashboard yaml の cap 越え（5%）：禁止
  - flaky 状態の文章 only 報告：禁止、必ず flaky_
    quarantine.lock.yaml entry
  - test artifact の手動編集による「直し」：禁止、
    必ず PR + drill_owner ack + Argo CD sync
