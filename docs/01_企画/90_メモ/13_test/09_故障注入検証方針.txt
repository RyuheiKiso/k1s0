============================================================
test 故障注入検証方針（v1_fault_chaos）
============================================================

■ 一文方針
  - test 軸は v1_fault_chaos verification_class を Litmus
    L1+ + Toxiproxy（network fault）+ Chaos Mesh（low
    blast radius、double-bound）+ AFL++（fuzz）の組合せで
    実装し、各軸 spec が宣言する fault mode（network /
    storage / clock / process / dependency / attacker）に
    対する resilience を chaos blueprint（chaos_blueprints
    .lock.yaml）の build artifact として固定し、blast
    radius を Kyverno admission policy で物理制限、prod
    gameday を OpenBao response wrapping の break-glass +
    二人承認 + audit_event で物理 enforce する。

■ 設計原則
  - chaos blueprint は bundle である。
      yaml に書く test.chaos.* attribute のうち、
      blueprint_id 1 つの値が他 6 dimension（fault_class
      / blast_radius / target_layer / drill_cadence_days
      / attacker_class / recovery_validation_class）を一意
      に導出する。author が dimension を個別に override
      する経路は持たない。
  - dimension override は禁止する。
      「blueprint_id_42 の blast_radius を緩めたい」
      要望は新 blueprint_id を切ることで表現する。
  - dead spec を CI で殺す。
      chaos_blueprints.lock.yaml に登録された全
      blueprint_id、Litmus workflow に保存された全
      experiment、AFL++ corpus に保存された全 input は、
      いずれも参照されなくなった時点で CI fail。
  - 6 fault_class を全 axis で coverage：
        - v1_network_fault：partition / latency / packet
          loss / DNS failure
        - v1_storage_fault：disk full / IO error / corruption
        - v1_clock_fault：drift / jump / freeze
        - v1_process_fault：kill / OOM / crash loop
        - v1_dependency_fault：upstream service / IDP /
          KMS / event broker outage
        - v1_attacker_fault：security15 threat 1:1
          attacker simulation（red team automated）
  - blast radius の物理制限：
      shadow cluster（infra01 passive）/ partial production
      / production gameday の 3 段階を Kyverno admission
      policy で物理 enforce、production gameday は
      OpenBao response wrapping の二人承認 break-glass
      経由でのみ起動可能。
  - drill_cadence_days を物理 property とする。
      cadence 越えの blueprint は Kyverno admission
      policy で関連 service deploy 物理 block、文章で
      「次回 drill する」は禁止。

■ blueprint_id 命名と field 構造
  - blueprint_id 命名規則：`<axis>__<fault_class>__
    <attacker_class_or_none>` の 3 segment（例：`infra01_
    _v1_network_fault__none` / `security15__v1_attacker_
    fault__credential_stuffing`）
  - 必須 field（10 field）：
        - blueprint_id：PK
        - fault_class：上記 6 enum
        - blast_radius：v1_shadow_only / v1_partial_prod
          / v1_prod_gameday
        - target_layer：tier1 / tier2 / tier3 / infra /
          data / security / ops の 7 enum
        - drill_cadence_days：30 / 90 / 180 / 365 enum
        - attacker_class：security15 threat 1:1 bind、
          または `none`（attacker 系以外）
        - recovery_validation_class：v1_slo_recovery
          / v1_data_recovery / v1_state_recovery / v1_
          security_containment の 4 enum
        - last_green_at：UTC ISO8601
        - last_green_blast_radius：実際に走った blast
          radius（cadence ごとに記録）
        - artifact_pointer：Litmus workflow CR / Toxiproxy
          config / AFL++ corpus dir 等

■ fault_class 詳細
  - v1_network_fault：
        - tool：Toxiproxy + Litmus chaos-network
        - fault：partition / latency injection / packet
          loss / DNS NXDOMAIN / TLS handshake reject
        - 主用 axis：07 transport / 09 observability /
          10 auth / infra01 / data01 cross-region
  - v1_storage_fault：
        - tool：Litmus chaos-disk + charybdefs
        - fault：disk full / IO error / read corruption /
          inode exhaustion
        - 主用 axis：data01 / 09 observability SoR
          ClickHouse / 12 schema PostgreSQL
  - v1_clock_fault：
        - tool：Litmus chaos-clock-skew
        - fault：drift +/- 5 min / sudden jump 24h /
          clock freeze
        - 主用 axis：08 migration window / 11 key
          rotation / 13 SLO burn rate / data01 RPO
          window
  - v1_process_fault：
        - tool：Litmus chaos-pod-kill / chaos-container-
          kill / Chaos Mesh stress-chaos
        - fault：random pod kill / OOM kill / crash
          loop / SIGTERM ignore
        - 主用 axis：infra01 / ops15 5 signal_class
          runbook
  - v1_dependency_fault：
        - tool：Litmus chaos-http-fault + Toxiproxy
        - fault：upstream / IDP / KMS / event broker
          unavailability、5xx / timeout / 429
        - 主用 axis：10 auth / 11 key / 14 OSS-lifecycle
          / 15 capacity
  - v1_attacker_fault：
        - tool：Litmus + 専用 attacker workflow + AFL++
          fuzz
        - fault：security15 threat 1:1（credential
          stuffing / RLS bypass attempt / token replay /
          SQL injection / fuzz parser / race-condition
          attacker）
        - 主用 axis：security15 / 32 data-tenant / 10
          auth / 12 schema

■ blast_radius の admission policy 制限
  - Kyverno admission policy:
        - require-blast-radius-annotation：chaos
          experiment CR に blast_radius 注釈必須
        - block-prod-gameday-without-break-glass：
          v1_prod_gameday は break-glass token 必須
        - require-recovery-validation-pointer：experiment
          に recovery_validation_class の artifact
          pointer 必須
        - block-during-active-incident：active incident
          中の chaos experiment block（drill_class が
          incident 関連の場合のみ allow、ChatOps 上で
          incident commander の ack 必須）。incident_
          active_duration > 14d の場合、当該 incident は
          v1_extended_incident に再分類され、cadence_
          escape_valve が発動：次回 chaos drill cadence
          期限を 30d 自動延長（最大 2 回まで）、ops lead
          二人承認 + audit_event subject に v1_cadence_
          escape_valve fact emit を必須化、関連 cell の
          drill_state は v1_drill_red_handled として
          coverage_matrix に物理記録（A5 の release_gate
          AND-gate 整合）。
        - block-during-global-freeze：global freeze
          window 内の v1_prod_gameday を block
  - blast_radius 段階：
        - v1_shadow_only：infra01 passive cluster 完全
          分離、自由起動 allow
        - v1_partial_prod：prod cluster の特定 namespace
          のみ、Mattermost incident channel 通知必須
        - v1_prod_gameday：prod 全域、break-glass 必須、
          二人承認（primary + secondary on-call）必須、
          audit_event subject に v1_chaos_gameday fact
          emit 必須

■ recovery_validation_class enum
  - v1_slo_recovery：
        - SLO burn rate が drill 後 N 分で baseline 復帰
          を物理 verify、未復帰は drill failure
  - v1_data_recovery：
        - data01 v1_zone_replicated 以上の data が RPO
          以内、restore_drill 経由で物理 verify
  - v1_state_recovery：
        - 32 RLS / 39 client 4-state / 08 migration phase
          の state machine が drill 後 invariant に戻る
  - v1_security_containment：
        - security15 attacker fault に対し containment
          が物理発火、attacker の lateral movement が
          物理に止まる

■ AFL++ fuzz の corpus 規律
  - corpus storage：
        - fuzz_corpus.lock.yaml に entry、Ceph RGW
          Object Lock Compliance mode で 365 day retention
  - corpus seed：
        - 12 schema producer 側の sample input
        - 07 transport の frame sample
        - 09 SemConv attribute の正常 sample
        - 10 auth token の expired / invalid sample
  - run cadence：
        - PR ごとに 5 min smoke fuzz
        - nightly に 60 min fuzz
        - quarter ごとに 24h dedicated fuzz（cluster
          shadow 上）
  - 発見した crash input：
        - hypothesis-database 互換 corpus に append-
          only 追加、property_axiom の corpus と統合管理

■ chaos drill cadence 表
  - tier1 系（07 / 08 / 09 / 10 / 11 / 12 / 13 / 14 /
    15）：30 day
  - tier2（32）：30 day
  - tier3（39）：30 day
  - infra01：90 day（zone partition / region failover）
  - data01：30〜180 day（preservation class 別）
  - security15：90 day（red-team），365 day（full red-
    team campaign）
  - client15：14〜30 day（distribution class 別）
  - ops15：drill 自体が self-bound、各 signal_class
    runbook drill の cadence は 11_ops/15 で宣言

■ prod gameday 規律
  - 起動経路：
        1. ops の change_calendar.lock.yaml に entry
          登録、72h 前
        2. break-glass token 発行（OpenBao response
          wrapping、有効期限 1h）
        3. primary + secondary on-call の二人承認
          （ChatOps slash command）
        4. audit_event subject に v1_chaos_gameday
          fact emit（必須 column：actor / blueprint_id
          / blast_radius / expected_duration /
          incident_ref（後追いで起票））
        5. drill 中も ops_event の hash chain は継続、
          chain divergence 不可
        6. 終了後 1h 以内に postmortem PR 起票必須
  - 失敗時：
        - drill 中 SLO burn rate 越えで Argo Rollouts
          + Kyverno が物理 freeze、人間 ack 不要
        - drill 失敗 → ops の v1_drill_failure signal
          として v1_drill_postmortem 起票

■ cross-axis bind（fault_chaos 列の cell）
  - 07 transport：handshake drop / partial decode /
    network partition / TLS reject
  - 08 migration：cutover failure / dual_window expiry
  - 09 observability：collector outage / span loss /
    sampling skew
  - 10 auth：IDP outage / credential stuffing
  - 11 key：KMS outage / key corruption
  - 12 schema：breaking rollback / fuzz parser
  - 13 SLO：recording rule drift / burn rate skew
  - 14 OSS-lifecycle：EoL freeze drill
  - 15 capacity：quota engine outage / noisy neighbor
  - 32 data-tenant：RLS bypass attempt（attacker fault）
  - 39 client：network partition / clock skew / offline
    duration extension
  - infra01：zone outage / region failover / control
    plane upgrade fault
  - data01：cross-region replication lag / cold
    archive corruption
  - security15：threat 1:1 attacker simulation（全
    threat 必須）
  - client15：SDK runtime fault（5 distribution_class
    全て）
  - ops15：drill 自体（self-bound）

■ 採用しない経路
  - 商用 chaos SaaS（Gremlin / AWS FIS / Harness Chaos）：
    採用しない、Litmus L1+ 単一深耕
  - 文章 only chaos drill：禁止、必ず chaos_blueprints
    .lock.yaml に entry + Litmus workflow CR で物理化
  - blast_radius 注釈なし experiment：禁止、admission
    policy で deploy block
  - prod gameday の単独承認：禁止、二人承認必須
  - drill skip の経済合理性主張：禁止、cadence 越えは
    関連 service deploy 物理 block
  - LLM-generated chaos blueprint の盲目的 merge：禁止、
    必ず人間 reviewer による blast_radius / recovery_
    validation_class check + 二人承認 PR
  - active incident 中の chaos experiment 自由起動：
    禁止、incident commander の ack 必須
