============================================================
test 変異検証方針（mutation testing）
============================================================

■ 一文方針
  - test 軸は mutation testing を「test の test」として
    pitest（JVM）+ mutmut（Python）+ Stryker Mutator
    （TS / .NET）+ go-mutesting（Go）+ cargo-mutants
    （Rust）の 5 言語 1 OSS L1+ 単一深耕で実装し、
    mutation_score（killed / total）を mutation_score.lock
    .yaml に build artifact として固定、quarterly
    monotonic increase を Kyverno admission policy で
    物理 enforce、equivalent mutant の認定は justification
    artifact 必須化、mutation testing 自体を全 5
    verification_class（type_invariant 含む）に再帰適用
    することで test の質を物理 measurable にする。

■ 設計原則
  - mutation_score は bundle である。
      yaml に書く test.mutation.* attribute のうち、
      module_id 1 つの値が他 5 dimension（mutation_
      operator_class / scope / cadence_days / equivalent_
      mutant_policy / score_floor）を一意に導出する。
      author が dimension を個別に override する経路は
      持たない。
  - dimension override は禁止する。
      「module_id_42 の score_floor を緩めたい」要望は
      新 module_id を切ることで表現する。
  - dead spec を CI で殺す。
      mutation_modules.yaml に登録された全 module_id、
      mutation_score.lock.yaml に列挙された全 entry、
      equivalent_mutants.lock.yaml に列挙された全 entry
      は、参照されなくなった時点で CI fail。
  - score_floor は monotonic increase only。
      mutation_score.lock.yaml の各 module_id score は
      四半期比較で必ず monotonic increase、下げる PR は
      Kyverno で merge block。新規 module 追加時は
      初期 score_floor を quarter 内に達成する責務が
      drill_owner に bind。
  - equivalent mutant は機械可読 justification 必須。
      equivalent mutant 認定は equivalent_mutants.lock
      .yaml に append-only entry、reason_class enum +
      symbolic_proof_pointer が必須、人間判断のみの
      文章 justification は禁止。
  - mutation testing は 5 verification_class 全てに
    再帰適用する：
        - v1_type_invariant に対して：型 mutation（型
          relax / 型 widening）が type test で検出
          されること
        - v1_property_axiom に対して：property mutation
          （boundary / generator override）が property
          test で検出されること
        - v1_contract_pair に対して：pact field mutation
          （field add / remove / type change）が Buf-
          breaking で検出されること
        - v1_scenario_replay に対して：scenario step
          mutation（step skip / step reorder）が
          Playwright trace で検出されること
        - v1_fault_chaos に対して：blueprint mutation
          （fault type swap / blast_radius reduce）が
          chaos workflow で検出されること

■ module_id 命名と field 構造
  - module_id 命名規則：`<axis>__<lang>__<module_path>`
    の 3 segment（例：`07_transport__rust__core/transport
    /codec`）
  - 必須 field（10 field）：
        - module_id：PK
        - language：rust / python / typescript / java /
          go / csharp / kotlin
        - mutation_operator_class：v1_arithmetic / v1_
          conditional / v1_boundary / v1_return_value /
          v1_increment / v1_void_method_call の 6 enum
        - scope：v1_per_module / v1_per_axis_subset /
          v1_full_codebase の 3 enum
        - cadence_days：v1_per_pr_smoke（1 day）/ v1_
          nightly（1 day）/ v1_weekly（7 day）/ v1_
          quarterly（90 day）の 4 enum
        - equivalent_mutant_policy：v1_strict（全
          equivalent mutant に symbolic_proof_pointer
          必須）/ v1_documented（reason_class enum +
          comment artifact 必須）
        - score_floor：percentile（0.0〜1.0）、四半期
          monotonic increase
        - last_run_at：UTC ISO8601
        - last_score：直近 score（killed / total）
        - artifact_pointer：mutation report HTML / XML
          / JSON の path

■ mutation_operator_class（PIT / mutmut / Stryker 標準）
  - v1_arithmetic：+ ↔ - / * ↔ /（数値演算 mutation）
  - v1_conditional：== ↔ != / < ↔ >=（条件 mutation）
  - v1_boundary：< ↔ <= / > ↔ >=（境界 mutation）
  - v1_return_value：return value swap（true → false /
    null → not null）
  - v1_increment：i++ → i--
  - v1_void_method_call：void method 呼出削除

  - 上記 6 operator は全 module で必須有効化、operator
    selective disable は dimension override として禁止。
    対象外 operator（言語固有の特殊 mutation）は新
    operator class として登録する経路でのみ拡張。

■ scope enum
  - v1_per_module：
        - module 単位の mutation、PR の changed file
          subset で limited run
        - cadence：v1_per_pr_smoke（1 day）
  - v1_per_axis_subset：
        - 1 軸の対応 module set 全体、nightly
        - cadence：v1_nightly
  - v1_full_codebase：
        - 全 codebase 全 module、quarterly
        - cadence：v1_quarterly
        - 実行：cluster shadow 上の dedicated executor

■ score_floor の monotonic increase 規律
  - mutation_score.lock.yaml は append-only 履歴 +
    current state の二系統 yaml
  - quarter 比較：直近 quarter の score >= 前 quarter
    の score
  - 例外なし：score 引き下げ PR は Kyverno で merge
    block、release_gate.lock.yaml AND-gate 物理 fail
  - 新規 module の grace：初期 score_floor は新規
    module 追加 quarter の翌 quarter までに達成必須、
    grace 越えは関連 service deploy block

■ equivalent mutant 規律
  - 認定経路：
        1. mutation testing 後、survived mutant が
          equivalent_mutants.lock.yaml に提案 entry
          として自動 append
        2. drill_owner（ownership_table.lock.yaml の
          drill_owner 軸）が reason_class enum を選択
        3. v1_strict policy module は symbolic_proof_
          pointer（KLEE / CBMC / formal proof）が必須、
          v1_documented policy module は comment artifact
          が必須
        4. PR 起票、人間 reviewer 1 人 + drill_owner の
          二重 ack で merge
  - reason_class enum：
        - v1_dead_code：実行不能 path（unreachable）
        - v1_logically_equivalent：意味論的に同等
          （e.g. i + 0 → i）
        - v1_safe_optimization：compiler 最適化等価
        - v1_test_independent：mutation 領域が test
          assertion の責任領域外
  - reason_class が v1_logically_equivalent の場合：
        - symbolic_proof_pointer 必須（KLEE / CBMC /
          Z3 等の SMT solver output）
        - L1+ 単一深耕：KLEE を symbolic proof tool L1+
          として採用、Z3 は SMT backend として cross-
          check

■ mutation report の SoR
  - mutation_score.lock.yaml：current state、cosign
    signed
  - mutation_history.lock.yaml：append-only 履歴、過去
    quarter の score 推移
  - mutation report HTML / XML / JSON：Ceph RGW Object
    Lock Compliance mode で 365 day retention
  - ClickHouse：mutation_score quarter ごとの aggregate
    metric、Grafana dashboard 入力

■ run pipeline
  - PR pipeline（v1_per_pr_smoke）：
        - changed file subset の per-module mutation、5
          min budget cap
        - red の場合 PR merge block
  - nightly pipeline（v1_nightly / v1_per_axis_subset）：
        - 各軸の subset を順次 mutation、120 min budget
          cap、cluster shadow 上
        - 結果は mutation_score.lock.yaml の current
          state を更新
  - quarterly pipeline（v1_quarterly / v1_full_
    codebase）：
        - 全 codebase 全 module、24h budget cap、cluster
          shadow 上 dedicated executor
        - 結果は quarter score の baseline、monotonic
          比較の入力

■ cross-axis bind
  - 13 SLO：v1_mutation_score_compliance を SLO 登録、
    quarter monotonic 違反で burn rate alert
  - 11 ops：mutation_score regress の v1_drill_failure
    signal_class へ bridge
  - 14 OSS-lifecycle：mutation framework 自身の major
    version migration drill 必須化
  - 05_カバレッジ行列方針：mutation_score は v1_
    property_axiom / v1_type_invariant cell の補助
    metric として bind、property test の質を mutation
    で物理 measurable に
  - 10 security：security-critical module（10 auth /
    11 key / 32 RLS）は score_floor が relaxed 不可、
    score 0.95 以上を物理要件

■ 採用しない経路
  - mutation testing skip の経済合理性主張：禁止、
    cadence 越えは関連 service deploy block
  - score_floor の引き下げ：禁止、monotonic increase
    only、PR merge block
  - 文章のみの equivalent mutant justification：禁止、
    reason_class enum + artifact pointer 必須
  - 商用 mutation SaaS（Diffblue Cover Pro / Sealights）：
    採用しない、OSS L1+ 単一深耕
  - LLM-only mutation 認定：禁止、人間 reviewer + drill
    _owner の二重 ack 必須
  - mutation testing を「ベストエフォート」と位置づけ：
    禁止、release_gate.lock.yaml の AND-gate 物理入力
