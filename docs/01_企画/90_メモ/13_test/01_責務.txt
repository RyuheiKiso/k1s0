============================================================
test 責務
============================================================

■ 一文定義
  - test は、tier1 / tier2 / tier3 / infra / data / security
    / ops の各層が宣言した個別軸の規律（transport / migration
    / observability / auth / key / schema / SLO / OSS-lifecycle
    / capacity / data-tenant / client-state / infra-topology
    / data-preservation / threat-model / client-distribution
    / ops-loop）を「単一の検証規律（type_invariant →
    property_axiom → contract_pair → scenario_replay →
    fault_chaos の 5 verification_class が axis × class の
    格子で完全に埋まる）の下で cross-cut に整合させる」
    layer であり、層 ⊥ 軸 ⊥ 検証クラス の格子で発生する全
    verification claim が必ず物理 artifact 経路（pact_broker
    pact / litmus chaos workflow / pitest mutation report /
    playwright trace / coverage_matrix.lock.yaml cell）に
    bind されることを meta-layer として保証する責務を持つ。

■ 責務の境界
  - test が責務を持つ：
      - 検証 lifecycle（type_invariant / property_axiom /
        contract_pair / scenario_replay / fault_chaos の 5
        verification_class）の宣言的真
      - axis × verification_class の coverage matrix（14 軸
        + meta + ops + 本軸 = 17 軸 × 5 class = 85 cell）
        の build artifact 化、欠損 cell ゼロの CI 不変条件
        化
      - mutation testing の score baseline（mutation_score
        .lock.yaml）と quarterly monotonic increase 規律
      - flaky test の quarantine cadence（quarantine_due_at
        / 隔離期限後の物理削除、文章 only での「修正中」は
        禁止）
      - test corpus（property seed / scenario journey /
        chaos blueprint / contract pact / mutation report）
        の単一の真と immutable archive
      - test 自体の build artifact 化：generator output と
        手書き drift = 0、test を「PR で書き加える」のでは
        なく「classes.yaml / coverage_matrix.lock.yaml / 各
        scenarios/ から導出される build artifact として生成
        される」形を採る
      - drill cadence（chaos / restore / contract / e2e）の
        last_green_at 物理 enforcement、cadence 違反は
        Kyverno で関連 service deploy 物理 block
      - test framework の L1+ 単一深耕（pytest / hypothesis
        / Playwright / Pact / Litmus / pitest / Apache JMeter を 1 機能
        カテゴリ 1 OSS で固定、横並び禁止）
      - 検証 loop の各 phase（specify → generate → execute
        → triage → learn）が空欄でないことの cross-axis
        operational coverage の CI assertion

  - test が責務を持たない：
      - 個別 OSS の選択（→ 02_採用OSS一覧 / 各層 04_採用
        OSS、test は L1+ 単一深耕の規律を踏襲するのみ）
      - SLI / SLO target 値の意味論
        （→ 05_tier1/13_SLO適合仕様、test は coverage_
          compliance / mutation_score_compliance を SLO に
          登録するのみで target 値自体の意味論は持たない）
      - 観測可能性 SoR の物理運用
        （→ 05_tier1/09_観測適合仕様 / 09_data、test は
          test execution の OTel trace / ClickHouse 保存を
          SoR に従属させる側）
      - 脅威モデルの宣言
        （→ 10_security/15_脅威モデル適合仕様、test は
          脅威の「攻撃者視点 fault injection」を fault_
          chaos の 1 class として転写するのみ、threat 自体
          は宣言しない）
      - 鍵 rotation cadence / KEK / DEK 階層
        （→ 05_tier1/11_鍵管理適合仕様、test は rotation
          drill の chaos 起動経路のみ）
      - cluster 構築 / 廃棄 / 位相
        （→ 08_infra/15_クラスタ位相適合仕様、test は
          topology change を fault_chaos の blueprint と
          して再現する側）
      - migration pair の compatibility 判定
        （→ 05_tier1/08_マイグレーション適合仕様、test は
          dry_run.lock.yaml の last_green_at を generate
          する Tekton Pipeline 側）
      - 運用 loop の宣言
        （→ 11_ops/15_運用ループ適合仕様、test は ops
          drill_failure signal_class の発火源として振る
          舞うのみ）
      - test の意味論（assertion 内容そのもの）の記述
        （→ 各層 spec、test は coverage matrix を埋める
          ことだけを物理 enforce、assertion の中身は各軸
          spec の所有）

■ 至高路線における立ち位置
  - test は 13 軸 + meta + security + ops の更に上位に立つ
    「検証規律 invariant」の管掌者である。各軸が defense-
    in-depth 層 A〜E を持つが、層 C（integration test）と
    層 D（runtime drill）のあらゆる verification artifact
    は test が宣言する coverage matrix の (axis ×
    verification_class) cell に flow し、test は cross-
    axis に「全 cell が必ず最新の last_green_at と一致した
    artifact を持つ」ことを assert する。
  - test は「文章運用に頼らず物理 enforcement に転写する」
    という infra / data / security / ops の哲学を、検証次元
    （verification_class ⊥ axis ⊥ phase）で再保証する meta-
    layer である。「test を後で書く」「flaky だから一旦
    skip」「coverage は努力目標」を全て禁止し、coverage_
    matrix.lock.yaml の green cell 完全性を 1.0.0 ship
    blocker とする。
  - 各層の spec が「cross-axis assertion」「cross-threat
    assertion」「cross-loop assertion」を持つように、test
    は「cross-class assertion」を持ち、verification_class
    ⊗ axis ⊗ phase ⊗ 層 の四次元 grid の全 cell に物理
    artifact 経路が宣言済みであることを CI で物理 enforce
    する。

■ 至高路線における原則
  - 検証 matrix の単一の真：coverage_matrix.lock.yaml が
    build artifact、手書き禁止。各軸 spec の verification
    宣言と各 verification_class の execution result から
    生成される。
  - artifact の物理転写：全 verification claim（type
    check / property test / pact / scenario / chaos
    blueprint / mutation report）は pytest / hypothesis /
    Pact Broker / Playwright / Litmus / pitest / Apache JMeter のいず
    れかに必ず物理転写される。「文章のみで test 済み」は
    禁止、CI fail。
  - last_green_at の物理 enforcement：全 (axis ×
    verification_class) cell は last_green_at を持ち、
    cadence 越え cell が 1 つでもあれば関連 service deploy
    を Kyverno で物理 block。文章のみで「次回検証する」は
    禁止。
  - mutation_score の不可逆性：mutation_score の四半期
    monotonic increase を artifact_lock で物理 enforce。
    「mutation testing は flaky だから今回 skip」は禁止、
    skip は新 verification_class を切ることでのみ表現可能。
  - flaky の物理 quarantine：flaky 認定 test は quarantine_
    due_at（既定 14 day）を持ち、期限後に修正されていなけ
    れば自動 delete + ownership 強制。文章で「flaky 修正
    中」は禁止。
  - 単一 OSS 深耕（test 道具立て）：1 機能カテゴリ
    （unit / property / contract / e2e / chaos / mutation
    / load）に対し L1+ 単一深耕。横並びは持たない。
  - 段階的 release 禁止：1.0.0 時点で 5 verification_class
    全てが 17 軸全 cell で coverage green であること。
    coverage 不能な (axis × class) cell が 1 つでも残って
    いれば ship blocker。
  - test の物理計測：test execution は test_minutes_per_
    week / mutation_score_quarterly / flaky_count_quarterly
    metric として 13 SLO に登録、四半期で必ず（test_
    minutes 単調 + mutation_score 単調増加 + flaky_count
    単調減少）する artifact 化された target を持つ。文章
    で「テストを充実させたい」は禁止、必ず verification_
    matrix_target.lock.yaml の backlog entry として物理化。
