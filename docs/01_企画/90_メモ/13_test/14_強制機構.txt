============================================================
test 強制機構
============================================================

■ 一文方針
  - test 層の規律は Kyverno admission policy + Tekton
    Pipeline + Argo CD sync wave + Pact Broker webhook +
    Litmus workflow CR + cosign signed build artifact の
    AND-gate + test_event の hash chain 物理 enforce の
    7 種で enforce、手書き coverage matrix / mutation
    report / chaos blueprint / pact 注釈は CI fail、最終
    safety net は cosign signature の物理的真正性 +
    Kyverno admission webhook の deploy block + Ceph RGW
    Object Lock Compliance mode の retention 物理 delete
    不可 とする。

        - Argo Workflows：scenario_replay の長時間 run

  - 層 E：物理 enforcement（OS / engine / 暗号 / 物理
    layer の物理機構）
        - cosign signature の cryptographic verification
          （build artifact が真正であることを公開鍵で
            verify、Sigstore 標準）
        - Kyverno admission webhook の物理拒否（deploy
          API request を webhook が deny で返却、kube-

        - Ceph RGW Object Lock Compliance mode：security
          incident reproducer / mutation equivalent
          mutant input / chaos drill failure log の
          retention 期限内 物理 delete 不可（10_security
          14 / 09_data 14 と共有）
        - test_event hash chain：cryptographic chain が
          divergence 時点を物理特定（暗号学的 impossibility
          of forgery）
        - Pact pact / mutation report / Playwright trace /
          chaos workflow 結果は cosign signed artifact、
          tampering 検出は signature verify 物理 fail
        - chaos blueprint の v1_prod_gameday は OpenBao
          response wrapping の二人承認 break-glass token
          物理発行（10_security 14 / infra 04 と共有）

■ Kyverno admission policy 一覧（test 担当部分）
  - require-coverage-cell-green：deploy 前に対象 service
    の関連 coverage cell が green、cadence 内
  - require-mutation-score-monotonic：mutation_score
    .lock.yaml の quarter monotonic increase
  - require-flaky-quarantine-cap：flaky_quarantine の
    cap 越えなし、quarantine_due_at 14 day 以内
  - require-pact-can-i-deploy：Pact Broker の can-i-
    deploy green
  - require-chaos-drill-cadence：chaos blueprint の
    cadence 越えなし、cadence 越え service deploy block
  - require-regression-corpus-added：defect 修正 PR に
    regression_corpus_added 注釈
  - require-snapshot-signed：snapshot 更新 PR が drill_
    owner ack 済み
  - require-blast-radius-annotation：chaos experiment
    CR に blast_radius 注釈
  - block-prod-gameday-without-break-glass：v1_prod_
    gameday は break-glass token 必須
  - block-on-equivalent-mutant-without-proof：v1_strict
    policy module の equivalent mutant に symbolic_proof
    _pointer 必須
  - block-on-non-cosign-test-artifact：test artifact が
    cosign signed でない場合 block
  - block-during-active-incident-chaos：active incident

  - block-during-global-freeze-chaos-prod-gameday：
    global freeze 内の v1_prod_gameday を block
  - block-on-performance-regression：perf regression red

  - block-on-flaky-cap-exceeded：flaky 認定数 / total

■ admission policy のライフサイクル
  - 全 admission policy は build artifact（test/policy/
    kyverno-test-policies.yaml）から生成、手書き禁止。
  - generator の input：
        - coverage_matrix.lock.yaml
        - mutation_score.lock.yaml / mutation_history
          .lock.yaml
        - flaky_quarantine.lock.yaml
        - chaos_blueprints.lock.yaml
        - properties.yaml / property_corpus.lock.yaml
        - scenarios.yaml / scenario_corpus
        - pacts.yaml + Pact Broker pact result
        - performance_scenarios.lock.yaml /
          performance_baseline.lock.yaml
        - snapshot_masks.lock.yaml
        - ownership_table.lock.yaml（4 軸）
        - registry.yaml（00_軸登録）
  - drift：
        - runtime 上の admission policy が build artifact
          と乖離した場合、Argo CD が drift として検出 +
          self-heal。

■ break-glass
  - 緊急時に test admission policy を bypass する経路：
        1. OpenBao response wrapping で短期 cluster-
          admin 相当 token + Argo CD admin token + Argo
          Rollouts promote token を発行
        2. 発行操作は audit_event subject に v1_test_
          break_glass fact emit（必須 column：actor /
          reason / ticket_ref / expected_duration /
          incident_ref）
        3. 使用後 1 時間以内に postmortem PR 起票必須
        4. break-glass 使用は 13 SLO error budget
          consumption として記録（v1_test_break_glass_
          count の増分、ops 14 と整合）
        5. break-glass 経由の coverage cell 一時 ack /
          mutation_score override / flaky 解除 / chaos
          v1_prod_gameday 起動 / pact strict deploy も
          後追いで artifact 化（再現性確保）
        6. break-glass session 中も test_event の hash
          chain は継続、chain divergence 不可
        7. v1_prod_gameday / mutation_score 引き下げ /
          coverage cell ack の break-glass は二人承認
          必須（ChatOps 上で primary + secondary on-
          call の双方 ack）

■ 採用しない強制機構
  - 商用 admission engine（OPA Gatekeeper / Styra DAS）：
    採用しない、Kyverno L1+ 深耕（infra 14 / data 14 /
    security 14 / ops 14 と同じ）。
  - 商用 test orchestration platform：採用しない、
    Tekton + Argo Workflows + Litmus + Pact Broker +
    Playwright + pytest + k6 の OSS L1+ 単一深耕。
  - 文章 only の test 規律：禁止、全規律は機械検証
    可能な形で codify。
  - 「便利だから break-glass を常用」：禁止、break-
    glass は incident IR + audit_event + postmortem
    PR 必須の例外経路のみ。
  - 「business 都合で chaos drill を一時 off」：禁止、
    cadence 越えは admission block で物理 block。
  - mutation_score 引き下げの一時 ack：禁止、monotonic
    only、PR merge block。
  - flaky 14 day 越え延長：禁止、cap = 14 day。
  - snapshot 手動更新 without artifact-signed PR：
    禁止、Kyverno で merge block。
  - audit_event のサンプリング：禁止、100% 保存
    （preservation v1_zone_replicated 以上、archive
    tier 移行のみ retention 戦略）。
  - cosign signing key を CI runner に長期保持：禁止、
    OpenBao Transit + sign-on-demand のみ、key material
    は CI runner に物理に存在しない（10_security 14 /
    ops 14 と整合）。
