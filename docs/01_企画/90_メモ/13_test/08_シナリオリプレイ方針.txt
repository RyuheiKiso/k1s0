============================================================
test シナリオリプレイ方針（v1_scenario_replay）
============================================================

■ 一文方針
  - test 軸は v1_scenario_replay verification_class を
    Playwright（browser / mobile / API）+ Apache JMeter（synthetic /
    load journey）+ chainsaw（k8s integration）の 3 OSS
    L1+ で実装し、各軸 spec が宣言する journey scenario
    を determinism_class に応じた再現性（v1_full_
    deterministic は trace byte 同一、v1_seeded_random は
    seed 固定下の observable invariant 同一、v1_clock_
    controlled は clock 制御下の state machine 等価、
    v1_observable_invariant は業務 invariant 同一）として
    artifact 化、shadow cluster（infra01 v1_multi_region_
    active_passive の passive 側）上で nightly replay を
    Tekton Pipeline + Argo Workflows で物理 enforce し、
    replay 失敗を ops の v1_drill_failure signal_class へ
    自動 bridge する。

■ 設計原則
  - scenario は bundle である。
      yaml に書く test.scenario.* attribute のうち、
      scenario_id 1 つの値が他 6 dimension（journey_class
      / replay_target / blast_radius / determinism_class
      / fixture_lifecycle / runtime_budget_minutes）を
      一意に導出する。author が dimension を個別に
      override する経路は持たない。
  - dimension override は禁止する。
      「scenario_id_42 の blast_radius を緩めたい」要望
      は新 scenario_id を切ることで表現する。
  - dead spec を CI で殺す。
      scenarios.yaml に登録された全 scenario_id、
      Playwright trace に保存された全 trace、JMeter result に
      保存された全 result、chainsaw test に保存された全
      kuttl assertion は、いずれも参照されなくなった時点
      で CI fail。
  - replay は determinism_class が宣言する等価関係を必須。
      scenario の input fixture（fixtures/）/ database
      seed（fixtures/seed.sql）/ network record（HAR /
      Pact stub）/ time clock（mocked clock）/ random
      seed の 5 系統が determinism_class に応じた等価関係
      を満たす：v1_full_deterministic は trace byte 同一、
      v1_seeded_random は seed 固定下での observable
      invariant 同一、v1_clock_controlled は clock 制御下
      での state machine 等価、v1_observable_invariant は
      業務 invariant（state machine 終端状態 / event 集合
      / 等価 hash）同一。等価関係 violation は scenario
      の bug として treat、scenario 失敗ではなく
      determinism_violation として独立 alert。byte-level
      deterministic を物理不可な transport（gRPC bidi /
      HTTP/3 + WebTransport / SSE / WebSocket 越境）の
      cell は v1_observable_invariant 必須、byte-
      deterministic は要求しない。
  - shadow cluster 上で実行：
      v1_scenario_replay の実行は production cluster
      で行わない、必ず passive cluster（infra01 v1_multi
      _region_active_passive の passive 側）で実行、prod
      gameday は別 verification_class（fault_chaos）で。

■ scenario_id 命名と field 構造
  - scenario_id 命名規則：`<axis>__<journey_class>__
    <replay_target>` の 3 segment（例：`08_migration__
    dual_phase__cutover_journey`）
  - 必須 field（8 field）：
        - scenario_id：PK
        - journey_class：v1_user_facing_journey / v1_
          internal_pipeline_journey / v1_admin_console_
          journey / v1_drill_journey の 4 class
        - replay_target：v1_full_native / v1_browser_spa
          / v1_thick_native / v1_thin_business / v1_api_
          only の 5 class（client15 と整合）
        - blast_radius：v1_isolated（shadow cluster
          完全分離）/ v1_partial_shadow（一部 shadow）/
          v1_prod_dryrun（prod read-only access のみ）/
          v1_prod_gameday（prod write、別 class へ転写
          要、scenario_replay では不可）
        - determinism_class：v1_full_deterministic /
          v1_seeded_random / v1_clock_controlled /
          v1_observable_invariant
        - fixture_lifecycle：v1_per_run / v1_per_journey
          / v1_immutable_corpus
        - runtime_budget_minutes：v1_fast_5 / v1_
          medium_15 / v1_long_60 / v1_extreme_240
        - artifact_pointer：Playwright trace dir / JMeter
          result file / chainsaw test dir 等

■ journey_class enum
  - v1_user_facing_journey：
        - 顧客視点の e2e、Playwright が driver
        - 例：login → tenant 切替 → 業務操作 → logout
        - 5 distribution_class 全てで再現必須
  - v1_internal_pipeline_journey：
        - 内部 pipeline の e2e、Apache JMeter + chainsaw が driver
        - 例：08 migration 4 phase / 11 key rotation /
          14 OSS major version migration
  - v1_admin_console_journey：
        - 管理 console の e2e、Playwright が driver
        - 例：tenant onboarding / quota 設定 / RLS policy
          確認 / postmortem PR 作成
  - v1_drill_journey：
        - drill / replay 専用、Tekton Pipeline + Litmus
          が driver
        - 例：data01 restore_drill / infra01 failover_
          drill / ops15 5 signal runbook drill

■ replay_target enum（client15 distribution_class と整合）
  - v1_full_native：Tauri thick desktop app（Linux /
    Windows / Mac）、Playwright + Tauri webview
  - v1_browser_spa：browser SPA、Playwright browser
  - v1_thick_native：mobile / desktop native via Tauri、
    Playwright + Tauri webview
  - v1_thin_business：thin business API consumer、
    Playwright API request
  - v1_api_only：API only、Apache JMeter / Playwright API request
  - v1_legacy_dotnet：legacy .NET Framework consumer、
    Playwright + .NET WebView

■ blast_radius enum
  - v1_isolated：
        - shadow cluster 完全分離、prod data 一切触らず
        - default、scenario_replay の 95% 以上を占める
  - v1_partial_shadow：
        - shadow cluster + prod read-only API access
        - data01 restore_drill / 09 SemConv attribute
          observability journey 等の一部
  - v1_prod_dryrun：
        - prod read-only access のみ、write 厳禁
        - 13 SLO の burn rate journey / 15 capacity の
          per_tenant_volume forecast journey 等
  - v1_prod_gameday：
        - prod write、scenario_replay class では不可、
          fault_chaos class へ転写必須
        - blast_radius 拒否規律：scenario_replay cell に
          v1_prod_gameday 注釈は Conftest fail

■ determinism class enum
  - v1_full_deterministic：
        - 全 input fixture / random seed / clock /
          network record が固定、replay は完全再現
  - v1_seeded_random：
        - random seed のみ deterministic、それ以外は
          fixture 化、再現失敗は seed の bug として treat
  - v1_clock_controlled：
        - clock のみ mocked（pause / advance）、time
          dependent property（08 migration window /
          11 key rotation cadence）の journey で必須
  - v1_observable_invariant：
        - trace byte 同一は要求しない。代わりに業務
          invariant（state machine の終端状態 / 観測
          event 集合 / 等価 hash / domain-level 不変
          条件）の同一を等価関係として要求。byte-level
          deterministic が物理不可な transport（gRPC
          bidi / HTTP/3 + WebTransport / SSE 越境 /
          WebSocket / kernel scheduler 依存の concurrent
          journey）の cell で必須。等価判定は scenario
          側で invariant_predicates.lock.yaml に
          machine-readable に宣言、Tekton Pipeline が
          assertion として物理 enforce。

■ fixture lifecycle enum
  - v1_per_run：
        - run ごとに新規生成、teardown で削除
  - v1_per_journey：
        - journey ごとに固定、journey 内 step で再利用
  - v1_immutable_corpus：
        - immutable archive、retention 365 day（Ceph
          RGW Object Lock Compliance mode）

■ runtime_budget_minutes enum
  - v1_fast_5：5 min、PR ごとに必ず実行
  - v1_medium_15：15 min、nightly pipeline
  - v1_long_60：60 min、weekly pipeline
  - v1_extreme_240：240 min、monthly pipeline、cluster
    shadow 上の dedicated executor

■ replay 経路と shadow cluster
  - shadow cluster：
        - infra01 v1_multi_region_active_passive の
          passive 側 cluster を replay 専用に共用、Argo
          CD sync wave で test artifact を deploy
        - data01 v1_cross_region_replicated の data
          replica を read-only access、write 厳禁
        - shadow cluster の cosign signed image は prod
          と同一、cosign verify が release_gate に入力
  - replay run の SoR：
        - test_event subject に v1_scenario_replay_run
          fact emit、ClickHouse + Ceph RGW 二重保存
        - Playwright trace（HAR + screenshot + video）/
          JMeter result / chainsaw assertion log は Ceph
          RGW に retention 90 day、failure 時 365 day
  - replay 失敗の bridge：
        - replay red の場合、ops の v1_drill_failure
          signal_class へ自動 bridge、severity_default
          v1_notify、test framework owner に Mattermost
          page

■ scenario corpus
  - scenarios.yaml：scenario_id catalog
  - corpus/：fixture / seed / HAR / clock / random seed
    の 5 系統 input
  - corpus は build artifact、cosign signed、scenarios.
    yaml と corpus の 1:1 整合は Conftest が物理 enforce

■ cross-axis bind（scenario_replay 列の cell）
  - 07 transport：reconnect journey（5 distribution_class
    全てで再現）。bidi / HTTP/3 + WebTransport / SSE /
    WebSocket 越境の cell は determinism_class が
    v1_observable_invariant 必須、byte-deterministic は
    要求しない
  - 08 migration：4 phase journey（pre / dual / cutover
    / post の 4 step）
  - 09 observability：trace continuity journey（OTel
    span の sampling boundary 通過）
  - 10 auth：login + step-up journey + logout
  - 11 key：rotation drill journey（cadence ごと）
  - 12 schema：schema migration journey（aggregate
    rename + DB column add の 7 declaration 同期）
  - 13 SLO：burn rate alert journey（fast burn / slow
    burn の 2 path）
  - 14 OSS-lifecycle：major version migration journey
    （pair_target の旧 → 新）
  - 15 capacity：per_tenant_volume overflow → cold
    archive journey
  - 32 data-tenant：tenant onboarding journey（GUC
    propagation の boundary 通過）
  - 39 client：offline → reconcile journey（4-state
    machine の dirty → reconciled path）
  - infra01：drain → migrate journey（zone partition
    failover）
  - data01：restore_drill journey（v1_zone_replicated
    以上 全 preservation_class）
  - security15：red-team replay journey（threat 1:1）
  - client15：5 distribution_class 全ての conformance
    journey（cadence ごと）
  - ops15：5 signal_class 全ての runbook drill journey

■ 採用しない経路
  - production cluster 上の scenario_replay：禁止、必ず
    shadow cluster
  - flaky scenario の長期残置：禁止、quarantine 14 day
    cap
  - non-deterministic scenario の cell bind：禁止、
    determinism_violation として独立 alert
  - 商用 e2e SaaS（BrowserStack / Sauce Labs / Mabl）：
    採用しない
  - LLM auto-record の盲目的 merge：禁止、Playwright
    codegen output は人間 reviewer による意味論 check
    必須
  - shadow cluster での write を経由した prod data
    汚染：禁止、Argo CD sync wave で write 経路 物理
    block
  - replay 失敗の文章 only triage：禁止、必ず ops の
    v1_drill_failure へ bridge して postmortem PR 起票
