============================================================
test 契約検証方針（v1_contract_pair）
============================================================

■ 一文方針
  - test 軸は v1_contract_pair verification_class を Pact
    L1+ + Pact Broker self-host + Buf-breaking との double-
    bound で実装し、隣接層間（producer / consumer / peer
    / SDK / DB / event / config の 7 declaration 系列）の
    contract が双方向に一致することを Pact pact + buf-
    breaking signature の二系統 artifact で物理 enforce
    し、breaking detection を Kyverno admission policy で
    PR merge block する。

■ 設計原則
  - contract pair は bundle である。
      yaml に書く test.contract.* attribute のうち、
      pair_id 1 つの値が他 5 dimension（producer_role /
      consumer_role / declaration_class / pact_lifecycle
      / breaking_policy）を一意に導出する。Pact 作者が
      dimension を個別に override する経路は持たない。
  - dimension override は禁止する。
      「pair_id_8 の breaking_policy を allow_with_
      annotation に変えたい」要望は新 pair_id を切る
      ことで表現する。
  - dead spec を CI で殺す。
      pacts.yaml に登録された全 pair_id、Pact Broker に
      publish された全 pact、buf workflow に declared 全
      module、proto に annotated 全 RPC method の retry /
      slo / quota / observability annotation 欠損は CI
      fail。
  - 7 declaration 系列を全 pair で完備：
        - producer_to_consumer：API producer → API
          consumer
        - peer_to_peer：tier1 ↔ tier1 / tier2 ↔ tier2 の
          同層 peer pact
        - sdk_to_server：12 client distribution の SDK ↔
          server pact（5 distribution_class 全て）
        - db_to_app：PostgreSQL ↔ application、12 schema
          aggregate qualified name の DB-side declaration
        - event_to_consumer：Kafka / NATS / event bus の
          producer ↔ consumer pact
        - config_to_runtime：flagd / config map → runtime
          consumer pact
        - infra_to_app：infra control plane ↔ workload
          contract（Kubernetes CRD / Argo CD application
          spec / Kyverno policy schema）
  - breaking detection は機械可読：Buf-breaking + Pact
    can-i-deploy + jsonschema diff の三系統で物理判定、
    人間判断を介在させる経路は持たない。
  - pact_lifecycle は append-only + tagging：pact
    publication は immutable、tag による rollout
    （v1_dev / v1_staging / v1_prod / v1_archived）で
    state 表現、削除は dead spec 検出のみ。

■ pair_id 命名と field 構造
  - pair_id 命名規則：`<axis>__<producer_role>__
    <consumer_role>__<declaration_class>` の 4 segment
    （例：`07_transport__server__client__producer_to_
    consumer`）
  - 必須 field（7 field）：
        - pair_id：PK
        - producer_role / consumer_role：service / SDK /
          DB / event / config 等の role enum
        - declaration_class：上記 7 系列の enum
        - pact_lifecycle：v1_dev / v1_staging / v1_prod /
          v1_archived
        - breaking_policy：v1_strict（既定）/ v1_
          deprecation_window（08 migration の dual_window
          中のみ allow）
        - artifact_pointer：Pact Broker の pact reference
          + buf-breaking signature reference

■ producer_role / consumer_role / declaration_class enum
  - producer_role：
        - tier1_server / tier2_service / tier3_app /
          infra_control_plane / data_engine /
          security_engine / ops_engine / sdk_runtime /
          db_engine / event_broker / config_runtime
  - consumer_role：
        - producer_role と同じ enum、producer ⊂ consumer
          として peer_to_peer は同 role 同士で表現
  - declaration_class：上記 7 系列、registry.yaml で
    自動拡張禁止（cap = 7、v2 でのみ +5 拡張）

■ pact 生成 pipeline
  - generator：
        - consumer 側で Pact runtime（pact-python /
          pact-jvm / pact-js / pact-net / pact-go /
          pact-rust）が test 中に pact を出力
        - 出力 pact は Tekton Pipeline `pact-publish`
          経由で Pact Broker self-host に publish
        - Pact Broker → producer の verify webhook を
          Tekton trigger に bind、producer 側で verify
          test を自動起動
        - Buf-breaking は producer 側 PR で proto / openapi
          / asyncapi の breaking detection を物理 fail
  - cosign：
        - publish された pact は cosign signed、verify
          結果も cosign signed
        - signature は release_gate.lock.yaml の AND-gate
          に入力

■ pact lifecycle と tagging
  - tag enum：
        - v1_dev：consumer の dev branch から publish、
          producer 側 verify 不要（参考用）
        - v1_staging：staging deploy 時の pact、producer
          verify 必須、verify red の場合 PR merge block
        - v1_prod：prod deploy 時の pact、producer verify
          必須 + can-i-deploy green が release_gate AND
          -gate に入力
        - v1_archived：rollback 後の pact、verify 不要、
          retention のみ（90 day）
  - tag 遷移：
        - dev → staging → prod は monotonic、逆遷移は
          rollback としてのみ allow（v1_archived へ）
        - 同 pair に複数 tag が同時 active な場合は
          can-i-deploy が AND（全 active tag が green）
  - tag 遷移経路：
        - 自動：consumer / producer の deploy event 経由
        - 手動：UI 上の手動 tag 遷移は audit_event 必須

■ breaking detection の 3 系統
  - 系統 1：Buf-breaking
        - proto / openapi / asyncapi の field add /
          remove / type change を Buf-breaking が物理
          判定、breaking 検出 PR は Kyverno で merge
          block
  - 系統 2：Pact can-i-deploy
        - Pact Broker の can-i-deploy command が consumer
          / producer 側の deploy 適合性を判定、red の場合
          deploy が Kyverno admission policy で block
  - 系統 3：jsonschema / CUE diff
        - non-proto schema（jsonschema / CUE / yaml
          schema）に対する diff、Buf-breaking 同等の規律
        - 13 SLO の SLO yaml schema、infra01 topology
          schema、data01 preservation schema 等が対象

■ breaking_policy enum
  - v1_strict（既定）：
        - 任意の field add / remove / type change を
          breaking として deploy block
        - 7 transport / 12 schema / 13 SLO / client15
          SDK distribution / 32 RLS が default
  - v1_deprecation_window：
        - 08 migration の dual_window 中のみ allow、
          dual_window_days の cadence_days 内に新 pair
          version の green が必須、cadence 越え は
          deploy block
        - 適用範囲：08 migration 4 phase 中の旧 / 新
          pair に限定、それ以外は v1_strict

■ Pact Broker self-host 構成
  - Pact Broker（OSS）を self-host、PostgreSQL backend
  - cosign 署名された pact のみ publish allowed、未署名
    pact は admission policy で reject
  - webhook：
        - Pact published → Tekton Pipeline `pact-verify`
          自動起動
        - Pact verify result → coverage_matrix.lock.yaml
          の v1_contract_pair 列 cell の last_green_at
          更新
        - can-i-deploy red → Mattermost incident channel
          に notify、ops の v1_change_induced signal
          として bridge

■ cross-axis bind（contract_pair 列の cell）
  - 07 transport：
        - producer = tier1_server、consumer = sdk_runtime
          (5 distribution_class 全て) の 5 pact、Buf-
          breaking + Pact 双方向 lock
  - 08 migration：
        - 4 phase の旧 / 新 pact pair、dual_window 中の
          v1_deprecation_window pair が cadence 内
  - 09 observability：
        - OTel exporter ↔ collector の pact、SemConv
          attribute schema の Buf-breaking
  - 10 auth：
        - IDP ↔ client の OIDC contract、Keycloak の
          discovery document jsonschema
  - 11 key：
        - KMS ↔ application の API contract、KMS
          plaintext / wrapped envelope schema
  - 12 schema：
        - producer / consumer / DB / event / config の 5
          declaration が aggregate qualified name で
          結節、本軸が双方向 lock
  - 13 SLO：
        - Sloth ↔ Pyrra の rule generator pact、recording
          rule の name space invariant
  - 14 OSS-lifecycle：
        - pair_target の旧 / 新 OSS API contract、major
          version migration drill 中の pact
  - 15 capacity：
        - quota engine ↔ admission policy の contract
  - 32 data-tenant：
        - GUC propagation contract、SessionContext の
          schema
  - 39 client：
        - client ↔ server resync contract、4-state machine
          transition contract
  - infra01 / data01 / security15 / client15 / ops15：
        - cluster ↔ control plane / replication / threat
          mitigation / SDK ↔ server / runbook ↔ alert の
          各 pact

■ 採用しない経路
  - 商用 Pact SaaS（Pactflow）：採用しない、self-host
  - Pact 以外の contract test（Spring Cloud Contract /
    Karate）：採用しない
  - 文章のみで「contract OK」：禁止、必ず Pact pact +
    Buf-breaking signature の双方を artifact 化
  - breaking_policy override の人間判断介在：禁止、
    deprecation_window のみ artifact 化された経路、
    v1_strict は機械的に block
  - 商用 schema registry（Confluent / AWS Glue）：採用
    しない、Apicurio Registry self-host（tier1/12 と整合）
  - LLM-generated pact の盲目的 merge：禁止、必ず人間
    reviewer による semantic check + can-i-deploy green
