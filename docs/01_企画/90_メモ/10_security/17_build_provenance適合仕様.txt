■ 設計原則
  - build_provenance_class は bundle である。
      yaml に書く security.build_provenance.* attribute のうち、
      build_provenance_class 1 つの値が他 5 dimension（hermetic_
      scope / artifact_signing_chain / dependency_lock_scope /
      rebuild_determinism / supply_chain_transparency）を一意
      に導出する。Buf workflow / Tekton Chains pipeline / Bazel
      build rule / Nix flake / Harbor admission policy / Kyverno
      verifyImages policy の作者が dimension を個別に override
      する経路は持たない。
  - dimension override は禁止する。
      「v1_runtime_image_release の rebuild_determinism を best_
      effort に下げたい」要望は新 class を切ることで表現する。
      class 数の爆発は意味論の規律として受け入れる。
  - dead spec を CI で殺す。
      classes.yaml に登録された全 class、scenarios.yaml に登録
      された全 assertion id、artifact_inventory.lock.yaml に
      列挙された全 artifact、provenance_attestation.lock.yaml
      に列挙された全 predicate、reproducibility_matrix.lock.yaml
      に列挙された全 hash entry は、いずれも参照されなくなった
      時点で CI fail とする。Harbor catalog のうち build_
      provenance_class 注釈が無い image は admission deny by
      default（class 未宣言 artifact の deploy / pull を物理
      reject）。
  - 5 種類 enforcement orchestrator を全 build_provenance_class
    に必須化する。
      tekton_chains_attestor / bazel_nix_hermetic_runner /
      reproducibility_consensus_verifier / cosign_rekor_witness_
      chain / kyverno_admission_verifier の 5 orchestrator は、
      各 class が必要とする層を宣言する。同一 enforcement は複
      数 orchestrator に分散しないが、同一 artifact では複数
      class が複数 orchestrator を併用する。
  - build reproducibility を物理 property とする。
      「同 input source git commit + 同 builder image digest +
      同 dependency lock hash → 同 output artifact bit hash」を
      reproducibility_consensus_verifier で複数 builder（Tekton
      + GitHub Actions self-hosted + Bazel remote-exec + Nix
      flake build の 4 経路）から並列実行し、N/N 全 builder で
      sha256 が一致することを CI で必ず検証する。13 SLO の
      v1_request_availability sub-class を本仕様の attestation_
      verify_failure event 経路で連結し、verify 失敗を即時
      alert + admission block に流す。
  - defense-in-depth は 5 層で構成する。
      層 A : compile（Tekton Chains が in-toto/slsaprovenance/
              v1.0 predicate を emit、Buf workflow codegen の
              in-toto link metadata と統合）
      層 B : lint（Conftest custom rule の 5 dcv_pr_blocks_*、
              GitHub Actions Required Status Check）
      層 C : chaos test（Litmus で attestation tampering 注入、
              consensus failure を property test）
      層 D : runtime（Kyverno admission policy の 5 dcv_kyverno
              _blocks_*、verifyImages + verifySLSAProvenance）
      層 E : 物理（Linux user namespace + seccomp + cgroup v2、
              Bazel sandbox + Nix sandbox の二重 sandbox、Rekor
              Merkle tree immutable log、HSM PKCS#11 transit、
              kube-bench CIS / NSA/CISA Hardening）
      任意の単層が破れても他層が必ず止める。物理 enforcement
      は最終 safety net。

  - yaml に書ける build_provenance_class は次の 5 値のみ。各
    artifact 実体は artifact_inventory.lock.yaml の枝で classes
    .yaml の keys と照合する。

      -----------------------------------+--------------------------------------+-------------------------------+--------------------------+--------------------------------+------------------------------------------------------
      v1_runtime_image_release           | codegen_compile_link_image_attest    | cosign_rekor_witness          | sbom_attested_mirror     | bit_for_bit_ci_verified        | rekor_plus_private_archive
      v1_library_sdk_release             | codegen_compile_link_image_attest    | cosign_rekor_witness_multiparty | nix_flake_pinned       | nix_flake_bit_identical        | rekor_plus_private_archive_plus_reviewer_attest
      v1_cli_or_oci_artifact_release     | codegen_compile_link_image_attest    | cosign_rekor_witness          | sbom_attested_mirror     | bit_for_bit_ci_verified        | rekor_plus_private_archive

  - 各 class の不変条件と典型用途：

      - v1_runtime_image_release
          - tier1 / tier2 server image / Companion sidecar image
            / infra runner image / ops-edge cluster image。
            production deploy 経路の本命。
          - hermetic_scope：codegen → compile → link → image
            build → attestation の全段で `RUN --network=none`
            (Buildkit) + Bazel sandbox + Nix sandbox の三重
            sandbox。internal mirror（Athens / Verdaccio /
            Harbor proxy / cargo registry proxy / NuGet feed）
            のみ通過、Internet 直接 fetch 物理不可能。
          - artifact_signing_chain：cosign keyless（GitHub
            Actions OIDC → OpenBao → Cosign Fulcio）+ Rekor
            inclusion proof + Witness multi-attestation（GitHub
            Actions runner + Tekton Chains の双方が独立 attest）。
          - dependency_lock_scope：sbom_attested_mirror。Syft
            生成 SPDX + CycloneDX 両 format が SBOM として
            attached、Harbor mirror 経由のみ通る dependency が
            in-toto material として lock。
          - rebuild_determinism：bit_for_bit_ci_verified。同
            input → 同 output の sha256 一致を Tekton + GitHub
            Actions + Bazel remote-exec の 3 builder で並行検
            証、3/3 一致で green。
          - supply_chain_transparency：rekor_plus_private_archive。
            Sigstore Rekor public log + Harbor 内 private cosign
            attestation archive 双方に publish、改竄不可能性を
            Merkle tree で計算量的保証。
          - 典型：tier1 server / tier2 業務 Service / Companion
            sidecar / infra runner / ops-edge cluster。
          - rotation_cadence_hours: 24（per-job ephemeral signing
            key）。

      - v1_library_sdk_release

            rust / go122 / python312 / ruby33 / dotnet_framework
            _4_6_2_plus / browser TypeScript / tauri rust+
            webview）。end-user の依存先として最も改竄影響が
            大きい artifact 群。
          - hermetic_scope：codegen_compile_link_image_attest。
            Nix flake で全 dependency の hash 固定 + Bazel
            sandbox で言語横断 hermetic + Buildkit `RUN
            --network=none` で OS 側 network egress 物理不可能。
          - artifact_signing_chain：cosign_rekor_witness_
            multiparty。GitHub Actions runner + Tekton Chains
            + 独立 isolated builder の 3 attestor が独立 OIDC
            keyless signing、reviewer_attest_signers_min: 2 で
            人間 reviewer attestation も in-toto link として
            付加。
          - dependency_lock_scope：nix_flake_pinned。Nix flake
            input の sha256 / sri hash が flake.lock で純粋
            関数的に固定、build graph 全体が hash addressed。
          - rebuild_determinism：nix_flake_bit_identical。
            consensus_builders_min: 3 で N/N 全 builder で nix
            build 結果 sha256 一致、SOURCE_DATE_EPOCH 不要
            （Nix が言語横断で deterministic build を物理保証）。
          - supply_chain_transparency：rekor_plus_private_
            archive_plus_reviewer_attest。Rekor public log +
            Harbor private archive + reviewer 2 名以上の人間
            attestation を in-toto link として 3 重 publish。
          - 典型：12_client/15 の 5 distribution_class のうち
            v1_thin_business_api_only を除く 4 class（v1_full_
            native_with_companion / v1_legacy_dotnet_framework
            / v1_browser_spa_typescript / v1_thick_native_via_
            tauri）の SDK package。
          - SLSA L4 schema 必須（reproducible: true / hermetic:
            true / parameterless: true）。

      - v1_cli_or_oci_artifact_release
          - Helm chart / OPA bundle / Apicurio subject bundle
            / CLI binary / Argo CD CMP / Kustomize plugin の
            OCI artifact 群。配布形が image とほぼ同等だが
            実行時に compile されない declarative artifact。
          - hermetic_scope：codegen_compile_link_image_attest。
            Helm chart は values schema 込みで Bazel + Nix で
            ビルド、OPA bundle は wasm compile を hermetic 化、
            CLI binary は Nix flake + cargo / go の reproducible
            build 経路。
          - artifact_signing_chain：cosign_rekor_witness。
            v1_runtime_image_release と同等の chain。
          - dependency_lock_scope：sbom_attested_mirror。
          - rebuild_determinism：bit_for_bit_ci_verified。
          - supply_chain_transparency：rekor_plus_private_
            archive。
          - 典型：argocd-cmp / kustomize-plugin / opa-bundle /
            helm-chart / apicurio-subject-bundle / k1s0-cli。

      - v1_thin_business_api_artifact
          - 12_client/15 の v1_thin_business_api_only
            distribution に対応する OpenAPI yaml only artifact。
            compile phase 不在のため hermetic は codegen のみ。
          - hermetic_scope：codegen_only。Buf workflow による
            .proto → OpenAPI yaml 派生のみ hermetic、compile
            / link / image build は不在。
          - artifact_signing_chain：cosign_rfc3161_timestamp。

          - dependency_lock_scope：hash_pinned_mirror。proto

            production namespace への deploy / pull を物理

■ dimension の根拠
  - hermetic_scope は build sandbox の射程：
        codegen_only                     → .proto → 派生 yaml
                                            まで sandbox（Buf
                                            workflow のみ）
        codegen_compile                  → compile phase まで
                                            sandbox（image build
                                            は best-effort）
        codegen_compile_link             → link 段まで sandbox
        codegen_compile_link_image       → image build 段まで
                                            sandbox（Buildkit
                                            `RUN --network=none`）
        codegen_compile_link_image_attest → attestation emit 段
                                            まで sandbox（Tekton
                                            Chains が hermetic
                                            container 内で
                                            in-toto predicate
                                            生成）
    複数粒度を重ねた表現は class 内 fixed。
  - artifact_signing_chain は signing trust anchor：
        cosign_keyless                    → Sigstore Fulcio + Rekor
        cosign_rfc3161_timestamp          → 上記 + RFC 3161 TSA
                                            （改竄時刻保証）
        cosign_rekor_witness              → 上記 + Witness multi-
                                            attestation chain
        cosign_rekor_witness_multiparty   → 上記 + 人間 reviewer
                                            attest（≥ 2 signers）
    混合は class 内 fixed。
  - dependency_lock_scope は依存 hash 固定の射程：
        lockfile_only           → 言語別 lockfile（Cargo.lock /
                                   package-lock.json / go.sum）
                                   のみ
        vendored                → 全 dependency を repo に
                                   vendoring
        hash_pinned_mirror      → Harbor / Athens / Verdaccio
                                   mirror の sha256 pin
        nix_flake_pinned        → Nix flake input の sri hash
                                   全 graph 固定
        sbom_attested_mirror    → 上記 hash_pinned_mirror + Syft
                                   生成 SBOM attestation 添付
  - rebuild_determinism は再現性の物理保証強度：
        best_effort                       → 保証なし
        source_date_epoch_pinned          → SOURCE_DATE_EPOCH
                                            による timestamp
                                            一意化のみ
        bit_for_bit_ci_verified           → 複数 builder で sha256
                                            一致を CI gate
        multi_builder_consensus           → 上記 + 独立 builder
                                            数 ≥ 3 で consensus
        nix_flake_bit_identical           → Nix が言語横断で
                                            deterministic build
                                            を物理保証
  - supply_chain_transparency は publish 経路の冗長度：
        log_only                                          → Harbor
                                                            内部 log のみ
        rekor_public                                      → 上記
                                                            + Sigstore
                                                            Rekor public
                                                            Merkle tree
        rekor_plus_private_archive                        → 上記
                                                            + Harbor private
                                                            cosign archive
        rekor_plus_private_archive_plus_reviewer_attest   → 上記
                                                            + 人間
                                                            reviewer
                                                            in-toto link

■ derived dimension（per-artifact threshold）を独立次元にしない理由
  - per-artifact の閾値（v1_library_sdk_release の consensus_
    builders_min=3 / reviewer_attest_signers_min=2 vs v1_runtime
    _image_release の rotation_cadence_hours=24）は本来 dimension
    たり得るが、5 class それぞれで「同じ hermetic_scope /
    artifact_signing_chain / dependency_lock_scope / rebuild_
    determinism / supply_chain_transparency 構造で閾値だけが
    instance 別」という同形操作になる。
  - 閾値は class instantiate 時の instance 属性として宣言し、
    build artifact が Tekton TaskRun manifest / Bazel build rule
    / Nix flake / Kyverno admission policy / Litmus chaos
    experiment を生成する形に統一。
  - infra / security オペレータ / 業務側で迷う余地がないため、
    独立 dimension 化する利得が乏しい。

■ 5 種類 enforcement orchestrator の責務分離（特殊機構）
  - orchestrator 1: tekton_chains_attestor
      - 全 class（v1_dev_or_canary_artifact 除く）の主担当。
        Tekton Chains が TaskRun ごとに in-toto/slsaprovenance/
        v1.0 predicate を emit、tool versions（buf / protoc /
        rustc / go / dotnet / node / cargo / npm / Bazel / Nix
        各 version）を pin、signed git commit hash を embed、
        reviewer attest を schema 必須化。
      - 12 schema 進化適合仕様の codegen hermeticity invariant /
        Buf workflow と統合、層 A の compile time enforcement。

  - orchestrator 2: bazel_nix_hermetic_runner
      - 全 class（v1_thin_business_api_artifact / v1_dev_or_
        canary_artifact 除く）の主担当。Bazel = remote-exec /
        build graph / cache、Nix = dependency lock + sandboxed
        build の責務分離で run。Linux user namespace + seccomp
        + cgroup v2 + `RUN --network=none` (Buildkit) の三重
        sandbox を物理層で強制。
      - 層 D の runtime + 層 E の physical を担当する hybrid
        orchestrator。

  - orchestrator 3: reproducibility_consensus_verifier
      - v1_runtime_image_release / v1_library_sdk_release / v1_
        cli_or_oci_artifact_release の主担当。Tekton + GitHub
        Actions self-hosted + Bazel remote-exec + Nix flake build
        の 4 経路で並行 build、reproducibility_matrix.lock.yaml
        に各 builder の sha256 を書き込み、N/N 一致 (consensus_
        status: green) を CI gate。
      - Litmus chaos で 1 builder が tampered な場合の consensus
        動作を property test、層 C の chaos test を担当。

  - orchestrator 4: cosign_rekor_witness_chain
      - 全 class（v1_dev_or_canary_artifact は keyless のみ）の
        artifact 生成後段の主担当。Cosign signature + Rekor
        inclusion proof + Witness multi-attestation を chain と
        して emit。HSM PKCS#11 backend（11_鍵管理） + per-job
        ephemeral signing key（OpenBao transit engine、24h
        rotation）で署名鍵を物理発行。
      - 層 D の runtime を担当。

  - orchestrator 5: kyverno_admission_verifier
      - 全 class の deploy / pull 段の最終 gate。Kyverno
        verifyImages + verifySLSAProvenance custom policy が
        admission webhook で物理 reject。08_infra/14_強制機構
        の既存 Kyverno policy bundle に dcv_kyverno_blocks_*
        5 policy を追加。
      - 層 E の物理 enforcement を担当。

  - 5 orchestrator は順次評価される（Tekton Chains → Bazel/Nix
    → reproducibility consensus → Cosign/Rekor/Witness → Kyverno）
    が、各 build_provenance_class は 1 orchestrator を「主担当」
    として宣言。他層は補助的に協調動作（例：v1_library_sdk_
    release の主担当は bazel_nix_hermetic_runner だが、
    reproducibility_consensus_verifier が 3/3 consensus を副担
    当）。

■ build reproducibility property（特殊機構）
  - 「同 input source git commit + 同 builder image digest +
    同 dependency lock hash → 同 output artifact bit hash」を
    property test として CI で必ず green を返すことを必須化：
        ∀ artifact a with a.build_provenance_class ∈
            {v1_runtime_image_release,
             v1_library_sdk_release,
             v1_cli_or_oci_artifact_release}:
          ∀ builder b1, b2, b3 ∈ a.builder_set:
            sha256(build(a, b1)) == sha256(build(a, b2))
                                  == sha256(build(a, b3))
        MUST hold

  - 検証手順：
      1. Tekton + GitHub Actions self-hosted + Bazel remote-exec
         + Nix flake build の 4 経路で並行 build。
      2. 各 builder の output artifact を Harbor に push、
         reproducibility_matrix.lock.yaml に sha256 を書き込み。
      3. consensus_status: green が N/N 全 builder bit-identical
         のときのみ満たされ、release pipeline が次段に進める。
      4. 違反検出は 13_test v1_fault_chaos の root cause
         investigation を trigger、ops15 runbook drill replay。

  - property に違反した場合の対応：
      - 1 builder のみ red → 当該 builder image の corruption
        suspected、builder image 再生成 + 全 attestation
        revoke。
      - 全 builder red → source code の non-deterministic
        construct（time-dependent / map iteration order /
        absolute path）混入の可能性。flake-checker / cargo
        deterministic / go GOFLAGS=-trimpath で root cause
        investigation。
      - Nix flake 採用 class（v1_library_sdk_release）で red
        → flake.lock のハッシュ不整合、Nix store rebuild +
        flake.lock 更新 PR。

■ v2 拡張ルール
  - 新 class の追加は purely additive：v1 class はそのまま残し、
    v2 で新規 class（例：v2_builder_tee_attestation、v2_air_
    gapped_offline_signing、v2_post_quantum_hybrid_signing）を
    追加する。
  - 既存 class の dimension 値変更は破壊的変更（major version
    up）。
  - 命名は vN_<scope>_<hermetic_kind> 形式に固定。
  - dimension override 禁止の規律は v1 → v2 跨ぎでも維持する。
  - SLSA L4+（builder TEE attestation）/ post-quantum hybrid
    signing（X25519 + ML-KEM-768 hybrid、Ed25519 + ML-DSA-65
    dual-sig）採用は v2 候補。v1 は SLSA L4（library SDK のみ）
    + classical signing（Ed25519 + ECDSA）に固定。

■ 至高路線における位置づけの帰結
  - 本仕様は「個別軸の規律から発生する全 build artifact
    attestation claim が単一の真の中で機械検証される」ことを
    requires する build provenance 軸。運用コスト度外視
    （CLAUDE.md 上位方針）の哲学に従い、Bazel + Nix の併用
    採用 / 三重 sandbox / multi-builder consensus 3/3 / reviewer
    attest 2 名 / 24h ephemeral signing key rotation / SLSA L4
    schema 必須 を v1 で固定する。「現実には起こりにくい」
    attestation tampering / reproducibility drift / hermetic
    egress を物理層 5 重で塞ぐことで、1.0.0 ship 時点の supply
    chain 安全性を「机上の計画」ではなく「物理 enforcement」
    として確立する。
  - 運用コスト最小化のために consensus_builders_min を 2 に
    緩めたり、Nix を v2 に逃がしたりする選択肢は本軸では取ら
    ない。「作業量を減らすために機能を削減するのは避ける」
    （CLAUDE.md）の規律に厳密に従い、Bazel remote-exec + Nix
    flake + Witness multi-attestation + Tekton Chains attestor
    + Kyverno verifyImages + verifySLSAProvenance の 6 機構を
    全て v1 必須とする。
  - 本軸が「OSS として公開する k1s0 自身の supply chain を
    OSS 業界 最高水準（CNCF graduation 同等以上）に保つ」こと
    を物理保証する。SLSA L4 達成 OSS は 2026 年時点で僅少で
    あり、本軸の v1 達成自体が 03_競合との差別化 の中核要素
    となる。

  - 本仕様の 5 ファイル（classes / scenarios / artifact_inventory
