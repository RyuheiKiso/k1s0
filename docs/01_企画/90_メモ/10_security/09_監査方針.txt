============================================================
security 監査方針
============================================================

■ 一文方針
  - 全ての特権操作 / 認証イベント / データアクセス /
    DDL / 制御平面操作 / break-glass / IR 動作は audit_
    event subject に append-only で emit、cryptographic
    chaining + WORM Object Lock + 鍵失効による cryptographic
    erasure 以外の論理 / 物理 delete 経路を持たない、
    最低 retention 7 年（v1_audit_log preservation_class）
    で物理保持する。

■ audit subject 階層（09 観測適合仕様 の 5 signal と整合）
  - 09 観測 SoR で signal_class = audit_event
    （v1_signal の 1 つ）として ClickHouse に store。
    本層は subject schema と immutability 規律を宣言。

  - audit_event subject の sub-class（fact_class）：
        v1_authn：認証成功 / 失敗 / token issue / token
                  refresh / token revoke
        v1_authz：認可決定（allow / deny）、RLS POLICY 経由
                  含む
        v1_data_access：DB / topic / cache の read /
                        write / delete（CDC + DB engine
                        audit）
        v1_ddl：schema 変更（DDL / migration apply /
                Apicurio subject 登録）
        v1_control_plane：Kubernetes API request（audit
                          policy 経由）/ Argo CD sync /
                          Kyverno admission decision /
                          OpenBao access
        v1_break_glass：cluster-admin / DB superuser の
                         短期発行 + 使用 + revoke
        v1_ir：IR playbook 起動 / step 完了 / postmortem
                登録
        v1_secret_lifecycle：OpenBao lease 発行 / 失効 /
                              rotation
        v1_supply_chain：cosign verify pass/fail / image
                          push / SBOM upload / Tekton
                          Chains attestation

■ schema 規律
  - 共通 column（全 audit fact 必須）：
        event_id : ULID（時刻 prefix sortable）
        emitted_at : TIMESTAMPTZ（µsec 精度）
        actor : structured（identity_class / identity_id /
                  session_id）
        capability : enum（read / write / delete / dos /
                       lateral）
        surface : enum（north_south / east_west /
                    control_plane / persistence /
                    supply_chain / build_time）
        asset : enum（pii / business_data / audit_log /
                   credential / availability）
        decision : enum（allow / deny / audit_only）
        target : structured（resource_kind / resource_id /
                   tenant_id?）
        threat_class_ref : text[]（threat_model 中の
                              threat_id への ref、複数可）
        prev_event_hash : bytes（前 event の hash chain）
        chain_root_id : ULID（hash chain の root を識別）
  - subject 別 column は fact_class 別 schema として
    Apicurio Registry に登録、12_スキーマ進化適合仕様 の
    breaking 判定 augment（PII column 含むため、PII rest
    暗号化が breaking 判定軸に追加される）。

■ immutability の三重化
  - 三重化 1：append-only DB schema
        ClickHouse table ENGINE = ReplicatedMergeTree、
        UPDATE / DELETE 系 mutation は Kyverno admission
        policy + ClickHouse settings で物理 block。
        partition は emitted_at by month、partition drop
        は archive_to_offline phase 経由のみ。
  - 三重化 2：cryptographic chaining
        各 audit event の prev_event_hash が前 event の
        hash と一致することを CI（日次 batch job）で検証。
        chain root は cosign signed snapshot として 14
        強制機構 で publish、chain divergence は incident。
  - 三重化 3：WORM Object Lock（archive 経路）
        archive_to_offline phase で Ceph RGW Object Lock
        Compliance mode に書き込み、retention 期限内の
        物理 delete を bucket policy で物理不可能化。
        Compliance mode は root 権限でも解除不可（infra
        04 と整合）。

■ retention 規律
  - hot tier（ClickHouse SSD）：90 日
  - warm tier（ClickHouse cold disk_s3）：1 年
  - archive tier（Ceph RGW Object Lock）：7 年（v1
    最低 retention）
  - 7 年経過後の処置：archive 鍵（KEK）の crypto-erase
    （tier1/11 の crypto-erase 経路）で論理消去、Object
    Lock の retention 期限と同期。物理 delete は最終
    cleanup で再現性を保つ。
  - 業務領域別 retention 延長（10 年 / 永続）は instance
    attributes で宣言、本層は最低値を物理 enforce。

■ ingest 経路の冗長化
  - 経路 A：application emit（tracing）
        OpenTelemetry SDK 経由、tier1 Library が共通化。
  - 経路 B：DB engine audit
        pgaudit（CloudNativePG）/ Kafka audit log /
        ClickHouse system.query_log / Valkey AUDIT
        （v2 候補）。
  - 経路 C：cluster audit policy
        Kubernetes audit policy（ALL request / metadata
        level + 機微 verb は RequestResponse level）、
        Falco の k8s_audit plugin で同 SoR に統合。
  - 経路 D：Kyverno admission audit
        admission decision 全件を Vector で audit_event
        subject に流す。
  - 4 経路の duplicate detection：event_id を ULID 化、
    重複は ClickHouse merge tree 側で aggregation、
    取りこぼしは coverage gap として CI alert。

■ 採用しない方針
  - audit_event の sampling：禁止。保存規律は「sampling 禁止 +
    drop 検出 (10_security/16) + audit backend file + webhook
    二重出力 + webhook 先 Vector persistent buffer (disk-backed)
    + rotated file log 再投入経路」の合算で「ingest gap > 0 で
    page、復旧経路を二系統」を物理保証する（hash chain 単独で
    100% 保存を語らない、kube-apiserver audit-only field は etcd
    snapshot から原理的に復元不能であるため etcd snapshot 経路に
    依存しない）。cost 削減は cold tier 移行のみ。
  - audit_event の logical delete（deleted_at）：禁止、
    crypto-erase 経路のみ。
  - 単一経路（application emit のみ）：禁止、4 経路冗長
    化必須。
  - audit DB の admin 直接書き込み：禁止、Vector pipeline
    経由のみ。pgaudit 経由含めて全 ingest が pipeline
    化される。
  - audit subject の column を業務都合で削減：12 schema
    の breaking 判定で block、削減 PR は admission
    block。
  - audit_event の暗号化 opt-out：PII を含む audit fact
    は envelope encryption 必須（tier2/22 / tier1/11 と
    整合）。

■ 同型構造（13 軸との整合）
  - audit_event subject 全 fact_class が threat_model.lock
    .yaml の actor / capability / surface / asset 軸に
    bind、threat_class_ref を column として持つことで
    cross-axis assertion が双方向に成立。
  - immutability の 3 三重化はそれぞれ data 14（DB
    engine 物理機構）/ 本層 14（cryptographic chain
    検証）/ infra 14（WORM Object Lock policy）に分散。
  - retention は 09_data の preservation_class（v1_audit_
    log）と双方向 lock、preservation_substrates.lock.yaml
    で物理整合。
