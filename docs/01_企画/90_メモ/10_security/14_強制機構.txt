============================================================
security 強制機構
============================================================

■ 一文方針
  - security 層の規律は Kyverno admission policy + 各層
    （tier1 / tier2 / tier3 / infra / data）の物理機構の
    cross-axis bind + cosign signed build artifact の AND-
    gate + audit chain cryptographic verification の 4 種
    で物理 enforce、手書き policy は CI fail、最終 safety
    net は cosign signature の物理的真正性と Ceph RGW
    Object Lock Compliance mode の物理不可逆性。

■ 5 層 defense-in-depth（security 規律全体）
  - 層 A：compile（threat_model / mitigation の type
    check）
        - threat_model.lock.yaml schema 検証（jsonschema /
          CUE）
        - mitigation_bindings.lock.yaml の各 pointer が
          実在 artifact を指すこと（ref resolution
          check）
        - pii_classification.lock.yaml の全 column が
          Apicurio Registry の subject に存在
        - drill_progress.lock.yaml / scenario_catalog
          .lock.yaml schema 検証
        - SBOM（SPDX + CycloneDX）syntax check（Syft）

  - 層 B：lint（policy / 規約 check）
        - Conftest custom rule（Rego）：
              - threat_model.lock.yaml の全 cell に
                mitigation pointer 存在
              - 文章 only mitigation（kind: textual）の
                数が 0（runbook も cap 5%）
              - PII column の breaking 緩和系 schema
                変更が breaking 判定 augment と整合
              - secret class taxonomy の全 entry に
                rotation cadence 宣言
              - boundary_mitigation の 6 surface × 4
                mitigation = 24 cell 全埋まり
              - threat_class coverage が drill scenario
                と双方向対応
        - Semgrep ruleset（自社 OSS rule）の build
          artifact 化 check
        - Trivy ignore list の expires_at 全 entry 検証

  - 層 C：integration test（chainsaw / kuttl /
    Testcontainers）
        - 全 admission policy が intended state を block
          / pass する test（security 担当部分）
        - cosign verify が unsigned image を block する
          こと
        - OpenBao dev mode を立ち上げ secret rotation
          cadence 違反時の admission block 試験
        - Falco ruleset の syscall 試験（test syscall
          発火 → audit_event 到達確認）
        - red_team_table_top scenario の自動 replay

  - 層 D：runtime（cluster 上の actual enforcement）
        - Kyverno admission webhook：本層担当 policy（後
          述一覧）の deploy / migration / DDL 全 block
        - ClickHouse mutation block：audit_event table
          への UPDATE / DELETE を engine 設定で物理 block
        - Falco / Tetragon detection ruleset の常駐
        - cert-manager の auto rotate cron による cadence
          維持
        - escalation_policy.lock.yaml の active escalation policy

  - 層 E：物理 enforcement（OS / engine / 暗号 / 物理
    layer の物理機構）
        - cosign signature の cryptographic verification
          （build artifact が真正であることを公開鍵で
            verify、Sigstore 標準）
        - Ceph RGW Object Lock Compliance mode：retention
          期限内の audit archive 物理 delete 不可（root
          権限でも解除不可、bucket policy が物理 lock）
        - OpenBao Transit 鍵の HSM-backed material：KEK
          は HSM 内で生成 + sign、export 不可（physical
          tamper resistance）。v1_data_kek は更に Shamir
          M-of-N で N region の独立 HSM partition + 独立
          OpenBao instance に share 分散保管され、単一
          region では KEK 物理復元の閾値（M）に達しない
          （05_tier1/11 backend hsm_pkcs11_shamir_distributed_v1
          / 05_tier1/17 と双方向 lock）。share 復元 ceremony は
          M region 健全時にのみ実行可能で、単一 region 復元
          試行は本層 admission で block + audit emit。
        - audit_event hash chain：cryptographic chain
          が divergence 時点を物理特定（暗号学的
          impossibility of forgery）
        - mTLS / TLS 1.3 の cipher suite 物理強制
          （weakcipher の TLS handshake は OS レベルで
            reject）

■ Kyverno admission policy 一覧（security 担当部分）
  - require-cosign-signed-image：本番 namespace の全
    image が cosign signed
  - require-sbom-attached：image に SBOM attach 必須
  - require-mtls-data-instance：data 層 instance への
    plaintext 接続 block
  - require-mtls-east-west：east-west 通信 mTLS 必須
  - require-network-policy-default-deny：全 namespace に
    default-deny ingress / egress NetworkPolicy
  - require-istio-sidecar：tier1 / tier2 / tier3 / data
    pod に Istio sidecar 必須
  - require-pii-class-annotation：DB schema / Kafka topic
    / ClickHouse table に pii_class 注釈
  - require-encryption-on-pii：v1_pii_xxx column の
    envelope encryption 必須
  - require-rls-on-pii-table：pii_class != none の table
    に POLICY + FORCE_RLS（tier2/32 と整合）
  - require-audit-event-on-data-access：v1_pii_special /
    finance / health column への access に audit_event
    emit 必須（DB engine pgaudit + application emit）
  - require-step-up-auth-on-special-pii：special PII
    column 変更 path に step-up auth 注釈
  - block-on-rotation-overdue：secret class 別 rotation
    cadence 違反時に block
  - block-on-cve-overdue：severity 別 patch SLO 違反時
    deploy block
  - block-on-drill-overdue：drill_progress.lock.yaml
    cadence 違反時 deploy block
  - block-on-postmortem-pending：active incident の
    postmortem PR が merged でない場合 block
  - block-on-audit-chain-break：audit_event hash chain
    divergence 時 deploy block
  - block-unsigned-commit-merge：merged commit が GPG /
    sigstore signed でない場合 block（v2 で全強制、v1
    は本番 branch のみ）
  - block-non-cosign-image-push：Harbor への non-signed
    push を block
  - block-secret-in-config-map：Kubernetes ConfigMap に
    secret-like value 含む場合 block
  - block-plaintext-pii-in-log：Vector pipeline で PII
    pattern 検出時 block + redact
  - audit-control-plane-access：control-plane API（Argo
    CD / etcd / Kyverno / OpenBao）への access を全件
    audit_event emit
  - require-falco-sidecar：本番 cluster 全 node に
    Falco daemonset、auto-recover 必須
  - require-tetragon-daemonset：同上、Tetragon
  - block-on-trivy-grype-mismatch：Trivy / Grype scan
    結果の critical CVE が不一致時 block
  - block-single-region-kek-reconstruction：v1_data_kek
    の Shamir share を単一 region の OpenBao instance のみ
    から取得して復元を試みる経路を block + audit_event
    emit。閾値 M 未満の region 集合からの復元 API 呼出も
    同様（05_tier1/11、05_tier1/17 と双方向 lock）。
  - block-direct-apicurio-write：Apicurio Registry の
    `/apis/registry/v3/groups/*/artifacts/*` および
    `/apis/registry/v3/admin/rules` 等の write API
    （PUT/POST/DELETE）を Apicurio Operator service account
    以外から呼ぶ経路を block + audit_event emit。Registry
    state は git SoT で Argo CD + Apicurio Operator が
    declarative reconcile する経路のみを唯一の真とする
    （05_tier1/12 registries.lock.yaml の governance 節 /
    05_tier1/18_apicurio_gitops_sot と双方向 lock）。
    Karapace への demote 経路でも同 governance を維持する
    ため admission policy 名は registry 種別 non-bound。

■ admission policy のライフサイクル
  - 全 admission policy は build artifact（security/
    policy/kyverno-security-policies.yaml）から生成、
    手書き禁止。
  - generator の input：
        - threat_model.lock.yaml（脅威 ↔ mitigation）
        - mitigation_bindings.lock.yaml（mitigation
          pointer ⇔ 各軸 spec）
        - pii_classification.lock.yaml（PII class）
        - rotation_progress.lock.yaml（tier1/11、secret
          rotation 状況）
        - drill_progress.lock.yaml（本層、drill cadence）
        - error_budget.lock.yaml（13 SLO）
        - oss_inventory.lock.yaml（14 OSS lifecycle、
          CVE 状況）
        - postmortem_progress.lock.yaml（本層、active
          postmortem の merged 状況）
  - drift：runtime 上の admission policy が build artifact
    と乖離した場合、Argo CD が drift として検出 + self-
    heal。

■ break-glass
  - 緊急時に admission policy を bypass する経路：
        1. OpenBao response wrapping で短期 cluster-admin
          相当 token + DB superuser token を発行
        2. 発行操作は audit_event subject に v1_break_
          glass fact emit（必須 column：actor / reason /
          ticket_ref / expected_duration）
        3. 使用後 1 時間以内に postmortem PR 起票必須
        4. break-glass 使用は 13 SLO error budget
          consumption として記録
        5. break-glass 経由の policy bypass も migration /
          DDL / config 変更を後追いで artifact 化
          （再現性確保）
        6. break-glass session 中も audit_event の hash
          chain は継続、chain divergence 不可

■ CI 不変条件（security 全体）
  - 違反は merge 不可。
        整合 1 ：threat_model.lock.yaml の全 cell が
                mitigation pointer 持つ（coverage_full）
        整合 2 ：mitigation pointer が全て実在 artifact
                を指す（physical_pointer_resolution）
        整合 3 ：boundary_mitigation の 24 cell 全埋まり
        整合 4 ：pii_classification.lock.yaml の全 column
                が Apicurio subject に存在 + DEK class
                bind
        整合 5 ：全 PII 分類列に envelope encryption +
                blind index（必要時）+ rest 暗号化解除
                breaking 判定（cross 12 schema）
        整合 6 ：secret class taxonomy 全 entry に
                rotation cadence、rotation_progress.lock
                .yaml 全件が cadence 内
        整合 7 ：drill_progress.lock.yaml 全 cadence
                内、red 状態ゼロ
        整合 8 ：scenario_catalog.lock.yaml が threat_
                model.lock.yaml の全 threat_class を
                cover
        整合 9 ：admission policy 全件が build artifact
                から生成、手書き policy ゼロ
        整合 10：cosign signed image / SBOM attached の
                cluster-wide enforcement（runtime
                drift = 0）
        整合 11：audit_event の hash chain 日次 verify
                green、divergence 履歴ゼロ
        整合 12：Trivy / Grype double-bound scan 結果が
                critical で一致
        整合 13：13 軸 + meta（00）+ security 軸の各
                spec の build artifact と本層の threat_
                model.lock.yaml / mitigation_bindings
                .lock.yaml が双方向 lock

■ 採用しない強制機構
  - OPA Gatekeeper 単独運用：採用しない、Kyverno L1+
    深耕（infra 14 / data 14 と同じ）。
  - 商用 admission engine（Styra DAS）：採用しない。
  - 文章 only の運用ルール：禁止、全規律は機械検証可能
    な形で codify。
  - 「便利だから break-glass を常用」：禁止、break-glass
    は incident IR + audit_event + postmortem PR 必須の
    例外経路のみ。
  - 「business 都合で envelope encryption を一時 off」：
    禁止、PII 分類列の平文化は admission block で物理
    block（tier2/22 / tier1/11 と整合）。
  - audit_event の sampling：禁止、100% 保存（archive
    tier 移行のみ retention 戦略）。
  - cosign signing key を CI runner に長期保持：禁止、
    OpenBao Transit + sign-on-demand のみ、key material
    は CI runner に物理に存在しない。
