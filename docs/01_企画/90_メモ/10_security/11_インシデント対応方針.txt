============================================================
security インシデント対応方針
============================================================

■ 一文方針
  - インシデント対応（IR）は class taxonomy 別に playbook
    を build artifact 化し、検知 → triage → contain →
    eradicate → recover → postmortem の 6 phase を必ず
    全 incident で踏破、postmortem PR の merge 完了が次の
    本番 release の物理 prerequisite として 1.0.0 ship blocker
    と connect する。

■ incident class taxonomy
  - v1_secret_exposure：secret の git / image / log への
    漏洩、API key / DB password / signing key compromise
  - v1_data_exfiltration：PII / business_data の不正 export
                          疑義
  - v1_data_tampering：DB / topic / audit 改竄、replication
                       divergence
  - v1_availability_loss：SLO 違反級の outage（13 SLO の
                          v1_availability budget exhaust）
  - v1_supply_chain_compromise：CI runner / image / dep の
                                 compromise 疑義（cosign
                                 verify fail / SBOM 不整合）
  - v1_privilege_escalation：cluster-admin / DB superuser
                              / RLS bypass の不正取得疑義
  - v1_audit_chain_break：audit_event の hash chain
                            divergence

■ 6 phase の playbook（class 共通骨格）
  - phase 1：検知（detection）
        signal source：09 観測 SoR の audit_event /
                       Falco / Tetragon / Trivy / cosign
                       verify / replication lag SLI /
                       admission policy decision
        detection rule：build artifact（detection_rules.lock
                        .yaml）から生成、ClickHouse query
                        として常駐
        page：on-call（Grafana OnCall）に SLO severity に
              応じて escalation
  - phase 2：triage
        IR commander 任命（class 別 escalation policy で
        自動）
        scope assessment：影響 tenant / asset / 期間の
                          初期推定（ClickHouse audit
                          query で機械化）
        severity 確定：likelihood × impact の即時評価、
                       SLO budget consumption 計上
  - phase 3：contain
        class 別の即時封じ込め（後述 class 別欄）
        contain action は audit_event の ir fact + 即時
        admission block / network policy / OpenBao revoke
  - phase 4：eradicate
        root cause 分析、患部の物理除去（compromised
        secret rotation / image 撤去 / replication
        divergence の物理 reset 等）
        eradicate action も audit_event 必須
  - phase 5：recover
        正常状態への復元、healthcheck pass、SLO 復帰
        確認、affected tenant への通知（v2 で自動化、v1
        は手動 + checklist）
  - phase 6：postmortem
        Markdown PR で blameless postmortem 起票、必須
        section（timeline / root cause / contributing
        factors / mitigation / lessons learned / action
        items）
        action item は GitHub Issue 化 + due date 必須
        postmortem PR merge 完了が次 release の物理
        prerequisite（release_gate.lock.yaml の AND-gate
        に postmortem_pending = 0 が入力）

■ class 別 contain action
  - v1_secret_exposure：
        - OpenBao 該当 secret class 全 lease 即時 revoke
        - rotate 後の新 secret を External Secrets で再配信
        - 漏洩経路の cleanup PR 起票（git history 改竄
          不能、purge は新 commit + 全 secret rotation で
          論理消去）
  - v1_data_exfiltration：
        - 該当 tenant への外向き egress を NetworkPolicy
          で即時 block（除：認証 / 監査 SoR）
        - 該当 actor identity の token revoke、SSH key
          revoke
        - audit_event を ClickHouse query で範囲特定、
          該当 fact を hot 保持期間延長
  - v1_data_tampering：
        - 該当 instance を read-only 化（CloudNativePG
          で primary 切離 → standby だけ access）
        - data 14 強制機構 の hash check / replication
          consistency check を即時実行
        - audit_event の hash chain 検証で改竄 boundary
          特定
  - v1_availability_loss：
        - 13 SLO の error_budget freeze（feature merge
          stop、infra rollback or scale）
        - infra 14 の failover_drill green である topology
          へ自動 failover（Argo Rollouts + Argo CD）
  - v1_supply_chain_compromise：
        - cosign signing key の即時 rotate（OpenBao
          Transit、key version bump）
        - 該当 image を Harbor で quarantine、admission
          policy で deploy 完全 block
        - 該当 build runner pod の destroy + 新 ephemeral
          pod 再作成（Tekton / GitHub Actions self-hosted）
        - SBOM 再 scan（Trivy + Grype double-bound）
  - v1_privilege_escalation：
        - 該当 identity の token / SSH / DB password 即時
          revoke
        - cluster RBAC の mirror snapshot を Argo CD で
          force sync、drift 検出
        - break-glass log を audit query で検査、不正
          break-glass の有無確認
  - v1_audit_chain_break：
        - chain divergence point の特定（hash mismatch
          event_id）
        - WORM Object Lock の archive snapshot から
          chain root を再 verify
        - chain 再構築（divergence 区間を separate chain
          として管理、root を cosign signed snapshot で
          再 publish）
        - 全 ingest 経路（4 経路）に取りこぼし疑義
          marking、coverage gap として CI alert

■ on-call rotation / escalation
  - L1 on-call：ops / SRE 24/7 rotation（v1 は単一 rotation、
    v2 で follow-the-sun）。
  - L2 escalation：security IR commander（class 別固定）、
    SLO severity に応じて自動 page。
  - L3 escalation：tech lead / executive、L2 で contain
    不能 / regulatory 通知必要時。
  - escalation policy は build artifact（escalation_policy
    .lock.yaml）、Grafana OnCall に同期。

■ red-team / drill cadence
  - 四半期 internal red-team 演習：incident class 別
    table-top + 実機 chaos drill（Litmus 経由、infra 11
    Chaos 工学方針 と整合）。
  - 年次外部 PenTest：外部 security firm による black-
    box / gray-box test、結果は vulns/ catalog 化。
  - drill 記録：ir_drill.lock.yaml に green / red、last_
    green_at 記録、cadence 違反は admission block（13 と
    integrate）。

■ 採用しない方針
  - blameful postmortem：禁止、必ず blameless。
  - postmortem 省略：禁止、全 incident で必須、merge は
    次 release の物理 prerequisite。
  - 文章 only の playbook：禁止、playbook は build
    artifact + 各 step に物理 action（API call / kubectl
    / OpenBao revoke 等）の pointer 必須。
  - IR commander の指名なき incident：禁止、検知時に
    自動 assign（class 別 escalation policy）。
  - regulatory 通知の judgment delay：v1_pii_special /
    v1_pii_finance / v1_pii_health の exfiltration 疑義
    は即時 L3 escalation + 法務 / DPO 連携（v2 で
    automation）。

■ 同型構造（13 軸との整合）
  - incident class（7 class）は threat_model.lock.yaml の
    threat_id と双方向 lock（threat_id → incident_class
    mapping を持つ）。
  - postmortem PR が release_gate.lock.yaml の AND-gate
    入力として 1.0.0 ship blocker。
  - drill cadence は infra 11 Chaos 工学方針 + data 11
    復旧訓練方針 と pair、ir_drill.lock.yaml が共通
    artifact、13 SLO の error_budget と connect。
