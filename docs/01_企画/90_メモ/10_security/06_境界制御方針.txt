============================================================
security 境界制御方針
============================================================

■ 一文方針
  - trust boundary は 6 surface（north-south / east-west /
    control-plane / persistence / supply-chain / build-time）
    で完全列挙、各 surface の crossing は authn + authz +
    transport 暗号化 + audit emit の 4 mitigation を必ず
    重ねた上で物理通過、いずれかが欠落する経路は admission
    block / network policy block / cosign verify fail で
    物理拒否する。

■ 6 surface の trust boundary 定義
  - v1_north_south：
        scope：tier1 Server 系 ingress（公開 RPC / HTTP）
        対向：v1_external_unauth / v1_external_auth
        4 mitigation：
            authn：tier1/10 認証適合仕様（OIDC / JWT）
            authz：tier1/10 + tier2/32 RLS POLICY
            transport：TLS 1.3（cert-manager 管掌、infra
                       配信、PFS only）
            audit：09 観測 SoR の auth_attempt subject
        物理層：Envoy Gateway / Istio gateway（infra
                提供）+ Envoy ext_authz filter
  - v1_east_west：
        scope：cluster 内 service ↔ service（gRPC /
               messaging）
        対向：v1_insider_application
        4 mitigation：
            authn：mTLS（Istio mutual TLS、cert-manager
                    が SPIFFE 形式 cert を配信）
            authz：Authorization Policy（Istio）+
                   namespace boundary
            transport：mTLS、plaintext fallback 経路ゼロ
            audit：Falco / Tetragon の east-west 通信
                   subject + Istio access log
        物理層：Istio sidecar / NetworkPolicy（infra
                14 で require-istio-sidecar 強制）
  - v1_control_plane：
        scope：Argo CD / etcd / Kyverno / External
               Secrets / OpenBao / Harbor / Tekton API
        対向：v1_insider_operator
        4 mitigation：
            authn：OIDC + WebAuthn 必須（infra 13 と
                   整合）
            authz：Kubernetes RBAC + namespace + Argo CD
                   project boundary
            transport：cluster 内 mTLS + 外部 TLS 1.3
            audit：k8s audit policy（ALL request /
                   metadata level + 機微 verb は
                   RequestResponse level）
        物理層：admission policy + audit webhook、
                cluster-admin 権限は break-glass のみで
                短期発行
  - v1_persistence：
        scope：CloudNativePG / Kafka / ClickHouse / Valkey
               / Apicurio Registry / Ceph RGW 物理 store
        対向：v1_insider_operator / v1_supply_chain
        4 mitigation：
            authn：DB superuser は OpenBao response
                   wrapping のみで短期発行、SCRAM /
                   mTLS で daemon 認証
            authz：tier2/32 RLS FORCE / tier1/11 鍵階層
                   / preservation_class 別 access policy
            transport：CloudNativePG mTLS / Kafka SASL_
                       SSL / ClickHouse mTLS、plaintext
                       禁止
            audit：DB engine audit（pgaudit）+ CDC
                   subject（audit_event）
        物理層：Kyverno admission（require-mtls-data-
                instance）+ DB engine 物理機構
  - v1_supply_chain：
        scope：source repo / CI runner / Harbor / SBOM
               / image / artifact
        対向：v1_supply_chain
        4 mitigation：
            authn：CI runner identity = OIDC short-lived
                   token（GitHub Actions OIDC → OpenBao
                   exchange）
            authz：repo / branch protection / required
                   reviewers / signed commits
            transport：HTTPS、SSH（公開鍵 only）
            audit：cosign signature 検証 log + Tekton
                   Chains attestation
        物理層：cosign verify（Kyverno）+ branch
                protection + GPG signed commits（v2）
  - v1_build_time：
        scope：build runner 内の動作（compile / test /
               package / sign）
        対向：v1_supply_chain
        4 mitigation：
            authn：build runner identity（GitHub OIDC）
            authz：build job が触れる secret は OpenBao
                   short-lived token のみ、long-lived
                   secret 不可
            transport：build artifact upload は cosign
                       sign 後 Harbor 経由のみ
            audit：in-toto / witness attestation +
                   Tekton Chains
        物理層：build runner = ephemeral pod（Tekton /
                GitHub Actions self-hosted ephemeral）、
                state 残存ゼロ

■ zero-trust 原則
  - 全 surface で「default deny」+ 「explicit allow」のみ。
    NetworkPolicy は default-deny ingress + default-deny
    egress を全 namespace で物理 enforce（infra 06 と整合）。
  - 全 service ↔ service 通信は mTLS 必須、plaintext
    fallback 経路ゼロ（v1_north_south の TLS termination
    点を含めて全経路 encrypted）。
  - 認証 token は short-lived（≤ 1 時間）、long-lived は
    OpenBao の管理下のみ（rotation 経路を持つ）。
  - east-west の認可は SPIFFE ID + service-account の
    joint で評価、IP based 認可は禁止。

■ 4 mitigation の必須化と検証
  - threat_model.lock.yaml の各 cell で、surface =
    crossing する場合は 4 mitigation 全てを mitigation
    pointer として持つことを CI で物理確認。
  - mitigation_bindings.lock.yaml に boundary_mitigation
    section を持ち、各 surface × 4 mitigation = 24 cell
    が全て physical pointer を持つことを CI が verify。
  - 文章 only mitigation は boundary section では限定
    禁止（cap 0%、runbook も不可）。

■ 採用しない方針
  - 「内部 network だから plaintext 許容」：禁止、全経路
    mTLS / TLS。
  - IP allowlist のみで認可：禁止、必ず identity 認証 +
    認可 policy が前段にある。
  - long-lived service account token：禁止、必ず short-
    lived（OIDC token / OpenBao lease）。
  - cluster-admin 常設運用：禁止、break-glass + 短期発行
    のみ。
  - 「特定 namespace のみ NetworkPolicy 適用」：全
    namespace に default-deny を物理 enforce。

■ 同型構造（13 軸との整合）
  - 6 surface × 5 actor × 4 mitigation の cross-cut が
    threat_model.lock.yaml に展開される。
  - boundary_mitigation の物理 enforcement は infra 14
    （Kyverno / Istio / NetworkPolicy）と data 14（DB
    engine 物理機構）に降りる。
  - audit emit は 09 観測 SoR の subject として共用、
    immutability 規律は本層 09_監査方針 / 14_強制機構 で
    宣言。
