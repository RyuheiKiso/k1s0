# 業界9業務カバレッジマトリクス

## 影響度の定義

| 記号 | 意味 |
|---|---|
| ◎ | 全業務共通基盤 — その軸の機能が業務の根幹を直接支える |
| ○ | 影響度高 — 業務の安定性・信頼性に大きく寄与する |
| △ | 影響度低 — 間接的に影響するが主要パスではない |
| — | 影響なし — その軸の変更は業務に実質的な影響を及ぼさない |

## 軸別カバレッジ解説

### tier1 (OSS / proto / supply chain)
SCADAテレメトリと計量装置連続データに◎: これらはデータ転送プロトコルに直接依存し、proto スキーマ変更・OSS ライフサイクルの影響が最大となる。FA生産指示・品質検査・在庫・受注は○: proto の安定性に間接依存する。図面collaborative review は△: ドキュメント系であり proto 依存が薄い。

### tier2 (ドメイン / テナント / 業界pack)
FA生産指示・在庫最新値・受注sub に◎: 業界固有の business logic が最も濃密に現れる領域であり、テナント分離・業界pack が根幹を担う。品質検査・図面review に◎: 業界横断的な品質規格 (ISO 9001, GMP, HACCP) を業界pack で抽象化する。

### tier3 (UI / UX / Companion)
FA生産指示・ライン稼働監視・品質検査・図面review・警報配信に◎: 現場オペレータが直接操作する UI レイヤであり、オフライン対応・WebAuthn step_up・リアルタイム更新 UX が業務継続性を左右する。

### infra (cluster / Kyverno / drill)
ライン稼働監視・SCADAテレメトリ・警報配信・計量装置連続データに◎: 常時稼働が要求されるストリーム系業務は infra の可用性・failover 訓練の品質に直結する。

### data (PostgreSQL / Kafka / PII)
品質検査結果配信・SCADAテレメトリ・在庫最新値・受注sub・計量装置に◎: 大量データの信頼性・整合性・RLS によるテナント分離が業務の核となる。

### security (threat model / cosign / KEK)
品質検査・SCADAテレメトリ・受注sub・警報配信に◎: 改竄・なりすまし・不正指示の影響が安全上の問題に直結する業務であるため threat model の優先度が高い。

### ops (SRE / on-call / incident)
ライン稼働監視・SCADAテレメトリ・警報配信・計量装置連続データに◎: 24/365 の可用性要件を持つ業務は ops の on-call 品質・SLO 管理と不可分。

### 業務担当者 (現場オペレータ)
全 9 業務に○以上: 現場オペレータは全業務の最終実行者であり、シナリオカバレッジが最も広い。特にFA生産指示・ライン稼働監視・品質検査・警報配信・計量装置は◎。

### 業務管理者
FA生産指示・図面review・在庫・受注・警報配信・計量装置に◎: 意思決定・承認・escalation の最終権限者として関与する。

### 外部監査人
品質検査結果配信に◎: ISO/GMP/HACCP 監査の主対象。SCADAテレメトリ・受注subにも○。

### 法務DPO
受注sub・品質検査に◎: PII (顧客情報・受注情報) が含まれる業務の GDPR/PIPA 対応の主担当。図面review・SCADAには△。
