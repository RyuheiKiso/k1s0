# a11y / i18n 修正

## 一文方針

CI の axe-core 自動検査 fail または i18n 翻訳キー未定義を起点に、個別 override ではなくデザインシステム側の color token / component 仕様を修正し、axe-core CI green と Web Vitals 閾値を両立させる。

> 午後 1 時半、自宅リモートの tier3 担当者（ジュニア級）が Playwright CI の axe-core 結果画面で「aria-label 欠落 × 3 / color contrast 違反 × 1」の fail を発見し修正作業を開始する。手元には axe-core のエラーレポートと Storybook のデザインシステムコンポーネント、Mattermost 越しにデザインシステム担当者と dual reviewer がいる。

## ペルソナ要約

主役: tier3 担当者（ジュニア級）、目的: 既存コンポーネントの a11y / i18n 違反を axe-core CI が green になるまで修正する

## 現状業務での痛み

- a11y / i18n を後付けで対応するため全コンポーネントを改修する必要が生じ、工数が予測不能になる
- axe-core 違反の影響範囲が把握できず、修正後にどこまで direct/影響波及するかが不明確
- i18n 文字列が各ファイルに散在しており、言語追加のたびに全ファイルを検索する必要がある

## k1s0 でこう変わる

- Backstage Template から生成されたコンポーネントは a11y・i18n が初期状態で満たされており後付け改修が不要になる
- axe-core CI が違反箇所を行レベルで特定し、修正対象が明確になる
- i18n 文字列が centralized store に集約され、言語追加が 1 箇所の追記で完結する

## Trigger（発火条件）

CI の axe-core 自動検査が fail した、または国際化（i18n）の翻訳キー未定義が検出された時。

## 想定頻度 / 典型きっかけ

想定頻度: イベント駆動（CI fail 時）。典型きっかけ: 「axe-core が aria-label 欠落 x 3 / color contrast 違反 x 1 を検出し merge が阻止された」

## 主役 / 関与者

- **主役**: tier3 担当者（ジュニア級）
- **関与**: デザインシステム担当者（color token / component 変更）/ dual reviewer

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|---|---|---|---|---|
| 主役（tier3）| ジュニア | 本社 IT 室 / リモート | Playwright CI / Jest CI | axe-core 違反特定 / aria-label 修正 / color token 修正 / pseudolocalization テスト |
| 関与（デザインシステム担当）| 中堅 | 本社 IT 室 | Backstage TechDocs | color token / component 仕様変更 / a11y 修正方針確認 / sign-off |
| 承認（dual reviewer）| 中堅〜シニア | 本社 IT 室 / リモート | GitHub PR | WCAG 2.1 AA 違反 0 件 / Web Vitals 閾値 / pseudolocalization 崩れなし / sign-off |

## 個人 KPI / 達成感

- axe-core WCAG 2.1 AA 違反 0 件を CI で確認でき、a11y 完了の達成感を定量的に得られる
- 修正コンポーネント数と残存違反数を PR 差分で可視化できる

## 工数 / 関与人数 / コスト感

- 工数: 0.5〜2 日（違反リスト抽出 1h + 修正 4〜12h + CI green 確認 1h）違反件数に依存
- 関与人数: 2〜3 名（tier3・デザインシステム担当者・dual reviewer）
- コスト感: 中〜高（後付け対応の場合）。Template からの新規作成なら低コスト

## 前提

- axe-core が CI に組込済み（WCAG 2.1 AA 基準）
- デザインシステムの color token と component 仕様が一元管理されている
- i18n locale file が共有リポジトリで管理されている
- （責務境界: [README 重要原則](./README.md#重要原則-tier3-が所有するもの--所有しないもの) を参照）

## 流れ

1. axe-core fail: 違反 rule（aria-label 欠落 / color contrast / keyboard navigation）を特定
2. 修正方針を決定（role / aria-label / tabIndex / focus management / color token 変更）
3. デザインシステムの color token / component 仕様に反映（個別 override ではなくシステム変更）
4. pseudolocalization テスト: i18n key の文字列を長い疑似言語に置換して layout が崩れないか確認
5. 翻訳キー未定義: locale file に key を追加（英語 fallback 必須 / 機械翻訳を使わず担当者が意味を確認）
6. axe-core CI が green になるまで修正を繰り返す（Web Vitals 閾値も再確認）
7. dual reviewer sign-off

## 業界 9 業務との紐付け

- **FA 生産指示・設備操作**: 生産指示画面の操作ミスを防ぐために a11y（screen reader / keyboard navigation）が適切に動作することが安全性に直結する
- **受注**: 受注入力フォームの i18n 対応により、多拠点・多言語の業務担当者が同一 UI を正確に操作できる基盤を整備する
- **ライン稼働監視・進捗実績**: 監視画面の color contrast 確保により、工場の騒音・照明環境下でも視認性を維持する

## 期待結果 / 観測指標

- axe-core: WCAG 2.1 AA 違反 0 件
- pseudolocalization: 全画面で layout 崩れ 0 件
- 翻訳キー: 英語 fallback 必須 / 未定義キー 0 件
- Web Vitals: LCP ≤ 2.5s / INP ≤ 200ms / CLS ≤ 0.1
- dual reviewer 2 名 sign-off 完了

## 失敗時の挙動 / escalation

- WCAG 2.1 AA 違反のまま merge → CI merge 阻止。**escalate 先**: デザインシステム担当者に Mattermost `#a11y-fail` で連絡（**SLA**: 24h 以内）。**runbook**: Backstage runbook `a11y-wcag-violation` を参照
- Web Vitals 閾値違反 → merge 阻止、ボトルネック特定。**escalate 先**: tier2 担当者に Mattermost `#perf-review` で相談（**SLA**: 48h 以内）
- color token の個別 override → lint 検出 → merge 阻止。**escalate 先**: デザインシステム担当者に Mattermost `#a11y-fail` で修正依頼（**SLA**: 24h 以内）
- 機械翻訳のまま merge → レビューで差し戻し。**escalate 先**: i18n 担当者に Mattermost `#i18n-review` で翻訳依頼（**SLA**: 48h 以内）

## 失敗パターン (anti-pattern)

- 違反を eslint-disable で抑制: CI が disable コメントを検知し merge 阻止される
- i18n を後回しにする: ハードコード文字列は i18n CI が検知するため初期実装から集約する
