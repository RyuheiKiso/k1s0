# 業界規制_自主点検

## 一文方針

ISO 9001 / GMP / HACCP / ISO 14001 の自主点検として、audit から証跡を抽出し、内部監査会議資料を作成する。外部監査人への提出前準備も兼ねる。

> 四半期末、業務管理者は来月の ISO 9001 内部監査に向けた自主点検を開始する。Backstage の audit hash chain 検索 UI で対象期間の品質管理プロセス証跡を抽出し、チェックリスト形式の内部監査資料を作成する。GMP 対応のプロセス記録と HACCP ハザード管理記録も合わせて抽出し、外部監査人が独立検証できる形式で資料を整理する。

## ペルソナ要約

主役: 業務管理者（シニア級）、目的: 定期内部監査 / 外部監査準備のために業界規制に対応した証跡を抽出・整理し、監査対応工数を最小化する

## 現状業務での痛み

- ISO 9001 / GMP / HACCP の監査証跡が複数システムに分散しており、統合資料の作成に数日を要する
- 証跡の改竄不在を証明する手段がなく、外部監査人から「この記録は事後修正されていないか」という指摘を受けることがある
- 規制の改定に合わせてチェックリストを都度更新しなければならず、最新要件との乖離に気づきにくい
- 外部監査人が独立して検証できる形式（hash 付き / タイムスタンプ付き）での証跡提出が求められても対応できない

## k1s0 でこう変わる

- audit hash chain により証跡が改竄不可能な形式で保存されており、外部監査人が独立検証できる
- 業界規制別（ISO 9001 / GMP / HACCP / ISO 14001）のチェックリストテンプレートが Backstage に組み込まれており、項目ごとに証跡を自動マッピングする
- RFC 3161 タイムスタンプが全証跡に付与されているため、事後修正不在の証明が即座にできる
- 外部監査人向けの証跡パッケージが Backstage から直接生成でき、準備工数が数日から数時間に削減される

## Trigger

定期内部監査 / 外部監査準備 / 規制更新への対応時（四半期末の内部監査スケジュールまたは外部監査通知受信をトリガーとする）

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 四半期〜年次
- 典型きっかけ: 「四半期末の ISO 9001 内部監査の自主点検」「GMP 認証の年次外部審査準備」「HACCP 計画の定期見直しサイクル到来」
- 頻度根拠: 製造業では四半期に 1 回以上の内部監査と年次の外部監査が慣行として存在する

## 個人 KPI / 達成感

- 内部監査開始 2 週間前までの自主点検完了率
- チェックリスト全項目の証跡マッピング完了率（目標: 対象期間の全項目 100%）
- 外部監査人からの「証跡不足」指摘件数 / 年（目標: ゼロ）
- 外部監査の初日に証跡パッケージを提出できた件数 / 年

## 工数 / 関与人数 / コスト感

- 四半期内部監査の自主点検: 半日〜1 日
- 年次外部監査の準備: 1〜2 営業日（外部監査人との事前調整含む）
- 失敗時（証跡欠損 / hash 検証失敗）: +半日〜1 日（data 担当者 + security 担当者と協働調査）
- 関与人数: 3〜5 名（業務管理者 + 内部監査担当者 + 品質保証担当者 + 必要に応じて外部監査人）

## 前提

- audit hash chain 検索 UI で対象期間の証跡が正常に参照できる
- audit_ingest_gap_monitor でログ欠損がないことが確認されている
- Backstage に業界規制別チェックリストテンプレートが設定されている
- 対象規制（ISO 9001 / GMP / HACCP / ISO 14001）の対象期間が明確になっている

## 流れ

1. 内部監査スケジュール（対象規制 / 対象期間）を確認し、Backstage の規制自主点検画面を開く
2. 対象規制（例: ISO 9001）のチェックリストテンプレートを選択し、対象期間を指定する
3. 「証跡自動マッピング」を実行し、チェックリスト各項目に対応する audit レコードを自動抽出する
4. 自動マッピングが不完全な項目（証跡が見つからない項目）を確認し、手動で検索・補完する
5. 全チェックリスト項目の証跡マッピングが完了したことを確認する
6. 外部監査人向け証跡パッケージ（チェックリスト + 証跡 CSV + hash 整合性証明書）を export する
7. export パッケージの hash 整合性が「pass」であることを確認する
8. 内部監査担当者に自主点検資料を提出する
9. 外部監査準備が必要な場合は、証跡パッケージを外部監査人向けに整理する

## Backstage プラグイン操作 UI

- **規制自主点検画面**: 業界規制別チェックリストテンプレートの選択と証跡抽出期間の指定
- **証跡自動マッピング**: チェックリスト各項目に対応する audit レコードを自動的に抽出・紐付けする機能
- **未マッピング項目補完**: 自動マッピングが不完全な項目に対して手動で audit ログを検索・紐付けする
- **証跡パッケージ export**: チェックリスト + 証跡 CSV + hash 整合性証明書（RFC 3161 タイムスタンプ付き）を zip 形式で出力

## 業務管理者の決定権限境界

- **実施可（単独で完結）**: 証跡抽出・チェックリスト記入・証跡パッケージ export・内部監査担当者への提出
- **escalation 必要（data 担当者 + security 担当者）**: hash 検証 fail 時の調査 / 証跡欠損の原因調査
- **escalation 必要（外部監査人）**: 証跡の法的証拠効力に関する判断（外部監査人が独立して判断する）

## 期待結果 / 観測指標 / 受入条件

- チェックリスト全項目の証跡マッピングが完了している（未マッピング項目ゼロ）
- export 証跡パッケージの hash 整合性が「pass」を示している
- 証跡パッケージに RFC 3161 タイムスタンプが付与されている
- 内部監査開始 2 週間前までに自主点検が完了している
- 受入条件: 上記 4 点が E2E テストで全て pass

## 失敗時の挙動 / escalation

- **証跡自動マッピングで大量の未マッピング項目が発生**: 対象期間の audit 記録の欠損または業界規制チェックリストテンプレートの設定ミスが原因。escalation 先: data 担当者（SLA: 1 営業日以内に原因確認）
- **hash 検証 fail**: security 担当者 + data 担当者に escalation。外部監査への提出を保留する（SLA: 2 営業日以内に調査完了）
- **外部監査直前の証跡欠損発覚**: 業務管理者は即座に外部監査人に状況を説明し、補足証跡の提出可否を確認する。escalation 先: data 担当者 + security 担当者（SLA: 外部監査開始 48 時間前までに解消）

## 失敗パターン（3 例）

1. **自主点検を外部監査の直前（1 週間前）に開始する**: 証跡欠損や hash 検証 fail が発覚した場合に修正時間がない。内部監査の 4 週間前、外部監査の 6 週間前に自主点検を開始する cadence を SOP に明記する
2. **証跡パッケージの hash 整合性を確認せずに外部監査人へ提出する**: 外部審査の場で改竄不在の証明ができず、信頼性に疑義が生じる。export 後の hash サマリ「pass」確認を内部審査の前提条件とする
3. **規制チェックリストテンプレートを最新規制に更新せずに使い続ける**: 旧基準のチェックリストで自主点検を完了してしまい、最新規制への対応漏れが外部監査で指摘される。規制改定通知を受信したら 1 営業日以内にテンプレート更新を tier2 担当者へ依頼する SOP とする
