# 設備リモート操作_v1_interactive

## 一文方針

設備リモート操作 (v1_interactive、bidi 双方向) で現場端末から設備への制御 op を送信し、応答 toast と設備状態 live tile を確認する。emergency stop 条件についても操作経路を確認する。

> 午後 1 時 30 分、ライン担当者が事務所の Windows tablet から搬送コンベアの速度を調整しようとしている。SPA のリモート操作パネルを開き、速度スライダーを「中速」にセットして「送信」をタップする。1 秒以内に設備側から「速度変更を受け付けました: 中速 (2.5 m/s)」の応答が返り、live tile の速度表示がリアルタイムで更新される。突然、温度センサーが異常値を示し、担当者は迷わず画面の赤い「非常停止」ボタンをタップする。

## ペルソナ要約

主役: 業務担当者 (ライン設備担当スタッフ級)、目的: 現場端末から設備をリモート操作し、設備状態をリアルタイムで確認しながら安全に制御する

## 現状業務での痛み

- 設備の操作盤まで毎回移動する必要があり、移動コストと設備から離れる時間が発生する
- 設備状態の変化をリアルタイムで確認する手段がなく、変更が反映されたかどうかを現地で目視確認するしかない
- 緊急停止が必要な場面で操作盤への移動に数十秒かかり、被害拡大のリスクがある
- 複数設備の状態を同時に把握する一覧画面がなく、担当者が各設備を個別に巡回する必要がある

## k1s0 でこう変わる

- SPA のリモート操作パネルで端末から直接設備を操作でき、操作盤への移動が不要になる
- bidi 双方向通信で設備の応答が 1 秒以内に端末に返り、設備状態変化をリアルタイムで確認できる
- 非常停止ボタンが SPA 画面上の最優先 UI として常時表示され、即座にタップできる
- 複数設備の live tile を 1 画面で一覧でき、設備巡回の頻度を削減できる

## Trigger

設備の遠隔操作指示が必要になった時 (速度調整 / パラメータ変更 / 緊急停止 / 起動・停止操作)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 日次 (設備担当者の勤務中に複数回)
- 典型きっかけ: 生産指示変更に伴う設備パラメータ調整 / 異常検出時の緊急停止 / 保全作業前の設備停止
- 頻度根拠: 製造ラインの設備操作は生産計画変更・品種切替・保全等で日常的に発生する

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| 設備担当者 (主役) | 現場スタッフ / 設備担当 | 事務所 / フロア | SPA 設備リモート操作パネル | パラメータ送信・応答確認・緊急停止 |
| ライン管理者 | 現場リーダー | 事務所 / フロア | 管理ダッシュボード | 設備状態監視・操作承認 (高権限操作時) |

## 個人 KPI / 達成感

- 設備操作の応答確認時間 (目標: 送信から応答確認まで 3 秒以内)
- 緊急停止の発動から設備停止確認までの所要時間 (目標: 5 秒以内)
- 設備操作の成功率 (目標: 99% 以上)
- 設備異常の発見から通報までの所要時間 (live tile 確認 → Mattermost 通報)

## 工数 / 関与人数 / コスト感

- 初回 (操作パネル習熟): 15 分
- 平常 (パラメータ調整): 1〜3 分
- 緊急停止: 10 秒以内
- 失敗時 (通信遅延・応答なし): 5〜10 分 (フォールバック手順 + 現地操作盤へ移動)
- 関与人数: 1〜3 名 (設備担当者 + ライン管理者 + 必要時に保全担当者)

## 前提

- 設備担当者アカウントに設備リモート操作権限が付与されている
- v1_interactive (bidi) が tier2 〜 設備 SCADA 間で接続済みである
- ネットワーク接続が安定している (< 200ms latency)
- 非常停止ボタンは認証不要・最優先 UI として SPA 画面上に常時表示される

## 流れ

1. SPA の設備リモート操作パネルを開く
2. 操作対象設備を選択し、現在の設備状態 live tile を確認する
3. 操作内容 (速度スライダー / パラメータ値) を設定する
4. 「送信」ボタンをタップして制御 op を tier2 → SCADA へ送信する
5. 1 秒以内に設備から応答が返り、SPA に「速度変更を受け付けました: X m/s」トーストが表示される
6. live tile の設備状態表示がリアルタイムで更新されることを確認する
7. (緊急時) 異常を検出した場合は「非常停止」ボタンを即座にタップする
8. 非常停止 op が最優先で送信され、設備から「停止完了」応答が返る
9. SPA に「非常停止: 設備Y が停止しました」のアラート表示と Mattermost 通知が送信される

## 現場の物理環境

- 騒音: 事務所での操作時は 40〜60 dB。フロアでの操作時は 80〜95 dB
- 照度: 事務所 300〜500 lux。フロアでは輝度最大設定
- 防塵: 事務所では手袋なし。フロアでは指先露出型手袋
- 立位時間: 事務所では着席。フロアでは立位
- 緊急性: 非常停止操作は数秒以内の判断・操作が求められる高緊張場面

## 使用デバイス・端末

- 主端末: Windows tablet / iPad
- SPA アクセス: Chrome / Safari
- 通知: Mattermost / Web プッシュ通知 / 端末音声アラート (非常停止時)
- 認証: 通常操作は Touch ID / 高権限操作 (設備停止・起動) は step_up

## 業務手順書 (SOP) との対応

| SOP 条項 | k1s0 対応 |
|----------|----------|
| 社内設備管理規程 §8.2 リモート操作手順 | SPA リモート操作パネルが公式のリモート操作手順として承認される |
| 社内安全規程 §12.1 非常停止手順 | SPA の非常停止ボタンが公式の緊急停止操作手段として承認される |
| ISO 62443 §4.1 安全機能の独立性 | 非常停止は認証不要・最優先 UI として SPA 安全設計に組み込まれる |

## 関連適合仕様 / 関連 OSS

- Bidi 適合仕様 (v1_interactive による双方向リアルタイム通信)
- SLO 適合仕様 (制御 op 応答 < 1s、非常停止 < 200ms)
- 認証適合仕様 (高権限操作時の step_up)
- React (SPA フロントエンド)
- WebSocket / gRPC (bidi 通信レイヤ)

## 期待結果 / 観測指標 / 受入条件

- 制御 op 送信から設備応答トーストまで 1 秒以内
- live tile の設備状態更新遅延 < 500ms
- 非常停止 op の送信から設備停止確認まで 5 秒以内
- Mattermost への緊急通知が 10 秒以内に届く
- 受入条件: リモート操作・非常停止双方の E2E テストが pass

## 失敗時の挙動 / escalation

- 制御 op 送信タイムアウト (1 秒超): 「応答がありません。再試行しますか？」ダイアログを表示。「現地操作盤で確認してください」フォールバック案内も表示
- 非常停止 op が 3 秒以内に応答しない場合: SPA が「非常停止の応答が確認できません。直ちに現地操作盤で停止してください」緊急アラートをフルスクリーン表示
- bidi 接続断: live tile が「接続断 - 最終値 (HH:MM)」にフォールバック。再接続まで制御 op 送信ボタンを非活性化
- escalation: 非常停止後 5 分以内に保全担当者が対応開始しない場合は工場長へ自動エスカレーション

## 失敗パターン (anti-pattern)

1. **live tile の設備状態を確認せずに制御 op を送信する**: 設備が既に異常状態にある場合に不適切なパラメータを送信してしまうリスクがある。SPA は制御 op 送信前に live tile の最終更新時刻が 10 秒以内であることを確認し、古い場合は「設備状態が古い情報です。最新の状態を確認してください」警告を表示する
2. **非常停止ボタンを誤操作してしまい、本来不要な停止が発生する**: ライン停止による生産損失が発生する。SPA は非常停止ボタンをタップした際に「非常停止を発動しますか？ (ラインが即座に停止します)」確認ダイアログを 1 秒間表示し、その後自動実行する (意図的な操作は 1 秒以内に「はい」を確認しなければならない)
3. **bidi 接続断に気づかず live tile の古い状態を見て操作を続ける**: 実際の設備状態と画面表示がずれたまま制御を行うリスクがある。SPA は接続断から 5 秒後に「接続断」アイコンをオーバーレイ表示し、制御 op ボタンを全て非活性化する
