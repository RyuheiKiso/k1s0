# 計量装置連続データ送信_Companion

## 一文方針

計量装置 → Companion (Tauri sidecar) → tier2 API の v1_bulk_upload (at-least-once / continuous push) でデータが途切れなく流れることを現場担当者が確認し、異常通知に対応する。

> 朝 6 時 50 分、計量ライン担当者が作業開始前に計量室の Windows PC を立ち上げる。Companion アプリ (Tauri sidecar) が自動起動し、計量装置と接続が確立されたことを示す緑インジケーターが点灯する。ラインが動き始めると、計量データが 1 秒ごとに画面下のストリームカウンターで増加していく。担当者はその数字を横目で確認しながら計量作業を続ける。午前 10 時、画面に「計量データ送信エラー: tier2 接続断 (3 件バッファ済み)」の黄色バナーが現れた。担当者はすぐにネットワーク担当に連絡する。

## ペルソナ要約

主役: 業務担当者 (計量ライン担当スタッフ級)、目的: Companion が計量装置のデータを途切れなく tier2 へ送信していることを監視し、異常時に適切に対処する

## 現状業務での痛み

- 計量データを手動で紙に記録して後からまとめて入力する二重作業が発生し、入力ミスが生じる
- 計量装置とシステムの接続状態を確認する手段がなく、後から「データが飛んでいた」ことが発覚する
- ネットワーク断絶時にデータが全て失われ、再計量や記録の再現が困難
- 計量異常 (上限・下限超過) が発生しても担当者への通知が遅れ、不良品が後工程に流れてしまう

## k1s0 でこう変わる

- Companion が計量装置からのデータを自動収集して tier2 へ連続送信するため、手動記録・転記が不要になる
- Companion のストリームカウンターと接続インジケーターで送信状態をリアルタイム確認できる
- ネットワーク断絶時はローカルバッファに蓄積して at-least-once で自動 resend するため、データ欠損が発生しない
- 計量異常は Companion が即座に端末とMattermost に通知するため、不良品の後工程流出を防止できる

## Trigger

計量ライン稼働開始時 (Companion 起動 → 計量装置接続確立 → データストリーム開始)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 日次 (勤務日ごとの計量ライン稼働)
- 典型きっかけ: 作業開始前の PC 起動 → Companion 自動起動
- 頻度根拠: 計量装置連続データは計量ライン稼働日に必ず発生する日次業務であり、1 勤務で数千〜数万件のデータが送信される

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| 計量担当者 (主役) | 現場スタッフ | 計量室 / ライン | Companion メイン画面 | 接続状態確認・ストリーム監視・異常対応 |
| 品質管理担当 | 品質管理スタッフ | 品質管理室 | 品質 DB ダッシュボード | 計量データの統計確認・異常値確認 |
| ネットワーク担当 | IT スタッフ | IT 室 | ネットワーク監視画面 | 接続断発生時の対応 |

## 個人 KPI / 達成感

- 1 勤務の送信成功件数 (目標: 計量件数 100%)
- データ欠損件数ゼロ (at-least-once 保証の確認)
- 異常通知の受信から対応開始までの所要時間 (目標: 2 分以内)
- ストリームカウンターの継続増加確認 (担当者の日常的な目視確認)

## 工数 / 関与人数 / コスト感

- 初回 (Companion セットアップ・計量装置接続設定): 30 分
- 平常 (起動確認・監視): 5 分 / 日 (起動確認のみ)
- 異常対応 (ネットワーク断絶・バッファ解消): 10〜30 分
- 失敗時 (Companion クラッシュ・計量装置接続断): 30〜60 分
- 関与人数: 1〜3 名 (計量担当者 + ネットワーク担当 + 品質管理担当)

## 前提

- Windows PC に Companion (Tauri sidecar) がインストール済みである
- 計量装置と Windows PC がシリアル / USB / LAN で接続されている
- Companion に計量装置のドライバ設定が完了している
- tier2 API エンドポイントが Companion に設定済みで、v1_bulk_upload が有効

## 流れ

1. 作業開始前に Windows PC を起動し、Companion が自動起動する
2. Companion が計量装置への接続を確立し、緑インジケーターが点灯する
3. 計量ラインが稼働を開始し、計量データが Companion のストリームカウンターに流れ始める
4. Companion が 1 秒ごとに v1_bulk_upload で tier2 API へデータを送信する
5. 担当者がストリームカウンターと接続インジケーターを定期的に目視確認する
6. (異常なし) 勤務終了時に Companion の「本日の送信件数: XXXX 件」サマリーを確認する
7. (異常あり) 黄色バナー「送信エラー: tier2 接続断 (N 件バッファ済み)」が表示される
8. 担当者がネットワーク担当に連絡し、接続断の原因を確認する
9. ネットワーク復帰後、Companion がバッファ済みデータを自動 resend する
10. 「バッファ N 件の resend 完了」トーストが表示される

## 現場の物理環境

- 騒音: 計量室の計量装置稼働音 (55〜75 dB)
- 照度: 計量室 300〜500 lux
- 防塵: 計量室は比較的清潔な環境だが、粉体計量では防塵マスク着用
- 立位時間: 計量作業中は立位継続 (2〜4 時間)
- PC 設置: 計量室内の固定 PC (デスクトップ + Windows)

## 使用デバイス・端末

- 主端末: Windows PC (デスクトップ / ラップトップ)
- Companion: Tauri ベースの Windows アプリ (sidecar)
- 計量装置インターフェース: RS-232C / USB / LAN 接続
- 通知: Windows トースト通知 / Mattermost デスクトップ通知

## 業務手順書 (SOP) との対応

| SOP 条項 | k1s0 対応 |
|----------|----------|
| ISO 9001 §7.1.5 監視・測定のための資源 | Companion が計量装置のデータを正確に収集・記録する手段として承認される |
| GMP §5.1 計量記録の完全性 | at-least-once 保証とバッファ機能で計量記録の欠損を防止する |
| 社内計量規程 §4.3 計量データの電子記録 | Companion による連続データ送信が電子記録の公式手段として承認される |

## 関連適合仕様 / 関連 OSS

- Tauri_companion_sidecar (Companion アプリケーション基盤)
- Bidi 適合仕様 (v1_bulk_upload による at-least-once 連続送信)
- SLO 適合仕様 (データ送信遅延 < 2 秒)
- Tauri (Windows ネイティブアプリ基盤)
- SQLite (ローカルバッファストレージ)

## 期待結果 / 観測指標 / 受入条件

- Companion 起動から計量装置接続確立まで 30 秒以内
- 計量データの連続送信が 1 秒ごとに実行され、ストリームカウンターで確認できる
- ネットワーク断絶時にローカルバッファへの蓄積が自動開始される
- 復帰後の at-least-once resend で全バッファデータが tier2 に到達する
- 受入条件: 接続断→復帰シナリオの E2E テストで欠損ゼロが確認済み

## 失敗時の挙動 / escalation

- 計量装置接続断: 「計量装置との接続が切断されました。ケーブルを確認してください」アラートを表示。接続確認手順を SPA 画面上に表示する
- Companion クラッシュ: Windows タスクトレイに「Companion が停止しました。再起動しますか？」通知。Mattermost でネットワーク担当・品質管理担当に自動通知
- ローカルバッファ容量超過 (>10,000 件): 「バッファが限界です。ネットワーク担当に連絡してください」フルスクリーンアラートを表示
- escalation: Companion が 1 時間以上停止している場合は品質管理担当と管理者に自動エスカレーション

## 失敗パターン (anti-pattern)

1. **ストリームカウンターを定期確認せず、長時間の接続断に気づかない**: 数時間分のデータがバッファに溜まり、復帰後の resend 負荷が大きくなる。担当者は 1 時間ごとにカウンターと接続インジケーターを確認する手順を SOP に含める
2. **Companion を手動で終了して計量装置を「切り離した」状態で作業する**: データ収集が停止してしまう。Companion 終了時に「計量データの収集が停止します。本当に終了しますか？」の確認ダイアログを表示し、意図しない終了を防ぐ
3. **バッファ蓄積中に計量ラインを増速して件数を増やす**: バッファ容量を超過してデータ欠損が発生するリスクがある。Companion は接続断中はバッファ使用率をリアルタイム表示し、80% 超過時に「速度を落とすことを推奨します」ガイダンスを表示する
