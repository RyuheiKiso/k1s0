# 図面collaborative_review

## 一文方針

図面 collaborative review (v1_interactive、双方向 presence) に複数拠点の担当者が参加し、presence indicator を確認しながら指摘・修正・承認を完了する。

> 水曜の午後 2 時、東京本社の設計担当者と大阪工場の品質担当者が同じ図面を SPA 上で開いている。それぞれのアバターが図面の異なる箇所に重なり、東京の担当者が穴径寸法にコメントを追加すると、0.5 秒後に大阪の画面にも赤い指摘マーカーが現れる。大阪の担当者は「この寸法は公差を ±0.05 に変更してほしい」とコメント欄に入力し、設計担当者がその場で修正案を提示する。両者の確認が完了し、承認ボタンをタップした瞬間、図面に「承認済み」スタンプが押される。

## ペルソナ要約

主役: 業務担当者 (設計担当 / 品質担当スタッフ級)、目的: 複数拠点の担当者とリアルタイムで図面指摘・修正・承認を行い、設計変更を確定する

## 現状業務での痛み

- 図面を PDF でメール送付して各担当者がコメントを返送するやり取りが複数回発生し、1 つの承認に数日かかる
- 異なるバージョンの図面に複数の担当者がコメントし、どのコメントが最新かわからなくなる
- 複数人が同じ箇所を同時にレビューしているかどうかわからず、重複確認や見落としが発生する
- 修正と承認の証跡が各担当者のメール受信フォルダに分散し、後から承認履歴を再構成できない

## k1s0 でこう変わる

- SPA の collaborative review で複数拠点の担当者が同一図面をリアルタイムで確認・コメントできる
- presence indicator で誰がどの箇所を見ているかが即座にわかり、重複確認と見落としを防止できる
- コメント・修正・承認が全て SPA 上のバージョン管理下に記録され、証跡が一元管理される
- リアルタイムの合意形成で 1 日以内の承認完了が可能になり、設計変更リードタイムを大幅短縮できる

## Trigger

図面の設計変更 / 承認依頼が来た時 (設計担当者が SPA に図面をアップロードして review 招集を行った時)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 週次〜月次
- 典型きっかけ: 設計変更が発生した時 / 新規部品の図面承認時 / 定期設計レビュー
- 頻度根拠: 製造業の設計変更は週次〜月次で発生し、承認 workflow に複数担当者が関与する標準的な業務プロセスである

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| 設計担当者 (主役) | 現場スタッフ / 設計担当 | 本社設計室 | SPA 図面 review 画面 | 図面アップロード・招集・修正対応・承認確定 |
| 品質担当者 (主役) | 品質管理スタッフ | 工場品質室 / 事務所 | SPA 図面 review 画面 | 指摘入力・修正確認・承認 |
| ライン管理者 | 現場リーダー | 工場事務所 | 管理ダッシュボード | 承認結果の確認 |

## 個人 KPI / 達成感

- 図面 review の所要時間 (目標: 招集から全員承認まで 1 日以内)
- コメント指摘の解消率 (目標: 全指摘が対応完了してから承認)
- 指摘の重複・見落とし件数ゼロ
- 承認証跡の完全性 (全承認者の承認記録が audit log に存在)

## 工数 / 関与人数 / コスト感

- 初回 (SPA review 機能習熟): 30 分
- 平常 (collaborative review 1 図面): 30〜60 分
- 大規模図面 (指摘多数): 2〜4 時間
- 失敗時 (concurrent_edit による競合・やり直し): 追加 30 分
- 関与人数: 2〜5 名 (設計担当 + 品質担当 + 必要時に管理者)

## 前提

- 参加者全員の SPA アカウントに図面 collaborative review の権限が付与されている
- v1_interactive (bidi) が review セッションに対して有効
- presence indicator が全参加者のアバターをリアルタイム表示できる状態
- 図面ファイル (PDF / SVG) が SPA にアップロード可能な形式・サイズである

## 流れ

1. 設計担当者が SPA に図面ファイルをアップロードし、review 参加者 (品質担当者等) を招集する
2. 招集された参加者の端末に「図面 review 招集: 部品X rev.3」push 通知が届く
3. 各参加者が通知から SPA の図面 review 画面を開く
4. presence indicator に参加者全員のアバターが表示され、online 状態を確認する
5. 設計担当者が図面の説明を行い、参加者が各自のペースで図面をスクロール・ズームして確認する
6. 品質担当者が気になる箇所をタップして指摘コメントを入力する (指摘マーカーが全参加者の画面に表示される)
7. 設計担当者が指摘に対して修正案をコメントで返答する
8. 合意が取れた指摘は「解決済み」に変更し、全指摘が「解決済み」になったら最終確認を行う
9. 参加者全員が「承認」ボタンをタップし、承認スタンプが図面に押される
10. tier2 が承認記録 (承認者全員 / 承認日時 / 図面バージョン) を audit log に emit する

## 現場の物理環境

- 騒音: 設計室 / 事務所 (40〜60 dB)。静かな環境での精密確認作業
- 照度: 設計室 300〜500 lux。図面の細部確認のため画面解像度・輝度が重要
- 防塵: 手袋なし。精密操作のため指先の自由が必要
- 立位時間: 着席での操作が標準
- 拠点間接続: 本社〜工場間の WAN / VPN 接続が安定していることが前提

## 使用デバイス・端末

- 主端末: iPad (大画面推奨) / PC ブラウザ (27 インチ以上のモニター推奨)
- SPA アクセス: Safari / Chrome
- 画面共有: SPA 内の presence indicator のみ使用 (外部の画面共有ツール不要)
- 通知: Web プッシュ通知 / Mattermost

## 業務手順書 (SOP) との対応

| SOP 条項 | k1s0 対応 |
|----------|----------|
| ISO 9001 §8.3.4 設計・開発の管理 | SPA collaborative review が設計管理の電子的レビュープロセスとして機能する |
| 社内設計規程 §5.2 図面承認手続き | presence indicator + 全員承認フローが図面承認手続きの公式プロセスとして承認される |
| 社内品質規程 §7.3 設計変更の記録 | audit log への emit が設計変更記録の電子証跡として機能する |

## 関連適合仕様 / 関連 OSS

- Bidi 適合仕様 (v1_interactive による双方向 presence review)
- クライアント状態適合仕様 (concurrent_edit への対応・コメント競合解消)
- SLO 適合仕様 (指摘コメントのリアルタイム反映 < 500ms)
- React (SPA フロントエンド)
- WebSocket / gRPC (bidi 通信レイヤ)

## 期待結果 / 観測指標 / 受入条件

- presence indicator が全参加者のアバターを 1 秒以内に表示する
- 指摘コメントの追加が全参加者の画面に 500ms 以内に反映される
- 全員承認後に audit log に全承認者・日時が記録される
- 拠点間 WAN 経由でも presence indicator が正常に動作する
- 受入条件: 複数拠点 E2E テスト (本社・工場間) で上記 4 点が全て pass

## 失敗時の挙動 / escalation

- 参加者の接続断: presence indicator からアバターが消え、他の参加者の画面に「品質担当者Y が切断されました」トーストが表示される。再接続後に変更がリプレイされる
- コメントの concurrent_edit 競合: シナリオ 04 の concurrent_edit フロー (presence indicator + 調整) と同様に処理される
- 図面ファイルの読み込み失敗: 「図面の読み込みに失敗しました。ファイル形式・サイズを確認してください」メッセージを表示
- escalation: review 招集から 24h 以内に全員承認が完了しない場合は設計担当者と管理者に Mattermost でリマインダーを送信

## 失敗パターン (anti-pattern)

1. **presence indicator で他の参加者が確認中の箇所を待たずに承認してしまう**: 他の参加者がまだ確認中の指摘が未解決のまま承認される可能性がある。SPA は「X さんがまだ確認中の指摘があります」ウォーニングを承認ボタン押下時に表示し、全指摘「解決済み」を条件とする
2. **コメントを入力せずにマーカーだけを置いて退席する**: 他の参加者がマーカーの意図を読み取れず、無駄なやり取りが発生する。SPA はマーカー追加時にコメント入力欄を必須化し、空コメントのマーカーを受け付けない
3. **チャット / メールで別途やり取りして SPA 外で合意を形成する**: 承認証跡が SPA 外に散在し、後からの監査で証跡が不完全になる。SPA は review セッション外でのコミュニケーションを禁止はしないが、SPA 外での合意は無効であることを review 開始時に表示する
