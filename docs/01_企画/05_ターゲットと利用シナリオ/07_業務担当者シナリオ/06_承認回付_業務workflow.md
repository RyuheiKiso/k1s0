# 承認回付_業務workflow

## 一文方針

検査不良票が上長承認 workflow に回付され、承認/差戻しのアクションを tier3 SPA から実施し、後続の是正対策通知と業務管理者ダッシュボードへの可視化まで完了する。

> 午前 11 時、品質管理担当者が SPA の通知エリアに「承認依頼: 不良票 QF-2024-0312 が回付されました」を確認した。タップして不良票を開くと、検査担当者が記録した不良内容・写真・寸法データが揃っている。担当者は内容を確認し「承認」ボタンを押す。その瞬間、是正対策担当者の Mattermost に「不良票 QF-2024-0312 が承認されました。是正対策を起票してください」の通知が届き、業務管理者ダッシュボードの承認状況グラフが更新される。

## ペルソナ要約

主役: 業務担当者 (品質管理担当 / 承認者スタッフ級)、目的: 検査不良票の承認または差戻し判断を適切に行い、是正対策フローを起動する

## 現状業務での痛み

- 不良票が紙または Excel で回付されるため、承認者が不在の場合に書類が机上で滞留し長時間放置される
- 承認・差戻しの履歴が台帳に手書きされ、後から「誰が・いつ・どのような理由で」承認したかを追跡できない
- 差戻し理由が口頭や付箋で伝えられるため、起票者への正確な情報伝達が難しい
- 業務管理者が承認状況をリアルタイムに把握できず、停滞案件の発見が遅れる

## k1s0 でこう変わる

- SPA に push 通知が届き、承認者が場所を問わずすぐに不良票を確認・承認できる
- 承認・差戻し・差戻し理由が全て audit log に自動記録され、後からいつでも追跡できる
- 差戻し理由が SPA の入力欄に記録されて起票者に通知されるため、正確な情報伝達が保証される
- 業務管理者ダッシュボードがリアルタイムで承認状況を可視化し、停滞案件を即座に識別できる

## Trigger

検査不良 / 出荷保留 / 品質逸脱が記録された時 (tier3 SPA が workflow を自動起票して承認者へ回付する)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 週次 (不良発生頻度に依存)
- 典型きっかけ: 検査担当者がシナリオ 02 で不良を記録した時 / 出荷検査で逸脱を検出した時
- 頻度根拠: 製造現場での不良発生は週次程度が標準的であり、承認回付は不良件数と 1:1 で発生する

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| 承認者 (主役) | 品質管理担当 / 上長 | 品質管理室 / 事務所 | SPA 承認タスク一覧 | 不良票確認・承認または差戻し |
| 検査担当者 | 現場スタッフ | 検査台 | SPA 検査入力フォーム | 不良票起票・差戻し対応 |

## 個人 KPI / 達成感

- 承認タスクの処理所要時間 (目標: 受取から 2 時間以内に承認 / 差戻し完了)
- 差戻し時の差戻し理由記入率 (目標: 100%)
- 当日の未処理承認タスク残件数 (目標: 業務終了時ゼロ)
- 是正対策起票の完了率 (承認後 24 時間以内)

## 工数 / 関与人数 / コスト感

- 初回 (SPA 利用開始当初): 10 分 (不良票の読み方・操作習熟込み)
- 平常 (承認): 3〜5 分
- 差戻し (理由記入含む): 5〜8 分
- 失敗時 (差戻し後の再回付・再確認): 10〜15 分
- 関与人数: 3〜5 名 (承認者 + 検査担当者 + 是正対策担当者 + 業務管理者)

## 前提

- 承認者アカウントに不良票承認権限が付与されている
- tier3 SPA が不良票 workflow を自動起票して承認者へ回付する機能が有効
- テナント分離により、自テナントの不良票のみが表示される
- 是正対策担当者のアカウントが SPA / Mattermost に登録済み

## 流れ

1. 検査担当者が SPA で不良を記録すると、workflow が自動起票されて承認者へ回付される
2. 承認者の SPA に「承認依頼: 不良票 QF-XXXX」push 通知が届く
3. 通知をタップして不良票詳細画面を開く
4. 不良内容 / 写真 / 寸法データ / 検査担当者コメントを確認する
5. 承認の場合: 「承認」ボタンをタップし、必要に応じてコメントを入力して確定する
6. 差戻しの場合: 「差戻し」ボタンをタップし、差戻し理由を必須入力欄に記入して確定する
7. tier2 が承認 / 差戻しを記録し、audit log に emit する
8. 承認の場合: 是正対策担当者の Mattermost に通知が届き、是正対策起票フローが開始される
9. 差戻しの場合: 検査担当者の SPA に「差戻し: QF-XXXX - [差戻し理由]」通知が届く
10. 業務管理者ダッシュボードの承認状況グラフがリアルタイムで更新される

## 現場の物理環境

- 騒音: 品質管理室・事務所 (40〜60 dB)
- 照度: 事務所 300〜500 lux
- 防塵: 手袋なし。不良写真確認のため画面の見やすさが重要
- 立位時間: 着席での操作が標準。緊急時は立位で端末確認も発生
- 精神的プレッシャー: 不良品の出荷保留判断は責任が大きく、慎重な確認が必要

## 使用デバイス・端末

- 主端末: iPad / Windows tablet / PC ブラウザ
- SPA アクセス: Safari / Chrome または PWA
- 通知: Mattermost / Web プッシュ通知
- 認証: Touch ID / パスワード (step_up なし、通常承認の場合)

## 業務手順書 (SOP) との対応

| SOP 条項 | k1s0 対応 |
|----------|----------|
| ISO 9001 §8.7 不適合なアウトプットの管理 | 不良票承認フローが不適合管理の電子的手順として機能する |
| ISO 9001 §10.2 不適合及び是正処置 | 承認後の是正対策起票フローが 10.2 要件の実施手順となる |
| 社内品質規程 §7.1 不良票回付と承認権限 | SPA 承認フローが公式の回付・承認手順として承認される |

## 関連適合仕様 / 関連 OSS

- テナント分離適合仕様 (自テナントの不良票のみ表示)
- SLO 適合仕様 (承認回付の通知遅延 < 5 秒)
- 認証適合仕様 (承認者の認証・audit log)
- React (SPA フロントエンド)
- Mattermost (是正対策起票通知チャネル)

## 期待結果 / 観測指標 / 受入条件

- 不良記録から承認者への通知まで 1 分以内
- 承認アクションから audit log emit まで 2 秒以内
- 業務管理者ダッシュボードのリアルタイム反映遅延 < 5 秒
- 差戻し理由が検査担当者に正確に通知される
- 受入条件: 承認・差戻し双方の E2E テストが pass

## 失敗時の挙動 / escalation

- 承認タスクが 8 時間未処理: 業務管理者の Mattermost に「承認待ち: QF-XXXX が 8h 滞留中」アラートを送信
- 承認操作後に tier2 接続失敗: Pending Queue に入り「送信待機中」バッジを表示。接続回復後に自動 resend
- 差戻し後に検査担当者が 24h 以内に再提出しない: 業務管理者に「再提出未着: QF-XXXX」アラートを送信
- escalation: 同一不良票が 3 回差戻しを繰り返した場合は業務管理者が介入する旨の通知を送信

## 失敗パターン (anti-pattern)

1. **不良写真や寸法データを確認せずに「承認」をタップする**: 不正な不良票が承認されて品質証跡が汚染されるリスクがある。SPA は写真ファイルの添付がある場合に「写真を確認しましたか？」チェックボックスを表示し、未チェックでは承認ボタンを非活性にする
2. **差戻し理由を「NG」や「確認不足」などの曖昧な記述にする**: 検査担当者が再提出時に何を修正すべきかわからず、差戻しが繰り返される。SPA は差戻し理由欄に最低 20 文字以上の入力を要求し、テンプレート選択肢 (「写真の追加が必要」「寸法値の再測定が必要」など) を提供する
3. **承認後に是正対策担当者への通知が届かなかったかどうかを確認しない**: 是正対策が放置されて品質問題が再発するリスクがある。SPA は承認後 24h 経過しても是正対策が未起票の場合、承認者にも「QF-XXXX の是正対策が未起票です」リマインダーを送信する
