# 検査結果入力_オンライン

## 一文方針

ライン上の検査担当が React SPA に検査結果を入力し、Idempotency-Key 付きで tier2 API に送信して品質 DB に記録する。

> 午前 10 時、ライン検査担当者が検査台で部品の寸法測定を終えた。手袋をつけたまま iPad を持ち上げ、SPA の検査入力フォームを開く。ロット番号はバーコードスキャンで自動入力され、測定値を数値フィールドに入力するだけで済む。「送信」ボタンをタップした瞬間、トーストが「記録しました」と表示される。検査担当者はその結果を目視確認し、次の部品の検査に移る。

## ペルソナ要約

主役: 業務担当者 (ライン検査担当スタッフ級)、目的: 検査工程完了ごとに測定値を正確かつ迅速に品質 DB へ記録する

## 現状業務での痛み

- 紙の検査票に手書きで測定値を記録し、後から担当者が PC に転記するため、記録とデータ入力の二重作業が発生する
- 手書き文字の判読ミスで転記エラーが生じ、品質データの信頼性が損なわれる
- 検査結果が品質 DB に反映されるまでに時間差があり、不良の早期発見が遅れる
- ネットワーク不安定時に入力したデータが消えてしまい、再入力が必要になる

## k1s0 でこう変わる

- SPA でバーコードスキャン → 測定値入力 → 送信の一連操作が現場で完結し、転記作業が不要になる
- 測定値は数値フォームで入力するため判読ミスが原理的に発生しない
- 送信完了と同時に品質 DB に記録されるため、不良の早期発見が可能になる
- Idempotency-Key により重複送信・網断時の再送が安全に行われ、データ消失リスクがなくなる

## Trigger

検査工程完了時 (部品・製品の測定・確認が終わるたびに発火)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 日次 (多数回、1 日 20〜100 件)
- 典型きっかけ: 検査台での測定完了 → iPad を手に取る
- 頻度根拠: 製造ラインの検査工程は生産ロットごとに必ず発生し、1 勤務あたり数十〜百件規模の入力が標準的である

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| 検査担当者 (主役) | 現場スタッフ | 検査台 / ライン上 | SPA 検査入力フォーム | バーコードスキャン・測定値入力・送信 |
| 品質管理担当 | 品質管理スタッフ | 品質管理室 | 品質 DB ダッシュボード | 入力された検査結果の確認・不良判定 |
| ライン管理者 | 現場リーダー | 事務所 / フロア | 管理ダッシュボード | 不良発生時の指示出し |

## 個人 KPI / 達成感

- 1 日の検査入力件数 (目標: 担当ロット数 100% 入力)
- 入力エラーゼロ率 (バーコードスキャン成功率)
- 1 件あたり入力所要時間 (目標: 30 秒以内)
- 当日不良率の即時把握 (品質担当への報告時間短縮)

## 工数 / 関与人数 / コスト感

- 初回 (SPA 利用開始当初): 2〜3 分 / 件 (操作習熟込み)
- 平常: 20〜30 秒 / 件
- 失敗時 (送信エラー・再送が必要な場合): 1〜2 分 / 件
- 関与人数: 1〜2 名 (検査担当者 + 品質管理担当)

## 前提

- 検査担当者アカウントが SPA に登録済みで、該当検査工程へのアクセス権が付与されている
- iPad / Windows tablet にバーコードスキャナが接続または内蔵カメラでスキャン可能
- ネットワーク接続済み (オフライン時はシナリオ 03 へ)
- 当日の生産ロット情報が tier2 に登録済みである

## 流れ

1. 検査台で部品の測定を完了し、iPad の SPA を起動する
2. 「検査結果入力」メニューをタップし、検査入力フォームを開く
3. バーコードスキャナ / カメラでロットバーコードを読み取り、ロット番号・品番・工程名が自動入力される
4. 測定値 (寸法 / 重量 / 外観区分など) を数値フィールドに入力する
5. 入力内容を確認し、「送信」ボタンをタップする
6. SPA が Idempotency-Key を付与して tier2 API に送信する
7. tier2 から 200 OK が返り、SPA に「記録しました」トーストが表示される
8. 品質管理担当のダッシュボードにリアルタイムで検査結果が反映される
9. 不良判定の場合は SPA に「不良: 承認 workflow を起票しますか？」ダイアログが表示される

## 現場の物理環境

- 騒音: 検査台周辺の機械音 (60〜80 dB)。ヘッドセット不使用で操作
- 照度: 検査台上 500〜1000 lux。iPad 画面は輝度最大で使用
- 防塵: 指先露出型手袋でのタッチ操作。バーコードスキャナのトリガーボタンも指先操作
- 立位時間: 検査工程中は立位継続 (1〜2 時間連続)
- 端末保管: 検査台横の専用ホルダーに設置、使用時のみ手持ち

## 使用デバイス・端末

- 主端末: iPad (バーコードスキャナ接続) / Windows tablet
- スキャナ: Bluetooth バーコードスキャナ または iPad 内蔵カメラ
- SPA アクセス: Safari / Chrome または PWA
- 認証: Touch ID (WebAuthn、作業開始時の 1 回認証)

## 期待結果 / 観測指標 / 受入条件

- 送信ボタンタップから「記録しました」トーストまで 3 秒以内
- バーコードスキャン成功率 99% 以上
- Idempotency-Key による重複送信防止が E2E テストで確認済み
- 品質管理ダッシュボードへのリアルタイム反映遅延 < 2 秒
- 受入条件: 上記 4 指標が全て CI / E2E で pass

## 失敗時の挙動 / escalation

- 送信タイムアウト: Idempotency-Key 付きで Pending Queue に積み、接続回復後に自動 resend。端末に「送信待機中 (1件)」バッジを表示
- バーコードスキャン失敗: 手動入力モードに切り替えるボタンを表示。手動入力時は入力補助のサジェストを表示
- 不良判定後の workflow 起票失敗: ローカルに下書き保存し、接続回復後に再起票を促すバナーを表示
- escalation: 1 時間以上送信失敗が継続する場合は Mattermost で品質管理担当とライン管理者に自動通知

## 失敗パターン (anti-pattern)

1. **バーコードスキャンをスキップして手入力でロット番号を入力する**: 打鍵ミスによる別ロットへの誤記録が発生しやすい。SPA は手動入力時に「バーコードスキャンを推奨します」の警告を表示し、入力値を品番マスタと照合して不一致の場合は確認ダイアログを出す
2. **送信前に SPA を閉じて (またはブラウザを閉じて) 入力値を消してしまう**: 再入力の手間が発生し、記録漏れのリスクがある。SPA は未送信の入力値を localStorage に自動保存し、次回起動時に復元ダイアログを表示する
3. **不良判定の workflow 起票ダイアログを「後で」で閉じて忘れる**: 不良品の見落としにつながる。SPA は「後で」選択後も Pending 件数バッジを表示し続け、業務終了時に未処理の確認を促す
