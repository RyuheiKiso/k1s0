# 出社_朝礼_ライン稼働確認

## 一文方針

朝の出社 → 朝礼 → tier3 SPA でライン稼働 live tile (v1_live_snapshot) を確認し、当日の生産指示 (FA) を把握して担当ラインの稼働を開始する。

> 朝 7 時 45 分、工場フロアの業務担当者がタイムカードを押し、ロッカーで iPad を受け取る。朝礼が始まる前の 5 分間、担当者は SPA のホーム画面を開き、昨夜から稼働していたラインの live tile を一目で確認する。緑のタイルが並んでいれば安堵し、黄・赤のタイルがあれば朝礼でリーダーに申告する準備を整える。朝礼終了後、生産指示 (FA) 画面で当日のロット番号と目標数量を確認し、担当ラインの稼働開始ボタンを押す。

## ペルソナ要約

主役: 業務担当者 (製造ライン現場スタッフ級)、目的: 当日の生産指示を把握しライン稼働を安全に開始する

## 現状業務での痛み

- 紙の生産指示書が朝礼前に届かず、口頭伝達だけで稼働を開始してしまい、ロット番号の取り違えが発生する
- ライン稼働状態の確認に別棟の監視 PC まで歩かなければならず、移動で 10 分以上を消費する
- 複数ラインの稼働状態を一覧できる画面がなく、担当外ラインの異常に気づくのが遅れる
- 生産指示の変更が朝礼後に紙で回付されるため、スタッフ間で情報の鮮度にばらつきが生じる

## k1s0 でこう変わる

- SPA のホーム画面でライン稼働 live tile を一覧確認でき、別棟への移動が不要になる
- 生産指示 (FA) がリアルタイムで SPA に配信されるため、紙による伝達遅延がなくなる
- 複数ラインの色分け表示 (緑 / 黄 / 赤) で異常ラインを即座に識別できる
- 生産指示変更も push 通知で端末に届くため、全スタッフが同一タイミングで情報を受け取れる

## Trigger

毎朝の出社時 (タイムカード打刻後〜朝礼開始まで)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 日次 (勤務日ごと)
- 典型きっかけ: 出社後の iPad 受取 → SPA 起動
- 頻度根拠: 製造業における日次勤務開始儀礼であり、全業務担当者が毎日必ず実施する最初の業務アクションである

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| 業務担当者 (主役) | 現場スタッフ | 工場フロア | SPA ホーム (live tile) | ライン稼働確認・生産指示確認・稼働開始 |
| ライン管理者 | 現場リーダー | 事務所 / フロア | 管理ダッシュボード | 朝礼での指示出し・異常ライン指摘 |
| tier3 担当者 | 開発者 | 開発拠点 | (非関与) | SPA の live tile 機能を提供 |

## 個人 KPI / 達成感

- 朝礼開始前に全担当ライン稼働状態の確認完了 (目標: 3 分以内)
- 当日生産指示ロット番号の正確な把握率 100%
- 稼働開始ボタン押下からライン始動確認までの所要時間 (目標: 1 分以内)
- 当日の生産目標数量に対する達成率 (退勤時に振り返る)

## 工数 / 関与人数 / コスト感

- 初回 (SPA 利用開始当初): 10 分 (操作習熟込み)
- 平常: 3〜5 分
- 失敗時 (SPA 接続不可 / live tile 読み込み失敗): 15〜20 分 (フォールバック手順 + 担当への連絡)
- 関与人数: 1〜3 名 (本人 + ライン管理者 + 必要に応じて tier3 サポート)

## 前提

- 業務担当者アカウントが SPA に登録済みで、担当ラインへのアクセス権が付与されている
- iPad / Windows tablet に SPA が起動できる状態 (ネットワーク接続済み)
- v1_live_snapshot が tier2 から正常に配信されている
- 生産指示 (FA) データが当日分まで tier2 に登録済みである

## 流れ

1. 出社後、ロッカーで iPad を受け取り SPA を起動する
2. SPA ホーム画面が表示され、担当ライン群の live tile が自動更新される
3. 各タイル色 (緑: 正常 / 黄: 注意 / 赤: 異常) を確認し、異常ラインを把握する
4. 異常タイルがある場合は詳細画面をタップし、異常内容を確認して朝礼申告内容を準備する
5. 朝礼に参加し、管理者の生産指示と自身の確認内容を照合する
6. 朝礼終了後、SPA の生産指示 (FA) 画面を開き、当日のロット番号・目標数量を確認する
7. 担当ラインの稼働開始ボタンを押下し、live tile がグリーンに遷移することを確認する
8. 稼働開始記録が SPA に自動保存されたことをトースト通知で確認する

## 現場の物理環境

- 騒音: 工場フロアの機械稼働音 (80〜95 dB 相当)。朝礼は騒音区画外で実施
- 照度: 工場フロア 200〜500 lux。iPad 画面輝度を最大に設定して使用
- 防塵: 手袋着用 (指先のみ露出型) での iPad タッチ操作が標準
- 立位時間: 朝礼〜稼働開始まで立位 20〜30 分
- 端末保管: 共有ロッカーでの一括保管・充電が標準運用

## 使用デバイス・端末

- 主端末: iPad (第 9 世代以降) / Windows tablet (Surface Go 相当)
- SPA アクセス: ブラウザ (Safari / Chrome) または PWA
- 通知: iPad プッシュ通知 / Mattermost モバイル通知
- 認証: パスワード + Touch ID (WebAuthn)

## 期待結果 / 観測指標 / 受入条件

- SPA ホーム画面の live tile が 1 秒以内に全担当ライン分表示される
- 稼働開始ボタン押下から tier2 への記録完了まで 3 秒以内
- 稼働開始トースト通知が端末に表示される
- Mattermost にライン管理者向け稼働開始通知が届く
- 受入条件: E2E テストで上記 4 点が全て pass

## 失敗時の挙動 / escalation

- live tile 読み込み失敗: SPA がオフラインバナーを表示し、最終キャッシュ値 + タイムスタンプを表示してフォールバック表示する
- tier2 接続不可: SPA が「現在 tier2 との接続を確認中」メッセージを表示し、3 秒ごとに再試行する
- 稼働開始ボタン押下後にタイムアウト: Pending Queue に入り、接続回復後に自動 resend、端末に「送信待機中」バッジを表示する
- escalation: 5 分以上接続不可の場合は端末の「サポートへ連絡」ボタンが有効化され、tier3 オンコールへ Mattermost アラートが飛ぶ

## 失敗パターン (anti-pattern)

1. **live tile を確認せずに稼働開始する**: 異常ラインに気づかないまま稼働開始してしまい、不良品を生産するリスクがある。SPA は稼働開始ボタン押下前に live tile の確認完了チェックを要求する
2. **生産指示 (FA) を朝礼の口頭情報だけで把握し SPA 確認をスキップする**: ロット番号の取り違えが発生しやすい。SPA は稼働開始前に FA 確認画面の表示履歴をチェックし、未確認の場合は警告を表示する
3. **異常タイルを「後で確認」にして朝礼に臨む**: 申告内容が不正確になる。SPA は未確認の異常タイルがある場合、稼働開始ボタンを非活性化してフロアリーダーへの確認を促す
