# legacy_NetFx_ERP_並行入力

## 一文方針

レガシー .NET Framework 4.8 ERP の WinForms 画面 (v1_legacy_http11 + SSE、per-tab 6 subscription) と tier3 SPA を併用し、ERP データを k1s0 に転記 / 連携させる。

> 午前 9 時、事務担当者がデスクトップ PC で .NET Framework 4.8 製の ERP システムを起動する。WinForms の受注入力画面で注文情報を入力しながら、隣のブラウザタブで tier3 SPA を開いて同じ情報を入力する。ERP の SSE 通知が「受注 RO-2024-0501 が確定しました」と表示されると、SPA 側にも自動的に受注データが連携されてくる。担当者は SPA で在庫引き当て操作を行い、ERP との整合性を確認しながら業務を進める。

## ペルソナ要約

主役: 業務担当者 (事務担当スタッフ級)、目的: レガシー ERP と k1s0 SPA を並行運用し、データの整合性を保ちながら業務を継続する

## 現状業務での痛み

- ERP での操作結果を k1s0 に手動転記する必要があり、二重入力の工数が発生する
- ERP と k1s0 でデータの不整合が発生しても気づく仕組みがなく、後から発覚して修正工数が大きくなる
- ERP の WinForms 画面は操作性が古く、若い担当者が使いこなすまでに時間がかかる
- ERP と k1s0 を切り替えて使う際に、どちらの画面が最新情報を持っているかが不明

## k1s0 でこう変わる

- v1_legacy_http11 + SSE 連携により ERP での操作結果が SPA に自動連携され、手動転記が不要になる
- ERP と SPA の整合性チェックがリアルタイムで行われ、不整合時は SPA にアラートが表示される
- SPA で ERP の補完操作 (在庫引き当て / 承認フロー) を実施でき、WinForms のみへの依存を段階的に減らせる
- per-tab 6 subscription で ERP 側の更新を SPA が最大 6 チャネルでリアルタイム受信し、画面切り替え不要で状態が同期される

## Trigger

ERP 側への入力が必要な業務時 (受注入力 / 発注処理 / 在庫更新 / 出荷処理など)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 日次
- 典型きっかけ: 受注が届いた時 / 発注承認が必要な時 / 在庫数量確認が必要な時
- 頻度根拠: 事務担当者は ERP を日常的に使用しており、ERP と k1s0 の並行運用が移行期間中の標準的な業務スタイルとなる

## 個人 KPI / 達成感

- ERP から SPA への自動連携成功率 (目標: 99% 以上)
- 手動転記件数ゼロ (自動連携が成功した場合)
- ERP と SPA のデータ不整合検出件数 (目標: 発生件数の 100% を当日中に解消)
- 1 日の ERP・SPA 並行操作による業務処理件数

## 工数 / 関与人数 / コスト感

- 初回 (ERP・SPA 並行運用習熟): 1〜2 時間
- 平常 (ERP 操作 + SPA 自動連携確認): ERP 操作時間 + 30 秒 (連携確認のみ)
- 不整合発生時 (手動修正): 5〜15 分 / 件
- ERP 停止時のフォールバック (SPA 単独運用): ERP 依存操作の一時停止
- 関与人数: 1〜3 名 (事務担当者 + 業務管理者 + 必要時に IT 担当)

## 前提

- .NET Framework 4.8 ERP が v1_legacy_http11 + SSE 対応版にアップデート済みである
- ERP の per-tab subscription が 6 チャネルに設定されている
- tier3 SPA が ERP の SSE イベントを受信して自動連携する機能が有効
- HTTP2_enforcement が有効で、ERP の HTTP/1.1 通信が適切に処理される

## 流れ

1. ERP WinForms を起動し、受注入力画面を開く
2. 同じ PC のブラウザで tier3 SPA を開き、受注一覧画面を表示する
3. ERP に受注情報を入力して確定操作を行う
4. ERP から SSE 通知「受注 RO-XXXX が確定しました」が発火する
5. SPA の受注一覧に ERP の受注データが自動連携されて表示される (手動転記不要)
6. SPA で在庫引き当て操作を行い、ERP と SPA の在庫数を照合する
7. 整合性チェックが通れば「ERP と在庫数が一致しています」インジケーターが表示される
8. 不整合が発生した場合は「ERP 在庫: X 個 / SPA 在庫: Y 個 (差異: Z 個)」不整合アラートが表示される
9. 不整合がある場合は原因を調査し、SPA または ERP の値を修正する
10. 当日の ERP・SPA 並行処理が完了し、業務終了時に整合性サマリーを確認する

## 期待結果 / 観測指標 / 受入条件

- ERP 確定操作から SPA への自動連携まで 10 秒以内
- per-tab 6 subscription が正常に動作し、6 タブ同時に SSE を受信できる
- 整合性チェックが ERP・SPA の在庫数を正確に比較して表示する
- 不整合アラートが発生から 1 分以内に事務担当者と管理者に通知される
- 受入条件: ERP→SPA 連携 E2E テストで上記 4 点が全て pass

## 失敗時の挙動 / escalation

- SSE 接続断 (ERP → SPA の連携が停止): SPA に「ERP 連携が中断されています」バナーを表示。手動転記モードへの切り替えオプションを表示
- per-tab subscription 上限超過 (7 タブ以上): 「ERP 連携のタブ数が上限 (6) を超えています。不要なタブを閉じてください」警告を表示
- 整合性チェック失敗 (差異 > 5 件): Mattermost で業務管理者に自動アラートを送信
- escalation: ERP 連携が 1 時間以上停止している場合は IT 担当と業務管理者に自動エスカレーション

## 失敗パターン (anti-pattern)

1. **整合性チェックのアラートを無視して業務を続ける**: ERP と SPA のデータ乖離が拡大し、後から大規模な修正作業が必要になる。SPA は不整合が 3 件以上になると在庫引き当て操作をロックし、「不整合を解消してから続けてください」メッセージを表示する
2. **SPA の自動連携を過信して ERP での確定操作の確認を怠る**: ERP で入力ミスがあっても SPA に誤ったデータが連携される。SPA の受注一覧に連携された受注の「元の ERP データを確認」リンクを表示し、定期確認を促す
3. **per-tab subscription の上限 (6) を知らずに多数のタブを開いてしまう**: 上限を超えたタブの SSE が無効になり、一部の ERP 更新が SPA に届かなくなる。SPA は現在アクティブな subscription 数を常時表示し、5 つ目のタブを開いた際に「あと 1 タブで上限です」警告を表示する
