# 警報受信_アラート対応

## 一文方針

警報配信 (v1_alert、低 lag + replay) を SPA / Companion で受信し、ライン停止手順に従い対応し、是正処理と報告まで完了する。

> 午後 2 時 15 分、ライン担当者の iPad が「警報: ライン C3 - 圧力センサー上限超過 (設定値: 0.8 MPa、実測: 1.2 MPa)」の赤いプッシュ通知を受信した。担当者は作業の手を止め、SPA の警報詳細画面を開く。警報の発生時刻・センサー値・推奨対応手順が表示されており、担当者は手順に従ってバルブを手動で絞り、設備担当者に Mattermost で報告する。是正完了後、SPA の「対応完了」ボタンをタップして警報をクローズする。

## ペルソナ要約

主役: 業務担当者 (ライン担当スタッフ級)、目的: 受信した警報の内容を素早く把握し、ライン停止手順に従って安全に対応し、是正処理と報告を完了する

## 現状業務での痛み

- 警報が監視室の警報板のみに表示されるため、フロアにいる担当者への伝達に時間がかかる
- 警報の内容・推奨対応手順が手元にない状態で対応を始め、手順書を取りに行く必要がある
- 警報の受信・対応開始・完了の記録が紙台帳のみで、後から対応時間の分析ができない
- 複数の警報が同時発生した場合に優先順位を判断する情報がなく、担当者が混乱する

## k1s0 でこう変わる

- 警報が SPA / Companion に即座に push 配信され、フロアにいる担当者が手元で受信できる
- 警報詳細画面に発生時刻・センサー値・推奨対応手順が表示され、手順書不要で対応に集中できる
- 受信・対応開始・完了の全アクションが自動記録され、対応時間の分析データとして活用できる
- 複数警報の優先度ランク (緊急 / 警戒 / 注意) が色分け表示され、担当者が優先順位を即座に判断できる

## Trigger

警報が配信された時 (センサー異常値 / 設備異常 / 品質逸脱 / 計量異常など)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 週次〜月次 (警報発生時)
- 典型きっかけ: センサー値が設定閾値を超過した時 / 設備の自己診断が異常を検出した時
- 頻度根拠: 製造現場の警報発生頻度は設備規模・老朽化に依存するが、週次〜月次が標準的な発生頻度である

## 主役 / 関与者

| 役割 | 級 | 主に居る場所 | 朝最初に見る画面 | このシナリオでの主要動作 |
|------|---|------------|----------------|----------------------|
| ライン担当者 (主役) | 現場スタッフ | ライン / フロア | SPA アラート一覧 | 警報受信・内容確認・対応実施・完了報告 |
| 設備担当者 | 現場スタッフ / 保全 | 事務所 / 保全室 | Mattermost | 対応支援・保全対応 |
| ライン管理者 | 現場リーダー | 事務所 | 管理ダッシュボード | 警報状況の監視・担当者への指示 |

## 個人 KPI / 達成感

- 警報受信から対応開始までの所要時間 (目標: 2 分以内)
- 対応完了報告の正確性 (是正内容の記録率 100%)
- 同日中の全警報対応完了率
- 再発警報の件数 (是正が有効であれば減少する)

## 工数 / 関与人数 / コスト感

- 注意レベル警報: 5〜10 分
- 警戒レベル警報 (ライン減速・一時停止): 15〜30 分
- 緊急レベル警報 (ライン停止・非常停止): 30〜60 分以上
- 失敗時 (誤対応・再警報): 追加 30〜60 分
- 関与人数: 2〜5 名 (担当者 + 設備担当 + ライン管理者 + 必要時に保全担当)

## 前提

- ライン担当者の端末に SPA の push 通知が有効化されている
- v1_alert (低 lag + replay) が tier2 で有効で、警報配信が設定済み
- 警報のレベル設定 (緊急 / 警戒 / 注意) と推奨対応手順が tier2 に登録済み
- Mattermost が通知チャネルとして設定されている

## 流れ

1. SPA / Companion に警報 push 通知が届く
2. 通知をタップして SPA の警報詳細画面を開く
3. 警報レベル / 発生時刻 / センサー値 / 対象設備 / 推奨対応手順を確認する
4. 「対応開始」ボタンをタップし、担当者名と対応開始時刻が記録される
5. 推奨対応手順に従って物理的な対応を実施する (バルブ操作 / ライン減速 / 停止など)
6. 対応完了後、SPA の「是正内容」テキスト欄に実施内容を記録する
7. 「対応完了」ボタンをタップし、警報がクローズされる
8. tier2 が対応記録 (担当者 / 対応開始〜完了時刻 / 是正内容) を audit log に emit する
9. ライン管理者の管理ダッシュボードで警報がクローズされたことを確認する
10. Mattermost でライン管理者へ対応完了を報告する

## 現場の物理環境

- 騒音: ライン稼働中 80〜95 dB。警報音が鳴る場合はさらに高騒音
- 照度: ライン上 200〜500 lux。iPad 輝度最大設定
- 防塵: 防塵手袋着用でのタッチ操作
- 立位時間: 警報対応中は移動・立位継続
- 緊急性: 警報レベルに応じて数秒〜数分での初動対応が求められる

## 使用デバイス・端末

- 主端末: iPad / Windows tablet (フロア携行型)
- Companion: Windows PC で動作 (計量ライン用)
- push 通知: iOS プッシュ通知 / Mattermost モバイル通知
- 認証: 対応開始・完了時はログイン済みセッションを使用

## 業務手順書 (SOP) との対応

| SOP 条項 | k1s0 対応 |
|----------|----------|
| 社内安全規程 §10.2 警報対応手順 | SPA の警報詳細画面に推奨対応手順が表示され、SOP に準拠した対応を支援する |
| ISO 9001 §10.2 不適合及び是正処置 | 是正内容の SPA 入力が是正処置の電子記録として機能する |
| 社内設備管理規程 §9.3 警報記録の保全 | audit log への自動 emit で警報対応の全記録が保全される |

## 関連適合仕様 / 関連 OSS

- Bidi 適合仕様 (v1_alert による低 lag 警報配信 + replay)
- SLO 適合仕様 (警報配信遅延 < 1 秒)
- クライアント状態適合仕様 (オフライン時の警報キャッシュ・replay)
- React (SPA フロントエンド)
- Mattermost (警報通知・対応完了報告チャネル)

## 期待結果 / 観測指標 / 受入条件

- 警報発生から担当者端末への配信まで 1 秒以内
- 警報詳細画面の推奨対応手順が警報タイプに対応した内容で表示される
- 対応開始・完了の記録が audit log に正確に emit される
- 管理ダッシュボードの警報ステータスが 5 秒以内にリアルタイム更新される
- 受入条件: 警報配信→対応→クローズの E2E テストが pass

## 失敗時の挙動 / escalation

- 警報受信後に担当者が 5 分以内に「対応開始」をタップしない: ライン管理者の Mattermost に「警報未対応: QF-XXXX が 5 分経過」アラートを送信
- 対応完了後も警報センサー値が改善しない (再警報): 「是正が不完全な可能性があります。設備担当者に連絡してください」メッセージを表示
- オフライン中に警報が発生: replay 機能でネットワーク復帰後に受信し、「X 分前に警報が発生しました」タイムスタンプ付きで表示
- escalation: 緊急レベル警報で 10 分以内に対応完了しない場合は管理者・保全担当者に自動エスカレーション

## 失敗パターン (anti-pattern)

1. **警報通知を「後で確認」として無視し、対応開始を遅らせる**: 緊急レベル警報では被害拡大のリスクがある。SPA は緊急レベル警報の場合、通知バナーをスワイプで消せない設計にし、警報詳細画面を開くまでバナーを表示し続ける
2. **是正内容を「対応した」の一言だけで完了報告する**: 後からの原因分析や再発防止に使えるデータが残らない。SPA は是正内容入力欄に「実施した対応の具体的な内容を記録してください」のプレースホルダーを表示し、最低 30 文字の入力を要求する
3. **対応完了後に replay 機能で過去の警報を確認しない**: 同様の警報が繰り返し発生しているパターンに気づかないまま対症療法を繰り返す。SPA は対応完了後に「過去 30 日間の同種警報発生件数: N 件」を表示して注意を促す
