# 25h_オフライン業務記録

## 一文方針

工場奥地で 25h ネットワーク断絶した検査担当が IndexedDB encrypted に 5 件オフライン記録し、復帰後に sync → Idempotency-Key TTL 超過 → user 確認 → 新 key で resend する。

> 夕方 4 時、工場奥地の冷凍倉庫内で点検作業を担当する検査担当者が、端末の電波表示が消えているのに気づいた。圏外は想定内だ。業務を止めるわけにはいかないので、SPA のオフラインモードで検査記録を続ける。IndexedDB に暗号化保存されるため、データ紛失の心配はない。翌朝、別フロアに出てネットワークが復帰すると、SPA が「5 件の未送信記録があります。うち 3 件は TTL を超過しています。再送しますか？」と確認を求めてくる。担当者は内容を確認し「再送する」をタップする。

## ペルソナ要約

主役: 業務担当者 (検査担当スタッフ級)、目的: 25h 超のオフライン状態でも業務記録を継続し、復帰後に安全に同期する

## 現状業務での痛み

- 圏外区画では入力ができず、作業メモを紙に残して後から転記するしかなく、記録漏れが発生する
- ネットワーク復帰後に一括入力する際、タイムスタンプが復帰時刻になり実際の作業時刻との乖離が生じる
- 重複送信を恐れて「既に送ったかどうか不明」な件は未送信のまま放置され、記録欠損が常態化する
- 長時間オフライン後の同期で何件がどのステータスかを把握できず、担当者が不安を抱えたまま業務を終える

## k1s0 でこう変わる

- SPA のオフラインモードで検査結果を入力すると、IndexedDB encrypted に実作業時刻付きで保存され、紙メモが不要になる
- 復帰後の sync で実作業時刻が正確に tier2 に記録され、タイムスタンプの乖離が解消される
- Idempotency-Key 管理により重複送信を防ぎ、TTL 超過時は user に確認してから新 key で安全に resend できる
- Pending Queue の件数・ステータスが SPA に常時表示されるため、担当者がオフライン件数を把握したまま帰宅できる

## Trigger

25h を超えるオフライン業務が発生した時 (ネットワーク断絶状態が 25h を超えて Idempotency-Key TTL が超過した時)

## 想定頻度 / 典型きっかけ / 頻度根拠

- 想定頻度: 月次〜四半期 (オフライン業務発生時)
- 典型きっかけ: 冷凍倉庫 / 地下設備 / 電波遮蔽区画での長時間作業
- 頻度根拠: 工場奥地や特殊環境での定期点検は月次〜四半期で発生し、そのたびに 25h 以上の圏外状態が生じる運用ケースが確認されている

## 個人 KPI / 達成感

- オフライン記録件数 (目標: 作業件数 100% を漏らさず記録)
- sync 完了率 (目標: 復帰後 10 分以内に全件 sync 完了)
- TTL 超過 resend 処理の完了所要時間 (目標: 確認ダイアログから 2 分以内)
- 記録欠損件数ゼロ (sync 後に品質 DB に全件が存在すること)

## 工数 / 関与人数 / コスト感

- 初回: 5 分 (オフラインモードの認識 + 入力操作習熟)
- 平常 (オフライン記録中): 20〜30 秒 / 件 (シナリオ 02 と同等)
- 復帰後 sync・TTL 確認処理: 3〜5 分
- 失敗時 (resend 失敗・再処理が必要): 10〜15 分
- 関与人数: 1〜2 名 (検査担当者 + 品質管理担当)

## 前提

- SPA がオフラインモードに対応しており、IndexedDB encrypted が端末に有効化されている
- 業務担当者が出発前にオンライン状態で SPA にログイン済みである (オフライン中の認証キャッシュが有効)
- Idempotency-Key の TTL が 24h に設定されている (25h 超過で TTL 切れとなる)
- ネットワーク復帰後に SPA がバックグラウンド sync を自動開始する設定が有効

## 流れ

1. 圏外区画に入り、SPA がオフラインバナー「ネットワーク未接続 - オフラインモードで動作中」を表示する
2. オフライン状態のまま SPA の検査入力フォームで測定値を入力する
3. 「送信」タップ時に SPA が「オフライン記録: IndexedDB に保存しました」トーストを表示する
4. 5 件の入力が完了し、Pending Queue の件数バッジが「5」になる
5. 25h 経過後、圏外区画を出てネットワークが復帰する
6. SPA がバックグラウンド sync を開始し、Idempotency-Key TTL を確認する
7. 5 件中 3 件が TTL 超過 (25h 経過) と判定される
8. SPA が「3 件の Idempotency-Key が期限切れです。新しい Key で再送しますか？」確認ダイアログを表示する
9. 担当者が各件の内容 (ロット番号・作業時刻) を確認し「再送する」をタップする
10. SPA が新 Idempotency-Key を生成して全 5 件を tier2 API に送信する
11. tier2 から 200 OK が返り、Pending Queue がゼロになり「5 件の記録が完了しました」トーストを表示する

## 現場の物理環境

- 騒音: 冷凍設備モーター音 (70〜85 dB)。地下設備では反響が大きい
- 照度: 冷凍倉庫内 100〜200 lux (暗め)。iPad 画面輝度は最大設定
- 防塵・防寒: 防寒手袋着用。指先カットタイプまたはタッチ対応手袋
- 立位時間: 点検作業中は立位・移動継続 (最大 8 時間)
- 端末保管: 防寒ジャケットのポケットに携行。バッテリー消耗に注意

## 使用デバイス・端末

- 主端末: iPad (防水・防塵ケース装着) / Windows tablet
- オフライン対応: PWA / ネイティブ相当の IndexedDB encrypted
- バッテリー: モバイルバッテリー携行が推奨
- 認証: 出発前のオンライン認証キャッシュを使用。生体認証は端末内で完結

## 業務手順書 (SOP) との対応

| SOP 条項 | k1s0 対応 |
|----------|----------|
| ISO 9001 §8.6 製品・サービスのリリース | オフライン記録でも実作業時刻が正確に保存され、品質証跡として有効 |
| 社内品質規程 §5.4 圏外作業時の記録規定 | SPA オフラインモードが圏外作業時の公式記録手段として承認される |
| GMP §4.9 記録の完全性 | IndexedDB encrypted により改ざん不可の電子記録が担保される |

## 期待結果 / 観測指標 / 受入条件

- オフライン記録 5 件が全て IndexedDB に暗号化保存されている
- 復帰後 sync で TTL 超過件数が正確にカウントされ確認ダイアログが表示される
- 新 Idempotency-Key での resend が全件 200 OK で完了する
- sync 完了後に品質 DB に 5 件全てが実作業時刻付きで存在する
- 受入条件: オフライン→復帰 E2E テストで上記 4 点が全て pass

## 失敗時の挙動 / escalation

- IndexedDB への保存失敗 (ストレージ容量不足): SPA が「ストレージ容量が不足しています。古い送信済み記録を削除しますか？」ダイアログを表示する
- 復帰後の sync でネットワークが再び切断された場合: sync を中断し、送信済み分と未送信分を分けてステータスを表示する
- resend の連続失敗 (3 回): Mattermost で品質管理担当とライン管理者に「X 件の resend が失敗しています」通知を送信する
- escalation: sync 失敗が 1 時間継続する場合は tier3 オンコールへ自動アラートを送信する

## 失敗パターン (anti-pattern)

1. **圏外区画に入る前に SPA にログインしておかない**: オフライン中に認証キャッシュが切れると入力不可になる。SPA は圏外遷移時に「認証キャッシュは X 時間有効です」を表示し、長期点検前には事前ログインを促す
2. **TTL 超過確認ダイアログを確認せず「キャンセル」で閉じる**: 未 resend のまま Pending Queue に残り続け、品質 DB に記録されない。SPA はキャンセル後も Pending バッジを表示し、業務終了時に再確認を求める
3. **復帰後に SPA を閉じてしまい sync が実行されない**: バックグラウンド sync はブラウザが生存している必要がある。PWA インストール済みの場合は Service Worker が自動 sync するが、非 PWA 環境ではアプリ終了時に「未送信 N 件があります。送信しますか？」ダイアログを出して保護する
